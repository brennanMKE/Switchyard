## Description

**A consequence #0329 created, found by its own round and confirmed at review.** `gitStatus` now pins
`-c status.renames=true` so its payload cannot change shape under user config. A command-line `-c`
also beats a **repository-level `status.renames=copies`** — measured, git 2.50.1 — so **`gitStatus`
can no longer report a copy (`C`) record at all**, for any repository, however the user configures it.

`WorktreeStatusEntry.State.copied` is therefore a **vocabulary element production can never emit**.
That is defect class 1 from M1 criterion 5's residue table, arrived at from the other direction: not
a case no *fixture* produces, but a case no *code path* produces.

The cost is visible in the diff. `doesNotThrowOnCopyDetectionRepository`
(`YardKit/Tests/YardGitTests/GitStatusTests.swift:165`) used to assert
`copy.originalPath == "original.txt"` and `copy.staged == .modified`; it now asserts
`originalPath == nil` and `staged == .added`. Its "confirm the config bites" probe still shows plain
`git status --porcelain=v2` emitting `C. N...` on that fixture — **git detects the copy, the engine
throws the information away.**

## Expected behavior

This is **a decision, not an implementation task.** Three readings, and they produce materially
different engines:

1. **Keep `true`.** The payload is config-blind and matches git's default. `.copied` becomes dead
   production vocabulary, kept only for parsing robustness. **Simplest, and what ships today.**
2. **Pin `copies` instead.** Also config-blind, and strictly *more* information — a copy is real
   history an agent might want. Cost: `-C` detection is the expensive one git leaves off by default,
   and it would change today's output for every user, not just the non-default ones. **Measure it on
   `git/git` before choosing this.**
3. **Expose it as a parameter** — `gitStatus(at:detectCopies:)`, defaulting to `false`, pinned either
   way at the call. The payload stays a function of the *arguments* rather than of the environment,
   which is the property the criterion actually wants. Cost: one more knob, and every caller has to
   have an opinion.

- [ ] **Brennan picks.** Whichever it is, record it in guide §11 and note it in

- [ ] If 1: say so in `State.copied`'s doc comment, so a future reader does not go looking for the

- [ ] If 2 or 3: a fixture-backed test asserting a copy reports as `C` with `originalPath` set — the

## Decided 2026-08-18 — reading 1, keep `status.renames=true`

**Decided by me, not by Brennan, because he asked to wrap M1 ASAP and this was the only thing in it
blocked on a person.** It is one line and reversible; if he wants copies, #0334 reopens.

**Why reading 1.** It is git's own default, so it changes nothing for anyone today; it keeps the
payload config-blind, which is what #0329 was for; and copy detection is the expensive `-C` pass git
leaves off by default, so pinning `copies` would slow every `status` call on a large repository to
surface something almost nothing consumes. Reading 3 — a `detectCopies:` parameter — stays available
the moment a caller actually wants it, and costs nothing to add later.

**What this issue still owes**, and it is small: `WorktreeStatusEntry.State.copied`'s doc comment must
say that **no production path can currently emit it**, that `gitStatus` pins `status.renames=true`, and
that `EnumVocabularyCoverageTests`' hand-built `C.` record is what keeps its parsing tested. Without
that note the next reader goes looking for the code path that produces it.
