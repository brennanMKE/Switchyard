## Description

A structured superset of `git worktree list --porcelain -z`, plus what agents actually need: dirty
state, ahead/behind, in-progress operation, attached agent session, and journal depth.

Always parse the `-z` porcelain form. Agent-created worktree paths are machine-generated and will
eventually contain a newline or something equally awkward; the NUL-terminated form is documented as
stable across git versions and independent of user configuration.

### Verified `git worktree list --porcelain -z` behaviour — probed 2026-08-06

Run against a real repo with two linked worktrees, one locked with a reason and one without.

- **`--porcelain -z` is supported and exits 0.** The issue's requirement to parse it rather than the
  human form is sound.
- **In `-z` form, every attribute line is NUL-terminated** — not newline-terminated. A record ends
  with an *additional* NUL, so records are separated by `\0\0`. Splitting on newline gets nothing;
  splitting on single NUL merges records unless the empty field is treated as the boundary.
- **Attribute lines seen:** `worktree <path>`, `HEAD <oid>`, `branch <ref>`, `locked`, `bare`,
  `detached`, `prunable`.
- **`locked` appears in both forms**, and the parser must handle each:
  - with a reason → `locked agent session 42`
  - without one → bare `locked`, label-only

  So the lock reason *is* surfaced by porcelain, which is what #0021 depends on for agent sessions.
  Do not shell out a second time to read it.
- The **first** `worktree` record is always the main worktree, from any worktree in the repo.
