## Description

**The app launches today and shows `Text("Hello, world!")`.** That is the whole of
`YardKit/Sources/YardUI/ContentView.swift`, and it is the only file in `YardUI`.

**Nothing structural is in the way of it showing real data.** Guide §11 decision 10 puts every view in
the package, and `YardUI` already depends on **`YardKit` and `YardGit`** (`Package.swift:35-36`), so a
view can call the engine directly. **The XPC layer is not required for this** — XPC exists so the
*CLI* can drive the app, not so the app can reach its own engine. CLAUDE.md: "The app owns the engine."

So the shortest path from here to something a human can look at is one view, and this issue is it.

## Expected behavior

- [ ] `ContentView` shows, for a repository the user picks:
      - a header from `whereAmI(path:)` — branch, short OID, upstream, and the four counts;
      - a list from `gitStatus(at:)` — one row per entry, showing `path`, the staged and worktree
        state characters, and `originalPath` when present.
- [ ] **A folder picker.** An `NSOpenPanel` limited to directories, opened from a toolbar button and
      from an empty-state button in the middle of the window. No hardcoded path, and no attempt to
      guess a repository at launch.
- [ ] **The engine calls must not run on the main actor.** `YardUI` sets
      `.defaultIsolation(MainActor.self)`, and `whereAmI`/`gitStatus` shell out to `git` synchronously —
      calling them directly from a view body or a `@MainActor` method **blocks the window**. Load them
      off the main actor and hop back to publish, e.g. a `nonisolated` async loader returning a plain
      `Sendable` value that the view assigns.
- [ ] **A chosen folder that is not a repository shows the error, not an empty list.** `whereAmI`
      throws there (#0140); catch it and show the message. An empty success state is the exact shape
      guide §9 M1 criterion 3 forbids, and #0287 found three engine functions violating it.
- [ ] **A `YardUITests` test that the loader returns real data for a real repository** — build a
      `FixtureRepository`, run the loader, assert the branch name and that the status entries match a
      known dirty file. Assert values, not non-nil.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, above the count in `docs/test-baseline.txt`.
- [ ] `xcodebuild build -project Switchyard.xcodeproj -scheme Switchyard -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO -quiet` succeeds. **Paste the result.**

## The files

`YardKit/Sources/YardUI/ContentView.swift`, new files alongside it in `YardKit/Sources/YardUI/` as
needed, and `YardKit/Tests/YardUITests/`.

**Do not touch the Xcode project.** `SwitchyardApp.swift` already renders `ContentView()`; new Swift
files under a synchronized group need no `project.pbxproj` edit, and Xcode rewrites that file while it
is open (CLAUDE.md).

## Notes

**Milestone M3.** This is the demo issue — its deliverable is *a window with real repository data in
it*, and everything else is in service of that.

**Deliberately not in scope**, each already an issue: the graph pane (#0052), the three-pane shell
(#0080), the sidebar (#0081), the detail pane (#0082), tabs (#0079), multi-window (#0078). **Do not
build toward them.** A single-pane window that works beats a three-pane shell that does not, and the
panes have their own issues precisely so this one can be small.

**No signing.** Build unsigned, per CLAUDE.md. If a signing error appears, stop and report — do not
change any signing setting.
