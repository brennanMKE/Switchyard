# 0106 — The layering tests scan too narrowly to catch what they guard

| | |
|---|---|
| **Status** | open |
| **Module** | YardKit |
| **Milestone** | M1 |

## Description

Two tests in `YardKit/Tests/YardKitTests/LayeringTests.swift` enforce the dependency direction:
`yardGitDoesNotImportYardKit` and the inverse added by #0104. Both would miss a real violation.

**They scan one directory level.** Each uses
`FileManager.default.contentsOfDirectory(at:includingPropertiesForKeys:)`, which does not recurse.
`Sources/YardGit/` and `Sources/YardKit/` are flat today, so both pass — but the first file added in a
subdirectory is unguarded, and nothing announces that.

**They match by exact prefix.** `trimmed.hasPrefix("import YardGit")` does not match
`@testable import YardGit`, nor an import with a leading attribute or an `internal import`.

Neither is a regression — #0104's new test was deliberately written in the same style as the existing
one, which is the right instinct. Both share the gap.

## Why this matters more than it looks

These two tests are the *only* mechanical enforcement of the project's layering. `CLAUDE.md` states
the direction in prose, and prose has already failed once: the manifest carried the wrong dependency
for weeks (#0104). A guard that cannot see a subdirectory is the same shape as a check that cannot
fail.

## Givens — verified on `main`, treat as true

1. The file is `YardKit/Tests/YardKitTests/LayeringTests.swift`.
2. Both tests derive the source root from `#filePath` by walking up three levels. That part is
   correct and portable — keep it.
3. `main` is at 134 tests.

## Expected behavior

- [ ] Both tests walk the tree recursively — `FileManager.enumerator(at:includingPropertiesForKeys:)`
      or equivalent — so a file in a subdirectory is scanned.
- [ ] Both match an import robustly enough to catch `@testable import X` and a plain `import X` with
      leading whitespace. A regex on the line, or a contains-check after stripping `@testable`, is
      fine. Do not try to parse Swift.
- [ ] Both assert the file set they scanned is **non-empty**, so a broken path silently scanning
      nothing fails loudly instead of passing. The existing test already does this; keep it and add
      the same to the new one.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest.
- [ ] `cd YardKit && swift build` succeeds and `swift test` prints a `Test run with N tests` line you
      paste. **N must be greater than or equal to 134.**

## Tests must be able to fail

Four mutations, each reverted afterwards:

1. Add `import YardKit` to a file in `Sources/YardGit/` → the first test fails.
2. Add `@testable import YardGit` to a file in `Sources/YardKit/` → the second test fails. **This is
   the one the current code misses.**
3. Create `Sources/YardKit/Sub/Offender.swift` containing `import YardGit` → the second test fails.
   **Also currently missed.**
4. Point a scan at an empty directory → the non-empty assertion fails.

Report each result, then confirm the suite is green and `git diff` is unchanged.

## Notes

Found during review of #0104. Note that adding the import also breaks compilation, since `YardGit`
needs `Clibgit2` — but a compile error is not proof the *test* works, which is exactly the confusion
#0104's round made. Mutate in a way that isolates the test.
