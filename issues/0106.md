## Description

Two tests in `YardKit/Tests/YardKitTests/LayeringTests.swift` enforce the dependency direction:
`yardGitDoesNotImportYardKit` and the inverse added by #0104. Both would miss a real violation.

**They scan one directory level.** Each uses
`FileManager.default.contentsOfDirectory(at:includingPropertiesForKeys:)`, which does not recurse.
`Sources/YardGit/` and `Sources/YardKit/` are flat today, so both pass — but the first file added in a
subdirectory is unguarded, and nothing announces that.

**They match by exact prefix.** `trimmed.hasPrefix("import YardGit")` does not match
`@testable import YardGit`, nor an import with a leading attribute or an `internal import`.

Neither is a regression — #0104's new test was deliberately written in the same style as the existing
one, which is the right instinct. Both share the gap.

## Why this matters more than it looks

These two tests are the *only* mechanical enforcement of the project's layering. `CLAUDE.md` states
the direction in prose, and prose has already failed once: the manifest carried the wrong dependency
for weeks (#0104). A guard that cannot see a subdirectory is the same shape as a check that cannot
fail.

### Defect 1 — the matcher can never match

`stripImportAttributes` removes `@testable `, `internal ` and `public `, but **never removes
`import `**. The caller then asks:

```swift
let marker = stripImportAttributes(from: trimmed)
#expect(!marker.hasPrefix("YardKit"), …)
```

`import YardKit` becomes `"import YardKit"`, and `.hasPrefix("YardKit")` is **false**. So is
`@testable import YardGit`. The assertion is unfalsifiable for every real import line — only a line
literally starting with the module name could trip it, and Swift has no such syntax.

Fix: consume `import ` too, or match the whole line:
`^\s*(@testable\s+)?(internal\s+|public\s+)?import\s+YardGit\b`. **Keep the `\b`** so a module
named `YardGitFoo` is not a false positive.

### Defect 2 — `skipDescendants()` disables the recursion it was added for

```swift
if isDir { enumerator.skipDescendants() }
```

`skipDescendants()` means *do not descend into the directory just returned* — and it is called on
every directory, so the walk never goes below one level. The `recursive:` parameter is inert, and the
old `contentsOfDirectory` branch is now dead code.

Proved independently: pointed at a fixture whose only `.swift` file lives in `Sub/`, the scan returned
`swiftFiles → []`. So mutation 3 has **two** independent causes; fixing the matcher alone would not
close it.

Fix: delete the `skipDescendants()` call. If the intent was to skip hidden directories, skip them by
name.

### Why this got through every check

`enumerator`, `@testable` and the non-empty assertion are all *present in the source* — which is what
made the round look compliant. `check-tests-assert.sh` passed too, correctly: it detects `return`
-shaped skips and missing assertion macros, **not an assertion whose predicate can never be true**.
