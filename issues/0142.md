## Description

**M1 exit criterion served (guide §9, criterion 5):** "every engine function has tests that can
fail: each has a mutation recorded against a named test that dies under it."

Found by the M1 milestone review, 2026-08-07. `gitStatus` / `WorktreeStatusParser`
(`YardKit/Sources/YardGit/WorktreeStatus.swift`) has mutation evidence, but no mutation is recorded
against a **named** test anywhere in `issues/`:

- #0013 carries a 5-row mutation table whose "required" column names categories ("the rename
  test", "the non-UTF-8 test"), not test identifiers; its work log asserts "All five mutations now
  fail, each with a named killing test" without recording the names.
- #0113's work log records two mutations by count only ("dropping `u` records fails three tests,
  restoring the off-by-one fails eight").
- #0131's named tests pin the wire encoding of the result types, not the parser's behavior.

Candidate killing tests already exist in
`YardKit/Tests/YardGitTests/WorktreeStatusTests.swift` (e.g.
`renameOriginalPathDoesNotLeakAsItsOwnRecord`, `parsesSubmoduleState`,
`nonUTF8PathSurvivesAlongsideItsNeighbours`).

## Expected behavior

Each mutation from #0013's table is re-applied, the exact test(s) that go red are named, the
mutation is reverted, and the mutation-to-named-test table is recorded in this issue's work log.
Any mutation that turns out not to die under a named test gets a test that kills it.
