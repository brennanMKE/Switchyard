## Description

**M1 exit criterion served (guide §9, criterion 5):** "every engine function has tests that can
fail: each has a mutation recorded against a named test that dies under it."

Found by the M1 milestone review, 2026-08-07. `gitStatus` / `WorktreeStatusParser`
(`YardKit/Sources/YardGit/WorktreeStatus.swift`) has mutation evidence, but no mutation is recorded
against a **named** test anywhere in `issues/`:

- #0013 carries a 5-row mutation table whose "required" column names categories ("the rename
  test", "the non-UTF-8 test"), not test identifiers; its work log asserts "All five mutations now
  fail, each with a named killing test" without recording the names.
- #0113's work log records two mutations by count only ("dropping `u` records fails three tests,
  restoring the off-by-one fails eight").
- #0131's named tests pin the wire encoding of the result types, not the parser's behavior.

Candidate killing tests already exist in
`YardKit/Tests/YardGitTests/WorktreeStatusTests.swift` (e.g.
`renameOriginalPathDoesNotLeakAsItsOwnRecord`, `parsesSubmoduleState`,
`nonUTF8PathSurvivesAlongsideItsNeighbours`).

## Expected behavior

Each mutation from #0013's table is re-applied, the exact test(s) that go red are named, the
mutation is reverted, and the mutation-to-named-test table is recorded in this issue's work log.
Any mutation that turns out not to die under a named test gets a test that kills it.

## Mutations recorded — run by the reviewer 2026-08-07

The criterion asks for a mutation recorded against a **named** test that dies under it. Each row below
was applied to `YardKit/Sources/YardGit/WorktreeStatus.swift`, the **full** suite run, the file
restored, and the tree verified clean afterwards. The suite's verdict comes from the
`Test run with N tests` line, not from name extraction — see the note at the end.

| # | mutation | verdict | named test(s) that died |
|---|---|---|---|
| R1 | `State.special(char:)` `"u"` → `.unmodified` | RED | *"all five porcelain v2 record types are parsed with exact paths"*; *"WorktreeStatusEntry.State initialisers are public"* |
| R2 | `State.special(char:)` `"?"` → `.unmodified` | RED | *"all five porcelain v2 record types are parsed with exact paths"*; *"refuses to remove a dirty worktree without force"* |
| R3 | `State.special(char:)` `"!"` → `.unmodified` | RED | *"all five porcelain v2 record types are parsed with exact paths"*; *"WorktreeStatusEntry.State initialisers are public"* |
| R4 | `State.init?(ychar:)` `"u"` → `.untracked` | **GREEN** | none — **unobservable** |

**R2 is worth noting for a reason beyond this issue:** it kills a test in a different area entirely,
*"refuses to remove a dirty worktree without force"*. `WorktreeRemove`'s dirty-detection reads the
status parser, so the `?` mapping is load-bearing for worktree removal as well as for `status`. That
coupling was not visible from either issue alone.

## The finding: `State.init?(ychar:)` is unreachable

R4 changes the `"u"` case of `init?(ychar:)` and **nothing fails**. `grep -rn "ychar" Sources/YardGit/`
returns only the declaration itself — **no caller anywhere in the engine**. It is dead code, which is
why no mutation of it can be observed.

That is the honest answer to this issue's criterion for that initialiser: it has no mutation-covered
test because it has no reachable behaviour. **Deleting it, or wiring it where the parser actually
handles the Y column, is a separate change and belongs in its own issue** — this one records
measurements and must not smuggle in a deletion.

## A note on how these were measured

Four attempts at the mutation harness were wrong before this one, and each failed *silently* in a
different way:

1. `continue` inside a `switch` that is not in a loop — a **compile error** I first read as "no test
   failed".
2. Extracting names with `✘ Test [A-Za-z0-9_]+` — matched the word `run` from the summary line
   *"Test run with 530 tests failed"*, so a real failure was reported as the test named `run`.
3. Requiring an identifier before `(` — these tests use **quoted display names**
   (`@Test("all five porcelain v2 record types…")`), so nothing matched and a genuinely red suite was
   reported as **GREEN**.
4. Only then: verdict from the `Test run with` summary line, names from `✘ Test "…"`.

The rule that survives: **decide pass/fail from the summary, never from whether a name was
extracted.** An empty name list means the parser failed, not that the suite passed.
