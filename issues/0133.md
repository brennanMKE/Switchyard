## Description

Apply #0129's settled wire pattern (Decisions 1–8) to the log and graph payloads:

| type | source file | traps |
|---|---|---|
| `CommitLogEntry`, `Trailer`, `SignatureStatus` | `YardKit/Sources/YardGit/CommitLog.swift` | `CommitLogEntry` is `Equatable` only — it needs `Sendable` added (public structs get no implicit `Sendable` across module boundaries; verify by compiling at planning time). `Trailer` is already `Sendable`. |
| `GraphRow` | `YardKit/Sources/YardGit/LaneAssignment.swift` | already `Sendable`; all four members simple |

The delicate one is **`SignatureStatus`: it has no raw type — #0127 settled that deliberately —
so its wire string is declared, not derived** (#0129 Decision 5): an explicit `encode(to:)` with
a single-value container encoding the case-name string (`"noSig"`, `"good"`, `"goodUntrusted"`,
`"bad"`, `"expiredSignature"`, `"expiredKey"`, `"revokedKey"`, `"cannotCheck"`, `"unknown"`),
pinned case-by-case with a literal test so no case can be added without a wire decision.

Other decisions landing here: `Trailer` encodes as `{"key":…,"value":…}`; `CommitLogEntry`'s
computed `subject` / `shortOid` / `hasProvenance` are not encoded (Decision 7); empty `parents`
and `trailers` encode as `[]`.

## Expected behavior (re-author to code level before dispatch, per CLAUDE.md)

      pre-change baseline by exactly the number of new tests, both counts settled and stated at
      planning time.
