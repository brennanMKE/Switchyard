## Description

**Finding 1 of the M1 milestone review, fourth pass, 2026-08-18.** M1 exit criterion 5 is unmet for
`WorktreePrune.runPrune`: **`GCResult.pruned`'s contents are never asserted**, only its emptiness.

`YardKit/Sources/YardGit/WorktreePrune.swift:157-159` trims the trailing empty line git leaves behind.
Two independent mutations survived the **full, unfiltered** suite:

| mutation | result |
|---|---|
| replace 157-159 with `return lines` (drop the trim) | `Test run with 1066 tests in 78 suites passed after 59.703 seconds` |
| `return Array(lines[lines.startIndex..<idx]).map { _ in "" }` (erase every line's content) | `Test run with 1066 tests in 78 suites passed after 64.261 seconds` |

**The first is a real wire defect, measured.** `git worktree prune -v` writes diagnostics to stderr
terminated by `\n` — confirmed with `od -c` on a live fixture:

```
0000060    -   e   x   i   s   t   e   n   t       l   o   c   a   t   i
0000100    o   n  \n
0000103
```

`split(separator: "\n", omittingEmptySubsequences: false)` therefore always yields a trailing `""`, and
the trim loop is the only thing removing it. Without it, `GCResult.pruned` ships
`["Removing worktrees/x: …", ""]` — **a spurious empty string in the `pruned` array of a
`schemaVersion: 1` envelope, on every successful `wt gc --prune`.**

The second mutation shows the gap is wider than one edge case. Every assertion in the suite is
emptiness-only: `#expect(result.pruned.isEmpty, …)` at `WorktreePruneGcTests.swift:81, 116, 200, 272`
and `#expect(!pruned.isEmpty, …)` at `185, 276`. `GcResultWireTests` pins the wire bytes but builds
`pruned:` from a **literal**, so it exercises the encoder, not `runPrune`.

Same shape as #0245, #0247, #0259 and #0262: *a field only ever asserted at its zero value*, so the
production code shaping its non-zero value is free to be wrong.
