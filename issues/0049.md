# 0049 — Implement SMAppService registration with repair-on-failure

| | |
|---|---|
| **Status** | open |
| **Module** | Switchyard |
| **Milestone** | M3 |
| **Platform** | macOS |
| **First seen** | 2026-08-06 |

## Description

Register the embedded launch agent as a login item so launchd owns the Mach service name.

**`SMAppService.status` can disagree with launchd.** Drive repair from an actually-failed broker
call, at most once per launch, rather than trusting the reported status — a status-driven repair loop
was a real source of confusion in RemoteControl.

## Expected behavior

- [ ] Registers on first launch and surfaces the "Requires approval" state with a link to Login Items.
- [ ] Repair is triggered by a failed broker call, not by `status`, and runs at most once per launch.
- [ ] The absence of an approval prompt is treated as success, not as a missing step.
- [ ] UI shows Mach service name, login-item status, endpoint registration, and client count.

## Notes

Guide §4 "XPC transport". Port from RemoteControl. Blocked by #0047.

**Keep exactly one copy of the built app on disk** — a DerivedData copy plus one in `/Applications`
confuses launchd's registration.
