## Description

Commits in a range with parents, refs, signature status, and trailers. Trailers matter because agent
provenance rides in them (#0038), and `--agent-only` filtering depends on parsing them properly.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/CommitLog.swift`. Create it; do not restructure existing files.
- [ ] Range syntax matches git's (`A..B`, `A...B`, single rev, `--limit`).
- [ ] Each commit reports parents, decorating refs, signature status, and parsed trailers.
- [ ] `--agent-only` filters to commits carrying `Agent-Name` trailers.
- [ ] Merge commits report all parents, in order.
- [ ] Tested against both ref formats.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N must be greater than 176.

## Review — round 1 failed on tool mechanics, not on judgment

Killed at the 1800s cap having produced **nothing**: exit 7, empty working tree, no
`CommitLog.swift`, no tests.

**The design was right.** The log shows the exploration phase completed properly — the issue,
`Issues.md`, `AGENTS.md`, `GitProcess.swift`, `FixtureRepository.swift`, `provenance.md` — and the
model independently arrived at the requirement this issue turns on: an explicitly delimited machine
format. It specified `%x01` as the field separator with `%H %P %D %G?` and
`%(trailers:only,…)`, and planned `SignatureStatus`, `Trailer`, `CommitLogEntry`, `AgentProvenance`
and `CommitLog.run(rangeArguments:agentOnly:)`. **None of that needs redoing.**

**It never wrote a single file.** Every attempt failed with:

```
Error: The write tool was called with invalid arguments: SchemaError(Missing key at ["content"]).
```

**188 times**, continuously, for roughly 25 minutes, until the timeout killed it. It emitted a `write`
call carrying `filePath` and no `content`, was told the input was invalid, and produced the identical
malformed call again.

### For round 2

1. **Never retry a tool call that just failed the same way.** `AGENTS.md` Rule 5 already says a clear
   stop beats a third attempt; this is that rule applied to tool mechanics rather than to shell
   commands.
2. **If `write` fails twice on the same file, create it with a shell heredoc instead** —
   `cat > path/File.swift <<'EOF' … EOF` — then edit normally. That path does not go through the
   failing schema.
3. **Build the file incrementally.** Both rounds that have locked up this way were writing a large
   new file in one shot. Write the type declarations first, verify with `swift build`, then add
   methods. A partial file that compiles is recoverable; a 300-line write that never lands is not.
4. The design in round 1's log is sound — reuse it rather than re-deriving it.

Nothing about this issue's text is at fault. It passed all eight preflight checks, names one source
file, states a baseline, and the model demonstrably understood it.
