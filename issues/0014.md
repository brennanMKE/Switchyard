## Description

Commits in a range with parents, refs, signature status, and trailers. Trailers matter because agent
provenance rides in them (#0038), and `--agent-only` filtering depends on parsing them properly.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/CommitLog.swift`. Create it; do not restructure existing files.
- [ ] Range syntax matches git's (`A..B`, `A...B`, single rev, `--limit`).
- [ ] Each commit reports parents, decorating refs, signature status, and parsed trailers.
- [ ] `--agent-only` filters to commits carrying `Agent-Name` trailers.
- [ ] Merge commits report all parents, in order.
- [ ] Tested against both ref formats.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N must be greater than 176.

### For round 2

1. **Never retry a tool call that just failed the same way.** `AGENTS.md` Rule 5 already says a clear
   stop beats a third attempt; this is that rule applied to tool mechanics rather than to shell
   commands.
2. **If `write` fails twice on the same file, create it with a shell heredoc instead** —
   `cat > path/File.swift <<'EOF' … EOF` — then edit normally. That path does not go through the
   failing schema.
3. **Build the file incrementally.** Both rounds that have locked up this way were writing a large
   new file in one shot. Write the type declarations first, verify with `swift build`, then add
   methods. A partial file that compiles is recoverable; a 300-line write that never lands is not.
4. The design in round 1's log is sound — reuse it rather than re-deriving it.

Nothing about this issue's text is at fault. It passed all eight preflight checks, names one source
file, states a baseline, and the model demonstrably understood it.

### Round 3 is a repair. Do not restructure, do not rewrite.

`CommitLog.swift` is on disk and **its design is sound** — the `%x01` format string, `SignatureStatus`,
`Trailer`, `CommitLogEntry` are all the right shape. Keep them. Fix these, in this order, running
`swift build` after **each** one:

1. **Fill in every `{ ... }` placeholder body.** Search the file for `{ ... }` — each is an unwritten
   implementation, not a syntax quirk.
2. **Delete the duplicate declarations** of `subject`, `shortOid` and `hasProvenance`. Keep one of
   each.
3. **Remove the second `--format` argument.** There are **four** occurrences of the string
   `--format` in the file; two are doc comments (lines 8 and 92) and must stay. The two that matter
   are the real argument sites: `formatString` at line 114, which is correct and stays, and line 136,
   which must go. `run()` does:
   ```swift
   if options.contains(.agentOnly) || true { args += ["--format=%B"] }
   ```
   `|| true` makes that unconditional, and **git honours the last `--format` on the command line** —
   so the `%x01` format is silently discarded and only `%B` ever reaches the parser. The whole
   delimited-format design is defeated by this one line. Delete it; there must be exactly one
   `--format`.
4. **Make the `switch parts.count` exhaustive**, and guard `parts[0]` / `parts[1]` rather than

5. **Delete `@_exported import FoundationNetworking`** — Linux-only, and this is a macOS-only package.
6. `Trailer.value` is assigned at line ~259 but declared `let`. Make it `var` or build the value
   before construction.
7. Remove the unused `let trimmed` around line 163, and `case between(OpenClosedRange<String>)` —
   there is no such type.

**The signature takes a path and a `GitProcess`,** like every other engine function here:

## Review — round 4, and the round-3 failure was my fault

**Round 3 fixed the build.** Zero compile errors, down from 35. No `{ ... }` placeholders, exactly one
`--format`, no `FixtureRepository` in production. That part is done and stays.

**Then it followed my instruction off a cliff.** Round 3's review said *"`formatString` at line 114 is
correct and stays"* and *"delete line 136"*. But `formatString` is:

```swift
static let formatString = "--format=%H\u{01}%P\u{01}%G?\u{01}%D"
```

There is **no `%B`** in it. Deleting the second `--format` removed the only source of message text, so
subject and trailers can never work. The model did exactly what it was told. This round is being
dispatched with `--force` past the 3-round cap because the cap exists to stop tasks that are not
converging, and this one was misdirected rather than failing.

### 1. The format string, exactly

```swift
static let formatString = "--format=%H\u{01}%P\u{01}%an\u{01}%G?\u{01}%D\u{01}%B%x00"
```

Six fields, then the raw body, then a **NUL record terminator**. `%B` must be last because it is the
only field that can contain the field separator's neighbours — newlines and blank lines — and `%x00`
is what makes multi-record output unambiguous.

### 2. `parse` must split on NUL, then on `\u{01}`

Round 3 splits on `_Delimiter.commit = "\n\n"` and then takes only
`group.split(separator: "\n").first`, so it returns **at most one entry, always**. Verified: a
four-commit repository returned `entryCount=1`.

The correct shape:

- split the whole output on `\u{0}` — each non-empty piece is one commit record;
- split each record on `\u{01}` into exactly **6** parts: oid, parents, author, signature flag, refs,
  body;
- `parents` is space-separated and may be empty (root commit) or hold two entries (merge);
- everything after the fifth separator is the body **verbatim, including newlines and blank lines**.
  Do not trim it, do not take `.first`.

### 3. `CommitLogEntry` needs `author` and `message`

Neither exists today, so the non-ASCII-author requirement is untestable and the multi-line-message
requirement is unmeetable. Add both as `public let`. `subject` becomes the first line of `message`.

### 4. `Trailer.parse` rejects every real trailer

Line 41 caps the key at four characters:

```swift
trimmed.distance(from: trimmed.startIndex, to: colon) <= 4
```

`Agent-Name` is 10, `Signed-off-by` is 13. Both return `nil`. Replace the length cap with the actual
rule: **a trailer key contains no whitespace.** Verified failing:
`Trailer.parse("Agent-Name: ornith") = nil`.

### 5. `case "G"` is unreachable

`switch ch.lowercased()` then `case "G"` can never match, so an invalid signature reports `.valid`.
Switch on the raw character instead of lowercasing.

### 6. Tests — the part round 3 skipped entirely

`try #require` appears **zero** times in the test file, and `trailers[0]` at line 103 crashes the whole
test binary with `Fatal error: Index out of range`, signal 5. A trap destroys the run summary; a
failed assertion is just a failing test.

Required, each against a fixture built under `build/`:

- a **multi-line** commit message, asserting the newlines survive verbatim — this is what the whole
  delimited format exists for;
- a message containing a **blank line**, asserting the blank line survives;
- a **merge commit**, asserting two parents;
- a **non-ASCII author**, asserting the name round-trips;
- a commit with `Agent-Name:` and `Signed-off-by:` trailers, asserting both parse.

Every test `throws`, uses `try`, never `try!`, and uses `try #require` before any subscript.
