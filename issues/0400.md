# 0400 — Label every local branch at its tip in the graph so branches are browsable

## Description

Brennan: *"What we want is all available local branches to be easy to browse."* Today a branch
name appears only as a small ref chip inside the commit row's text, and the rows are what #0399
removes. With the text gone, the graph needs its own way to name branches.

The reference is the GitUp screenshot attached to #0399 (`issues/0399/gitup-batty.png`): each
local branch's tip carries its name as a label above its lane, and the labels run across the top of
the map. Clean-room rules apply, as in #0399: work from the screenshot and this description only.

## Expected behavior

- [ ] Every local branch (`refs/heads/*`) is labelled at the node of its tip commit in the graph,
      and the label shows the branch name.
- [ ] Labels for several branches at the same tip don't overlap: they stack or combine.
- [ ] The current branch's label is visually distinct (HEAD). A remote-tracking ref at its own
      commit gets a secondary style, like `origin/main` in the screenshot.
- [ ] Clicking a label selects that branch's tip commit, the same as clicking the branch in the
      sidebar (#0401).

## Notes

On Batty that is 127 branches. The planning pass has to measure whether labels at tips stay
legible at that count with the current lane layout (`graphRows`), or whether the lane layout
itself needs to change to give each branch its own column, as in the screenshot. If it needs the
layout change, split that out as its own issue.
