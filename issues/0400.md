## Description

Brennan: *"What we want is all available local branches to be easy to browse."* Today a branch
name appears only as a small ref chip inside the commit row's text, and the rows are what #0399
removes. With the text gone, the graph needs its own way to name branches.

The reference is the GitUp screenshot attached to #0399 (`issues/0399/gitup-batty.png`): each
local branch's tip carries its name as a label above its lane, and the labels run across the top of
the map. Clean-room rules apply, as in #0399: work from the screenshot and this description only.

## Expected behavior

- [ ] Every local branch (`refs/heads/*`) is labelled at the node of its tip commit in the graph,
      and the label shows the branch name.
- [ ] Labels for several branches at the same tip don't overlap: they stack or combine.
- [ ] The current branch's label is visually distinct (HEAD). A remote-tracking ref at its own
      commit gets a secondary style, like `origin/main` in the screenshot.
- [ ] Clicking a label selects that branch's tip commit, the same as clicking the branch in the
      sidebar (#0401).

## Notes

On Batty that is 127 branches. The planning pass has to measure whether labels at tips stay
legible at that count with the current lane layout (`graphRows`), or whether the lane layout
itself needs to change to give each branch its own column, as in the screenshot. If it needs the
layout change, split that out as its own issue.

## Re-plan (planning update, 2026-09-22, after #0399 and #0405)

**What #0399 and #0405 already deliver:**
- #0405 loads 5,000 commits, so every Batty branch tip is in the graph.
- #0399 leaves the ref chips as the only text in a row, one chip per branch, remote or tag, at
  its tip commit.
- The HEAD chip is already distinct (`RefChipView`: semibold, filled checkmark), and a remote chip
  is dashed.
- Clicking a chip clicks its row, which selects the tip.

**What's left, from a look at the #0399 branch on Batty:** every chip starts at the gutter's
right edge (`HStack { LaneGutterView(width: gutterWidth); chips }`), not beside its own node. With
Batty's lanes, a label can sit a hundred points or more from the dot it names. This issue anchors
each row's chips just right of that row's node. The chips then draw over any lanes further right,
so they get an opaque backing.

**Clean-room:** this is our own layout decision, taken from the screenshot's visible behaviour
(the label sits by its lane). It is not derived from GitUp's source.

### Files and literal changes

**`YardKit/Sources/YardUI/LaneGeometry.swift`**: add below `xOffset(forLane:)`:

```swift
    /// #0400: where a row's ref chips start -- just right of that row's own
    /// node, so a branch label sits beside the commit it names rather than
    /// at the gutter's far edge.
    public static func labelLeading(forLane lane: Int) -> CGFloat {
        xOffset(forLane: lane) + nodeRadius + 6
    }
```

**`YardKit/Sources/YardUI/CommitHistoryView.swift`**

1. In `CommitHistoryRow.body`, replace the `HStack(alignment: .center, spacing: 4) { … }` that
   holds `LaneGutterView(...)`, the chips' `ForEach` (with its `.opacity`) and `Spacer(minLength: 0)`
   with this `ZStack`. Keep every modifier that follows it (`.frame(height:)` and the
   accessibility modifiers) unchanged:

```swift
        ZStack(alignment: .leading) {
            LaneGutterView(row: graphRow, segments: segments, owners: owners, localOids: localOids,
                           isHead: isHead, width: gutterWidth)
            // #0400: the chips start beside this row's node, over any lanes
            // to its right; RefChipView's opaque backing keeps them legible.
            HStack(spacing: 4) {
                ForEach(chips, id: \.self) { chip in
                    RefChipView(chip: chip, tint: BranchColor.color(for: chip))
                }
            }
            .opacity(isRemoteOnly ? 0.6 : 1)
            .padding(.leading, LaneGeometry.labelLeading(forLane: graphRow?.lane ?? 0))
        }
        .frame(maxWidth: .infinity, alignment: .leading)
```

2. In `RefChipView.body`, directly after the existing `.background { switch chip.kind { … } }`
   block, add an opaque backing behind it:

```swift
            // #0400: chips can sit over lanes to their right; an opaque
            // capsule behind the tint keeps the name legible.
            .background(Capsule().fill(.background))
```

**`YardKit/Tests/YardUITests/LaneGeometryTests.swift`**: append:

```swift
@Test("a row's labels start just right of that row's own node (#0400)")
```
