## Description

**Finding of #0160's ninth umbrella review, 2026-08-18.** The composed rewrite mapping's `source` is an
unpinned decision.

`YardKit/Sources/YardGit/JournalEntryMetadata.swift:197`, inside `RewriteMapping.composing(with:)`:

```diff
- return RewriteMapping(source: next.source, rewrites: composedRewrites + unconsumed)
+ return RewriteMapping(source: source,      rewrites: composedRewrites + unconsumed)
```

`Test run with 1104 tests in 78 suites passed after 64.139 seconds.` — **full suite, unfiltered.**

**The decision it inverts is stated in that function's own doc comment**: *"`source` becomes
`next.source`: the newest invocation is authoritative, the same rule `JournalObserved` already applies
to the foreign path's final invocation."* Nothing enforces it.

**Measured on the real `Fixup.run` existing-commit path**, three genuinely logged `post-rewrite`
invocations replayed in order — the flow
`attachingAnExistingCommitFixupMappingKeepsThePreCheckpointHeadReachable` already stands up:

```
unmutated  PROBE composed.source=rebase
mutated    PROBE composed.source=amend        (test still passes)
```

So one `switchyard fixup` against an existing commit stores its mapping labelled `amend` when the
authoritative invocation was the `rebase`. **The composed mapping is the only mapping a
multi-invocation operation stores**, so this is the label that survives.

**Why this is the one gap and not a general complaint:** the **single**-attach source *is* pinned —
hardcoding `"amend"` in `attachRewrite` kills `attachingAnOwnFixupRebaseMappingLandsOnTheInFlightEntry`
— and the **foreign** half's source is pinned byte-exactly. The composed own-path source is the only
place the same field is unguarded.
