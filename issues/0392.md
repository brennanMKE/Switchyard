### Measured refusals and outcomes (`git tag`)

git 2.50.1, 2026-09-12, scratch repositories with `GIT_EDITOR=false` and no global config.

| Situation | git's behaviour | This wrapper |
|---|---|---|
| create a name that exists | exit 128 `fatal: tag 'v1' already exists` | `.tagExists(name:)`, before mutation |
| create an invalid name (`bad name`) | exit 128 `fatal: 'bad name' is not a valid tag name.` | `.invalidName(name:)`, before mutation |
| `check-ref-format refs/tags/<n>` | accepts `v1.0` and **`-x`**; refuses `bad name`, `a..b`, `x.lock` | also refuse a leading `-`, so a name can never be read as an option |
| create at an unknown target | exit 128 `fatal: Failed to resolve 'nosuch' as a valid ref.` | `.unknownRevision(_:)`, before mutation |
| annotated `git tag -a -m ann v2 HEAD~1` | exit 0; `git cat-file -t v2` = `tag` | `.annotated(message:)` |
| delete | exit 0 `Deleted tag 'v1' (was 195a90b)` | `Result` |
| delete a missing tag | exit 1 `error: tag 'v1' not found.` | `.unknownTag(name:)`, before mutation |
| `tag.gpgSign=true`, **lightweight** `git tag light` | exit 1 `error: there was a problem with the editor 'false'` — git turns it into an annotated tag and asks for a message | always pass `--no-sign` for lightweight tags (*measured*: `tag --no-sign light` → exit 0, type `commit`) |
| `tag.gpgSign=true`, annotated, signing broken (`gpg.program=false`) | exit 128 `error: gpg failed to sign the data:` | `.signingFailed(reason:)` |
| `-s -m`, signing broken | exit 128, the same message | `.signingFailed(reason:)` |
| `tag.gpgSign=true`, `--no-sign -a -m` | exit 0, unsigned | explicit `.noSign` |

*Measured* `git tag -h`: `-s, --[no-]sign  annotated and GPG-signed tag`, `-a, --[no-]annotate`,
`-m, --message`.

**Signing follows #0060's explicit-flag rule**, with one difference: `CommitCreate.signingInEffect`
reads commit signing configuration, while tags use `tag.gpgSign`. So for `.config`, read `tag.gpgSign`
(`git config --type=bool --get tag.gpgSign`, *not measured*), then pass `-s` or `--no-sign`
explicitly. `.sign` → `-s`; `.noSign` → `--no-sign`. When signing is in effect, use
`GitProcess.signingTimeout`.

### Surface — `YardKit/Sources/YardGit/Tags.swift` (new, *not compiled*)

```swift
public enum Tags {
    public enum Kind: Equatable, Sendable {
        case lightweight
        case annotated(message: String)
    }

    public struct Result: Sendable, Equatable, Encodable {
        public let name: String
        /// The ref's value: the commit for a lightweight tag, the tag object for an annotated one.
        public let oid: String
    }

    public static func create(name: String, target: String = "HEAD", kind: Kind,
                              signing: CommitCreate.Signing = .config, at path: String,
                              git: GitProcess = GitProcess(), extraEnvironment: [String: String] = [:]) throws -> Result
    public static func delete(name: String, at path: String,
                              git: GitProcess = GitProcess(), extraEnvironment: [String: String] = [:]) throws -> Result
}

public enum TagError: Error, Equatable, Sendable, CustomStringConvertible {
    case invalidName(name: String)
    case tagExists(name: String)
    case unknownTag(name: String)
    case unknownRevision(String)
    case emptyMessage
    case signingFailed(reason: String)
}
```

`.signingFailed` maps to `.signingFailed`; everything else to `.repositoryError`. Operations run
inside `JournalCheckpoint.around`, with operation names `tag-create` and `tag-delete`. A lightweight
tag is never signed; `signing` applies only to `.annotated`.

**Undo** is the question #0391 records: `undo` of a delete writes the tag's recorded value back (the
tag object's id for an annotated tag, which stays in the object database), while `undo` of a create
leaves the tag, under guide §11 decision 20. The decision there applies here too.

## Expected behavior

- [ ] `Tags.create` (lightweight and annotated) and `Tags.delete` each run inside one journal
      checkpoint; `delete` is exactly undone by `JournalUndo.undo`, and create's undo follows #0391's
      decision.
- [ ] Every refusal in the table is typed and raised before mutation, and a lightweight tag is created
      correctly with `tag.gpgSign=true`.
- [ ] Signing uses the explicit flag, with a broken signer yielding `.signingFailed`. Tests live in
      `YardKit/Tests/YardGitTests/TagsTests.swift`; `swift test` prints `Test run with N tests`.
