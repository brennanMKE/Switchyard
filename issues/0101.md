# 0101 — Decide whether switchyard's stdout is always JSON, or only under --json

|---|---|

## Description

**This is a decision for Brennan, not an implementation task.** Two documents currently read
differently, and every command written from here on inherits whichever answer is chosen.

`docs/switchyard-development-guide.md` §6 says:

> Every command has a `--json` mode, and agents are expected to use it. Human-readable output is the
> courtesy; JSON is the contract.

That phrasing makes `--json` a **mode** — so the default is human-readable and JSON is opt-in.

`CLAUDE.md` says `--json` on every command with `"schemaVersion": 1` in every response, and #0092 —
which is merged — emits a JSON envelope on **every** path unconditionally, with no flag parsing at
all. Verified: `yard`, `yard noop` and `yard bogus-command` all emit JSON today regardless of flags.

## Why it has to be settled now

`yard --help` is the case that forces it. Help text is inherently human-readable, so under
"always JSON" it has to be a JSON string containing the help — which is odd but consistent — while
under "JSON only with `--json`" it is plain text, and `yard --help --json` returns the structured
spec.

The answer also decides whether every future command needs two output paths or one, which is why it
is worth answering before #0012–#0020 are written rather than after.

## The options

**A — stdout is always JSON.** Simplest to implement and to test; a caller never has to know which
mode it is in, and the "stdout is JSON and nothing else" contract from #0091 holds unconditionally.
Cost: `yard --help` in a terminal prints JSON, which is unpleasant for the human user the courtesy
was meant for.

**B — human by default, JSON under `--json`.** Matches the guide as written and is the conventional
Unix shape. Cost: two output paths per command forever, and a class of bug where a command's human
and JSON paths disagree. The `--json` flag also has to be parsed before anything else can be decided.

**C — always JSON, except `--help` and `--version`.** A narrow carve-out for the two commands that
exist for humans. Keeps one output path for everything an agent actually calls.

## What to do

- [ ] Brennan picks A, B, or C.
- [ ] The choice is recorded in `docs/switchyard-development-guide.md` §11 as a settled decision.
- [ ] `CLAUDE.md` and the guide are reconciled so they no longer read differently.
- [ ] If B or C, file the follow-up to add flag parsing and adjust #0092's unconditional behaviour.

## Notes

Raised while writing #0088, which needs `yard --help` to do something specific and cannot proceed
past that point without an answer. #0088 is scoped to avoid the question — it renders help through
the existing envelope so it is correct under option A and a small change under B or C.

No implementation should guess at this. A wrong guess is cheap to fix in one command and expensive
once twenty commands have copied it.

## Decision — 2026-08-06

**Brennan chose option C: stdout is JSON on every command except `--help` and `--version`.**

Those two exist for humans and print plain text. Everything an agent actually calls emits a JSON
envelope unconditionally — no `--json` flag required, and no second output path per command to keep
in sync. `switchyard --help` stays readable in a terminal.

Recorded as settled decision 6 in guide §11. Consequences:

- #0092's unconditional-JSON behaviour is **correct as merged** for every command it handles; nothing
  about it needs revisiting.
- #0088 can render `--help` as plain text rather than wrapping it in an envelope. Its text was
  deliberately scoped to be a small local change either way, and that change is now known.
- No `--json` flag parsing is needed in M1. A `--json` variant of `--help` returning the structured
  spec may come later; nothing depends on it.
- The "stdout is JSON and nothing else" contract from #0091 holds for every command an agent calls,
  which is what makes it a contract rather than a convention.
