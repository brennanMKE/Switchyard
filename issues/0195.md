## Description

**Found by the M1 milestone review, 2026-08-17.** Verified by reading the source; not an M1 exit
criterion, so it was filed rather than reported as a finding.

`YardKit/Sources/YardGit/WorktreeRemove.swift:130` builds its error from a caught
`GitProcess.Failure` using `error.localizedDescription`:

```swift
.lockFailed(detail: error.localizedDescription)
```

**No engine error type conforms to `LocalizedError`** — they all use `CustomStringConvertible` — so
`localizedDescription` falls back to Foundation's generic rendering and the caller sees

```
The operation couldn't be completed. (YardGit.GitProcess.Failure error 1.)
```

instead of git's own message. Git's stderr, which is the only thing that explains *why* the removal was
refused, is discarded at exactly the point a user needs it.

## Expected behavior

- [ ] `WorktreeRemove.swift:130` uses `error.description` (or interpolates the failure directly), so
      git's stderr reaches the caller.
- [ ] A test asserting the detail contains something from git's real output rather than the Foundation
      fallback — drive a real failure (removing a worktree with a lock, which the existing fixtures
      already build) and assert on a substring of git's message.
- [ ] A mutation recorded as observed: put `localizedDescription` back and confirm the test dies.
- [ ] `swift test` prints a `Test run with N tests` line exceeding the count in
      `docs/test-baseline.txt` by exactly 1.

## Notes

Worth a grep for the same mistake elsewhere before writing the fix: `localizedDescription` on any
type that only conforms to `CustomStringConvertible` renders the same useless string. If there are
other sites, fix them in this issue and say so; if there are none, say that too.

**The grep is the part worth keeping.** It found two other `localizedDescription` call sites —
`GitProcess.swift:146` and `CommandLineRunner.swift:81` — and left both alone, because they catch
genuine `NSError`-backed Foundation throws where `localizedDescription` is exactly right. A round that
had "fixed" all three would have made two of them worse while looking thorough. The issue asked for a
sweep; what it needed was a sweep plus a distinction, and the round supplied the distinction.

The fixture is worth noting too: it forces a **real** failure by chmodding the worktree's private git
dir to `0o555` so `git worktree unlock` cannot unlink its `locked` file, measures git's actual stderr
first (`warning: unable to unlink '…/locked': Permission denied`), and restores the mode in a `defer`.
Asserting on a substring of a message git really printed is the difference between this test and one
that pins a string someone imagined.
