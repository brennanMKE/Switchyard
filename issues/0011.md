## Description

JSON is the contract; human-readable output is the courtesy. Agents break on inconsistent output
shapes far more often than on missing features, so the envelope is fixed once and versioned.

Every response carries `"schemaVersion": 1`. Failures in `--json` mode emit
`{"schemaVersion":1,"ok":false,"error":{"code":"…","message":"…","hint":"…"}}` **on stdout**, not a
bare string on stderr — an agent parsing stdout should never have to also parse stderr to find out
what went wrong.

## Expected behavior

- [ ] Envelope and error types live in `YardKit` and are used by every command.
- [ ] Exit codes match guide §6 exactly: 0 success, 1 usage, 2 broker unreachable, 3 app unavailable, 4 request failed, 5 session terminated, 6 repository error, 7 human declined, 8 blocked on conflicts, 9 signing failed.
- [ ] Codes 2–5 match RemoteControl and are not renumbered.
- [ ] Error codes are a closed enum, so an agent can branch on them.
- [ ] Tests assert the failure envelope goes to stdout and the exit code is set correctly.

## Review — round 1 rejected

Round 1 produced `Envelope.swift` (135 lines), `ExitCode.swift` (78) and `JsonEnvelopeTests.swift`
(200). `swift build` succeeds and **58 tests pass** — and the contract is still wrong. Green tests
are not evidence here, because the tests assert the wrong thing.

**Fix in round 2:**

1. **Exit codes 4 and 5 are swapped, and the tests bake the error in.** `ExitCode.swift` has
   `case sessionTerminated = 4` and `case requestFailed = 5`. Guide §6 and this issue both say
   **4 = request failed, 5 = app terminated the session**. `sessionTerminatedMatchesRemoteControl`
   expects 4 and `requestFailedMatchesRemoteControl` expects 5, so the suite passes while asserting
   the inverse of the contract. This breaks the "codes 2–5 match RemoteControl, do not renumber"
   criterion — the one thing about exit codes that is non-negotiable, because `yard` and `remotectl`
   must agree.

2. **The stdout/exit-code criterion is unmet.** Every test round-trips a struct through
   `JSONEncoder` in-process. Nothing captures stdout, spawns `yard`, or inspects a process exit
   status. The criterion says the failure envelope goes to **stdout** and the **exit code is set** —
   that needs a subprocess test, not an encoder test.

3. **Nothing uses it.** `Sources/yard/main.swift` is untouched, still the placeholder. The criterion
   is "used by every command"; right now it is used by none.

4. **Error codes are not a closed enum.** `EnvelopeError.code` is a free-form `String`, and the
   tests invent values (`"broken_lock"`, `"broker_error"`) that match no `ExitCode.codeLabel`. The
   criterion is explicit: a closed enum, so an agent can branch on it. A free string cannot be
   branched on safely.

5. **Scope violation — you edited `CLAUDE.md`.** 11 lines of workflow doctrine unrelated to this
   issue. That file is agent configuration, not issue work. It has been reverted on this branch.
   Per `AGENTS.md` rule 4: implement only what the issue asks for.

Keep the envelope's shape and the `schemaVersion` handling — those are right.

**Before claiming completion, run the tests and paste the `Test run with N tests` line.** Round 1's
log contains no such line; the run was cut off by a mistyped path (`brenbanMKE`), so no passing run
was ever observed, yet the round reported success.

## Review — round 2 rejected; issue is being split

Round 2 fixed the exit codes (`requestFailed = 4`, `sessionTerminated = 5`, with the tests corrected
to assert them) and added a real closed `EnvelopeErrorCode` enum. 64 tests pass, and unlike round 1
the log genuinely contains a passing run. That progress is kept.

**Three criteria remain unmet after two rounds, and a new defect was introduced:**

1. **`main.swift` is still the 12-line placeholder** — untouched in both rounds. Nothing uses the
   envelope.
2. **No subprocess test.** `envelopeFailWriteEmitsJsonToStdout` has a docstring claiming it replaces
   "stdout/stderr with pipes"; the body does a `JSONEncoder` round trip and never calls `write()`.
   The name asserts something the code does not do.
3. **`EnvelopeError.code` is still `String`.** The closed enum exists but is not the field's type, and
   `matchExitCode()` switches on raw strings with `default: fatalError`.
4. **New:** `StandardStream.stderr` calls `Swift.print`, which writes to **stdout**. `write()` emits
   `[error] <code>: <message>` to stdout *before* the JSON, so an agent parsing stdout gets a
   non-JSON prefix line — breaking the precise contract this issue exists to establish.

**Diagnosis: this issue is too large to delegate, same as #0010.** Two rounds failed on the *same*
sub-criteria — the wiring and the subprocess test were skipped both times — which is the signature of
an issue asking for too many separable things at once. A third round on the same text would most
likely reproduce it.

**Superseded by #0090–#0093.** Do not re-dispatch as written. Rounds 1 and 2 are committed on this
branch; the exit-code table and the closed enum are worth carrying forward, the stdout path is not.
