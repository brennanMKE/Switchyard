# 0350 — A typed refusal for staging a combined hunk

## Description

**Found by #0342's round, 2026-09-03.** Since decision 26 (guide §11), `HunkParser` parses `diff --cc`
combined blocks instead of dropping them, so a conflicted file's hunks are now **visible** in
`listHunks` listings with stable ids. Staging one is still refused — `git apply` does not accept
combined patches (measured: exit 128, "No valid patches in input"), so the all-or-none refusal keeps
conflicted content out of the index — but the failure surfaces as **git's own raw exit 128**, not a
typed `StagingError`. Before #0342 the refusal was `unknownHunkIDs` (typed) because the hunks were
invisible; now they are visible and the error is untyped.

The safety property holds (conflicted content cannot reach the index, all-or-none preserved); this
issue is about the error's shape, which an agent parses.

## Expected behavior

- [ ] `selectPatch` (or the staging entry point that assembles the patch) detects that a requested
      hunk id belongs to a combined (`diff --cc`) block and refuses with a **typed** error — e.g.
      `StagingError.combinedHunkNotStageable(path:)` — carrying the path and a detail string that
      says what the user should do instead (resolve the conflict; the hunk is not stageable).
- [ ] The refusal happens BEFORE `git apply` is invoked, so the error is ours, not git's.
- [ ] A test staging a conflicted file's hunk id asserts the typed error, replacing the current
      assertion on git's apply failure.
- [ ] Unstaging the same shape gets the same treatment if it shares the path.
- [ ] `cd YardKit && swift test` prints `Test run with N tests` with **N greater than 1305**, the
      count on main before this change. State the delta.

## Notes

The place is `selectPatch` in `YardKit/Sources/YardGit/Staging.swift`, not the parser — #0342's
report says exactly that. The combined blocks reach `listHunks` because `git diff` prints unmerged
paths as combined blocks during a conflict; the parser's verbatim policy (decision 26) is correct and
is not to be revisited here.
