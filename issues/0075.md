## Description

The clean-room process has a required artifact: when a GitUp idea informs a design decision, the
idea is written into `docs/` **in your own words**, and the implementation is written from that note
rather than from the source.

This is not paperwork. It is what makes "clean-room" a true description of the process rather than a
claim about intent, and it is the thing that would matter if the question were ever asked seriously.

## Expected behavior

- [ ] A note exists for the snapshot/undo model, written before #0027 is implemented.
- [ ] A note exists for graph lane assignment, written before #0015 is implemented.
- [ ] A note exists for the rebase engine scope (#0060).
- [ ] Each note is written from understanding, contains no GitUp code, and does not paraphrase its source line by line.
- [ ] Each note records the date and what was read to form the understanding.

## Notes

Guide §2. Blocks #0015, #0027, #0060.

GitUp is GPLv3 and Switchyard is MIT, which makes this stricter, not looser. Never paste GitUp
source into a context window and ask for a Swift port — that is a derivative work regardless of how
it is phrased.

## Fix

Three notes under `docs/clean-room/`, each written before the issue it gates, each recording the date
and what was read to form the understanding — so the sequence read → close → write → implement is
auditable rather than asserted.

- `snapshot-and-undo.md` (before #0027) — why undo restores captured state instead of inverting
  operations, which git primitives capture each piece, and the two places Switchyard deliberately
  differs from GitUp: snapshots that outlive the process, and a cross-tool guard.
- `graph-lane-assignment.md` (before #0015) — the lane algorithm's shape, the lane-compaction step
  whose absence produced 4,145 lanes in the spike, and the #0003 constraints it must respect.
- `rebase-engine-scope.md` (before #0060) — the hypothesis that a rewrite pipeline over
  `commit-tree` and `cherry-pick` replaces a rebase engine for every M5 command.

## Verification

Each note cites git's documented behavior, `docs/engine-findings.md` measurements, and GitUp's own
README — never GitUp source. No GitUp code or test data was copied, and the graph note states
explicitly that GitUp's fixtures are GPLv3 test data which must not be reused.

`docs/clean-room/README.md` records the process and the required-artifact rule, so the next person
writing a note follows the same sequence.

## Gotchas

**This issue cannot be delegated.** It is the clean-room boundary itself, and it is the one place
where a licensing error would look like ordinary Swift afterwards. It is listed under "What is not
delegated" in `issues/Issues.md`.

The rebase note's recommendation is a **hypothesis to test in #0060**, not a settled decision — it
says so, because a note that overstates its confidence would be implemented from as though it were
verified.
