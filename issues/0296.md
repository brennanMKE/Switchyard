## Description

**Finding 4 of the M1 milestone review, eighth pass, 2026-08-18, and the one with a cross-command
consequence.** `worktreeAdd` loses `--detach` undetected, and then `wt new` and `wt list` **disagree
about the same worktree**.

`YardKit/Sources/YardGit/WorktreeAdd.swift:204`, `["--detach", path, committish]` → `[path, committish]`:
full suite green, `Test run with 1103 tests in 78 suites passed after 90.544 seconds`.

**Measured against the engine**, `worktreeAdd(target: .detached(at: "docs"))` where `docs` is a branch:

```
pristine:  engineSuccess=true engineBranch=nil  actualDetached=true   actualBranch=nil
mutant:    engineSuccess=true engineBranch=nil  actualDetached=false  actualBranch="docs"
```

`wt new` reports a **detached** worktree — `branch: nil`, from the `.detached` arm at
`WorktreeAdd.swift:162` — while `wt list` reports the same worktree **attached to `docs`**. Two M1
engine functions describing one worktree differently, which is exactly the cost #0278 argued for an
unpinned path field. It also **silently claims the branch**, so a later `wt new <path> docs` is refused
with `fatal: 'docs' is already used by worktree`.

**Why nothing catches it, and this is the sharp part:** `detachedWorktreeHasNoBranch`
(`WorktreeAddTests.swift:159`) passes `.detached(at: base)` where `base` is a **raw SHA** — and git
detaches on a raw SHA *with or without* `--detach` (measured). **The fixture cannot produce the
distinguishing state even unmutated.** That is #0245's `includeIgnored` reasoning exactly.
`argumentsNeverContainForce` (`:298`) walks `.detached(at: "abc")` but asserts only the absence of
`--force` and the `["worktree","add"]` prefix.
