## Description

In the Changes view, select an unstaged file and press its row's **Stage** button. The file moves
to Staged Changes, but the diff pane drops to **"Select a file to see its changes"** and no row is
highlighted. The same happens in reverse with **Unstage**, and when **Stage Hunk** stages a file's
last hunk.

`WorkingChangesView.selection` names a path **and a side** (`FileSelection(path:staged:)`), and
`selectedRow` looks the path up on that side only:

```swift
    private var selectedRow: WorkingChanges.Row? {
        guard let selection else { return nil }
        return (selection.staged ? changes.staged : changes.unstaged)
            .first { $0.path == selection.path }
    }
```

After the refresh the path is on the other side, so `selectedRow` is `nil`.

### Measured (VM, 2026-09-30, throwaway hardening spike on the switch fixture)

The spike clicked `notes.txt` (unstaged), then its `stage-file-notes.txt` button.
`changesRow("notes.txt", staged: true)` appeared, then after 1 s
`text(containing: "Select a file to see its changes").exists == true`. Screenshot:
`issues/0569/0572-staged-file-blanks-diff.png`. Staged Changes (1) lists notes.txt, no row is
highlighted, and the pane shows the placeholder.

## The change — two files

### 1. `YardKit/Sources/YardUI/WorkingChanges.swift` — a pure helper

Add it inside `public nonisolated struct WorkingChanges`, directly after `isClean`:

```swift
    /// #0572: the side a selected file is shown on after a refresh — its
    /// own side while the path is still listed there, else the other side
    /// (a Stage or Unstage moved the whole file), else `nil` (it left both
    /// lists: committed, discarded, or conflicted).
    public func sideShowing(path: String, staged: Bool) -> Bool? {
        let own = staged ? self.staged : unstaged
        if own.contains(where: { $0.path == path }) { return staged }
        let other = staged ? unstaged : self.staged
        if other.contains(where: { $0.path == path }) { return !staged }
        return nil
    }
```

### 2. `YardKit/Sources/YardUI/WorkingChangesView.swift` — the selection follows its file

In `body`, the modifier chain ends with the `.sheet(isPresented: $showingStashSheet) { … }` block.
Append after it:

```swift
        // #0572: a Stage or Unstage that moved the selected file keeps it
        // selected, on the side it moved to, so its diff stays on screen.
        .onChange(of: changes) {
            guard let selection,
                  let staged = changes.sideShowing(path: selection.path, staged: selection.staged),
                  staged != selection.staged else { return }
            self.selection = FileSelection(path: selection.path, staged: staged)
        }
```

`WorkingChanges` is `Equatable` (checked), and the write happens in response to a refresh the
user started. It is not written from `body` or from a layout callback.

A file on **both** sides (one hunk staged) keeps its selection unchanged, as it does today.

## Verification

### Unit test — append to `YardKit/Tests/YardUITests/WorkingChangesTests.swift`

It uses that file's existing `entry(_:_:_:)` helper:

```swift
@Test func aSelectionFollowsItsFileToTheOtherSide() {
    let changes = WorkingChanges(status: WorktreeStatus(entries: [
        entry("both.txt", .modified, .modified),
        entry("staged.txt", .modified, .unmodified),
        entry("edited.txt", .unmodified, .modified),
    ]))
    // Still on its own side: stays.
    #expect(changes.sideShowing(path: "both.txt", staged: false) == false)
    #expect(changes.sideShowing(path: "both.txt", staged: true) == true)
    #expect(changes.sideShowing(path: "edited.txt", staged: false) == false)
    // Staged whole: selected as unstaged, now only staged.
    #expect(changes.sideShowing(path: "staged.txt", staged: false) == true)
    // Unstaged whole: selected as staged, now only unstaged.
    #expect(changes.sideShowing(path: "edited.txt", staged: true) == false)
    // Gone from both lists.
    #expect(changes.sideShowing(path: "committed.txt", staged: true) == nil)
}
```

Measured 2026-09-30 in a throwaway worktree with the helper applied: `Test run with 2 tests …
passed` (with `--filter "aSelectionFollows|JournalMenuRouting"`).

### VM spike — `SwitchyardUITests/0572StagedSelectionUITests.swift`, new

```swift
// 0572StagedSelectionUITests.swift
//
// #0572: staging the selected file keeps it selected — on the staged side,
// with its diff still on screen — instead of blanking the diff pane.

import XCTest

final class Spike0572StagedSelectionUITests: XCTestCase {
    @MainActor
    func testStagingTheSelectedFileKeepsItsDiff() {
        let app = XCUIApplication()
        app.launchWithSwitchFixture()
        let unstaged = app.changesRow("notes.txt", staged: false)
        XCTAssertTrue(unstaged.waitForExistence(timeout: 30), "notes.txt is not listed as unstaged")
        unstaged.click()
        let added = app.staticTexts["+local edit"]
        XCTAssertTrue(added.waitForExistence(timeout: 30), "the diff does not show notes.txt's edit")

        app.buttons["stage-file-notes.txt"].click()
        XCTAssertTrue(app.changesRow("notes.txt", staged: true).waitForExistence(timeout: 30),
                      "notes.txt was not staged")
        XCTAssertTrue(added.waitForExistence(timeout: 30),
                      "staging the selected file blanked its diff")
        XCTAssertFalse(app.text(containing: "Select a file to see its changes").exists,
                       "the diff pane fell back to its placeholder")
        XCTAssertTrue(app.buttons.matching(NSPredicate(
            format: "title == 'Unstage Hunk' OR label == 'Unstage Hunk'")).firstMatch.exists,
                      "the diff shown is not the staged side's")
        let shot = XCTAttachment(screenshot: app.windows.firstMatch.screenshot())
        shot.name = "0572-staged-diff-kept"
        shot.lifetime = .keepAlways
        add(shot)
    }
}
```

## Mutations the review runs

1. Make the helper's other-side line `return nil`. **Measured 2026-09-30**: the unit test fails
   at `sideShowing(path: "staged.txt", staged: false) == true` and at
   `sideShowing(path: "edited.txt", staged: true) == false`.
2. Delete the `.onChange(of: changes)` block. The unit test stays green, and the spike fails at
   "staging the selected file blanked its diff".

## Expected behavior

Stage or Unstage on the selected file, or staging its last hunk, keeps that file selected and
its diff on screen, now from the side it moved to.
