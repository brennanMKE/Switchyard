# 0161 — HunkParser: conflict-format lines must not corrupt neighbouring file diffs

| | |
|---|---|
| **Status** | open |
| **Module** | YardGit |
| **Milestone** | M2 |
| **Platform** | macOS |
| **First seen** | 2026-08-07 |

## Description

Two conflict-format lines in `git diff` output corrupt `HunkParser`'s per-file attribution, and one
of them breaks unstaging during a merge conflict. Both fixes are two small edits to
`YardKit/Sources/YardGit/Hunks.swift` plus three tests appended to
`YardKit/Tests/YardGitTests/HunksTests.swift`. **Both edits and all three tests are given verbatim
below and were compiled, run, and mutation-tested by the planner on 2026-08-07.** The round's work
is transcription plus running the verification.

The defect, measured: during a merge conflict, `git diff --cached` prints the line
`* Unmerged path m.txt` at the unmerged path's **sorted position** — which places it after the
block of any staged file sorting before it. The parser's catch-all appends it to that file's
`headerLines`, so `FileDiff.headerText` ends with the marker line, and the reconstructed patch
(`headerText + patchText`, the exact input hunk-level unstaging feeds `git apply --cached
--reverse`) is refused:

```
error: patch with only garbage at line 5
```

Second, plain `git diff` prints unmerged paths as **combined diffs** (`diff --cc m.txt`, `@@@`
headers). Measured twice with different path orderings, git emits every `diff --cc` block **ahead
of** every `diff --git` block, so today's parser — which opens files only on `diff --git ` — happens
to skip them safely. Correctness must not hang on that ordering: if a `diff --cc` block ever
followed an open file, its `--- a/m.txt` line would **overwrite the open file's path** (verified by
mutation MA2 below: the parsed path flips from `a.txt` to `m.txt`).

## Givens — each measured on this machine 2026-08-07, git 2.50.1 (Apple Git-155)

1. A conflict in `m.txt` (both sides edited the same line, `merge` left 3 unmerged index entries)
   plus a staged edit in `a.txt`. `git -c core.quotepath=false diff --cached --no-color
   --no-ext-diff --no-textconv --no-renames --default-prefix --unified=3` prints exactly:

   ```
   diff --git a/a.txt b/a.txt
   index 2cdcdb0..1c76fbc 100644
   --- a/a.txt
   +++ b/a.txt
   @@ -1,3 +1,3 @@
   -a1
   +a1 CHANGED
    a2
    a3
   * Unmerged path m.txt
   ```

2. Feeding that reconstruction back: a patch whose header block contains the
   `* Unmerged path m.txt` line fails `git apply --cached` with
   `error: patch with only garbage at line 5`. (A clean reconstruction applies.)

3. The same conflict seen by plain `git diff` (same flags, worktree edits in `a.txt` and `z.txt`):
   the `diff --cc m.txt` block prints **first**, before both `diff --git` blocks, even though
   `m.txt` sorts between them. Reproduced with the conflict in a first-sorting name too.

4. The full suite on a clean copy of this package prints `Test run with 554 tests in 35 suites`
   (`docs/test-baseline.txt` agrees at authoring time). With the three tests below appended it
   prints `Test run with 557 tests` — **+3 exactly**. In a `git archive` scratch copy the run line
   ends `failed … with 1 issue`: that is `ServiceNamesTests.bundleIdentifierMatchesXcodeProject`
   reading `project.pbxproj` outside the archive, present with and without these edits; in a real
   worktree the suite is green.

## The edits — `YardKit/Sources/YardGit/Hunks.swift`, exact before and after

**Edit 1.** In `parse(_:)`, directly after the `diff --git ` branch and before the
`guard file != nil` line. Before:

```swift
            if line.hasPrefix("diff --git ") {
                closeFile()
                file = FileBuilder(path: try Self.pathFromDiffGitLine(line),
                                   headerLines: [line])
                continue
            }
```

After:

```swift
            if line.hasPrefix("diff --git ") {
                closeFile()
                file = FileBuilder(path: try Self.pathFromDiffGitLine(line),
                                   headerLines: [line])
                continue
            }
            if line.hasPrefix("diff --cc ") {
                // A combined diff — an unmerged path. It has no stable ids
                // and is not stageable; close the open file so none of its
                // lines (`--- a/…`, `@@@ …`, `++<<<<<<<`) are mis-attributed
                // to a neighbouring file. Measured: git prints all `diff
                // --cc` blocks ahead of every `diff --git` block, but
                // correctness here must not depend on that ordering.
                closeFile()
                continue
            }
```

**Edit 2.** The catch-all at the end of the prefix chain. Before:

```swift
            } else if !line.isEmpty {
                // index lines, similarity scores, and anything else git adds.
                file?.headerLines.append(line)
            }
```

After:

```swift
            } else if line.hasPrefix("* Unmerged path ") {
                // `git diff --cached` prints this at the unmerged path's
                // sorted position, so it can land between two file blocks.
                // Appended to headerText it poisons the reconstructed patch:
                // measured, `git apply` refuses it with "patch with only
                // garbage". It belongs to no file; drop it.
            } else if !line.isEmpty {
                // index lines, similarity scores, and anything else git adds.
                file?.headerLines.append(line)
            }
```

A body line can never be mistaken for either marker: body membership is consumed by the header's
line counts before the prefix chain runs (Given 6 of #0016), and diff body lines begin only with
` `, `-`, `+`, or `\`.

## The tests — append to `YardKit/Tests/YardGitTests/HunksTests.swift`

Append at the end of the file (use `cat >>` or the edit tool — **never `cat >` onto this existing
file**, AGENTS.md Rule 5c):

```swift

// MARK: - Conflict-format lines

@Test func unmergedPathLineIsNotAppendedToThePreviousFilesHeader() throws {
    // Measured: `git diff --cached` during a merge prints `* Unmerged path
    // m.txt` at its sorted position — here after a.txt's block. Appended to
    // headerText, the reconstructed patch fails `git apply` with "patch with
    // only garbage at line 5".
    let text = """
    diff --git a/a.txt b/a.txt
    index 2cdcdb0..1c76fbc 100644
    --- a/a.txt
    +++ b/a.txt
    @@ -1,3 +1,3 @@
    -a1
    +a1 CHANGED
     a2
     a3
    * Unmerged path m.txt

    """
    let files = try HunkParser().parse(text)
    #expect(files.map(\.path) == ["a.txt"])
    let file = try #require(files.first)
    #expect(file.headerText == """
    diff --git a/a.txt b/a.txt
    index 2cdcdb0..1c76fbc 100644
    --- a/a.txt
    +++ b/a.txt

    """)
    #expect(file.hunks.count == 1)
}

@Test func combinedDiffBlockDoesNotCorruptAnOpenFile() throws {
    // Synthetic order: a `diff --cc` block after a `diff --git` block.
    // Measured git output puts all --cc blocks first, but the parser must
    // not depend on that: without a boundary here, the --cc block's
    // `--- a/m.txt` line would overwrite the open file's path.
    let text = """
    diff --git a/a.txt b/a.txt
    index 2cdcdb0..1c76fbc 100644
    --- a/a.txt
    +++ b/a.txt
    @@ -1,3 +1,3 @@
    -a1
    +a1 CHANGED
     a2
     a3
    diff --cc m.txt
    index abd82df,846f043..0000000
    --- a/m.txt
    +++ b/m.txt
    @@@ -1,1 -1,1 +1,5 @@@
    ++<<<<<<< HEAD
     +main version
    ++=======
    + side version
    ++>>>>>>> side

    """
    let files = try HunkParser().parse(text)
    #expect(files.map(\.path) == ["a.txt"])
    let file = try #require(files.first)
    #expect(file.hunks.count == 1)
    #expect(!file.headerText.contains("m.txt"))
}

@Test func combinedDiffFirstThenNormalFileParses() throws {
    // The order git actually emits (measured): every `diff --cc` block
    // precedes every `diff --git` block.
    let text = """
    diff --cc m.txt
    index abd82df,846f043..0000000
    --- a/m.txt
    +++ b/m.txt
    @@@ -1,1 -1,1 +1,5 @@@
    ++<<<<<<< HEAD
     +main version
    ++=======
    + side version
    ++>>>>>>> side
    diff --git a/z.txt b/z.txt
    index c1c940f..b759132 100644
    --- a/z.txt
    +++ b/z.txt
    @@ -1,3 +1,3 @@
    -z1
    +z1 CHANGED
     z2
     z3

    """
    let files = try HunkParser().parse(text)
    #expect(files.map(\.path) == ["z.txt"])
    #expect(files.first?.hunks.count == 1)
}
```

The diff literals are measured output; the test-source indentation inside the multiline strings is
load-bearing (a body line ` a2` keeps its leading space).

- Found while planning hunk-level staging: `unstageHunks` (follow-up issue in the #0040 family)
  reconstructs staged patches during conflicts, and without Edit 2 its round-trip fails with the
  exact garbage error in Given 2. That issue's mutation table re-verifies this dependency
  end-to-end.
- Sequencing: independent of #0040 (staging reads the **unstaged** listing, where the measured
  `diff --cc`-first ordering keeps today's parser safe); the unstage issue is blocked on this one.
- Conflicted files remain unlisted and unaddressable by hunk id — that is by design (#0016's
  recorded limitation), not something this issue changes. This issue only stops conflict-format
  lines corrupting *neighbouring* files.
