## Description

**Found by the #0034 umbrella review, 2026-08-17. This is a data-loss path, not a reporting gap.**

#0034's model says *"both kinds capture state identically"* and rests the redo rule on it: *"redo after
undo returns to the exact post-operation state — the first undo captured that state, and the final redo
restores those bytes."* That is true of refs and false of everything else.

`JournalCheckpoint.checkpoint` captures all three primitives (`JournalCheckpoint.swift:56-68`).
`JournalRestore.restoreAssumingLock` step 7 does not:

```swift
let checkpoint = try JournalCheckpoint.writeEntry(
    capturing: current,          // a RefSnapshot, and only that
    operation: operation,
    ...
```

`writeEntry`'s `index:` and `worktree:` default to `nil`, so `captured` becomes `refsOnly`. **That is
the call site every undo, every redo, and every explicit restore goes through.** The behaviour is
pinned by a passing test — `JournalRestoreTests.thePreRestoreEntryRecordsItsOperationAndKind:204`
asserts `undoMeta.captured == .refsOnly`.

**The concrete loss.** With staged and unstaged work present, `undo` restores the checkpoint's index and
worktree — overwriting that work — while the traversal entry it just wrote recorded neither. `redo` then
restores refs and `HEAD` and honestly reports `index`/`worktree`/`untracked` as `.notCaptured`. The work
is gone and no journal entry holds it. Identically, `restore <id>` clobbers the current index and
worktree and `report.checkpoint` cannot bring them back — which contradicts `JournalRestore.swift:47`,
*"restore is itself a mutation, so it is itself undoable."*

**Why seven green per-issue reviews left it standing.** #0171's Expected behavior describes capture for
the *checkpoint* flow only; #0188's literal change edits `checkpoint`'s `withLock` body and never
touches restore's `writeEntry` call. Every round-trip assertion around traversal compares `RefSnapshot`s
only — `undoRestoresTheCheckpointAndRedoReturnsByteExactly:93`,
`twoUndosThenTwoRedosReplayTheChainAndReturnToTheExactPresent:127`,
`restoreItselfIsUndoableThroughItsPreRestoreCheckpoint:121`. Nothing in `issues/` mentions it.

## Expected behavior

- [ ] `YardKit/Sources/YardGit/JournalRestore.swift` — `restoreAssumingLock` captures
      `IndexSnapshot`, `WorktreeSnapshot` and `SequencerSnapshot` alongside its existing step-3
      `RefSnapshot.capture` — **the same single "one capture, one truth" moment, before the guard** —
      and passes all of them to the `JournalCheckpoint.writeEntry` call at step 7, around line 298.
      No other production file changes: `JournalCheckpoint.writeEntry` already takes `index:`,
      `worktree:` and `sequencer:` parameters (#0171, #0188).
- [ ] A test in `YardKit/Tests/YardGitTests/UndoRoundTripSuiteTests.swift` that dirties **both** the
      index and the worktree, undoes, redoes, and compares `ls-files -s` bytes, tracked file contents,
      and the untracked list against the pre-undo state.
- [ ] A second test in that same file doing the same across an explicit `restore` followed by
      `restore(report.checkpoint.id)`, which is the claim in `JournalRestore.swift:47`.
- [ ] A mutation dropping `index:`/`worktree:` from the new call, **observed red** in both tests.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line where N is **greater than** the
      count in `docs/test-baseline.txt` by exactly 2. The delta is the criterion; read the baseline
      file rather than trusting any absolute written here.

## Notes

**Capture cost is already-settled policy**, not a new trade-off: `docs/journal-capture-policy.md` and
guide §11 decision 3 accepted it for `checkpoint`, and this makes restore consistent with it rather than
cheaper.

Sequence this **after #0188** (merged 2026-08-17), so the sequencer is available to capture at the same
moment. Note #0188's finding while writing the call: `SequencerSnapshot.keepAlive` returns **tree** oids
and must not go into the anchor's parents — reachability comes from tree embedding.

Also update #0034's decision 1 and 2 prose once this lands, since the "captures identically" claim
becomes true rather than aspirational.
