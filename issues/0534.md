## Description

Every diff in the app is drawn exactly one way: whitespace changes shown, three lines of context,
changed lines tinted whole. A re-indent buries the one real edit in it, a one-word change reads as a
whole replaced line, and there is no way to see more of the file around a hunk. Guide §11 decision
40 ranked whitespace and word-diff options third; the two ahead of it have shipped.

**Guide §11 decision 42** is the design. In short:

- **A Diff Options bar** over the diff in the Changes view, the commit changes window and the stash
  pane: a menu with **Ignore Whitespace**, **Highlight Changed Words** and **Context** (3 lines,
  10 lines, Whole File), and a line saying which options are on.
- **Ignore Whitespace is `git diff -w`** (`--ignore-all-space`), chosen over `-b` and
  `--ignore-space-at-eol` by measurement on git/git (decision 42 has the numbers). `-w` drops a
  whitespace-only file from the listing entirely, so each view keeps its standard file list and
  notes "Only whitespace changed in <path>".
- **Word highlights are computed in the app** from each hunk's own body (paired `-`/`+` runs of
  equal length, token diff), not by `--word-diff=porcelain`: 0.108 s for a 139,492-line git/git
  diff against porcelain's 0.454 s, and the hunk body — what staging sends — is never changed. On
  by default, app-wide.
- **Context** is `--unified=N` after the pinned `--unified=3` (git takes the last); Whole File is
  `--unified=2147483647`.
- **Staging and discarding act on the standard diff only.** The engine already guarantees it —
  staging re-lists with the pinned flags, and a filtered hunk id is refused by name (#0535 pins it
  with a test). The Changes view adds the visible half: with any option on, the hunk buttons are
  disabled, lines are not selectable, and the bar says "Hunks and lines can’t be staged or
  discarded" with **Reset**. File-level actions stay. Ignore Whitespace and Context are per view and
  not persisted, so disabled staging never outlives the look it was for.

## Questions for Brennan (the plan assumed an answer to each; none blocks a child)

1. **Ignore Whitespace and Context are not remembered** — per view, back to standard when the view
   goes (the Changes view resets after selecting a commit and coming back; each commit window starts
   standard). Assumed: this, because any non-standard option turns hunk staging off, and a
   remembered "whitespace hidden" would greet a later session with disabled buttons and changes it
   cannot see. The alternative is one app-wide `@AppStorage` like Highlight Changed Words. Want the
   options remembered?
2. **Highlight Changed Words is on by default** and app-wide (it also shows in the review sheet,
   the Resolve pane and rerere's detail, which draw through `FileDiffView`). Assumed on: it changes
   nothing but tint.
3. **The options live on a bar over the diff, not in the View menu**, and have no keyboard
   shortcuts. Menu items would need a focused-value route to whichever pane owns the diff.
   Assumed: the bar is enough for now. Want View ▸ Ignore Whitespace (and a shortcut)?
4. **Context choices are 3 lines, 10 lines and Whole File.** Whole File draws every line of the
   file in a non-lazy stack (`FileDiffView`'s `HunkView`); a very large file (git/git's
   `sequencer.c` is ~6,000 lines) was not timed in the app — the planning VM run used a 32-line
   file. Assumed: acceptable for now; if it is slow, a follow-up makes the hunk body lazy.
5. **Hunk and line staging is off (not remapped) while an option is on.** Assumed: this — a `-w`
   context line is the *new* text, so a filtered hunk does not correspond line for line to the
   standard one, and staging with the options fails (`git apply`: "patch does not apply",
   measured). File-level Stage/Unstage/Discard stay. More context alone *could* be staged if the
   engine took options too — want that later?
6. **No CLI flags in this pass** (`switchyard hunks` stays the standard listing). Assumed: the
   agent surface acts on hunk ids, which must be standard ones anyway.
