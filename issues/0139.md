# 0139 — wt gc engine result is a tuple and cannot encode to the v1 envelope

## Description

**M1 exit criterion served (guide §9, criterion 2):** "The engine behind each of `wt list`, `wt new`,
`wt rm`, `wt where`, `wt gc`, `wt repair` … returns a type that encodes to a `schemaVersion: 1`
envelope."

Found by the M1 milestone review, 2026-08-07. `WorktreePrune.gc` in
`YardKit/Sources/YardGit/WorktreePrune.swift` returns
`(reports: [Report], pruned: [String])` — a tuple. Tuples are non-nominal and cannot conform to
`Encodable`, so the full `wt gc` result cannot pass through `EncodableResult` into an `Envelope`.
Five of the six `wt` engine functions return a nominal encodable type; `gc` is the one that does not.

The existing wire test `envelopeWrapsPruneAndRepairPayloads` in
`YardKit/Tests/YardWireTests/MaintenanceWireTests.swift` wraps only `[Report]` — the `pruned` list
never rides an envelope, and no test could make it, because there is no type to encode. An agent
calling `wt gc --prune` needs both halves in one response: what was reported and what was actually
pruned.

## Expected behavior

`WorktreePrune.gc` returns a named result type (e.g. a `GcResult` struct carrying `reports` and
`pruned`) that is `Encodable & Sendable`, with a wire test in `YardWireTests` pinning its byte
shape and an envelope-wrap test, following the #0129 pattern. Existing callers and the four
`mutation*` tests in `WorktreePruneGcTests.swift` updated to the new shape and still green.
