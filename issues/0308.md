# 0308 — Decide whether SHA-256 repositories are supported

## Description

**A decision for Brennan, raised by the M1 milestone review's eleventh pass.** **Does Switchyard support
SHA-256 repositories?** Today the answer differs from file to file, and nothing records an intent.

**Measured:**

| site | behaviour on a SHA-256 repository |
|---|---|
| `SignatureVerification.swift:158` | **handles it** — recognises the `gpgsig-sha256` header (though nothing pinned that until #0306) |
| `LaneAssignment.swift:158` | **rejects it** — requires `token.count == 40`, so `graphRows` throws `malformedLine` on any 64-character oid |

So `verify` works and `graph` throws, on the same repository, for the same reason nobody decided
anything.

**This is not a criterion-5 item** — it is a missing feature, not a missing test, which is why the review
raised it as a proposal rather than filing it against M1.

## What answering it looks like

- [ ] **Decide, and record it in guide §11.** Three defensible answers: support SHA-256 now; declare it
      out of scope with a stated reason; or defer it to a named milestone. Any of the three is fine; the
      current state — *accidentally half-supported* — is not.
- [ ] **If supported:** audit every place the engine assumes a 40-character oid, not just
      `LaneAssignment.swift:158`. `grep -n "40" YardKit/Sources/YardGit/*.swift` is the starting point and
      will over-report; the real question is which comparisons are length checks on an oid.
- [ ] **If out of scope:** `graphRows`' failure should be a **structured refusal naming the reason**, not
      `malformedLine` — an agent hitting it deserves to be told the repository's hash algorithm is
      unsupported rather than that git's output was malformed. That is M1 criterion 3's territory.
- [ ] **If deferred:** say which milestone, and file the audit as an issue there.

## The files

`docs/switchyard-development-guide.md` §11 for the decision; `YardKit/Sources/YardGit/LaneAssignment.swift`
and any other length-assuming site if the answer is "support" or "refuse cleanly".

## Notes

**Milestone M5** — parked with the other open design questions rather than assigned to a milestone in
flight, because the answer changes scope rather than fixing a defect.

**Not blocking M1.** M1's exit criteria say nothing about hash algorithms, and the review was explicit
that this is a proposal rather than a finding. It is filed so the half-supported state is a recorded
decision-in-waiting rather than an accident nobody noticed.

**#0306 is the related test-only issue** and stands whichever way this goes.
