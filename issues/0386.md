## Description

**Child of #0380.** **Question:** does `Section(_:isExpanded:content:)` inside a `.listStyle(.sidebar)`
`List` show a disclosure control and collapse its rows on macOS 26, including when
`.searchable(placement: .sidebar)` is on the same list?

**Why it matters:** #0371 collapses Remotes and Tags by default this way. #0378 adds the filter field
to the same list, and specifies showing matches inside collapsed sections.

### Build

Tab **0386 sections** of #0380's spike app.

### Observe

1. Capture the window (`docs/windows-command.md`).
2. Hover each section header, then click its disclosure control (or the header) for Branches and for
   Remotes. Record whether the rows hide and show, and whether the right-hand status text changes.
3. With Remotes collapsed, type `0012` into Filter. Record whether Remotes' matching rows appear.

### Pass or fail, and what changes

- **Pass** — the headers carry a working disclosure control and the status text follows it. #0371 is
  unchanged. Step 3's result goes to #0378: either filtering already shows matches inside a collapsed
  section, or #0378 must expand sections while filtering, as it specifies.
- **Fail** — there is no control, or the rows do not collapse. #0371 switches to one `DisclosureGroup`
  per section inside plain `Section`s; re-run step 3 against that layout.
