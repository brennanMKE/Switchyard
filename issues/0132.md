## What is on the wire, and what deliberately is not — settled here

1. **`Hunk.body` rides the wire; the computed `patchText` does not** (#0129 Decision 7).
   `patchText` is a pure join — `([header] + body).joined(separator: "\n") + "\n"` — and both
   `header` and `body` ride the wire, so a reader reconstructs it losslessly. An agent staging by
   hunk id needs the id and the lines to show a human; shipping the same lines twice would roughly
   double every diff payload for nothing. `FileDiff.headerText` (stored) stays on the wire because
   `patchText`'s own doc comment defines the `git apply --cached` input as `headerText` + hunk
   patch text — dropping it would strand the reconstruction.
2. **`BlameLine.isUncommitted` is not encoded** (Decision 7): the wire carries `oid` verbatim, and
   the reader derives uncommittedness from the 40-zero constant, which the tests pin literally.
   `isBoundary` IS stored (parsed from porcelain's `boundary` marker) and rides the wire.
3. **Decision 6 has no subject here — checked and clear.** Neither file carries a `[UInt8]`
   member. Both parsers take `String` (the lossy decode happens at the `GitProcess` boundary), and
   both refuse C-quoted paths explicitly (`Failure.quotedPath`) rather than mis-parsing them, so
   `path`/`originalPath` are plain strings end to end. Unlike #0131, there are no raw bytes to
   keep off the wire.
4. **`DiffArea` gets no conformance.** It is a request parameter — `listHunks` returns
   `[FileDiff]`, and no result type carries it. `HunkParser.Failure` and `BlameParser.Failure` get
   none either: they are thrown errors, surfaced as `EnvelopeFail` by the CLI layer in M3, never
   payloads inside a success envelope.
5. **`[FileDiff]` and `[BlameLine]` ride as bare JSON arrays in `result`** — `listHunks` and
   `blameFile` return arrays with no wrapper type, the same shape #0131 settled for
   `conflictedFiles(at:)`. The envelope test pins both.

## Givens — each measured on this machine, 2026-08-07

1. **Both `Hunk`/`FileDiff` and `BlameLine` are already `Sendable`** (`public struct Hunk:
   Sendable, Equatable`, `public struct FileDiff: Sendable, Equatable`, `public struct BlameLine:
   Sendable, Equatable`), so `Encodable` alone satisfies `EncodableResult`'s bound. Measured: the
   test file below constructs `EncodableResult(…)` and compiles. Every `Equatable` is synthesized —
   no custom `==` in either file (the #0130 Given-3 class, checked and clear) — and neither file
   contains any existing `extension`, so both appends are plain end-of-file appends with no
   search-and-replace hazard (the #0130 Given-7 class, checked and clear).
2. **The derived hunk ids in the fixture are `e0cf3dfb859e` and `c930666f6ddd`** — produced by the
   real `HunkParser.hunkID` derivation (#0016: SHA-256 over path, a 0 separator byte, and the
   joined body; first 12 hex) running on the pasted diff. The literals pin the derivation itself:
   under mutation 5 (separator byte removed) the same fixture derives `8bb2c9946a14` and
   `34ffb501bcda` and both diff tests go red. Id stability is the whole point of #0016 — an id
   drift is a wire break even though no `CodingKeys` changed.
3. **Git appends a tab after a path containing a space** on `---`/`+++` lines — measured with
   `od -c`: `… t   x   t  \t  \n …`. The fixture path `release notes.txt` exercises it, and the
   tab rides inside `headerText` as the two-character JSON escape `\t` in the literal. Inside a
   `#"…"#` raw string that stays a literal backslash-t, which is exactly right — do not convert it
   to a real tab.
4. **The blame fixture covers all three wire-visible attribution states** in one file: line 1 from
   the root commit (porcelain emits `boundary`, parsed to `isBoundary: true`), line 2 from an
   ordinary second commit, line 3 uncommitted worktree content — the all-zeros oid, author
   `Not Committed Yet`, and git's fabricated summary `Version of poem.txt from poem.txt`. Also
   measured: the parser strips the angle brackets from `author-mail`, so the wire carries
   `"authorEmail":"not.committed.yet"` — brackets gone. The literals are pasted from the real
   parse; do not restore the brackets.
5. **`JSONEncoder` escapes forward slashes**: `a/script.sh` encodes as `a\/script.sh` (visible in
   every `headerText` literal). Do not "fix" the literals; they are pasted from a real run.
6. **A hunk with an empty `body` is unproducible by `HunkParser`** — a `HunkBuilder` exists only
   after an `@@` header parses, and git does not emit a hunk with no lines — so the
   empty-array-encodes-as-`[]` rule is pinned where it is real: `hunks` on a mode-only `FileDiff`,
   from a real chmod diff. `"hunks":[]` is present, never omitted; only the nil optionals
   (`oldMode`, `newMode`) are omitted.
7. **Baseline.** `docs/test-baseline.txt` reported 467 on 2026-08-07 as this planning pass
   finished (#0130 and #0131 landed mid-pass), and it moves often. Trust the delta, not the
   absolute: on a fresh clone of that `main` the measured result after this change is
   **`Test run with 474 tests in 26 suites`**, +7 exactly. (The mutation rows were observed on an
   earlier 453 tree the same day; neither source file differs between the two.)
8. **Deleting any of the three `CodingKeys` enums is UNOBSERVABLE** — measured: with all three
   deleted the seven tests stay green, because every stored property is encoded under a key
   byte-identical to its member name (#0129 Decision 3) and synthesis ignores computed properties
   (`patchText`, `isUncommitted`) with or without the enum. These types are the #0129/#0130 plain
   class, not #0131's byte-carrying class where the enum enforces Decision 6. The enums' presence
   is a grep criterion in Expected behavior instead.

## Change 1 — `YardKit/Sources/YardGit/Hunks.swift`, append at end of file

```swift
// MARK: - Wire encoding (#0132)

/// `Hunk` is a `schemaVersion: 1` payload component: it encodes through
/// `YardKit`'s `Envelope` via `EncodableResult` (`Encodable & Sendable`).
/// Plain-stdlib `Encodable` — the engine still imports nothing.
extension Hunk: Encodable {
    /// The stable wire keys. Identical to the stored-member names on purpose;
    /// no raw values — the case name IS the wire key, and `DiffBlameWireTests`
    /// pins the encoded bytes. The computed `patchText` is not encoded
    /// (#0129 Decision 7): it is a pure join of `header` and `body`, which
    /// both ride the wire, so a reader can reconstruct it losslessly.
    private enum CodingKeys: String, CodingKey {
        case id, path, oldStart, oldCount, newStart, newCount, header, body
    }
}

extension FileDiff: Encodable {
    /// Stable wire keys, identical to the stored-member names; no raw values.
    /// An empty `hunks` array (binary or mode-only change) encodes as `[]`,
    /// never omitted — only nil optionals (`oldMode`, `newMode`) are omitted.
    private enum CodingKeys: String, CodingKey {
        case path, oldMode, newMode, isBinary, headerText, hunks
    }
}
```
