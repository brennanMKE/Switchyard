## Description

Every build command in `CLAUDE.md`, `AGENTS.md`, `README.md` and `scripts/make-release.sh`
(`SCHEME="Switchyard"`, line 30) passes `-scheme Switchyard`, but the only scheme under version
control is `Switchyard.xcodeproj/xcshareddata/xcschemes/Switchyard UITests.xcscheme`. The
`Switchyard` scheme exists only in Brennan's Xcode user state (`xcschememanagement.plist` names
`Switchyard.xcscheme_^#shared#^_`, but the file was never committed). So on a fresh clone:

**Measured 2026-09-26, detached worktree of `main` at `2395a63`:**

```
$ xcodebuild -list -project Switchyard.xcodeproj      # Schemes: section
        BrokerAgent
        switchyard

$ xcodebuild build -project Switchyard.xcodeproj -scheme Switchyard -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO -quiet
xcodebuild: error: The project named "Switchyard" does not contain a scheme named "Switchyard". The "-list" option can be used to find the names of the schemes in the project.
exit 65
```

(`switchyard`, lower case, is SwiftPM's auto-generated scheme for the CLI executable in `YardKit`;
it is not the app.)

The fix is one new file, derived from the committed UI-test scheme: same app `BuildActionEntry`,
`LaunchAction`, `ProfileAction`, `AnalyzeAction`, `ArchiveAction`; the UI-test build entry removed;
the `TestAction` testable switched to the unit-test target. Target IDs are from
`Switchyard.xcodeproj/project.pbxproj`:

| target | BlueprintIdentifier | product |
|---|---|---|
| `Switchyard` | `26B64D3330251BCE00EB4FD0` | `Switchyard.app` |
| `SwitchyardTests` | `26B64D4030251BCF00EB4FD0` | `SwitchyardTests.xctest` |

The UI-test scheme's own header comment already says "The Switchyard scheme's Test action stays
unit-tests-only" — this file is what that sentence refers to. `BrokerAgent` needs no entry: the app
target depends on it (`PBXTargetDependency`) and `buildImplicitDependencies = "YES"` builds it.

## Verification

All from the worktree root, **unsigned only**. Never pass `-allowProvisioningUpdates`; never run
the tests (the unit-test bundle is hosted in `Switchyard.app`, so running it launches the app on
this Mac).

1. `xcodebuild -list -project Switchyard.xcodeproj` — paste the `Schemes:` block.
2. `xcodebuild build -project Switchyard.xcodeproj -scheme Switchyard -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO -derivedDataPath build/dd -quiet; echo EXIT $?`
   — must print `EXIT 0` and no `error:` line.
3. `xcodebuild build-for-testing -project Switchyard.xcodeproj -scheme Switchyard -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO -derivedDataPath build/dd -quiet; echo EXIT $?`
   — must print `EXIT 0`, and `build/dd/Build/Products/Debug/Switchyard.app/Contents/PlugIns/SwitchyardTests.xctest`
   must exist.
4. No Swift changed, so no `swift test` is required; the round reports `no package changes` in
   place of the `Test run with N tests` line.
