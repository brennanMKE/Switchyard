## Description

The third journal snapshot primitive (git internals §3): the working tree, captured with
`git stash create` — which builds a stash commit **without touching the worktree or the stash
stack** — plus an explicit untracked-files tree, because `stash create` does not capture
untracked files at all.

**Structured stub, split from #0027 on 2026-08-07.** Re-authored to code level at its own
planning pass before dispatch, per CLAUDE.md. The facts below were measured on this machine,
git 2.50.1 (Apple Git-155), 2026-08-07.

## Measured facts — run on this machine, 2026-08-07

1. **`git stash create -u` silently ignores `-u`** (re-confirming the internals doc's 2026-08-06
   correction): with one tracked modification and one untracked file present, it printed a commit
   oid whose `git rev-list --parents -n1` shows **2 parents**, whose tree contains the tracked
   file only (`git ls-tree -r <oid> --name-only` listed `a.txt`, not `u.txt`), left
   `git stash list` empty, and left the worktree modification in place.

2. **`git stash create` with only untracked changes prints nothing and exits 0.** Empty stdout is
   the "nothing tracked to capture" case, not an error — a snapshot with untracked-only changes
   must still capture the untracked tree, and the empty-oid case must be represented, not
   force-unwrapped.

3. Untracked capture per internals §3: build a tree from untracked non-ignored paths via a
   temporary `GIT_INDEX_FILE` + `git add`/`update-index` + `write-tree` + `commit-tree`, and
   record that oid alongside the stash commit's. (`GitProcess` passes environment via
   `extraEnvironment:`.)

## Expected behavior (to be authored to code level)

- [ ] `YardKit/Sources/YardGit/WorktreeSnapshot.swift`: capture returns the stash-form commit oid
      (nil-able, per fact 2) plus an untracked-tree commit oid (nil-able); restore reapplies both.
- [ ] A test asserts the stash stack is untouched by capture (`git stash list` empty before and
      after) — the property that makes `stash create` usable here.
- [ ] A test asserts an untracked file survives a snapshot/restore round trip. Without it this
      regresses invisibly (internals §3's warning).
- [ ] A tracked modification survives a round trip after `git checkout -- .` wiped it.
- [ ] Restore verified by round-trip, not by inspection.
- [ ] `YardKit/Tests/YardGitTests/WorktreeSnapshotTests.swift` gains the tests; the diff lists
      exactly two files.
