## Description

**Child of #0380.** **Question:** in `.alert(_:isPresented:actions:message:)` containing a `TextField`,
do a `Button`'s `.disabled(…)` state and the message `Text` update live as the user types?

**Why it matters:** #0363 uses an alert for New Branch… and Rename…, with the confirming button
disabled while `RefNameProblem` reports a problem.

### Build

Tab **0385 alert** of #0380's spike app.

### Observe

Open **New Branch…** and type `m`, `ma`, `mai`, `main`, `main2`. After each, record whether
**Create Branch** is enabled and what the message reads. Then clear the field.

The live behaviour to look for: disabled while empty and at `main`, enabled otherwise; the message
reads "A branch named “main” already exists" exactly while the field holds `main`.

### Pass or fail, and what changes

- **Pass** — both the button and the message update live. #0363 is unchanged.
- **Partial** — the button updates but the message stays frozen. #0363 cannot show the reason in an
  alert, so both dialogs move to sheets, as in the fail case.
- **Fail** — neither updates. #0363's New Branch… and Rename… become sheets: a `TextField`, the
  `RefNameProblem` text below it in `.secondary`, the confirming button as `.defaultAction`, and
  Cancel as `.cancelAction`.

## Expected behavior

- [ ] The observation is recorded here: versions, and the button state and message after each
      keystroke.
- [ ] #0363 is updated per the outcome.
