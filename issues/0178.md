## Description

**Filed by #0041's review on 2026-08-08. Two behaviours that are correct in the shipped code and
unguarded by any test.**

#0041 landed `HookInstall` with chaining: an existing foreign hook moves to `.switchyard-chained`
and the wrapper runs it, propagating its exit status. Review confirmed the chaining itself is well
covered — a mutation that overwrites instead of chaining turns three test functions red. These two
paths are not.

## 1. A non-executable pre-existing hook

#0041's Given 7 asserts the wrapper's `[ -x "$chained" ]` test preserves git's own semantics: git
does not run a non-executable hook, so neither should the wrapper. **No test covers it.**

Review wrote a temporary probe and **the behaviour is correct** — the bytes are preserved at
`.switchyard-chained`, the non-executable mode survives the rename, and the hook does not run. So
this issue is about evidence, not a fix. Make that probe a permanent test.

Assert all three: contents preserved, mode bits preserved through the rename, and the chained hook
does **not** execute. The third is an absence assertion, so **mutate the fixture** — make the hook
executable — and confirm the test goes red. Otherwise it passes for free.

## 2. The rename-then-write window is not atomic

`moveItem` followed by `write` means that if the write fails after the rename, the foreign hook
sits at `.switchyard-chained` with no wrapper in place — **the user's hook silently stops running**
until #0158 restores it.

It surfaces as `.failed(...)` rather than silently succeeding, so it is visible to a caller. But it
is untested, and the window is real.

Decide and record which this is:

- **acceptable and documented** — the failure is reported, and recovery is #0158's job; or
- **worth closing** — write the wrapper to a temporary path and rename it into place last, so the
  foreign hook is never without a wrapper.

If the second, the ordering becomes: write wrapper to temp → move foreign hook aside → rename temp
over the hook path. Measure what that costs and whether any window remains.

Either way this issue must leave a test that drives a failure **after** the rename and asserts what
the caller observes and what state the hook directory is left in.

## Notes

Both findings came from a reviewer probing beyond the mutation table — the same pattern that
produced #0176 and #0177 from #0167. The code was right in every case; the evidence was missing.
`docs/review-failures.md` check 0b covers the general lesson.
