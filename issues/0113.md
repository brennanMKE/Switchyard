## Description

The parser and the five basic states, split out of #0013 after its round produced nothing. #0013
bundled the parser, renames and copies, submodule state, three path-encoding hazards and both ref
formats into one round; this issue is the half that everything else builds on.

## Scope — deliberately narrow

**In:** parsing `git status --porcelain=v2 -z` into per-file entries that distinguish **staged**,
**unstaged**, **untracked**, **ignored** and **conflicted**.

**Out, and owned by #0013:** renames and copies with both paths, submodule state, and paths
containing spaces, newlines or non-UTF-8 bytes. Do not attempt them here — a file that tries to cover
everything is what failed.

## Givens — verified, treat as true

1. New file `YardKit/Sources/YardGit/WorktreeStatus.swift`.
2. **`GitProcess` is a concrete struct** — `GitProcess()`, `run(_:at:)`, `capture(...)`. There is no
   runner protocol and no injection seam; do not invent one. Read
   `YardKit/Sources/YardGit/GitProcess.swift` first.
3. **Never concatenate onto `.git/`.** Use `git rev-parse --git-path`. A reftable repository has no
   `.git/refs` at all.
4. In `FixtureRepository`, commit names like `"a"` are keys in **`repo.oids`**, not refs, and
   `addWorktree(named:branch:)` **creates** the branch it is given.
5. **Run `git status --porcelain=v2 -z` against a fixture with each state present and read the real
   bytes before writing the parser.** Round 1 of #0013 ran it against a *clean* worktree, got nothing,
   recorded "empty repo state", and wrote a parser against an imagined format.

   **Build that fixture under `build/` in this worktree** — e.g. `build/probe-repo`. Your sandbox
   auto-rejects `$TMPDIR` and `/tmp`, and round 1 of *this* issue died on exactly that: it ran
   `mkdir -p $TMPDIR/yard-test && git init`, was rejected, and stopped. `build/` is gitignored.

   Note the asymmetry that makes this confusing: `FixtureRepository` uses `NSTemporaryDirectory()`
   and works fine, because `swift test` is not sandboxed. Only commands **you** run are restricted.
6. `main` is at 176 tests.

## Expected behavior

- [ ] `WorktreeStatus.swift` parses `--porcelain=v2 -z` — never the human-readable form.
- [ ] Per-file entries distinguish staged, unstaged, untracked, ignored and conflicted.
- [ ] Ignored files appear only when asked for; `--porcelain=v2` omits them without
      `--ignored`, so decide and state which the function requests.
- [ ] Returns a value type. No printing.
- [ ] Tested against both ref formats via `FixtureRepository`.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest.
- [ ] Tests are `throws` and use `try` — **never `try!`**, and no subscript into a collection without
      a preceding `#require`. A trap destroys the whole run summary and has cost two rounds.
- [ ] `cd YardKit && swift build` succeeds and `swift test` prints a `Test run with N tests` line you
      paste. **N must be greater than 176.**

## Tests must be able to fail

Build a fixture that has **all five states at once** and assert the classification of each. A test
with one modified file passes for a parser that returns a constant.

Then prove it binds: make the parser report every entry as untracked, confirm the tests fail, restore.

## Notes

If `write` fails twice on the same file, create it with a shell heredoc instead —
`cat > path/File.swift <<'EOF'` … `EOF`. Two rounds were lost to a truncated `write` tool call, and
retrying it identically never succeeds. See `AGENTS.md` Rule 5b.

Build the file incrementally: declare the types, run `swift build`, then add the parsing. A partial
file that compiles can be finished; a large write that never lands leaves nothing behind.
