## Description

The parser and the five basic states, split out of #0013 after its round produced nothing. #0013
bundled the parser, renames and copies, submodule state, three path-encoding hazards and both ref
formats into one round; this issue is the half that everything else builds on.

## Scope — deliberately narrow

**In:** parsing `git status --porcelain=v2 -z` into per-file entries that distinguish **staged**,
**unstaged**, **untracked**, **ignored** and **conflicted**.

**Out, and owned by #0013:** renames and copies with both paths, submodule state, and paths
containing spaces, newlines or non-UTF-8 bytes. Do not attempt them here — a file that tries to cover
everything is what failed.

## Givens — verified, treat as true

2. **`GitProcess` is a concrete struct** — `GitProcess()`, `run(_:at:)`, `capture(...)`. There is no
   runner protocol and no injection seam; do not invent one. Read
   `YardKit/Sources/YardGit/GitProcess.swift` first.
3. **Never concatenate onto `.git/`.** Use `git rev-parse --git-path`. A reftable repository has no

4. In `FixtureRepository`, commit names like `"a"` are keys in **`repo.oids`**, not refs, and

## Review — round 2, and round 3 is the last

Exit 0 after 1709s, and **the suite is red**: `✘ Test run with 180 tests in 15 suites failed … with 8

### 1. The round broke the layering test

`WorktreeStatus.swift` line 2 is `import YardKit`, inside `YardGit`.
`LayeringTests.yardGitDoesNotImportYardKit` fails. That test exists because the dependency direction
is `app → YardKit → nothing` and `YardGit → Clibgit2`; inverting it is how the CLI ends up linking
things it must not. **Remove the import.** Nothing in this task needs `YardKit`.

### 2. Here are the real bytes. Stop trying to obtain them.

You have now attempted twice to build a fixture and read `--porcelain=v2 -z` output, and both attempts
were rejected by the sandbox. **Do not try again.** These were captured from a real repository with
all five states present simultaneously, `git status --porcelain=v2 -z --ignored`, NUL shown as a line
break:

```
1 .M N... 100644 100644 100644 df967b96a579e45a18b8251732d16804b2e56a55 df967b96a579e45a18b8251732d16804b2e56a55 base.txt
1 A. N... 000000 100644 100644 0000000000000000000000000000000000000000 19d9cc8584ac2c7dcf57d2680375e80f099dc481 staged.txt
u AA N... 000000 100644 100644 100644 0000000000000000000000000000000000000000 ba2906d0666cf726c7eaadd2cd3db615dedfdf3a 2299c37978265a95cbe835a4b0f0bbf15aad5549 conflict.txt
? untracked.txt
! ignored.txt
```

**Five record types, and round 2 handled only one of them.** Its guard was
`record.hasPrefix("1 ") || record.hasPrefix("2 ")`, so `?`, `!` and `u` were silently dropped.

| leading token | meaning | fields before the path |
|---|---|---|
| `1` | ordinary changed entry | **8** — `XY`, `sub`, `mH`, `mI`, `mW`, `hH`, `hI` |
| `u` | unmerged (conflicted) | **10** — `XY`, `sub`, `m1`, `m2`, `m3`, `mW`, `h1`, `h2`, `h3` |
| `?` | untracked | **1** — the token itself |
| `!` | ignored | **1** — the token itself |
| `2` | renamed or copied | out of scope — that is #0013 |

`XY` is two characters: **X is the index/staged state, Y is the worktree state.** `A.` is a staged
add with a clean worktree; `.M` is an unstaged modification; `AA` on a `u` record is both-added.

**Round 2's path extraction never skipped those fields**, so it produced
`path = "N... 100644 100644 100644 df967b… 61cf0b… staged.txt"`. Split the record on spaces, drop the
right number of leading fields for the record type, and **rejoin the remainder** — a path may contain
spaces.

**`!` records only appear when `--ignored` is passed.** Decide whether to request it and say so; the
issue asks for a deliberate choice, and round 2 made none because it never invoked git at all.

### 3. The parser must actually invoke git

`WorktreeStatus.swift` contains no `GitProcess` reference — it is a bare `parse(data:)` and the tests
shell out themselves. There must be a function that runs
`git status --porcelain=v2 -z` (plus `--ignored` if chosen) through `GitProcess` and returns the
entries. Keep the pure parser as an internal function if you like — that is good design — but the
public entry point takes a path and a `GitProcess`.

### 4. Smaller defects, all named

- `WorktreeStatusParser` is a **`class` with mutable state**. The issue asked for a value type.
- Line 98 is `parts[2...]` inside a branch guarded by `parts.count == 2` — an out-of-range trap that
  only survives because the branch is currently unreachable.
- Lines 155-165: `if let firstChar = … { } else if let secondChar = statusStr.dropFirst().first { }`.
  The `else if` can never run, so the worktree character is never parsed and every entry reports its
  default.
- Branch-header detection looks for `## `; porcelain v2 emits `# branch.oid`, `# branch.head`.
- It redeclares `Character.isHexDigit`, which is already in the stdlib.
- The hand-crafted test bytes are **invented** — they split one record into two NUL-terminated pieces.
  Real `-z` puts the whole record, path included, in one. Those tests pass on a shape git never emits.
  Replace them with the verbatim records above.
