## Description

Apply #0141's settled mechanism (Decisions 1–6: `ExitClass` in the engine, raw values are the §6
codes, conformance through `ExitClassCarrying` in each error type's own file, one fact — the
number — per failure) to the remaining engine error enums. #0141 established it on
`WorktreeContext.Error`, `WorktreeRemoveError`, and `WorktreeAddError`; this issue finishes the
sweep so guide §9 M1 criterion 3's exit-code half holds for every failure mode.

Known facts for the planning pass, verified 2026-08-07 while authoring #0141:

- All ten map to `.repositoryError` (6) under #0141 Decision 5's reasoning: an unclassified git
  failure, an unlistable worktree set, and a malformed porcelain/diff/blame/rev-list record are
  all repository-state failures. Nothing in the engine today produces an 8 or a 9 — those arrive
  with M2's mutating and signing operations.
- `FixtureRepository.Error` is deliberately excluded (#0141 Decision 6): fixture infrastructure,
  not a product failure mode.
- Tests append new `@Test` functions to the existing `@Suite` in
  `YardKit/Tests/YardWireTests/ExitClassWireTests.swift` (created by #0141) — same shape as
  #0141's per-enum tests, including the count assertion so no loop can go vacuous, plus rows in
  the `conformancesAreReachableThroughAnyError`-style runtime-cast test for each new conformer.
- If #0140 lands a new `whereAmI` not-a-repository error first, its conformance belongs here too;
  re-check at planning time.

## Expected behavior

Every error enum in the table conforms to `ExitClassCarrying` in its own source file, each with a
doc comment stating why its class is 6, and `ExitClassWireTests` pins every case of every enum the
way #0141's tests do. `LayeringTests` stays green in both directions; nothing under
`YardKit/Sources/YardKit/` changes.
