## Description

**Found by the second #0044 umbrella review, 2026-08-17. The reviewer marked its claim unverified and
asked the orchestrator to run the mutation; it was run and the claim holds.**

**Measured: gating step 5 behind `if !allowDifferentWorktree` leaves all 908 tests green.**

#0044 decision 3 requires the sibling-disturbance check to run on the target snapshot in **every**
restore path. #0175 opened a new path — the cross-worktree override — and its own final
Expected-behavior checkbox says *"`WorktreeDisturbance` still refuses a sibling-disturbing restore
**under the override**"*. Nothing tests that:

- `allowDifferentWorktree` appears in exactly two test call sites, and `crossWorktreeFixture` produces
  **no disturbance** — the sibling's branch oid is identical in `recorded`, `current` and `applied`, so
  the check passes trivially.
- The disturbance tests never pass the override.

Structurally the check cannot be skipped today, because step 5 is unconditional. That was equally true
of `bypassGuard` before **#0203**, which is the same defect class in the same file — and this is the
path where the disturbance check is the **only** protection. #0175's own planning update says so: *"the
guard is therefore not the thing protecting a cross-worktree restore. `WorktreeDisturbance` is."*

## Expected behavior

- [ ] One test in `YardKit/Tests/YardGitTests/JournalRestoreTests.swift`: a **live** sibling holding a
      checked-out branch, a foreign entry whose snapshot would move that branch, restored with
      `allowDifferentWorktree: true` — asserting `WorktreeDisturbance.Error.wouldDisturb` is thrown and
      that nothing was written (entry count and a fresh `RefSnapshot.capture` both unchanged).
- [ ] The mutation **observed red**: wrap step 5's disturbance block in `if !allowDifferentWorktree { … }`.
      Measured before filing: without the new test, the whole suite stays green under it.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt` by exactly 1. State the delta before running.

## Notes

**No production change.** The code is already correct; this is evidence, the same shape as #0203, #0192
and #0178 item 1.

It is roughly a 30-line composition of two things that already exist: the assertions from
`restoreRefusesToDisturbASiblingsCheckoutEvenWithBypassGuard` and the fixture from
`crossWorktreeFixture`. **The fixture needs one change** — `crossWorktreeFixture` deliberately leaves the
sibling's branch oid identical across snapshots, so the new test must move it, the way the
`bypassGuard` test does with `update-ref` plumbing.

`WorktreeDisturbance` excludes the caller's own checkout and any **detached** sibling, so a fixture that
gets either detail wrong passes for the wrong reason.
