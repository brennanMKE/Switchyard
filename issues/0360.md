## Description

Two single-commit replay operations from GitUp's commit-node context menu (see #0359's capture)
that Switchyard does not have in any form: **Revert Against Current Branch** (apply the inverse of
a commit onto the current branch as a new commit) and **Cherry-Pick Against Current Branch**
(replay a commit from another branch onto the current branch).

The engine half is small — both are `git cherry-pick` (or `cherry-pick --no-commit` + inverse
apply for revert) against a known target, which #0060's decision already measured for structured
conflict reporting (exit 1, `CHERRY_PICK_HEAD`, `# Conflicts:` list, `--abort` verified clean).
The new work is the typed wrapper, the CLI verbs, and the journal discipline.

## Expected behavior

- [ ] `yard revert <commit>` applies the inverse commit to the current branch through
      `CommitCreate`'s signing path; `yard cherry-pick <commit>` replays it. Both non-interactive.
- [ ] Both auto-checkpoint and are exactly undoable; conflicts exit 8 leaving git's own resumable
      state (the measured cherry-pick shape).
- [ ] Refusals typed before mutation: reverting a merge (needs `-m`, refused with a reason),
      picking a commit already reachable from the current branch, unknown commit.
- [ ] Signed commits stay signed per the #0060 explicit-`-S` rule.
- [ ] Both appear as #0359 context-menu items when the node permits (the disabled states mirror
      the typed refusals).

## Notes

The menu's disabled-state logic is the UI half of the engine's refusal knowledge — the same
pattern #0359 established.
