## Description

Brennan chose option B of the branch-map design exploration on 2026-09-26: a **folded staircase**
with **merged branches dimmed**. Guide §11 **decision 29** records the design, every default, and
his words. This umbrella replaces #0410's recency-ordered lanes in `BranchMapLayout`, which crossed
connectors over unrelated lanes, drew merge edges and unlabelled runs, and grew one row per commit.

The design exploration is a working HTML/JS prototype built from this repository's real data (a
scratchpad page, not checked in). Its layout code is ours, not GitUp's, and #0426 translates the
algorithm into Swift in our own structure.

**#0431 is a prerequisite bug fix found while planning.** `BranchStatus.read` throws on git's
bracketed `[ahead N]`, so the sidebar shows no branch status on any real repository, and #0430 would
dim nothing there. It touches only `BranchStatus.swift` and its tests, so it can be dispatched at
any time, alongside any child. It must merge before #0430.

**Overlap with concurrent work.** #0416 (open into window) and #0417 (native tabs) edit
`ContentView.swift` and `WindowState.swift`. Only **#0428** and **#0430** touch `ContentView.swift`,
each by one argument on the `CommitHistoryView(` call in `historyPane(summary:)` (`branchTips:`,
then `repositoryPath:`). Dispatch #0428 after #0416 has merged. #0416's branch also adds a
`run_spike_if_selected` line to `scripts/run-ui-tests-vm.sh`, and #0427, #0429 and #0430 each add
theirs after the last one. None of the five touch `WindowState.swift` or the window toolbar; the recency
pop-up sits at the top of the History pane for that reason (decision 29).
