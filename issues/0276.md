## Description

**Finding 1 of the M1 milestone review, sixth pass, 2026-08-18.** `wt where` never checks the worktree
name it reports — the field the command exists to answer.

`YardKit/Sources/YardGit/WorktreeWhere.swift:66`, mutated:

```swift
worktreeName: ctx.worktreeName.map { _ in "bogus-worktree" },   // was: ctx.worktreeName
```

`Test run with 1078 tests in 78 suites passed after 91.242 seconds.` — **full suite, unfiltered.** The
`map` preserves nil-ness deliberately, so every existing assertion still holds.

**Why nothing catches it:** every concrete assertion on the field is `nil`
(`WorktreeWhereTests.swift:18, 97, 112`); the two linked-worktree cases assert `!= nil` only (`:60`,
`:176`); and `WorktreeIdentityWireTests.swift:56` pins `"worktreeName":"switchyard-0042"` from a
hand-built literal, so it exercises the encoder rather than `yardWhere`.

**The fixture at `WorktreeWhereTests.swift:56` already names the worktree `agent-a`.**
`#expect(result.worktreeName == "agent-a")` is one line away and absent.

`WorktreeContext.worktreeName` itself *is* pinned indirectly, by
`WorktreeContextTests.readsAnotherWorktreesHead`. What is unpinned is **`yardWhere`'s propagation of
it**, which is the engine function criterion 2 names.
