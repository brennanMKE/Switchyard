# 0250 — Decision 2's text still says a restore can delete

## Description

**Finding 5 of #0044's fourth umbrella review, 2026-08-17.** #0044 **decision 2**'s operative sentence
still reads:

> names every sibling worktree whose checked-out branch the snapshot would **move, delete, or
> re-create**

**A restore can no longer delete anything.** `RefSnapshot.restore` emits `update` for recorded refs and
nothing else (`RefSnapshot.swift:206-208`); the deletion loop was removed by #0231 under guide §11
**decision 20**. The behaviour is right; the decision's text is not.

`WorktreeDisturbance`'s own type comment was corrected to "move or re-create" by **#0244** — the
decision it implements was not. That is the same mismatch #0244 existed to fix, one layer up, and stale
decision text is what produced #0244 in the first place.

**Two artefacts carry the stale word into the code:**

- `Disturbance.target` is documented as never nil in practice, on the strength of the deletion case
  that can no longer occur.
- `Error.description`'s `d.target.map { "move to \($0)" } ?? "delete it"` — the `?? "delete it"` branch
  is now **unreachable**, and would produce a message describing something the engine cannot do.

## Expected behavior

- [ ] Decision 2's sentence in `issues/0044.md` says what is true, and says when it changed and why —
      a pointer to decision 20, so a reader of the decision alone is not misled.
- [ ] `Disturbance.target`'s doc comment matches reality.
- [ ] The unreachable `"delete it"` branch is removed, or — if `target` stays optional for wire
      stability — the message says something true for a nil target. **Say which you chose and why**;
      changing an error's user-facing text is a contract change, so if any test pins that string it
      must be updated deliberately rather than incidentally.
- [ ] Mutation: whatever you replace the branch with, prove a test sees the message. If none does,
      that is worth saying — an error string nothing asserts is its own small finding.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.

## The files

`issues/0044.md` (decision 2's text), `YardKit/Sources/YardGit/WorktreeDisturbance.swift`, and
`YardKit/Tests/YardGitTests/WorktreeDisturbanceTests.swift` if a test pins the string.
