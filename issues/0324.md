## Description

**Finding 2 of the M1 milestone review, fourteenth pass, 2026-08-18 (first half).** `verify` reports a
**validly signed commit as unverifiable** under `log.showSignature`.

`YardKit/Sources/YardGit/SignatureVerification.swift:90` invokes `git log` without
`--no-show-signature`. **`log.showSignature = true` prepends a verification line even with a custom
`--format`** — measured against a real SSH-signed commit (throwaway key in the scratchpad; nothing
registered anywhere):

```
Good "git" signature for t@t with ED25519 key SHA256:aqNIt…
87b9f758dfeacb0116fe788f37803cebc7d295ad^A^AT^AG^AHEAD -> main^Asigned subject
```

**Measured through the engine**, same repository, config off then on:

```
verify default:        state=good  format=ssh  signer=Optional("t@t")
verify showSignature:  state=cannotCheck(reason: "unrecognized %G? flag \"Good \"git\" signature …\"")
                       signer=nil
```

**The blast-radius argument runs the other way from #0320's:** the population that sets
`log.showSignature` is precisely the population whose commits are signed — **`verify`'s entire
audience**.

## Expected behavior

- [ ] `SignatureVerification.run` passes `--no-show-signature`.
- [ ] A named test setting `log.showSignature=true` and asserting `verify` still reports the signature's
      real state.
- [ ] **The fixture needs a signed commit.** `installFakeGpg` already exists in the suite (see #0270)
      and needs no key material — **prefer it to generating a real key**. If you must use a real SSH key,
      it goes in the scratchpad and is never registered anywhere; say what you did.
- [ ] **Verify the config bites first**: plain `git log --format=%G?` under it must emit the prose line.
- [ ] **Mutation:** drop `--no-show-signature`. The new test must redden.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, above the count in `docs/test-baseline.txt`.

## Notes

**Milestone M1**, criterion 5 — **class 2**. **#0325 is the same config on `log`**, where the
consequence is different: `CommitLogEntry.oid` becomes an English sentence. Two files, two consequences,
two issues — the #0318/#0319 precedent.

**Measured to be a no-op when the config is unset**, on both a signed and an unsigned repository.

**The signed-commit fixture, measured 2026-08-18 — use SSH signing, not gpg.** `installFakeGpg`
(`CommitCreateGPGTests.swift:39`) is `private` to that file **and** a fake gpg cannot produce a
signature git will call *good*, which is what this issue needs. SSH signing needs no key material
beyond a throwaway keypair and no external tool beyond `ssh-keygen`. Verified end to end:

```sh
ssh-keygen -q -t ed25519 -N "" -C t@t -f "$repo/k" </dev/null
git config gpg.format ssh
git config user.signingkey "$repo/k.pub"
printf "t@t $(cat "$repo/k.pub")\n" > "$repo/allowed"
git config gpg.ssh.allowedSignersFile "$repo/allowed"
git commit -S -m ...
```

Measured output on that fixture (git 2.50.1):

```
git log -1 --format=%H                          -> 64f4916d3b19c0a81e151971c3c4a04b55f3349e
git -c log.showSignature=true log -1 --format=%H -> Good "git" signature for t@t with ED25519 key
                                                    SHA256:KEn7up2tM8A1el4fRI4gkUtSp8nv+lBLTVIa4A5q0zc
                                                    64f4916d3b19c0a81e151971c3c4a04b55f3349e
git -c log.showSignature=true log -1 --no-show-signature --format=%H
                                                 -> 64f4916d3b19c0a81e151971c3c4a04b55f3349e
```

**The key fingerprint differs per run** — it is a fresh keypair — so never assert on it.

**The exact mechanism, measured 2026-08-18 on the SSH fixture above** — `SignatureVerification.run`
(`SignatureVerification.swift:90`) runs `["log", "-1", "--format=%G?\u{01}%GS\u{01}%GK", revision, "--"]`
and takes `logOutput.lines.first`, splitting it on `\u{01}`:

```
default:                          G \001 t@t \001 SHA256:KEn7up2t…
log.showSignature=true:           Good "git" signature for t@t with ED25519 key SHA256:KEn7up2t…
log.showSignature + --no-show-signature:
                                  G \001 t@t \001 SHA256:KEn7up2t…
```

Under the config the **first line contains no `\u{01}` at all**, so `fields` has one element, `flag`
becomes the whole English sentence, `signer` and `key` become `""`, and `parse`'s `switch flag` falls
through every named case to its default. A validly signed commit is reported as if git could not
verify it.
