## Description

`ReviewSheetModel.lineChoices(for:)` (`YardKit/Sources/YardUI/ReviewSheet.swift`, line 309 on
`main`) builds the review sheet's per-line comment picker. It reads each body line's marker with
`body.first`, and builds the label from `body.dropFirst()`. Both work on **Character**s. When the
file's line opens with a combining mark (U+0301), the marker and the mark are one Character:
`"+\u{301}x".first` is `"+\u{301}"`, so the line hits `default` and is skipped. Every later line then
gets a number one too low, so a comment picked on a later line attaches to the wrong line.

Measured 2026-09-29 on `main`, hunk `newStart: 3`, body `[" keep", "+\u{301}x", " tail"]`:

- **before:** numbers `[3, 4]`, labels `["3  keep", "4  tail"]`.
- **after:** numbers `[3, 4, 5]`, labels `["3  keep", "4  \u{301}x", "5  tail"]`.

Both halves are needed. With only the marker fixed, `body.dropFirst()` drops the whole
`"+\u{301}"` Character, and the label reads `"4  x"` (measured, mutation 2).

The same Character read is in `LineStaging.swift`, `DiffLineSelection.swift`, `FileDiffView.swift`
and `SplitCommitSheet.swift`. Those files are in flight under #0476–#0480, so they are #0488, not
this issue.

## The files

### 1. `YardKit/Sources/YardUI/ReviewSheet.swift`

Replace

```swift
        for body in hunk.body {
            guard let marker = body.first else { continue }
            switch marker {
            case " ", "+":
                choices.append(
                    LineChoice(number: newLine, label: "\(newLine)  \(body.dropFirst())"))
```

with

```swift
        for body in hunk.body {
            // The marker is the line's first *scalar*: a line opening with a
            // combining mark fuses with it into one `Character`, so
            // `body.first` would be `"+\u{301}"` and the line would be
            // skipped (#0487, measured).
            guard let marker = body.unicodeScalars.first else { continue }
            switch marker {
            case " ", "+":
                choices.append(
                    LineChoice(number: newLine,
                               label: "\(newLine)  \(Substring(body.unicodeScalars.dropFirst()))"))
```

### 2. `YardKit/Tests/YardUITests/ReviewSheetTests.swift`

Insert this block **inside the suite**, immediately after the closing `}` of `@Test func lineChoicesListTheNewSideLinesOfTheHunkBody()` (the line after its `#expect(choices.map(\.label) == ["3  keep", "4  added", "5  tail"])`):

```swift
    // MARK: - #0487: a body line opening with a combining mark

    /// A body line is its marker scalar plus the file's line. When the file's
    /// line opens with U+0301, Swift fuses the marker and the mark into one
    /// `Character`, so `body.first` was `"+\u{301}"`: the line was not
    /// offered, and every later line was numbered one short (measured on
    /// `main`: numbers `[3, 4]`, labels `["3  keep", "4  tail"]`).
    @Test func aLineOpeningWithACombiningMarkIsOfferedAndNumbered() {
        let hunk = Hunk(
            id: "h", path: "f.txt",
            oldStart: 2, oldCount: 2, newStart: 3, newCount: 3,
            header: "@@ -2,2 +3,3 @@",
            body: [" keep", "+\u{301}x", " tail"])

        let choices = ReviewSheetModel.lineChoices(for: hunk)

        #expect(choices.map(\.number) == [3, 4, 5])
        #expect(choices.map(\.label) == ["3  keep", "4  \u{301}x", "5  tail"])
    }
```
