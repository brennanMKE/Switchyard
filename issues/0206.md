## Description

**Found by the third #0034 umbrella review, 2026-08-17.** It is #0205's own goal, one case over.

Guide §11 decision 14 says a restore must not leave a sequencer describing an operation the
just-restored refs no longer match — measured consequences: `git status` advertises a resumable rebase,
`git rebase --continue` fails to lock the ref, and `git rebase --abort` silently reverts the restore.

**A layout mismatch escapes both branches that enforce it:**

- `SequencerSnapshot.restore` removes the destination only for **its own** layout
  (`YardKit/Sources/YardGit/SequencerSnapshot.swift:142-143`).
- #0205's `clear` runs only in the `else if` branch, reached when the target captured **nothing**
  (`JournalRestore.swift:361-372`).

So restoring a `rebase-apply` snapshot while a `rebase-merge` is standing — or the reverse — leaves
**both** directories on disk. The restored one is correct; the other is exactly the stale state decision
14 exists to eliminate.

Nothing is red today because no fixture produces a `rebase-apply` state: it is reachable only through
`git rebase --apply` or `git am`. That is the same reason the sequencer wiring looked green before #0188
— **the suite cannot reach the code**, so its silence means nothing.

## Expected behavior

- [ ] Restoring a captured sequencer clears **any other** layout's directory as well as materialising
      its own. The smallest form is likely for `JournalRestore` step 8b to clear before it restores,
      since `SequencerSnapshot.clear` already loops `Layout.allCases` — but check whether clearing the
      target's own layout first and then restoring it is safe, or whether `clear` needs an "except this
      layout" parameter. Say which you chose and why.
- [ ] A test in `YardKit/Tests/YardGitTests/UndoRoundTripSuiteTests.swift` that builds the mismatch:
      a captured `rebase-merge` snapshot restored while a `rebase-apply` directory stands, asserting
      only the captured layout survives. **Building a real `rebase-apply` state needs
      `git rebase --apply` or `git am`** — verify the fixture helper can do it before designing around
      it, and if it cannot, construct the directory directly and say that is what you did.
- [ ] A mutation, observed: restore the current behaviour (clear only in the `else if` branch) and
      confirm the new test goes red.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt` by exactly 1. The delta is the criterion.

## Notes

Read guide §11 decision 14 first — it carries the three measurements that say why a stale sequencer is
not a cosmetic problem, and this issue inherits all of them.

**Scope note:** `SequencerSnapshot` covers rebase only. `.git/sequencer` (multi-commit cherry-pick and
revert), `MERGE_HEAD` and `CHERRY_PICK_HEAD` are **not** captured by anything, and #0034 decision 3
scopes the piece as "sequencer (mid-rebase)" deliberately. Widening that is a separate question and
must not be folded in here.
