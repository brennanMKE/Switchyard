## Description

**Proposal 4 of the M1 milestone review, eighth pass, 2026-08-18.** Two of `whereAmI`'s five probes omit
the `exitCode == 0` check their three siblings make.

| probe | line | guards `exitCode == 0`? |
|---|---|---|
| stash | `WhereAmI.swift:235` | **yes** |
| untracked (`ls-files`) | `:246` | **yes** |
| staged (`diff-index --cached`) | `:285` | **yes** |
| **unstaged** | `:270` | **no** — `try?` only |
| **conflicts** | `:298` | **no** — `try?` only |

The review **could not show this is behaviour-bearing on git 2.50.1** — it could not construct a state
where those two commands exit non-zero while still producing parseable output — so it filed it as an
inconsistency rather than a finding. That is the right call and this issue inherits it.

**It is the shape #0287 was filed against**, though: an engine reporting a count of zero when the
command that produces the count did not succeed is a *success value with empty fields*, which M1
criterion 3 forbids. The difference is only that #0287's three sites were demonstrably reachable and
these two are not — yet.

## Expected behavior

- [ ] **First, try to prove it reachable**, and treat a negative as a real result. Candidates worth
      trying rather than reasoning about: a corrupted index, a `diff-index` against an unborn `HEAD`, an
      unreadable working-tree file, a `git` shim that exits non-zero with output on stdout. **If you can
      construct one, this stops being a consistency change and becomes a criterion 3 fix — say so.**
- [ ] **If it is not reachable**, add the two guards anyway for consistency with the three siblings, and
      **say plainly in the report that no test can distinguish the change** — do not manufacture a test
      that passes for another reason.
- [ ] Either way, **say which of the two outcomes happened**. An honest "I could not make it fail, here
      is what I tried" is the deliverable if the first box comes back negative.
- [ ] If a test *is* constructible, mutation: remove the guard again; the test must redden.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, at or above the count in `docs/test-baseline.txt`.

## The files

`YardKit/Sources/YardGit/WhereAmI.swift`, and
`YardKit/Tests/YardGitTests/WhereAmITests.swift` if a test proves constructible.

## Notes

**Milestone M1.** **Not filed as a criterion violation** — the review was explicit that it could not

written down, because it is the third time this question has come up in M1.
