## Description

**Finding 1 of the M1 milestone review, thirteenth pass, 2026-08-18.** `gitStatus` loses **every
untracked file** under `status.showUntrackedFiles = no`, and two M1 engine functions then contradict each
other about the same worktree.

`YardKit/Sources/YardGit/WorktreeStatus.swift:406`:

```swift
var args: [String] = ["status", "--porcelain=v2", "-z"]
```

Nothing pins the config. **Measured, git 2.50.1**, one untracked file in a `FixtureRepository.linear()`:

```
PROBE default entries:                        ["newfile.txt"]
PROBE showUntrackedFiles=no entries:          []
PROBE whereAmI untrackedCount, same config:   1
```

**`whereami` uses `ls-files -o --exclude-standard`, which is plumbing and ignores the config.** So under
ordinary user configuration `status` says the worktree is clean while `whereami` says it has an untracked
file — the same contradiction #0296 was filed for between `wt new` and `wt list`.

**Not a preference.** `--porcelain=v2` exists to be a stable machine format, and **every other
format-stability lever in the engine is pinned explicitly** — `--no-color`, `--no-ext-diff`,
`--no-textconv`, `--no-renames`, `-c core.quotepath=false`, `--unified=3`. This one is the exception.

**Measured non-issues, for contrast**, so the fix is not over-applied: `color.ui=always`,
`core.quotepath=true` and `status.relativePaths` all leave `--porcelain=v2 -z` byte-identical.

      --porcelain=v2` under it must omit the file.
