## Description

Split out of #0012, whose round 1 timed out partly on breadth.

Git refuses to check out a branch that another worktree already has — measured 2026-08-07:

```
$ git checkout feature
fatal: 'feature' is already used by worktree at '/private/var/folders/rb/q_nwky4n2dng6stt0t4msj100000gn/T/yard0109fix.VVzB06nrz8/repo-wt-feature'
(exit 128)
```

That is free mutual exclusion between agents — `docs/switchyard-development-guide.md` treats
worktrees as the unit of agent isolation for exactly this reason. But the refusal is only useful if
the caller can find out **which** worktree holds the branch, rather than just being told no.

**One deliverable:** the function `siblingWorktree(holding:at:git:)` and its result struct in
`YardKit/Sources/YardGit/SiblingWorktree.swift`, with tests in
`YardKit/Tests/YardGitTests/SiblingWorktreeTests.swift`. The implementation is written out below —
type it in as given. The work of this round is the test file.

2. **A detached linked worktree, measured the same day** (`git worktree add --detach`): its record
   keeps the `HEAD <oid>` line, **gains an explicit `detached` line, and has no `branch` line** —
   both signals, not either/or:

   ```
   worktree /private/var/folders/rb/q_nwky4n2dng6stt0t4msj100000gn/T/yard0109fix.VVzB06nrz8/repo-wt-detached
   HEAD 7debce78d03073e4525f265b0bd8c1eb9c7f2792
   detached
   ```

3. **The first record is the main worktree, from any worktree.** Measured by running the same
   command from inside `repo-wt-feature`: record order is identical, main worktree first.

4. **`worktreeList` in `YardKit/Sources/YardGit/WorktreeList.swift` already parses all of this.**
   It runs the `-z` (NUL-terminated) porcelain form — same fields, measured identical on the same
   fixture — and its parser already: strips `refs/heads/` from `branch` (so
   `WorktreeEntry.branch == "feature"`, never `"refs/heads/feature"`), sets `detached: Bool` from
   the `detached` line, leaves `branch` nil for a detached entry, and marks the first record
   `isMainWorktree`. **Do not run `git worktree list` yourself — call `worktreeList`.**

5. `WorktreeContext.canonicalize(_:)` is `static` and internal, so
   `SiblingWorktree.swift` (same module) can call it. `WorktreeContext.resolve(path:git:)` returns
   a context whose `topLevel: String?` is already canonicalized (nil for a bare repository).

6. `GitProcess`'s parameter label is `workingDirectory:`, **not** `at:` — a previous revision of
   this issue said `run(_:at:)`, which does not compile. Full signatures below.

7. `FixtureRepository.addWorktree(named:branch:)` always creates the worktree **with a new branch**
   (`git worktree add -b`). There is no detached variant; the detached test detaches afterwards
   with `GitProcess` (exact call in the test plan below).

## The deliverable — `YardKit/Sources/YardGit/SiblingWorktree.swift`

```swift
// SiblingWorktree.swift — which worktree holds a branch (#0109)

import Foundation

/// The worktree that has a branch checked out, found via
/// `git worktree list --porcelain -z` (through `worktreeList`).
public struct SiblingWorktree: Sendable, Equatable {

    /// Absolute, canonicalized path of the worktree holding the branch.
    public let path: String

    /// Short branch name, without `refs/heads/`.
    public let branch: String

    /// HEAD oid of that worktree, when porcelain reported one.
    public let head: String?

    /// True when the holder is the repository's primary worktree.
    public let isMainWorktree: Bool

    /// True when the holder is the same worktree the query ran from —
    /// false when the branch is held by a sibling.
    public let isCurrent: Bool

    public init(path: String, branch: String, head: String?,
                isMainWorktree: Bool, isCurrent: Bool) {
        self.path = path
        self.branch = branch
        self.head = head
        self.isMainWorktree = isMainWorktree
        self.isCurrent = isCurrent
    }
}

/// Reports which worktree has `branch` checked out, or nil when none does.
///
/// `branch` may be a short name (`feature`) or a full ref
/// (`refs/heads/feature`). A detached worktree holds no branch and is never
/// reported. Errors from `worktreeList` and `WorktreeContext.resolve`
/// propagate; there is no new error type.
public func siblingWorktree(
    holding branch: String,
    at path: String,
    git: GitProcess = GitProcess()
) throws -> SiblingWorktree? {
    let name = branch.hasPrefix("refs/heads/")
        ? String(branch.dropFirst("refs/heads/".count))
        : branch
    let entries = try worktreeList(path: path, git: git)
    guard let match = entries.first(where: { !$0.detached && $0.branch == name }),
          let matchPath = match.path else {
        return nil
    }
    let holder = WorktreeContext.canonicalize(matchPath)
    let current = try WorktreeContext.resolve(path: path, git: git).topLevel
    return SiblingWorktree(
        path: holder,
        branch: name,
        head: match.head,
        isMainWorktree: match.isMainWorktree,
        isCurrent: current == holder
    )
}
```

## Tests — `YardKit/Tests/YardGitTests/SiblingWorktreeTests.swift`

`import Testing`, `@testable import YardGit`. Every test is
`@Test(arguments: FixtureRepository.RefFormat.supported())`, builds its own fixture, and calls
`repo.destroy()` in a `defer`. Fixture recipe common to all: `var repo = try
FixtureRepository(refFormat: format)` then `try repo.build([.init("a")])`.

Six tests, by name:

1. **`siblingHoldsBranch`** — `let wt = try repo.addWorktree(named: "agent", branch: "feature")`.
   Call `siblingWorktree(holding: "feature", at: repo.url.path)`. `#expect` the result is non-nil,
   its `path == wt.path`, its `path != repo.url.path` (the caller's own path — this inequality is
   the #0094 mutation guard), `branch == "feature"`, `isCurrent == false`,
   `isMainWorktree == false`.
2. **`mainWorktreeReportedFromLinked`** — same fixture; call
   `siblingWorktree(holding: "main", at: wt.path)` **from the linked worktree**. `#expect`
   `path == repo.url.path`, `path != wt.path`, `isMainWorktree == true`, `isCurrent == false`.
3. **`ownWorktreeReportsIsCurrent`** — call `siblingWorktree(holding: "main", at: repo.url.path)`.
   `#expect` `path == repo.url.path`, `isCurrent == true`, `isMainWorktree == true`.
4. **`unheldBranchReportsNothing`** — `try repo.branch("idle")` (creates the ref, checked out
   nowhere). `#expect(try siblingWorktree(holding: "idle", at: repo.url.path) == nil)`.
5. **`detachedWorktreeHoldsNoBranch`** —
   `let wt = try repo.addWorktree(named: "det", branch: "doomed")`, then detach it:
   `try GitProcess().run(["checkout", "-q", "--detach"], workingDirectory: wt.path)`.
   `#expect(try siblingWorktree(holding: "doomed", at: repo.url.path) == nil)`.
6. **`fullRefNameMatchesShortName`** — with the `feature` worktree present, `#expect` that
   `siblingWorktree(holding: "refs/heads/feature", at: repo.url.path)` equals
   `siblingWorktree(holding: "feature", at: repo.url.path)` and is non-nil.

**The deliverable existed, correct and byte-identical to the issue's block, in about two minutes** —
six reads of files whose signatures the issue had already pasted, then two writes. Zero
signature-hunting. All four mutations killed by the test the issue named.

The remaining twelve minutes and twenty-one edits went on one thing, and it is the useful finding:
**the issue asserted a fact that was not true.** It said `FixtureRepository.url` and
`WorktreeContext.canonicalize` were comparable. They were not — `canonicalize` used
`resolvingSymlinksInPath()`, documented to **strip** a leading `/private`, while `FixtureRepository.url`
was changed to `realpath(3)` earlier the same day. Stashing the model's fix drops the new suite to six
failures, so it is load-bearing.

**Every existing test hid it**, because they all call `canonicalize` on *both* sides of a comparison.
The defect only surfaced the first time a test compared a canonicalized path against a raw
`repo.url.path`.

So the lesson is narrower than "measure the facts": **a pasted-signature issue is only as good as its
weakest asserted fact**, and the ones about path identity deserve the same measurement the porcelain
records got. That is the difference between this round and #0108, which needed no hand finish — the
same format, and one unmeasured claim was the entire cost.

The hand finish repaired what the fix left behind:

- `realpath(3)` returns nil for a path that does not exist, and the fallback did no symlink resolution
  at all — `/tmp/x` stayed `/tmp/x` while `/tmp` alone resolved to `/private/tmp`. It now resolves the
  deepest existing ancestor and re-appends the tail, with a test covering both.
- `WorktreeRemove.swift` had its own `canonicalize` still on the stripping form, under a doc comment
  claiming it matched `WorktreeContext` "so /private/var paths compare correctly". It delegates now.
- Two fixture helpers were dead code that force-unwrapped `oids` and destroyed the repository in a
  `defer` before returning it.
