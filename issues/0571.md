## Description

Each local branch row in the sidebar carries the #0372 status, for example
`↑1 vs origin/main · not merged`. Two parts of it go stale: the ahead/behind numbers and the
merged state. `RepositorySidebarView` reads them in a `.task` keyed on the **worktree path**
alone:

```swift
        .task(id: summary.currentWorktreePath) {
            …
            guard let path = summary.currentWorktreePath else { return }
            branchStatus = nil
            contentStates = nil
            guard let report = try? await BranchStatus.read(at: path) else { return }
            branchStatus = report
            contentStates = try? await BranchStatus.contentPass(for: report, at: path)
        }
```

`ContentView.refreshAfterMutation` hands the sidebar a new `RepositorySidebarSummary` after
every commit, amend, push, fetch, pull, switch, stash and undo. The path in it does not change,
so the task never runs again. The row keeps whatever it read when the window opened, until the
repository is opened again.

### Measured (VM, 2026-09-30, a throwaway hardening spike on the switch fixture)

- **Before the commit**, the `switch-main` row reads `in sync vs origin/switch-main`.
- The spike stages `notes.txt` and commits `audit commit` with ⌘↩.
- The header then reads `On branch switch-main · 1 ahead of origin/switch-main`.
- **After a further 3 s** the row **still** reads `in sync vs origin/switch-main`, and no
  `↑1 vs origin/switch-main` text exists anywhere in the window.
- Screenshot: `issues/0569/0571-sidebar-in-sync-after-commit.png`.

## The change — one file, `YardKit/Sources/YardUI/RepositorySidebarView.swift`

Key the task on the refs as well as the path. `RefSnapshot` is `Equatable` (checked:
`public struct RefSnapshot: Sendable, Equatable`), which is all `.task(id:)` needs. Any commit,
push, fetch or undo moves a ref, so the key changes and the status is re-read. A repository
switch still clears the old numbers first; a refresh of the same repository keeps them on screen
until the new ones land, so the row does not flicker.

1. Add, next to the other `@State` properties (after `contentStates`):

```swift
    /// #0571: the worktree `branchStatus` was read for. A refresh of the
    /// same worktree keeps the old numbers on screen until the new ones
    /// land; a different worktree clears them first.
    @State private var branchStatusPath: String?
```

2. Add this private type inside `RepositorySidebarView`:

```swift
    /// #0571: what the branch status is re-read for — the worktree, and
    /// every ref, since a commit, push, fetch or undo moves one.
    private struct BranchStatusKey: Equatable {
        let path: String?
        let refs: RefSnapshot
    }
```

3. Replace the `.task(id: summary.currentWorktreePath) { … }` block quoted above with:

```swift
        .task(id: BranchStatusKey(path: summary.currentWorktreePath, refs: summary.refs)) {
            // #0372: the synchronous-load read is one `for-each-ref` process
            // (decision 27's budget); the content pass is the background
            // fill that lands after the rows appear. #0571: re-read whenever
            // a ref moves, not only when the worktree changes; a repository
            // switch must not show the previous repository's numbers for a
            // moment, so only a new path clears them first.
            guard let path = summary.currentWorktreePath else { return }
            if branchStatusPath != path {
                branchStatus = nil
                contentStates = nil
                branchStatusPath = path
            }
            guard let report = try? await BranchStatus.read(at: path) else { return }
            branchStatus = report
            contentStates = try? await BranchStatus.contentPass(for: report, at: path)
        }
```

`RefSnapshot` comes from `YardGit`, which the file already imports.

## Verification

### VM spike — `SwitchyardUITests/0571SidebarStatusUITests.swift`, new

```swift
// 0571SidebarStatusUITests.swift
//
// #0571: the sidebar's branch status follows a commit — the switch
// fixture's switch-main reads "in sync" until a commit makes it ↑1.

import XCTest

final class Spike0571SidebarStatusUITests: XCTestCase {
    @MainActor
    func testTheBranchRowCountsACommit() {
        let app = XCUIApplication()
        app.launchWithSwitchFixture()
        XCTAssertTrue(app.text(containing: "in sync vs origin/switch-main").waitForExistence(timeout: 30),
                      "switch-main does not start in sync with origin")
        let stage = app.buttons["stage-file-notes.txt"]
        XCTAssertTrue(stage.waitForExistence(timeout: 30), "notes.txt has no Stage button")
        stage.click()
        XCTAssertTrue(app.changesRow("notes.txt", staged: true).waitForExistence(timeout: 30),
                      "notes.txt was not staged")
        let editor = app.textViews["commit-message"]
        editor.click()
        editor.typeText("0571 commit")
        app.buttons["commit-button"].click()
        XCTAssertTrue(app.header(beginningWith: "On branch switch-main · 1 ahead").waitForExistence(timeout: 30),
                      "the commit did not land")
        XCTAssertTrue(app.text(containing: "↑1 vs origin/switch-main").waitForExistence(timeout: 30),
                      "the sidebar row still does not count the commit")
        let shot = XCTAttachment(screenshot: app.windows.firstMatch.screenshot())
        shot.name = "0571-sidebar-ahead"
        shot.lifetime = .keepAlways
        add(shot)
    }
}
```

## Mutation the review runs

Change the task's id back to `summary.currentWorktreePath`. The spike fails at the `↑1` assertion.

## Expected behavior

After any in-app operation that moves a ref, each branch row's ahead/behind and merged state
match the header, with no reopen needed. Opening another repository still never shows the
previous repository's numbers.
