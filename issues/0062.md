## Description

Split a commit into two along a hunk boundary, non-interactively — the operation `git rebase -i`
makes agents fail at, because it wants an editor and a shell.

## Expected behavior

- [ ] Splits at a specified hunk boundary using the stable hunk IDs from #0016.
- [ ] Both resulting commits build the same final tree as the original — asserted by a test.
- [ ] Commit messages for both halves are settable non-interactively.
- [ ] Auto-checkpoints; undo restores exactly.
- [ ] Signed commits stay signed.
