## Description

Split a commit into two along a hunk boundary, non-interactively — the operation `git rebase -i`
makes agents fail at, because it wants an editor and a shell.

## Expected behavior

- [ ] Splits at a specified hunk boundary using the stable hunk IDs from #0016.
- [ ] Both resulting commits build the same final tree as the original — asserted by a test.
- [ ] Commit messages for both halves are settable non-interactively.
- [ ] Auto-checkpoints; undo restores exactly.
- [ ] Signed commits stay signed.

## Planning pass — 2026-09-09, to code level. One round.

**The mechanism** (per #0060's decision — `commit-tree` walk, no rebase engine): split rewrites one
commit `C` (default `HEAD`) into two, along a hunk boundary named by #0016's stable hunk ID —

1. **Locate**: `commitDiff(C)` (Hunks.swift, the `diff-tree --root -p --cc` path that handles root
   and merge shapes) is parsed into hunks; the caller names one by its stable content-derived id.
   Unknown id = typed refusal, nothing touched.
2. **First half**: reset the index to `C^` (or the empty tree for a root commit), apply ONLY the
   chosen hunk's patch `--cached`, and create commit `A` with parent `C^` via
   `git commit-tree` + explicit `-S` when signing is in effect (the #0060 rule: never
   config-reliant). Message `--first <msg>` (default: C's original).
3. **Second half**: apply the REMAINING hunks on top, create commit `B` with parent `A`, message
   `--second <msg>` (default: C's original). `B`'s tree must equal `C`'s tree — the criterion
   asserted by a test, checked before the ref moves.
4. **Move the ref**: descendants of `C` (if any) are replayed with `git cherry-pick` onto the new
   pair, then the branch ref moves once via `update-ref --stdin` — until it moves, any failure
   leaves history untouched. Whole operation inside one `JournalCheckpoint.around(operation:
   "split")`; conflicts leave the pick in progress (resumable, exit 8).
5. **Signing**: `CommitCreate.Signing` forwarded to both halves and the replay — explicit-flag
   rule, never config.
