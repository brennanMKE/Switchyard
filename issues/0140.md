## Description

**M1 exit criterion served (guide §9, criterion 3):** "Every failure mode returns a structured error
carrying the exit code from §6 — not a trap, and not a success value with empty fields."

Measured on a scratch copy of `main` (`e0327cc`), 2026-08-07 — `whereAmI` on an empty temp
directory returns, with no error:

```
WhereAmI(branch: nil, upstream: nil, ahead: nil, behind: nil, isMidRebase: false,
isMidMerge: false, isMidCherryPick: false, stashCount: 0, untrackedCount: 0,
unstagedCount: 0, stagedCount: 0, hasConflicts: false, conflictCount: 0,
headOID: "", rawHead: "")
```

That is the criterion's exact forbidden shape. The cause: every probe in
`YardKit/Sources/YardGit/WhereAmI.swift` degrades individually — `try? git.run` falls back to
`""`/`false`, and every `git.capture` guard returns `nil`/`0` on a non-zero exit — so "git said
fatal: not a git repository fifteen times" and "a quiet repository" produce the same value.

**One deliverable: `whereAmI` throws `WorktreeContext.Error.notARepository` on a non-repository,
via a `WorktreeContext.resolve` gate at the top of the function, with tests pinning both sides of
the line** (a non-repository throws; an empty-but-real repository still returns the legitimate
empty state). Engine + tests only — no `CommandSpec`, no `runYard` arm, no CLI wiring (M3, guide
§11 decision 11), and **no exit-code mapping** (#0141 owns mapping engine errors to §6 codes; do
not absorb it here).

### Why this error type and this gate — decided

- `WorktreeContext.Error.notARepository(path:detail:)` already exists and already means exactly
  this. `worktreeWhere` and `siblingWorktrees` gate through `WorktreeContext.resolve` today, so
  reusing it keeps one not-a-repository vocabulary; a new `WhereAmIError` would add a second for
  no gain.
- The other engine reads need no gate: `commitLog`, `conflicts`, `hunks`, and `worktreeStatus`
  issue their primary command through `try git.run(...)`, which throws
  `GitProcess.Failure.exited` on a non-repository (audited 2026-08-07). `whereAmI` is the outlier
  because *every* probe in it is individually tolerant.
- Resolving `WorktreeContext` first is what CLAUDE.md requires anyway ("resolved once per
  invocation"). The context value is discarded on purpose: the probes below already shell through
  `git -C path` and `rev-parse --git-path`, which is worktree- and reftable-correct, and threading
  the context through them is not this issue.
- The gate distinguishes non-repository from **empty repository** by asking git, not by inspecting
  fields: `git rev-parse --git-dir` succeeds in a `git init`-with-no-commits repository, so
  `resolve` succeeds there and the existing empty-state contract (`branch: "main"`,
  `headOID: ""`) is untouched. Mutation 2 proves the distinction is pinned.

## Change 3 — `YardKit/Tests/YardGitTests/FailingGitFixture.swift`, replace the whole file (existing file: use the `write`/`edit` tool, never `cat >` — Rule 5c)

The complete new content:

```swift
// FailingGitFixture.swift

import Foundation
import Testing
@testable import YardGit

/// Pins the count-closure defaults: every count field lands at zero when git
/// runs but exits non-zero. This is the anchor for the "`return 0` mutated to
/// 99" mutation — changing any default flips the first test red.
///
/// Before #0140 this file wired `/usr/bin/false` in as git. The
/// not-a-repository gate resolves `WorktreeContext` first, and a git that
/// cannot answer `rev-parse` is indistinguishable from no repository — so a
/// git that fails *everything* now throws at the gate (the second test pins
/// exactly that). To keep the count defaults reachable, the first test uses a
/// shim that answers `rev-parse` with the real git and exits 1 for every
/// other command, run against a real repository.

/// Writes an executable shim script that passes `rev-parse` invocations
/// through to `/usr/bin/git` and exits 1 for everything else. Returns the
/// shim's path; the caller owns (and removes) the containing directory.
private func writeRevParseOnlyShim(in dir: String) throws -> String {
    let shimPath = dir + "/git-shim.sh"
    let script = """
    #!/bin/sh
    case "$*" in
      *rev-parse*) exec /usr/bin/git "$@" ;;
      *) exit 1 ;;
    esac
    """
    try script.write(toFile: shimPath, atomically: true, encoding: .utf8)
    try FileManager.default.setAttributes(
        [.posixPermissions: 0o755], ofItemAtPath: shimPath)
    return shimPath
}

@Test func countsAreZeroWhenGitRunsNonZero() throws {
    // The production code that reads stash/untracked/staged/unstaged counts
    // does not care whether the command failed to launch; it only cares about
    // the exit code and uses `0` for both failure modes. We check all four so
    // a mutation that replaces any single `return 0` with another value (99,
    // for instance) must fail this test rather than continuing green.

    let repo = try FixtureRepository.linear()
    defer { repo.destroy() }

    let shimDir = NSTemporaryDirectory() + "yard-fail-git-\(UUID().uuidString)"
    try FileManager.default.createDirectory(
        atPath: shimDir, withIntermediateDirectories: true)
    defer { try? FileManager.default.removeItem(atPath: shimDir) }

    let git = GitProcess(executablePath: try writeRevParseOnlyShim(in: shimDir))
    let info = try whereAmI(path: repo.url.path, git: git)

    #expect(info.stashCount == 0, "stash count must be zero when git runs non-zero")
    #expect(info.untrackedCount == 0, "untracked count must be zero when git runs non-zero")
    #expect(info.stagedCount == 0, "staged count must be zero when git runs non-zero")
    #expect(info.unstagedCount == 0, "unstaged count must be zero when git runs non-zero")
}

@Test func fullyFailingGitThrowsAtTheGate() throws {
    // `/usr/bin/false` launches and exits 1 for everything, including the
    // `rev-parse` calls `WorktreeContext.resolve` makes — so even inside a
    // real repository the gate cannot tell it from "not a repository" and
    // throws rather than returning a success value built from failures.
    let repo = try FixtureRepository.linear()
    defer { repo.destroy() }

    let git = GitProcess(executablePath: "/usr/bin/false")
    #expect(throws: WorktreeContext.Error.self) {
        _ = try whereAmI(path: repo.url.path, git: git)
    }
}
```

Why the shim, not `/usr/bin/false`: the old fixture's whole point is that the count closures
default to 0 on a non-zero git exit, and under the gate a git that fails `rev-parse` never
reaches them (Given 4). Passing `rev-parse` through satisfies the gate (and the `--git-path`
probes, which is fine — the counts are what this file pins) while `stash list`, `ls-files`, and
both `diff-index` calls still exit 1. The test's temp directory holds only the shim script; the
repository is a real `FixtureRepository`.
