## Description

**Child of #0380.** **Question:** when a SwiftUI menu `Button` is `.disabled(true)` and carries
`.help("…")`, does macOS show that text as a tooltip on hover — in a context menu, and in a menu-bar
menu?

**Why it matters:** #0359 delivers every disabled item's reason (for example "Already the newest
commit on “main”") through `.help`, and #0360–#0363 add more reasons the same way. If the tooltip
never appears, every reason is invisible.

### Build

Tab **0381 help** of #0380's spike app, and the last item of the menu bar's **Spike** menu.

### Observe

1. Right-click the tab's text. Hover **Disabled With Help** for 3 seconds, then **Enabled With Help**
   for 3 seconds.
2. Open **Spike** in the menu bar and hover **Disabled With Help** for 3 seconds.

For each of the three items, record whether a tooltip appeared and its text.

### Pass or fail, and what changes

- **Pass** — both disabled items show their help text. #0359 is unchanged; note "confirmed by #0381"
  beside its `.help` paragraph.
- **Fail** — neither disabled item shows a tooltip. #0359's re-plan picks one of:
  - **(a)** keep the item enabled and show the reason in an alert when it is chosen. The reason is
    always reachable, but the menu stops showing which actions are possible.
  - **(b)** add an always-disabled second line under the item carrying the reason in secondary text.
    Visible, but it doubles the menu's height.
  - **(c)** set `NSMenuItem.toolTip` through AppKit. Native, but SwiftUI menus expose no bridge to it.
- **Partial** (one menu only) — record which menu failed; the same options apply to that menu.
