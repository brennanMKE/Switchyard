This is the #0481 audit's shape 2, and #0482 and #0487 fix it elsewhere. A diff body line is a marker
scalar (` `, `-`, `+`, `\`) followed by the file's own line. When the file's line opens with a
combining mark (U+0301), Swift fuses the marker and the mark into **one `Character`**. So
`line.first` is `"+\u{301}"`, never `"+"`, and `line.hasPrefix("+")` is false. Both were measured
with `swift` 6 on 2026-09-29. The fix everywhere is `line.unicodeScalars.first`. Where the text
after the marker is used, it is `Substring(line.unicodeScalars.dropFirst())`, not
`line.dropFirst()`, because #0487's second mutation shows `dropFirst()` drops the mark along with
the marker.

Sites, as they stand on `main` at `b39dd314` or in the named issue's planned code:

| file | site | effect of the bug |
|---|---|---|
| `YardKit/Sources/YardGit/LineStaging.swift` (new in #0476) | `hunk.body[index].first` and `raw.first` as the marker (issue text lines 189, 199, 456) | a `+\u{301}x` / `-\u{301}x` line is not recognised as a changed line, so it cannot be selected and staged, and a patch built around it may be wrong |
| `YardKit/Sources/YardUI/DiffLineSelection.swift` (new in #0479) | `hunk.body[line].first` (issue text line 91) | the line cannot be clicked into a selection |
| `YardKit/Sources/YardUI/FileDiffView.swift:107` | `DiffLineView.marker` is `line.first` | the line gets no green or red tint |
| `YardKit/Sources/YardUI/SplitCommitSheet.swift:181` | `previewLines` filters on `hasPrefix("+")` / `hasPrefix("-")` | the line is missing from the split sheet's three-line preview |

The planning pass should reproduce each one before changing it. `LineStaging` and
`DiffLineSelection` can be reproduced with a fixture like #0482's: a 20-line file whose line 2 is
`"\u{301}b"`, edited to `"\u{301}B"`. `FileDiffView` and `SplitCommitSheet` are private view code
with no test seam. Either lift the marker read into a `nonisolated` helper that a test can reach,
or record that no test covers those two sites.
