## Description

**Finding 1 of the M1 milestone review, seventh pass, 2026-08-18 — and the first M1 finding against
criterion 3 rather than criterion 5.** Three engine functions have a failure mode that returns a
**success value with empty fields**, and nothing detects it.

Deleting each `guard output.exitCode == 0 else { throw … }` leaves the full suite green —
`Test run with 1092 tests in 78 suites passed`, three separate runs:

| file:line | function | what the mutant returns |
|---|---|---|
| `YardKit/Sources/YardGit/WorktreeList.swift:84-86` | `worktreeList` | `[]` |
| `YardKit/Sources/YardGit/WorktreeWhere.swift:57-59` | `yardWhere` | a result with `mainWorktreePath == nil` |
| `YardKit/Sources/YardGit/WorktreeRepair.swift:36-41` | `WorktreeRepair.run` | `[]` |

**Criterion 3 forbids exactly this** — *"not a trap, and not a success value with empty fields"* — and
the compliant and forbidden implementations are today indistinguishable to the suite.

**Why nothing catches it.** Every existing reference to these three error values **constructs them
directly**: `ExitClassCoverageTests.swift:52,54,55`, `ExitClassWireTests.swift:187,217,230,246,248,249`,
`DescriptionCoverageTests.swift:194,200,215`. Those pin each error type's exit class and description —
never that the engine ever *reaches* it.

**This is an outlier, not the house standard**: `WorktreeRemoveTests.swift:246`, `CommitCreateGPGTests`
and `FixupTests` all assert throws from real engine calls.

## The fixtures already exist — measured by the review, which wrote and ran the probes both ways

- **`worktreeList` and `WorktreeRepair.run`**: point them at an **empty directory**. `git` exits 128,
  `not a git repository`. Both probes pass on pristine and fail under the mutation with
  *"an error was expected but none was thrown"*.
- **`yardWhere`** needs `rev-parse` to succeed while `worktree list` fails — and that shim is **already
  in the test target**: `writeRevParseOnlyShim` at
  `YardKit/Tests/YardGitTests/FailingGitFixture.swift:22`. The probe passes on pristine, fails under the
  mutation.

## Expected behavior

- [ ] A named test per site — three in all — asserting the engine function **throws** when its
      underlying `git` command exits non-zero. Use `#expect(throws:)` against the concrete error type,
      not merely "some error", so the classification is pinned too.
- [ ] **Reuse `writeRevParseOnlyShim`** for `yardWhere` rather than writing a second shim.
- [ ] **Mutation, one per site:** delete that site's `guard output.exitCode == 0`. Each must redden its
      own test and no other. Confirm each landed where you meant.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, above the count in `docs/test-baseline.txt`.
