## Description

`HunkParser.parse` (`YardKit/Sources/YardGit/Hunks.swift`, line 183 on `main`) splits `git diff`
output with `text.split(separator: "\n", omittingEmptySubsequences: false)`. That splits on the
`"\n"` **Character**. Swift treats `"\r\n"` as a single Character (one grapheme cluster), so it never
equals `"\n"` and a CRLF line is never split.

Measured 2026-09-29 on `main` (git 2.54.0), through `listHunks`: a repository with `a.txt` =
`"a\r\nb\r\nc\r\n"` and `b.txt` = `"x\ny\n"`, both then edited (`b` → `B`, `y` → `Y`), unstaged:

- **before:** `files.map(\.path) == ["a.txt"]`. `a.txt`'s one hunk has the body
  `[" a\r\n-b\r\n+B\r\n c\r\ndiff --git a/b.txt b/b.txt", "index …", "--- a/b.txt", "+++ b/b.txt",
  "@@ -1,2 +1,2 @@", " x"]`. The CRLF body became one line, so the header's counts were never used
  up and the hunk swallowed the next file. `b.txt` is missing from the Changes view's diff.
- **after this change:** `["a.txt", "b.txt"]`, bodies `[" a\r", "-b\r", "+B\r", " c\r"]` and
  `[" x", "-y", "+Y"]`.

A scratch check in Swift confirms the cause: `"@@ -1,2 +1,2 @@\n a\r\n-b\r\n+B\r\n"` splits into 2
pieces by Character and 5 by `unicodeScalars`.

The fix splits on the `unicodeScalars` view instead. Each piece is a
`Substring.UnicodeScalarView`, turned back into a `String` through `Substring`. Everything else in
the parser is unchanged: each line keeps its trailing `"\r"`, which is what `git apply` needs to
match the file (#0476's CRLF case measures that). Hunk ids are unaffected for LF files; for a CRLF
file they were computed from a mis-parsed body and now come from the right one.

This is the prerequisite for line selection (#0474): with the bug, a CRLF hunk has one selectable
"line".

## The files

### 1. `YardKit/Sources/YardGit/Hunks.swift` — in `HunkParser.parse`

Replace

```swift
        for lineSub in text.split(separator: "\n", omittingEmptySubsequences: false) {
            let line = String(lineSub)
```

with

```swift
        // Split on the newline *scalar*, not the `Character`: Swift reads
        // "\r\n" as one Character, so a Character split leaves a CRLF
        // file's lines joined and its hunk swallows every file after it
        // (#0475, measured).
        for lineSub in text.unicodeScalars.split(separator: "\n", omittingEmptySubsequences: false) {
            let line = String(Substring(lineSub))
```

```swift
// MARK: - #0475: CRLF lines

/// Swift reads "\r\n" as one `Character`, so a parser that splits on the
/// "\n" Character never splits a CRLF line: the file's whole body became one
/// line, its counts were never consumed, and the hunk swallowed every file
/// after it (measured on `main`: `files.map(\.path) == ["a.txt"]`).
@Test func aCRLFFileSplitsIntoItsLinesAndTheNextFileStillLists() throws {
    var repo = try FixtureRepository()
    defer { repo.destroy() }
    try repo.build([.init("base", files: ["a.txt": "a\r\nb\r\nc\r\n", "b.txt": "x\ny\n"])])
    try repo.writeUntracked(["a.txt": "a\r\nB\r\nc\r\n", "b.txt": "x\nY\n"])

    let files = try listHunks(at: repo.url.path, area: .unstaged)

    #expect(files.map(\.path) == ["a.txt", "b.txt"])
    #expect(files.first?.hunks.map(\.body) == [[" a\r", "-b\r", "+B\r", " c\r"]])
    #expect(files.last?.hunks.map(\.body) == [[" x", "-y", "+Y"]])
}
```
