## Description

Three doc comments in `YardKit/Sources/YardGit/WhereAmI.swift` describe commands the code does not
run. Small, but this is the file an agent-facing command is built on, and a comment that names the
wrong git plumbing sends the next reader to the wrong manual page.

Filed rather than folded into #0012's round 3, which is deliberately scoped to a test-file repair
after two timeouts.

## Givens — verified on `main`, treat as true

1. `rawHead`'s comment claims a `"ref: refs/heads/main"` form. The code always calls
   `git rev-parse HEAD`, so the value is always a SHA or empty.
2. `unstagedCount` and `stagedCount` comments say `git diff --name-status`. The code uses
   `git diff-index`.

## Expected behavior

- [ ] Each comment names the command actually run and describes the actual return shape.
- [ ] No behaviour changes. This is comments only.
- [ ] `cd YardKit && swift build` succeeds and `swift test` prints a `Test run with N tests` line you
      paste. **N must equal 181**, the count on `main` — a comment change must not move it.

## Notes

If a comment and the code disagree, **change the comment**. Do not "fix" the code to match a comment;
the code's behaviour is covered by tests and the comment is not.

## Review — round 1 fixed three comments and invented three others

Exit 0 in 181s. Every stated criterion passed: 181 tests exactly, no executable line changed (proven
by `git diff -U0 | grep -vE '^[+-][[:space:]]*///'` returning nothing), no other file touched, no
scope violation. It did not reach for `/tmp`.

**And the file is now less accurate than before.** The three corrections are right — `git rev-parse
HEAD`, `git diff-index`, SHA-or-empty — and each was padded with confident elaboration that is simply
untrue:

1. **`unstagedCount`** gained: *"The code passes the index bytes it built from `ls-files` instead of
   relying on the on-disk index, so `-z` is preferred for correctness against paths with whitespace or
   newlines."* The code runs `git diff-index --name-status HEAD` against the on-disk index, passes no
   stdin, never uses `-z`, and splits stdout on `"\n"`. **Every clause is false.** This replaces one
   wrong comment with a longer, more plausible wrong comment.

2. **`stagedCount`** gained: *"there is no index cache, so the two numbers should match in practice."*
   `--cached` and plain `diff-index` are different comparisons and the counts routinely differ — that
   is why both fields exist. **False and actively misleading.**

3. **`rawHead`** gained: *"callers should treat a SHA length of less than 7 as 'unborn' rather than
   relying on this property."* No length check exists anywhere; unborn is signalled by the empty
   string, which line 121 returns. **Invented API advice.**

One added claim was checked and is **true** — a non-zero exit on a fresh repository yields zero files,
because `GitProcess.capture` returns `Output` without throwing (only `run` throws). Keep that one.
