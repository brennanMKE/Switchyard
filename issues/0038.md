## Description

Commit, optionally from a specific hunk set, optionally signed, optionally carrying agent
provenance. A signed commit carrying provenance trailers is a meaningfully stronger claim about who
wrote code than an unsigned one, and no existing client offers it.

Trailers follow the `Co-authored-by` convention so existing tooling ignores them gracefully:

```
Agent-Name: claude-code
Agent-Model: claude-opus-5
Agent-Session: 01J8X...
```

## Expected behavior

- [ ] `-m`, `--sign`, `--hunk ID...`, `--agent`, `--model`, `--session` all implemented.
- [ ] Auto-checkpoints before running, so `yard undo` works without the caller having asked.
- [ ] Never invokes `GIT_EDITOR` under any circumstance, including a missing `-m`.
- [ ] Trailers are covered by the signature — written before signing, not appended after.
- [ ] Trailer format documented in `docs/provenance.md`.
- [ ] Repository hooks run — `pre-commit` and `commit-msg` are not skipped.

**What remains here: provenance trailers on a commit, covered by the signature.**

### Measured, 2026-08-17, git 2.50.1 — `git commit --trailer` does exactly what is needed

```
git commit -m "subject line" \
  --trailer "Agent-Name: claude-code" \
  --trailer "Agent-Model: claude-opus-5" \
  --trailer "Agent-Session: 01J8X"
```

produces this commit body, byte-for-byte (`od -c` of `%B`):

```
subject line\n\nAgent-Name: claude-code\nAgent-Model: claude-opus-5\nAgent-Session: 01J8X\n\n
```

Three facts that make this the right mechanism rather than string-concatenating the message ourselves:

1. **Git inserts the blank-line separator itself** — `-m "third" --trailer "Agent-Name: x"` yields
   `third\n\nAgent-Name: x\n\n`. Building the block by hand means re-deriving that rule.
2. **Order is preserved as given**, verified with `%(trailers:key=…)`.
3. **An existing trailer block is extended, not duplicated.** A message already ending in
   `Signed-off-by: someone <s@e>` gained `Agent-Name:` *inside the same block*, with no second blank
   line. Hand-built concatenation gets this wrong in exactly the case that matters — a `-m` message the
   caller already gave trailers to.

**Signature coverage comes free and is the reason to use `--trailer` at all**: git assembles the full
message *before* writing the commit object, so any signature is over the final message by construction.
Appending trailers after the fact would require rewriting the commit and would invalidate the signature —
which is what this issue's criterion is guarding against. **This cannot be tested here**: verifying a
signature needs a signing key, and creating one is forbidden (CLAUDE.md, Code signing). State the
argument in the doc comment and leave it untested rather than faking it.

## Change 1 — `YardKit/Sources/YardGit/CommitCreate.swift`

`run` gains a `trailers:` parameter, defaulting to empty so every existing call site is unchanged:

```swift
    /// Provenance trailers to attach, in order. Passed as `--trailer`, never
    /// concatenated into `message`: git inserts the blank-line separator
    /// itself, preserves the given order, and **extends an existing trailer
    /// block rather than starting a second one** — all measured (#0038). It
    /// also assembles the whole message before writing the object, so a
    /// signature covers the trailers by construction; appending them
    /// afterwards would mean rewriting the commit and invalidating it.
    public static func run(
        message: String,
        signing: Signing = .config,
        trailers: [Trailer] = [],
        in workingDirectory: String,
        git: GitProcess = GitProcess(),
        extraEnvironment: [String: String] = [:]
    ) throws -> CommitCreate {
        let args = ["commit", "-m", message]
            + trailers.flatMap { ["--trailer", $0.description] }
            + arguments(for: signing)
```

`Trailer` already exists (`CommitLog.swift:61`) with `key`, `value` and a `description` of
`"\(key): \(value)"`, which is exactly `--trailer`'s expected form. **Reuse it — do not declare a second
trailer type.**

## Change 2 — tests in `YardKit/Tests/YardGitTests/CommitCreateTests.swift`

1. `provenanceTrailersLandInTheCommitBody` — commit with the three trailers from `docs/provenance.md`,
   then assert `git log -1 --format=%B` equals the measured bytes above **exactly**, and that
   `%(trailers:key=Agent-Name)` returns the value. Asserting the whole body rather than "contains" is
   what pins the separator and the ordering.
2. `trailersExtendAnExistingBlockRatherThanStartingASecond` — a `-m` message already ending in
   `Signed-off-by: someone <s@e>`, plus one `--trailer`, asserting the result has **one** blank line
   before the block and both trailers in it. This is the case hand-built concatenation gets wrong.
3. `noTrailersLeavesTheMessageUnchanged` — the default path, asserting the body is exactly the message.
