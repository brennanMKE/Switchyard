## Description

Apply #0129's settled wire pattern (Decisions 1–8) to the status and conflicts payloads:

| type | source file | traps |
|---|---|---|
| `WorktreeStatus`, `WorktreeStatusEntry` (+ nested `State`, `SubmoduleState`) | `YardKit/Sources/YardGit/WorktreeStatus.swift` | `WorktreeStatus`, `WorktreeStatusEntry`, and `State` declare no `Sendable`; public types get no implicit `Sendable` across module boundaries, so `EncodableResult`'s `Encodable & Sendable` bound fails without adding it. Verify by compiling at planning time. |
| `ConflictedFile` (+ nested `StageEntry`, `Kind`) | `YardKit/Sources/YardGit/Conflicts.swift` | already `Sendable` throughout |

Wire decisions that land here:

- **`pathBytes` and `originalPathBytes` are not encoded** (#0129 Decision 6) — the wire carries
  the lossily-decoded `path` / `originalPath` strings only. `CodingKeys` therefore deliberately
  omits those members; the literal tests must include a non-ASCII path to pin the decoded form.
- `WorktreeStatusEntry.State` and `ConflictedFile.Kind` are String-raw enums and encode as their
  raw values (`"M"`-family and `"UU"`-family strings, #0129 Decision 5).
- `SubmoduleState` encodes as an object of its three stored Bools (`commitChanged`,
  `hasModifications`, `hasUntracked`); the computed `isSubmodule`-style conveniences and
  `WorktreeStatusEntry`'s var defaults follow Decision 7 (stored properties only).
- `WorktreeStatus` is a wrapper around `entries` — decide at planning time whether it encodes as
  `{"entries":[…]}` or as a bare array, and pin it with a literal.

## Expected behavior (re-author to code level before dispatch, per CLAUDE.md)

- [ ] Each type gains `Encodable` (+ `Sendable` where listed above) with an explicit `CodingKeys`
      enum; nil optionals omitted, never `null`.
- [ ] Literal-JSON tests in `YardKit/Tests/YardWireTests/StatusConflictsWireTests.swift`,

      real run at planning time.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line; N must exceed the
      pre-change baseline by exactly the number of new tests, both counts settled and stated at
      planning time.
