## Description

**Finding of #0160's twelfth umbrella review, 2026-08-18.** `RewriteMapping.composing(with:)`'s
duplicate-suppression bookkeeping is unpinned, and a regression there stores the pre-operation `HEAD`
mapped to **an intermediate commit that never survived the operation**.

`YardKit/Sources/YardGit/JournalEntryMetadata.swift:189`, inside `composing(with:)` (`:183-198`):

```diff
- chainedFrom.insert(index)
+ chainedFrom.insert(-1)
```

`✔ Test run with 1129 tests in 80 suites passed after 56.113 seconds.` — **full suite, zero failures.**

`chainedFrom` records which of `self`'s pairs `next` consumed by chaining, so `unconsumed` omits them.
Break it and every chained pair is **also** re-emitted.

**Measured** against the production invocation sequence — the standalone `amend` and the final `rebase`,
with the mid-rebase `amend` dropped exactly as a live `isMidRebaseAmend` drops it:

```
pristine   STORED source=rebase count=2
             9f796fd2 -> bb9c03d8
             f7e2d15a -> bb9c03d8      (headBefore -> result.head)

mutated    STORED source=rebase count=3
             fca5165c -> b4f635da
             574ed0a7 -> b4f635da      (headBefore -> result.head)
             574ed0a7 -> 50f8d252      (headBefore -> the INTERMEDIATE commit)
```

`headBefore` now maps to **two different new oids**, one of them the commit the standalone `--fixup`
amend produced and the rebase then replaced — **a commit no ref in the resulting history reaches.**
That is exactly the wrongness #0233 and #0234 exist to eliminate: #0233 keeps intermediate oids out of
the store, #0234 composes so the chain collapses to `headBefore → head`. **`chainedFrom` is the only
thing keeping the intermediate pair from returning through `unconsumed`, and nothing asserts it.**

## Why nine passes missed it — worth knowing, not just recording

**The complementary mutation *is* killed.** Dropping `unconsumed` entirely reddens
`attachingAnExistingCommitFixupMappingKeepsThePreCheckpointHeadReachable:972`. But it is killed by a
**test-replay artifact**: that test attaches all *three* logged invocations, including the mid-rebase
`amend` that a live `isMidRebaseAmend` filters out. **In the real two-invocation sequence `unconsumed`
is always empty**, so the test constrains the "too few pairs" direction and never observes "too many".

The tenth pass looked here and recorded only the **order** of `composedRewrites + unconsumed` as a
proposal. The **content** question is a different one, and it is the one with teeth.
