# 0473 — Undo does not restore worktree bytes byte-for-byte under content filters (autocrlf, eol, LFS)

## Description

Measured by the #0467 (Discard) planner on 2026-09-29. `WorktreeSnapshot` hashes worktree files
through git's content filters. Under `core.autocrlf=input`, a CRLF file comes back from
`JournalUndo.undo` with LF line endings. `.gitattributes` `eol`/`text` settings and Git LFS
smudge/clean filters behave the same way. This affects every journaled operation's Undo, not only
Discard, and silently changes the user's files.

## Expected behavior

- [ ] Reproduced first: a CRLF file under `core.autocrlf=input`, an eol attribute, and (if
      measurable locally) an LFS-tracked path, each checkpointed, modified, and undone.
- [ ] `WorktreeSnapshot` captures and restores raw worktree bytes (for example `hash-object
      --no-filters` and a raw write on restore), so all three come back byte-for-byte, with tests
      that fail without the change.

Needs an Opus planning pass before dispatch; read docs/switchyard-git-internals-and-undo.md first.
