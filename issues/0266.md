## Description

**Finding 2 of the M1 milestone review, fourth pass, 2026-08-18.** M1 exit criterion 5 is unmet for
`worktreeAdd`'s `.branch` target: **the `branch` it returns is never asserted.**

`YardKit/Sources/YardGit/WorktreeAdd.swift:159-161`:

```swift
    case let .branch(name):
        branchName = name.hasPrefix("refs/heads/")
            ? String(name.dropFirst("refs/heads/".count)) : name
```

Two surviving mutations, **full unfiltered suite**:

| mutation | result |
|---|---|
| `branchName = name` (drop the `refs/heads/` stripping) | `Test run with 1066 tests in 78 suites passed after 49.468 seconds` |
| `branchName = nil` (return no branch at all) | `Test run with 1066 tests in 78 suites passed after 48.639 seconds` |

**The second is the telling one: the entire `.branch` arm can return `nil` and nothing reddens.**
`WorktreeAddTarget.branch` appears exactly once in the suite — `WorktreeAddTests.swift:91`,
`target: .branch("held")` — and that is the *branch-already-in-use refusal* test, which never reaches
the success path. So `wt new <path> <existing-branch>` has its `branch` wire field entirely unasserted,
and the normalization on lines 160-161 has never been executed by a test.

The first mutation is a wire-shape defect: `wt new` against `refs/heads/feature` would emit
`"branch":"refs/heads/feature"` where every other producer of that field emits the short name —
`WorktreeList.parsePorcelain:135-139`, and the `.newBranch` arm. The contrast is the argument: the
`.newBranch` arm's `branch`/`head` **are** asserted (`WorktreeAddTests.swift:138, 161`), and a mutation
there kills four named tests.

## Expected behavior

- [ ] A named test in `YardKit/Tests/YardGitTests/WorktreeAddTests.swift`: create a branch, add a
      worktree onto it with `target: .branch("feature")` (short name), and assert `result.branch ==
      "feature"` — and assert `result.head` too while the fixture is there, since the same arm produces it.
- [ ] A second assertion, or a second test, passing **`"refs/heads/feature"`** and asserting the result
      is still `"feature"`. That is the half the stripping exists for, and it is the half no fixture
      currently reaches.
- [ ] **Mutation 1:** `branchName = name`. The `refs/heads/` case must redden.
- [ ] **Mutation 2:** `branchName = nil`. Both must redden. Confirm each landed where you meant.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.
