## Description

**Finding 1 of the M1 milestone review, twelfth pass, 2026-08-18.** `gitStatus` **throws** on any
repository configured for copy detection, and the `C` element of git's XY alphabet is unasserted.

`YardKit/Sources/YardGit/WorktreeStatus.swift:69`, mutated `case "R", "C":` → `case "R":`:
**full suite green, 1115 tests.**

**Measured, git 2.50.1** — a copy whose source is also modified, with `status.renames=copies`:

```
2 C. N... 100644 100644 100644 9ce8ef… 9ce8ef… C100 b.txt	a.txt
```

Under the mutation `WorktreeStatusParser` throws `unrecognizedStatusCharacter("C")`, so **`status` fails
outright on that repository** rather than degrading. `C` is a documented element of git's alphabet and
is production behaviour today; nothing can fail on it.

Same shape as #0293 (`color.ui`): real git output that no fixture produces.
