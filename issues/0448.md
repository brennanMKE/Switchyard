# 0448 — Edit ▸ Undo never reaches the journal: `undo:` is always taken by the responder chain

## Description

**The bug, reproduced in the VM on unpatched `main` (8a1ed9eb), 2026-09-28.** In the standard
fixture, select the tip commit and press ⌥⌘R (Revert). The revert commit appears. The Edit menu then
offers **Undo Revert**, enabled and correctly titled from the journal. Choosing it does nothing: the
revert commit stays in History, and no alert appears. `Spike0448UndoReachesJournalUITests` (below)
failed on unpatched `main` with "Edit ▸ Undo Revert left the revert commit in History". The planning
prototype's #0445 spike failed the same way for Undo Commit.

**Cause.** `JournalCommands` (`YardKit/Sources/YardUI/JournalMenu.swift`) does this in both buttons:

```swift
Button(target?.undoTitle ?? "Undo") {
    if NSApp.sendAction(Selector(("undo:")), to: nil, from: nil) { return }
    target?.perform(.undo)
}
```

#0393's spec said to forward `undo:` to the responder chain **only when the first responder is an
`NSText` view**, so that text editors keep their own undo. The implementation forwards
unconditionally. `sendAction` returns `true` whenever any responder in the chain accepts `undo:`, and
with a list or the map focused something does. So the method returns before `target?.perform(.undo)`
ever runs. That something accepts it is inferred from the measured behaviour; *which* responder is
not identified, and does not need to be.

**The fix** gates the forward on the same test the enabled check already uses, factored into one
testable function: `JournalMenu.routesToText(_:)`. Text editing keeps ⌘Z while a text view is
first responder. Otherwise the journal runs.

## The files

### 1. `YardKit/Sources/YardUI/JournalMenu.swift` — two edits

At the end of `public nonisolated enum JournalMenu`, after `redoOperation(in:)`'s closing brace,
add:

```swift

    /// #0448: whether Undo and Redo belong to text editing rather than the
    /// journal — true only while an `NSText` view (a field editor, a
    /// `TextEditor`) is the key window's first responder.
    @MainActor
    public static func routesToText(_ firstResponder: NSResponder?) -> Bool {
        firstResponder is NSText
    }
```

In `JournalCommands.body`, replace from `let editingText = …` through the Redo button's
`target?.perform(.redo)` so it reads exactly:

```swift
        let editingText = JournalMenu.routesToText(NSApp.keyWindow?.firstResponder)
        CommandGroup(replacing: .undoRedo) {
            // #0448: forward only while a text view is first responder.
            // Sent unconditionally, `undo:` found a taker in the responder
            // chain with no text view focused, and the journal never ran
            // (measured in the VM, 2026-09-28).
            Button(target?.undoTitle ?? "Undo") {
                if JournalMenu.routesToText(NSApp.keyWindow?.firstResponder),
                   NSApp.sendAction(Selector(("undo:")), to: nil, from: nil) { return }
                target?.perform(.undo)
            }
            .keyboardShortcut("z", modifiers: .command)
            .disabled(!(target?.undoEnabled ?? false) && !editingText)

            Button(target?.redoTitle ?? "Redo") {
                if JournalMenu.routesToText(NSApp.keyWindow?.firstResponder),
                   NSApp.sendAction(Selector(("redo:")), to: nil, from: nil) { return }
                target?.perform(.redo)
```

The rest of the Redo button (its `.keyboardShortcut` and `.disabled` lines) is unchanged.

### 2. `YardKit/Tests/YardUITests/JournalMenuRoutingTests.swift` — new file, exactly this

```swift
// JournalMenuRoutingTests.swift — Edit ▸ Undo reaches the journal unless text is being edited (#0448)

import AppKit
import Testing
@testable import YardUI

@MainActor
@Test func undoRoutesToTextOnlyWhileATextViewIsFirstResponder() {
    #expect(JournalMenu.routesToText(NSTextView()))
    #expect(!JournalMenu.routesToText(NSTableView()))
    #expect(!JournalMenu.routesToText(NSWindow()))
    #expect(!JournalMenu.routesToText(nil))
}
```

### 3. `SwitchyardUITests/0448UndoReachesJournalUITests.swift` — new file, exactly this

```swift
import XCTest

/// #0448: Edit ▸ Undo reaches the journal. Revert the tip with ⌥⌘R, then
/// choose Edit ▸ Undo Revert: the revert commit must leave History.
final class Spike0448UndoReachesJournalUITests: XCTestCase {
    @MainActor
    func testEditUndoRevertTakesTheRevertBack() {
        let app = XCUIApplication()
        app.launchWithFixtureRepository()
        app.selectHistoryRow(subject: UITestFixture.tipSubject)

        app.typeKey("r", modifierFlags: [.command, .option])
        let revert = app.historyRows(containing: UITestFixture.revertSubject).firstMatch
        XCTAssertTrue(revert.waitForExistence(timeout: 30), "⌥⌘R wrote no revert commit")

        app.menuBars.menuBarItems["Edit"].click()
        let undo = app.menuBars.menuItems["Undo Revert"]
        XCTAssertTrue(undo.waitForExistence(timeout: 10), "the Edit menu offers no Undo Revert")
        undo.click()

        XCTAssertTrue(
            app.waitUntilDisappears(revert, timeout: 30),
            "Edit ▸ Undo Revert left the revert commit in History — the menu " +
            "forwarded undo: to the responder chain instead of the journal")
    }
}
```
