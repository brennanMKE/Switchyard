## Description

The branch/tag management legs of GitUp's context menu (#0359): **Add Tag… (T)**,
**Create Branch… (B)**, **Edit Local Branch "main" (→)** — rename, delete, set upstream.
Switchyard's engine reads refs extensively (`wt list`, `graph`, the sidebar's branch list) but
creates none of them: there is no tag creation, no branch create/rename/delete, anywhere.

These are ref operations, so the journal's ref-snapshot machinery covers undo — but the guards
differ per operation: deleting a branch with unmerged commits is data loss (GitUp confirms;
Switchyard should refuse without `--force` and journal the deletion when forced), renaming a
checked-out branch must move `HEAD`'s symref, and tag creation can be lightweight or annotated
(and signed — `git tag -s` shells out to the same signing path).

## Expected behavior

- [ ] `yard tag <name> <commit>` (annotated and lightweight), `yard branch create <name>
      [<start>]`, `yard branch rename <old> <new>`, `yard branch delete <name> [--force]`,
      `yard branch upstream <name> <upstream>` — all non-interactive, all typed-refusal-first.
- [ ] Deleting the checked-out branch, deleting an unmerged branch without `--force`, renaming
      onto an existing name, and creating a tag that exists are typed refusals touching nothing.
- [ ] Every mutation auto-checkpoints and is exactly undoable (ref snapshots already cover
      branch/tag state — verify, don't assume).
- [ ] The sidebar's branch list (#0358) gains the management affordances; the context menu
      (#0359) gains the items.

### Name validation the UI can do honestly

*Measured* `git check-ref-format --branch`: `feature/x`, `@` and `naïve` are accepted. Refused are
`a b`, `a..b`, `a~b`, `-x`, `a.lock`, `HEAD`, `a/`, `.a`, `a:b` and `a?b`. Directory/file clashes
are refused at creation, not by `check-ref-format`: with `feature` present,
`git branch feature/x` → `fatal: cannot lock ref 'refs/heads/feature/x': 'refs/heads/feature' exists`.
The reverse clash, `deep` against `deep/a`, is refused the same way. A tag may share a branch's
name (`git tag feature` exits 0).

The UI checks only what it knows for certain from `RefSnapshot`; git's full grammar stays the
engine's typed refusal. Re-implementing `check-ref-format` in Swift would drift.

```swift
// Appended to YardKit/Sources/YardUI/RefManagement.swift (created by #0362)

/// #0363: the name problems the UI can know for certain before git sees the
/// name. Everything else `git check-ref-format` rejects arrives as the
/// engine's typed refusal.
public nonisolated enum RefNameProblem {
    public static func forBranch(_ name: String, in refs: RefSnapshot) -> String? {
        problem(name, kind: "branch", prefix: "refs/heads/", refs: refs)
    }

    public static func forTag(_ name: String, in refs: RefSnapshot) -> String? {
        problem(name, kind: "tag", prefix: "refs/tags/", refs: refs)
    }

    private static func problem(_ name: String, kind: String, prefix: String, refs: RefSnapshot) -> String? {
        if name.isEmpty { return "Enter a \(kind) name" }
        if name.contains(where: \.isWhitespace) { return "A \(kind) name can’t contain spaces" }
        let full = prefix + name
        for entry in refs.refs where entry.name.hasPrefix(prefix) {
            if entry.name == full { return "A \(kind) named “\(name)” already exists" }
            if full.hasPrefix(entry.name + "/") || entry.name.hasPrefix(full + "/") {
                let other = String(entry.name.dropFirst(prefix.count))
                return "“\(other)” already exists, so “\(name)” can’t be used"
            }
        }
        return nil
    }
}
```

*Measured* results, against a snapshot holding `refs/heads/main`, `refs/heads/feature`,
`refs/heads/deep/a` and `refs/tags/v1`:

| call | result |
|---|---|
| `forBranch("")` | "Enter a branch name" |
| `forBranch("a b")` | "A branch name can’t contain spaces" |
| `forBranch("feature")` | "A branch named “feature” already exists" |
| `forBranch("feature/x")` | "“feature” already exists, so “feature/x” can’t be used" |
| `forBranch("deep")` | "“deep/a” already exists, so “deep” can’t be used" |
| `forBranch("v1")` | nil |
| `forTag("v1")` | "A tag named “v1” already exists" |
| `forTag("feature")` | nil |

The problem text sits under the field in `.secondary` style, updating as the user types. The
confirming button is disabled while it is non-nil.

### Dialogs

- **New Branch…** — `.alert("New Branch", isPresented:)` containing
  `TextField("Branch name", text:)`, **Create Branch**, and **Cancel** (`role: .cancel`). Message:
  "Starts at <shortOid> “<subject>”." That modifier shape *compiled* in #0359's scratch view.
  *Not verified*: whether an alert's `.disabled` button and message update live as the user types. **Spike #0385** settles it.
  If they do not, use a small sheet with the same fields — do not ship a Create button that
  accepts an invalid name. Creating does **not** check the branch out; the engine verb is create.
- **New Tag…** — a sheet: Name field; `Toggle("Annotated", isOn:)`, on by default because an
  annotated tag records who and when; a message field enabled only while annotated; **Create Tag**
  and **Cancel**. No signing control — the engine follows the explicit `-S` rule. Validation comes
  from `RefNameProblem.forTag`.
- **Rename…** — an alert with the field pre-filled with the current name; **Rename** is disabled
  while unchanged or while `RefNameProblem.forBranch` is non-nil. For the checked-out branch, the
  message adds "HEAD follows the new name." That is the symref move the Description requires, said
  so the user is not surprised.
- **Set Upstream…** — a sheet with a `Picker("Upstream", selection:)` over `refs/remotes/*` from
  `RefSnapshot`, excluding names ending in `/HEAD` (`for-each-ref` lists
  `refs/remotes/origin/HEAD` as a commit, *measured*). Pre-select `origin/<name>` when it exists,
  otherwise the current upstream. **Set Upstream** and **Cancel**.
- **Delete Branch…** — disabled, with the reason as `.help`, when:
  - it is the checked-out branch → "Can’t delete the checked-out branch" (typed refusal);
  - another worktree has it checked out → "Checked out in worktree “<folder name>”".
    `WorktreeEntry.branch` is already the short name (`refs/heads/` stripped, *measured* in
    `YardKit/Sources/YardGit/WorktreeList.swift`), so compare it directly. git refuses this too;
    confirm the engine types it.

  Otherwise it confirms, and the copy depends on reachability. "Merged" is **not** git's
  `branch --merged`, which lists 4 of Batty's 122 branches because work lands by squash
  (*measured*, #0373):
  - the branch tip reachable from `HEAD` in the window → title "Delete branch “feature”?",
    message "Its commits are all on “main”."; run **without** `--force`;
  - otherwise → title "Delete unmerged branch “feature”?", message "<N> commit(s) on it aren’t on
    “main” and will no longer be on any branch." (N from `BranchTipImpact.make(rows:head:
    <branch tip> target: <HEAD>)`'s `removed`, with "at least" when `isLowerBound`); run **with**
    `--force`.

  If the first path's delete is refused as unmerged by git's own rule, show the second dialog then.
  The UI never forces on a guess that the branch was merged. Buttons: **Delete Branch**
  (`role: .destructive`, no default-action shortcut) and **Cancel**.

### After each operation

Refresh through #0359's `refreshAfterMutation`, never `ContentView.reload()`.

- **Create branch or tag**: the chip appears on the node and the row appears in the sidebar in sort
  order. The commit selection does not move.
- **Rename**: the selection stays; chips and the sidebar row relabel in place.
- **Delete**: keep the selection if its commit is still loaded, otherwise select `HEAD`. Commits
  no ref holds any more leave the graph.
- **Failures**: the #0359 alert shape, titled "Couldn’t Create Branch" / "Couldn’t Rename Branch"
  / "Couldn’t Delete Branch" / "Couldn’t Create Tag" / "Couldn’t Set Upstream", with the engine's
  message.
