## Description

Wrap `git worktree prune` and additionally report what is prunable and which worktrees hold an
abandoned agent session — the mess left behind when an agent crashes or a container is torn down
mid-run.

## Givens — verified on `main`, treat as true

1. `YardKit/Sources/YardGit/WorktreeContext.swift` provides `WorktreeContext.resolve(...)` plus
   `topLevel: String?` (nil in a bare repo), `gitDir`, `commonDir`, `worktreeName: String?`,
   `isLinkedWorktree`, `isBare`, and `path(for:git:)`. Use it; do not resolve paths yourself.
2. **`WorktreeContext` does not expose the main worktree's path.** If you need it, take the **first**
   `worktree <path>` line of `git worktree list --porcelain` — that entry is the main worktree from
   any worktree in the repo. Verified from inside a linked worktree. Do not derive it by trimming
   `/.git` off `commonDir`; that breaks on bare repos and on a `.git` file pointing elsewhere.
3. `YardKit/Sources/YardGit/FixtureRepository.swift` provides — verified by reading it, these are
   the real signatures:

   ```swift
   public func addWorktree(named name: String, branch: String) throws -> URL
   public func addWorktree(path targetDir: String, branch: String) throws -> URL
   public func lockWorktree(_ path: URL, reason: String) throws     // ← you need this one
   public mutating func build(_ commits: [Commit]) throws
   public mutating func branch(_ name: String, at commit: String? = nil) throws
   public func destroy()
   ```

   **`lockWorktree(_:reason:)` already exists.** Do not shell out to `git worktree lock` in a test
   and do not add a second helper. Tests build a **real** linked worktree, not a simulated one.
   `repo.oids` is populated only by `build(_:)` — force-unwrapping it for anything else traps and
   aborts the whole suite, which cost #0112 a round.
4. **Every shell-out goes through `GitProcess`** (`YardKit/Sources/YardGit/GitProcess.swift`). Do not
   construct `Process` directly — the boundary is centralised there so it stays testable, and
   libgit2 does not run hooks.
5. **Never build a path by concatenating onto `.git/`.** Resolve through `git rev-parse --git-path`
   or `WorktreeContext`. Reftable repositories have no `.git/refs/**` at all and return nothing
   rather than erroring.

## Probed 2026-08-07 against real repositories — these supersede the 2026-08-06 notes

**1. `git worktree list --porcelain` already reports prunability. There is no discovery command to
write.** A worktree whose directory is gone gains a fourth line:

```
worktree /…/w1
HEAD f16ed35…
branch refs/heads/w1
prunable gitdir file points to non-existent location
```

The reason after `prunable ` is git's own wording — report it verbatim, do not paraphrase it.

**2. A *locked* worktree whose directory is gone is never reported `prunable`, and `prune` never
touches it.** It keeps its `locked <reason>` line and nothing else changes:

```
worktree /…/w2
HEAD f16ed35…
branch refs/heads/w2
locked switchyard-agent:session=abc123
```

Verified: deleted both `w1` (unlocked) and `w2` (locked), ran `git worktree prune -v`, and only `w1`
was reaped. **So "never removes a worktree still locked by a live agent session" is git's guarantee,
not code you write.** Do not reimplement it. What you *do* write is the report: an **abandoned
session** is an entry that has a `locked` line whose reason begins `switchyard-agent:` **and** whose
worktree directory does not exist on disk. Git will never clean these up on its own — that is the
mess this command exists to surface.

Checking the worktree directory's existence with `FileManager` is correct here: it is a worktree
path, not a `$GIT_DIR` path. Report it; **never remove it**. A missing directory can also mean an
unmounted volume, and the whole point of a lock is that something else claims the entry.

**3. `switchyard-agent:` is the lock-reason prefix.** #0021 will write it; it is settled here so this
issue does not have to wait. Anything else in a `locked` reason belongs to the user and is reported
as a plain lock, not an abandoned session.

**4. `--dry-run -v` produces byte-identical output to the real `-v` run.** Both print one line per
reaped entry:

```
Removing worktrees/w1: gitdir file points to non-existent location
```

**5. Both `prune -v` and `repair` write to stderr, not stdout.** Verified by redirecting each stream
separately: `git worktree prune --dry-run -v 2>/dev/null` prints **nothing**.
`GitProcess.Output.text` and `.lines` are **stdout only** — parsing them gives an empty result and a
round that reports "nothing to prune" for every repository. Use `Output.standardError`.

## The safety finding that shapes this command

**`git worktree prune` cannot tell a *moved* worktree from a *deleted* one, and reaping a moved one is
not recoverable.** Verified end to end:

1. `git worktree add ../w1`, then `mv ../w1 ../w1-moved`.
2. `git worktree list --porcelain` reports the **old** path as
   `prunable gitdir file points to non-existent location` — exactly what a deleted worktree reports.
3. `git worktree prune` reaps it. The directory is **still on disk**, full of the user's work.
4. `git worktree repair ../w1-moved` now fails, exit 1:
   `error: unable to locate repository; .git file does not reference a repository`.

Before the prune, that same repair would have succeeded. Pruning is what makes it unrecoverable.

**Therefore: reporting is the default and pruning is opt-in.** `switchyard wt gc` with no flag
reports and changes nothing. Actually pruning requires an explicit flag — name it `--prune`. Do not
invert this into `--dry-run` on a destructive default; the whole finding above is why.

### Verified `git worktree` behaviour — probed 2026-08-06, still true

Run against a real repo with a linked worktree, not read from the man page.

- **`git worktree remove <path>` refuses a dirty worktree with exit `128`** and the message
  `fatal: '<path>' contains modified or untracked files, use --force to delete it`.
  `--force` then succeeds. "Dirty" includes untracked files, not just modifications.
- **`git worktree prune -v`** prints one line per reaped entry:
  `Removing worktrees/<name>: gitdir file points to non-existent location`, and the entry disappears
  from `git worktree list --porcelain`.
- **`git worktree repair <path>`** prints `repair: gitdir incorrect: <path-to-admin-gitdir-file>`.

**The counter-intuitive one, and the reason it is written down:** after a linked worktree is *moved*
on disk, `git -C <new-path> status` **still exits 0**. The worktree keeps working from the inside,
because its own `.git` file still points at the administrative directory. What breaks is the
*reverse* pointer — the `worktrees/<name>/gitdir` file in the main repository still names the old
location. So a test asserting "status fails before repair" would be **wrong**, and would pass or fail
for reasons unrelated to the code under test. Assert on the administrative state, or on an operation
run from the main repository, not on `status` from inside the moved worktree.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/WorktreePrune.swift`. Create it; do not restructure existing files.
- [ ] Parses `git worktree list --porcelain` for `prunable` and `locked` lines. Reports each prunable
      worktree with **git's own reason string, verbatim**.
- [ ] Reports abandoned sessions: `locked` with a reason beginning `switchyard-agent:`, and the
      worktree directory absent from disk. Reported, **never removed**.
- [ ] **Reporting is the default.** Pruning happens only under an explicit `--prune`. See the safety
      finding above — this is not a stylistic preference.
- [ ] Reads pruning output from `Output.standardError`, not `.text` / `.lines`.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] New tests go in **`YardKit/Tests/YardGitTests/`**. `Tests/YardGit/` is not a declared target
      path; a file there is silently never compiled, the suite stays green, and the count does not
      move. That cost #0095 a round.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line
      you paste. **`main` reported 216 on 2026-08-07.** Run `swift test` on the branch before your
      change for its own baseline, paste that too, and N must exceed it.
