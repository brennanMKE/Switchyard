## Description

**Filed by #0170's review on 2026-08-08, from a mutation the reviewer invented rather than one in
the table.**

#0170 decision 3 states that id-bearing rebuild defects — `missingSnapshotCommit`,
`missingMetadata`, `anchorNotACommit` — **fold into the listing as items in id order**, carrying
their defect. The whole point is that a listing which silently omits a broken entry hides exactly
the state an agent needs to diagnose.

**Nothing tests it.** Review deleted the entire id-bearing fold from `recover`, replacing those
three cases with `break`, and ran the full suite: **712 tests, green.** A second mutation removing
`records.sort` is green for the same reason — no fixture ever creates an id-bearing rebuild defect,
so the sort is a no-op in every existing test.

`JournalList` has no other consumer, so nothing else in the suite could have caught either.

## The consequence in plain terms

A repository whose snapshot commit was garbage-collected would **list as though the entry never
existed.** An agent asking "what happened to my journal?" gets a clean, shorter list instead of an
entry marked defective — the failure mode #0030 chose skip-and-report specifically to avoid.

The decode-failure half of decision 3 *is* covered, by M6 and by
`metadataWhoseIdDisagreesWithItsAnchorIsADefectNotAChainEntry`. Only the rebuild-defect half is
bare.

## What this issue must deliver

- A fixture that produces each of the three id-bearing rebuild defects. #0030's own tests build
  them, so the construction is known and need not be re-derived: `update-ref` accepts a blob for a
  ref in a custom namespace (`anchorNotACommit`), and deleting the snapshot commit's loose object
  yields `missingSnapshotCommit` — with the object path resolved through
  `git rev-parse --git-path`, never string-built onto `.git/`.
- Assertions that each appears **as an item**, in **id order**, with its defect set and
  `position == nil` — not merely that no error was thrown.
- **A mutation row per assertion**, each observed red. Specifically, the two mutations that are
  currently green must both go red: deleting the id-bearing fold, and removing `records.sort`.
- Parameterise over both ref formats.

Expected: **+1 to +3 tests**.

## Planning update — 2026-08-08, authored in-context

**The gap re-confirmed against the merged code.** `JournalList.list` folds every recovery record
into an `Item`, and the guard is `record.defect == nil, let metadata = record.metadata`. Both the
decode-failure half **and** the id-bearing rebuild half take the same `position: nil` branch — but
only the decode half has a fixture. `anUndecodableMetadataEntryListsWithADefectAndSinksNothing` and
`metadataWhoseIdDisagreesWithItsAnchorIsADefectNotAChainEntry` both plant a bad **blob**; nothing
plants an anchor that is not a commit, or an anchor whose commit is gone.

So deleting the id-bearing fold from `recover`, or removing `records.sort`, leaves the suite green —
measured by #0170's review.

## Givens — from the merged code, verified by reading it

1. `JournalAnchor.refPrefix` is `public`, and `JournalAnchor.refName(for:)` is
   `refPrefix + id.string`. A test can plant an arbitrary oid at an anchor ref with
   `git update-ref <refPrefix><id> <oid>` — this is exactly what `JournalRebuildTests.plantAnchor`
   does, and #0030 measured that `update-ref` accepts a **blob** for a ref in a custom namespace.
2. `JournalListTests` already has `Self.writeEntry(_:worktree:in:)` and `Self.id(_:)`; it has **no**
   `plantAnchor`, so this issue adds one.
3. The existing defect tests use `try #require(listing.items.last)` rather than `items[1]`,
   deliberately: under a mutation that drops the defective item a raw subscript **traps** and
   destroys the run summary instead of failing the test. Follow that pattern.

## Change 1 — `YardKit/Tests/YardGitTests/JournalListTests.swift`, append a helper and one test

Append inside the existing suite. **Append; do not rewrite the file** (Rule 5c).

```swift
    /// Plants an arbitrary oid at an entry's anchor ref. #0030 measured that
    /// `update-ref` accepts a blob for a ref in a custom namespace, which is
    /// how the `anchorNotACommit` defect is constructed without file surgery.
    private static func plantAnchor(
        _ oid: String, id: JournalEntryID, in context: WorktreeContext
    ) throws {
        try GitProcess().run(
            ["update-ref", JournalAnchor.refName(for: id), oid],
            workingDirectory: context.topLevel ?? context.gitDir)
    }

    /// #0030's id-BEARING defects — an anchor that is not a commit — must fold
    /// into the listing as items in id order, carrying their defect, exactly
    /// as the decode-failure defects do. Deleting that fold, or the sort,
    /// leaves every other test green: a repository whose snapshot commit was
    /// garbage-collected would list as though the entry never existed, which
    /// is the failure skip-and-report exists to prevent.
    @Test(arguments: FixtureRepository.RefFormat.supported(git: GitProcess()))
    func anAnchorThatIsNotACommitListsInIdOrderWithItsDefect(
        format: FixtureRepository.RefFormat
    ) throws {
        let repo = try FixtureRepository.linear(refFormat: format)
        defer { repo.destroy() }
        let context = try WorktreeContext.resolve(path: repo.url.path)

        // Plant the DEFECTIVE entry first, so a listing that drops it also
        // loses the earlier id — proving order, not just presence.
        let badID = try Self.id("01")
        let blob = try #require(try GitProcess().run(
            ["hash-object", "-w", "--stdin"],
            workingDirectory: repo.url.path,
            standardInput: Data("not a snapshot commit".utf8)).lines.first)
        try Self.plantAnchor(blob, id: badID, in: context)
        let good = try Self.writeEntry(try Self.id("02"), worktree: nil, in: context)

        let listing = try JournalList.list(in: context)

        #expect(listing.items.count == 2)
        let first = try #require(listing.items.first)
        #expect(first.entry.id == badID)
        #expect(first.metadata == nil)
        #expect(first.position == nil)
        #expect(try #require(first.defect).contains("not a snapshot commit"))

        let second = try #require(listing.items.last)
        #expect(second.entry == good)
        #expect(second.defect == nil)
        // The healthy entry is still placed on the chain: one broken anchor
        // must not sink the listing an agent uses to diagnose the breakage.
        #expect(second.position != nil)
        #expect(listing.foreignRefs.isEmpty)
    }
```

The defective entry is planted at the **lower** id on purpose: a fold that drops id-bearing defects
loses `items.first`, so `count == 2` and the `first.entry.id == badID` assertion both fail. That is
what makes this test cover the **sort** as well as the fold.
