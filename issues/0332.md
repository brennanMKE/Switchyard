## Description

**Proposal D from #0160's fourteenth umbrella pass — recorded by the ninth, twelfth and fourteenth
passes now, which is the argument for filing it rather than noting it a fourth time.**

`YardKit/Sources/YardGit/JournalObserved.swift:310` mints each observed entry's id with
`after: …last?.id`. Replacing that with `after: nil` leaves the full suite green (1135 tests, 80
suites).

**What the argument buys:** `JournalEntryID.generate(after:)` guarantees the new id sorts **after**
the one it is given. Without it, two observed entries minted inside the same millisecond order by
their random bits — and `JournalObserved.list` sorts by id string, so the journal would report them
in an order that is not the order they happened in. The window is small and the consequence is
silent, which is exactly the combination a test has to cover because a human never will.

**The identical exposure exists on the `ref_updates` overload**, which is why the ninth pass placed
this on #0153's listing surface rather than on #0160.

## Expected behavior

- [ ] A named test minting **two observed entries back to back** — close enough together that they can
      share a millisecond — and asserting the second's id sorts strictly after the first's.
      **Do not assert on elapsed time**; assert the ordering property.
- [ ] **Make the collision reachable rather than hoping for it.** If two natural calls cannot be
      relied on to land in the same millisecond, drive `JournalEntryID.generate(after:)` directly with
      a fixed timestamp for the ordering property, **and** keep an end-to-end test that two
      consecutively recorded observed entries list in recording order. Say which one pins what.
- [ ] Cover **both** call sites — the `post-rewrite` path at `:310` and the `ref_updates` overload.
- [ ] **Mutation:** `after: …last?.id` → `after: nil`, at each site in turn. Each must redden a named
      test.
- [ ] **No production change is expected.** The current code is correct; this pins it.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, at or above the count in `docs/test-baseline.txt`.
