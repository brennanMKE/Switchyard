## Description

`HunkParser.HunkBuilder.consumePlain` (`YardKit/Sources/YardGit/Hunks.swift`, line 409 on `main`)
reads a body line's marker with `line.first`. That is a **Character**. When the file's line opens
with a combining mark (U+0301 COMBINING ACUTE ACCENT), the marker and the mark are one grapheme
cluster, so `line.first` is `"-\u{301}"`, which matches none of `" "`, `"-"`, `"+"`. The line
consumes neither count, the hunk still wants body when the file's next `@@` header arrives
(`wantsMoreBody` checks only the counts in plain mode, and runs before the `@@ ` dispatch), and the
second hunk is appended to the first as a body line.

#0475 fixed the *line* split in the same parser; this is the remaining Character read.

Measured 2026-09-29 on `main` (git 2.54.0), through `listHunks(area: .unstaged)`: `a.txt` of 20
lines `line 1`…`line 20` with line 2 = `"\u{301}b"`, edited to `"\u{301}B"` and line 18 to `LINE 18`:

- **before:** `hunks.count == 1`; the body is `[" line 1", "-\u{301}b", "+\u{301}B", " line 3",
  " line 4", " line 5", "@@ -15,6 +15,6 @@ line 14", " line 15"]`: the second hunk's header is a
  body line.
- **after:** 2 hunks; the first body is `[" line 1", "-\u{301}b", "+\u{301}B", " line 3", " line 4",
  " line 5"]`.

Scratch check, `swift` 6: `"+\u{301}x".first == "+"` is `false`,
`"+\u{301}x".unicodeScalars.first == "+"` is `true`.

**Not changed, on purpose:** `consumeCombined` (`@@@` hunks) also reads Characters
(`line.prefix(statusColumns)`), but it cannot swallow a header: `wantsMoreBody` for a combined hunk
also requires the marker to be ` `, `-` or `+`, and an `@@@` header's first Character is `@`
(#0342's conjunction). A missed consumption there is invisible, so there is no failing test to write
and it stays as it is. `wantsMoreBody(marker:)`'s own `marker == "\\"` check is only ever true for
git's `\ No newline` line, which never carries a combining mark.

## The files

### 1. `YardKit/Sources/YardGit/Hunks.swift`

Replace

```swift
        private mutating func consumePlain(_ line: String) {
            guard let marker = line.first else { return }
```

with

```swift
        private mutating func consumePlain(_ line: String) {
            // The marker is the line's first *scalar*: a file line opening
            // with a combining mark fuses with it into one `Character`, so
            // `line.first` would be `"-\u{301}"` and consume neither count
            // (#0482, measured).
            guard let marker = line.unicodeScalars.first else { return }
```

### 2. `YardKit/Tests/YardGitTests/HunksTests.swift`

Append at the end of the file:

```swift

// MARK: - #0482: a changed line that opens with a combining mark

/// A body line is its marker scalar plus the file's line. When the file's
/// line opens with a combining mark (U+0301), Swift fuses the marker and the
/// mark into one `Character`, so `line.first` is `"-\u{301}"`, never `"-"`:
/// the line consumed neither count, the hunk still wanted body when the next
/// `@@` header arrived, and the second hunk was swallowed into the first
/// (measured on `main`: `hunks.count == 1`).
@Test func aChangedLineOpeningWithACombiningMarkLeavesTheNextHunkSeparate() throws {
    var repo = try FixtureRepository()
    defer { repo.destroy() }
    var old = (1...20).map { "line \($0)" }
    old[1] = "\u{301}b"
    var new = old
    new[1] = "\u{301}B"
    new[17] = "LINE 18"
    try repo.build([.init("base", files: ["a.txt": old.joined(separator: "\n") + "\n"])])
    try repo.writeUntracked(["a.txt": new.joined(separator: "\n") + "\n"])

    let file = try #require(try listHunks(at: repo.url.path, area: .unstaged).first)

    #expect(file.hunks.count == 2)
    #expect(file.hunks.first?.body == [" line 1", "-\u{301}b", "+\u{301}B", " line 3", " line 4", " line 5"])
}
```
