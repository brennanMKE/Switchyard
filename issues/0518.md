## Description

The two context-menu entry points of guide §11 decision 39:

- **`WorkingChangesView`** — a file row's context menu gains **Show History** and **Blame** (above
  #0471's Discard Changes…) when `FileInspectorTarget.forWorkingRow` gives a target: not on an
  untracked or a conflicted row; Blame disabled on a deleted row. A new trailing init parameter
  `onInspect: ((FileInspectorTarget) -> Void)? = nil` — defaulted, so every existing caller and test
  compiles unchanged. A staged row's menu, empty until now, now has the two items.
- **`CommitDetailView`** — each changed file's `Label` gains a context menu with the same two items,
  at that commit (`forCommitFile`; Blame disabled for a file the commit deleted), and the identifier
  `commit-file-<path>` the VM spike finds it by. Same defaulted `onInspect` parameter.
- **`ContentView`** passes `onInspect: { fileInspector = $0 }` to both.

Merge commits list no files (`CommitDetailView` shows "Merge commit diffs are not shown yet"), so
they have no entry point here; File ▸ Show File History… (#0519) covers any file.
