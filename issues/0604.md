## Description

**Brennan, 2026-10-06:** *"You said fixup works now. I see it is disabled. Look at the current app."*

Measured on his screen (DaDaDa, on `main`, `screencapture -l` of the Switchyard window): the selected
commit was `ad423e5 adds docs 3`, the tip of `docs3`, reachable from `main` only through the merge
`2ddf973`. Fixup with Parent was disabled with the reason "Only commits in “main”’s own history can
be rewritten" — correct per decision 46 — but **nothing on screen said so**.
`YardKit/Sources/YardUI/CommitActionMenu.swift` puts the reason in `.help(...)` only, and macOS shows
no tooltip on a disabled menu item. The rules (`CommitActionRules.reason` in
`YardKit/Sources/YardUI/CommitActions.swift`) already compute a reason for every disabled item; the
menu discards it.

## Expected behavior

- In both the History context menu and the menu-bar Commit menu, a disabled item shows its
  `disabledReason` where a person can read it without hovering (to be planned: e.g. a menu-item
  subtitle — SwiftUI renders a second `Text` in a menu `Button` as a subtitle on recent macOS; to be
  measured in the VM, not assumed).
- A VM spike opens the Commit menu on a commit off `HEAD`'s first-parent chain and reads the reason
  text from the menu.

## Plan (in progress, 2026-10-06)

Prototype on branch `plan/0604` (worktree `../sy-plan-0604`): reasons drawn as the menu item's
subtitle (a second `Text` in the `Button` label), and one shared reason shown once at the top when
every item is disabled for the same reason. VM measurements pending; this section is replaced when
they land.
