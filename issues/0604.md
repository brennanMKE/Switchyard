## Description

**Brennan, 2026-10-06:** *"You said fixup works now. I see it is disabled. Look at the current app."*

Measured on his screen (DaDaDa, on `main`, `screencapture -l` of the Switchyard window): the selected
commit was `ad423e5 adds docs 3`, the tip of `docs3`, reachable from `main` only through the merge
`2ddf973`. Fixup with Parent was disabled with the reason "Only commits in “main”’s own history can
be rewritten" — correct per decision 46 — but **nothing on screen said so**.
`YardKit/Sources/YardUI/CommitActionMenu.swift` puts the reason in `.help(...)` only — a tooltip
that appears only while the pointer rests on the item (#0381), so a glance at the menu shows nothing. The rules (`CommitActionRules.reason` in
`YardKit/Sources/YardUI/CommitActions.swift`) already compute a reason for every disabled item; the
menu discards it.

## Decision (guide §11 decision 49)

- A **disabled item with its own reason shows that reason as the item's subtitle**: the `Button`
  label becomes two `Text`s, and SwiftUI draws the second as a smaller secondary line under the
  title. Enabled items carry no subtitle and are unchanged. `.help` stays for the hover.
- When **every item is disabled for one reason** (no commit selected: "Select a commit first";
  another operation running; an operation in progress) the reason is shown **once**, as a
  disabled `Text` line and a divider above the items, and no item carries a subtitle.
- Both menus get it from one view: `CommitActionMenuItems` renders the menu bar's Commit menu
  (`CommitCommands`, same file) and the History row's context menu
  (`YardKit/Sources/YardUI/BranchMapView.swift`, the row menu's `CommitActionMenuItems(states:branchName:perform:)`).
  No other source file changes.

### 2. New file `SwitchyardUITests/0604DisabledReasonUITests.swift`

No pbxproj edit: `SwitchyardUITests/` is a synchronized group (no existing spike is named in

```swift
// 0604DisabledReasonUITests.swift
//
// #0604 (guide §11 decision 49): a disabled Commit-menu item shows why it is
// disabled without hovering — the reason is the item's subtitle — and when
// every item shares one reason it is shown once, as a line above them.
//
// The subtitle is drawn but not in the accessibility tree: XCUITest reports
// only the item's title, and `value` stays empty even with
// `.accessibilityValue` (measured, the planner's first two VM runs). So the
// spike reads it the way a person does — from the pixels, with Vision's
// text recognizer over the item's own screenshot.

import Vision
import XCTest

final class Spike0604DisabledReasonUITests: XCTestCase {
    @MainActor
    func testADisabledItemShowsItsReasonInTheMenu() {
        let repo = GitRepo(path: HistoryFixture.path("cherry-pick"))
        let pick = repo.oid("pick-source")
        XCTAssertEqual(repo.headBranch(), "main")
        XCTAssertFalse(repo.git("rev-list", "--first-parent", "main").contains(pick),
                       "“pick source commit” is on main's first-parent chain — the fixture changed")
        let app = XCUIApplication()
        app.launchWithHistoryFixture("cherry-pick")

        // No commit selected: every item is disabled for one reason, shown once.
        app.menuBars.menuBarItems["Commit"].click()
        XCTAssertTrue(app.menuBars.menuItems["Select a commit first"].waitForExistence(timeout: 10),
                      "the Commit menu does not say “Select a commit first” with no commit selected")
        app.typeKey(.escape, modifierFlags: [])

        // A commit off main's first-parent chain: Fixup with Parent is
        // disabled, and its reason is drawn under its title.
        app.selectHistoryRow(subject: HistoryFixture.pickSubject)
        app.menuBars.menuBarItems["Commit"].click()
        assertShowsReason(app.menuBars.menuItems["Fixup with Parent"], in: "the Commit menu")
        app.typeKey(.escape, modifierFlags: [])

        // The History row's context menu renders the same items.
        app.historyRows(containing: HistoryFixture.pickSubject).firstMatch.rightClick()
        assertShowsReason(app.windows.firstMatch.menuItems["Fixup with Parent"], in: "the row's context menu")
        app.typeKey(.escape, modifierFlags: [])
    }

    /// `fixup` exists, is disabled, and draws the off-chain reason.
    @MainActor
    private func assertShowsReason(_ fixup: XCUIElement, in menu: String,
                                   file: StaticString = #filePath, line: UInt = #line) {
        XCTAssertTrue(fixup.waitForExistence(timeout: 10), "\(menu) has no Fixup with Parent",
                      file: file, line: line)
        XCTAssertFalse(fixup.isEnabled, "Fixup with Parent is enabled in \(menu) on a commit off main's chain",
                       file: file, line: line)
        let shot = fixup.screenshot()
        let attachment = XCTAttachment(screenshot: shot)
        attachment.name = "0604-fixup-item"
        attachment.lifetime = .keepAlways
        add(attachment)
        let lines = (try? recognizedLines(in: shot.pngRepresentation)) ?? []
        XCTAssertTrue(
            lines.contains { $0.localizedCaseInsensitiveContains("own history can be rewritten") },
            "Fixup with Parent shows no reason in \(menu); the item reads \(lines)", file: file, line: line)
    }

    /// The text lines Vision reads in a PNG, top to bottom.
    private func recognizedLines(in png: Data) throws -> [String] {
        let request = VNRecognizeTextRequest()
        request.recognitionLevel = .accurate
        request.usesLanguageCorrection = false
        try VNImageRequestHandler(data: png).perform([request])
        return (request.results ?? []).compactMap { $0.topCandidates(1).first?.string }
    }
}
```

**Why Vision.** The subtitle is drawn but is **not** in the accessibility tree XCUITest reads —
measured: the item's `title` is `Fixup with Parent`, `label` and `value` are empty, and a search of
the whole menu bar for the reason text by `title`/`label`/`value` finds 0 elements; adding
`.accessibilityValue(reason)` to the `Button` left `value` empty. So the spike reads the reason the
way a person does, from the item's own screenshot. Vision is a system framework; `import Vision`
autolinks, no target change.

## Expected behavior

- In both the History context menu and the menu-bar Commit menu, a disabled item draws its
  `disabledReason` as a subtitle under its title; enabled items are unchanged.
- When every item shares one reason, it is shown once as a disabled line at the top, and under no
  item.
- `CommitActionMenuReasons` carries that rule, pinned by two Swift Testing tests.
- `Spike0604DisabledReasonUITests` (in the `history` group) reads the reason from the menu bar and
  the row's context menu with Vision, and the shared line by its title.
