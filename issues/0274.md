## Description

**Findings 2 and 3 of #0160's sixth umbrella review, 2026-08-18.** Two checks that are still correct
and are **no longer pinned** — each was pinned when it landed, and #0264's changes moved the coverage
out from under them.

**Sequenced after #0273**, deliberately. Decision 24 may delete some of this code outright, and pinning
a check that is about to be removed wastes a round. Do #0273 first, then whatever survives gets a test.

### Finding 2 — #0261's stale-slot clear

`JournalCheckpoint.swift:320-324`. Deleting the clear outright (`if false {`) leaves **1072 tests in 78
suites green, twice on the full suite**.

Why it went dark: #0264 removed `slotNamesALiveEntry` and the slot write is an unconditional overwrite,
so `anOutOfBandAbortsStaleSlotMustNotDivertALaterUnrelatedOperationsRewrite` now passes on the overwrite
alone and never exercises the clear.

**The clear is not dead logic** — it is the only thing that removes a stale slot when the intervening
switchyard call **succeeds**, because a successful call never reaches the write. It is simply
unprotected, so a future round could delete it as "subsumed" using #0264's own reasoning and lose real
coverage silently.

### Finding 3 — #0253's `stillInProgress`

Two mutations, both **SURVIVED** the full suite:

| file:line | mutation |
|---|---|
| `JournalCheckpoint.swift:552` | `guard stillLive, stillInProgress,` → `stillInProgress \|\| true` |
| `JournalCheckpoint.swift:467` | `stillInProgress ?? (currentSequencer != nil)` → `?? true` |

**The second is materially the fifth review's mutation 5, which that pass recorded as killing
`aSuccessfulAttachThroughTheFileRemovesIt`.** It no longer does: #0264 resolves `liveOrigHead` from the
same `currentSequencer`, so `guard let liveOrigHead` fails first in every case `stillInProgress` used to
catch. The behaviour is still correct; the mechanism — a **public parameter** #0217's hook glue is
documented to supply — is now decorative and unprotected.

## Expected behavior

- [ ] **Do #0273 first.** Then, for each of the two checks, establish whether it **still exists**. If

- [ ] For each surviving check, a named test that dies when it is removed. The clear needs the case it
      uniquely covers: a stale slot, then an intervening switchyard call that **succeeds**, then a
      later operation — the success path is the whole point, because the write path no longer reaches
      the clear.
- [ ] **Mutations, one per surviving check**, each confirmed on the intended line, each reddening its
      own test and no other. If a mutation reddens a test that was already passing for a different
      reason, that test is not the pin — say so and write one that is.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.

## Notes

**Parent #0160**, bullet 2. Same shape as **#0255** and **#0260**: correct production behaviour that no
test can distinguish from its opposite.

**The general lesson is worth more than either finding.** A pin can go stale without anyone touching the
test or the behaviour it names — a *neighbouring* change can start failing first and mask it. That is
now part of what an umbrella review checks, and it found two on its first deliberate look.
