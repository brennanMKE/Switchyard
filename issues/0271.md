## Description

**Finding 4 of the M1 milestone review, fifth pass, 2026-08-18.** `wt rm`'s **agent-lock filter** is
unpinned — the half of the condition that distinguishes an agent's lock from a human's.

```swift
// WorktreeRemove.swift:122
if entry.locked, let reason = entry.lockReason, !reason.isEmpty || reason.isEmpty {
// was: if entry.locked, let reason = entry.lockReason, reason.contains("agent") {
```

`✔ Test run with 1074 tests in 78 suites passed after 115.010 seconds.` — full suite.

`worktreeRemove` documents at `WorktreeRemove.swift:117-120` that it releases **agent** locks only and
*"leave[s] other locks alone — a human lock is not the same as an agent session"*. But every locked
worktree in `WorktreeRemoveTests.swift` is locked with an agent reason — `"agent session id-42"` at
line 136, `"agent session id-99"` at line 175 — so nothing exercises the discriminating half.

**With the guard gone, `wt rm` silently unlocks and deletes a worktree a human locked deliberately**,
and the suite is green. Same class as #0245 (`includeIgnored`) and #0267 (`--no-renames`): a conditional
whose absence nothing detects.

## Expected behavior

- [ ] A named test in `YardKit/Tests/YardGitTests/WorktreeRemoveTests.swift` that locks a worktree with
      a **non-agent** reason — something a human would write, with no occurrence of the word `agent` —
      and asserts the removal does **not** release it: `lockedRelease == false`, and the worktree still
      exists afterwards.
- [ ] Assert what the caller is told, not only what happened: whether removal refuses or reports, the
      test should pin the observable outcome the way the agent-lock tests do for their side.
- [ ] **Mutation:** replace `reason.contains("agent")` with a tautology. The new test must redden
      **while** the existing agent-lock tests stay green — that pairing is what shows the new test
      covers the other half rather than duplicating them. Confirm the mutation landed where you meant.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.
