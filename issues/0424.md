## Description

Reported by the #0416/#0417 planner on 2026-09-26. `scripts/run-ui-tests-vm.sh` (around line 189)
runs its stale-clone sweep before it takes its lease. The sweep deletes every
`switchyard-uitest-<YYYYMMDD>-<HHMMSS>-<pid…>` clone except its own. A second run started while a
first is still going therefore stops and deletes the first run's live clone. The planner avoided
this by serialising its runs by hand. The #0418 planner's runs used the same names.

## Expected behavior

- [ ] The sweep deletes only clones whose owning run is dead. The owning pid is recoverable from the
      clone name, or from a record written when the clone is created. `kill -0` decides.
- [ ] Two overlapping runs both finish, and neither one's clone is deleted by the other.

## Not planned yet

This needs an Opus planning pass before dispatch: the exact clone-name → pid mapping (names such as
`switchyard-uitest-20260926-182300-406652` carry a per-spike suffix after the pid), and the
literal edit.
