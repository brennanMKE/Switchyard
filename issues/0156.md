## Description

The per-repository metadata cache, `$GIT_COMMON_DIR/switchyard/journal.json`
(`ServiceNames.journalMetadataRelativePath`). **It is an index and a convenience, never the
truth**: #0028 stores every entry's metadata inside the anchored snapshot commit itself, so this
file exists to make `switchyard journal` fast and to carry the fields that only make sense outside
the commit (`snapshotRef`, prune bookkeeping). Deleting it must lose nothing — #0030 rebuilds it
from `refs/switchyard/journal/*` alone, and that rebuild is a stated M2 exit criterion.

**Structured stub, split from #0028 on 2026-08-07.** Re-authored to code level at its own planning
pass before dispatch, per CLAUDE.md.

## Measured facts to build on

- **`git rev-parse --git-path` must NOT locate this file.** For an unknown subpath it resolves
  per-worktree, not shared — measured at #0149's planning pass: from a linked worktree,
  `--git-path switchyard/repository-id` returns `<repo>/.git/worktrees/<name>/switchyard/...`.
  The journal is per-repository, so address the file relative to `WorktreeContext.commonDir`,
  which both worktrees agree on (same measurement). `switchyard/` is our own state directory, not
  git's — the CLAUDE.md `$GIT_DIR` rule forbids parsing *git's* files, and `commonDir` itself
  comes from `git rev-parse` via `WorktreeContext`. #0149 settles where the `"switchyard"`
  directory-name constant lives; reuse its answer rather than re-deciding.
- The atomic-replace, typed-error, injected-location pattern is established by
  `RepositoryRegistry` (#0029): `Data.write(options: .atomic)`, missing file reads as empty,
  torn file is a typed error, unsupported `schemaVersion` is a typed error.

## Expected behavior — sketch; re-author to code level at dispatch

- [ ] One new production file `YardKit/Sources/YardGit/JournalMetadataCache.swift`: read all
      cached rows, append a row, remove a row (pruning deletes anchor and cache row together,
      #0033), against an injected `WorktreeContext`.
- [ ] A row carries the #0155 metadata plus `snapshotRef`; the file declares `schemaVersion: 1`.
- [ ] Reading from a linked worktree and from the main worktree returns the same rows — one
      journal per repository, tested against a real `git worktree add` fixture.
- [ ] A missing file is an empty cache; a torn file is a typed `ExitClassCarrying` error
      (`.repositoryError`) telling the caller to rebuild (#0030) — never silent invention.
- [ ] A mutation table, every row applied and observed red with the killing test named; criterion
      stated as a delta over the then-current baseline.

## Resolved — 2026-08-09, written in-context

`JournalMetadataCache` in `YardKit/Sources/YardGit/`, plus six tests. 812 → 818.

**The layering question the stub left open, resolved:** `YardGit` cannot import `YardKit`
(`LayeringTests` forbids both directions), yet `ServiceNames.journalMetadataRelativePath` lives in
`YardKit`. The engine defines its own `relativePath` constant — the arrangement that already exists
between `RefSnapshot.switchyardNamespace` and `ServiceNames.journalRefPrefix`. Checked before
deciding: `journalMetadataRelativePath` is **not** in `ServiceNamesTests`' forbidden list (only
`bundleIdentifier`, `journalRefPrefix` and `cliInstallPath` are), so the engine-side copy is
permitted rather than merely tolerated.

**Mutations, all observed red:** addressing from `gitDir` rather than `commonDir` (2 expectations —
the per-worktree split the design exists to prevent); a missing file throwing instead of reading
empty (5); dropping the id sort (2); the schema probe never firing (1).

**Three guards fired on this file within seconds of it compiling** — a missing `ExitClassCarrying`
registry row (#0181), a missing description row (#0182), and `ServiceNamesTests` catching a
hardcoded ref-prefix literal **in a doc comment**. All three were built earlier the same day and all
three caught real omissions in new code, which is the first evidence they work on something other
than their own fixtures.

`remove(id:)` is deliberately silent when the row is absent: #0033 deletes the cache row **before**
the anchor, so a re-run after a crash between the two must not fail on a row that is already gone.
