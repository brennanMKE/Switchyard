## Description

Every engine test needs real repositories built in a temp directory. This harness is the foundation
of the whole test suite and has to be built before the read commands are tested, not after.

**Every fixture is built twice** — once with the default ref format and once with
`git init --ref-format=reftable` — and the suite runs against both. Reftable becomes the default in
Git 3.0; discovering the engine cannot read it should happen in CI, not on a user's repository.

## Expected behavior

- [ ] Builder constructs repos with arbitrary commit DAGs from a compact description.
- [ ] Every fixture is parameterized over both ref formats and the suite runs both.
- [ ] Fixtures for: linear history, merges, octopus merge, detached HEAD, empty repo, conflicts, mid-rebase, linked worktree, untracked files.
- [ ] Temp directories are cleaned up even when a test fails.
- [ ] Fixtures never touch the user's global git config or `~/.ssh`.
- [ ] Reftable fixtures are skipped with a clear message when the local git is too old, not silently passed.

## Fix

`FixtureRepository` in `YardGit` builds throwaway repositories from a compact DAG description:
named `Commit` values with parents wired by name, so a test writes the shape it wants rather than a
sequence of git commands. `RefFormat.supported()` probes what the local git can create, and the
ready-made shapes (`linear`, `merged`, `octopus`, `conflicted`) cover the cases most tests need.

It lives in `YardGit` rather than the test target so the CLI's tests, future app-side tests, and
diagnostic tooling all build the same fixtures.

## Verification

`swift test` — **50 tests in 6 suites passed**. Every shape test is parameterized over
`RefFormat.supported()`, so each runs twice on this machine (git 2.50.1 supports both formats).

Coverage: linear, two-parent merge, octopus (3 parents), conflicted (asserting `git write-tree`
actually refuses the unmerged index), empty repo, detached HEAD, untracked files, linked worktree
sharing `$GIT_COMMON_DIR`, and an interrupted rebase leaving sequencer state.

## Gotchas

**#0009's guard caught this file building a `.git` path by hand.** `isMidRebase` originally used
`url.appendingPathComponent(".git")`, which is wrong in a linked worktree where the sequencer
directories live under `$GIT_DIR`, not `$GIT_COMMON_DIR`. It now asks
`rev-parse --git-path rebase-merge`. The harness has to obey the same rule as the engine it tests.

**A reduced matrix is reported, not silently accepted.** If the local git cannot create reftable
repositories, `localGitSupportsBothRefFormats` records an issue naming the git version and saying
coverage is reduced — rather than quietly running half the suite and passing.
