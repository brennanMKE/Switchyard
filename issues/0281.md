## Description

**Finding 6 of the M1 milestone review, sixth pass, 2026-08-18.** `conflicts` stage **modes** can be
hardcoded and nothing notices.

`YardKit/Sources/YardGit/Conflicts.swift:133`, mutated:

```swift
return ConflictedFile.StageEntry(oid: tokens[oid], mode: "100644")   // was: mode: tokens[mode]
```

`Test run with 1078 tests in 78 suites passed after 80.739 seconds.` — **full suite, unfiltered.**

**Why nothing catches it:** every `mode` assertion in the tree is the string `"100644"`
(`ConflictsTests.swift:25-27`; the rest are hand-built literals in `StatusConflictsWireTests.swift`).
**No fixture ever conflicts an executable (`100755`), a symlink (`120000`), or a gitlink (`160000`).**

The mutation is precisely isolated: the nil-stage guard tests `tokens[mode] != "000000"` and is
untouched, so the `base`/`ours`/`theirs` nil tests stay green and only the reported mode is affected.

## Expected behavior

- [ ] A test conflicting a file whose mode is **not** `100644` — an executable (`100755`) is the
      cheapest — asserting the reported stage `mode` matches.
- [ ] A symlink (`120000`) too if the fixture is cheap; say so either way rather than widening silently.
- [ ] **Mutation:** hardcode `mode: "100644"` at `Conflicts.swift:133`. Must redden. Confirm it landed
      there, and that the nil-stage tests stay green — that pairing shows the new test isolates the mode.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.
