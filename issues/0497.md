## Description

This week the app gained staging, committing, amending, discarding, fetch/pull/push, stashes and
undo/redo. The agent-facing CLI exposes none of them: `CommandRegistry.all` (30 entries on `main`
at `86cfead3`) has no `stage`, `commit`, `undo`, … and the generated skill says "Undo is not a CLI
command in this build." An agent driving `switchyard` still has to fall back to raw `git` for the
most common operations, which bypasses the journal the whole product is built on.

**Guide §11 decision 37 is the design.** Each verb is a thin arm in `YardCommands` over the exact
engine call the app's button makes, reached the way every other engine command is reached (argv
over XPC to the app, `runEngineCommand`, envelope back), journaled by the engine, with its
`CommandSpec`, schema file, skill section and `--help` regenerated, and tested in-process against
fixture repositories. The whole set was prototyped in a planning worktree (`../sy-plan-cli`): it
compiled, every verb was run through `yard-engine` against scratch repositories, and the full
suite passed with every new test (YardCommandsTests 122 → 171).

## Questions for Brennan

Each has a decision in place (decision 37) and is cheap to reverse. Answer in this file.

1. **Repository-relative paths.** CLI paths are relative to the repository top, as `status` prints
   them, not to the current directory as `git add` takes them. An agent in a subdirectory that
   passes `../x` gets exit 6. Chosen because every path the CLI prints is repository-relative, so
   an agent can pass them straight back. Would you rather the CLI resolve paths the way git does?
2. **`discard` with no `--yes`.** Decided against a confirmation flag (journaled, `undo` restores
   it, `drop` asks nothing either). If you want a guard for agents, `--yes` is a one-line addition
   per arm.
3. **`stash push` defaults to git's: untracked files stay** unless `--include-untracked`. The app's
   sheet defaults the checkbox on. Agents know git's default; confirm the mismatch is right.
4. **Exit classes from the error (6/8/9) for the new verbs only.** The older rewrite arms still
   flatten to 4. Retrofit them to `engineFailure` in a follow-up?
5. **Out of scope, pending your call:** line-level staging over the CLI (#0474's question), `commit
   --hunk`, provenance trailers (`--agent/--model/--session`), `journal` / `checkpoint` /
   `restore`, force-push, `pull --rebase`, `stash branch`, stashing selected paths.
6. **`fetch` / `pull` / `push` from the CLI run in the app's environment** (decision 32): SSH agent
   and keychain credentials work, a helper not on the app's minimal `PATH` does not (#0450
   question 1). Same answer applies here.
