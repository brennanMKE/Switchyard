## Description

**Finding 1 of the M1 milestone review, fourteenth pass, 2026-08-18.** `listHunks` **silently drops a
hunk** under `diff.suppressBlankEmpty`, and returns a patch `git apply` will refuse.

`YardKit/Sources/YardGit/Hunks.swift:375-377` pins six diff levers and `core.quotepath=false`, but not
this one. **Measured, git 2.50.1** — the config removes the leading space from **blank context lines**:

```
default:            suppressBlankEmpty=true:
 a$                  a$
 $                  $          <- the space is gone
-b$                 -b$
```

`HunkParser.HunkBuilder.body.didSet` (`Hunks.swift:315`) decrements `oldRemaining`/`newRemaining` from
`added.first`, which is `nil` for an empty line — so **a blank context line consumes no budget** while
`wantsMoreBody` keeps returning true.

**Measured through `listHunks`**, a file with one blank context line inside each of two hunks:

```
PROBE default files: 1 hunks: 2
  header=@@ -1,6 +1,6 @@          bodyLines=7
  header=@@ -14,7 +14,7 @@ line 13  bodyLines=8

PROBE suppressBlankEmpty files: 1 hunks: 1
  header=@@ -1,6 +1,6 @@          bodyLines=9
      … [ line 04] [] [ line 06] [@@ -14,7 +14,7 @@ line 13] [ line 14]
```

**The second hunk does not exist in the output.** Hunk 1 swallows the next `@@` header as body text,
every hunk id changes, and `patchText` becomes a patch `git apply` will refuse.

**Worse than #0293**, which reported "nothing changed": here the caller gets a **plausible-looking wrong
answer**, and hunk ids are M2's stage/unstage contract.

**Why no fixture can produce it:** every fixture in `HunksTests.swift` is built from `base20()` —
`line 01`…`line 20`, no blank lines.
