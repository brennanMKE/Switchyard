## Description

Hunk-level staging by the stable IDs from #0016 — the non-interactive replacement for `git add -p`,
which agents cannot use because it demands a terminal.

## Expected behavior

- [ ] `stage --hunk <id>...` and `unstage --hunk <id>...` accept multiple IDs in one call.
- [ ] A stale or unknown ID is a structured error, never a silently wrong hunk.
- [ ] Staging multiple hunks in one call is atomic — all or none.
- [ ] Auto-checkpoints before running.
- [ ] Round-trip test: list hunks, stage the second, re-list, assert the first is still listed and valid.
