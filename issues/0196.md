## Description

**Found by the M1 milestone review, 2026-08-17.** A latent crash, one flag away.

`YardKit/Sources/YardGit/CommitLog.swift:272`:

```swift
for i in 0 ..< lines.count - 1 {
```

This is the only range in the package built by subtraction. It is total **today** only because
`split(separator:omittingEmptySubsequences: false)` returns `[""]` — one element — for an empty body,
so the worst case is `0 ..< 0`. Flip that flag, or reach this code with a genuinely empty collection,
and it becomes `0 ..< -1`, which traps: *"Range requires lowerBound <= upperBound"*.

Guide §9's M1 criterion 3 says failures must not be traps. This one is unreachable rather than absent,
which is why it is a filed issue and not a review finding — but "unreachable because of an argument
passed at one call site" is a weak guarantee for a crash.

## Expected behavior

- [ ] The loop no longer depends on `count - 1` being non-negative. `for pair in lines.adjacentPairs()`
      shape, `zip(lines, lines.dropFirst())`, or a guard that returns early on fewer than two elements
      — whichever reads best next to the surrounding code.
- [ ] A test that reaches this code with an empty commit message and asserts a value rather than
      trapping. A commit with an empty message needs `--allow-empty-message`; verify that the fixture
      helper can build one before designing around it.
- [ ] A mutation recorded as observed: flip `omittingEmptySubsequences` to `true` (or otherwise force
      the empty case) and confirm the new test dies without the fix and passes with it.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line where N is **greater than**
      the count in `docs/test-baseline.txt` by exactly 1. The delta is the criterion; read the
      baseline file rather than trusting any absolute written here.
