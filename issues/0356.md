## Description

There is no way to produce an app build a person can put into `/Applications` and actually use.
Today the only build is the Xcode Debug product in DerivedData — which the CLI installer
correctly refuses (#0353's durability gate), so the real install path (#0353, #0354) has never
been exercisable end to end. The 2026-09-11 demo failed partly for this reason: the only app that
existed was a build-product app that by design cannot install its CLI.

This issue is the **build-and-package entry point**: one script that produces a Release
`Switchyard.app` artifact, version-stamped, self-contained, and copyable to another machine
(same-user testing across two machines needs no Developer ID and no notarization — Gatekeeper
only blocks *quarantined* downloads, and a directly copied app carries no quarantine attribute).
Developer ID signing and notarization are the *later* distribution concern and are explicitly out
of scope here; when they arrive they extend this script, and every signing step in them is a
human action (Rule 2 — the script must never pass `-allowProvisioningUpdates` or touch
certificates/keychains).

Absorbs **#0074** (Write scripts/make-release.sh — unscheduled; this is its M6 form with the
measured requirements attached).

## Expected behavior

- [ ] `scripts/make-release.sh` produces `build/Switchyard-<sha>.app` (or a zip of it) from a
      Release configuration — `xcodebuild archive` + export, or an equivalent documented path —
      with `CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO` as the default local mode.
- [ ] The artifact is self-contained: the embedded CLI, the broker agent plist and binary, and
      the package frameworks all ride inside the bundle (verified with `otool -L` showing no
      `/opt/homebrew` or build-machine paths, and the bundle layout matching what
      `AgentRegistrar` expects).
- [ ] A preflight gate fails fast before the slow steps: state which mode is running (unsigned
      local vs signed) and refuse early with a readable message when prerequisites are missing.
- [ ] The script is idempotent and cleans its own scratch under `build/`.
- [ ] A manual scenario (UNRUN) documents: run the script → copy the app to `/Applications` →
      launch → the Settings surface (#0352) shows the broker state → install the CLI →
      `switchyard --version` works.
- [ ] `swift test` is unchanged by the script's presence.

## Notes

The durability gate (#0353) is the reason this matters: an `/Applications` build is the only kind
that can install the CLI, and the broker registration (#0354) should be diagnosed from a real
installed app, not a DerivedData one. CI wiring (#0076, unscheduled) can call this script later.
