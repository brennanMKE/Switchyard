## Description

The remaining non-interactive history rewrites: move a commit within the branch
(`--before|--after <ref>`), remove a commit, and rewrite a message.

## Expected behavior

- [ ] `reorder`, `drop`, and `reword` all implemented and non-interactive.
- [ ] `reword` never invokes `GIT_EDITOR`.
- [ ] Each auto-checkpoints and is exactly undoable.
- [ ] Conflicts during any of them exit 8 with a resumable state.
- [ ] Signed commits stay signed through each rewrite.
- [ ] Refusing cleanly is preferred over a partial rewrite when the operation is impossible.

## Planning pass — 2026-09-09, to code level. One round.

**The mechanism** (per #0060's decision — the commit-tree walk Split and Absorb already use): all
three operations are one shape — compute the replacement commit list for the branch, rebuild it
with `commit-tree`, replay descendants with `cherry-pick`, move the ref once via
`update-ref --stdin`, all inside one `JournalCheckpoint.around`. The three commands differ only in
how the list is modified:

- **`reword <commit> --message <msg>`**: same walk, that commit's message replaced. `GIT_EDITOR`
  is pinned `false` in `GitProcess` and never invoked — the message arrives as a flag.
- **`drop <commit>`**: same walk, that commit removed from the list. Refuse when the commit is a
  merge (a dropped merge's second parent would be silently lost) — typed refusal, nothing touched.
- **`reorder <commit> (--before|--after) <ref>`**: same walk, that commit moved to the named
  position. Refuse when the target position is not on the same first-parent chain (typed refusal —
  a cross-branch reorder is a rebase, not a reorder).

Conflicts surface only where the modified list actually conflicts, as the pick-in-progress exit-8
state (Split's measured shape). Signing: `CommitCreate.Signing` forwarded to every rebuilt commit
and the replay — the explicit-`-S` rule. Refusal-before-mutation is the default posture: every
impossible operation is detected before the first object is written.
