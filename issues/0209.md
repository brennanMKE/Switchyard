## Description

**Split out of #0038 on 2026-08-17.** Every mutating command auto-checkpoints before it runs, so
`switchyard undo` works without the caller having asked.

This is a **policy spanning commit, fixup, stage and unstage**, not a property of any one of them, which
is why it is one issue rather than a bullet copied into four. #0034's model already states it — *"the
pre-operation capture every mutating command writes"* — and the #0034 umbrella review found that
**`grep -rn "JournalCheckpoint.checkpoint" YardKit/Sources` returns zero call sites**: the primitive
exists and nothing calls it. The auto-checkpoint has been assigned to "the command layer" by #0040,
#0162 and guide §371 without any issue owning it.

## What has to be decided

**Where the checkpoint is taken.** The engine functions (`CommitCreate.run`, `Staging.stageHunks`,
`Unstaging.unstageHunks`) are composable primitives, and a checkpoint inside each one would fire
several times for a composed operation like fixup — which would litter the journal and make `undo`
step through halves of a single user action.

- **At the command layer** (M3's `runYard` arms) — one checkpoint per user command, which is what the
  journal's model wants. But M3 does not exist yet, so M2's exit criterion *"undo round-trips every
  mutating command"* would be unmet until it does.
- **In a thin composing layer in `YardGit`** that each command calls — available now, and the place a
  future CLI arm would call anyway.
- **In each primitive, with a flag to suppress it** — available now, but every composed operation has
  to remember to suppress, and forgetting is silent.

**Measure the cost before choosing**: a checkpoint captures refs, index, worktree and sequencer
(#0171, #0188, #0200). Time one against a fixture with a large worktree, because "every mutating
command" means this runs constantly.

## Expected behavior

- [ ] The placement decision recorded in guide §11, in the shape of decisions 12–14.
- [ ] Whichever layer is chosen, one checkpoint per user-level operation — a composed operation writes
      **one** entry, and a test proves it by counting entries after a fixup-shaped sequence.
- [ ] `switchyard undo` after each mutating operation restores the pre-operation state, verified by the

- [ ] A mutation, observed: remove the checkpoint call and confirm the round-trip test fails rather than

- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in

## Notes

**This is M2's exit criterion, not a nicety**: guide §9 requires `checkpoint`, `undo`, `redo`, `journal`,
`restore`, `commit`, `fixup`, `stage` and `unstage` to work, and an `undo` that has nothing to restore
to because no command checkpointed is not working.

Related: #0034 decision 1's taxonomy names three entry kinds and this is the second of them. The other
two — explicit `checkpoint` and the pre-restore entry — both exist and are tested.

## Decision and plan — 2026-08-17. A composing layer in `YardGit`, applied to one command.

### Where the checkpoint is taken — decided

**A thin composing layer in `YardGit`.** Recorded as guide §11 decision 15; taken in Brennan's absence
under the standing instruction, reversible, and flagged.

Against the alternatives:

- **The command layer (M3's `runYard` arms)** is where one-checkpoint-per-user-command belongs
  architecturally, and it is where a CLI arm will call this from. But M3 does not exist, and M2's exit
  criterion — *"undo round-trips every mutating command"* — would stay unmet until it did. A criterion
  that cannot be met in its own milestone is the #0115 mistake repeated.
- **Inside each primitive with a suppress flag** makes every composition responsible for remembering to
  suppress, and forgetting is silent — the journal fills with half-operations and `undo` steps through
  halves of one user action. The failure mode is invisible until someone undoes.
- **The composing layer** is available now, is the exact seam a CLI arm calls, and keeps the primitives
  pure — `stageHunks` and `CommitCreate.run` stay composable without writing journal entries, which is
  what lets `commitHunks` compose them and still produce **one** entry.

### Scope — one command, and the rest listed

This issue delivers the helper and applies it to **`commitHunks`** only, because that is the composed
command that exists today (#0208, merged) and it is the one that proves the property: two primitives,
one entry. **Applying it to `stageHunks`, `unstageHunks` and `fixup` is #0212**, filed alongside, because
each is a separate call site with its own tests and folding four into one issue is the shape that has
never converged here.

## Change 1 — `YardKit/Sources/YardGit/JournalCheckpoint.swift`, append

```swift
public extension JournalCheckpoint {

    /// Runs `body` with a pre-operation journal entry written first, so
    /// `switchyard undo` works without the caller having asked (#0034
    /// decision 1's second entry kind).
    ///
    /// **One entry per user-level operation, not per primitive.** The
    /// primitives this wraps — `stageHunks`, `CommitCreate.run` — deliberately
    /// write no entries of their own, so a composed command like `commitHunks`
    /// produces exactly one. A checkpoint inside each primitive would litter
    /// the journal and make `undo` step through halves of a single action
    /// (guide §11 decision 15).
    ///
    /// The checkpoint is taken **before** `body` and is not rolled back if
    /// `body` throws: an entry describing the state before a failed attempt is
    /// correct and cheap, and removing it would need a second write on the
    /// error path for no gain.
    static func around<T>(
        operation: String,
        at path: String,
        command: String? = nil,
        agent: JournalEntryMetadata.Agent? = nil,
        git: GitProcess = GitProcess(),
        _ body: () throws -> T
    ) throws -> T {
        let context = try WorktreeContext.resolve(path: path, git: git)
        _ = try checkpoint(
            operation: operation, command: command, agent: agent,
            in: context, git: git)
        return try body()
    }
}
```

`WorktreeContext.resolve(path:git:)` is how every other `at path:` entry point gets a context — check
its exact label before transcribing, and do **not** build one by hand.

## Change 2 — `YardKit/Sources/YardGit/Staging.swift`

`commitHunks` wraps its existing body:

```swift
    return try JournalCheckpoint.around(
        operation: "commit", at: path, git: git) {
        try stageHunks(ids: ids, at: path, git: git)
        return try CommitCreate.run(...)
    }
```

**The clean-index check stays outside the wrapper.** A refusal must not write a journal entry — #0044
decision 4's "when the guard refuses, nothing has been written" is the same principle, and a caller who
gets an error should not find a checkpoint recording it.

## Change 3 — tests in `YardKit/Tests/YardGitTests/CommitHunksTests.swift`

1. `commitHunksWritesExactlyOneJournalEntry` — count `JournalAnchor.list` before and after; assert the
   difference is **1**, not merely non-zero. Two primitives run inside; one entry is the claim.
2. `undoAfterCommitHunksRestoresThePreCommitState` — the round trip. `UndoRoundTripSuiteTests` has the
   helpers; assert refs, `ls-files -s` bytes and tracked contents match the pre-commit state.
3. `aRefusedCommitHunksWritesNoEntry` — the dirty-index refusal from #0208, asserting the entry count is
   unchanged.

## Notes — what is deliberately not measured here

The original filing asked for a **timing** measurement, on the grounds that "every mutating command"
means this runs constantly. It is not in this issue, and the honest reason is that it needs a
large-worktree fixture nothing in the suite builds, and the number would be meaningless against
`FixtureRepository`'s handful of files. **The round should not invent one.** If the cost turns out to
matter it will show up as slow tests first; file it then, with a fixture built for it.
