# 0209 — Auto-checkpoint before every mutating command

| | |
|---|---|

## Description

**Split out of #0038 on 2026-08-17.** Every mutating command auto-checkpoints before it runs, so
`switchyard undo` works without the caller having asked.

This is a **policy spanning commit, fixup, stage and unstage**, not a property of any one of them, which
is why it is one issue rather than a bullet copied into four. #0034's model already states it — *"the
pre-operation capture every mutating command writes"* — and the #0034 umbrella review found that
**`grep -rn "JournalCheckpoint.checkpoint" YardKit/Sources` returns zero call sites**: the primitive
exists and nothing calls it. The auto-checkpoint has been assigned to "the command layer" by #0040,
#0162 and guide §371 without any issue owning it.

## What has to be decided

**Where the checkpoint is taken.** The engine functions (`CommitCreate.run`, `Staging.stageHunks`,
`Unstaging.unstageHunks`) are composable primitives, and a checkpoint inside each one would fire
several times for a composed operation like fixup — which would litter the journal and make `undo`
step through halves of a single user action.

- **At the command layer** (M3's `runYard` arms) — one checkpoint per user command, which is what the
  journal's model wants. But M3 does not exist yet, so M2's exit criterion *"undo round-trips every
  mutating command"* would be unmet until it does.
- **In a thin composing layer in `YardGit`** that each command calls — available now, and the place a
  future CLI arm would call anyway.
- **In each primitive, with a flag to suppress it** — available now, but every composed operation has
  to remember to suppress, and forgetting is silent.

**Measure the cost before choosing**: a checkpoint captures refs, index, worktree and sequencer
(#0171, #0188, #0200). Time one against a fixture with a large worktree, because "every mutating
command" means this runs constantly.

## Expected behavior

- [ ] The placement decision recorded in guide §11, in the shape of decisions 12–14.
- [ ] Whichever layer is chosen, one checkpoint per user-level operation — a composed operation writes
      **one** entry, and a test proves it by counting entries after a fixup-shaped sequence.
- [ ] `switchyard undo` after each mutating operation restores the pre-operation state, verified by the
      round-trip helpers `UndoRoundTripSuiteTests` already has.
- [ ] A mutation, observed: remove the checkpoint call and confirm the round-trip test fails rather than
      silently having nothing to undo to.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt`; state the delta once the shape is settled.

## Notes

**This is M2's exit criterion, not a nicety**: guide §9 requires `checkpoint`, `undo`, `redo`, `journal`,
`restore`, `commit`, `fixup`, `stage` and `unstage` to work, and an `undo` that has nothing to restore
to because no command checkpointed is not working.

Related: #0034 decision 1's taxonomy names three entry kinds and this is the second of them. The other
two — explicit `checkpoint` and the pre-restore entry — both exist and are tested.
