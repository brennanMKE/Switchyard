## Description

**Decision pending: Brennan to confirm option 2.** Filed 2026-09-12 with option 2 as the planned
work. If Brennan picks another option, this issue is re-planned before dispatch.

When an in-app operation stops on a conflict (exit class `.blockedOnConflicts` from #0359's
rewrites, or from #0387–#0389), the app today shows only a header warning (#0369) and disabled menu
items. Nothing lets the user resolve, continue or abort from the app.

### Options

| # | Option | For | Against |
|---|---|---|---|
| 1 | **Status only** — the header warns, items disable, the user finishes in git or a terminal | no new code | the app offers no way forward |
| 2 | **"Resolve Conflicts…" and "Abort" in the header.** The app registers an app-side pending resolve and opens the existing resolve pane (#0057); after resolution it continues the operation where git can | reuses the built pane; the user stays in control; no surprise sheet | the store needs an app-owned request path, plus a continue step per operation type |
| 3 | **Open the pane automatically** when an operation stops on a conflict — option 2's plumbing plus unrequested presentation | fastest path to resolution | an unasked-for sheet interrupts; Abort must still be offered |
| 4 | **Abort on conflict** — roll back through the journal and report "stopped on a conflict; nothing changed" | simplest; never leaves a half-finished state | conflicting merges and rebases become impossible in the app |

**Recommendation: option 2**, with option 3 as a later refinement if option 2 proves to be too many
clicks.

### Facts the design rests on

Read from source at `1b00f27` unless marked *measured*.

- **The store.** The app owns `private let pendingResolves = PendingResolveStore()` in
  `Switchyard/AppXPCServer.swift`. `PendingResolveStore.awaitDecision(for: ResolveRequest, owner: PendingOwner = PendingOwner()) async -> ResolveOutcome`
  registers a pending resolve and suspends. `ResolveRequest(commonDir:pathspec:timeoutSeconds:)`.
  `ResolveOutcome` has `.decided(ResolveReply)`, `.timedOut`, `.superseded`, and an abandoned case.
- **The CLI path.** `runResolveRequest(requestData:workingDirectory:store:onPending:owner:) async -> Data`
  (`YardKit/Sources/YardCommands/ResolveRequestServing.swift`) fills in `commonDir` and the conflict
  details before registering. The app-side registration **reuses it** with an encoded request, so the
  pane gets the same details. `ResolveCenter` presents the pane per repository
  (`activePane(forRepositoryPath:)`), which `ContentView`'s sheet already binds.
- **What "continue" means depends on the operation** (*measured*, git 2.50.1):
  - **single revert or cherry-pick** (#0387): `REVERT_HEAD` / `CHERRY_PICK_HEAD`, no `sequencer`
    directory → `git revert --continue` / `git cherry-pick --continue` (listed by `-h`; the revert
    continue is *not measured*);
  - **merge** (#0388): `MERGE_HEAD` → commit the merge (`git commit --no-edit` with the explicit
    signing flag — *not measured*);
  - **`Rewrite` / `Split` / rebase onto** (#0389): one multi-commit `git cherry-pick` → the `sequencer`
    todo holds the remaining picks. `git cherry-pick --continue` finishes them, **but `HEAD` stays
    detached and the branch does not move**, because the ref move lives in `Rewrite.perform`'s memory.
    **Continue is therefore not offered for these** until the plan (ref name, old tip, attached) is
    persisted — separate engine work, and not this issue. Resolve then Abort only;
  - **`Fixup`**: `git rebase --autosquash` → `git rebase --continue` updates the ref itself (*not
    measured*).
- **Abort** = `JournalUndo.undo(steps: 1, in: context)`, restoring the pre-operation entry
  `JournalCheckpoint.around` wrote. A restore clears a sequencer the target never captured (guide §11
  decision 14). Whether it also clears `MERGE_HEAD` / `REVERT_HEAD` / `CHERRY_PICK_HEAD` without a
  `sequencer` directory is *unverified*; a fixture test decides, and the operation's own
  `git … --abort` is the fallback.

### Files and literal changes (planning update, 2026-09-23)

Re-verified against main at 3e784cf and **measured on git 2.54.0 (Apple Git-157)** in
`build/scratch0394/` (scratch, not committed). Corrections to the facts above:

- Conflicted single revert leaves `REVERT_HEAD` + `MERGE_MSG` + `AUTO_MERGE`, **no sequencer dir**
  (as stated); `git revert --continue --no-gpg-sign` was **accepted** and completed on the branch.
- Conflicted merge leaves `MERGE_HEAD` + `MERGE_MSG` + `MERGE_MODE` + `AUTO_MERGE`;
  `git commit --no-edit --no-gpg-sign` completes it with git's own `MERGE_MSG`.
- A multi-commit `git cherry-pick` on a branch keeps **HEAD attached** (`.git/sequencer/` +
  `CHERRY_PICK_HEAD`). The detached replay is **Rewrite's own** `checkout --detach`
  (`Rewrite.swift:599`). So the Continue gate for picks is `isMidCherryPick && branch != nil` — a
  foreign multi-pick is git-owned and continues correctly; only the detached replay is excluded.
- All four `-h` listings carry `--continue`. Every measured `--abort` (merge, revert, cherry-pick,
  each after resolve+stage) removes all of its state files, leaving only `ORIG_HEAD`.
- **JournalRestore (JournalRestore.swift steps 8–8c) restores refs/HEAD/index/worktree and the
  rebase-merge/rebase-apply layouts only** — it never touches `MERGE_HEAD`/`REVERT_HEAD`/
  `CHERRY_PICK_HEAD` or cherry-pick's `.git/sequencer/`. Undo alone cannot clear a
  merge/revert/pick stop; the operation's own `--abort` after the undo is **required**, not a
  fallback.

**1. `YardKit/Sources/YardGit/ConflictHandoff.swift` (new)** — engine home so the package suite
drives the exact bodies:

```swift
public enum ConflictHandoff {
    public enum Kind: Equatable, Sendable, CaseIterable { case revert, cherryPick, merge, rebase }
    public static func name(of kind: Kind) -> String            // "revert"|"cherry-pick"|"merge"|"rebase"
    public static func inProgressKind(for state: WhereAmI) -> Kind?   // same precedence as TrackingSummary
    public static func continuableKind(for state: WhereAmI) -> Kind?  // nil for the detached replay
    public static func runContinue(kind: Kind, signing: CommitCreate.Signing = .config,
                                    at path: String, git: GitProcess = GitProcess()) throws -> String
    public static func runAbort(at path: String, git: GitProcess = GitProcess()) throws
}
```

Continue argv, per kind — `+ CommitCreate.arguments(for: signing)` on revert/cherry-pick/merge
(measured accepted on `revert --continue`; cherry-pick rides the same porcelain — its fixture or
manual check confirms), **bare** for rebase (it replays its own recorded flags):
revert → `["revert", "--continue"]`; cherryPick → `["cherry-pick", "--continue"]`;
merge → `["commit", "--no-edit"]`; rebase → `["rebase", "--continue"]`. `runContinue` returns
`rev-parse HEAD`. `runAbort` = resolve the context, `try JournalUndo.undo(steps: 1, in: context)`,
then probe via `rev-parse --git-path` + `fileExists` in the order `MERGE_HEAD` → `REVERT_HEAD` →
`CHERRY_PICK_HEAD` → rebase dirs and `try?` the first match's own `--abort` — the same
tolerated-abort shape `Replay.abort` uses.

**2. `YardKit/Sources/YardUI/RepositoryHeaderView.swift` (edit)** — beside #0369's label, an HStack
of actions; the view grows three optional closures (defaults nil, so previews stay valid):

```swift
var onResolveConflicts: (() -> Void)?   // rendered iff whereAmI.hasConflicts
var onContinue: (() -> Void)?           // iff ConflictHandoff.continuableKind(for: whereAmI) != nil
var onAbort: (() -> Void)?              // iff ConflictHandoff.inProgressKind(for: whereAmI) != nil
```

`"The repository returns to where it was before \(name)."`. **How the header learns the state:
WhereAmI fields only** — what #0369 shipped (`TrackingSummary.operationInProgress`); no new flag,
no wire change.

**3. `YardKit/Sources/YardUI/ContentView.swift` (edit)** — `ContentView` gains
`public var onBeginInAppResolve: ((String) async -> Void)?` (init param, nil in tests/previews),
passes the three closures into `RepositoryHeaderView` in `repositoryView(summary:)`, and adds

- `beginResolve()` → `Task { await onBeginInAppResolve(repositoryPath); await refreshAfterMutation

  the refresh follows.
- `runContinue(kind:)` / `runAbort()` → the @concurrent wrappers below, then

**5. `Switchyard/AppXPCServer.swift` (edit)** — `@MainActor func beginInAppResolve(repositoryPath:)`:

encodes `ResolveRequest(commonDir: "", pathspec: nil, timeoutSeconds: 86_400)` and
`await runResolveRequest(requestData:workingDirectory: repositoryPath, store: pendingResolves,

**6. Tests.** New `YardKit/Tests/YardGitTests/ConflictHandoffTests.swift` (swift-testing,
`FixtureRepository`, drive the real engine ops into `.blockedOnConflicts`, then `runAbort`, then
assert through `try whereAmI(path:)` — the same probe the header renders — plus raw
`rev-parse --git-path` + `fileExists` probes):

- `abortClearsConflictedMerge` — `Merge.run(intent: .noFastForward, branch:)` → isMidMerge false,
  hasConflicts false, `MERGE_HEAD` absent, branch tip == pre-merge tip.
- `abortClearsConflictedRevert` — `Replay.revert` → isMidRevert false, `REVERT_HEAD` absent, tip
  restored.
- `abortClearsConflictedCherryPick` — `Replay.cherryPick` → isMidCherryPick false,
  `CHERRY_PICK_HEAD` absent.
- `abortClearsConflictedFixupRebase` — `Fixup.run(target:)` → isMidRebase false.
- `abortClearsConflictedRewriteReplay` — a `Rewrite` replay forced to conflict → branch attached
  again, tip == old tip, `git-path sequencer` absent, isMidCherryPick false.

These five decide the facts section's unverified claim empirically, and every iteration must reach
an assertion (no skip-loops). Beside `TrackingSummaryTests` (YardUITests): pure gate tests over
hand-built `WhereAmI` values — `continuableKind` nil for a detached pick, non-nil for
attached pick / merge / rebase / revert; `#require` on every extracted value.

**Out of scope:** the Rewrite-family continue (the ref move lives in `Rewrite.perform`'s memory;
persisting the plan — ref name, old tip, attached — is separate engine work); option 3's auto-open;
any CLI-side continue/abort verbs; any `WhereAmI` wire change.

**Verification.** `cd YardKit && swift test` once at the end must print
`Test run with N tests` with **N > 1957** (baseline measured on main at 1c7a72c; 3e784cf adds no
tests). Manual pane hand-off (reviewer, dev run): merge two divergent branches from the row menu →
failure alert; header shows the warning plus Resolve/Abort; Resolve opens the pane with the merge's
conflict; resolve per card and Submit → pane dismisses, header refreshes, **Continue (merge)**
appears; Continue creates the merge commit. Again with a conflict, then **Abort** → dialog
"Abort merge?" → tip restored (`yard whereami`). One Continue each for fixup (rebase), revert and
cherry-pick.

## Expected behavior

- [ ] (Pending Brennan's confirmation of option 2.) After an in-app operation stops on a conflict, the
      header offers Resolve Conflicts… (opening the existing resolve pane from an app-side pending
      resolve) and Abort (a journal undo to the pre-operation state, confirmed first).

      merge, fixup), never for the `Rewrite`-family replay.

      `Test run with N tests`, and the pane hand-off is recorded by a manual check.
