## Description

The visible half of guide §11 decision 38 for the sidebar:

- **`RepositorySidebarView`** gains `refContext: RefActionContext?`, `onRefAction`, `onDeleteRef`
  (all defaulted, so previews and `RerereSurfaceTests` compile unchanged). A local branch row:
  **double-click** switches when `RefActionRules.switchReason` is `nil` (the double-tap gesture is
  attached before the existing single tap, so SwiftUI tries it first; single-click still selects),
  and a context menu with **Switch to “x”** and **Delete Branch…**. A remote row: **Check Out as
  Local Branch**. A tag row: **Delete Tag…**. A disabled item's `.help` is its reason. With
  `refContext == nil` the menus are empty.
- **`RefActionDialogs`** (new file `YardKit/Sources/YardUI/RefActionDialogs.swift`), a
  `ViewModifier` like `StashDropDialog` so `ContentView.body` stays within the type-checker's
  budget: the delete `confirmationDialog` (destructive button titled by the confirmation, no Return
  shortcut — #0359's rule) and the dirty-tree `.alert` (**Stash Changes and Switch**, **Cancel**).
- **`ContentView`**: `runningRef` (folded into `isBusy`, the Edit menu's busy check and
  `runJournal`'s guard, and the progress line), `pendingRefDelete`, `checkoutBlocked`, the sidebar
  arguments, the modifier, and `runRefAction(_:)` — `runStashAction`'s shape: busy flag, await
  `performRefAction`, then `refreshAfterMutation { _, _ in nil }`. Two refusals become questions: a
  `CheckoutBlocked` sets `checkoutBlocked`; `RefManageError.unmergedBranch` from a non-forced
  delete sets `pendingRefDelete = .unmergedBranch(name)`. Anything else is `actionFailure`.

Every state write is in a button, gesture or menu action, or after an `await` in the task
(event-origin — swift-guidance's Observation rules); nothing is written from `body`.

### 1. `YardKit/Sources/YardUI/RefActionDialogs.swift` — new file, exactly this

```swift
// RefActionDialogs.swift
//
// #0510: the ref actions' two presentations (guide §11 decision 38), as a
// modifier so `ContentView.body` stays inside the type-checker's budget —
// the shape `StashDropDialog` took.
//
// - Delete Branch… / Delete Tag…, and the second question an unmerged
//   branch asks: a destructive button with no Return shortcut (#0359's
//   rule for Delete Commit…), and Cancel.
// - A checkout the engine refused because it would overwrite local changes:
//   Stash Changes and Switch, or Cancel.

import SwiftUI

struct RefActionDialogs: ViewModifier {
    @Binding var pendingDelete: RefDeleteConfirmation?
    @Binding var blocked: CheckoutBlocked?
    let onConfirm: (RefAction) -> Void

    func body(content: Content) -> some View {
        content
            .confirmationDialog(
                pendingDelete?.title ?? "",
                isPresented: Binding(
                    get: { pendingDelete != nil },
                    set: { if !$0 { pendingDelete = nil } }),
                titleVisibility: .visible,
                presenting: pendingDelete
            ) { confirmation in
                Button(confirmation.confirmTitle, role: .destructive) {
                    pendingDelete = nil
                    onConfirm(confirmation.action)
                }
                Button("Cancel", role: .cancel) { pendingDelete = nil }
            } message: { confirmation in
                Text(confirmation.message)
            }
            .alert(
                blocked?.title ?? "",
                isPresented: Binding(
                    get: { blocked != nil },
                    set: { if !$0 { blocked = nil } }),
                presenting: blocked
            ) { notice in
                Button("Stash Changes and Switch") {
                    blocked = nil
                    onConfirm(notice.retry)
                }
                Button("Cancel", role: .cancel) { blocked = nil }
            } message: { notice in
                Text(notice.message)
            }
    }
}
```

    // MARK: - #0510: switching and deleting refs (guide §11 decision 38)

    /// #0510: runs one ref action — one journal checkpoint in the engine,
    /// so Edit ▸ Undo reverts it — then refreshes in place. Two refusals
    /// are questions, not failures: a checkout that would overwrite local
    /// changes offers Stash Changes and Switch, and an unmerged branch asks
    /// again before it is forced. Everything else is the failure alert.
    private func runRefAction(_ action: RefAction) {
        guard let repositoryPath, !isBusy, !journalRunning else { return }
        runningRef = action
        Task {
            defer { runningRef = nil }
            do {
                try await performRefAction(action, at: repositoryPath)
            } catch {
                if let blocked = CheckoutBlocked(action: action, error: error) {
                    checkoutBlocked = blocked
                } else if case let .deleteBranch(name, false) = action,
                          case .unmergedBranch? = error as? RefManageError {
                    pendingRefDelete = .unmergedBranch(name)
                } else {
                    actionFailure = action.failure(for: error)
                }
            }
            await refreshAfterMutation { _, _ in nil }
        }
    }

    // MARK: - #0457: Fetch, Pull and Push
