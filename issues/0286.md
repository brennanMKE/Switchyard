## Description

**Proposal 3 of #0160's seventh umbrella review, 2026-08-18, filed because it is cheap and the failure
is a real loss of information.** A failed entry-id write **replaces the body's error**.

`YardKit/Sources/YardGit/JournalCheckpoint.swift:344-345`, inside `around`'s catch:

```swift
try entry.id.string.write(toFile: path, atomically: true, encoding: .utf8)
```

An unguarded `try` in a `catch` block. If that write fails, the thrown `NSCocoaError` **replaces** the
original error the body threw — so a `FixupError.blockedOnConflicts`, which tells the caller the rebase
is resumable and how, is discarded and the caller instead sees a file-write failure it can do nothing
with.

**The classification is the point of that error.** `blockedOnConflicts` carries exit class 8, and the
whole conflict-resume flow depends on the caller being able to distinguish "your operation stopped and
you can continue it" from "something went wrong".

**Narrow, and worth fixing anyway:** the directory was observed to exist moments earlier, so the write
rarely fails. But the whole purpose of the surrounding code is to preserve the operation's state for
recovery, and this is the one line that can destroy the caller's ability to act on it.

## Expected behavior

- [ ] The write becomes `try?`, so a failure degrades to **no-attach** — the same safe degradation
      every other path in this mechanism takes — and the body's original error is rethrown intact.
- [ ] The same audit for `createDirectory` on the adjacent lines: if it can throw and replace the
      error, it gets the same treatment. **Name what you found either way** rather than fixing only the
      line this issue quotes.
- [ ] **A test that the body's error survives a failed write.** Make the write fail deterministically —
      injecting a `FileManager` that refuses, or pointing the path at a location that cannot be created
      — and assert the error the caller receives is the body's, not the file system's. If you cannot
      make it fail without contorting production code, **say so and leave the test out** rather than
      adding one that passes for another reason.
- [ ] **Mutation:** restore the unguarded `try`. The new test must redden.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.

## Notes

**Parent #0160.** Guide §11 decision 19 as amended, and decision 24.

**The totality invariant this protects is stated in `attachRewrite`'s own doc comment** — *"a failed
attach must never surface as a non-zero hook exit"*. This is the write side of the same principle: a
failed *record* must never surface as a different error than the operation's own.
