## Description

**Finding 1 of #0044's fourth umbrella review, 2026-08-17 — and it needs Brennan's decision, because
the fix changes what a restore promises.**

**A sibling's ordinary commit permanently blocks the caller's undo.** The plainest two-agent shape
there is: agent A in the main worktree, agent B in a linked worktree on `agent-branch`. A checkpoints,
A works, **B makes one ordinary `git commit` in its own worktree**, A undoes its own work:

```
PROBE3 A's undo FAILED: restore would disturb another worktree:
  refs/heads/agent-branch is checked out in …-wt-agent; restore would move to 5a0c126f…
PROBE3 after a fresh checkpoint, undo OK -> [01M09JVMHMEJYM5E2YYF8GZWQC]
PROBE3 second undo (back past B's commit) FAILED: … same refusal
```

A's cursor is nil here, so the cross-tool guard never runs — **this is the disturbance check alone**,
step 5, decision 2.

**Why it is permanent rather than transient.** Every checkpoint captures **every** ref, so every one of
A's entries records `agent-branch` at some pre-commit value. Once B commits, **A's entire history
before that commit is unreachable by undo**. A fresh checkpoint buys exactly one step — it resets A's
cursor to present and truncates its redo tail — and does not restore reach.

**The refusal is individually correct.** Restoring that snapshot really would move a branch out from
under B's checkout, which is the loss decision 2 exists to prevent. Nothing here is a bug in the sense
of code doing what it was not told to.

## The gap, stated as the decision it needs

**#0044 has no decision about restoring *partially*.** Decision 2 says refuse the whole operation.
Guide §11 **decision 20** has since established the opposite instinct for refs — *touch only what you
recorded, leave the rest alone* — and #0211 established the shape of reporting what was given up, via
`Report.detachedFrom`.

**A — restore the rest, leave a live sibling's held branch alone, and report it.** The caller's own
history becomes reachable again; the sibling keeps its commit; the `Report` names every branch that was
not restored, the way `detachedFrom` already names the branch `HEAD` gave up. **What it gives up:** a
restore no longer means "the repository matches this snapshot", which is a promise decision 20 has
already partly spent. An agent that undoes and then reads its own refs would see one it did not expect.

**B — keep refusing, and make it recoverable.** Add a way to proceed that is not a fresh checkpoint —
a documented force, or a "restore everything except the disturbed branches" flag. Keeps the promise
exact; costs a flag surface that does not exist until M3, and until then the deadlock stands.

**C — accept it.** Two agents must coordinate: B should work on its own branch *and* A should not
checkpoint refs it does not own. Cheapest, and it makes the two-agent story — which is #0044's own
stated premise — considerably weaker than the milestone claims.

**My recommendation is A**, for the same reason decision 20 went the way it did: the caller's own work
being unreachable is a worse failure than the repository not matching a snapshot exactly. But A changes
a promise stated in `RefSnapshot`'s type comment, so it is yours.

## Decided — option A, guide §11 decision 23. Planned 2026-08-17.

Taken in Brennan's absence on decisions 14–20's terms, after he asked whether I could make the calls
needed to keep moving. The guide entry carries the reasoning and **what it spends**; this is the shape.

**It is reversible and it is flagged.** If Brennan reads it differently, the change is a refusal
restored and a `Report` field removed.

### The change — `YardKit/Sources/YardGit/JournalRestore.swift`

Today step 5 throws on any disturbance:

```swift
let disturbances = WorktreeDisturbance.disturbances(
    restoring: applied, current: current, worktrees: worktrees, callerPath: context.topLevel)
guard disturbances.isEmpty else {
    throw WorktreeDisturbance.Error.wouldDisturb(disturbances: disturbances)
}
```

Instead: **drop each disturbed branch from the snapshot about to be applied**, and record it. The
shape to copy is #0211's, a few lines above — `WorktreeDisturbance.detachingHeldHead` returns
`(snapshot, detachedFrom:)` and `JournalRestore.Report` carries `detachedFrom`. Add the sibling:

```swift
/// Branches a live sibling worktree has checked out, which this restore left at
/// their current values rather than moving (guide §11 decision 23). Empty in the
/// ordinary case. `HEAD`'s own equivalent is `detachedFrom`.
public let leftAlone: [String]
```

with a `[]` default in the public `init`, exactly as `detachedFrom` was added.

**Keyed on liveness, not on the override.** `Disturbance.prunable` already carries it, and #0211's
`detachingHeldHead` reads it the same way — a prunable holder holds nothing, and decision 5's existing
rule covers that case.

**`requireUndisturbed` keeps its meaning for callers that want the refusal.** Do not delete it; it is
the shape #0044 decision 2 describes and a future force surface will want. Say what still calls it.

### The trap

**Dropping the branch from `applied` must not also drop it from the guard's scope in a way that hides
a foreign move.** Step 4 runs *before* step 5 and is scoped from `applied` (#0232, #0248) — so if you
drop refs before the guard, a foreign move to a third value on a dropped branch stops being reported.
**Drop after the guard**, and say in a comment why the order matters.

### Tests — `YardKit/Tests/YardGitTests/JournalRestoreTests.swift`

- **The measured probe becomes the headline test.** A checkpoints, works; B commits in its own worktree
  on `agent-branch`; A's undo **succeeds**, B's commit survives at its new value, and
  `report.leftAlone == ["refs/heads/agent-branch"]`.
- **A's history stays reachable**: a second undo, back past B's commit, also succeeds. That is the
  property this issue exists for — one step is not enough.
- **A prunable holder is still restored**, not left alone, and does not appear in `leftAlone`.
- **The caller's own checked-out branch** is still restored — `theCallersOwnCheckedOutBranchIsNotA
  Disturbance` covers the detection; assert the restore end of it.
- **A foreign move on a branch that will be left alone is still refused** by step 4 — the trap above,
  as a test.
- **Every existing disturbance test** that asserts a refusal now asserts the new behaviour instead.
  There are at least six (`restoreRefusesToDisturbASiblingsCheckout`, its `bypassGuard` and
  cross-worktree variants, `rewindingTheSiblingsBranchIsReportedByName`,
  `aPrunableWorktreeStillRefusesAndSaysHowToRelease`, `reportIsSortedAndSeesADanglingCheckout`).
  **Do not delete them** — each pins something decision 2 still needs, and the prunable one must keep
  refusing. Report what each asserts afterwards, and if any cannot be re-expressed, say so rather than
  removing it.

**Mutations:** refuse again on a live holder (the headline test must redden); drop the branch *before*
the guard instead of after (the foreign-move test must redden); ignore `prunable` (the prunable test
must redden).
