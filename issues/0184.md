## Description

**Filed by #0151's review on 2026-08-08, from a mutation the reviewer invented.**

`CLAUDE.md`'s cardinal rule — *"Never read `$GIT_DIR` with `FileManager`… No string concatenation
onto `.git/` anywhere in the codebase"* — is **mutation-enforced on `IndexSnapshot.capture` and
unenforced on `IndexSnapshot.restore`.**

#0151's row 6 replaces the capture-side path resolution with `base + "/.git/index"` and kills
`captureInALinkedWorktreeSeesItsOwnIndex`. Review applied the mirror mutation to `restore`:

```swift
let indexPath = try context.path(for: "index", git: git)   →   let indexPath = base + "/.git/index"
```

**All 13 tests pass.** No test performs a **raw restore inside a linked worktree** —
`captureInALinkedWorktreeSeesItsOwnIndex` only captures, and both of its snapshots come back
`.tree`, so the raw path never runs there.

The shipped code is correct; it does resolve through `WorktreeContext`. This is a coverage gap.

## Why it matters more than the usual gap

**#0171 composes `IndexSnapshot.restore` inside `JournalRestore`, and undo in an agent worktree is
the entire point of M2's criterion** — *"undo round-trips every mutating command, including with an
unmerged index"*. The unmerged case is exactly the case that takes the raw path. So the one
combination that is untested is the one the milestone criterion depends on.

Worktrees are also where this rule bites hardest: `HEAD` is per-worktree, `refs/heads/*` is
per-common-dir, and `git rev-parse --git-path` resolves **per-worktree**. A concatenated
`.git/index` silently addresses the main worktree's index from a linked one — it does not error, it
writes to the wrong file.

## What this issue must deliver

- **A raw round-trip inside a linked worktree**: create a linked worktree, produce a conflicted (or
  skip-worktree) index there so capture takes the `.raw` path, wreck the index, restore, and assert
  the bytes and the `ls-files -v` stage listing match.
- **Assert the main worktree's index was NOT touched** — that is the failure a concatenated path
  actually produces, and asserting only "the linked worktree is correct" would miss it.
- **Row A as its mutation row**: `base + "/.git/index"` in `restore`, observed red against the new
  test specifically.
- A wreck-took-effect guard, since "the index matches after restore" passes for free if the wreck
  was a no-op. #0151's planner hit exactly that vacuity in its own first probe, and #0151 now
  carries four such guards, all proven load-bearing by fixture mutation.

Expected: **+1 test**, parameterised over both ref formats if the fixture allows.

## Planning update — 2026-08-08, authored in-context

**A correction to this issue's own filing, found by measuring it.** The filing said a concatenated
`.git/index` "silently addresses the main worktree's index from a linked one — it does not error, it
writes to the wrong file." **That is false.** Measured on git 2.50.1:

```
$ cd <linked worktree>
$ git rev-parse --path-format=absolute --git-path index
<main>/.git/worktrees/side/index
$ file -b .git
ASCII text                      # .git is a FILE here, a gitdir pointer — not a directory
```

Writing to `<linked>/.git/index` therefore fails outright:

```
NotADirectoryError: [Errno 20] Not a directory: '<linked>/.git/index'
```

So the real defect is **a raw restore that cannot work at all in a linked worktree**, surfacing as
`IndexSnapshot.Error.indexFileUnwritable`. That is louder than silent corruption and still wrong:
undo in an agent worktree with an unmerged index — the exact combination M2's criterion names —
would fail rather than restore. The severity claim in the filing was overstated; the gap is real.

## Given — measured 2026-08-08, git 2.50.1

1. In a linked worktree `.git` is a regular file containing `gitdir: …`, so any path built by
   appending `/.git/<name>` is unreachable, not merely wrong.
2. `git rev-parse --path-format=absolute --git-path index` resolves **per-worktree**:
   `<common>/.git/worktrees/<name>/index` in a linked worktree, `<main>/.git/index` in the main one.
3. **`git update-index --skip-worktree <file>` is the cheapest raw trigger.** `git ls-files -v`
   then prints `S b.txt`, and #0151's capture takes the `.raw` path on any line not starting `H `.
   Note `write-tree` still **succeeds** here (`f4b3548…`), which is why the flag probe exists
   independently of the refusal fallback — #0151 rows 1 and 2 are compound for this reason.

## Change 1 — `YardKit/Tests/YardGitTests/IndexSnapshotTests.swift`, append one test

Append inside the existing suite, after `captureInALinkedWorktreeSeesItsOwnIndex`. **Append; do not
rewrite the file** (Rule 5c).

```swift
    /// #0151 pinned the `$GIT_DIR` rule on the CAPTURE side only: its row 6
    /// concatenates `.git/index` in `capture` and dies here. The mirror
    /// mutation in `restore` left all 13 tests green, because no test ever
    /// took the RAW path inside a linked worktree — capture there returns
    /// `.tree`. #0171 composes exactly that path, and an unmerged index in an
    /// agent worktree is what M2's criterion names.
    ///
    /// Measured: in a linked worktree `.git` is a FILE, so a concatenated
    /// `.git/index` is unreachable (`ENOTDIR`) rather than wrongly reachable.
    @Test func rawRestoreInALinkedWorktreeWritesItsOwnIndex() throws {
        var repo = try FixtureRepository.linear()
        defer { repo.destroy() }
        let wt = try repo.addWorktree(named: "agent-b", branch: "agent-b-branch")
        defer { try? FileManager.default.removeItem(at: wt) }

        // Force the raw path: skip-worktree makes `ls-files -v` print `S`,
        // which #0151 treats as raw even though write-tree would succeed.
        try "raw path\n".write(to: wt.appendingPathComponent("skipped.txt"),
                                atomically: true, encoding: .utf8)
        try git.run(["add", "skipped.txt"], workingDirectory: wt.path)
        try git.run(["update-index", "--skip-worktree", "skipped.txt"],
                    workingDirectory: wt.path)

        let ctx = try WorktreeContext.resolve(path: wt.path)
        let snapshot = try IndexSnapshot.capture(in: ctx)
        guard case .raw = snapshot else {
            Issue.record("expected a raw capture, got \(snapshot)")
            return
        }

        let wtIndexPath = try ctx.path(for: "index", git: git)
        let before = try Data(contentsOf: URL(fileURLWithPath: wtIndexPath))
        let mainCtx = try WorktreeContext.resolve(path: repo.url.path)
        let mainIndexPath = try mainCtx.path(for: "index", git: git)
        let mainBefore = try Data(contentsOf: URL(fileURLWithPath: mainIndexPath))

        // Wreck the linked worktree's index, and prove the wreck took effect.
        try git.run(["read-tree", "--empty"], workingDirectory: wt.path)
        #expect(try git.run(["ls-files"], workingDirectory: wt.path).text.isEmpty)

        try snapshot.restore(in: ctx)

        #expect(try Data(contentsOf: URL(fileURLWithPath: wtIndexPath)) == before)
        #expect(try git.run(["ls-files", "-v"], workingDirectory: wt.path)
            .text.contains("S skipped.txt"))
        // The main worktree's index must be untouched by any of this.
        #expect(try Data(contentsOf: URL(fileURLWithPath: mainIndexPath)) == mainBefore)
    }
```
