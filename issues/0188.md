## Description

**Filed by #0035 on 2026-08-09.** #0174 built `SequencerSnapshot` — capture and restore of an
interrupted rebase, proven by a test that runs `git rebase --continue` to completion after a
wreck-and-restore. **Nothing calls it.** `JournalCheckpoint` does not capture it, so
`JournalRestore` reports `.sequencer` as `.notCaptured` on every entry.

#0035's suite asserts that honestly rather than omitting the case, so the gap is visible where the
work is. But it means **M2's criterion is met for four of its five stated cases**: an unmerged
index, a detached `HEAD`, untracked files, and a staged-and-unstaged mix all round-trip; a
mid-rebase sequencer does not.

## Why this is not just "call the function"

`JournalEntryMetadata.Captured` has `refs`, `head`, `index`, `worktree`, `untracked` — **no
`sequencer` field**. Adding one is a change to a wire format pinned by golden-bytes tests (#0155,
#0179), which is why #0171 stopped at the index and worktree rather than carrying on.

The work is therefore:

- **Add `sequencer` to `Captured`** with a decode default, so entries written before this change
  still decode. Update the three golden-bytes tests to the new pinned bytes — and **measure the new
  bytes, do not hand-write them**; #0179's row 1 exists because a renamed key changes the wire
  silently.
- **Capture in `JournalCheckpoint`**, adding the snapshot's `keepAlive` oids to the anchor's
  parents. Note `AUTO_MERGE` holds a tree reachable from no ref — #0174 measured this — so omitting
  it leaves a restore pointing at an object maintenance may reclaim.
- **Restore in `JournalRestore`**, and stop reporting `.sequencer` as `.notCaptured` when it was.
- **Turn #0035's `midRebaseSequencerIsHonestlyReportedAsNotCaptured` into a real round trip**, using
  #0174's fixture: rebase to a conflict, checkpoint, wreck, restore, `git rebase --continue` runs to
  completion.

## Mutation rows this must carry

| # | mutation | expected |
|---|---|---|
| 1 | Capture the sequencer but leave `captured.sequencer` false | **RED** — restore skips it and the round trip fails. The honesty property is the point. |
| 2 | Omit the `AUTO_MERGE` oid from keep-alive | **RED** after aggressive gc — the restore finds a dangling tree |
| 3 | Skip zero-byte files (the #0174 trap, re-checked at this layer) | **RED** — the rebase does not resume |

## Notes

The pattern to copy is #0171, which wired the index and worktree the same way. Two lessons from that
issue apply directly: **do not locate a keep-alive commit through the code under test** (a helper
that reads parents returns a ref tip when the parent is missing, and the assertion passes for free),
and **do not claim a restore ordering is load-bearing without mutating it** — `WorktreeSnapshot`
aims at a temporary index, so ordering there turned out not to matter and the comment saying it did
was wrong.
