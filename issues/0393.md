## Description

**Filed 2026-09-12 at the coordinator's request; Brennan has not explicitly confirmed this one** — it
is being put to him directly.

Edit ▸ **Undo** (⌘Z) and **Redo** (⇧⌘Z) in the app reverse and replay journaled operations for the
repository in the key window, through `JournalUndo`. Today the journal's undo is an engine function
only: no `undo` arm exists in `YardCommands`, `switchyard` or `yard-engine` (*measured*, grep, #0359).
So every "undoable" claim in M7 has no path a human can reach.

### Engine calls (verified against source at `1b00f27`)

- `JournalUndo.undo(steps: Int = 1, command: String? = nil, agent: JournalEntryMetadata.Agent? = nil, lockTimeout: Duration = .seconds(10), in context: WorktreeContext, git: GitProcess = GitProcess()) throws -> [JournalRestore.Report]`,
  and `redo` with the same parameters. They throw `JournalUndo.Error.nothingToUndo` / `.nothingToRedo`.
- `JournalList.list(in context: WorktreeContext, git: GitProcess = GitProcess()) throws -> JournalList.Listing`.
  `Listing.items: [Item]` (`Item.entry`, `Item.metadata: JournalEntryMetadata?`) and
  `Listing.state: JournalChain.State` (`cursor`, `undoTarget`, `redoTarget: RedoStep?`).
  `JournalEntryMetadata.operation: String` is display-only (#0034 decision 7), which is exactly this use.
- `WorktreeContext.resolve(path:git:) async throws`.
- `JournalRestore.Report` carries `detachedFrom: String?` and `leftAlone: [String]`.

All three engine calls are synchronous. Wrap each in a `@concurrent` loader in
`YardKit/Sources/YardUI/RepositoryLoader.swift`, the pattern `forgetRerereResolution` uses.

### Behaviour

- **Titles name the operation.**
  - Undo: `Undo <title>`, from the operation of the entry `state.undoTarget` names.
  - Redo: `Redo <title>`, from the operation of the entry `state.cursor` names, when
    `state.redoTarget != nil`.

  This derivation comes from `JournalUndo`'s doc: undo restores `undoTarget` (the pre-operation
  capture of that operation), and the cursor then stands on it. *Unverified* — the fixture test proves
  it by undoing a reword and reading both titles.
- **Title map** (pure, in `YardKit/Sources/YardUI/JournalMenu.swift`):
  - measured from each engine's `around` call — `reword` → "Edit Message", `drop` → "Delete Commit",
    `reorder` → "Move Commit", `fixup` → "Fixup", `split` → "Split", `absorb` → "Absorb";
  - named by M8 — `revert` → "Revert", `cherry-pick` → "Cherry-Pick", `merge` → "Merge",
    `rebase-onto` → "Rebase", `set-tip` → "Set Branch Tip", `branch-create` → "New Branch",
    `branch-rename` → "Rename Branch", `branch-delete` → "Delete Branch", `tag-create` → "New Tag",
    `tag-delete` → "Delete Tag";
  - anything else, or no metadata → plain "Undo" / "Redo".
- **Disabled** when `undoTarget` / `redoTarget` is nil, while any in-app operation or undo runs, or
  when no repository is open.
- **After** a traversal, refresh through #0359's in-place refresh — never `ContentView.reload()`, which
  blanks the window. Keep the selection if its commit is still loaded; otherwise select `HEAD`.
- **When a report is not clean**: if any `Report.detachedFrom` is non-nil or `leftAlone` is non-empty,
  show an informational alert: "Undone, but “<branch>” is checked out in another worktree and was left
  as it is." (guide §11 decisions 16 and 23).
- **Failures** (a lock timeout, a cross-tool refusal) show an alert with the engine's message.
- **Text editing keeps its own undo.** Replacing the `.undoRedo` command group removes the system Undo
  that text fields and editors rely on (#0359's message editor, #0375's split sheet). When the key
  window's first responder is an `NSText` view, the menu items forward `undo:` / `redo:` down the
  responder chain (`NSApp.sendAction(Selector(("undo:")), to: nil, from: nil)`) instead of calling the
  journal. *Not compiled*; the reviewer checks ⌘Z inside the commit-message editor by hand.

### Wiring (*not compiled*)

- `YardKit/Sources/YardUI/JournalMenu.swift` (new):
  - the pure title map, `JournalMenuTitles.undo(operation:)` / `.redo(operation:)`;
  - a `JournalMenuTarget` value (titles, enabled flags, `perform(.undo | .redo)`), published by
    `ContentView` with `.focusedSceneValue`;
  - a `public struct JournalCommands: Commands` containing `CommandGroup(replacing: .undoRedo)`.
- `Switchyard/SwitchyardApp.swift`: `.commands { SwitchyardCommands(); JournalCommands() }` — the one
  app-side line.
- `ContentView` re-reads `JournalList.list` after every load and every in-app mutation, so the titles
  stay current.

## Expected behavior

- [ ] Edit ▸ Undo and Redo, with ⌘Z and ⇧⌘Z, traverse the journal of the key window's repository;
      their titles name the operation, and they disable when there is nothing to undo or redo.
- [ ] The graph, header and sidebar refresh in place after a traversal, and a not-clean `Report`
      surfaces its alert.
- [ ] The title map and the undoTarget/cursor derivation are unit-tested in
      `YardKit/Tests/YardUITests/JournalMenuTests.swift`; `swift test` prints `Test run with N tests`,
      and the text-field ⌘Z check is recorded by hand.
