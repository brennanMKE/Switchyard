## Description

`skills/yard/SKILL.md` is generated from the same command metadata that produces `--help` (#0010),
so it cannot drift from the binary. Hand-written prose restating flags goes stale within a milestone,
and a skill that lies about flags is worse than no skill.

**What is generated is reference; what is written is judgment.** Generate the command tables, flags,
exit codes, and schemas. Hand-write the short workflow narratives — how to go from a messy branch to
a clean one, when to checkpoint, what to do when `undo` refuses. Keep the two clearly separated in
the source so regeneration never clobbers the prose.

## Expected behavior

- [ ] `scripts/generate-skill.sh` produces `skills/yard/SKILL.md` from the metadata.
- [ ] Generated and hand-written regions are separated by explicit markers.
- [ ] Regeneration preserves hand-written prose — asserted by a test that runs it twice.
- [ ] A CI check fails when the committed skill is stale relative to the binary.
- [ ] Every command, flag, and exit code appears.

## Notes

Guide §8. Blocked by #0010. Ships continuously from M1 — a command lands with its documentation
regenerated or it does not land.

## The skill directory is `skills/switchyard/`, not `skills/yard/`

#0102 renamed the binary to `switchyard`. The `skills/yard/` path is still written that way in
`CLAUDE.md` and guide §4 and §8, deliberately — that directory does not exist yet, and renaming a
path to a thing nobody has built is churn.

**This issue creates it, so this issue picks the name: `skills/switchyard/SKILL.md`.** Update those
three prose references in the same change, so the docs and the filesystem agree the moment the
directory exists.
