## Description

**Found by the M1 milestone review, 2026-08-17.** #0142 promised this issue and it was never filed.

`WorktreeStatusEntry.State.init?(ychar:)` — `YardKit/Sources/YardGit/WorktreeStatus.swift:68` — has no
caller in the engine. #0142's mutation R4 is recorded **GREEN** for exactly that reason, with the note:

> *"Deleting it, or wiring it where the parser actually handles the Y column, is a separate change and
> belongs in its own issue."*

This is that issue. It is a real fork, not a cleanup: either the parser should be using it for the
worktree (Y) column and does not, in which case something is under-parsed, or it is dead and should
go.

## Expected behavior

- [ ] Establish which it is by reading how the parser handles the Y column today, and record the answer
      in the issue before changing anything.
- [ ] If dead: delete it, and confirm no test referenced it (a test that referenced dead code was
      testing nothing).
- [ ] If it should be wired: wire it, with a test that distinguishes a Y-column state the parser
      currently gets wrong, plus the mutation that kills it.
- [ ] `swift test` prints a `Test run with N tests` line; state the delta once the fork is settled —
      it is 0 for a deletion and +1 or more for a wiring.

## Notes

The cheap answer is "delete it", and the reason to look first is that #0142's mutation went green,
which means **no test can tell the difference either way** — that is equally consistent with dead code
and with a gap in the parser.
