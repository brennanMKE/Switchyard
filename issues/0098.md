## Description

The app has no icon — `Switchyard/Assets.xcassets/AppIcon.appiconset/` holds only the stock Xcode
template `Contents.json`, whose entries are **iOS** idioms on a macOS-only app. `Switchyard.png` at
the repo root is the artwork, and is already committed.

This task is mechanical: downscale, generate, copy, build. Everything you need to know has been
verified and is stated below as fact — do not re-derive it, and do not run `icongen -h` to check.

## Givens — all verified, treat as true

1. `Switchyard.png` is **1254×1254** and already tracked at the repo root. Nothing to do for it.
2. `icongen` requires a **1024×1024** source, so a downscale is required first.
3. **`icongen -p macOS -o <dir>/Assets.xcassets <src>` writes to `<dir>/Assets.xcassets/AppIcon-macOS.appiconset/`** —
   note the `-macOS` suffix. It does **not** write `AppIcon.appiconset`, and it does not create a
   catalog-root `Contents.json`.
4. That generated directory contains exactly 11 files: `Contents.json` plus ten PNGs named
   `mac-16.png`, `mac-16@2x.png`, `mac-32.png`, `mac-32@2x.png`, `mac-128.png`, `mac-128@2x.png`,
   `mac-256.png`, `mac-256@2x.png`, `mac-512.png`, `mac-512@2x.png` (16…1024 px).
5. Its `Contents.json` is already macOS-only — every entry is `"idiom" : "mac"` with a `filename`.
6. The Xcode build setting is `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`. **Do not change it.**
   The generated contents must therefore land in a directory still named `AppIcon.appiconset`.
7. `Switchyard/Assets.xcassets/` also contains `AccentColor.colorset/` and a catalog-root
   `Contents.json`. **Neither may be touched.** Only `AppIcon.appiconset/` changes.

## You cannot write outside the worktree

Your sandbox auto-rejects writes to `/tmp`, `/var/tmp`, and any path outside this working directory.
A previous attempt at this issue failed for exactly that reason and produced nothing.

Put every intermediate under **`build/`** inside the worktree. It is already in `.gitignore`, so it
stays untracked. Create it if absent.

## Expected behavior

- [ ] `build/Switchyard-1024.png` is produced from `Switchyard.png` with `sips -z 1024 1024`, and is verified 1024×1024. Downscale from the original, never upscale.
- [ ] `icongen -p macOS -o build/Assets.xcassets build/Switchyard-1024.png` runs successfully.
- [ ] The **contents** of `build/Assets.xcassets/AppIcon-macOS.appiconset/` replace the contents of `Switchyard/Assets.xcassets/AppIcon.appiconset/` — the destination directory keeps its `AppIcon.appiconset` name. Delete the destination's old contents first so no stale template file survives.
- [ ] `Switchyard/Assets.xcassets/AppIcon.appiconset/` ends up with exactly the 11 files listed in Given 4, and its `Contents.json` has no iOS entries.
- [ ] `Switchyard/Assets.xcassets/AccentColor.colorset/` and the catalog-root `Contents.json` are byte-identical to before — confirm with `git status`.
- [ ] `xcodebuild build -project Switchyard.xcodeproj -scheme Switchyard -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO -quiet` succeeds — paste the real output.
- [ ] The build emits no asset-catalog warning about a missing or mismatched icon size.
- [ ] `build/` is not staged and does not appear in `git status` as untracked noise.

## Notes

**Do not hand-write `Contents.json`.** Use the one `icongen` generated. A hand-edited catalog drifts
from the files on disk and fails at build time rather than at edit time.

**Do not touch signing settings.** An icon change never requires them; see `CLAUDE.md`.

If a command is rejected by the sandbox, do not announce a plan and stop — retry inside the worktree.
Round 1 failed by describing the remaining steps instead of running them.
