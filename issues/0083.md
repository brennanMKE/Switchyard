# 0083 — Persist and restore window and tab state

| | |
|---|---|
| **Status** | resolved |
| **Module** | Switchyard |
| **Milestone** | M3 |
| **Platform** | macOS |
| **First seen** | 2026-08-06 |

## Description

Reopening the app should restore the windows that were open, the repository tabs in each, their
order, and which tab was active. Without this, multi-window and tabs are a per-session convenience
that a restart throws away.

State belongs in the state directory from guide §3 (`$XDG_STATE_HOME/switchyard/`), which the CLI
and the app share.

## Expected behavior

- [ ] Windows, their tabs, tab order, and the active tab are restored on relaunch.
- [ ] A repository that has moved or been deleted is reported in its tab rather than crashing or silently vanishing.
- [ ] Restoration does not resurrect the phantom-window problem from #0078 — window count is asserted after a restore.
- [ ] Corrupt or partial state degrades to a single empty window, never to a crash loop.
- [ ] State writes are not so frequent that they thrash on every tab switch.

## Notes

Guide §3, §4 "Multiple windows". Blocked by #0029, #0079.

Test the deleted-repository case explicitly. Agent worktrees get created and torn down constantly,
so a stale tab pointing at a removed path is the normal case here, not an edge case.

## Placement — settled 2026-08-07

Every view and everything around it goes in **`YardKit/Sources/YardUI/`**, the package target created
by **#0126**. Not in the Xcode project.

The Xcode project keeps only the `@main` `App` type, the asset catalog, `Info.plist`, entitlements,
`SMAppService` registration, and the embedded `switchyard` binary.

**Why it matters for this issue specifically:** a view in the app target can only be exercised by a UI
test, and UI tests cannot run under CLI-driven `xcodebuild` on this machine — the runner times out
enabling automation mode without Accessibility rights. Anything built here would ship untested. In
`YardUI` it is reachable from `swift test`.

`YardUI` sets `.defaultIsolation(MainActor.self)`, so views are main-actor isolated exactly as they
are in the app target today.

Tests go in `Tests/YardUITests` and import **without** `@testable`, so they see what the app sees.

## Planning update — 2026-09-03. The files, the seams, and the verification count.

- `YardKit/Sources/YardUI/WindowState.swift` — `WindowStore` gains save/restore: the window list,
  each window's tab ids in order, and the active tab, as JSON.
- `YardKit/Sources/YardUI/RepositoryTabs.swift` — `RepositoryTabs` gains a restore seam: tabs are
  inserted keyed by the stored `commonDir` **without resolving** them. A stored tab whose repository
  has moved or been deleted stays present and is reported in its tab (the agent-worktree case, which
  is normal, not an edge case) — never dropped, never a crash.
- `Switchyard/SwitchyardApp.swift` — declarations only: stores restore from state on first
  construction. No logic a test would want moves into the app target.
- State lives in **`ServiceNames.stateDirectory()`** (#0029's seam, already used by
  `RepositoryRegistry` and `RecentOperations`) — reuse it; a second location is a bug.
- Writes are structural-change-driven (open/close/reorder/activate), debounced so a tab switch does
  not thrash. Tests assert the **count** of writes, never wall-clock time.
- Tests (`Tests/YardUITests/`, no `@testable`): save → fresh store → restore preserves windows, tab
  order, and the active tab; a restored tab whose `commonDir` no longer resolves stays present and
  reports missing; restore never exceeds the stored window count (the #0078 phantom trap, asserted
  after restore); corrupt/partial JSON degrades to one empty window.
- Verification: `cd YardKit && swift test` — **N greater than 1229**, the count on main before this
  change. `xcodebuild build … CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO` prints
  `** BUILD SUCCEEDED **`.
- Not testable here: a real relaunch. The store seam is the deliverable; the launch smoke test is
  #0125's.
