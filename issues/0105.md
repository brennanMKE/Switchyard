## Description

`YardKit/Tests/YardKitTests/YardBinaryContractTests.swift` (#0093) proves the stdout and exit-code
contract by spawning the real binary. It works, and it was mutation-checked. But **8 of its 9 tests
open with `guard binaryExists else { return }`** — so if the binary is missing they pass in 0.001s
having spawned nothing, and only the dedicated existence test fails.

The suite as a whole still fails loudly, which is why #0093 was accepted. But per-test quiet-skipping
is the exact shape that issue existed to eliminate, and it will be copied by the next subprocess test
someone writes.

Compounding it, `try? proc.run()` swallows a launch failure: an exec error that got past the
existence check surfaces as `status 0` and empty stdout — a confusing assertion failure rather than a
diagnostic.

## Givens — verified on `main`, treat as true

1. The file is `YardKit/Tests/YardKitTests/YardBinaryContractTests.swift`.
2. The locator is `Bundle(for: BundleAnchor.self).bundleURL.deletingLastPathComponent()
   .appendingPathComponent("switchyard")` and is **correct** — do not change it. `Bundle.allBundles`
   does not work here; see #0093.
3. `swift test` builds the executable, so a missing binary means something is genuinely wrong rather
   than merely un-built.
4. `main` is at 134 tests.

## The scan now finds six of these, not two

`scripts/check-tests-assert.sh` gained a **SKIPSHAPE** check on 2026-08-07 — a bare `return` inside a
`@Test` body, which exits before the assertions and reports success. It is **advisory**, not a hard
failure, precisely because six already exist and a detector that is always red is one nobody reads.
**This issue is what makes it promotable.**

```
GitProcessTests.swift:51            return
WhereAmITests.swift:87              guard let mPath = … else { return }
WorktreeContextTests.swift:195      guard let walker = fm.enumerator(…) else { return }
YardBinaryContractTests.swift:83    guard binaryExists else { return }
YardBinaryContractTests.swift:91    guard let dict = json as? [String: Any] else { return }
YardBinaryContractTests.swift:99    guard binaryExists else { return }
```

`WhereAmITests.swift:87` is the worst of them and is worth understanding before fixing any: the test
merges `repo.oids["a"]!`, which is an **ancestor**, so git says `Already up to date.` and exits 0,
`MERGE_HEAD` is never created, and the test returns before its single `#expect`. **Mid-merge has no
coverage at all**, and the test's name says it does. Fixing the `return` without fixing the merge
would just turn a silent pass into a failure.

## Expected behavior

- [ ] **All six SKIPSHAPE instances above are resolved** — each either fails loudly or genuinely
      cannot skip. Then make SKIPSHAPE a hard failure in `check-tests-assert.sh` by adding
      `$SKIPSHAPE` back to the `FOUND` loop, and say in the commit that you did.
- [ ] The two instances in `WhereAmITests.swift` and `WorktreeContextTests.swift` are **#0112's**,
      not this issue's. Coordinate: SKIPSHAPE can only be promoted once both issues have landed, so
      whichever lands second does the promotion and says so.
- [ ] A missing binary fails **every** test that needs it, with a message naming the path — not a
      silent early `return`. A shared helper that traps, or a `#require` on the URL, is fine; the
      requirement is that no test can pass without having spawned the process.
- [ ] `try? proc.run()` becomes a real `try` whose failure surfaces as a test failure naming the
      launch error.
- [ ] Dead code removed: `jsonStart` is built and never used, which is a compiler warning, and
      `_ = stdoutString(data: stdout)` discards its result.
- [ ] `successNoNonJsonPrefixOrSuffix` either checks a suffix or is renamed to say what it does. It
      currently checks only the first character. The real prefix/suffix guarantee comes from parsing
      the whole buffer in the other tests, so this one's name overstates it.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest.
- [ ] `cd YardKit && swift build` succeeds and `swift test` prints a `Test run with N tests` line you
      paste. **N must be greater than or equal to 134.**
- [ ] `swift build` produces **no warnings** from this file. Paste the build output.

## Tests must be able to fail

Prove it by mutation, and use the sharper of the two mutations from #0093's review:

- Rename the binary → every test that needs it must fail, not just the existence check.
- **Repoint the locator at `/bin/echo`** — a real executable that spawns and answers wrong. Tests must
  fail on the actual output. A missing-binary mutation only proves the existence check works.

Restore afterwards and confirm the suite is green and `git diff` is unchanged.
