## Description

Three rounds of #0096 failed to produce a working test file for it, and the cap is spent. This issue

pollutes stdout for a CLI whose contract is JSON on stdout, and it was reverted.

## The single fact that lost three rounds

**Git only marks an *unlocked* worktree `prunable`.** Delete a locked worktree's directory and
`git worktree list --porcelain` still reports only `locked <reason>` — never `prunable`. Verified
directly:

```
deleted, unlocked  →  prunable gitdir file points to non-existent location
deleted, locked    →  locked switchyard-agent:session=gone        (no prunable line)
```

Round 3's fixture created four worktrees and deleted only the two **locked** ones. So zero prunable
entries existed, and every `.prunable` assertion failed before any mutation was applied. The round's
own debug output said so — `prunable=false` on all five entries — and it spent the remaining twenty
minutes adding more logging instead.

**Deleting the *unlocked* worktree's directory is the only thing in the fixture that produces a
`.prunable` report.** One missing `removeItem` accounted for all four baseline failures.

## The second fact: a present agent-locked worktree is deliberately absent from `reports`

`gc` reports two kinds of entry and nothing else: `.prunable` and `.abandonedSession`. An agent-locked
worktree whose directory **still exists** is neither, so it does not appear. Round 3's tests looked it
up anyway, got `nil`, and force-unwrapped — which is what crashed the process.

It is present in the fixture precisely so a test can assert it is **absent** from `reports`. Assert
absence with `#expect(!reports.contains { … })`, never by looking it up.

## Tests must be able to fail

**Never write `#expect(x != nil)` followed by `x!`.** `#expect` records an issue and **keeps going**,
so the force unwrap traps, the test process dies, and swift-testing emits no run summary at all — the
whole suite's result is lost, not just that test's. Round 3 died exactly this way. Use
`let x = try #require(...)`, which stops the test.

Every `if let` that guards an assertion needs an `else` that records a failure, or it must be a
`try #require`. `scripts/check-tests-assert.sh` now flags a comment-only `else` as `EMPTYELSE`, and
flags `#expect(x != nil)` followed by `x!` as `EXPECTBANG`. **Run it — it currently reports all three
of this file's crash sites**, at lines 216, 241 and 295. Both scans must be clean before you finish.

Do not assert things no mutation can falsify. Round 3 had three: `#expect(!entries.isEmpty)` when the
main worktree is always listed, and `#expect(!reports.isEmpty)` self-described in its own message as
holding "regardless of mutation".
