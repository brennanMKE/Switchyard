## Description

The second journal snapshot primitive (git internals §3): this worktree's index, captured as a
real git object and restored exactly — including the unmerged case, which is the one place in the
project where reading a git file directly is correct, because the file *is* the state.

**One deliverable: `IndexSnapshot` with a round-trip-tested `capture`/`restore`.** One new engine
source file and one new engine test file. **Both are written out below in full and were compiled,
run, and mutation-tested in a scratch copy of this package (from `git archive` of `b85ff9e`) on
2026-08-08** — the suite measured **748 before and `Test run with 761 tests in 53 suites` after,
delta +13 exactly**, and all eleven mutation rows plus one fixture mutation were observed red with
the killing test recorded. The round's work is transcription plus running the verification.

**This is a two-round issue**, split at the file boundary because a single round writing two large
new files has truncated before (preflight 10b; #0019 r1, and #0027's round truncated once on a
~200-line `write`). Round 1 writes Change 1 and proves the tree still builds and passes at the
baseline. **Round 2 writes** Change 2 and lands the +13.

Consumed by #0171, which wires this into checkpoint and restore. Until then nothing calls it —
`JournalCheckpoint` keeps writing `captured: .refsOnly` and `JournalRestore.Report` keeps naming
the index `.notCaptured`.

## Decisions — settled at this planning pass, measured, binding on #0171

1. **Two capture forms, `.tree(oid:)` and `.raw(blob:)`, matching the wire exactly.**
   `JournalEntryMetadata.Captured.index` already encodes `false` / `"tree"` / `"raw"` (#0155
   decision 4, hand-written single-value `Codable`), and `JournalAnchor.Contents` already carries
   `indexTree` / `indexBlob` slots with tree-entry names `index` / `index.raw` (#0028). This type
   maps onto the two captured values through `IndexSnapshot.captured`; `false` is the caller's
   case — an entry carrying no `IndexSnapshot` at all. **#0171's stub says `index: "blob"` in two
   places; that wording is stale — the measured wire value is `"raw"`** (`JournalEntryMetadataTests`
   pins the bytes), and its planning pass must reconcile to `"raw"`.
2. **The ordinary index is a tree, built by `write-tree` against a temporary copy — never against
   the real index.** Measured: a *successful* `write-tree` writes a cache-tree extension back into
   its index file (Given 4), so pointing it at the real index mutates the state being captured. A
   *failed* `write-tree` leaves its index file untouched (also Given 4). `GIT_INDEX_FILE` is
   passed via `GitProcess`'s `extraEnvironment:`. Storage-wise the tree deduplicates: an index
   matching an existing tree costs no new objects, where a raw blob costs the compressed index
   (Given 9: 400 KB → 184 KB, 461 KB → 223 KB). Both paths are milliseconds (Given 9).
3. **The raw form is taken whenever a tree would lose something, decided by three measured
   triggers**, all evaluated against the copy so the decision and the captured bytes describe one
   moment of the index:
   - **Flag probe:** any `git ls-files -v` line not beginning `H ` — unmerged entries are tagged
     `M`, one line per stage (Given 3); `S` is skip-worktree; lowercase is assume-unchanged. A
     tree round trip silently clears the flag bits (Given 5), and a cleared skip-worktree bit in a
     sparse checkout reads as mass deletion.
   - **`write-tree` refusal:** the measured unmerged fatal (Given 1), kept as the catch-all behind
     the flag probe — any refusal, including one a future git adds, falls back to raw rather than
     failing capture, the same treat-unknown-as-safe rule the hook layer uses.
   - **Entry-count comparison:** `write-tree` *succeeds* on an index with an intent-to-add entry
     and silently drops it from the tree (Given 6) — success alone does not prove the tree
     faithful. `ls-files -s` (copy) versus `ls-tree -r <tree>` line counts; `write-tree` can only
     omit, never invent, and both listings quote special characters into single lines.
4. **A split index is normalized on the copy before either form.** The split link file references
   `sharedindex.<sha>`, which git prunes on its own schedule, and a blob of the link alone is
   fatal once it does (Given 7). `update-index --no-split-index` against the copy merges the
   shared entries in — conflict stages preserved, real index untouched — and is a **byte-identical
   no-op on a non-split copy** (Given 7), so the byte-for-byte claim survives normalization
   unqualified in the ordinary case.
5. **Raw restore writes the blob's bytes to the index file atomically**, resolved through
   `WorktreeContext.path(for: "index")` — in a linked worktree that is
   `$GIT_DIR/worktrees/<name>/index` (Given 8), and `<topLevel>/.git/index` is not even a
   directory path there. `Data.write(options: .atomic)` stages into a sibling temporary file and
   renames, so no reader sees a partial index. This is the sanctioned exception to *"never read
   `$GIT_DIR` with `FileManager`"* (CLAUDE.md): no plumbing exists that writes arbitrary bytes to
   the index file, because the byte-exact file **is** the state being restored. Tree restore is
   `git read-tree <oid>`, which writes under git's own `index.lock` protocol and replaces an
   unmerged index without complaint (Given 2). Neither touches the worktree: entries whose files
   moved on read as modified afterwards, which is what they are.
6. **No lock is taken here.** Like `RefSnapshot`, this is a primitive; #0171 composes it inside
   `JournalRestore`/`JournalCheckpoint`'s existing `JournalLock.withLock`. A concurrent *non-git*
   writer racing the atomic rename is the same cross-tool hazard every git tool has, and the
   guard's domain, not this type's.
7. **Errors are `IndexSnapshot.Error`, `ExitClassCarrying` as `.repositoryError`,
   `CustomStringConvertible` naming the path/command** — both conformances asserted (#0181/#0182:
   9 of 26 `ExitClassCarrying` conformances shipped unasserted before), each with a mutation row.

## Givens — each measured on this machine, git 2.50.1 (Apple Git-155), 2026-08-08

1. **`git write-tree` refuses an unmerged index**, verbatim, exit 128 — re-measured this pass on a
   fresh three-stage conflict (both-sides-edit `f.txt`, the `FixtureRepository.conflicted()`
   shape):

   ```
   f.txt: unmerged (4b48deed3a433909bfd6b6ab3d4b91348b6af464)
   f.txt: unmerged (b19a1e93bec1317dc6097229e12afaffbfa74dc2)
   f.txt: unmerged (950b81b7eee953d050aa05a641f8e056c85dd1bd)
   fatal: git-write-tree: error building trees
   exit=128
   ```

2. **The raw blob round-trips byte-identically, non-vacuously.** On the real conflicted index
   (262 bytes): `git hash-object -w -- <index>` → `caf8b1f4…`; `git cat-file blob` → `cmp` against
   the file: identical. End to end: 3 unmerged entries recorded, conflict resolved (`ls-files
   --unmerged` then empty — the wreck verified non-vacuous), bytes written back over the index:
   `ls-files --unmerged` identical to the recording and the file identical to the blob;
   `git status --porcelain` prints `UU f.txt`, exit 0. An earlier probe of this pass compared two
   *empty* unmerged listings because the wrecking merge had been refused — the vacuity was caught
   and re-measured, which is why the non-empty guard is load-bearing in the tests below.
3. **`ls-files -v` tags:** a conflicted index prints `M f.txt` once per stage (three lines);
   skip-worktree prints `S sw.txt`; assume-unchanged prints lowercase `h sw.txt`; a plain cached
   entry prints `H f.txt`. **An intent-to-add entry also prints `H`** — the flag probe cannot see
   it, which is what the count comparison is for.
4. **`write-tree` mutates its index file on success and not on failure.** Copy of a merged index:
   `write-tree` exit 0 printed a tree and the copy **differed** from the original afterwards
   (cache-tree extension; the real index untouched). Copy of a conflicted index: exit 128 and the
   copy byte-identical afterwards.
5. **A tree round trip clears flag bits.** With `S sw.txt` set, `write-tree` on a copy then
   `read-tree <tree>`: `ls-files -v` shows `H sw.txt`. The flag survives nowhere in a tree.
6. **`write-tree` silently drops intent-to-add entries.** With `ita.txt` added `-N`: `ls-files -s`
   lists it (as the empty blob `e69de29…`), `write-tree` exits 0, and `ls-tree -r` of the result
   does **not** contain it — same tree oid as without the entry. An ita file is also invisible to
   `ls-files --others` (measured — binding note for #0152 below).
7. **Split index, four measurements.** (a) A conflicted index *can* be split (`update-index
   --split-index`, exit 0; link file 114 bytes against the 262-byte original). (b)
   `update-index --no-split-index` with `GIT_INDEX_FILE=<copy>` merges the shared entries into the
   copy — all three unmerged entries preserved, 262 bytes again, real index untouched. (c) The
   same command on a **non-split** copy is a byte-identical no-op (shasum unchanged). (d) With the
   `sharedindex.*` file deleted, reading the split index — real or copy — is
   `fatal: … index file open failed: No such file or directory`, exit 128.
8. **Paths.** `git rev-parse --path-format=absolute --git-path index` in a linked worktree returns
   `<commonDir>/worktrees/<name>/index` (measured). In a repository with no commits and no index
   file yet, git treats the missing file as an empty index: `ls-files -v` prints nothing and
   `write-tree` prints the empty tree `4b825dc642cb6eb9a060e54bf8d69288fbee4904`, both exit 0; a
   later `read-tree` recreates the file.
9. **Costs, 5000-file repo (400 KB index), five runs each:** the full tree path (copy + normalize
   + flag probe + `write-tree` + count check) ~48 ms per capture; the raw path (copy + normalize +
   `hash-object -w`) ~20 ms. Loose-blob sizes: 400 759 B index → 184 440 B object; the real
   `git/git` fixture's 461 240 B index → 222 872 B. Neither path is a performance concern; the
   tree form is preferred for the ordinary case because it deduplicates to zero marginal objects
   when the tree already exists.
10. **Baseline.** `docs/test-baseline.txt` read **748** as this pass finished, and the scratch
    archive of `b85ff9e` measured **748 in 52 suites** with these files absent and **761 in 53
    suites** with them present. The delta is **+13** — thirteen new test functions, two of them
    parameterized over both ref formats. Trust the delta, not the absolute.

// IndexSnapshot.swift — capture and restore of this worktree's index (#0151)

import Foundation

/// A point-in-time capture of this worktree's index, restorable exactly —
/// the second journal snapshot primitive (git internals §3). The index is
/// per-worktree state, resolved through `WorktreeContext.path(for: "index")`,
/// never by concatenating onto `.git/`.
///
/// Two capture forms, matching the entry metadata's wire values
/// (`JournalEntryMetadata.IndexCapture`: `"tree"` / `"raw"`) and the anchor
/// tree-entry names (#0028: `index` / `index.raw`):
///
/// - **`.tree`** — the ordinary case. The index is copied to a temporary
///   file and `git write-tree` runs against the copy via `GIT_INDEX_FILE`,
///   so the real index is never touched. Measured: a *successful*
///   `write-tree` writes a cache-tree extension back into its index file,
///   which is why capture must never aim it at the real one.
///
/// - **`.raw`** — the index file's own bytes, stored as a blob. This is the
///   one place in the project where reading a git file directly is correct,
///   because the file *is* the state (CLAUDE.md): `git write-tree` refuses
///   an unmerged index outright (measured: the stage lines plus
///   `fatal: git-write-tree: error building trees`, exit 128), and a tree
///   cannot carry per-entry index flags at all. The blob round-trips
///   byte-for-byte (measured: `hash-object -w` → `cat-file blob` → `cmp`,
///   identical).
///
/// The raw form is taken whenever a tree would lose something, each trigger
/// measured on git 2.50.1:
///
/// - **Unmerged entries.** `ls-files -v` tags them `M`, and `write-tree`
///   refuses them.
/// - **`skip-worktree` and `assume-unchanged` flags** (`S` / lowercase
///   tags). A tree round trip silently clears them — measured: `S sw.txt`
///   became `H sw.txt` — and a cleared skip-worktree bit in a sparse
///   checkout reads as mass deletion.
/// - **Intent-to-add entries.** `write-tree` *succeeds* and silently drops
///   them from the tree (measured: the entry present in `ls-files -s`,
///   absent from `ls-tree -r`), so success alone does not prove the tree is
///   faithful; the entry-count comparison catches what the flag probe and
///   the exit code both miss.
///
/// A split index (`git update-index --split-index`) is normalized before
/// either form: the raw link file references `sharedindex.<sha>`, which git
/// prunes on its own schedule, and a blob of the link alone dangles once it
/// does (measured: `fatal: … index file open failed`, exit 128). Running
/// `update-index --no-split-index` against the *copy* merges the shared
/// entries in — conflict stages preserved, real index untouched — and is a
/// byte-identical no-op on a non-split copy (both measured), so the ordinary
/// byte-for-byte claim survives normalization.
///
/// Like `RefSnapshot`, this primitive takes no lock: the composing flows
/// (#0171) run it inside `JournalLock.withLock`.
public enum IndexSnapshot: Sendable, Equatable {

    /// A plain merged index, captured as the tree `write-tree` built from
    /// the temporary copy. Deduplicates against existing objects — an index
    /// matching `HEAD` costs nothing new — and stays valid as long as the
    /// anchor holds it reachable.
    case tree(oid: String)

    /// The index file's bytes as a blob, self-contained (split form merged),
    /// restored byte-for-byte.
    case raw(blob: String)

    /// This capture as the entry metadata records it — the `false` case is
    /// the caller's (an entry that carries no `IndexSnapshot` at all).
    public var captured: JournalEntryMetadata.IndexCapture {
        switch self {
        case .tree: .tree
        case .raw: .raw
        }
    }

    public enum Error: Swift.Error, Equatable, CustomStringConvertible, Sendable {
        /// The index file exists but could not be copied or read.
        case indexFileUnreadable(path: String, detail: String)
        /// A raw restore could not write the index file back.
        case indexFileUnwritable(path: String, detail: String)
        /// A plumbing command printed nothing where a single OID was
        /// required.
        case malformedPlumbingOutput(command: String)

        public var description: String {
            switch self {
            case let .indexFileUnreadable(path, detail):
                "cannot read index file \(path): \(detail)"
            case let .indexFileUnwritable(path, detail):
                "cannot write index file \(path): \(detail)"
            case let .malformedPlumbingOutput(command):
                "\(command) printed no object id"
            }
        }
    }

    // MARK: - Capture

    /// Captures this worktree's index without modifying it.
    ///
    /// A repository whose index file does not exist yet (fresh `git init`)
    /// reads as empty everywhere below — measured: `ls-files -v` prints
    /// nothing and `write-tree` prints the empty tree, both exit 0 — so it
    /// captures as `.tree` of the empty tree with no special case.
    public static func capture(
        in context: WorktreeContext,
        git: GitProcess = GitProcess()
    ) throws -> IndexSnapshot {
        let base = context.topLevel ?? context.gitDir
        let indexPath = try context.path(for: "index", git: git)
        let workCopy = FileManager.default.temporaryDirectory
            .appendingPathComponent("switchyard-index-\(UUID().uuidString)")
        defer { try? FileManager.default.removeItem(at: workCopy) }
        let environment = ["GIT_INDEX_FILE": workCopy.path]

        // The one sanctioned direct read of a `$GIT_DIR` file: the copy is
        // the moment being captured, and every probe below runs against it,
        // so the decision and the captured bytes cannot describe different
        // states of the index.
        var snapshotBytes: Data?
        if FileManager.default.fileExists(atPath: indexPath) {
            do {
                try FileManager.default.copyItem(
                    at: URL(fileURLWithPath: indexPath), to: workCopy)
            } catch {
                throw Error.indexFileUnreadable(
                    path: indexPath, detail: String(describing: error))
            }
            // Normalize a split index into its self-contained form on the
            // copy (byte-identical no-op otherwise, measured) — a blob of
            // the split link file would dangle when git prunes
            // sharedindex.<sha>. Reads the shared file from the real
            // repository via `-C`.
            try git.run(["update-index", "--no-split-index"],
                        workingDirectory: base, extraEnvironment: environment)
            do {
                snapshotBytes = try Data(contentsOf: workCopy)
            } catch {
                throw Error.indexFileUnreadable(
                    path: workCopy.path, detail: String(describing: error))
            }
        }

        // Raw trigger 1: any entry not plainly cached. `M` is an unmerged
        // stage (one line per stage, measured), `S`/lowercase are
        // skip-worktree and assume-unchanged flags a tree cannot carry.
        let flags = try git.run(["ls-files", "-v"],
                                workingDirectory: base, extraEnvironment: environment)
        if flags.lines.allSatisfy({ $0.hasPrefix("H ") }) {
            // Raw trigger 2: write-tree refuses (the unmerged fatal, and
            // any refusal a future git adds — falling back is always safe,
            // so no output parsing decides this).
            let written = try git.capture(["write-tree"],
                                          workingDirectory: base,
                                          extraEnvironment: environment)
            if written.exitCode == 0, let tree = written.lines.first, !tree.isEmpty {
                // Raw trigger 3: the tree must carry every entry.
                // write-tree succeeds while silently dropping intent-to-add
                // entries (measured), so the entry counts are compared —
                // write-tree can only omit, never invent, and both listings
                // quote special characters into single lines.
                let inIndex = try git.run(["ls-files", "-s"],
                                          workingDirectory: base,
                                          extraEnvironment: environment)
                let inTree = try git.run(["ls-tree", "-r", tree],
                                         workingDirectory: base)
                if inIndex.lines.count == inTree.lines.count {
                    return .tree(oid: tree)
                }
            }
        }

        guard let snapshotBytes else {
            // Unreachable: a missing index file is empty, and an empty index
            // has no flags, no refusal, and no dropped entries.
            throw Error.indexFileUnreadable(
                path: indexPath, detail: "no index file to snapshot")
        }
        let hashed = try git.run(["hash-object", "-w", "--stdin"],
                                 workingDirectory: base,
                                 standardInput: snapshotBytes)
        guard let blob = hashed.lines.first, !blob.isEmpty else {
            throw Error.malformedPlumbingOutput(command: "hash-object")
        }
        return .raw(blob: blob)
    }

    // MARK: - Restore

    /// Applies the capture to this worktree's index.
    ///
    /// - `.tree` restores through `git read-tree`, which writes under git's
    ///   own `index.lock` protocol and replaces an unmerged index without
    ///   complaint (measured: exit 0 over a three-stage conflict, entry
    ///   list identical to the capture). The restored entries carry no stat
    ///   cache, so the next status re-stats the worktree — slower once,
    ///   never wrong.
    ///
    /// - `.raw` writes the blob's bytes back to the index file atomically:
    ///   `Data.write(options: .atomic)` stages into a temporary file and
    ///   renames it into place, so no reader ever sees a partial index. The
    ///   worktree is untouched either way; entries whose files moved on
    ///   simply read as modified, which is what they are.
    public func restore(
        in context: WorktreeContext,
        git: GitProcess = GitProcess()
    ) throws {
        let base = context.topLevel ?? context.gitDir
        switch self {
        case let .tree(oid):
            try git.run(["read-tree", oid], workingDirectory: base)
        case let .raw(blob):
            let bytes = try git.run(["cat-file", "blob", blob],
                                    workingDirectory: base).standardOutput
            let indexPath = try context.path(for: "index", git: git)
            do {
                try bytes.write(
                    to: URL(fileURLWithPath: indexPath), options: .atomic)
            } catch {
                throw Error.indexFileUnwritable(
                    path: indexPath, detail: String(describing: error))
            }
        }
    }
}

}
