## Description

**Finding of the M1 milestone review, third pass, 2026-08-17.** M1 exit criterion 5 — *"every engine
function has tests that can fail: each has a mutation recorded against a named test that dies under
it"* — is unmet for `whereAmI`'s four count fields.

**Mutation, measured.** `YardKit/Sources/YardGit/WhereAmI.swift:306-309`, the return site:

```swift
        stashCount: 0,
        untrackedCount: 0,
        unstagedCount: 0,
        stagedCount: 0,
```

`Test run with 1047 tests in 78 suites passed after 83.518 seconds` — **full suite, unfiltered, zero
failures**.

A weaker and far more realistic mutation survives too: dropping `--cached` from the `stagedCount`
probe at `WhereAmI.swift:263`, so the field silently reports the *unstaged* count:

```swift
            ["diff-index", "--name-status", "HEAD"], workingDirectory: path),
```

`Test run with 1047 tests in 78 suites passed after 81.039 seconds`.

**Why nothing catches it.** Every call site in the suite that reaches these four fields asserts them
equal to zero, in a fixture that cannot produce anything else:

| where | what it asserts |
|---|---|
| `YardKit/Tests/YardGitTests/WhereAmITests.swift:26-29` | all four `== 0`, in a repository with **no commits** |
| `YardKit/Tests/YardGitTests/FailingGitFixture.swift:55-58` | all four `== 0` under a git that exits non-zero |
| `YardKit/Tests/YardWireTests/WhereAmIWireTests.swift:28,42,60,124` | constructs a `WhereAmI` **value literal** — never calls the function |
| `YardKit/Tests/YardCommandsTests/WhereAmICommandTests.swift` | `branch`, `headOID`, `conflictCount` only |

No fixture in the suite ever stashes, stages, edits, or leaves an untracked file and then asks
`whereAmI` what it sees.

**The adjacent fields are covered**, so this is a precise gap, not a general complaint: mutating
`headOID`/`rawHead` to `""` (`WhereAmI.swift:312-313`) reddens
`PipelineContractTests."whereAmI is public and its fields are reachable"` and
`WhereAmICommandTests.repositoryPathReturnsSuccessEnvelopeWithBranchAndShortOID`.

All four fields are published in `YardKit/Schemas/whereami.json:96-119` as non-optional ints with
agent-facing meanings, so an agent reads them and believes them.

## Expected behavior

- [ ] A fixture with **asymmetric** counts — 1 stash, 2 untracked, 3 unstaged, 4 staged — so a
      mutation that *transposes* any two fields dies as well as one that zeroes them. Equal counts
      would let a transposition survive, which is the defect this issue is about, one level up.
- [ ] A named test in `YardKit/Tests/YardGitTests/WhereAmITests.swift` asserting all four against that
      fixture, each to its own distinct value.
- [ ] **Mutation 1:** zero all four at `WhereAmI.swift:306-309`. The new test must redden.
- [ ] **Mutation 2:** drop `--cached` at `WhereAmI.swift:263`. The new test must redden — this is the
      realistic one, and a test that only catches mutation 1 has not met the criterion.
- [ ] **Mutation 3:** transpose `unstagedCount` and `stagedCount` at the return site. The new test must
      redden. Confirm each mutation landed on the line you meant before believing any run.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.

## The files

`YardKit/Tests/YardGitTests/WhereAmITests.swift`, and `YardKit/Tests/YardGitTests/FixtureRepository.swift`
if the fixture needs a helper to reach the asymmetric state. **No production change** — `WhereAmI.swift`
is correct; nothing can detect it being wrong.
