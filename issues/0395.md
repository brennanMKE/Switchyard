## Description

The VM policy (2026-09-22, `docs/ui-test-automation-vm.md`, AGENTS.md Rule 13) removes the reason
#0382, #0383, #0385 and #0386 were blocked on human observation: inside the Tart guest, Automation
Mode is enabled without authentication, so XCUITest can synthesize the hover/keystroke/click
interactions an unattended host process cannot. This issue re-derives the four blocked spike
observations as automated UI tests run in the VM, and resolves the spikes from the test results.

Parent context: #0380 (umbrella). #0381 and #0384 are already resolved and are not re-derived.

### Decisions recorded under Rule 12 (high confidence, reversible)

- **S0 sharing model: clone-and-diverge.** `tart clone changeover-uitest-golden
  switchyard-uitest-golden` (APFS COW, cheap). Reason: the golden must carry a different Xcode
  than Changeover's eventually; sharing one golden recreates the "golden carries both Xcodes"
  problem. The clone starts identical, so Changeover runs are unaffected.
- **Guest toolchain for first runs: Xcode 26.6 on guest macOS 26.4, as-is.** Host Xcode 27.0 has
  `LSMinimumSystemVersion` **26.6** (measured 2026-09-22 from
  `/Applications/Xcode.app/Contents/Info.plist`), so it cannot launch on the 26.4 guest. The four
  spike questions are about macOS 26 SwiftUI behaviour, so 26.4 is the right environment anyway.
  **Filed question:** does Switchyard's current `main` build with the 26.6 toolchain, or has the
  host's 27.0 upgrade introduced 27-only APIs? The first guest build answers it; if it fails, the
  fix is a newer base image tag (guest macOS ≥ 26.6), which costs a ~68 GB pull and needs Brennan's
  disk call — blocked on that answer only if the build actually fails.
- **Test shape: a new `SwitchyardUITests` XCUITest target** driven only inside the guest. The
  `Switchyard` scheme's Test action stays unit-tests-only; the UI scheme is invoked only in the
  guest (Changeover's pattern).
- **Script location: `scripts/run-ui-tests-vm.sh`**, adapted from Changeover's
  `run-ui-tests-vm.sh` with its non-negotiables intact (run-id-shaped sweep, EXIT trap, read-only
  export share, results via `tart exec` tar stream, memory preflight).

### Guest compatibility gate (before any UI test is authored)

1. Clone the golden, boot headless, verify: `sw_vers`, `xcodebuild -version` (26.6 17F113),
   `automationmodetool` (mode disabled + authentication not required), console user `admin`.
2. Export `main` via `git archive HEAD` into a per-run directory under `build/`, share read-only,
   copy into the guest, and run `swift build` on the `YardKit` package with the guest toolchain.
   Green build = the VM can build Switchyard today; red build lists the 27-only APIs blocking it.

### Round 1 scope (planning update, 2026-09-22)

One deliverable: the pipeline proves itself end to end with a smoke test. The four spike
re-derivations are later rounds against the working pipeline.

- **`scripts/run-ui-tests-vm.sh`** (new) — adapted from
  `~/Developer/brennanMKE/Changeover/run-ui-tests-vm.sh` (read it; keep its non-negotiables:
  run-id `switchyard-uitest-<YYYYMMDD>-<HHMMSS>-<pid>`, EXIT trap before creating anything,
  `git archive HEAD` export, run-id-shaped stale-clone sweep that can never match a golden,
  read-only `--dir` share, results pulled back through `tart exec` tar streaming, memory
  preflight). It clones **`switchyard-uitest-golden`** (the Switchyard golden, decision S0) and
  runs `xcodebuild -project Switchyard.xcodeproj -scheme 'Switchyard UITests' -destination
  'platform=macOS' test` in the guest.
- **`Switchyard/AppDelegate.swift`** — a `-uiTestRepository <path>` launch argument handled at
  startup that calls `RepositoryOpener.open(path:)` (`YardKit/Sources/YardUI/RepositoryOpener.swift`
  line 32, the non-interactive gate) so a UI test launches the app with a repository already open,
  no `NSOpenPanel`. Fixture repositories are generated per-run **inside the guest** (`git init` +
  scripted commits) — nothing is shared read-write, nothing host-live is touched.
- **`Switchyard.xcodeproj`** — a `SwitchyardUITests` target (XCUITest) plus a shared scheme
  **`Switchyard UITests`** whose Test action runs only that target; the `Switchyard` scheme's Test
  action stays unit-tests-only. The pbxproj edit is the risky part — verify with
  `xcodebuild -list` and `-showBuildSettings` after editing, and keep the target's settings
  unsigned (`CODE_SIGNING_ALLOWED=NO`).
- **`SwitchyardUITests/SmokeUITests.swift`** (new) — launches the app with
  `-uiTestRepository <fixture>` and asserts the repository header shows the fixture's branch
  name. This is the pipeline proof, not a spike re-derivation.

The guest golden is `switchyard-uitest-golden` (cloned from the updated
`changeover-uitest-golden`: macOS 26.6.2, Xcode 27.0 27A266a, Automation Mode auth-free — gate
recorded in `docs/ui-test-automation-vm.md`). Stop the gate clone before running; the script
manages its own clones.
