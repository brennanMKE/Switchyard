## Description

**Split out of #0051 on 2026-08-17.** #0051 lands the installer's state machine, its reports, and
`shellQuoted`. This issue performs the act: create the symlink at `/usr/local/bin/switchyard`, sweep the
legacy `~/.local/bin/switchyard` first, uninstall in full reverse, and drive both from
**File ▸ Install Command Line Tool…**.

Split because everything here needs an admin authorization prompt and a real filesystem outside a temp
directory, which is the opposite of what makes #0051's half testable.

## Expected behavior

- [ ] Install runs `mkdir -p <dir> && ln -sfn <bundled> <destination>` through `NSAppleScript` with
      administrator privileges, every path passed through #0051's `shellQuoted`.
- [ ] **The legacy link is cleared first**, in the same privileged step. It sits earlier on `PATH`, so
      leaving it shadows the install that just succeeded.
- [ ] A cancelled authentication dialog is **not** an error — it is a user decision, and it must not
      surface as a failure alert. RemoteControl's installer distinguishes them by the AppleScript error
      number; read it there rather than guessing the code.
- [ ] Install **refuses** when `isBundleDurable` is false, with the reason.
- [ ] Uninstall removes the link and leaves nothing behind, and the state machine reports
      `notInstalled` afterwards.
- [ ] The File menu item is added to the app's command surface, and it presents #0051's `Report`
      values. The installer still presents nothing itself.
- [ ] Verified by hand, by Brennan or by a human at the machine, and the steps recorded in
      `scripts/verify-xpc.md` (#0054) or a sibling document. **A round may not install anything on this
      machine.**

## Notes

`../../RemoteControl/docs/cli-embedding-and-install.md` §4 and §5, and
`../../RemoteControl/BridgeKit/Sources/BridgeKit/CLIInstaller.swift` (MIT, same author).
**Blocked by #0051 and #0050** — there is nothing to link until the binary is embedded.

The `NSAppleScript` call is made in-process rather than by shelling out to `osascript`; the source
comment there explains why, and it matters for how the authorization prompt is attributed.
