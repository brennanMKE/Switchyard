# 0238 — The ref_updates kind's date encoding is unpinned

## Description

**Proposal from #0160's second umbrella review, 2026-08-17**, filed as an ordinary issue because it is
#0153's surface rather than #0160's.

`JournalObserved.record(_ updates:…)` — the **`ref_updates`** overload — sets
`encoder.dateEncodingStrategy = .iso8601`, and **nothing pins it**. Deleting that line leaves
`swift test --filter "JournalObserved|ReferenceTransaction"` green at 31 tests. Only the `rewrites`
kind has a byte-exact test through the production write path
(`aForeignRewriteRecordWritesTheExactPinnedBytes`, added by #0235).

Without the strategy a `Date` encodes as a raw epoch `Double`, so the two observed kinds would drift
into different on-disk shapes with nothing to notice.

## Expected behavior

- [ ] One test mirroring `aForeignRewriteRecordWritesTheExactPinnedBytes` for the `ref_updates` kind:
      drive `JournalObserved.record(_ updates:…)` with a fixed `now:`, read the blob back off disk, and
      assert the full byte string including `"timestamp":"…Z"`.
- [ ] Mutation: delete `encoder.dateEncodingStrategy = .iso8601` from that overload and confirm the new
      test reddens with the epoch-double form. Restore, confirm green.
- [ ] `cd YardKit && swift test` twice in the foreground, both green, above the count in
      `docs/test-baseline.txt`.

## Notes

Small and self-contained. `aForeignRewriteRecordWritesTheExactPinnedBytes` in
`YardKit/Tests/YardGitTests/JournalObservedTests.swift` is the template — including reading the blob
through the file's `cat-file` helper rather than `JournalAnchor.metadata(for:in:git:)`, which
hardcodes the journal namespace (that is **#0236**'s to fix; if #0236 lands first, use the accessor).

Related: #0153 (observed ref transactions), #0235 (which added the strategy and pinned the other kind).
