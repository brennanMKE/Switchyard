## Description

Entries expire on a count limit and an age limit, both configurable, defaulting to generous values
since the marginal cost of a snapshot is a few small objects.

Pruning deletes the anchor ref and the metadata entry together; the objects then become unreachable
and ordinary maintenance reclaims them. **`yard` never calls `git gc` itself** — deciding when to
repack someone's repository is not this tool's business.

## Expected behavior

- [ ] Count limit and age limit both implemented and configurable.
- [ ] `yard journal --prune` removes anchor ref and metadata entry atomically — never one without the other.
- [ ] No `git gc` invocation anywhere in the codebase, asserted by grep.
- [ ] Pruning is safe to interrupt: a killed prune leaves no dangling metadata pointing at a deleted ref.
