## Description

Side-by-side screenshots of the same repository (Batty, 2,061 commits, 13 visible branches) taken
2026-09-12, both windows showing the same checkout:

- `build/gitup-batty.png` — GitUp's Map view: every branch is a **colored lane** with its name
  labeled at the tip (`main` in red carrying a HEAD badge, `issue/0404` orange, `issue/0364`
  yellow, `issue/0405` green, `issue/0403` purple, `issue/0402` pink, …), remote lanes
  (`origin/main`) drawn **dashed**, merge points drawn as converging curves into the lanes they
  merged into, and a status line reading "On branch main · tracking upstream origin/main ·
  12 commits ahead". One glance answers: what branches exist, where each diverged, what is merged,
  where HEAD sits, and how far the branch is ahead.
- `build/switchyard-batty.png` — Switchyard showing the same repo: the sidebar's "Branches"
  section is a **flat alphabetical list** of names with identical generic icons — no lanes, no
  tip commits, no ahead/behind, no indication of which branches are merged, scrolled off after a
  dozen entries. The main area is a flat commit list whose only nod to topology is a single thin
  vertical line with dots — one lane, no branch colors, no divergence, no merges visible. A
  reviewer cannot see where any branch diverges, whether it is merged, or what the history's
  shape is.

**The engine already has the hard part.** `yard graph` exists (#0003's lane assignment —
`LaneAssignment.swift`, stable topo order, generation numbers), and `YardUI` already ships
`LaneGeometry.swift` and `LaneGutterView.swift`. The pieces are built and tested; the app's main
history view simply does not use them. This is not a "build a graph engine" issue — it is "wire
the existing engine output into the app's history view and the sidebar's branch list".

## Expected behavior

- [ ] The app's history view renders the commit graph with **per-branch colored lanes** from the
      engine's lane assignment — merges drawn as converging edges, not a single straight line.
- [ ] Branch tip labels render at their lane's head, with a HEAD marker on the current branch.
- [ ] Remote lanes render visually distinct (dashed or dimmed), the way GitUp distinguishes them.
- [ ] The sidebar's Branches section binds to live data: tip oid, ahead/behind vs upstream, and
      merged-into-main indication — not a flat name list with generic icons.
- [ ] The tracking status ("on branch main, 12 ahead") is visible without opening a detail pane.
- [ ] The window title names the open repository (measured: it reads "Switchyard" while GitUp's
      reads "Batty" — a second window cannot be told apart from the first).
