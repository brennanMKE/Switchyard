## Description

`EnvelopeError.code` is typed `String`, so a consumer branches on a free-form string and
`matchExitCode()` cannot be exhaustive — it ends in `default: fatalError`. Change the field to the
enum that already exists beside it.

This is a small, local change. **Roughly five lines of production code.** If you find yourself
rewriting the file, stop — you have misread the task.

## Givens — verified on `main`, treat as true

The file is **`YardKit/Sources/YardKit/Envelope.swift`**. It exists. Read it before editing.

1. `public enum EnvelopeErrorCode: String, Sendable` is declared at line 83 and already has all ten
   cases with their wire strings: `ok`, `usage`, `broker_unreachable`, `app_unavailable`,
   `request_failed`, `session_terminated`, `repository_error`, `human_declined`,
   `blocked_on_conflicts`, `signing_failed`.
2. **Those raw values are the wire contract. Do not rename a case and do not change a raw value.**
   A previous round changed `case usage = "usage"` to `case usageError = "usage_error"` and broke the
   JSON output.
3. **Do not add cases.** In particular do not add an `.unknown` case — a catch-all is a free-form
   string wearing an enum's clothes, and removing that is the entire point of this issue.
4. `EnvelopeErrorCode` already has `public var exitCode: ExitCode` (line 155), a switch over all ten
   cases with **no `default:`**. It is already exhaustive and correct. Use it.
5. `EnvelopeError` is declared at line 171. Today: `public let code: String`, its `init` does
   `self.code = code.rawValue`, and `matchExitCode()` (line 204) switches over *string literals* and
   ends `default: fatalError(...)` at line 216.
6. `ExitCode` in `YardKit/Sources/YardKit/ExitCode.swift` is complete and correct. Do not edit it.
   The exit-code mapping is fixed and codes 2-5 match RemoteControl exactly, so they are not
   renumberable: `ok`→0, `usage`→1, `brokerUnreachable`→2, `appUnavailable`→3, `requestFailed`→4,
   `sessionTerminated`→5, `repositoryError`→6, `humanDeclined`→7, `blockedOnConflicts`→8,
   `signingFailed`→9.
7. `matchExitCode()` keeps its signature: `public func matchExitCode() -> ExitCode`, an **instance**
   method on `EnvelopeError` switching on `self.code`. Do not make it static and do not change what
   it takes or returns. Round 1 re-derived it as `static func matchExitCode(_ exitCode: Int32) ->
   EnvelopeError?`, and a switch over `Int32` can never be exhaustive — which made the criterion
   unsatisfiable by construction.
8. These types already exist in the same file and **must not be rewritten or removed**:
   `EnvelopeFail`, `EnvelopeSchema`, `EncodableResult`, `StandardStream`, `write()`, `terminate()`.
   Round 1 lost all six by rewriting the file.

## Expected behavior

- [ ] `EnvelopeError.code` is typed `EnvelopeErrorCode`, not `String`.
- [ ] The `init` stores the enum directly rather than `.rawValue`.
- [ ] `matchExitCode()` contains **no `default:` and no `fatalError`**. Once `code` is the enum this
      is simply `code.exitCode` — do not write a second ten-case switch that duplicates line 155.
- [ ] The emitted JSON is **byte-identical** to before: `"code"` is still the snake_case string, not
      an object or a number. `EnvelopeErrorCode` already encodes as a single value, so this holds if
      you leave its `encode(to:)` alone.
- [ ] `EnvelopeErrorCode` declares `CaseIterable`. This is additive, changes no wire format, and is
      what makes "every case" mechanically true instead of only true in a test's name.
- [ ] A test iterates the **synthesized** `allCases` — not a hand-written array — and asserts, for
      every one of the ten cases, that encoding an `EnvelopeError` built from it produces the
      expected wire string, and that `matchExitCode()` returns the matching `ExitCode`.
- [ ] That test opens with `#expect(EnvelopeErrorCode.allCases.count == 10)` so the loop cannot
      silently run zero times.
- [ ] `swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N
      must be **greater than 82**, the count on `main` before this change.

## Tests must be able to fail

A previous round wrote `for code in allCases { guard case .ok = code else { continue }; ... }`, which
iterates ten cases and tests one, under a name promising all ten. It was green and it proved nothing.

- Every iteration of a loop over cases must reach an assertion.
- Every test function must contain at least one `#expect`.
- Enumerate cases with `CaseIterable`, never a hand-written array. A hand-written list means the
  next case added is silently untested and nothing fails.
- Note the polarity: inside a loop, `if case .x = v { continue }` **skips** `.x` and is fine;
  `guard case .x = v else { continue }` **discards everything except** `.x` and is a coverage bug
  even though it compiles. Round 1 shipped both spellings four lines apart in one file.

Before you finish, re-read each test and ask what production change would make it fail. If the answer
is "none", it is not done.
