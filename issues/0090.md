# 0090 — Make EnvelopeError.code a closed enum

| | |
|---|---|

## Description

`EnvelopeErrorCode` already exists as a closed enum on `issue/0011`, but `EnvelopeError.code` is
still typed `String`, so a consumer still branches on a free-form string. One field, one type change.

The criterion is explicit for a reason: an agent must be able to branch on the error code safely. A
`String` cannot be exhaustively switched, which is why `matchExitCode()` currently ends in
`default: fatalError`.

## Expected behavior

- [ ] `EnvelopeError.code` is typed `EnvelopeErrorCode`, not `String`.
- [ ] `matchExitCode()` switches exhaustively over the enum with **no `default:` and no `fatalError`**.
- [ ] The enum's raw values are the snake_case wire strings, so JSON encoding is unchanged.
- [ ] A test round-trips every case through `JSONEncoder`/`JSONDecoder` and asserts the wire string.
- [ ] `swift build` succeeds and `swift test` prints a `Test run with N tests` line you paste.

## Notes
