## Description

**Finding 2 of the M1 milestone review, ninth pass, 2026-08-18 — and it lands on the tests #0287 itself
created.** All three of #0287's failure-path tests assert only **that** the engine threw, never **what
the error carried**.

Each uses a bare `#expect(throws: SomeError.self)` and never inspects the thrown value:

| production site | test | surviving mutation |
|---|---|---|
| `WorktreeList.swift:85` — `couldNotList(detail: output.standardError)` | `WorktreeListTests.swift:369` `notARepositoryThrowsCouldNotList` | `detail: ""` |
| `WorktreeWhere.swift:58` — `couldNotListWorktrees(detail: list.standardError)` | `WorktreeWhereTests.swift:249` `couldNotListWorktreesThrowsWhenListFails` | `detail: ""` |
| `WorktreeRepair.swift:39` — `notRepaired(detail:, exitCode: Int(output.exitCode))` | `WorktreeRepairTests.swift:377` `notARepositoryThrowsNotRepaired` | `exitCode: 0` |

All three applied together: `Test run with 1110 tests in 78 suites passed after 55.058 seconds` — and
each also survived its own filtered run.

**Each of those tests carries the docstring** *"Criterion 3 forbids a success value with empty fields on
a failed `git` call"* — **and then permits precisely a structured error with empty fields, undetected.**
That is the irony worth fixing rather than the mere gap.

**The exit class is separately pinned** and the review confirmed it rather than assuming: mutating
`WorktreeWhere.Error.exitClass` to `.signingFailed` kills `worktreeWhereErrorCasesAreRepositoryErrors`
and `everyRegistrySampleCarriesItsDeclaredClass`. **This is the detail payload only.**

**The pattern already exists one file over**, from the same era: `WhereAmITests.swift:286-288` asserts
`path == dir` and `detail.contains("not a git repository")` on `WorktreeContext.Error.notARepository`.

## Expected behavior

- [ ] Each of the three tests binds the thrown error and asserts its **payload**: that `detail` contains
      git's actual message (`"not a git repository"` for two of them; whatever the shim produces for
      `yardWhere`), and that `notRepaired`'s `exitCode` is git's real non-zero code.
- [ ] Use `#expect(throws:)`'s closure form or a `do`/`catch` that binds — **not** a bare type check.
      `WhereAmITests.swift:286-288` is the model.
- [ ] **Do not assert git's exact wording.** `detail.contains(...)` on a stable fragment, not equality
      with a full message — git's phrasing is not ours to pin.
- [ ] **Mutations, one per site:** `detail: ""` for the two, `exitCode: 0` for the third. Each must
      redden its own test and no other. Confirm each landed where you meant.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, at or above the count in `docs/test-baseline.txt` (strengthening three existing tests may
      not move it — say so explicitly if it does not).
