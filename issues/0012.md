## Description

The single highest-value command in the project. An agent today spends four or five `git`
invocations and fragile text parsing to answer "where am I"; this replaces that preamble with one
call and one object.

Contents: branch, upstream, ahead/behind, in-progress rebase/merge/cherry-pick, stash count, dirty
paths, and conflict count.

**Scoped down 2026-08-06 after round 1 timed out.** Signing configuration moved to #0108, and the
sibling-worktree object to #0109. Both were independently useful and neither is needed to answer
"where am I" at all.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/WhereAmI.swift`. Create it; do not restructure existing files.
- [ ] One call returns every field above; no field requires a follow-up command.
- [ ] Correct on a detached `HEAD`, mid-rebase, mid-merge, mid-cherry-pick, and in a linked worktree.
- [ ] Correct on an empty repository with no commits — a common agent starting state.
- [ ] Tested against both ref formats via the fixture harness (#0024).
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N must be greater than the count on `main` before this change.

## The API you must use — read these files before writing code

Round 1 wrote 679 lines against types that do not exist, and only opened `GitProcess.swift` in the
last five lines of its log. **Read `YardKit/Sources/YardGit/GitProcess.swift` and
`WorktreeContext.swift` first.** Everything below is verified.

**`GitProcess` is a concrete struct, not a protocol.**

```swift
public struct GitProcess: Sendable {
    public init(executablePath: String = "/usr/bin/git")
    public func run(...)      // -> Output
    public func capture(...)  // -> Output
}
```

There is **no** `GitProcess.GitRunner`, no `Platform`, and no injection seam. Construct it with
`GitProcess()` and call it. Do not invent an abstraction to make it testable — the tests run against
real repositories built by `FixtureRepository`.

**`WorktreeContext` has no memberwise init and no nested `WorktreeInfo`.** It is built by
`WorktreeContext.resolve(...)` and exposes `topLevel: String?`, `gitDir`, `commonDir`,
`worktreeName: String?`, `isLinkedWorktree`, `isBare`, plus `path(for:git:)` and `resolveRef(...)`.

**Never touch `.git/…` with `FileManager`.** Round 1 did this four times:

```swift
FileManager.default.fileExists(atPath: basePath + "/.git/rebase-merge")   // rejected
```

`rebase-merge`, `rebase-apply`, `MERGE_HEAD` and `CHERRY_PICK_HEAD` all come from
**`git rev-parse --git-path <name>`**, which is correct in a linked worktree and on a reftable
repository, where `.git/refs` does not exist at all. That is a hard project rule in `CLAUDE.md`, not
a preference.

## Fixture affordances that already exist

Do not build repository states by hand. `FixtureRepository` provides `build(_:)`, `branch(_:at:)`,
`checkout(_:)`, `checkoutDetached(_:)`, `addWorktree(named:branch:)`, `writeUntracked(_:)`,
`beginInterruptedRebase(onto:)`, `revParse(_:)`, `refNames()`, `isMidRebase`, `destroy()`, and
`RefFormat.supported(git:)` for the dual-format sweep.
