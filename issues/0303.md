## Description

**Finding of #0160's tenth umbrella review, 2026-08-18.** `attachingRewrite`'s carry-through is
unpinned — **and the test that claims to prove it cannot fail.**

`YardKit/Sources/YardGit/JournalEntryMetadata.swift:125-132` states the decision in its own comment:
*"Every other field carries through unchanged (#0221)"*. Mutating line 130 to drop them all:

```diff
-            guardRefs: guardRefs, agent: agent, traversal: traversal,
+            guardRefs: [:], agent: nil, traversal: nil,
```
(with `command: nil, label: nil` above)

`✔ Test run with 1110 tests in 78 suites passed after 52.862 seconds.` — **full suite.** Narrowed to
`agent: agent` → `agent: nil` **alone**: green again. So `command`, `label`, `guardRefs`, `agent` and
`traversal` are **each individually unpinned**; an attach may blank all five and nothing notices.

## The test that looks like the pin is a tautology

`PostRewriteAttachTests.swift:287-293`:

```swift
// Every other field comes back byte-identical: comparing the
// re-read metadata to the pre-attach value with the mapping added
// by hand (rather than through `attachRewrite` again) proves the
// persisted bytes, not just the in-memory value, carry every
// untouched field forward.
#expect(after == beforeAttach.attachingRewrite(mapping))
```

**The parenthetical is wrong about its own mechanism.** `attachRewrite` builds the stored value as
`existing.attachingRewrite(mapping)` — so **both sides of the `==` run the same function on the same
input**. Any field-handling change inside `attachingRewrite` applies identically to both sides, which is
exactly why the mutation stays green. The expectation does pin the serialize/deserialize round trip; it
cannot pin the carry-through it says it pins.

That is **`AGENTS.md` Rule 7 from the reviewer's side**: a test whose body cannot fail for the property
its name and comment claim.

## Why it matters, and the honest limit

`traversal`'s presence **is** the entry kind (guide §11 decision 7), and `agent`/`command` are exactly
the fields `around(operation:at:command:agent:)` exists to carry for M3's CLI. A lossy attach rewrites
an entry into something the chain and the listing read differently.

**Stated plainly: nothing can observe this today.** No in-tree caller passes `command` or `agent` to
`around`, no production writer populates `guardRefs`, and the only entries carrying `traversal` are
undo/redo entries, which rewrite no commits and so never receive an attach. **It is latent, and it goes
live the first time M3's CLI supplies `command`/`agent` to a `fixup`.**
