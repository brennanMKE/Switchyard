## Description

**Finding 3 of the M1 milestone review, fourteenth pass, 2026-08-18.** `log` returns **mojibake** under
`i18n.logOutputEncoding`.

`YardKit/Sources/YardGit/CommitLog.swift:195` passes no `--encoding`. `i18n.logOutputEncoding=ISO-8859-1`
re-encodes `%B` and `%an` out of UTF-8, and `GitProcess.Output.text` (`GitProcess.swift:79`) is
`String(decoding:as: UTF8.self)` — **lossy rather than failing**. Measured through `CommitLog.run`:

```
PROBE log default subject:      [sujet café élève]
PROBE log ISO-8859-1 subject:   [sujet caf� �l�ve]

bytes default: [… 99,97,102,195,169 …]
bytes iso:     [… 99,97,102,239,191,189 …]      (U+FFFD)
```

**A `schemaVersion: 1` envelope is UTF-8 by definition**, so this is the same category as the existing
`core.quotepath=false` pin — not a user preference.

## Expected behavior

- [ ] `CommitLog.run` passes `--encoding=UTF-8`.
- [ ] A named test with a **non-ASCII commit subject and author** under `i18n.logOutputEncoding=ISO-8859-1`,
      asserting the round-trip is byte-exact.
- [ ] **Assert on bytes, not just on the string.** The failure produces U+FFFD, which compares unequal to
      the original but *looks* like a string difference; asserting the UTF-8 bytes makes the report
      unambiguous, and the review's measurement is in that form.
- [ ] **Verify the config bites first**: plain `git log --format=%s` under it must produce the
      replacement characters.
- [ ] **Mutation:** drop `--encoding=UTF-8`. The new test must redden.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, above the count in `docs/test-baseline.txt`.
