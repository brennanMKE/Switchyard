**Why nothing catches it:** all six tests that call `WorktreeRepair.run` assert cardinality only —
`reports.count == 1` (`WorktreeRepairTests.swift:108`), `!reports.isEmpty` (`:168`, `:188`, `:349`),

against `parseReport` fed hand-written stderr strings (`:51-52, 62-63, 72-73, 85-86`).

So the engine can return a constant repair record of the right length and the milestone's `wt repair`
coverage does not notice.
