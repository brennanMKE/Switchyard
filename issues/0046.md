## Description

A plain double-clicked app cannot publish a named Mach service — `NSXPCListener(machServiceName:)`
only works when launchd owns the name, and launchd only learns a name from a launchd property list.
So a small launch agent embedded in the bundle declares the name and acts as a bootstrap broker.

The broker holds the app's anonymous listener endpoint so the CLI can find it. `NSXPCListenerEndpoint`
is a live Mach right — it can be passed over an existing XPC connection and nowhere else, never
written to disk — which is the entire reason a broker must exist rather than the app leaving its
endpoint somewhere readable.

## Expected behavior

- [ ] Publishes `co.sstools.Switchyard.broker` via its launchd plist and `MachServices`.
- [ ] Accepts and stores the app's endpoint; hands it to CLI clients on request.
- [ ] `yard ping` reaches it with the app never launched — launchd starts it on demand.
- [ ] Restarting the broker mid-session does not disturb an attached CLI, verified manually.
- [ ] Holds no traffic after the handoff — it is out of the data path.

### The shape, read from the source

```swift
@objc public protocol BrokerProtocol {
    /// Liveness check that does not depend on the app running at all.
    func brokerPing(reply: @escaping @Sendable (String) -> Void)
    /// Called by the app after it creates its anonymous listener.
    func registerAppEndpoint(_ endpoint: NSXPCListenerEndpoint)
    /// Called by the CLI. Replies `nil` when no app has registered.
    func appEndpoint(reply: @escaping @Sendable (NSXPCListenerEndpoint?) -> Void)
}
```

Three details from RemoteControl's implementation that are load-bearing and easy to lose in a port:

1. **The endpoint registry is guarded by a lock, not an actor.** XPC invokes each connection's methods
   on its own queue, so the registry is reachable from several queues concurrently. Its own comment
   says why a lock rather than an actor.
2. **Only the connection that registered may clear the endpoint.** RemoteControl tracks whether *this*
   connection is the registering one; without that, any client could clear another's registration.
3. **`@Sendable` on every reply closure.** CLAUDE.md's gotcha: XPC invokes these off the main queue, and
   under `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` an unmarked closure inherits main-actor isolation
   and **crashes with `SIGTRAP` at runtime with no compiler warning**. #0045 set the BrokerAgent target
   to `SWIFT_DEFAULT_ACTOR_ISOLATION = nonisolated`, which reduces the risk in *this* target — but the
   app side, which #0047 writes, is MainActor by default, so the protocol must carry `@Sendable`
   regardless.

## Where the protocol goes

**`YardKit`, not `YardGit`.** It is an XPC/app identifier concern, the same category as `ServiceNames`,
and `YardGit` must not grow app-layer surface (guide §11 decision 13's reasoning applies unchanged).
Put it in `YardKit/Sources/YardKit/XPCProtocols.swift`, matching RemoteControl's file name.

**The broker executable is not a package target**, so it cannot `import YardKit` unless #0045's Xcode
target is given the product dependency. **Check first**: if `BrokerAgent` has no `YardKit` product
dependency, adding one is in scope for this issue and is the same four-line pbxproj edit #0045 made —
and **Xcode must be closed**, per Rule 5d and #0045's precondition. If it is already there, say so.

## What cannot be verified in this round, and must not be faked

**`yard ping` reaching the broker with the app never launched is #0048's criterion, not this one** — the
CLI client does not exist yet. Do not write a test that claims it.

**launchd on-demand start cannot be exercised here either**: it needs the agent registered with launchd,
which is `SMAppService` (#0049) and a real install. This issue's criterion *"`yard ping` reaches it with
the app never launched"* is therefore **deferred to #0048/#0049** — say so in the report rather than
inventing a probe. `docs/xpc-cli-architecture.md` in RemoteControl describes the manual verification,
and #0054 owns writing ours.

**What you *can* test in this round**: the endpoint registry as a plain type — store, read back, clear
by the owning connection, clear rejected from a different one. Extract it so it is testable without XPC,
which is what makes this issue more than a transcription.
