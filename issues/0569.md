## Description

This pass came after every open feature issue had resolved. It looked for rough edges that nobody
had filed, the way a daily user would hit them. Two methods:

1. **Throwaway exploratory XCUITests in the VM.** They lived in a detached worktree and were never
   committed. They drove whole flows on the existing fixtures, with a screenshot at every step and
   soft checks, so one run surfaced as much as possible. The flows:
   - changes fixture: open, Stage Hunk, Diff Options while the staged side is shown, commit with
     the composer, Amend, Undo Amend, Undo Commit, the network buttons with no remote, every menu's
     enabled state, 900 pt;
   - switch fixture: switch over a local change, Stash Changes and Switch, back, Pop, Show History,
     Blame, a blame link, close;
   - large-history fixture: open, Paths and Content search, a commit's file, Blame, History, 900 pt;
   - remotes fixture: Add Remote with a duplicate name and with a bad URL, Fetch the bad remote,
     Remove, Rename to an invalid name, a second repository as a tab, ⌘T, an empty tab's menus and
     toolbar;
   - focused reproductions of a static audit's findings.

   In all: five `run-ui-tests-vm.sh` runs and 17 clones. `tart list` was clean after each run.
2. **A read-only static audit of `YardUI`** (a subagent), covering: swallowed errors, busy flags,
   enablement, stale state and layout. Its findings were **filed only where a VM run reproduced
   them**. The rest are listed under Observations.

Every filed issue carries its before-fix evidence (a screenshot and the failing spike step), the
literal change, a VM spike, and a named mutation. #0570-#0573's fixes, together with their spikes,
were trialled in the VM from the planner's throwaway worktree and passed (run `r3`). #0574's was
trialled in run `r4`, which also showed that two of its original parts were not real defects or
had no mechanical fix. #0574 was narrowed and says why.

## Observations — not reproduced, or not defects, so not filed

- **Commit actions stay enabled while Undo/Redo runs**, and Undo stays enabled while
  Continue/Abort/Resolve runs. Static audit: `ContentView.isBusy` omits `journalRunning`, and
  `journalMenuTarget`'s `busy` omits `conflictActionRunning`. Every other runner guards both. A real
  asymmetry, but a timing race the VM runs could not hit on the small fixtures. **Worth a
  planning pass on its own.** The fix is two boolean terms, but proving it needs a slow journal
  traversal.
- **⌘⌫ in the sidebar Filter triggers Delete Commit…** (static audit). **Not reproduced.** With a
  branch row selected and text in the filter, ⌘⌫ cleared the field and no dialog appeared
  (VM, 2026-09-30).
- **A selected commit rewritten outside the app.** The audit said the refresh keeps a
  `selectedCommit` that is gone. On the main fixture, `git commit --amend` in the guest followed by
  re-activation left the old tip still reachable from `spike-side` and `alpha-fork`, so it was not
  gone. Not reproduced. It needs a fixture whose rewritten commit is on no other branch.
- **Silent failures.** None of these was triggered in the VM:
  - a failed Paths/Content search shows "0 matches" (`CommitHistoryView` `catch { found = [] }`);
  - a failed Diff Options reload shows the standard diff under a non-standard option;
  - a failed Co-Author `interpret-trailers` does nothing;
  - a failed sidebar reload after a rerere Forget leaves a spinner.

  Each is a `try?` or empty `catch` in `YardUI`. A search on `5994` in Content scope reports
  **2 matches**, not 1. That is correct: `-S` finds commit 5994, which adds the string, and 5995,
  which removes it.
- **History's "merged" dimming is keyed on lane names, not oids** (`CommitHistoryView` `.task(id:)`).
  Likely stale after an in-app merge, the same shape as #0571. Not exercised in the VM. Check it
  when #0571 lands.
- **File ▸ Open Recent lists only repositories already open** (`Switchyard/Commands.swift`). The
  file's own comment says this is deliberate for now. **Brennan's call:** a real recent-documents
  list, or rename the menu.
- **A `switchyard://` open once came up as a second window, not a tab.** Seen once, in the
  remotes run, after two Add Remote sheets and a failure alert in the first window:
  `windows=2 tabs=0`. A probe (run `r4`) reported `windows=1 tabs=2` straight after a
  `-uiTestRepository` launch, and `windows=1 tabs=3` for a third repository. Not reproduced.
  The suspect is a sheet or alert in the key window. Worth a spike that opens a repository
  while an alert is on screen.
- **Add Remote with a URL that does not exist** adds the remote, then shows a clear
  `Couldn't Fetch "broken"` alert (git's message verbatim), and the remote stays configured.
  Arguably right, since `git remote add` does the same, but a user may expect the add to be
  refused. Duplicate names and names with spaces are refused (the confirm button stays
  disabled). That is good.
- **Dark mode** could not be checked. Neither `-AppleInterfaceStyle Dark` as a launch argument
  nor `defaults write -g AppleInterfaceStyle Dark` from the test runner before launch changed the
  app's appearance in the guest. With the launch argument, the first attempt opened **no
  window** within 60 s. **VM tooling gap:** the golden image needs dark appearance set at the
  image level (or an `osascript` System Events toggle) for a dark run. The static audit found
  no hardcoded `Color.black`/`.white` outside two `.clear`-blend punch-outs.
- **SmokeUITests failed as the second launch after a long exploratory flow** 3 times in 7
  clones (the branch "never appeared"). A resize-then-quit probe and an idle probe (run `r3`)
  both passed. This is consistent with the documented launch-count quirk, and no app defect was
  shown.
- **`Stash Changes…` wraps onto two lines at 900 pt.** Recent Messages, Co-Author and a one-line
  Stash Changes… need about 290 pt, and the Detail pane has 280. That is a design question
  (icon-only buttons? move Stash Changes… again?), not a mechanical fix. **Brennan's call.**
- **The macOS "App Background Activity" notification** covers the top-right of every guest
  screenshot, including the toolbar's Push button and the Filter field. Known VM trap (#0432).
