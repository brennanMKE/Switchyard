## Description

The engine is a hybrid: libgit2 for the object database, DAG traversal, index, diff, blame, and
merge; `git` for network operations, hooks, signing, worktrees, and sparse checkout. That boundary
is only maintainable if it is visible in one place.

One `GitProcess` type owns every invocation. No `Process` construction scattered through the
codebase. This also makes the boundary testable and makes it possible to move operations across it
later — which #0004 may force wholesale.

## Expected behavior

- [ ] `GitProcess` handles argument construction, environment, working directory, stdin, and exit codes.
- [ ] stderr is captured and surfaced in errors rather than discarded.
- [ ] Environment is explicit: `GIT_EDITOR` and pagers are disabled so nothing can ever go interactive.
- [ ] A marker environment variable is set so the hook handler can recognize `yard`'s own invocations (#0042).
- [ ] Tests cover a failing command, a command producing large output, and one taking stdin.
- [ ] Grep confirms no other `Process(` in `YardGit`.

## Notes

Guide §5 "The hybrid boundary". Blocked by #0006.

## Fix

`GitProcess` in `YardGit` owns every `git` invocation. `run` throws on non-zero exit;
`capture` returns the result whatever the code, for commands that use exit status as information
(`diff --quiet`, `merge-base --is-ancestor`). `-C` carries the working directory rather than the
process CWD, so git resolves it the way git does — including for worktrees.

## Verification

`swift test` — **24 tests in 4 suites passed**. Covers the three cases the issue named plus the
boundary guard: a failing command carrying stderr, ~600 KB of output, stdin via
`update-ref --stdin`, and no `Process(` outside `GitProcess.swift`.

Two of the new tests found real bugs in *themselves* on first run, which is the guards working:
`noOtherSwiftSourceHardcodesTheIdentifiers` (from #0007) caught this file using the literal
`refs/switchyard/`, and the boundary guard's path was one directory short. Both fixed.

## Gotchas

**Both pipes must be drained concurrently.** Reading stdout to completion before stderr deadlocks as
soon as stderr fills its buffer — invisible on small output, which is exactly what a naive test
produces. `handlesOutputLargerThanThePipeBuffer` generates ~600 KB specifically to catch it.

**`git var GIT_EDITOR` is the real assertion**, not the environment dictionary. Setting the variable
proves nothing about whether git honors it; asking git does.

**`YardGitTests` cannot import `YardKit`** — that is the layering rule — so engine tests cannot use
`ServiceNames` constants and must use neutral values. The stdin test uses `refs/test/stdin-batch`
rather than the journal namespace for this reason.
