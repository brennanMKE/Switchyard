## Description

The end-to-end composition the M2 criterion gestures at, split from #0030 at its 2026-08-08
planning pass: **regenerate `journal.json` from a `JournalRebuild.Result`, and prove that
deleting the cache and rebuilding yields rows equal to what was lost.** #0030 deliberately
neither reads nor writes the cache (its Decision 5) — rebuild consulting the cache would
derive the cache from itself — so the rewrite lands here, against #0156's real
`JournalMetadataCache` API once it exists.

**Structured stub. Re-authored to code level at its own planning pass before dispatch, per
CLAUDE.md.**

## Facts to build on, measured at #0030's pass (2026-08-08)

- `JournalRebuild.rebuild(in:)` returns `Result(entries: [RecoveredEntry], defects: [Defect])`,
  entries oldest-first, `metadataJSON` byte-exact (mutation-pinned). Cache-only fields are
  derivable: `snapshotRef` is `JournalAnchor.refName(for: id)`.
- #0030's `rebuildIgnoresAndSurvivesDeletionOfTheCacheDirectory` already deletes
  `<commonDir>/switchyard/` for real and proves rebuild output is unaffected; what it cannot
  prove before #0155/#0156 exist is row-level equality between a written cache and a rebuilt
  one. That equality test is this issue's deliverable.

## Expected behavior — sketch; re-author to code level at dispatch

- [ ] A function (home decided at planning: `JournalRebuild` extension or `JournalMetadataCache`
      member) that writes the #0156 cache file from a `JournalRebuild.Result` plus #0155 decode.
- [ ] The test: populate ≥3 entries through the normal write path, snapshot the cache rows,
      delete `$GIT_COMMON_DIR/switchyard/` recursively for real, rebuild, rewrite, and assert
      the recovered rows equal the snapshot. Undecodable metadata surfaces as the #0155 typed
      error or a reported row-level defect — never a silently invented row.
- [ ] A mutation table, every row applied and observed red with the killing test named;
      criterion stated as a delta over the then-current baseline.
