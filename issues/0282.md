## Description

**Finding 7 of the M1 milestone review, sixth pass, 2026-08-18.** `wt gc` reports an abandoned session's
**lock reason** and nothing checks it.

`YardKit/Sources/YardGit/WorktreePrune.swift:136`, mutated:

```swift
return Report(path: path, type: .abandonedSession, lockReason: "switchyard-agent:MUTATED")
// was: lockReason: entry.lockReason
```

`Test run with 1078 tests in 78 suites passed after 82.154 seconds.` — **full suite, unfiltered.**

**Why nothing catches it:** `WorktreePruneGcTests.swift:293` asserts `abandonedEntry.lockReason != nil`
and nothing more. The fixture writes `switchyard-agent:session=gone` (`:52`) and never compares against
it. `MaintenanceWireTests.swift:38` pins the wire bytes from a directly constructed `Report`.

**The lock reason carries the session id** — the actionable part of an abandoned-session report, and
what a human or agent uses to decide whether the session is really gone. The engine can substitute one
constant for every worktree undetected.

**The sibling fields are covered, and the review confirmed that rather than assuming it:**
`Report.reason` and `Report.removable == true` die under mutation, because `MaintenanceWireTests.swift:49-59`
calls the real `report(entries:)`. Only `lockReason` has no engine-level path.

## Expected behavior

- [ ] `WorktreePruneGcTests` asserts the reported `lockReason` **equals** the reason the fixture wrote
      (`switchyard-agent:session=gone`), not merely that it is non-nil.
- [ ] Two abandoned worktrees with **different** session ids in one report, so a mutation returning one
      constant for all of them dies as well as one returning a fixed string.
- [ ] **Mutation:** the constant `lockReason` above. Must redden. Confirm it landed on line 136.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.
