# 0353 — CLI install: the AppTranslocation gate is missing and the DerivedData refusal does not say what to do

| | |
|---|---|
| **Status** | open |
| **Module** | YardKit |
| **Milestone** | M6 |
| **Platform** | macOS |
| **First seen** | 2026-09-11 |

## Description

Two gaps in `CLIInstaller` (`YardKit/Sources/YardKit/CLIInstaller.swift`), both already solved in
Batty and portable under the MIT sibling rule:

1. **No AppTranslocation refusal.** `isBundleDurable` checks only `/DerivedData/` and
   `/Build/Products/`. A user who downloads a release DMG and runs the app straight from
   `~/Downloads` gets Gatekeeper translocation — macOS runs the app from a read-only
   `/private/var/folders/…/AppTranslocation/<uuid>/` mount — which contains neither substring, so
   the gate passes and `install()` creates a symlink into a mount macOS reclaims. Batty's #0275
   fixed exactly this: add `/AppTranslocation/` to the check and throw a **distinct**
   `bundleTranslocated` error whose message says to drag the app to `/Applications` *and relaunch*
   (a translocated instance stays translocated until relaunch — telling the user only to move the
   app would have them retry in the still-translocated instance).
2. **The DerivedData refusal does not say the way out.** Measured 2026-09-11: running the app from
   Xcode DerivedData (the normal developer path) makes every install attempt refuse
   `bundleNotDurable` — correct by design (a symlink into a build product dies on the next clean),
   but the demo user read it as "the app is broken". The refusal message must say the remedy:
   move the app to `/Applications`, relaunch, then install.

## Expected behavior

- [ ] `isBundleDurable` refuses `/AppTranslocation/` bundles with a distinct, actionable error.
- [ ] The `bundleNotDurable` message names the remedy (move to `/Applications`, relaunch).
- [ ] Tests pin both refusals and their messages (the four-state inspection tests' idiom).

## Notes

to Switchyard's `CLIInstaller`), `docs/batty-cli-install.md` §5. The install surface itself is
