## Description

Brennan, 2026-09-12: `WhereAmI` gains a revert-in-progress state, filed as its own issue (engine and
schema). **Blocks #0360**, whose menu items must not leave a conflicted revert invisible.

### Measured (git 2.50.1, 2026-09-12, plain git in a scratch repository)

A three-commit history editing one file (`a` → `b` → `c`), then `git revert --no-edit HEAD~1`:

- exit status 1 (conflict);
- `$(git rev-parse --git-path REVERT_HEAD)` **exists**; `CHERRY_PICK_HEAD` does not; there is no
  `sequencer` directory;
- line 2 of `git status`: `You are currently reverting commit facab7d.`

`WhereAmI` probes only `MERGE_HEAD` and `CHERRY_PICK_HEAD`, in both the synchronous and asynchronous
`whereAmI` (`YardKit/Sources/YardGit/WhereAmI.swift`). So today a conflicted revert reports no
operation in progress.

### Schema compatibility

The guide states no rule for adding a field to a `schemaVersion: 1` payload (*measured*: grep of
`docs/switchyard-development-guide.md` for "additive" and "new field" finds only unrelated entries).
A new boolean is additive for readers that ignore unknown keys, and Brennan approved "engine +
schema" on 2026-09-12. `schemaVersion` stays 1; say so in the work log.
