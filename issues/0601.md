## Description

Brennan, 2026-10-06, answering #0580's question 3: *"I will often create the first commit with a
good commit message for the current issue. Then make "wip" commits which just have "wip" as the
commit message. When I run fixup I combine each commit until I get to the one with the good
message."*

Today that is N repetitions of Fixup with Parent (⌥⌘F) from the tip down, and N Undo steps to take
it back. He wants **one action**: select the commit with the good message and fold every commit
above it into it.

## The design (guide §11 decision 48)

- **Commit ▸ Fixup Newer Commits into This** (⌃⌥⌘F, also in the History row's context menu),
  placed directly under Fixup with Parent.
- **Result:** the selected commit rebuilt with **the tip's tree**, its **own parents**, its
  **message byte for byte** and its **author and author date**; the committer is the current
  identity. Every newer commit's message is dropped. The ref `HEAD` names (branch, or `HEAD` when
  detached) moves once. That is exactly what N repeated Fixup-with-Parent folds from the tip down
  produce (each keeps the parent's message and author), in one step.
- **Engine:** `Rewrite.fixupNewer(into:)` — one `git commit-tree <tip>^{tree}` with the selected
  commit's parents, using the existing `copyCommit`/`StoredCommit` from
  `YardKit/Sources/YardGit/RewriteFixup.swift`, then `moveRef` — inside
  `JournalCheckpoint.around(operation: "fixup-newer")`. One journal entry; **Edit ▸ Undo Fixup
  Newer Commits**. The index and the working tree are never read or written.
- **Enabled** on any commit of `HEAD`'s first-parent chain **except** the tip ("No newer commits on
  “main” to fold in") and any commit with a merge above it ("A merge commit above this one can’t be
  folded in" — folding the merge would drop its other parents). The selected commit **may be the
  root** (the result is a new root) or **a merge** (the result keeps all its parents). Staged
  changes do not disable it. Busy and operation-in-progress guards as for every action.
- **Not added:** a CLI verb (question 1 below).

## Questions for Brennan (assumptions in force meanwhile)

1. **A CLI verb?** None is added. If wanted: `switchyard fixup --into <commit>` (or a separate
   `fixup-newer <commit>`) calling `Rewrite.fixupNewer(into:)`, `--json` returning `{"head":
   "<oid>"}` like `reword`. It would naturally land with #0580 question 1 (`switchyard fixup
   <commit>` for Fixup with Parent), so the two verbs are designed together. **Assumed:** no verb.
2. **The name.** "Fixup Newer Commits into This" says what moves where and does not depend on the
   History list's newest-on-top orientation (the branch map can be drawn either way). Alternatives
   considered: "Fixup Commits Above into This", "Fixup Children". **Assumed:** the title above, Undo
   title "Undo Fixup Newer Commits".
3. **The shortcut.** ⌃⌥⌘F, next to ⌥⌘F (Fixup with Parent) and ⇧⌥⌘F (Squash with Parent). It is in
   no reserved set (`allocatedShortcutsAreDistinctAndAvoidTheReservedSet`). **Assumed:** ⌃⌥⌘F.

## Expected behavior

- Selecting the good-message commit and choosing Commit ▸ Fixup Newer Commits into This folds every
  newer commit into it in one step — its message and author kept, the tip's tree, one Edit ▸ Undo —
  proven by #0602's engine tests and #0603's VM spike reading git.
