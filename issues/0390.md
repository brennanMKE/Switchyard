## Description

**Blocks #0362**

The set-tip leg of #0362's engine half, split out on 2026-09-12 (M8). It uses **`git reset --keep`
semantics** — option 2 of #0362's uncommitted-changes question, the recommendation filed for
Brennan. The tip moves, and the index and working tree follow it. Uncommitted edits to files that
are identical in both tips are kept. If anything would be overwritten, it refuses and touches
nothing.

This replaces #0362's original engine bullet ("moves the branch ref transactionally
(`update-ref --stdin`)"). Moving the ref alone is option 3, which would leave the removed commits'
content behind as uncommitted changes.

**No CLI verb here.** Guide §6 names no `set-tip` command, so the verb is left for a later issue.

### Measured behaviour of `git reset --keep`

git 2.50.1, 2026-09-12, scratch repositories.

| Situation | git's behaviour | This wrapper |
|---|---|---|
| an uncommitted edit to a file that differs between the tips | exit 128 `error: Entry 'f' not uptodate. Cannot merge.` / `fatal: Could not reset index file to revision 'HEAD~1'.` — `HEAD` did not move | `.localChangesWouldBeOverwritten(paths: ["f"])` |
| an untracked file the target tracks | exit 128 `error: Untracked working tree file 'newfile2' would be overwritten by merge.` / `fatal: Could not reset index file to revision 'tr'.` | `.localChangesWouldBeOverwritten(paths: ["newfile2"])` |
| an unrelated edit, plus an untracked file | exit 0; the tip moved; the edit and the untracked file were kept | success |
| a staged change whose content equals the target's | exit 0; `HEAD` at the target, the file matches, nothing left staged | success |
| target equals the tip (`reset --keep HEAD`) | exit 0, no-op | `.nothingToDo`, before mutation |
| unknown revision | exit 128 `fatal: ambiguous argument 'nosuch': unknown revision or path not in the working tree.` | `.unknownRevision(_:)`, before mutation (`rev-parse --verify <rev>^{commit}`) |
| detached `HEAD` | **exit 0** — git moves the detached `HEAD` | `.detachedHead`, before mutation |
| target on no local branch | `git for-each-ref --contains <oid> --format=%(refname) refs/heads` prints nothing (exit 0) for a dangling commit and `refs/heads/main` for `main~1` | `.targetNotOnBranch(target:)`, before mutation |

Not measured: an unmerged index. Refuse it before mutation with `.blockedOnConflicts(files:)` via
`conflictedFiles(at:git:)`, mirroring `Rewrite.refuseUnmergedIndex`.

### Surface — `YardKit/Sources/YardGit/SetBranchTip.swift` (new, *not compiled*)

The name is `SetBranchTip`, not `BranchTip`, because #0366 plans a `YardUI.BranchTip` and `YardUI`
imports `YardGit`.

```swift
public enum SetBranchTip {
    public struct Result: Sendable, Equatable, Encodable {
        public let head: String
        public let previousTip: String
    }

    public static func run(
        target: String,
        at path: String,
        git: GitProcess = GitProcess(),
        extraEnvironment: [String: String] = [:]
    ) throws -> Result
}

public enum SetBranchTipError: Error, Equatable, Sendable, CustomStringConvertible {
    case unknownRevision(String)
    case detachedHead
    case nothingToDo
    case targetNotOnBranch(target: String)
    case localChangesWouldBeOverwritten(paths: [String])
    case blockedOnConflicts(files: [ConflictedFile])
}
```

`.blockedOnConflicts` maps to exit class `.blockedOnConflicts`; everything else to `.repositoryError`.
No commit is created, so there is no signing.

### Sequence

1. **Refusals before mutation**, in this order: resolve; detached (`symbolic-ref -q HEAD`); unmerged
   index; no-op; not on a local branch.
2. **Inside** `JournalCheckpoint.around(operation: "set-tip", at: path, git: git) { scoped in … }`,
   run `git reset --keep <oid>` through `scoped.capture`.
3. **On non-zero**, parse the measured `error: Entry '<path>' not uptodate. Cannot merge.` and
   `error: Untracked working tree file '<path>' would be overwritten by merge.` lines into
   `.localChangesWouldBeOverwritten(paths:)`. Any other failure → `GitProcess.Failure`.

**git's own refusal comes after the checkpoint is written**, because it cannot be predicted without
running the reset. `JournalCheckpoint.around` documents that the pre-operation entry is kept when the
body throws, so a refused set-tip leaves one entry describing an unchanged state. The refusal itself
changes nothing — `HEAD` was measured unmoved.
