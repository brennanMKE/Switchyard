## Description

`envelopeFailWriteEmitsOnlyJsonToStdout()` in
`YardKit/Tests/YardKitTests/JsonEnvelopeTests.swift` captures stdout through a `Pipe`, then calls
`close(pipeWriteFd)` on a descriptor that `pipe.fileHandleForWriting` still owns. When that
`FileHandle` deinitialises it closes the same descriptor a second time.

Harmless today, because nothing else in the process is allocating descriptors between the two closes.
It is a real hazard in a longer-running test process: a second close can land on an unrelated
descriptor that the runtime reallocated in between, and the resulting failure appears somewhere with
no connection to this test.

Found during review of #0091 and deliberately left for a follow-up rather than spending another round
on an accepted result.

## Expected behavior

- [ ] The capture helper in `YardKit/Tests/YardKitTests/JsonEnvelopeTests.swift` closes the write end
      exactly once. Either take ownership away from the `FileHandle`
      (`pipe.fileHandleForWriting.closeFile()` and no raw `close`), or duplicate the descriptor and
      close the duplicate — one owner, one close.
- [ ] The restored `stdout` descriptor is also closed exactly once.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line
      you paste. **N must be greater than or equal to 124**, the count on `main` — this is a
      correctness fix to an existing test, so the count need not rise, but it must not fall.
- [ ] The test still fails if the `[error]` line is written to stdout again. Say how you confirmed
      that, rather than asserting it.

## Notes

Do not restructure the test or change what it asserts — the assertion is correct and was
mutation-checked when #0091 landed. This is about descriptor ownership only.

Round 1: exit 0, 1044s, accepted. The model took the issue's *second* permitted route — dup the
descriptor and close the dup — rather than the one the dispatch brief suggested. Both were allowed by
the Expected behavior, and it said which it chose and why.

Verified by mutation: flipping `EnvelopeFail.write()` back to stdout makes the test fail with
`first byte should be '{', got '[error] broker_unreachable: Th'`. Five repeat runs showed no
intermittency — weak evidence on its own, since a descriptor bug is intermittent by nature, but a
single failure would have been decisive.

Reading the file rather than trusting the original one-line report found **three** ownership problems
where the review had named one: the raw `close()` on a borrowed write fd, a second `FileHandle` over
the read end, and `savedStdout`, which turned out to be correct and was left alone.
