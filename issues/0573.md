## Description

`ContentView.refreshAfterMutation` backs every in-place refresh: after each commit, stage, stash,
switch, remote operation and undo, and whenever the window becomes active (#0447). On failure it
does this:

```swift
        } catch {
            errorMessage = String(describing: error)
            summary = nil
        }
```

With `summary == nil`, `body` shows the "Couldn't open <path>" screen, whose only button is
**Choose Folder…**. Nothing ever loads the repository again:

- `.task(id: repositoryPath)` does not re-run, because the path has not changed.
- The activation refresh requires `summary != nil`:

  ```swift
              if isActive, summary != nil, !isBusy, !journalRunning {
                  Task { await refreshAfterMutation { _, _ in nil } }
              }
  ```

So one transient failure kills the tab for good. Examples: the repository folder is moved or
renamed in Finder while the app is in the background, an external drive is slow to remount, or
one `git` read fails. The same happens when the repository comes straight back.

### Measured (VM, 2026-09-30, throwaway hardening spike on the main fixture)

1. The spike opened `/Users/admin/uitest-fixture-repo` and moved it to `…-moved` with
   `FileManager.moveItem`. It then activated Finder and re-activated the app.
2. The window showed `Couldn't open /Users/admin/uitest-fixture-repo`, with the detail
   `not a git repository: … (fatal: cannot change to '/Users/admin/uitest-fixture-repo': No such
   file or directory)`.
3. The spike moved the folder back and did two more deactivate/activate cycles, 3 s apart.
4. **Still `Couldn't open`**, and no History row exists. Screenshot:
   `issues/0569/0573-window-dead-after-repo-returns.png`.

## The change — one file, `YardKit/Sources/YardUI/ContentView.swift`

In the `.onChange(of: appearsActive, initial: true)` handler, replace the block quoted above with:

```swift
            if isActive, summary != nil, !isBusy, !journalRunning {
                Task { await refreshAfterMutation { _, _ in nil } }
            } else if isActive, summary == nil, errorMessage != nil, repositoryPath != nil {
                // #0573: a window whose refresh failed (the repository was
                // moved, or git failed once) tries again when it comes back.
                Task { await reload() }
            }
```

`reload()` is the open-a-repository path. It clears the error, shows the Loading spinner, and
either brings the repository back or shows `Couldn't open` again. A window whose first open
failed also retries on activation, which is what a person expects after fixing the folder.

## Verification

### VM spike — `SwitchyardUITests/0573RecoverWindowUITests.swift`, new

```swift
// 0573RecoverWindowUITests.swift
//
// #0573: a window whose refresh failed — its repository moved away while
// the app was in the background — shows the repository again once the
// folder is back and the app is activated.

import XCTest

final class Spike0573RecoverWindowUITests: XCTestCase {
    /// Sends the app to the background and back: #0447's refresh trigger.
    @MainActor
    private func deactivateAndReturn(_ app: XCUIApplication) {
        XCUIApplication(bundleIdentifier: "com.apple.finder").activate()
        usleep(1_500_000)
        app.activate()
    }

    @MainActor
    func testTheWindowRecoversWhenTheRepositoryComesBack() throws {
        let app = XCUIApplication()
        app.launchWithFixtureRepository()
        let header = app.header(beginningWith: "On branch \(UITestFixture.branch)")
        XCTAssertTrue(header.waitForExistence(timeout: 30), "the fixture did not open")

        let repo = UITestFixture.repositoryPath
        let moved = repo + "-moved"
        try FileManager.default.moveItem(atPath: repo, toPath: moved)
        deactivateAndReturn(app)
        XCTAssertTrue(app.text(containing: "Couldn't open").waitForExistence(timeout: 30),
                      "the refresh did not notice the repository was gone")

        try FileManager.default.moveItem(atPath: moved, toPath: repo)
        deactivateAndReturn(app)
        XCTAssertTrue(header.waitForExistence(timeout: 30),
                      "the window stayed on Couldn't open after the repository came back")
        let shot = XCTAttachment(screenshot: app.windows.firstMatch.screenshot())
        shot.name = "0573-recovered"
        shot.lifetime = .keepAlways
        add(shot)
    }
}
```

`scripts/run-ui-tests-vm.sh`: add `run_spike_if_selected 0573 Spike0573RecoverWindowUITests` after

## Mutation the review runs

Delete the `else if … { Task { await reload() } }` branch. The spike fails at its last
assertion.

## Expected behavior

A window showing `Couldn't open` for a repository that is reachable again shows it the next time
the app is activated. It never gets stuck on Choose Folder… for a path that is fine.
