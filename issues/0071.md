## Description

Open question in guide §11, and it needs answering **before the identifiers in §3 are baked in**.
Renaming after `ServiceNames.swift`, the Mach service name, the launchd plist, and the install path
are all in place is a much larger change than it looks.

`yard` as a binary name in `/usr/local/bin` is the sharpest risk — it is short and generic, and a
collision means a user's existing tool gets shadowed by ours or vice versa.

## Notes

**Research complete 2026-08-06; the decision is Brennan's.** Findings in `docs/name-availability.md`.

**`yard` collides with the Ruby YARD documentation tool**, which declares
`s.executables = ['yard', 'yardoc', 'yri']`, has 230,081,312 RubyGems downloads, and whose default
gem executable directory on this machine is `/usr/local/bin` — the exact path guide §3 specifies for
our CLI. It is free on this machine today, which is how the collision stays invisible until a user
hits it.

`Switchyard` as a product name is crowded (npm and crates.io taken, several GitHub projects, the
retired JBoss SwitchYard ESB) but nothing is a Mac git client and the Homebrew formula name is free.

Recommendation: rename the binary now. `ServiceNames.cliName` and `cliInstallPath` are one constant
each today; after #0026 publishes the JSON schemas and #0066 generates the skill, the same rename
touches agent-facing contracts.

Left open pending Brennan: the new binary name, plus domain and App Store checks (the latter needs
App Store Connect access and only matters if #0073 chooses App Store distribution).

## Decision — 2026-08-06

**Brennan chose `switchyard` as the binary name.** Not a short alias: the full product name, typed in
full on every invocation. It collides with nothing, needs no explanation, and an alias can be added
later if the length becomes annoying — whereas an alias added later is cheap and a rename added later
is not.

Recorded as settled decision 4 in guide §11. The rename itself is #0102.

`YardKit` and `YardGit` keep their names. They are module names, not commands, and the collision that
forced this decision was specifically about `/usr/local/bin`.
