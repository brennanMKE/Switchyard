## Description

The final assembly: a registry holding every `CommandSpec`, and `main.swift` using it so
`yard --help` and `yard schema` actually work.

## Givens — verified on `main`, treat as true

1. **`main.swift` is no longer the shape this issue originally assumed.** #0092 reduced it to
   argument collection, one call to `runYard`, a write, and an exit. All logic lives in
   `YardKit/Sources/YardKit/CommandLineRunner.swift`:

   ```swift
   public func runYard(arguments: [String]) -> (stdout: String, stderr: String, exitCode: ExitCode)
   ```

   **Three elements, not two.** An earlier draft of this issue said two; `stderr` was added when the
   human-readable error line landed. Destructure all three or you will not compile.

   **Extend `runYard`, not `main.swift`.** Nothing in `main.swift` can be unit-tested, because
   SwiftPM cannot `@testable import` an executable target.

2. `runYard` today handles exactly three cases. Verified by running the built binary on
   2026-08-07 — this is the real output, not a paraphrase:

   | invocation | exit | stdout |
   |---|---|---|
   | `switchyard` | 0 | `{"ok":true,"result":"switchyard 0.0.1","schemaVersion":1}` |
   | `switchyard noop` | 0 | success envelope with an empty result |
   | `switchyard bogus` | 1 | `{"error":{"code":"usage","message":"Unknown subcommand 'bogus'."},"ok":false,"schemaVersion":1}` |

   **`switchyard --help` and `switchyard schema` currently exit 1 with `Unknown subcommand`.** That is
   the defect this issue closes; confirm it yourself before you start so you can tell your change
   apart from the status quo.

2b. **The exact signatures you are assembling** — read them, do not assume:

   ```swift
   public nonisolated func renderHelp(for spec: CommandSpec) -> String            // ONE spec
   public nonisolated func renderSchema(for spec: CommandSpec) throws -> String   // ONE spec, THROWS
   ```

   `renderSchema` **throws**, and `runYard` does not. The `schema` path needs a `do`/`catch` that
   returns a failure envelope rather than propagating.

2c. `CommandSpec` is `(name, summary, flags, exitCodes, schemaName)`; `FlagSpec` is
   `(long, short: Character?, argument: String?, help)`; `ExitCodeSpec` is `(code: Int32, meaning)`.
   `ExitCode` has ten cases from `.success = 0` through `.signingFailed = 9`.

3. These exist on `main` and are what this issue assembles — do not reimplement either:
   - `YardKit/Sources/YardKit/CommandSpec.swift` (#0085) — the metadata type.
   - `YardKit/Sources/YardKit/HelpRenderer.swift` (#0086) — `renderHelp(for:) -> String`.
   - `SchemaEmitter.swift` (#0087) — `renderSchema(for:) -> String`. **If #0087 has not merged when
     you start, stop and say so** rather than writing your own emitter.

4. `Atomic` is **not available** in this toolchain. A previous round crashed on it. `static let` on
   an enum is the whole mechanism needed here.

## Output shape — settled by #0101

`--help` and `--version` print **plain text**. Every other command emits a JSON envelope
unconditionally. That is guide §11 settled decision 6; do not reopen it.

- `switchyard --help` writes the rendered help text to stdout as-is — no envelope, no JSON wrapper.
- `switchyard schema` **is** an agent-facing command, so it emits its JSON inside an envelope like
  everything else.
- **Do not add `--json` flag parsing.** No command needs it: JSON is unconditional for everything
  except the two human commands.
- For every path other than `--help`/`--version`, stdout stays JSON and nothing else.

## How `schema` gets its JSON into the envelope — settled here, do not redesign

`renderSchema(for:)` returns **pretty-printed JSON text**, and `Envelope`'s `result` is `Encodable`.
Handing the text to `EncodableResult` would encode it as a *JSON string containing escaped JSON*,
which is useless to an agent. Do not do that.

**Assemble the `schema` response as text.** `runYard` returns a `String` already, so build:

```
{"schemaVersion":1,"ok":true,"result":{"commands":[<renderSchema output>,<renderSchema output>,…]}}
```

by joining the already-valid `renderSchema` outputs with `,`. Each piece is a complete JSON document,
so the concatenation is valid JSON by construction. Do not add a second serializer and do not change
`renderSchema` — its byte-stable sorted-key output is #0087's contract with `docs/contracts/`.

**Because this is string assembly, it must be proven by parsing, not by eyeballing.** A test must run
the `schema` path, feed the stdout to `JSONSerialization.jsonObject(with:)`, and assert on the parsed
structure — `result.commands` is an array whose count equals `CommandRegistry.all.count`, and each
element has a non-empty `command` key. A test that compares strings would pass on malformed JSON.

## What the registry holds

Two specs, both real:

- **`switchyard`** — the top-level command. Its flags are `--help` and `--version`; its exit codes are
  at least `0` and `1`. `switchyard --help` renders **this** spec through `renderHelp(for:)`.
- **`noop`** — the command `runYard` already handles.

`renderHelp(for:)` takes a single spec, so per-subcommand help (`switchyard noop --help`) is **out of
scope**. Do not add it, and do not write a second renderer that walks the registry.

## Out of scope — do not touch

- `jsonString` in `CommandLineRunner.swift` uses `try!` and `!`. It is pre-existing and tracked as
  **#0114**. Leave it exactly as it is; changing it here makes the diff unreviewable.
- `main.swift`, `HelpRenderer.swift`, `SchemaEmitter.swift`, `Envelope.swift`, `ExitCode.swift`.
  `git diff --stat` should show **`CommandRegistry.swift` (new)**, `CommandLineRunner.swift`, and one
  test file. Nothing else.

## Expected behavior

- [ ] New file `YardKit/Sources/YardKit/CommandRegistry.swift` with `enum CommandRegistry { static let all: [CommandSpec] }` — a `let`, not a mutable store. **No `Atomic`, no global mutable state.**
- [ ] Registry contains the two specs described above.
- [ ] `runYard` gains `--help`, `--version`, and `schema` handling. `main.swift` is not modified at all.
- [ ] `--help` and `--version` print **plain text** — first byte is not `{`. Everything else is JSON.
- [ ] Arguments stay guarded before any subscript — no `args.first!`. The existing guard in
      `runYard` already does this; do not remove it.
- [ ] A test asserts every spec in the registry has a non-empty `name`, a non-empty `schemaName`, and at least one documented exit code.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] New tests go in **`YardKit/Tests/YardKitTests/`**. `Tests/YardKit/` is not a declared target
      path; a file there is silently never compiled, the suite stays green, and the count does not
      move. That cost #0095 a round.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests`
      line you paste. **`main` reported 225 on 2026-08-07** (216 was stale — #0095, #0110 and #0112 have merged since). Run `swift test` on the branch before
      your change for its own baseline, paste that number too, and N must exceed it.
- [ ] `swift run switchyard --help` prints the rendered help as plain text, exit 0. Paste the real

- [ ] `swift run switchyard schema` emits the JSON schemas inside an envelope. Paste the real output

- [ ] Every path other than `--help`/`--version` still puts valid JSON on stdout and nothing else —

## Tests must be able to fail

- Assert any extraction is non-empty before comparing it. A helper that silently returns nothing
  turns the next assertion into `[] == []`, which passes unconditionally — that cost #0087 a round.
- No `#expect(true)` or any assertion whose operands are literals.
- **A `guard case … else { continue }` inside a loop over the registry is not a test.** It silently
  skips every element that does not match and the loop then asserts nothing. Iterate and assert on
  each element unconditionally.
