## Description

The final assembly: a registry holding every `CommandSpec`, and `main.swift` using it so
`yard --help` and `yard schema` actually work.

## Givens — verified on `main`, treat as true

1. **`main.swift` is no longer the shape this issue originally assumed.** #0092 reduced it to
   argument collection, one call to `runYard`, a write, and an exit. All logic lives in
   `YardKit/Sources/YardKit/CommandLineRunner.swift`:

   ```swift
   public func runYard(arguments: [String]) -> (stdout: String, exitCode: ExitCode)
   ```

   **Extend `runYard`, not `main.swift`.** Nothing in `main.swift` can be unit-tested, because
   SwiftPM cannot `@testable import` an executable target.

2. `runYard` today handles exactly three cases, all verified by running the binary:

   | invocation | exit | stdout |
   |---|---|---|
   | `yard` | 0 | success envelope carrying the version string |
   | `yard bogus-command` | 1 | failure envelope, `error.code` = `usage` |
   | `yard noop` | 0 | success envelope |

3. These exist on `main` and are what this issue assembles — do not reimplement either:
   - `YardKit/Sources/YardKit/CommandSpec.swift` (#0085) — the metadata type.
   - `YardKit/Sources/YardKit/HelpRenderer.swift` (#0086) — `renderHelp(for:) -> String`.
   - `SchemaEmitter.swift` (#0087) — `renderSchema(for:) -> String`. **If #0087 has not merged when
     you start, stop and say so** rather than writing your own emitter.

4. `Atomic` is **not available** in this toolchain. A previous round crashed on it. `static let` on
   an enum is the whole mechanism needed here.

## Output shape — settled by #0101

`--help` and `--version` print **plain text**. Every other command emits a JSON envelope
unconditionally. That is guide §11 settled decision 6; do not reopen it.

- `switchyard --help` writes the rendered help text to stdout as-is — no envelope, no JSON wrapper.
- `switchyard schema` **is** an agent-facing command, so it emits its JSON inside an envelope like
  everything else.
- **Do not add `--json` flag parsing.** No command needs it: JSON is unconditional for everything
  except the two human commands.
- For every path other than `--help`/`--version`, stdout stays JSON and nothing else.

## Expected behavior

- [ ] New file `YardKit/Sources/YardKit/CommandRegistry.swift` with `enum CommandRegistry { static let all: [CommandSpec] }` — a `let`, not a mutable store. **No `Atomic`, no global mutable state.**
- [ ] Registry contains at least one real spec: `yard --help` itself.
- [ ] `runYard` gains `--help` and `schema` handling. `main.swift` is not modified at all.
- [ ] Arguments stay guarded before any subscript — no `args.first!`. The existing guard in
      `runYard` already does this; do not remove it.
- [ ] A test asserts every spec in the registry has a non-empty `name`, a non-empty `schemaName`, and at least one documented exit code.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests`
      line you paste. **N must be greater than the count on `main` immediately before this
      change** — state both numbers so the increase is visible rather than asserted.
- [ ] `swift run switchyard --help` prints the rendered help as plain text, exit 0. Paste the real
      output and exit code, obtained by running it.
- [ ] `swift run switchyard schema` emits the JSON schemas inside an envelope. Paste the real output
      and exit code.
- [ ] Every path other than `--help`/`--version` still puts valid JSON on stdout and nothing else —
      first byte `{`, last `}`.

## Notes

Split out of #0010, whose round crashed on `Atomic` (not available here) and force-unwrapped
`args.first!` before checking for empty arguments. Both mistakes are called out above so they are not
repeated.

Blocked by #0085 and #0086 (both merged) and #0087 (in flight).

#0101 is settled — see the output-shape section above. Blocked by #0102, the binary rename, so the
command name in your test assertions is `switchyard`.

**Target placement:** `yard` is an `executableTarget`, so `@testable import yard` does **not** link in
SwiftPM — anything that needs unit tests must live in the `YardKit` library target. This was found
the hard way on #0085, whose round burned itself discovering the link error. Only `main.swift` and
code that genuinely cannot be unit-tested belong in `Sources/yard/`.

## Tests must be able to fail

- Assert any extraction is non-empty before comparing it. A helper that silently returns nothing
  turns the next assertion into `[] == []`, which passes unconditionally — that cost #0087 a round.
- No `#expect(true)` or any assertion whose operands are literals.
- The registry test must fail if a spec is added with an empty `name`, an empty `schemaName`, or no
  exit codes. Say how you confirmed that rather than asserting it.
