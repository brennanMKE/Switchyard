## Description

**Blocks #0361**

The engine half of #0361, split out on 2026-09-12 (M8). #0361 is now UI-only. Following the
recommendation Brennan received: **unrelated histories are refused unless an explicit flag allows
them, and a detached `HEAD` is refused** — git does neither by itself (measured below).

**No CLI verb here.** Guide §6 names no `merge` command, so `switchyard merge` is left for a later
issue.

### Measured refusals and outcomes

git 2.50.1, 2026-09-12, scratch repositories with `GIT_EDITOR=false` and no global config.

| Situation | git's behaviour | This wrapper |
|---|---|---|
| already up to date (`merge --no-ff --no-edit main~1`) | **exit 0** `Already up to date.` — no commit, no error | `.alreadyUpToDate(source:)`, before mutation: `merge-base --is-ancestor <source> HEAD` exits 0 |
| detached `HEAD` | **exit 0** — a two-parent merge commit is made on the detached `HEAD` | `.detachedHead`, before mutation: `symbolic-ref -q HEAD` exits non-zero |
| unrelated histories | exit 128 `fatal: refusing to merge unrelated histories`; `git merge-base main other` exits 1 with no output | `.unrelatedHistories(source:)`, before mutation, **unless** `allowUnrelatedHistories: true`, which passes `--allow-unrelated-histories` (measured: exit 0, merge made) |
| `--ff-only` on diverged history | exit 128 `hint: Diverging branches can't be fast-forwarded, …` | `.fastForwardNotPossible(source:)`, before mutation: `merge-base --is-ancestor HEAD <source>` exits non-zero |
| unmerged index | exit 128 `error: Merging is not possible because you have unmerged files.` | `.blockedOnConflicts(files:)`, before mutation (`conflictedFiles(at:git:)`) |
| content conflict | exit 1, `MERGE_HEAD` present, `UU f` | `.blockedOnConflicts(files:)`, state left for #0057's resolve pane (#0394) |
| an untracked file the merge would overwrite | exit 2 `error: The following untracked working tree files would be overwritten by merge:` — `HEAD` unchanged, no `MERGE_HEAD`, file untouched | git's own refusal: rethrow `GitProcess.Failure` unchanged |

Also *measured*: `git merge -h` lists `--ff-only`, `--[no-]allow-unrelated-histories` and
`-S, --[no-]gpg-sign`.

### Surface — `YardKit/Sources/YardGit/Merge.swift` (new, *not compiled*)

```swift
public struct Merge: Equatable, Sendable {
    public enum Intent: Equatable, Sendable {
        /// `--no-ff`: always a merge commit, with this message (`-m`, never an editor).
        case mergeCommit(message: String)
        /// `--ff-only`: move the branch forward, or refuse.
        case fastForwardOnly
    }

    public enum Outcome: String, Sendable, Equatable, Encodable {
        case mergeCommit, fastForward
    }

    public struct Result: Sendable, Equatable, Encodable {
        public let head: String
        public let outcome: Outcome
    }

    public static func run(
        source: String,
        intent: Intent,
        allowUnrelatedHistories: Bool = false,
        signing: CommitCreate.Signing = .config,
        at path: String,
        git: GitProcess = GitProcess(),
        extraEnvironment: [String: String] = [:]
    ) throws -> Result
}

public enum MergeError: Error, Equatable, Sendable, CustomStringConvertible {
    case unknownRevision(String)
    case detachedHead
    case emptyMessage
    case alreadyUpToDate(source: String)
    case unrelatedHistories(source: String)
    case fastForwardNotPossible(source: String)
    case blockedOnConflicts(files: [ConflictedFile])
    case signingFailed(reason: String)
}
```

`MergeError: ExitClassCarrying` follows `RewriteError`'s mapping.

### Sequence

1. **Resolve**: `rev-parse --verify <source>^{commit}` → `.unknownRevision`.
2. **Refuse a detached `HEAD`**, then an unmerged index, then an empty `.mergeCommit` message (after
   trimming).
3. **Up to date?** `merge-base --is-ancestor <source> HEAD` → `.alreadyUpToDate`.
4. **Related?** `git.capture(["merge-base", "HEAD", sourceOid], …)` exit 1 → `.unrelatedHistories`,
   unless allowed.
5. **`.fastForwardOnly`**: `merge-base --is-ancestor HEAD <source>` non-zero → `.fastForwardNotPossible`.
6. **Inside** `JournalCheckpoint.around(operation: "merge", at: path, git: git) { scoped in … }`, run:
   - `git merge --no-ff -m <message> <CommitCreate.arguments(for: signing)> [--allow-unrelated-histories] <oid>`, or
   - `git merge --ff-only <oid>`.

   Use the signing timeout exactly as `Rewrite.perform` does.
7. **Classify a failure**:
   - conflicts → `.blockedOnConflicts`, `MERGE_HEAD` left;
   - a signing failure → `git merge --abort`, then `.signingFailed` (*the abort after a signing failure
     is not measured* — the test covers it);
   - anything else → rethrow.

The merge message is the caller's. The app pre-fills git's own default wording, measured in #0361:
`Merge branch 'feature'`, `Merge remote-tracking branch 'origin/feature'`, `Merge commit '<oid>'`.

## Expected behavior

- [ ] `Merge.run` makes a merge commit (`.mergeCommit`) or fast-forwards (`.fastForwardOnly`) inside one
      journal checkpoint, and `JournalUndo.undo` restores the pre-state — including dropping the merge
      commit (fixture test).
- [ ] Every typed refusal in the table is raised before mutation, and unrelated histories merge only
      with `allowUnrelatedHistories: true`.
- [ ] A conflict throws `.blockedOnConflicts` with `MERGE_HEAD` left. Tests live in
      `YardKit/Tests/YardGitTests/MergeTests.swift`, and `swift test` prints `Test run with N tests`.
