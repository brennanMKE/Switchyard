## Description

`gitStatus(at:includeIgnored:git:)` is `public` and returns a `public struct WorktreeStatus`, whose
`entries` property is **internal**. So an out-of-module caller can obtain the value and can do
nothing with it.

Proved, not inferred. A throwaway SwiftPM package depending on the `YardGit` product:

```swift
import YardGit
let status = try gitStatus(at: ".")
for e in status.entries { print(e.path, e.staged, e.worktree) }
```

```
error: 'entries' is inaccessible due to 'internal' protection level
```

`WorktreeStatusEntry.path`, `.staged`, `.worktree` and the `State` enum are internal for the same
reason — declared with a bare `var`/`enum` inside a `public struct`, which does not inherit the
struct's access level.

**The tests cannot catch this.** `YardGitTests` uses `@testable import YardGit`, which grants
internal access, so the existing tests compile and pass against an API no real caller can use. That
is the whole failure: the test suite and the caller see different modules.

## Givens — verified on `main` 2026-08-07, treat as true

1. The file is `YardKit/Sources/YardGit/WorktreeStatus.swift`. The internal members are:
   - `WorktreeStatus.entries` (line 65) and its `init(entries:)` (line 67)
   - `WorktreeStatusEntry.path`, `.staged`, `.worktree` (lines 12, 15, 18)
   - `WorktreeStatusEntry.State` (line 21) and all three of its initialisers
2. **Every other public entry point in `YardGit` is fine.** The same probe compiled clean for
   `whereAmI`, `worktreeList`, `worktreeRemove` and `yardWhere` — each one's result type exposes its
   fields. This is one type, not a systemic problem, so do not widen the diff.
3. `WorktreeStatus` conforms to `ExpressibleByArrayLiteral` with a `public init(arrayLiteral:)`,
   which is the only currently-public way to construct one — an odd asymmetry worth removing by
   making the real initialiser public too.

### Assertions that cannot fail

`check-tests-assert.sh` passed, and these were still there — found by reading:

```swift
#expect(info.branch != nil || info.branch == nil)   // :205
#expect(info.headOID.count >= 0)                    // :206
#expect(info.rawHead.count >= 0)                    // :214
#expect(status.entries.count >= 0)                  // :187
#expect(entry.head != nil || true)                  // :230
for c in State.allCases { _ = c }                   // asserts nothing
```

A `Count` is never negative and `x != nil || x == nil` is a tautology. **The `whereAmI` test asserts
nothing falsifiable at all.** Assert something a wrong implementation would get wrong — `headOID.count
== 40`, `branch == "main"` on a fixture whose branch you created, `entries.count == 1` for a repo with
one modified file. The checker now flags these shapes as `ALWAYSTRUE`.

Also: `makeTempRepo()` runs `git init` in `parent` and returns `parent/repo`, a directory that is never
created.
