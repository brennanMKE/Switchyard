# 0116 — gitStatus returns a value no caller outside YardGit can read

| | |

## Description

`gitStatus(at:includeIgnored:git:)` is `public` and returns a `public struct WorktreeStatus`, whose
`entries` property is **internal**. So an out-of-module caller can obtain the value and can do
nothing with it.

Proved, not inferred. A throwaway SwiftPM package depending on the `YardGit` product:

```swift
import YardGit
let status = try gitStatus(at: ".")
for e in status.entries { print(e.path, e.staged, e.worktree) }
```

```
error: 'entries' is inaccessible due to 'internal' protection level
```

`WorktreeStatusEntry.path`, `.staged`, `.worktree` and the `State` enum are internal for the same
reason — declared with a bare `var`/`enum` inside a `public struct`, which does not inherit the
struct's access level.

**The tests cannot catch this.** `YardGitTests` uses `@testable import YardGit`, which grants
internal access, so the existing tests compile and pass against an API no real caller can use. That
is the whole failure: the test suite and the caller see different modules.

## Givens — verified on `main` 2026-08-07, treat as true

1. The file is `YardKit/Sources/YardGit/WorktreeStatus.swift`. The internal members are:
   - `WorktreeStatus.entries` (line 65) and its `init(entries:)` (line 67)
   - `WorktreeStatusEntry.path`, `.staged`, `.worktree` (lines 12, 15, 18)
   - `WorktreeStatusEntry.State` (line 21) and all three of its initialisers
2. **Every other public entry point in `YardGit` is fine.** The same probe compiled clean for
   `whereAmI`, `worktreeList`, `worktreeRemove` and `yardWhere` — each one's result type exposes its
   fields. This is one type, not a systemic problem, so do not widen the diff.
3. `WorktreeStatus` conforms to `ExpressibleByArrayLiteral` with a `public init(arrayLiteral:)`,
   which is the only currently-public way to construct one — an odd asymmetry worth removing by
   making the real initialiser public too.

## Expected behavior

- [ ] `WorktreeStatus.entries`, its initialiser, `WorktreeStatusEntry`'s three stored properties, and
      `WorktreeStatusEntry.State` (with its cases) are `public`. `WorktreeStatusEntry` needs a
      `public init` — a public struct's memberwise initialiser is internal.
- [ ] No behaviour changes: every existing test still passes unmodified. (The overall count DOES
      rise, because of the new target below — it is the *existing* tests that must not change.)
- [ ] The diff touches only `WorktreeStatus.swift` plus the new test target below.

## The check that makes this class visible — build it as part of this issue

A test target that imports **without** `@testable` is the only thing that sees what a caller sees.

- [ ] Add a `YardGitPublicAPITests` target to `Package.swift` at `Tests/YardGitPublicAPITests`,
      depending on `YardGit`, containing `import YardGit` — **never `@testable import`**.
- [ ] It exercises each public entry point through its public surface only: read `status.entries` and
      an entry's `path`/`staged`/`worktree`, read fields off `whereAmI`, `worktreeList`,
      `worktreeRemove` and `yardWhere`. Compilation is most of the value; add one real assertion per
      call so the tests are not inert.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line you paste. **`main` reported
      272 on 2026-08-07.** Paste the branch's own pre-change baseline too; N must exceed it.
- [ ] **Mutation**: revert `entries` to internal and confirm the new target **fails to compile**.
      That compile failure is the proof this target does its job. Restore, confirm green.
- [ ] Add a note at the top of the new file: any new public API in `YardGit` gets a line here, the
      same way a new command gets its skill regenerated.

## Tests must be able to fail

A test in `YardGitTests` cannot fail on this defect no matter what it asserts, because `@testable`
grants it internal access. **Do not add one there and call it coverage.** The mutation above is the
only evidence that counts.
