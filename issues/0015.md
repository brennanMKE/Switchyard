## Description

The GitUp map view as data: the commit DAG with topology and lane assignment, windowed by `--limit`
and filtered by `--refs`. This is the engine the app's graph view renders in M3, and it is a
genuinely non-trivial algorithm.

**Clean-room constraint applies with full force here.** GitUp's lane assignment is well tested and
worth understanding, but it is GPLv3. Read it to understand the shape of the problem, close it,
write a design note in `docs/` in your own words, and implement from the note.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/LaneAssignment.swift`. Create it; do not restructure existing files.
- [ ] Lane assignment is stable: the same input produces the same lanes across runs.
- [ ] Windowed traversal, so a 50k-commit repo does not require full-history layout.
- [ ] Octopus merges, orphan branches, and multiple roots all lay out without crashing.
- [ ] Uses `commit-graph` when present, per the #0003 measurement.
- [ ] Performance on the #0003 fixture repo is within the numbers that milestone recorded.
- [ ] A design note exists in `docs/` written before the implementation.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N must be greater than the count on `main` before this change.
