## Description

Apply #0129's settled wire pattern (Decisions 1–8) to the signing payloads:

| type | source file | traps |
|---|---|---|
| `SignatureVerification` (+ nested `State`, `Format`) | `YardKit/Sources/YardGit/SignatureVerification.swift` | `State.cannotCheck(reason:)` carries an associated value, so `State` encodes as an object with a stable `code` string plus an optional `reason` — uniform across all eight cases (Decision 5, no string-or-object unions). `Format` has no raw type and no associated values: case-name string via explicit `encode(to:)` (`"ssh"`, `"openpgp"`, `"x509"`, `"none"`, `"unrecognized"`). |
| `SigningConfig` (+ nested `Format`) | `YardKit/Sources/YardGit/SigningConfig.swift` | `Format.unrecognized(String)` carries the raw config value, so this `Format` also encodes as an object: `code` plus optional `value`. `commitSigningEnabled` is `Bool?` and its nil-vs-false distinction is the type's whole point — nil is OMITTED (Decision 4), and the literal tests must pin all three states (`true`, `false`, absent). `willSign` / `canVerifySSHSignatures` are computed, not encoded (Decision 7). |

Both types are already `Sendable`.

## Expected behavior (re-author to code level before dispatch, per CLAUDE.md)

      enums, the enums explicit `encode(to:)` per Decision 5.

      `State` and `Format` case string/shape, the three `commitSigningEnabled` states, and one
      envelope passthrough, literals pasted from a real run at planning time.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line; N must exceed the
      pre-change baseline by exactly the number of new tests, both counts settled and stated at
      planning time.
