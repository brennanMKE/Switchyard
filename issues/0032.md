## Description

Two `yard` processes in the same repository must not interleave journal writes. With agents running
in parallel worktrees against a shared `$GIT_COMMON_DIR`, this is a routine occurrence rather than a
race that needs contriving.

A lock file under `.git/switchyard/` with a timeout, failing cleanly rather than blocking forever.

## Expected behavior

- [ ] Lock is per-repository (common dir), not per-worktree — the journal is shared.
- [ ] Timeout is bounded and configurable; expiry produces a clear error, never an indefinite hang.
- [ ] A stale lock from a killed process is detected and recovered, not honored forever.
- [ ] Test runs two concurrent `yard` mutations and asserts both the journal and the repo stay consistent.
