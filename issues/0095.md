## Description

Remove a worktree, releasing its lock and any attached agent session. Refuses when the worktree is
unclean unless `--force`, matching `git worktree remove`'s own behavior.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/WorktreeRemove.swift`. Create it; do not restructure existing files.
- [ ] Releases the lock set by `yard wt new --agent` (#0021) before removing.
- [ ] Refuses an unclean worktree without `--force`; the refusal is a structured error naming what is dirty, not a bare failure.
- [ ] Never passes `--force` to git on an agent's behalf.
- [ ] Tests cover: clean removal, refusal when dirty, and successful removal with `--force`.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `swift build` succeeds and `swift test` prints a `Test run with N tests` line you paste.

## Notes

Split out of #0022. Blocked by #0009, #0024.

Matching git's own refusal semantics matters more than convenience here — an agent that can silently
delete uncommitted work is exactly what the journal exists to prevent.
