# 0114 — `jsonString` in CommandLineRunner traps instead of failing

| | |
|---|---|
| **Status** | in-progress |
| **Module** | YardKit |
| **Milestone** | M1 |
| **Platform** | macOS |
| **First seen** | 2026-08-07 |

## Description

Every envelope `switchyard` writes goes through this, at the bottom of
`YardKit/Sources/YardKit/CommandLineRunner.swift`:

```swift
private func jsonString<T: Encodable>(_ value: T) -> String {
    let data = try! JSONEncoder().encode(value)
    return String(data: data, encoding: .utf8)!
}
```

Two traps on the only path that produces output. The project's own rule is that `try!` does not
appear in Switchyard, and it appears here in the single function every command depends on.

Today neither trap can fire — `Envelope` and `EnvelopeFail` encode fixed shapes. But `EncodableResult`
wraps **any** `Encodable & Sendable`, so the first command whose payload has a non-string dictionary
key, a non-finite `Double`, or a throwing custom `encode(to:)` crashes the process instead of
emitting a failure envelope. An agent sees a signal, not `{"ok":false}`.

## Givens — verified on `main`, treat as true

1. The file is `YardKit/Sources/YardKit/CommandLineRunner.swift`; `jsonString` is `private` and has
   exactly the two call sites in that file.
2. `runYard` returns `(stdout: String, stderr: String, exitCode: ExitCode)` — three elements.
3. `EnvelopeFail(code:message:)` and `EnvelopeErrorCode` are in `Envelope.swift`. **There is no
   `internalError` case.** The ten cases, verified by reading `Envelope.swift:84`, are: `ok`,
   `usage`, `brokerUnreachable`, `appUnavailable`, `requestFailed`, `sessionTerminated`,
   `repositoryError`, `humanDeclined`, `blockedOnConflicts`, `signingFailed`.

   **Use `.requestFailed`, and do not add a case.** Adding one means touching `ExitCode`,
   `codeLabel`, the `init(from:)` decoding switch, and the exit-code contract that CLAUDE.md says
   must not be renumbered — far more than this issue is worth. `.requestFailed` is documented as
   "failed for a reason unrelated to reachability or termination", which is what an encoding failure
   is from the caller's side.
4. `EncodableResult` (`Envelope.swift:62`) wraps `any (Encodable & Sendable)`, which is why the
   failure is reachable in principle even though no current command triggers it.

## Expected behavior

- [ ] `jsonString` no longer uses `try!` or a force-unwrap. `grep -c 'try!' CommandLineRunner.swift`
      returns 0.
- [ ] Encoding failure produces a **hand-written literal failure envelope** — a `String` constant, not
      another encode that could itself fail — and `runYard` returns it with a non-zero exit code.
- [ ] The output for every currently-working invocation is **byte-identical** to before. Paste the
      before and after stdout for `switchyard`, `switchyard noop`, and `switchyard bogus`.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest.
- [ ] Tests go in `YardKit/Tests/YardKitTests/`. `Tests/YardKit/` is not a declared target path and a
      file there is silently never compiled.
- [ ] `cd YardKit && swift build` succeeds and `swift test` prints a `Test run with N tests` line you
      paste, greater than the branch's own pre-change baseline, which you also paste.

## Tests must be able to fail

The whole point is a path that cannot currently be reached, so **the test must construct a payload
that genuinely fails to encode** and assert the failure envelope comes back. A type whose
`encode(to:)` throws is the direct way; a `Double.infinity` under the default
`JSONEncoder.NonConformingFloatEncodingStrategy` is another.

A test that only checks the happy path proves nothing — it passed before the change too. Say which
payload you used and paste the envelope it produced.
