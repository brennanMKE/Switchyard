## Description

**Split out of #0048 on 2026-08-17.** #0047 gave the app an anonymous listener and registered its
endpoint with the broker, but its `ListenerDelegate.shouldAcceptNewConnection` returns **`false`** —
serving an accepted connection was explicitly out of that round's scope. #0048 builds the client side
and defines `AppServiceProtocol`. This issue closes the loop: the app accepts the connection and
exports an object implementing that protocol, so `switchyard ping` reaches the app rather than the
broker.

Small on purpose. It is the last link in the chain the three previous issues built, and until it lands
nothing can prove the chain works.

## Expected behavior

- [ ] `ListenerDelegate.shouldAcceptNewConnection` sets `exportedInterface = XPCInterfaces.appService`
      and `exportedObject`, resumes the connection, and returns `true`.
- [ ] The exported object implements `appPing` and replies with something that identifies the app
      instance — the bundle version is enough; do not invent a payload format, #0194 owns that.
- [ ] Every closure XPC invokes is `@Sendable`. The app target compiles with
      `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, so a closure that inherits main-actor isolation
      dies with `SIGTRAP` in `_swift_task_checkIsolatedSwift` and **no compiler warning**. #0047's
      `AppXPCServer.swift` has the pattern and the comment explaining it.
- [ ] Accepting a connection must not create per-CLI session state — that is #0213, deliberately after
      this.
- [ ] The app builds unsigned: `** BUILD SUCCEEDED **`.
