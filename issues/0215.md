## Description

**Split out of #0048 on 2026-08-17.** #0047 gave the app an anonymous listener and registered its
endpoint with the broker, but its `ListenerDelegate.shouldAcceptNewConnection` returns **`false`** —
serving an accepted connection was explicitly out of that round's scope. #0048 builds the client side
and defines `AppServiceProtocol`. This issue closes the loop: the app accepts the connection and
exports an object implementing that protocol, so `switchyard ping` reaches the app rather than the
broker.

Small on purpose. It is the last link in the chain the three previous issues built, and until it lands
nothing can prove the chain works.

## Expected behavior

- [ ] `ListenerDelegate.shouldAcceptNewConnection` sets `exportedInterface = XPCInterfaces.appService`
      and `exportedObject`, resumes the connection, and returns `true`.
- [ ] The exported object implements `appPing` and replies with something that identifies the app
      instance — the bundle version is enough; do not invent a payload format, #0194 owns that.
- [ ] Every closure XPC invokes is `@Sendable`. The app target compiles with
      `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, so a closure that inherits main-actor isolation
      dies with `SIGTRAP` in `_swift_task_checkIsolatedSwift` and **no compiler warning**. #0047's
      `AppXPCServer.swift` has the pattern and the comment explaining it.
- [ ] Accepting a connection must not create per-CLI session state — that is #0213, deliberately after
      this.
- [ ] The app builds unsigned: `** BUILD SUCCEEDED **`.

## Planning update — 2026-08-17. One file, one delegate method.

**Edit `Switchyard/AppXPCServer.swift`.** #0047 left the shape ready: `ListenerDelegate` is already a
`private nonisolated final class` at the bottom of that file, already the listener's strongly-held
delegate, and its `shouldAcceptNewConnection` currently returns `false` with a comment naming this
issue. Replace that body; add the exported object beside it. No new file, no other file.

```swift
private nonisolated final class ListenerDelegate: NSObject, NSXPCListenerDelegate {
    func listener(
        _ listener: NSXPCListener,
        shouldAcceptNewConnection connection: NSXPCConnection
    ) -> Bool {
        // Both must be set BEFORE resume(), or calls silently do nothing — no
        // error, no reply, no crash. Same rule as the client side.
        connection.exportedInterface = XPCInterfaces.appService
        connection.exportedObject = AppService()
        connection.resume()
        return true
    }
}
```

`AppService` is a small `NSObject` conforming to `AppServiceProtocol` (#0048 declares it). **One
instance per accepted connection** — the delegate is called once per connection, the object is
retained by the connection, and it is released when that connection invalidates. That is what keeps
this issue free of session state, which is #0213.

`appPing` replies with the app's version, read from `Bundle.main.infoDictionary` —
`CFBundleShortVersionString`, falling back to `"unknown"`. Not a new payload type: a bare `String`, as
`BrokerProtocol.brokerPing` already does.

### Isolation — the part that crashes rather than warns

`AppService` is reached on **XPC's own queues**, not the main actor, and the app target compiles with
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. So:

- Declare it `nonisolated final class AppService: NSObject, AppServiceProtocol`, matching how
  `ListenerDelegate` is declared today.
- The `reply` closure is `@escaping @Sendable` in the protocol; if the implementation needs anything
  main-actor-isolated, it must hop with `Task { @MainActor in … }` and call `reply` from inside — it
  must **not** be made `@MainActor` to make the compiler quiet, because XPC will still call it off the
  main queue and the process dies with `SIGTRAP` in `_swift_task_checkIsolatedSwift`, with no warning
  at build time. `AppXPCServer.swift:70-78` carries the full explanation; read it.
- For `appPing` specifically, `Bundle.main.infoDictionary` is safe to read from any queue, so no hop is
  needed. Say so rather than adding one defensively.
