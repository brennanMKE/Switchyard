## Description

The half of the original #0042 that needs the journal store: take the
`ReferenceTransaction.Decision.updates` a foreign `committed` transaction produced (#0042's
decision core) and persist them as **observed** journal entries — distinct from undoable ones —
in the metadata store #0027/#0028 build. This is what lets the guard say *what* moved a ref
between two `switchyard` commands instead of merely that something did.

## Expected behavior

- [ ] A committed foreign transaction's updates land as an observed entry (operation, refs with
      old/new values, timestamp, worktree), marked so `undo` never offers to revert it.
- [ ] The journal's own ref writes never produce an entry (the #0042 marker path, exercised end
      to end through the store).
- [ ] Failure to persist never surfaces as a non-zero hook exit — the #0042 totality invariant
      holds through this layer too.
- [ ] `swift test` prints a `Test run with N tests` line; N must exceed the pre-change baseline
      (re-measure at planning time; state the delta).

## Planning note — 2026-08-09. A design fork that needs Brennan's call.

**This issue cannot be implemented without deciding where observed entries live**, and the two
options produce materially different work. Recording both rather than picking.

### The constraint that creates the fork

`undo` must never offer to revert an observed entry. But #0155 decision 2 is explicit: **an entry's
kind is decided by the presence of `traversal`, never by matching the `operation` string.** There is
no third kind today, and `JournalChain` treats every non-traversal entry as an undo target
(#0166). So "observed" needs a representation, and `operation: "observed"` is exactly what the
design forbids.

### Option A — a new optional field on the entry metadata

Add `observed: ObservedTransaction?` to `JournalEntryMetadata`, mirroring `traversal`: presence
marks the kind.

- Consistent with the established idiom, and observed entries stay in the journal namespace, so
  **#0030 recovers them from refs alone** like everything else.
- But it changes a **wire format pinned by golden-bytes tests** (#0155, #0179), and `chainNode`
  must become optional or gain a sibling — it has **four call sites** (`JournalRestore`,
  `JournalUndo`, `JournalList` ×2). `JournalList` also needs a `ChainPosition` case so observed
  entries list with a position rather than reading as defective.
- Realistically two issues: the metadata/chain change, then this one composing on it.

### Option B — a separate ref namespace

Write observed entries under `refs/switchyard/observed/` rather than the journal namespace.

- No wire change, no `chainNode` change, no new `ChainPosition`. They cannot appear on the chain
  because they are not in the journal's ref space at all — the strongest possible form of "undo
  never offers them".
- But `JournalRebuild` scans `JournalAnchor.refPrefix`, so **observed entries are not recovered by
  a rebuild** unless it learns a second namespace. Whether that matters is the real question: they
  are a record of *foreign* activity, and losing them on a rebuild may be acceptable — but that is
  a decision, not an oversight to discover later.
- `RefSnapshot` already filters the whole `refs/switchyard/` namespace, so capture/restore is
  unaffected either way.

### What I would recommend, and why it is still your call

**Option B**, on the grounds that it makes the safety property structural rather than enforced by
four call sites agreeing — and #0157 just demonstrated how easily a filter that must be applied
everywhere gets missed. The cost is that rebuild recovery becomes a deliberate choice rather than a
free consequence.

Not started. Blocked on this decision.

### Measured, in a scratch worktree, before this was written

An entry written into `refs/switchyard/observed/` while an ordinary checkpoint exists:

```
PROBE journal list: ["01M07D41Q2Y3A27M00GEZYAMDH"]
PROBE real entry listed: true
PROBE observed entry listed: false
PROBE all switchyard refs:
refs/switchyard/journal/01M07D41Q2Y3A27M00GEZYAMDH
refs/switchyard/observed/01M07D41R3V01NS7JP06HNRW3H
PROBE listing item count: 1
PROBE listing defects: 0
```

So the invisibility is real at both layers — `JournalAnchor.list` filters on `refPrefix`
(`JournalAnchor.swift:316-326`) and `JournalList.list` reads through it — and an observed entry does
**not** show up as a defect, which was the other way this could have gone wrong.

**One plumbing fact worth having:** `for-each-ref refs/switchyard/` matches **nothing**. A
trailing-slash prefix needs a glob — `for-each-ref 'refs/switchyard/**'` — which is what produced the
listing above. `JournalAnchor.list` is unaffected because it passes the prefix to a `--format` query
whose results it filters itself.

### Two defects in the salvaged implementation, for the planner's benefit only

`salvage/main-off-workflow` carries a `JournalObserved.swift` from the off-workflow window. **Do not
copy it.** It declares `observedNamespace` and then calls `JournalAnchor.write(contents, id:in:git:)`,
which hardcodes the **journal** namespace through `refName(for:)` — so every observed entry would
have landed on the undo chain, which is the one thing decision 12 exists to prevent. It also
re-declares `ReferenceTransaction.RefUpdate` as a byte-identical `RefUpdateRecord`, including its
three computed properties.

## Change 1 — `YardKit/Sources/YardGit/JournalAnchor.swift`, a namespace parameter

`write` currently hardcodes the journal namespace. Give it a parameter that defaults to today's
behaviour, so every existing call site is unchanged:

```swift
    public static func write(
        _ contents: Contents,
        id: JournalEntryID,
        in context: WorktreeContext,
        namespace: String = refPrefix,
        git: GitProcess = GitProcess()
    ) throws -> Entry {
```

and at the `update-ref` at line 298, `refName(for: id)` becomes `namespace + id.string`:

```swift
        try git.run(["update-ref", "--stdin"], workingDirectory: base,
                    standardInput: Data("create \(namespace + id.string) \(commit)\n".utf8))
```

Compiled and run: `swift build` clean, and the probe above used exactly this.

## Change 2 — `YardKit/Sources/YardGit/ReferenceTransaction.swift`

`RefUpdate` is `Equatable, Sendable` and **not** `Encodable` (verified: no extension anywhere in
`YardKit/Sources`). Add the conformance so observed metadata can carry the real type instead of a
copy of it. Pin the wire shape the same way every other engine type does — hand-written keys, not
synthesis:

```swift
/// `RefUpdate` rides inside an observed journal entry's metadata (#0153), so
/// its keys are pinned rather than synthesized: a rename here silently changes
/// bytes already written into a repository's refs.
extension ReferenceTransaction.RefUpdate: Encodable {
    private enum CodingKeys: String, CodingKey {
        case oldValue, newValue, refName
    }
}
```

## Change 3 — `YardKit/Sources/YardGit/JournalObserved.swift`, new file

```swift
// JournalObserved.swift — observed foreign ref transactions (#0153)

import Foundation

/// Records the ref updates a **foreign** `committed` transaction made, as
/// entries in their own ref namespace.
///
/// **They are not journal entries and must never become undo targets.** Guide
/// §11 decision 12 makes that structural rather than enforced: these live under
/// `refs/switchyard/observed/`, which `JournalAnchor.list` does not read, so
/// nothing downstream — the chain, the listing, undo — can see them however it
/// is later changed. Measured: an entry here is absent from both
/// `JournalAnchor.list` and `JournalList.list`, and is not reported as a defect.
///
/// The cost, taken deliberately and tracked as #0190: `JournalRebuild` scans the
/// journal prefix, so a rebuild does not recover these.
public enum JournalObserved {

    /// Where observed entries live. Deliberately NOT `JournalAnchor.refPrefix`.
    public static let refPrefix = RefSnapshot.switchyardNamespace + "observed/"

    /// What one observed entry stores. `schemaVersion` is pinned separately
    /// from `JournalEntryMetadata`'s: these are a different shape with a
    /// different lifetime, and sharing a version number would tie two formats
    /// together that have no reason to change together.
    public struct Metadata: Sendable, Equatable, Encodable {
        public static let currentSchemaVersion = 1

        public let schemaVersion: Int
        public let updates: [ReferenceTransaction.RefUpdate]

        public init(updates: [ReferenceTransaction.RefUpdate],
                    schemaVersion: Int = Metadata.currentSchemaVersion) {
            self.schemaVersion = schemaVersion
            self.updates = updates
        }
    }

    /// Writes one observed entry. Returns the anchor so a caller can assert on
    /// it; callers in the hook path ignore it (#0191).
    @discardableResult
    public static func record(
        _ updates: [ReferenceTransaction.RefUpdate],
        in context: WorktreeContext,
        now: Date = Date(),
        git: GitProcess = GitProcess()
    ) throws -> JournalAnchor.Entry {
        let encoder = JSONEncoder()
        encoder.outputFormatting = [.sortedKeys, .withoutEscapingSlashes]
        let json = try encoder.encode(Metadata(updates: updates))
        return try JournalAnchor.write(
            JournalAnchor.Contents(metadataJSON: json),
            id: JournalEntryID.generate(now: now, after: try list(in: context, git: git).last?.id),
            in: context,
            namespace: refPrefix,
            git: git)
    }

    /// Every observed entry, oldest first. Mirrors `JournalAnchor.list` but
    /// over this namespace.
    public static func list(
        in context: WorktreeContext,
        git: GitProcess = GitProcess()
    ) throws -> [JournalAnchor.Entry] {
        let base = context.topLevel ?? context.gitDir
        let output = try git.run(
            ["for-each-ref", "--format=%(objectname) %(refname)", refPrefix],
            workingDirectory: base).text
        return output.split(separator: "\n").compactMap { line in
            let fields = line.split(separator: " ", maxSplits: 1)
            guard fields.count == 2 else { return nil }
            let name = String(fields[1])
            guard name.hasPrefix(refPrefix),
                  let id = JournalEntryID(String(name.dropFirst(refPrefix.count)))
            else { return nil }
            return JournalAnchor.Entry(id: id, commit: String(fields[0]))
        }.sorted { $0.id.string < $1.id.string }
    }
}
```

**Read `JournalAnchor.list` (line 310) before writing `list` here** and match how it reads the
metadata blob and handles a ref whose last component is not an id — this file's `list` is
deliberately the simpler sibling, but it must not disagree with it about what a malformed ref means.

## Change 4 — `YardKit/Tests/YardGitTests/JournalObservedTests.swift`, new file

Three tests, in a `struct JournalObservedTests` matching the other journal test files:

1. `anObservedEntryIsInvisibleToTheJournalAndItsListing` — the probe above, as a test: write an
   ordinary checkpoint and an observed entry into the same fixture, then assert the checkpoint's id
   **is** in `JournalAnchor.list` and `JournalList.list(in:).items`, and the observed id is in
   **neither**, and `listing.items.compactMap(\.defect)` is empty.
2. `observedEntriesRoundTripTheirRefUpdates` — `record` two updates, read the entry back through
   `JournalObserved.list`, decode its metadata blob, and assert the updates come back identical
   including `refName`, `oldValue`, `newValue`.
3. `theObservedNamespaceIsNotTheJournalNamespace` — assert `JournalObserved.refPrefix !=
   JournalAnchor.refPrefix` and that a written entry's ref name starts with the former. Cheap, and it
   is the one assertion that fails loudly if someone later "simplifies" `record` to use the default
   namespace.
