## Description

**Finding 3 of the M1 milestone review, fourth pass, 2026-08-18.** M1 exit criterion 5 is unmet for
`listHunks`: removing `"--no-renames"` from its argument vector at `YardKit/Sources/YardGit/Hunks.swift:377`
left the **full unfiltered suite green** — `Test run with 1066 tests in 78 suites passed after 57.215
seconds`.

**This is not a cosmetic flag.** It is documented as load-bearing at `Hunks.swift:367-368` — *"a rename
would put two different paths on the `diff --git` line"* — and the consequence is a hard failure, not a
degraded result. Measured on git 2.50.1 with a staged `git mv old.txt new.txt`:

```
--- WITH --no-renames:
diff --git a/new.txt b/new.txt
new file mode 100644
--- WITHOUT --no-renames:
diff --git a/old.txt b/new.txt
similarity index 100%
rename from old.txt
```

`HunkParser.pathFromDiffGitLine` requires `both == path + " b/" + path` (`Hunks.swift:262`). For
`a/old.txt b/new.txt` that check fails and the parser throws `Failure.malformedFileHeader`. So without
the flag `listHunks` **fails outright on any repository with a rename in the diff** — and
`diff.renames` is on by default in modern git, so this is the ordinary case, not an exotic one.

A failure mode of an M1 engine function, protected only by an unasserted flag.
