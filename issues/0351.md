## Description

**Flake, caught 2026-09-03 chasing a main failure.**
`ReviewRequestServingTests.rangeRequestResolvesTheCommitDiffAndDeliversItToTheSheet`
(ReviewRequestServingTests.swift:180) fails intermittently — roughly 1 in 3-4 full-suite runs under
load — with `Expectation failed: registered → nil`: the test's bounded wait never observed the
pending registration. Observed three times total (once uncaptured at the #0055 r3 close-out, once
under #0056's mid-round run on `appDeathMidReviewExitsFive`'s neighbour, once captured on main at
05329e6). Filtered runs of the same test pass every time; the failure only appears deep in a
saturated full suite.

The delivery chain is: `runReviewRequest` computes the diff (async), calls `onPending` (the bridge
hops to the main actor into `ReviewSheetBridge.pendingDidRegister`, which routes the tab and attaches
the diff), then `ReviewServing.handle` registers the pending. Round 2's design made the two arrivals
order-independent (a diff arriving before registration is stashed per commonDir). The flake says one
of the hops still has a window under saturation — or the test's bounded wait is simply too short for
a saturated machine.

## Expected behavior

- [ ] Diagnose which it is: a genuine ordering window in the delivery chain, or a test deadline
      that does not tolerate load. Say which, with the evidence.
- [ ] If a code window: fix it (the stash path, the hook hop, or the store's hook firing outside the
      lock are the suspects — read `PendingReviewStore.swift`'s `onPendingChange` contract, which is
      documented caller-owned).
- [ ] If a deadline: make the wait generous enough that a saturated machine cannot exceed it (the
      Rule 7c principle — lateness under load is not failure), and assert the delivery happened.
- [ ] The test passes 10 consecutive full-suite runs, or 20 filtered runs with an artificial
      `--jobs`-style load if a full-suite loop is unaffordable. State which you ran.
- [ ] `cd YardKit && swift test` prints `Test run with N tests` with **N equal to the count on main**
      (1463 — this fix adds no behaviour). A lower number is a finding.

## Notes

The flake is in #0055's merged code; #0056's `appDeathMidReviewExitsFive` flaked once in the same
window and may share the root cause — check its wait shape too while you are there.
