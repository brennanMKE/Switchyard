## Description

Measured 2026-09-27 on the host. On `main` at `997fb348`, the command below builds successfully and
`codesign --verify --deep --strict` passes, but `open`-ing the app dies in dyld.

```
xcodebuild build -project Switchyard.xcodeproj -scheme Switchyard -destination 'platform=macOS' \
  -derivedDataPath build/dd CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO
```

The crash, from `~/Library/Logs/DiagnosticReports/Switchyard-2026-09-27-191946.ips`:

```
Library not loaded: @rpath/Switchyard.debug.dylib
... code signature in '.../Contents/MacOS/Switchyard.debug.dylib' not valid for use in process:
mapping process and mapped file (non-platform) have different Team IDs
```

### Root cause (planner, measured 2026-09-27)

A Debug build has `ENABLE_DEBUG_DYLIB = YES` (both schemes, both `build` and `build-for-testing`,
from `xcodebuild -showBuildSettings`), so `Contents/MacOS/Switchyard` is a 3-page stub and the app
is `Contents/MacOS/Switchyard.debug.dylib` (plus `__preview.dylib`, loaded only by Previews).
#0418's `scripts/adhoc-seal-app.sh` signs the bundle with `--options runtime`, so the stub gets
`flags=0x10002(adhoc,runtime)`. **The hardened runtime turns on library validation, which requires
every non-platform library to carry the executable's Team ID — and an ad-hoc signature has no Team
ID at all.** So the fix the issue first proposed (re-sign every nested Mach-O, inside-out) **does not
work**. Measured with a two-file C fixture on the host (a stub that links `@rpath/Fake.debug.dylib`,
the shape Xcode builds; the fixture is a 4-line program, not the app):

| main executable | dylib | result |
|---|---|---|
| linker-signed | linker-signed | exit 0 |
| ad-hoc, `--options runtime` | linker-signed | **exit 134**, `different Team IDs` (this bug) |
| ad-hoc, `--options runtime` | re-signed ad-hoc | **exit 134**, `different Team IDs` |
| ad-hoc, `--options runtime` | re-signed ad-hoc, `--options runtime` | **exit 134**, `different Team IDs` |
| ad-hoc, **no runtime** | linker-signed | **exit 0** |
| ad-hoc, runtime + `disable-library-validation` entitlement | linker-signed | exit 0 |

**Decision (planner, high confidence): seal a bundle that has a `*.dylib` in `Contents/MacOS`
without `--options runtime`; every other bundle keeps it.** Reasons:
- Only the "no runtime" and "entitlement" rows work. The entitlement would be the first entitlement
  the ad-hoc path applies (#0418 deliberately applies none) and it is a security exemption; dropping
  the runtime for Debug is the narrower change and is what an unsigned Debug build had before #0418.
- A Release build (`make-release.sh`) has no debug dylib, so it keeps exactly the signature #0418
  measured end to end (variant C). Nested executables (`BrokerAgent`, the CLI) keep
  `--options runtime` in both configurations — they link only system libraries.
- Bonus: #0418 noted a sealed Debug build could not be attached by lldb because of the hardened
  runtime; a Debug build without it can be.

After the fix, the real Debug build (host build of `main` at `12c7785e` in `../sy-plan-0434`, not
launched on the host): stub `flags=0x2(adhoc)`, `Sealed Resources version=2 rules=13 files=7`,
`BrokerAgent flags=0x10002(adhoc,runtime)`, `codesign --verify --deep --strict` exit 0.

### Why XCUITest did not crash

**It was not XCUITest — it was the VM.** Measured 2026-09-27 in a clone of
`switchyard-uitest-golden` (guest macOS 26.6.2; host macOS 27.0):

- `csrutil status` in the guest: **`System Integrity Protection status: disabled.`** (host:
  enabled). `nvram boot-args` and `kern.bootargs` are empty, so no `amfi_get_out_of_my_way`.
- The launch smoke below, run against **unfixed** `main` with a plain `open` (no XCUITest):
  `pid=1900 crash-reports-before=0 after=0` — the same Debug build that dies on the host **ran fine
  in the guest**.
- The 4-line C fixture in the guest: main ad-hoc `--options runtime` + linker-signed dylib →
  **exit 0** (host: 134). The same main signed `--options library,runtime` → **exit 134**,
  `different Team IDs`; `--options library` alone → **exit 134**.

So on a SIP-disabled Mac, AMFI waives the library validation the hardened runtime *implies*, but
still enforces an *explicit* `library-validation` flag. Every XCUITest launch in the VM passed
because every VM launch would have passed. Whether the waiver is due to SIP or to 26.6.2 vs 27.0
was not isolated (SIP cannot be re-enabled in a clone without a recovery boot) — SIP is the
documented relaxation and the likely cause; the smoke step below does not depend on which.

**Consequence for the VM step:** an `open` alone cannot catch this bug in this golden image. The
smoke therefore re-signs a hardened main executable ad-hoc with `--options library,runtime` before
launching it, which makes the guest enforce what a stock SIP-enabled Mac enforces. A build without
the hardened runtime (the fix) is launched as built. The golden image keeps SIP disabled — changing
it is out of scope and may be what its UI automation relies on.

### Why the VM missed it

`run-ui-tests-vm.sh` only ever launched the app through XCUITest (above), and the #0418 VM CLI
check used the Release artifact, which has no debug dylib. Nothing `open`ed a plain Debug build,
which is what a person does. Part 3 below adds exactly that step. (Note for the orchestrator:
`docs/review-failures.md`'s #0418 row says the dylib "was not re-sealed"; re-sealing it would not
have helped — the cause is the hardened runtime on an ad-hoc executable.)

# #0434: the launch smoke. XCUITest is not how a person starts the app, and
# it tolerated a Debug build that dies in dyld on an ordinary launch (see
# issues/0434.md for why). So, in its own clone: build the `Switchyard`
# scheme Debug and unsigned exactly as a person does, `open` it on the
# fixture, and require the process alive 10 s later with no new crash report
# in the guest's ~/Library/Logs/DiagnosticReports.
run_launch_smoke() {
  local label="launch-smoke"
  start_guest 0 "$label"
  log "[$label] Building the Debug Switchyard scheme unsigned and opening it"
  set +e
  local rc
  tart exec "$CLONE" /bin/zsh -lc "
    cd $GUEST_SRC
    xcodebuild build -project Switchyard.xcodeproj -scheme Switchyard -destination 'platform=macOS' \
      -derivedDataPath build/dd CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO \
      > $GUEST_RESULTS/xcodebuild-$label.log 2>&1 \
      || { echo 'LAUNCH SMOKE FAILED: xcodebuild build failed'; exit 1; }
    app=$GUEST_SRC/build/dd/Build/Products/Debug/Switchyard.app
    # The golden image runs with SIP disabled, and a SIP-disabled Mac waives the
    # library validation the hardened runtime implies: the #0434 build that died
    # on the host launched fine here. An EXPLICIT library-validation flag is
    # still enforced with SIP off (both measured 2026-09-27, issues/0434.md), so
    # a hardened main executable is re-signed ad-hoc with it and the guest then
    # refuses what a stock Mac refuses. Ad-hoc only: no identity, no keychain.

        || { echo 'LAUNCH SMOKE FAILED: could not add library-validation'; exit 1; }

    cp \$reports/Switchyard*(N) $GUEST_RESULTS/
