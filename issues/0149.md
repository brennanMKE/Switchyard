# 0149 — Implement durable repository identity in YardGit

| | |
|---|---|
| **Status** | open |

## Description

A durable, opaque repository identity — a generated id stored at
`$GIT_COMMON_DIR/switchyard/repository-id` — so the repository registry (#0029) keeps **one entry
per repository across a move on disk**. The registry consumes it as a plain `String`, so neither
`YardGit` nor `YardKit` imports the other (the #0141 shape).

The id lives inside the repository because that is the only store that moves with it: a path-keyed
registry cannot tell "moved" from "deleted plus unrelated new repo", and an id it carries along can.

## Givens — verified

All measured 2026-08-07 on git 2.50.1 (Apple Git-155), in a scratch repo with one linked worktree.

1. **`--git-path` must NOT be used to locate this file.** For an unknown subpath it resolves
   per-worktree, not shared — measured:

   ```
   main worktree:    git rev-parse --path-format=absolute --git-path switchyard/repository-id
                     → <repo>/.git/switchyard/repository-id
   linked worktree:  same command
                     → <repo>/.git/worktrees/linked/switchyard/repository-id
   ```

   Address the file relative to `WorktreeContext.commonDir` instead, which both worktrees agree on
   (measured: `git rev-parse --path-format=absolute --git-common-dir` from the linked worktree
   prints the main `<repo>/.git`). This is the documented pattern for our per-repo state:
   `ServiceNames.repoStateDirectoryName` is "Per-repository directory, relative to
   `$GIT_COMMON_DIR`". CLAUDE.md's `$GIT_DIR` rule forbids parsing *git's* files; `switchyard/` is
   our own state, and `commonDir` itself comes from `git rev-parse` via `WorktreeContext`.

2. **The file survives a move.** Measured: created `.git/switchyard/repository-id`, `mv`'d the
   repository directory, and afterwards `git rev-parse --git-common-dir` reports the new location,
   `git status` exits 0, and the id file reads back byte-identical.

## Decisions to settle at the planning pass — do not dispatch before

- **Where the `"switchyard"` per-repo directory-name constant lives.** It is currently
  `ServiceNames.repoStateDirectoryName` in `YardKit`, which `YardGit` must not import. Options:
  move the per-repository constants (`repoStateDirectoryName`, `journalMetadataRelativePath`) into
  `YardGit` and keep `ServiceNames` for app/CLI/XPC identifiers; or accept the literal in `YardGit`
  with a test in `Tests/YardWireTests` pinning agreement with `ServiceNames`. The same tension
  exists for #0028's `journal.json` — settle once, here, and record it in guide §11.
- **Id format.** No ordering requirement (unlike #0028's entry ids) — a UUID string is enough.
- **Degenerate cases.** A malformed/empty id file (regenerate or error?); a `cp -r`'d repository
  (two repos, one id — the registry's last-writer-wins keeps one entry; document, decide whether to
  detect).

## Expected behavior — sketch; re-author to code level at dispatch, per the planning standard

- [ ] One new production file `YardKit/Sources/YardGit/RepositoryIdentity.swift`: read-or-create
      the id at `<commonDir>/switchyard/repository-id`, file mode 0600, directory created 0700.
- [ ] Resolving from the main worktree and from a linked worktree of the same repository returns
      the same id — test against `FixtureRepository` plus `git worktree add`.
- [ ] The id is unchanged after the repository directory is moved with `FileManager.moveItem` and
      re-resolved through a fresh `WorktreeContext` — the moved-repo pin this issue exists for.
- [ ] A cross-boundary test in `YardKit/Tests/YardWireTests/`: register a fixture in
      `RepositoryRegistry` (injected scratch directory), move the fixture on disk, re-resolve the
      id, re-register — outcome is `.updated(previousCommonDir:)` and the registry holds exactly
      one entry.
- [ ] `swift test` prints `Test run with N tests` where N must exceed the then-current
      `docs/test-baseline.txt` count; state the expected N when re-authoring.
