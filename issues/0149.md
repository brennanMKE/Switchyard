# 0149 — Implement durable repository identity in YardGit

| | |
|---|---|
| **Status** | in-progress |
| **Module** | YardGit |
| **Milestone** | M2 |

| **First seen** | 2026-08-07 |

## Description

A durable, opaque repository identity — a generated id stored at
`$GIT_COMMON_DIR/switchyard/repository-id` — so the repository registry (#0029) keeps **one entry
per repository across a move on disk**. The registry consumes it as a plain `String`, so neither
`YardGit` nor `YardKit` imports the other (the #0141 shape).

The id lives inside the repository because that is the only store that moves with it: a path-keyed
registry cannot tell "moved" from "deleted plus unrelated new repo", and an id it carries along can.

## Givens — verified

All measured 2026-08-07 on git 2.50.1 (Apple Git-155), in a scratch repo with one linked worktree.

1. **`--git-path` must NOT be used to locate this file.** For an unknown subpath it resolves
   per-worktree, not shared — measured:

   ```
   main worktree:    git rev-parse --path-format=absolute --git-path switchyard/repository-id
                     → <repo>/.git/switchyard/repository-id
   linked worktree:  same command
                     → <repo>/.git/worktrees/linked/switchyard/repository-id
   ```

   Address the file relative to `WorktreeContext.commonDir` instead, which both worktrees agree on
   (measured: `git rev-parse --path-format=absolute --git-common-dir` from the linked worktree
   prints the main `<repo>/.git`). This is the documented pattern for our per-repo state:
   `ServiceNames.repoStateDirectoryName` is "Per-repository directory, relative to
   `$GIT_COMMON_DIR`". CLAUDE.md's `$GIT_DIR` rule forbids parsing *git's* files; `switchyard/` is
   our own state, and `commonDir` itself comes from `git rev-parse` via `WorktreeContext`.

2. **The file survives a move.** Measured: created `.git/switchyard/repository-id`, `mv`'d the
   repository directory, and afterwards `git rev-parse --git-common-dir` reports the new location,
   `git status` exits 0, and the id file reads back byte-identical.

## Decisions to settle at the planning pass — do not dispatch before

- **Where the `"switchyard"` per-repo directory-name constant lives.** It is currently
  `ServiceNames.repoStateDirectoryName` in `YardKit`, which `YardGit` must not import. Options:
  move the per-repository constants (`repoStateDirectoryName`, `journalMetadataRelativePath`) into
  `YardGit` and keep `ServiceNames` for app/CLI/XPC identifiers; or accept the literal in `YardGit`
  with a test in `Tests/YardWireTests` pinning agreement with `ServiceNames`. The same tension
  exists for #0028's `journal.json` — settle once, here, and record it in guide §11.
- **Id format.** No ordering requirement (unlike #0028's entry ids) — a UUID string is enough.
- **Degenerate cases.** A malformed/empty id file (regenerate or error?); a `cp -r`'d repository
  (two repos, one id — the registry's last-writer-wins keeps one entry; document, decide whether to
  detect).

## Planning update — 2026-08-17. The layering decision, settled.

### Decision: per-repository layout constants live in `YardGit`

Recorded as guide §11 decision 13. Taken as an ordinary layering choice, not escalated, because the
code has already made it — twice — and this only removes the duplication:

- `JournalLock` builds `context.commonDir + "/switchyard/" + fileName` from a **literal**
  (`JournalLock.swift:70`), with a doc comment explaining why `--git-path` cannot be used.
- `JournalMetadataCache` carries a literal too, its comment admitting it is *"a copy of
  `ServiceNames.journalMetadataRelativePath`"* (`JournalMetadataCache.swift:23`).

So the alternative — "accept the literal in `YardGit` with a wire test pinning agreement" — is the
status quo, and the status quo is two unpinned copies. The rule that makes `ServiceNames` valuable is
that it is a *single* source of truth; per-repository layout is a different concern from the bundle
identifier, Mach service name and URL scheme it exists for, and `YardGit` must not import `YardKit`
(the #0141 shape).

**`ServiceNames` keeps app, CLI and XPC identifiers. `YardGit` owns where things sit inside a
repository.** A test in `YardKit/Tests/YardWireTests/` pins the two against each other so a rename on
either side fails loudly rather than diverging silently — that target imports both and is the only
place that can.

**Scope discipline:** this issue introduces the constant and uses it for its own file. **Migrating
`JournalLock` and `JournalMetadataCache` off their literals is #0199**, filed alongside this, because
it touches the journal's locking path and deserves its own mutation table.

## Change 1 — `YardKit/Sources/YardGit/RepositoryLayout.swift`, new file

```swift
// RepositoryLayout.swift — where switchyard's own state sits inside a repository (#0149)

import Foundation

/// Paths **switchyard** owns inside a repository, all relative to
/// `$GIT_COMMON_DIR`.
///
/// These live in `YardGit` rather than in `ServiceNames` deliberately (guide
/// §11 decision 13): `YardGit` must not import `YardKit`, and per-repository
/// layout is a different concern from the bundle identifier and Mach service
/// name that `ServiceNames` exists for. A test in `Tests/YardWireTests` — the
/// one target that imports both — pins these against `ServiceNames` so a
/// rename on either side fails loudly.
///
/// **Never resolve these through `git rev-parse --git-path`.** For a subpath
/// git does not know, `--git-path` answers **per-worktree**: measured, a
/// linked worktree resolves `switchyard/repository-id` to
/// `<repo>/.git/worktrees/<name>/switchyard/repository-id` while the main
/// worktree resolves it to `<repo>/.git/switchyard/repository-id`. Two
/// worktrees would then disagree about the repository's identity. Address
/// them from `WorktreeContext.commonDir`, which both agree on.
public enum RepositoryLayout {

    /// Our per-repository directory, relative to `$GIT_COMMON_DIR`.
    public static let stateDirectoryName = "switchyard"

    /// The repository identity file, relative to `$GIT_COMMON_DIR`.
    public static let repositoryIDRelativePath = stateDirectoryName + "/repository-id"

    /// Absolute path of our state directory for a resolved context.
    public static func stateDirectory(in context: WorktreeContext) -> String {
        context.commonDir + "/" + stateDirectoryName
    }
}
```

## Change 2 — `YardKit/Sources/YardGit/RepositoryIdentity.swift`, new file

Read-or-create, and **the create must be atomic**, because two `switchyard` invocations in different
worktrees can race here and a repository with two identities defeats the whole point:

```swift
// RepositoryIdentity.swift — a durable, opaque repository identity (#0149)

import Foundation

/// A repository's durable identity: an opaque id stored **inside** the
/// repository, at `<commonDir>/switchyard/repository-id`.
///
/// It lives in the repository because that is the only store that moves with
/// it. A path-keyed registry cannot tell "moved" from "deleted, plus an
/// unrelated new repository at the same path"; an id the repository carries
/// along can. #0029's registry consumes it as a plain `String`, so neither
/// package imports the other.
public enum RepositoryIdentity {

    public enum Error: Swift.Error, Equatable, CustomStringConvertible {
        case unreadable(path: String, detail: String)
        case unwritable(path: String, detail: String)

        public var description: String {
            switch self {
            case let .unreadable(path, detail):
                "cannot read the repository id at \(path): \(detail)"
            case let .unwritable(path, detail):
                "cannot write the repository id at \(path): \(detail)"
            }
        }
    }

    /// The id for this repository, creating one on first call.
    ///
    /// **A malformed or empty file is replaced, not reported.** The id is
    /// opaque and carries no information, so regenerating loses nothing except
    /// the link to registry rows that referenced the old value -- and a
    /// truncated id would break that link anyway while looking valid. The
    /// alternative, failing, would make every command in the repository fail
    /// on a one-byte corruption in a file nothing else needs.
    public static func resolve(
        in context: WorktreeContext,
        uuid: () -> String = { UUID().uuidString }
    ) throws -> String {
        let fm = FileManager.default
        let directory = RepositoryLayout.stateDirectory(in: context)
        let path = context.commonDir + "/" + RepositoryLayout.repositoryIDRelativePath

        if let data = fm.contents(atPath: path),
           let existing = String(data: data, encoding: .utf8)?
               .trimmingCharacters(in: .whitespacesAndNewlines),
           !existing.isEmpty {
            return existing
        }

        let generated = uuid()
        do {
            try fm.createDirectory(
                atPath: directory, withIntermediateDirectories: true,
                attributes: [.posixPermissions: 0o700])
            // Written to a staging file and renamed into place: two
            // invocations in different worktrees can reach this line at once,
            // and a rename is the only step that cannot interleave. The loser
            // of the race then reads the winner's id on its next resolve.
            let staging = path + ".\(ProcessInfo.processInfo.processIdentifier)"
            try Data(generated.utf8).write(to: URL(fileURLWithPath: staging))
            try fm.setAttributes([.posixPermissions: 0o600], ofItemAtPath: staging)
            if fm.fileExists(atPath: path) {
                try? fm.removeItem(atPath: staging)
                return try resolve(in: context, uuid: uuid)
            }
            try fm.moveItem(atPath: staging, toPath: path)
        } catch let error as Error {
            throw error
        } catch {
            throw Error.unwritable(path: path, detail: String(describing: error))
        }
        return generated
    }
}
```

**Read that `if fm.fileExists` branch before transcribing it** and satisfy yourself it terminates: it
recurses at most once, because the only path to it is another process having created the file, and the
read at the top then succeeds.

## Change 3 — tests

1. `resolveCreatesAnIdAndTheSecondCallReturnsIt` — two calls, same value; assert the file exists at
   `<commonDir>/switchyard/repository-id` and its mode is `0o600` and the directory's is `0o700`.

3. `theIdSurvivesAMoveOnDisk` — resolve, `FileManager.moveItem` the whole fixture directory, resolve
   through a **fresh** `WorktreeContext`, assert the same id. The pin this issue exists for.
4. `anEmptyIdFileIsReplaced` — write an empty file at the path, resolve, assert a non-empty id comes
   back and the file now holds it.

`YardKit/Tests/YardWireTests/RepositoryIdentityRegistryTests.swift`, two tests — this target imports
both packages, which is why the cross-boundary assertions live here:

5. `theLayoutConstantsAgreeWithServiceNames` — `RepositoryLayout.stateDirectoryName ==
   ServiceNames.repoStateDirectoryName`, and
   `ServiceNames.journalMetadataRelativePath.hasPrefix(RepositoryLayout.stateDirectoryName + "/")`.
   This is the pin the decision above promises.

   is `.updated(previousCommonDir:)` and the registry holds **exactly one** entry.

## Notes

The `cp -r`'d repository case — two repositories sharing one id — is **documented and not detected**:
the registry's row is keyed by identity, so the copy silently takes over the original's row on its
next registration. Detecting it needs a second signal (the common dir at creation time, say) and a
policy for what to do when they disagree, which is not worth designing before anything consumes it.
Recorded here so the next reader does not mistake it for an oversight.
