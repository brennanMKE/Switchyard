# 0336 — listHunks merges two hunks under diff.interHunkContext

## Description

**The seventh config lever, and the first one found by #0330's sweep rather than by a review pass —
on its first run.** `listHunks` pins `--unified=3` to override `diff.context` (#0294) but pins nothing
against **`diff.interHunkContext`**, so a user's setting merges two otherwise-separate hunks into one.

Measured independently at review, git 2.50.1 — a 20-line file, one line inserted after `line 03` and
`line 17` edited, run through `listHunks`'s exact argument vector:

```
default:                        @@ -1,6 +1,7 @@
                                @@ -14,7 +15,7 @@ line 13

diff.interHunkContext=10:       @@ -1,20 +1,21 @@          <- ONE hunk

plus --inter-hunk-context=0:    @@ -1,6 +1,7 @@
                                @@ -14,7 +15,7 @@ line 13   <- restored
```

**Two hunks become one**, so `FileDiff.hunks` changes shape and every hunk id derived from it changes
with it. This is the same defect as #0294, one flag over: `--unified=3` bounds the context *within* a
hunk, `--inter-hunk-context` bounds the gap at which two hunks *merge*, and only the first was pinned.

**`0` is git's own default** when `diff.interHunkContext` is unset, so pinning it preserves today's
behaviour exactly and changes only the non-default case — the same argument as #0329's
`status.renames=true`.

## Expected behavior

- [ ] `listHunks` adds `--inter-hunk-context=0` to its argument vector, beside `--unified=3`, with the
      measurement in the doc comment that already explains the other pins.
- [ ] A named test in `HunksTests.swift` following the `color.ui` / `diff.context` / `core.abbrev`
      precedent — a `private func …ConfiguredRepo(_:)` helper setting `diff.interHunkContext` to 10 on
      the two-hunk fixture — asserting `file.hunks.count == 2` and both hunks' header fields.
- [ ] **Verify the config bites first**, and make that probe capable of failing (preflight 8m): plain
      `git diff` under the config must print **one** `@@` line, not two.
- [ ] **Mutation:** drop `--inter-hunk-context=0`. The new test must redden.
- [ ] **Remove the allow-list entry in `ConfigImmunityTests.swift`** — the row
      `"listHunks(.unstaged)|diff.interHunkContext=10"` — as part of this change, and confirm the sweep
      passes without it. That is what makes the exemption self-expiring rather than permanent.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, above the count in `docs/test-baseline.txt`.
