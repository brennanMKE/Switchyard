## Description

**Filed alongside #0149's planning pass, 2026-08-17**, to keep that issue to one deliverable.

Guide §11 decision 13 puts per-repository layout constants in `YardGit`, as `RepositoryLayout`
(#0149 introduces it). Two existing sites still carry literals:

- `YardKit/Sources/YardGit/JournalLock.swift:70` —
  `self.lockFilePath = context.commonDir + "/switchyard/" + Self.fileName`
- `YardKit/Sources/YardGit/JournalMetadataCache.swift:23` — a comment that admits it holds *"a copy of
  `ServiceNames.journalMetadataRelativePath`"*.

Neither is pinned against `ServiceNames`, so a rename on either side diverges silently. That is the
duplication decision 13 exists to remove, and it is exactly the shape of defect that survives review:
both literals are correct today.

## Expected behavior

- [ ] Both sites use `RepositoryLayout` rather than a literal `"switchyard"` / `"switchyard/..."`.
- [ ] `grep -c '"switchyard/' YardKit/Sources/YardGit/*.swift` finds no path literal outside
      `RepositoryLayout.swift` — doc comments may still say `switchyard/` in prose, so check what the
      grep actually matches rather than trusting the count.
- [ ] The `YardWireTests` pin from #0149 covers the journal cache path as well as the state directory.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **equal to** the count in
      `docs/test-baseline.txt` — this is a refactor and adds no test, so the delta is **zero** and any
      count **greater than** or less than the baseline means something else moved. Read the baseline
      file for the number rather than trusting any absolute written here.

## Notes

**Blocked by #0149**, which introduces `RepositoryLayout`.

`JournalLock` is on the journal's write path and `JournalMetadataCache` on its read path, so run the
whole journal suite rather than a filtered subset — a wrong path here does not fail loudly, it silently
locks nothing (`JournalLock.swift:47-53` explains why: a per-worktree path means two invocations take
different locks and serialise nothing).
