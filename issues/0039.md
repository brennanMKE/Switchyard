## Description

Squash staged changes (or `HEAD`) into a target commit and autosquash in one step. GitUp's flagship
operation, and the one an agent most often needs after review feedback lands on an older commit.

## Expected behavior

- [ ] Single command performs both the fixup commit and the autosquash rebase.
- [ ] Auto-checkpoints first; `yard undo` restores the pre-fixup state exactly (#0035).
- [ ] Conflicts during the rebase exit 8 with structured conflict data, leaving a resumable state.
- [ ] Signed commits stay signed after the rewrite when signing is configured.
- [ ] Refuses cleanly when the target is not an ancestor of `HEAD`.

## Planning update — 2026-08-17. Every fact below was measured on git 2.50.1 (Apple Git-155).

**Scope is the staged-index fixup.** "or `HEAD`" — taking an existing commit and squashing it into an
older one — is a second mode with a different mechanism (rewrite that commit's message to `fixup!`,
then autosquash) and is **#0214**. This issue is: stage, `git commit --fixup=<target>`, autosquash,
one checkpoint around the pair.

### Create `YardKit/Sources/YardGit/Fixup.swift`

```swift
public struct Fixup: Equatable, Sendable {
    /// Oid of `HEAD` after the autosquash rebase.
    public let head: String
    public init(head: String) { self.head = head }

    public static func run(
        target: String,
        signing: CommitCreate.Signing = .config,
        at path: String,
        git: GitProcess = GitProcess(),
        extraEnvironment: [String: String] = [:]
    ) throws -> Fixup
}

public enum FixupError: Error, Equatable, Sendable, CustomStringConvertible {
    case targetNotAncestor(target: String)
    case nothingStaged
    case blockedOnConflicts(files: [ConflictedFile])
    case signingFailed(reason: String)
}

extension FixupError: ExitClassCarrying {
    public var exitClass: ExitClass {
        switch self {
        case .targetNotAncestor, .nothingStaged: .repositoryError
        case .blockedOnConflicts: .blockedOnConflicts
        case .signingFailed: .signingFailed
        }
    }
}
```

`ConflictedFile` is already `Equatable` and `Sendable` (`Conflicts.swift:12`), so the enum synthesizes
both.

### The sequence, and the measured behaviour behind each step

1. **Refuse a non-ancestor target.** `git merge-base --is-ancestor <target> HEAD` — measured **exit 0**
   for an ancestor and **exit 1** for a non-ancestor, so use `git.capture` and read `exitCode`, never
   `run` (`GitProcess.swift:96` says exactly this about `--is-ancestor`). Non-zero → `.targetNotAncestor`.
2. **Refuse an empty index.** `git diff --cached --name-only` with no lines → `.nothingStaged`. Measured:
   `git commit --fixup=HEAD` with nothing staged prints `nothing to commit, working tree clean` and does
   **not** create a commit, so without this check the round would report success having done nothing.
   `Staging.commitHunks` reads the same command for the opposite guard (`Staging.swift:155`).
3. **Everything after this point runs inside one `JournalCheckpoint.around(operation: "fixup", at: path,
   git: git) { … }`** — one entry for the pair, which is the trap #0209 exists for and #0212 fixed for
   `commitHunks`. `around` is internal to `YardGit` and takes no `extraEnvironment`; that is fine, it
   only resolves a `WorktreeContext`.
4. **`git commit --fixup=<target>` + `CommitCreate.arguments(for: signing)`.** Measured output:

   ```
   $ git commit --fixup=ce1693d403c7ce96492df54d4ec8c6ab8c02c52f
   [main 6707e9b] fixup! c2
   $ git log --format='%H %s' -3
   6707e9bd… fixup! c2
   51fedcc… c3
   ce1693d… c2
   ```

   The subject is `fixup! <target's subject>` and the commit lands on top of `HEAD`, **not** next to the
   target. Nothing in this step needs the target's message — git reads it.
5. **`git rebase --autosquash <base>` with `git.capture`.** `<base>` is `"\(target)^"`, except when the
   target is the root commit, where `<target>^` does not resolve — measured:

   ```
   $ git rebase --autosquash dfbd3ebe…^
   fatal: invalid upstream 'dfbd3ebe2239927bf048cabffc595da14bdf45bb^'
   ```

   For a root target pass **`--root`** instead of a base; measured to autosquash correctly (a 3-commit
   repo with a `fixup!` for the root ended at 2 commits, the fixup folded into the root). Detect it with
   `git rev-parse --verify --quiet <target>^` (exit non-zero → root) via `capture`.

   **`-i` is not needed and must not be passed.** Measured: plain `git rebase --autosquash <base>` runs
   the whole autosquash non-interactively on 2.50.1 — no `GIT_SEQUENCE_EDITOR`, no editor. Do not set
   `GIT_SEQUENCE_EDITOR`; `GitProcess` already pins `GIT_EDITOR` to `false`.

   Signing flags: `.sign` → `--gpg-sign`, `.noSign` → `--no-gpg-sign`, `.config` → **no flag**. That last
   one is load-bearing and measured both ways:

   | repo config | rebase flags | signatures on the rewritten commits |
   |---|---|---|
   | `commit.gpgsign=true` | none | **kept** (`gpgsig` present on all rewritten commits) |
   | unset, originals made with `-S` | none | **dropped** (`gpgsig` count 0) |
   | unset, originals made with `-S` | `--gpg-sign` | **kept** |

   So "signed commits stay signed when signing is configured" is satisfied by `commit.gpgsign`, which is
   what "configured" means here; a repo that signs only by passing `-S` by hand is not configured to sign
   and git will not re-sign it. Do not try to detect per-commit signatures and re-sign to match.
6. **On exit 0**, `git rev-parse HEAD` → `Fixup(head:)`.
7. **On non-zero, classify by the index, not the message.** Call `conflictedFiles(at: path, git: git)`
   (`Conflicts.swift:176`):
   - **non-empty → `.blockedOnConflicts(files:)`, and leave the rebase in progress.** The criterion asks
     for a resumable state; measured, git leaves `$(git rev-parse --git-path rebase-merge)` populated and
     a `u UU` record in `git status --porcelain=v2 -z`. Do not abort.
   - **empty → `CommitCreate.classify(stderr:signingInEffect:)`** with
     `CommitCreate.signingInEffect(signing, in: path, git: git, extraEnvironment: extraEnvironment)`.
     Measured stderr from a rebase whose signing failed:

     ```
     error: gpg failed to sign the data:
     gpg: signing failed: No secret key

     error: failed to write commit object
     ```

     `failed to write commit object` is already in `CommitCreate.signingFailureMarkers`
     (`CommitCreate.swift:159`), so that classifier matches a rebase's stderr unchanged — reuse it, do not
     write a second matcher. On a match, **`git rebase --abort` first**, then throw `.signingFailed`: a
     half-finished rebase that can never sign is not resumable, and the criterion for conflicts does not
     extend to it. Convert `CommitCreate.Failure.signingFailed(reason:)` into `FixupError.signingFailed`.
   - **neither → `git rebase --abort`, then `GitProcess.Failure.exited(code:stderr:arguments:)`.**

### Tests — `YardKit/Tests/YardGitTests/FixupTests.swift`

`FixtureRepository` presets `commit.gpgsign=false` and `gc.auto=0` (`FixtureRepository.swift:104`), so a
fixture never signs unless a test opts in. **Create no signing key.** Use the fake-`gpg.program` pattern
from `CommitCreateGPGTests.swift` — that file's header states the rule and its `installFakeGpg`,
`succeedingGpgScript` and `failingGpgScript` helpers are the shapes to copy (they are `private` to that
file; duplicate them, do not make them public). Both were re-measured through `git rebase` during this
planning pass: the succeeding script yields `gpgsig` on every rewritten commit, the failing one yields
the stderr pasted above and **zero** `u` records.

At least these:

- **Happy path.** Three commits, fixup targeting the middle one, one staged file. After: `git log
  --oneline` has three entries, the target's tree contains both files, no `fixup!` subject survives.
- **Non-ancestor.** Target on a sibling branch → `.targetNotAncestor`, and `git rev-parse HEAD` is
  unchanged.
- **Nothing staged** → `.nothingStaged`, and no commit was created.
- **Conflict.** Both the target and a later commit rewrite the same line, so the fixup cannot apply —
  the fixture used while planning is: `c1` writes `f.txt` = `a`, `c2` = `b`, `c3` = `c`, then stage
  `f.txt` = `z` and fix up into `c2`. Assert `.blockedOnConflicts` with one file at `f.txt`, kind `UU`,
  **and** that the rebase is still in progress (`git rev-parse --git-path rebase-merge` exists). Clean up
  with `git rebase --abort` so the fixture destructor is not fighting a live rebase.
- **Undo.** Record `HEAD` before, run a successful fixup, then `JournalUndo` — `HEAD` and the branch tip
  return to the recorded oid. This is criterion 2 and it is the one that must not be asserted by reading
  a journal entry's existence; assert the oids.
- **Signing preserved** with the succeeding fake gpg and `commit.gpgsign=true`: every rewritten commit
  has a `gpgsig` header. Read it with `git cat-file commit <oid>`, not `%G?` — measured, `%G?` prints `N`
  for a perfectly present signature when `gpg.ssh.allowedSignersFile` is unset, so it answers a different
  question than the criterion asks.
- **Signing failure** with the failing fake gpg → `.signingFailed`, and the repo is **not** mid-rebase
  afterwards.
