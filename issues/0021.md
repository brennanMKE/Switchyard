## Description

Worktrees are the natural unit of agent isolation: one agent, one worktree, one branch, one
checkout. Git already refuses to check out a branch that another worktree holds, which is free
mutual exclusion between agents rather than an obstacle.

`--agent <id>` locks the worktree with a machine-readable reason. Lock's intended use is removable
media, but "an agent session is live here" is an equally valid reason, and it makes `prune` safe to
run at any time while making an abandoned session visible in `git worktree list --verbose`.

## Expected behavior

- [ ] Flags implemented: `--branch`, `--from`, `--detach`, `--agent <id>`, `--template <name>`, `--sparse <paths>`.
- [ ] `--agent` locks with a parseable reason that #0020 can read back.
- [ ] The branch-already-checked-out refusal is surfaced as a structured error **naming the worktree that holds it**.
- [ ] `--force` is never passed on an agent's behalf.
- [ ] `--sparse` uses `--no-checkout` first, then configures sparse checkout, then checks out.
- [ ] Sparse use enables `extensions.worktreeConfig` first — and prompts, since older git refuses repos with it.

## Notes
