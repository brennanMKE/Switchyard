## Description

**Finding 3 of the M1 milestone review, seventh pass, 2026-08-18.** `listHunks` can drop
`--no-ext-diff` and `--no-textconv` undetected.

`YardKit/Sources/YardGit/Hunks.swift:377`, mutation removing both flags: full suite green,
**1092 tests in 78 suites**.

**Both are behaviour-bearing, and the review built the fixtures rather than reasoning about them:**

| flag | what the mutant does |
|---|---|
| `--no-ext-diff` | with `diff.external` set to a no-op script, `listHunks` returns **`[]`** instead of `["f.txt"]` |
| `--no-textconv` | with a `diff.up.textconv` filter, the hunk body comes back **`-ORIG LINE 1`** instead of `-orig line 1` — the engine reports *converted* text as if it were the file's bytes |

The second is the worse one: an agent staging or reverting from those hunks would be acting on text that
is not in the file.

**The other four flags on that vector are pinned** — `--default-prefix` by
`listHunksIgnoresDiffNoprefixConfig`, `core.quotepath=false` by `listHunksHandlesANonASCIIPath`,
`--no-renames` by #0267's test. These two are the remaining gap.

**#0267 and #0283 both judged these "not worth a fixture" because they need an external diff driver.
That judgment is now disproven** — the review wrote both drivers as ordinary shell scripts in the
fixture and they work. Recording it because the same reasoning would otherwise be reached a third time.

## Expected behavior

- [ ] A named test with `diff.external` pointed at a no-op script, asserting `listHunks` still returns
      the file's diff.
- [ ] A named test with a `textconv` filter configured for an attribute, asserting the hunk body carries
      the **file's own bytes** and not the converted text.
- [ ] **Each fixture verifies its own premise**: that the configured driver actually takes effect —
      `git diff` run without the engine's flags should show the converted or suppressed output. A driver
      git silently ignores pins nothing.
- [ ] **Mutation, one per flag**, isolated: each must redden its own test and no other. Confirm each
      landed on line 377 and that the two are tested separately — the review's combined mutation proves
      the pair but not which.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, above the count in `docs/test-baseline.txt`.
