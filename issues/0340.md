## Description

**MVP work: the History pane's content.** #0339 put a real repository on screen; #0080 splits the
window into Sidebar / History / Detail with placeholders. This issue builds the view that fills the
middle one — the thing that makes the window look like a git client rather than a status list.

**Self-contained on purpose.** It adds a view and its tests and **does not touch `ContentView.swift`**,
so it can run concurrently with #0080. Wiring is three lines and lands with whichever issue is second.

## The engine entry point this renders

```swift
public static func run(
    path: String,
    rangeArguments: [String],
    options: CommitLogOptions = [],
    git: GitProcess = GitProcess()
) throws -> [CommitLogEntry]
```

in `YardKit/Sources/YardGit/CommitLog.swift:158`. `CommitLogEntry` carries `oid`, `shortOid`,
`parents`, `author`, `refs`, `signatureStatus`, `message`, `subject` and `trailers`.

## Expected behavior

- [ ] `YardKit/Sources/YardUI/CommitHistoryView.swift`, a `public struct CommitHistoryView: View`
      taking `[CommitLogEntry]` and rendering one selectable row per commit: **subject**, `shortOid`,
      author, and the refs when non-empty.
- [ ] **Selection is `@Binding var selection: String?`** keyed on `oid`, so #0082's detail pane can
      observe it without this view owning navigation.
- [ ] A loader beside #0339's, in `RepositoryLoader.swift` or its own file: `@concurrent`, calling
      `CommitLog.run(path:rangeArguments:)` with a **bounded** range — `["-100", "HEAD"]` — because an
      unbounded log on a large repository is the first thing that will make this window feel broken.
      Say in a comment that the bound is a placeholder for paging, not a decision.
- [ ] **The engine call must not run on the main actor**, for the reason #0339's loader documents:
      `YardUI` sets `.defaultIsolation(MainActor.self)` and `CommitLog.run` shells out to `git`
      synchronously.
- [ ] Tests in `YardKit/Tests/YardUITests/`: the loader returns real commits for a `FixtureRepository`
      with **at least three commits**, asserting the **subjects in order**, newest first. Assert
      values, not counts — a test that only checks `count == 3` passes when the order reverses.
- [ ] `cd YardKit && swift test` twice, foreground, 900000 ms timeout, both green, above
      `docs/test-baseline.txt`.

## The files

`YardKit/Sources/YardUI/CommitHistoryView.swift` (new), `YardKit/Sources/YardUI/RepositoryLoader.swift`
(or a new loader file), and `YardKit/Tests/YardUITests/`.

**Do not edit `ContentView.swift`** — that is #0080's file this round, and two rounds editing it is a
conflict for no benefit.

## Notes

**Milestone M3.** Sibling of #0080; #0052 (the graph with its lane rendering) is the richer version of
this pane and is **not** this issue — a flat list ships now, lanes come later.

**No actions.** Selecting a commit changes a binding and nothing else. Checkout, revert, cherry-pick and

appear.
