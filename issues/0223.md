## Description

Guide §11 decision 15 settles that **engine-backed command arms cannot live in `YardKit`**, which the
CLI links, and must not live in the app target, where `swift test` cannot reach them. They go in a new
package target that depends on both `YardGit` and `YardKit` and is linked by the **app alone**.

This issue creates that target and moves nothing into it yet. #0124 — `switchyard whereami` — is the
first arm and is where the first real command lands.

Filed separately because it is a **manifest and project change**, which is a different kind of work
from writing a command, and because a round that does both tends to finish neither. Structural work
converges when it is transcription: both edits are pasted below.

## The `Package.swift` edit, verbatim

Insert this target after the `YardUI` target and before `.executableTarget(name: "switchyard", …)`:

```swift
        // Engine-backed command arms. Depends on BOTH the engine and the
        // envelope layer, and is linked by the app alone — guide §11 decision
        // 15. It exists so a command that opens a repository can be reached
        // from `swift test`: it cannot live in YardKit, which the CLI links,
        // and code in the app target has no test that can run here.
        .target(
            name: "YardCommands",
            dependencies: ["YardGit", "YardKit"],
            path: "Sources/YardCommands"
        ),
```

and this test target after `YardKitTests`:

```swift
        .testTarget(
            name: "YardCommandsTests",
            dependencies: ["YardCommands"],
            path: "Tests/YardCommandsTests"
        ),
```

and this product, after the `YardUI` library in the `products:` list:

```swift
        // Linked by the app; deliberately NOT a dependency of `switchyard`.
        .library(name: "YardCommands", targets: ["YardCommands"]),
```

**Do not add `YardCommands` to the `switchyard` executable target's dependencies.** That is the whole
point of the target existing, and `LayeringTests` asserts the CLI does not reach `YardGit`.

## The `Switchyard.xcodeproj/project.pbxproj` edit

The app target already carries `YardGit` and `YardKit` product dependencies from the same **local**
package, so this is one more of the same shape. Invent a 24-hex id that does not appear in the file
(check with `grep -c`), then:

**1.** In the `XCSwiftPackageProductDependency` section, beside the existing entries:

```
		CCCCCCCCCCCCCCCCCCCCCCCC /* YardCommands */ = {
			isa = XCSwiftPackageProductDependency;
			productName = YardCommands;
		};
```

No `package = …` line — the local-package entries omit it, and `YardKit` is a local package
reference (`XCLocalSwiftPackageReference "YardKit"`, `relativePath = YardKit`).

**2.** Add `CCCCCCCCCCCCCCCCCCCCCCCC /* YardCommands */,` to the **`Switchyard` app target's**
`packageProductDependencies`, which today lists `YardGit` and `YardKit`. No other target.

## What goes in the target

One file, and it is a seam rather than a feature:

**`YardKit/Sources/YardCommands/EngineCommands.swift`** — the entry point the app will call and #0124
will extend:

```swift
/// Runs a command that needs the engine, returning the rendered envelope and
/// the exit code — the same pair `runYard` returns, so the app can try this
/// first and fall back to `runYard` for the commands that need no repository.
public func runEngineCommand(
    arguments: [String],
    workingDirectory: String
) -> (stdout: String, stderr: String, exitCode: ExitCode)?
```

Returning `nil` for "not one of mine" is what lets the app compose the two without either side
enumerating the other's commands. **In this issue it returns `nil` for every input** — there are no
engine arms yet — and that is the honest shape, not a stub with a `fatalError`.

## Expected behavior

- [ ] `swift build` succeeds with the new target present.
- [ ] `cd YardKit && swift test` prints `Test run with N tests` where **N is greater than 995**, the
      count on `main` at 2026-08-17. The new test target must contain at least one real test —
      `runEngineCommand` returns `nil` for `noop` and for an unknown command, which is the contract
      #0124 depends on.
- [ ] `xcodebuild build … CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO` prints
      `** BUILD SUCCEEDED **`, and `import YardCommands` compiles inside an app-target file. Prove it
      by adding the import to one app file, building, then removing it and building again — a product
      dependency that resolves but is not linked compiles the same as one that is.
- [ ] `LayeringTests` still passes unchanged: `YardKit` does not import `YardGit`, and the CLI target
      does not depend on `YardCommands`. Say which assertions you checked.
- [ ] `otool -L` on the built `switchyard` binary is unchanged.
