## Description

Brennan, 2026-10-05: *"We need more test automations … use git commands to set up the git
workspace with the main branch and multiple other branches to test merges and rebases … Make sure
the UI test automation is comprehensive."*

Every Commit-menu operation has engine tests in YardGit, and none had a VM spike. The only
history spike was #0430 (merged-lane dimming). Nothing drove **the app's** path — Commit menu →
`CommitActionRequest` → `performCommitAction` → journal checkpoint → refresh — and then read what
git actually holds. A merge commit "with no file change" is exactly what only that path can show.

This umbrella adds that suite. Each spike:

1. launches on its **own copy** of one fixture repository built with git commands;
2. selects a History row and chooses the action from the menu bar's **Commit** menu (the same
   `CommitActionMenuItems` the row context menu renders);
3. reads git from the test runner (`GitRepo`, `/usr/bin/git` via `Process`) — refs, parents,
   `ls-tree`, file contents, the working tree, `status --porcelain`;
4. chooses **Edit ▸ Undo <operation>** and asserts `GitStateSnapshot` (every branch and tag, HEAD,
   HEAD's tree, porcelain status) equals the pre-state.

## Rule this umbrella installs

`docs/review-failures.md` preflight checklist and `AGENTS.md` Rule 13b: **a Commit-menu action
ships with a VM spike that asserts git state** (and Undo restores the snapshot).
