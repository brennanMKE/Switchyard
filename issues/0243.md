# 0243 — Payload schema optional flags are unbound to the type

## Description

**Found reviewing #0194, 2026-08-17.** The payload schema's **`optional` flags are not bound to the
type's actual behaviour**, only to the checked-in file.

#0194's binding test pins **field names**: it encodes a fully-populated value and asserts the schema's
field names are exactly the encoded keys. That is real and it catches renames in both directions. But
it says nothing about which fields may be **absent**, and absence is the part an agent gets wrong at
parse time.

Measured: flipping `optional: true` → `false` on `whereami`'s `branch` field reddens only
`SchemaGoldenTests`' `checkedInSchemasMatchEmitter` — the file no longer matches the emitter. Regenerate
the file alongside the change and the suite is green with a schema that now claims `branch` is always
present. Nothing compares the flag to what `WhereAmI` actually encodes.

This matters because of the convention it is describing: **absent means absent**, not `null`. An agent
told a field is required, which is then simply missing, fails in a way the schema was supposed to
prevent.

## Expected behavior

- [ ] A second binding test, alongside #0194's: encode a **minimally**-populated value — every optional
      nil — and assert the keys that are **absent** are exactly the fields the schema marks `optional`.
      Together with #0194's fully-populated test that pins both halves of the contract.
- [ ] Mutations, each run and reported: flip one `optional: true` to `false` **and** regenerate the
      golden file, confirming the new test reddens where the golden gate no longer does; then the
      reverse — mark a required field optional — and confirm it reddens too.
- [ ] The helper is written so the next command's shape gets the same check for free. #0115's
      per-command pattern already requires a payload shape; say whether this check belongs in that
      pattern's step list, and add it if so.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.
