# 0048 — Implement the yard XPC client with launch, poll, and exit codes

## Description

The CLI side: connect to the broker by Mach service name, request the app's endpoint, launch the app
by bundle identifier if the endpoint is nil, poll until registration completes (app registration
races app launch), then open a direct connection.

**Degradation must be explicit.** An interactive command with no app running fails with exit 3 and a
message naming what is missing. It never silently falls back to a non-interactive path, because an
agent would then proceed without the human approval it was told to obtain.

## Expected behavior

- [ ] The bounded poll loop is bounded — a broken app cannot hang the CLI forever.
- [ ] A nil endpoint immediately after launch is treated as normal, not as failure.
- [ ] Exit codes 2 (broker unreachable), 3 (app unavailable), 4 (request failed), 5 (session terminated) all reachable and correct.
- [ ] `--no-launch` fails instead of launching the app.
- [ ] `--require-app` fails fast when the app is not available.
- [ ] Cold-start latency measured and recorded.
