## Description

**Blocks #0360**

The engine half of #0360, split out on 2026-09-12 (Brennan: engine issues go in M8). #0360 is now
UI-only. Related: **#0376** (`WhereAmI.isMidRevert`) — until it lands, a conflicted revert is
invisible to the header. Conflict continue and abort from the app is #0394.

**One wrapper, one issue.** `git revert` and `git cherry-pick` are the same sequencer porcelain. They
take the same flags (`--[no-]edit`, `-S`/`--[no-]gpg-sign`, `--abort`, `--continue`; *measured*
with `-h`, git 2.50.1), refuse a merge with the same error, and differ only in verb and state file
(`REVERT_HEAD` / `CHERRY_PICK_HEAD`). So this is one type with two entry points — the shape
`Rewrite` already uses for `reword` / `drop` / `reorder`.

**No CLI verb here.** Guide §6 names neither `revert` nor `cherry-pick`, so the verbs are left for a
later issue once §6 names them.

### Measured refusals and outcomes

git 2.50.1, 2026-09-12, scratch repositories with `GIT_EDITOR=false` and no global config. Every row
was run.

| Situation | git's behaviour | This wrapper |
|---|---|---|
| revert a merge commit | exit 128 `error: commit <oid> is a merge but no -m option was given.` / `fatal: revert failed`; nothing changed | `.mergeRefused(commit:)`, before mutation |
| cherry-pick a merge commit | exit 128, the same error with `fatal: cherry-pick failed` | `.mergeRefused(commit:)`, before mutation |
| cherry-pick a commit already reachable from `HEAD` (`main~1`) | exit 1 `The previous cherry-pick is now empty…` **and `CHERRY_PICK_HEAD` is left behind** | `.alreadyOnBranch(commit:)`, before mutation: `merge-base --is-ancestor <oid> HEAD` exits 0 |
| cherry-pick a commit whose change is already on the branch but which is not an ancestor | exit 1 "now empty", `CHERRY_PICK_HEAD` left, clean status; `git cherry-pick --abort` exits 0 and clears it | after the pick: non-zero exit, no conflicted files, state file present → abort → `.emptyResult(commit:)` |
| unknown revision | exit 128 `fatal: bad revision 'nosuch'` (both verbs) | `.unknownCommit(_:)`, before mutation (`rev-parse --verify <rev>^{commit}`) |
| a local change the pick would overwrite (a staged new file the commit adds) | exit 128 `error: your local changes would be overwritten by cherry-pick.`; nothing changed | git's own refusal: rethrow `GitProcess.Failure` unchanged, after `--abort` as a no-op safety |
| an unrelated uncommitted edit | exit 0; the pick succeeds and the edit is kept | success |
| revert that conflicts | exit 1, `REVERT_HEAD` present, `UU f`, **no** `sequencer` directory; `git revert --abort` exits 0 and restores | `.blockedOnConflicts(files:)`, state left for resumption |
| clean revert | exit 0, subject `Revert "s1"` | `Result(head:)` |

A single cherry-pick conflict was measured by #0060: exit 1, `CHERRY_PICK_HEAD`, and a clean
`--abort`.

### Surface — `YardKit/Sources/YardGit/Pick.swift` (new, *not compiled*)

```swift
public enum Pick {
    public struct Result: Sendable, Equatable, Encodable {
        /// The full oid of the new commit `HEAD` now names.
        public let head: String
    }

    public static func revert(
        commit: String,
        signing: CommitCreate.Signing = .config,
        at path: String,
        git: GitProcess = GitProcess(),
        extraEnvironment: [String: String] = [:]
    ) throws -> Result

    public static func cherryPick(
        commit: String,
        signing: CommitCreate.Signing = .config,
        at path: String,
        git: GitProcess = GitProcess(),
        extraEnvironment: [String: String] = [:]
    ) throws -> Result
}

public enum PickError: Error, Equatable, Sendable, CustomStringConvertible {
    case unknownCommit(String)
    case mergeRefused(commit: String)
    case alreadyOnBranch(commit: String)
    case emptyResult(commit: String)
    case blockedOnConflicts(files: [ConflictedFile])
    case signingFailed(reason: String)
}
```

`PickError: ExitClassCarrying`: `.blockedOnConflicts` → `.blockedOnConflicts`, `.signingFailed` →
`.signingFailed`, everything else → `.repositoryError` — the `RewriteError` mapping.

### Sequence

Everything cited was verified against `YardKit/Sources/YardGit/Rewrite.swift` at `1b00f27`.

1. **Resolve** the commit with `rev-parse --verify <commit>^{commit}` → `.unknownCommit`.
2. **Refuse an unmerged index**: `conflictedFiles(at:git:)` non-empty → `.blockedOnConflicts`. This
   mirrors `Rewrite.refuseUnmergedIndex`.
3. **Parents** via `rev-list --parents -n 1 <oid>` (as `Rewrite.parentOids`); more than one →
   `.mergeRefused`.
4. **Cherry-pick only**: `git.capture(["merge-base", "--is-ancestor", oid, "HEAD"], …)` exit 0 →
   `.alreadyOnBranch`. Revert applies to any non-merge commit, as git does.
5. **Inside** `JournalCheckpoint.around(operation: "revert" | "cherry-pick", at: path, git: git) { scoped in … }`,
   run `git revert --no-edit <signing> <oid>` or `git cherry-pick <signing> <oid>` through `scoped.capture`.
   - `<signing>` is `CommitCreate.arguments(for: signing)` — internal, in the same module.
   - The timeout is `CommitCreate.signingInEffect(signing, in: path, git: git, extraEnvironment: extraEnvironment) ? GitProcess.signingTimeout : nil`,
     exactly as `Rewrite.perform` does.
6. **Exit 0** → `Result(head: rev-parse HEAD)`.
7. **Non-zero** — classify as `Rewrite.classifiedPickFailure(output:arguments:signing:at:git:extraEnvironment:)`
   does:
   - conflicts → `.blockedOnConflicts`, leaving the state;
   - a signing failure (`CommitCreate.classify(stderr:signingInEffect:)`) → `--abort`, then `.signingFailed`;
   - a state file present (via `rev-parse --git-path REVERT_HEAD|CHERRY_PICK_HEAD`) with no conflicts
     → `--abort`, then `.emptyResult`;
   - anything else → `--abort`, then `GitProcess.Failure`.

   `classifiedPickFailure` and `isSigningFailure(_:)` live in a `private extension Rewrite`. Promote
   them to internal and parameterise the abort verb, rather than duplicating the classifier.

**The journal.** A refusal in steps 1–4 writes no entry. The checkpoint is not rolled back when the
body throws (`JournalCheckpoint.around`'s documented contract), so a git-side failure leaves one
pre-operation entry. That is harmless, and it is what `undo` uses.

**Unverified — the fixture test decides.** Guide §11 decision 14 says a restore clears a sequencer
the target never captured. A conflicted *single* revert leaves `REVERT_HEAD` with no `sequencer`
directory. Whether `JournalUndo.undo` also clears `REVERT_HEAD` / `CHERRY_PICK_HEAD` is not measured.
If it does not, file it as a finding.

## Expected behavior

- [ ] `Pick.revert` and `Pick.cherryPick` each make one new commit on the current branch inside one
      journal checkpoint, and `JournalUndo.undo` restores the pre-state (fixture test).
- [ ] Every typed refusal in the table is raised before mutation with no journal entry written; the
      empty-result case aborts and leaves no `CHERRY_PICK_HEAD`.
- [ ] A conflict throws `.blockedOnConflicts` with git's state left for resumption, and a signing
      failure aborts and throws `.signingFailed`. Tests live in
      `YardKit/Tests/YardGitTests/PickTests.swift`, and `swift test` prints `Test run with N tests`.
