## Description

#0091 routed the human-readable `[error] <code>: <message>` line to real stderr, so that stdout could
carry JSON and nothing else. #0092 then moved all I/O out of the entry point into a pure
`runYard(arguments:)` that returns a string and an exit code — and in doing so stopped calling
`EnvelopeFail.write()`, which is what emitted that line.

The result: running `yard bogus-command` writes **0 bytes to stderr**. Verified directly. The JSON
contract is intact and the exit code is right, but a human running `yard` by hand now gets a wall of
JSON and no plain-language error.

This is not a defect in either issue's implementation — both did exactly what they specified. It is
the seam between them, and it was found by capturing stderr during #0092's review rather than by
either issue's own criteria.

## Givens — verified on `main`, treat as true

1. `yard bogus-command` currently emits a valid failure envelope on stdout, exit 1, and nothing on
   stderr.
2. `EnvelopeFail.write()` in `YardKit/Sources/YardKit/Envelope.swift` still writes the human line to
   `FileHandle.standardError` and the JSON to stdout. It is correct and has no caller in the binary.
3. `runYard(arguments:) -> (stdout: String, exitCode: ExitCode)` in
   `YardKit/Sources/YardKit/CommandLineRunner.swift` performs no I/O deliberately — that is what
   makes it unit-testable, and it must stay that way.
4. **#0104 has since removed `import YardGit` from that file**, and the version string is now the
   CLI's own — `"switchyard 0.0.1"`, with no libgit2 component. Do not reintroduce either; the CLI
   does not link the engine.
5. `main` is at 134 tests.

## Expected behavior

- [ ] `yard <unrecognised>` writes the JSON envelope to stdout **and** the `[error] <code>: <message>`
      line to stderr, using the wire string (`error.code.rawValue`), not the Swift case name.
- [ ] `runYard` still performs no I/O. Return the stderr text alongside the rest — e.g. widen the
      tuple to `(stdout: String, stderr: String, exitCode: ExitCode)` — and let `main.swift` do both
      writes. Do not reintroduce `FileHandle` into `runYard`.
- [ ] Success paths write nothing to stderr.
- [ ] stdout remains JSON and nothing else on every path — this is the contract #0091 established and
      it must not regress.
- [ ] A test asserts the returned stderr text is empty for a success case and contains the code and
      message for a failure case.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you
      paste. **N must be greater than 134**, the count on `main` before this change.

## Notes

While here: `CommandLineRunner.swift` has two private helpers, `jsonString<T: Encodable>` and
`jsonEncode(_: EnvelopeFail)`, where the generic one subsumes the other. Collapsing them is in scope.

If `Envelope.write()` still has no caller after this, delete it — it was added to mirror
`EnvelopeFail.write()` and specified-but-dead code is worse than no code.
