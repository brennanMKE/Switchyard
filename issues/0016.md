## Description

Stable hunk ids are what make precise agent-driven staging possible. `git add -p` is interactive and
therefore unusable by an agent, which is why agents today either stage whole files or generate
patches by hand and get them wrong.

The id has to survive the round trip that matters: list hunks, decide, stage a subset by id. So it
is derived from the hunk's *content* — the body lines git prints — and never from its position: the
measurement in Given 2 shows that staging one hunk shifts the `@@` line numbers of every later hunk
in the same file while leaving their body bytes untouched. Hash the body, exclude the header, and
ids survive staging; any edit to the hunk's own lines produces a new id, which is what makes a stale
id *detectable* — it no longer appears in a fresh listing.

**One deliverable:** the listing engine — `listHunks(at:area:git:)`, its result types `FileDiff` and
`Hunk`, and the pure parser `HunkParser` in `YardKit/Sources/YardGit/Hunks.swift`, with tests in
`YardKit/Tests/YardGitTests/HunksTests.swift`. **Both files are written out below in full and were
compiled, run, and mutation-tested on 2026-08-07 — type them in as given.** The round's work is
transcription plus running the verification.

**Staging by id is NOT in this issue.** It is #0040 ("stage and unstage by hunk ID"), and the
earlier draft's criterion "staging a stale hunk id must produce a clear error" belongs there — a
listing function has no id argument to reject. What this issue must deliver toward that error is the
detectability above, pinned by the test `editInsideAHunkChangesItsId`. This issue is also **engine
only**: no `CommandSpec`, no `runYard` arm, no CLI wiring — see Notes.

### 1. The data source, and the flags that pin it against user config

Unstaged hunks are `git diff` (index vs worktree); staged hunks are `git diff --cached` (HEAD vs
index — measured to work on an unborn branch too: exit 0, diffing the index against the empty
tree). Every listing runs with:

```
git -c core.quotepath=false diff [--cached] --no-color --no-ext-diff --no-textconv \
    --no-renames --default-prefix --unified=3
```

Each flag closes a measured hole: `--no-ext-diff`/`--no-textconv` stop diff drivers replacing or
fabricating patch text; `--no-renames` guarantees the two sides of `diff --git a/P b/P` are the
same path (which is what makes that line parseable when P contains spaces); `--unified=3` pins
against `diff.context`; and `--default-prefix` restores `a/`/`b/` even when the user sets
`diff.noprefix` — measured:

```
$ git -c diff.noprefix=true diff …            → diff --git one.txt one.txt
$ git -c diff.noprefix=true diff --default-prefix …  → diff --git a/one.txt b/one.txt
```

### 2. The stability measurement the id design falls out of

A 20-line file (`line 01` … `line 20`), committed, then edited twice: a line inserted after
`line 03`, and `line 17` replaced. `git diff` emits exactly:

```
diff --git a/f.txt b/f.txt
index 036b411..0aea296 100644
--- a/f.txt
+++ b/f.txt
@@ -1,6 +1,7 @@
 line 01
 line 02
 line 03
+inserted after 03
 line 04
 line 05
 line 06
@@ -14,7 +15,7 @@ line 13
 line 14
 line 15
 line 16
-line 17
+line 17 CHANGED
 line 18
 line 19
 line 20
```

Staging **only the first hunk** (file header + first hunk piped to `git apply --cached`), the
remaining unstaged diff is:

```
diff --git a/f.txt b/f.txt
index 8c8a9f3..0aea296 100644
--- a/f.txt
+++ b/f.txt
@@ -15,7 +15,7 @@ line 13
 line 14
 line 15
 line 16
-line 17
+line 17 CHANGED
 line 18
 line 19
 line 20
```

and `git diff --cached` shows the first hunk under its original header, body byte-identical.

Three facts to hold on to:

- **The surviving hunk's body is byte-identical; only `@@ -14,7` became `@@ -15,7`.** So the id is
  SHA-256 over the file path plus the body lines, `@@` header excluded, truncated to 12 hex chars.
  The header's exclusion also drops the `@@ … @@ line 13` function-context trailer, which is
  derived from old-side content *above* the hunk and can change when an earlier hunk is staged.
- **Staging the second hunk is the weak direction** — it shifts nothing before it, so a test that
  stages the *second* hunk (as this issue's earlier draft asked) passes even with a
  position-derived id. The test below stages the **first** and asserts the second's id survived
  its own header moving.
- **The id follows the change across areas**: after staging, the staged listing reports that hunk
  under the id it had while unstaged, because path and body are unchanged.

The pinned hash vector, measured with `printf 'f.txt\0-x\n+y' | shasum -a 256` →
`b88468cda3e31995…`; the id (first 12) is `b88468cda3e3`. The test asserts this literal.

### 3. Hunk separation distance

At `--unified=3`, edits **6 or fewer lines apart merge into one hunk** (their context runs touch).
Measured: edits at lines 10 and 16 of the 20-line file produced *one* hunk spanning both. The
two-hunk fixture's edits (after line 03, at line 17) are far enough apart; keep them that way.

### 4. Binary, mode-only, new, and deleted files — the hunkless shapes

All measured verbatim. A modified binary file (no `---`/`+++`, no hunks):

```
diff --git a/bin.dat b/bin.dat
index d7cd33e..84554ac 100644
Binary files a/bin.dat and b/bin.dat differ
```

(a *staged new* binary prints `Binary files /dev/null and b/newbin.dat differ`). A true mode-only
change is **three lines** — no `index`, no `---`/`+++` — so its path can only come from the
`diff --git` line:

```
diff --git a/one.txt b/one.txt
old mode 100644
new mode 100755
```

A staged new file and a staged deletion (note omitted counts: `+1` and `-1` mean count 1):

```
diff --git a/added.txt b/added.txt
new file mode 100644
index 0000000..d5a09df
--- /dev/null
+++ b/added.txt
@@ -0,0 +1 @@
+brand new
```

```
diff --git a/one.txt b/one.txt
deleted file mode 100644
index 587be6b..0000000
--- a/one.txt
+++ /dev/null
@@ -1 +0,0 @@
-x
```

### 5. Path quirks, all three measured

- **A path containing a space gets a trailing TAB** on the `--- a/…` and `+++ b/…` lines
  (`--- a/my file.txt<TAB>`). The parser strips one trailing tab.
- **`-c core.quotepath=false` un-quotes non-ASCII paths** (`a/pä.txt` raw; without it git prints
  `"a/p\303\244.txt"`). Paths containing a double quote or control character stay C-quoted even
  with the flag (`"a/we\"ird.txt"`, `"a/ta\tb.txt"`) — the parser **throws**
  `Failure.quotedPath` for those rather than mis-parsing; silently wrong paths are the bug class
  this project does not ship.
- With `--no-renames` the `diff --git a/P b/P` sides are always equal, so P's length is
  `(remainder − 3) / 2` and the split is unambiguous even with spaces; the code verifies the two
  halves match and throws `Failure.malformedFileHeader` otherwise.

### 6. Body membership is decided by the header's counts, not by line prefixes

An added line reading `++ x` prints in the body as `+++ x` — prefix dispatch would take it for a
file header. The hunk header's old/new counts say exactly how many body lines follow (` ` counts
on both sides, `-` old, `+` new); the parser consumes precisely that many, plus any
`\ No newline at end of file` marker lines (`\` counts on neither side). A file whose last line
has no newline produces that marker after **each** side, measured:

```
@@ -1 +1 @@
-only line
\ No newline at end of file
+only line CHANGED
\ No newline at end of file
```

### 7. The patch text round-trips through `git apply --cached`

`git apply --cached` with no file argument reads the patch from stdin. `FileDiff.headerText`
followed by `Hunk.patchText` applies cleanly — verified: after applying the no-newline hunk above,
the unstaged diff is empty, i.e. the reconstruction is byte-faithful including the `\` lines.
This concatenation is exactly what #0040's stage-by-id will feed git.

### 8. Two swift-testing macro facts the tests already encode — do not "fix" them backward

- `#expect(try f() == x)` does **not** compile when `f` throws (`call can throw, but it is not
  marked with 'try'` inside the macro expansion); hoist the call:
  `let y = try f(); #expect(y == x)`. The tests below already do.
- `#expect(s.allSatisfy(\.isHexDigit))` hits the same macro error; use a closure:
  `s.allSatisfy { $0.isHexDigit }`. Already done below.

## The deliverable — `YardKit/Sources/YardGit/Hunks.swift`, in full

```swift
// Hunks.swift — per-file diffs split into hunks with stable, content-derived ids (#0016)

import CryptoKit
import Foundation

/// Which diff a hunk listing describes.
public enum DiffArea: String, Sendable, CaseIterable {
    /// Index vs worktree — `git diff`.
    case unstaged
    /// HEAD vs index — `git diff --cached`. Works on an unborn branch too;
    /// git diffs the index against the empty tree and exits 0.
    case staged
}

/// One hunk of one file's diff, with a stable content-derived id.
///
/// The id is the first 12 hex characters of SHA-256 over the file path and
/// the hunk's body lines — the `@@` header line is deliberately excluded,
/// because its line numbers shift when an earlier hunk in the same file is
/// staged while the change itself is untouched. Staging a hunk therefore
/// leaves every other hunk's id unchanged, and the staged listing reports
/// the just-staged hunk under the id it had while unstaged. Any edit to the
/// hunk's own lines (including its context lines) produces a different id,
/// which is what makes a stale id detectable: it no longer appears in a
/// fresh listing, and a future stage-by-id must refuse it rather than guess.
public struct Hunk: Sendable, Equatable {

    /// Stable id: 12 lowercase hex characters, plus `-N` (N ≥ 2) when the
    /// same file contains N hunks with identical bodies.
    public let id: String

    /// Path relative to the repository root, as the file's diff reports it.
    public let path: String

    /// Old-side start line from the `@@` header. 0 for a newly added file.
    public let oldStart: Int
    /// Old-side line count. An omitted count in the header means 1.
    public let oldCount: Int
    /// New-side start line from the `@@` header.
    public let newStart: Int
    /// New-side line count. An omitted count in the header means 1.
    public let newCount: Int

    /// The full `@@ -a,b +c,d @@ …` line, exactly as git printed it.
    public let header: String

    /// Body lines, each with its leading marker — ` `, `-`, `+`, or `\`
    /// (the `\ No newline at end of file` marker), exactly as git printed
    /// them.
    public let body: [String]

    public init(id: String, path: String,
                oldStart: Int, oldCount: Int, newStart: Int, newCount: Int,
                header: String, body: [String]) {
        self.id = id
        self.path = path
        self.oldStart = oldStart
        self.oldCount = oldCount
        self.newStart = newStart
        self.newCount = newCount
        self.header = header
        self.body = body
    }

    /// The hunk as patch text: the header line, the body lines, and a
    /// trailing newline. Prepending the owning `FileDiff.headerText` yields
    /// input `git apply --cached` accepts byte-for-byte.
    public var patchText: String {
        ([header] + body).joined(separator: "\n") + "\n"
    }
}

/// One file's part of a diff: its hunks, or the binary / mode-only facts
/// when there are none. Binary changes and mode-only changes are represented
/// with an empty `hunks` array, never silently dropped.
public struct FileDiff: Sendable, Equatable {

    /// Path relative to the repository root. Taken from the `+++ b/…` line
    /// (or `--- a/…` for a deletion); for binary and mode-only files, which
    /// have neither, derived from the `diff --git a/P b/P` line.
    public let path: String

    /// From an `old mode` or `deleted file mode` header line. Nil when the
    /// mode did not change and the file was not deleted.
    public let oldMode: String?

    /// From a `new mode` or `new file mode` header line. Nil when the mode
    /// did not change and the file is not new.
    public let newMode: String?

    /// True when git printed `Binary files … differ` (or a binary patch)
    /// instead of hunks.
    public let isBinary: Bool

    /// The raw header lines — `diff --git` through the last line before the
    /// first `@@` — joined with newlines, trailing newline included.
    public let headerText: String

    /// Empty for binary and mode-only changes.
    public let hunks: [Hunk]

    public init(path: String, oldMode: String?, newMode: String?,
                isBinary: Bool, headerText: String, hunks: [Hunk]) {
        self.path = path
        self.oldMode = oldMode
        self.newMode = newMode
        self.isBinary = isBinary
        self.headerText = headerText
        self.hunks = hunks
    }
}

/// Parses `git diff` patch output into per-file hunks.
///
/// Pure function on text — no `Process` construction, no filesystem access.
/// Expects the flags `listHunks(at:area:git:)` passes: no color, no external
/// diff, no rename detection (so the two sides of `diff --git` are always
/// the same path), default `a/`/`b/` prefixes, and `core.quotepath=false`.
public struct HunkParser {

    public enum Failure: Error, Equatable, CustomStringConvertible {
        /// A path git C-quoted despite `core.quotepath=false` — it contains
        /// a double quote or a control character. Refused explicitly rather
        /// than mis-parsed.
        case quotedPath(String)
        /// A `diff --git a/P b/P` line whose two sides do not match.
        case malformedFileHeader(String)
        /// An `@@` line that does not parse as `@@ -a[,b] +c[,d] @@ …`.
        case malformedHunkHeader(String)

        public var description: String {
            switch self {
            case let .quotedPath(line):
                "unsupported quoted path in diff header: \(line)"
            case let .malformedFileHeader(line):
                "malformed diff file header: \(line)"
            case let .malformedHunkHeader(line):
                "malformed hunk header: \(line)"
            }
        }
    }

    public init() {}

    public func parse(_ text: String) throws -> [FileDiff] {
        var files: [FileDiff] = []
        var file: FileBuilder?
        var hunk: HunkBuilder?

        func closeHunk() {
            if let done = hunk { file?.hunks.append(done) }
            hunk = nil
        }
        func closeFile() {
            closeHunk()
            if let done = file { files.append(done.build()) }
            file = nil
        }

        for lineSub in text.split(separator: "\n", omittingEmptySubsequences: false) {
            let line = String(lineSub)

            if line.hasPrefix("diff --git ") {
                closeFile()
                file = FileBuilder(path: try Self.pathFromDiffGitLine(line),
                                   headerLines: [line])
                continue
            }
            guard file != nil else { continue }  // preamble; git emits none

            if let open = hunk {
                if open.wantsMoreBody(marker: line.first) {
                    hunk?.body.append(line)
                    continue
                }
                closeHunk()
            }

            if line.hasPrefix("@@ ") {
                hunk = try HunkBuilder(header: line)
            } else if line.hasPrefix("old mode ") {
                file?.oldMode = String(line.dropFirst("old mode ".count))
                file?.headerLines.append(line)
            } else if line.hasPrefix("new mode ") {
                file?.newMode = String(line.dropFirst("new mode ".count))
                file?.headerLines.append(line)
            } else if line.hasPrefix("deleted file mode ") {
                file?.oldMode = String(line.dropFirst("deleted file mode ".count))
                file?.headerLines.append(line)
            } else if line.hasPrefix("new file mode ") {
                file?.newMode = String(line.dropFirst("new file mode ".count))
                file?.headerLines.append(line)
            } else if line.hasPrefix("Binary files ") || line.hasPrefix("GIT binary patch") {
                file?.isBinary = true
                file?.headerLines.append(line)
            } else if line.hasPrefix("--- ") {
                if let path = try Self.path(fromMarkerLine: line, prefix: "--- a/") {
                    file?.path = path
                }
                file?.headerLines.append(line)
            } else if line.hasPrefix("+++ ") {
                if let path = try Self.path(fromMarkerLine: line, prefix: "+++ b/") {
                    file?.path = path
                }
                file?.headerLines.append(line)
            } else if !line.isEmpty {
                // index lines, similarity scores, and anything else git adds.
                file?.headerLines.append(line)
            }
        }
        closeFile()
        return files
    }

    // MARK: - Ids

    /// First 12 hex characters of SHA-256 over the path and the body lines.
    /// The `@@` header is excluded on purpose — see `Hunk.id`.
    static func hunkID(path: String, body: [String]) -> String {
        var hasher = SHA256()
        hasher.update(data: Data(path.utf8))
        hasher.update(data: Data([0]))
        hasher.update(data: Data(body.joined(separator: "\n").utf8))
        let digest = hasher.finalize()
        return digest.map { String(format: "%02x", $0) }.joined().prefix(12)
            .lowercased()
    }

    // MARK: - Header parsing

    /// Path from `diff --git a/P b/P`. Rename detection is off, so the two
    /// sides are always the same path and its length is unambiguous even
    /// when it contains spaces: strip `diff --git a/`, and the path is the
    /// first half of the remainder around ` b/`.
    static func pathFromDiffGitLine(_ line: String) throws -> String {
        let rest = String(line.dropFirst("diff --git ".count))
        if rest.hasPrefix("\"") { throw Failure.quotedPath(line) }
        guard rest.hasPrefix("a/") else { throw Failure.malformedFileHeader(line) }
        let both = String(rest.dropFirst(2))          // "P b/P"
        // both.count = P.count + " b/".count + P.count
        let pathCount = (both.count - 3) / 2
        guard pathCount > 0, (both.count - 3) % 2 == 0 else {
            throw Failure.malformedFileHeader(line)
        }
        let path = String(both.prefix(pathCount))
        guard both == path + " b/" + path else {
            throw Failure.malformedFileHeader(line)
        }
        return path
    }

    /// Path from a `--- a/P` or `+++ b/P` line, nil for `/dev/null`. Git
    /// appends a tab after a path that contains a space; strip it.
    static func path(fromMarkerLine line: String, prefix: String) throws -> String? {
        let body = String(line.dropFirst(4))
        if body == "/dev/null" { return nil }
        if body.hasPrefix("\"") { throw Failure.quotedPath(line) }
        guard line.hasPrefix(prefix) else { throw Failure.malformedFileHeader(line) }
        var path = String(line.dropFirst(prefix.count))
        if path.hasSuffix("\t") { path.removeLast() }
        return path
    }

    // MARK: - Builders

    struct FileBuilder {
        var path: String
        var headerLines: [String]
        var oldMode: String?
        var newMode: String?
        var isBinary = false
        var hunks: [HunkBuilder] = []

        func build() -> FileDiff {
            var seen: [String: Int] = [:]
            let built = hunks.map { hunk -> Hunk in
                let digest = HunkParser.hunkID(path: path, body: hunk.body)
                let occurrence = (seen[digest] ?? 0) + 1
                seen[digest] = occurrence
                return Hunk(
                    id: occurrence == 1 ? digest : "\(digest)-\(occurrence)",
                    path: path,
                    oldStart: hunk.oldStart, oldCount: hunk.oldCount,
                    newStart: hunk.newStart, newCount: hunk.newCount,
                    header: hunk.header, body: hunk.body)
            }
            return FileDiff(path: path, oldMode: oldMode, newMode: newMode,
                            isBinary: isBinary,
                            headerText: headerLines.joined(separator: "\n") + "\n",
                            hunks: built)
        }
    }

    struct HunkBuilder {
        let header: String
        let oldStart: Int, oldCount: Int, newStart: Int, newCount: Int
        var body: [String] = [] {
            didSet {
                guard let added = body.last, let marker = added.first else { return }
                switch marker {
                case " ": oldRemaining -= 1; newRemaining -= 1
                case "-": oldRemaining -= 1
                case "+": newRemaining -= 1
                default: break                   // "\" counts on neither side
                }
            }
        }
        private var oldRemaining: Int
        private var newRemaining: Int

        /// Body membership is decided by the header's line counts, not by
        /// line prefixes alone: an added line reading `++ x` prints as
        /// `+++ x`, which prefix-dispatch would swallow as a file header.
        /// After both counts are consumed, only a trailing `\ No newline`
        /// marker still belongs to the hunk.
        func wantsMoreBody(marker: Character?) -> Bool {
            oldRemaining > 0 || newRemaining > 0 || marker == "\\"
        }

        /// Parses `@@ -a[,b] +c[,d] @@ …`. An omitted count means 1.
        init(header: String) throws {
            func range(_ token: Substring) throws -> (Int, Int) {
                let parts = token.split(separator: ",", omittingEmptySubsequences: false)
                guard let start = Int(parts[0]),
                      parts.count <= 2,
                      let count = parts.count == 2 ? Int(parts[1]) : 1 else {
                    throw Failure.malformedHunkHeader(header)
                }
                return (start, count)
            }
            let tokens = header.split(separator: " ")
            guard tokens.count >= 4, tokens[0] == "@@", tokens[3].hasPrefix("@@"),
                  tokens[1].hasPrefix("-"), tokens[2].hasPrefix("+") else {
                throw Failure.malformedHunkHeader(header)
            }
            self.header = header
            (oldStart, oldCount) = try range(tokens[1].dropFirst())
            (newStart, newCount) = try range(tokens[2].dropFirst())
            oldRemaining = oldCount
            newRemaining = newCount
        }
    }
}

/// Lists the hunks of every changed file in the repository at `path`, for
/// one diff area. Empty when that diff is empty.
///
/// The flags pin git's output against user config: `--no-color`,
/// `--no-ext-diff` and `--no-textconv` (drivers would replace or fabricate
/// patch text), `--no-renames` (a rename would put two different paths on
/// the `diff --git` line), `--default-prefix` (overrides `diff.noprefix`
/// and `diff.mnemonicprefix`), `--unified=3` (overrides `diff.context`),
/// and `core.quotepath=false` so non-ASCII paths print raw.
public func listHunks(
    at path: String,
    area: DiffArea,
    git: GitProcess = GitProcess()
) throws -> [FileDiff] {
    var arguments = ["-c", "core.quotepath=false", "diff"]
    if area == .staged { arguments.append("--cached") }
    arguments += ["--no-color", "--no-ext-diff", "--no-textconv", "--no-renames",
                  "--default-prefix", "--unified=3"]
    let output = try git.run(arguments, workingDirectory: path)
    return try HunkParser().parse(output.text)
}
```

```swift
/// `line 01` … `line 20`, one per line, trailing newline.
private func base20() -> String {
    (1...20).map { String(format: "line %02d", $0) }.joined(separator: "\n") + "\n"
}

/// The two-hunk edit: a line inserted after `line 03`, and `line 17`
/// replaced — far enough apart that git keeps them as separate hunks
/// (edits within 6 lines of each other merge into one hunk at -U3).
private func edited20() -> String {
    var lines = (1...20).map { String(format: "line %02d", $0) }
    lines[16] = "line 17 CHANGED"
    lines.insert("inserted after 03", at: 3)
    return lines.joined(separator: "\n") + "\n"
}

    var repo = try FixtureRepository(refFormat: format)
    try repo.build([.init("base", files: ["f.txt": base20()])])
    try repo.writeUntracked(["f.txt": edited20()])
    return repo

    // file header plus that hunk's patch text, applied to the index.
```

## Notes

Guide §6. Feeds **#0040** (stage and unstage by hunk id), which consumes `FileDiff.headerText` +
`Hunk.patchText` via `git apply --cached` exactly as Given 7 measured, and which owns the
"staging a stale id fails with a clear error" behavior split out of this issue's earlier draft.
The earlier draft's blockers are settled: #0009 (`WorktreeContext`/`GitProcess`) is resolved,
#0011 is wontfix; everything this issue needs is on `main`.

**CLI wiring is deliberately absent.** No `hunks` `CommandSpec`, no `runYard` arm, no `--json`
shape. Whether the CLI may call the engine directly or must marshal over XPC is the open
architectural question tracked in #0115; wiring specified before Brennan decides it would be
rework. The engine function is the stable half either way.

**Design decisions, so nobody relitigates them mid-round:**

- **Not `git patch-id`.** It normalizes whitespace, so two hunks differing only in whitespace
  would collide — unacceptable for staging precision — and it costs one process per hunk.
  SHA-256 over the raw body lines keeps whitespace significant and is pure.
- **Duplicate-content hunks** (identical body *and* context twice in one file) get `-2`, `-3`
  suffixes in listing order. Their ordering among themselves is the one thing a content hash
  cannot pin; documented on `Hunk.id`.
- **Recorded limitations, deliberate:** renames list as delete + add (`--no-renames`; a rename
  never splits into stageable hunks anyway); untracked files do not appear (`git diff` does not
  list them — `WorktreeStatus` covers them); a path git C-quotes even under `quotepath=false`
  (double quote or control character in the name) throws `Failure.quotedPath` rather than
  mis-parsing. Lifting any of these is future work, not this round.
