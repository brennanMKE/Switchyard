## Description

**Finding 1 of the M1 milestone review, 2026-08-17.** `gitStatus(at:includeIgnored:git:)`
(`YardKit/Sources/YardGit/WorktreeStatus.swift:424`) — the engine function M1 criterion 1 names for
`switchyard status` — **has no test that can fail.**

The review ran fourteen mutations across all thirteen M1 engine functions. Thirteen killed a named
test. **Both mutations of `gitStatus` survived:**

- **Removing `--ignored` entirely** (`if includeIgnored { … }` → `if false`).
  `gitStatusIncludeIgnored` asserts `statusIgnored.entries.count >= status.entries.count`, which
  equality satisfies. The fixture writes `.hidden`, which is in no `.gitignore`, so the flag has
  nothing to change **even unmutated**. `includeIgnored` is a documented parameter with **zero**
  behavioural coverage.
- **Removing `-z`.** The parser accepts newline-separated porcelain and returns one entry with a
  mangled path; `gitStatusReturnsAccessibleEntries` asserts only `!entries.isEmpty` and
  `!e.path.isEmpty`, so it stays green.

The contrast is the useful part: **the same `-z` mutation applied to `conflictedFiles` turns six tests
red**, because those assert exact paths. That is the shape `gitStatus` is missing.

Its only three call sites in the whole suite are in
`YardKit/Tests/YardGitPublicAPITests/PipelineContractTests.swift` (lines 197, 216, 219), inside tests
written as public-API **reachability** checks rather than behaviour checks. **The production code is
correct**; nothing can detect it being wrong.

**Not covered by #0142**, whose recorded mutation table is against `WorktreeStatusParser`'s internals
(`State.special(char:)`), not against `gitStatus`'s own argument construction and parse wiring.

## Expected behavior

- [ ] A test that makes `includeIgnored` load-bearing: a real `.gitignore` and an ignored file, with
      the ignored path **absent** at `includeIgnored: false` and **present** at `true`.
- [ ] A test asserting **exact paths**, so `-z` is load-bearing — the shape `ConflictsTests` already
      has and this function lacks.
- [ ] Both mutations from the review run and reported: `if false` on the `--ignored` append, and
      dropping `-z`. Each must redden a named test.
- [ ] A dedicated test file. `gitStatus` is the only one of M1's thirteen without one;
      `WorktreeStatusTests` is parser-level and never calls the public function. Name it so the
      distinction is visible.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, **N greater than 1037**.

`YardKit/Sources/YardGit/WorktreeStatus.swift` (read only — the production code is correct),
