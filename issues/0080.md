## Description

The content of a tab: **Sidebar / Graph / Detail**, horizontally split. This issue is the shell and
its geometry; the three panes themselves are #0081, #0052, and #0082.

## Expected behavior

- [ ] Three resizable panes with sensible minimum widths, so no pane can be dragged to unusable.
- [ ] Sidebar and Detail can each be collapsed and restored, with a keyboard shortcut and menu item.
- [ ] Split positions persist per window across launches, and are not shared between windows.
- [ ] Layout is correct at the smallest window size the app permits.
- [ ] Light and dark appearance both correct.
- [ ] Pane geometry lives in the view layer only — no engine logic here.

## Placement — settled 2026-08-07

Every view and everything around it goes in **`YardKit/Sources/YardUI/`**, the package target created
by **#0126**. Not in the Xcode project.

The Xcode project keeps only the `@main` `App` type, the asset catalog, `Info.plist`, entitlements,
`SMAppService` registration, and the embedded `switchyard` binary.

**Why it matters for this issue specifically:** a view in the app target can only be exercised by a UI
test, and UI tests cannot run under CLI-driven `xcodebuild` on this machine — the runner times out
enabling automation mode without Accessibility rights. Anything built here would ship untested. In
`YardUI` it is reachable from `swift test`.

`YardUI` sets `.defaultIsolation(MainActor.self)`, so views are main-actor isolated exactly as they
are in the app target today.

Tests go in `Tests/YardUITests` and import **without** `@testable`, so they see what the app sees.

## Planning update — 2026-08-17. One stale reference corrected, and the split that makes this testable.

**The Notes name two files that do not exist.** `find` over `../../Batty` returns no `PaneView.swift`
and no `SplitContainerView.swift`. What Batty actually has is a **split *tree*** in `BattyKit` —
`SplitTreeEqualizationTests`, `SplitTreePanePositionTests`, `SplitTreeFullDimensionTests`,
`AppStateStorePaneSplitTests` and a dozen more — because Batty splits panes arbitrarily at runtime.

**Switchyard has three fixed panes.** Do **not** port that model: it solves a problem this issue does
not have, and its tests are the bulk of it. Use `NavigationSplitView` (sidebar + content + detail is
exactly its shape) or two nested `HSplitView`s, and say which you chose and why. Reading Batty's tests
for the *sizing pitfalls* is still worthwhile; copying its tree is not.

### What is testable, and it is not the geometry

SwiftUI layout cannot be asserted from `swift test`, and UI tests cannot run here at all. So the
deliverable that carries tests is the **persistence model**, which is also criterion 3:

- **`YardKit/Sources/YardUI/PaneLayout.swift`** — a `Codable`, `Equatable`, `Sendable` value holding
  the two split fractions and the collapsed state of the sidebar and detail panes, with the minimum
  widths as constants on it and a `clamped(toWidth:)` that enforces them.
- Tests: a layout round-trips through `Codable`; `clamped` never produces a pane below its minimum,
  including at the smallest window width the app permits (state that width); collapsing and restoring
  returns the **previous** fraction rather than a default; **two windows' layouts are independent** —
  criterion 3's second half, and it is a property of the store, not of any view.

The view then reads and writes that value. Keep the geometry declarations free of logic (criterion 6)
so there is nothing in them worth testing.

### Persistence

Per **window**, not per app — `@SceneStorage` is the SwiftUI-native answer and it is scene-scoped by
construction, which is exactly criterion 3. If the round finds `@SceneStorage` unworkable with the
window model #0078 builds, fall back to keying the store by `WindowID` and say so; do **not** use
`@AppStorage`, which is app-wide and would share one layout between every window.

### Dark mode

Criterion 5 is a code review, not a test: semantic colours only — no hardcoded light-mode values, no
`Color(white:)`. The `swift-guidance` skill's dark-mode section is the reference; load it.
