## Description

#0356 produces the app artifact; this issue makes it **distributable**: a version-stamped
`Switchyard-<sha>.dmg` whose window shows the app beside an Applications alias, so the install
gesture is drag-and-drop. A DMG also survives machine-to-machine transfer cleanly (scp, AirDrop,
a shared folder) and mounts read-only, which is the shape a non-developer tester on a second
machine expects.

For the two-machine testing loop this quest serves, the DMG is **unsigned-local**: no Developer
ID, no notarization — a directly copied DMG carries no quarantine attribute, so Gatekeeper
accepts the app on first launch. Notarized distribution is a later, separate piece of work and
every step of it (certificates, notarization, stapling) is human-only under Rule 2.

## Expected behavior

- [ ] `scripts/make-release.sh package` (or a sibling script) produces
      `build/Switchyard-<sha>.dmg` from the #0356 app artifact.
- [ ] The DMG's layout is drag-to-Applications: the app and an `/Applications` link in one
      window, with a background/positioning that does not look accidental.
- [ ] Mounting the DMG and dragging the app yields a working `/Applications/Switchyard.app`
      whose first launch registers the broker (or surfaces #0354's typed state) and whose
      Settings can install the CLI.
- [ ] A verify script (UNRUN) documents: mount → drag → launch → the #0354/#0353 checks — the
      full second-machine acceptance path.
- [ ] The DMG build is reproducible from a clean tree and does not require Homebrew tooling
      beyond what is already declared.

## Notes

`hdiutil create` is the base mechanism; a window-layout tool (e.g. `create-dmg`) is optional
polish and may be a follow-up if it adds a dependency. The notarization/Developer ID story is
deliberately deferred and human-only (Rule 2); this issue's artifact is for machines the author
controls.
