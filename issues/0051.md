# 0051 — Implement CLIInstaller and the File menu install action

| | |
|---|---|

## Description

Symlink `/usr/local/bin/yard` into the bundle, driven from **File ▸ Install Command Line Tool…**.
The installer lives in the package, not the app target, because it presents no UI and returns
results the app renders — which is what makes its state machine unit-testable, and where the actual
bugs were last time.

## Expected behavior

- [ ] Symlink, not copy, so the link tracks the bundle.
- [ ] Four states modeled, not a boolean: not installed, installed correctly, installed elsewhere, stale link.
- [ ] **Refuses to install when the app is running from a build directory** — a link into DerivedData breaks on the next clean build.
- [ ] Sweeps `~/.local/bin` for a stale link it previously created.
- [ ] Detects `PATH` shadowing by another `yard` and reports it.
- [ ] Privilege escalation for `/usr/local/bin` (root-owned) handled with a clear prompt.
- [ ] Returns reports; the app presents them. The installer presents no alerts itself.
- [ ] Uninstall action fully reverses it.
- [ ] State machine and shell quoting unit-tested in the package.
