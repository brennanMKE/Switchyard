## Description

The storage half of the original #0043, split off when #0043 was re-authored to the
decision core. #0043's `PostRewrite.decide` turns one hook invocation into a
`Decision` — source (`amend`/`rebase`), `isOwnInvocation`, the ordered
`[Rewrite]` mapping, and a malformed-line count. This issue persists that:

- **Own invocations** (`isOwnInvocation == true` — the marker `GitProcess` sets)
  attach the mapping to the **in-flight journal entry** for the `switchyard`
  operation that ran the rewrite. This is why #0043 routes rather than skips:
  for `switchyard`'s own rebases the hook is the *only* source of the mapping.
- **Foreign invocations** become **observed** entries, the same class #0153
  defines for foreign ref transactions, so `undo` never offers to revert them.
- Only the **final `rebase` invocation** of a rebase is authoritative: measured
  on git 2.50.1 (#0043 Givens), squash/fixup/reword steps raise extra `amend`
  invocations mid-rebase whose old oids are intermediate commits that never
  existed in the pre-rewrite history. Persistence must not double-record a
  rebase from its mid-flight `amend` invocations.
- A **dropped commit appears in no mapping line at all** (measured — absence is
  the representation). Naming drops explicitly requires the pre-rewrite commit
  set from the journal entry's snapshot; that comparison lives here, not in the
  parser.

## Expected behavior

- [ ] An `amend`/`rebase` `Decision` from a foreign rewrite lands as an observed
      journal entry carrying source, the ordered old→new pairs, timestamp, and
      worktree, marked so `undo` never offers to revert it.
- [ ] A `Decision` with `isOwnInvocation == true` attaches its mapping to the
      corresponding in-flight journal entry instead of creating an observed one.
- [ ] Mid-rebase `amend` invocations do not double-record a rebase.
- [ ] Failure to persist never surfaces as a non-zero hook exit — #0043's
      totality invariant holds through this layer.
- [ ] #0064 (`rewrite-diff`) can read the stored mapping to compute its ranges.
- [ ] `swift test` prints a `Test run with N tests` line; N must exceed the
      pre-change baseline (re-measure at planning time; state the delta).

## Planning note — 2026-08-17. Four deliverables, and one the store cannot hold yet.

**Not dispatched: this issue is oversized as written**, and the sizing rule (one verb per issue) is
the one whose violation shows up as a round getting partway into each of several pieces — #0010,
#0011 and #0012 all failed that way. The Expected behavior list has four independent deliverables
with different failure modes:

1. a foreign rewrite becomes an observed entry;
2. an **own** invocation attaches its mapping to the in-flight journal entry;
3. mid-rebase `amend` invocations do not double-record a rebase;
4. persistence failure never produces a non-zero hook exit.

(4) is the same invariant #0191 is closing for ref transactions and should be settled the same way,
in whichever issue lands first. (3) is a deduplication rule whose correctness depends on (2).

### The design point that has to be settled before any of it is planned to code level

**`JournalObserved` cannot carry a rewrite mapping today.** #0153 landed
`JournalObserved.Metadata` with exactly one payload field:

```swift
public let updates: [ReferenceTransaction.RefUpdate]
```

A rewrite is not a ref update — `PostRewrite.Rewrite` is an old→new **commit** pair
(`PostRewrite.swift:61`), and a `Decision` also carries a `source` of `.amend` or `.rebase`
(`:39`, `:106`). So deliverable (1) needs one of:

- **a second payload field** on `Metadata`, optional, alongside `updates` — cheap, but every observed
  entry then carries a shape that is empty for the other kind, and the wire format grows a variant
  that must be pinned in both directions;
- **a payload discriminator** — `Metadata` becoming an enum over `refUpdates` / `rewrites` — honest
  about the two kinds, and a wire change to a format that has existed for one day;
- **a separate ref namespace per kind**, e.g. `refs/switchyard/observed/rewrites/`, which keeps each
  metadata shape single-purpose and costs a second `list`.

I have not picked one. All three are defensible and the choice changes what gets built, so it belongs
in a planning pass with the wire tests in view — not in a note written while two rounds are in flight.

### What (2) needs that does not exist

"The **in-flight journal entry** for the `switchyard` operation that ran the rewrite" presumes a way
to identify that entry from inside a hook. Nothing in `YardGit` exposes one today: `JournalAnchor`
mints an id at write time and the hook runs *during* the operation, before the entry is written. That
is a real mechanism to design — an environment variable carrying the id, a lock-file convention, or
recording the mapping first and attaching it afterwards — and it is the substance of deliverable (2),
not an implementation detail of it.

**Next step:** split into at least three issues once the payload question is settled, with (4) folded
into whichever lands first. Do not dispatch this issue as written.

## Split into #0220 and #0221 — 2026-08-17. This becomes the umbrella.

The planning note above said this issue is oversized as written and named the two things blocking it.
Both are now answered, and the work is filed as children:

- **#0220 — foreign rewrites become observed entries.** Carries the payload question's answer: a
  **`kind` discriminator added additively** to `JournalObserved.Metadata`, one namespace, no
  `schemaVersion` bump. Of the three readings listed above, a second optional field leaves both kinds
  ambiguous and a second ref namespace costs a `list` on every read for a distinction a key already
  makes. Deliverable (3) — mid-rebase `amend` invocations must not double-record — goes here, because a
  **foreign** rebase raises them too. Deliverable (4), the totality invariant, goes here as well, since
  this is the half that lands first.
- **#0221 — own invocations attach to the in-flight entry.** Carries the mechanism question's answer:
  `JournalCheckpoint.around` **writes the entry before running its body**, so the id exists before any
  git subprocess starts and can be exported through the environment the same way the own-invocation
  marker already is. That is a variable, not a design.

This issue stays open as the parent and is reviewed once both resolve, per CLAUDE.md's umbrella rule.
Do not dispatch it directly.
