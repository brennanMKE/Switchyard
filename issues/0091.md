# 0091 — Emit the failure envelope to stdout, and nothing else

| | |
|---|---|
| **Status** | open |
| **Module** | YardKit |
| **Milestone** | M1 |

## Description

`EnvelopeFail.write()` must put **exactly one thing** on stdout: the JSON envelope. Today it emits a
human-readable `[error] <code>: <message>` line first, so an agent parsing stdout hits a non-JSON
prefix and fails on the first character.

JSON is the contract, and the contract is that stdout carries JSON and nothing else.

This is a small, local change — one type and one method. If you find yourself rewriting the file,
stop; you have misread the task.

## Givens — verified on `main`, treat as true

The file is **`YardKit/Sources/YardKit/Envelope.swift`**. Everything below is present in your
worktree right now. Read it before editing.

1. `StandardStream` is declared at line 206 and is, in full:

   ```swift
   public indirect enum StandardStream {
       case stderr

       func print(_ message: String) {
           _ = Swift.print(message, terminator: "\n")
       }
   }
   ```

   **`Swift.print` writes to stdout.** The case is named `.stderr` and does not write to stderr. That
   is the bug — the name is not the behaviour.

2. `EnvelopeFail.write(stream:)` is at line 239 and reads:

   ```swift
   public func write(stream: StandardStream = .stderr) {
       stream.print("[error] \(error.code): \(error.message)")

       let data = try! JSONEncoder().encode(self)
       FileHandle.standardOutput.write(data)
       fflush(stdout)
   }
   ```

   The `stream.print` call is the line that pollutes stdout. The `FileHandle.standardOutput` write
   below it is correct and stays.

3. `terminate()` at line 248 calls `write()` and then exits with `error.matchExitCode().rawValue`.
   Its exit behaviour is correct — do not change it.

4. `error.code` is of type `EnvelopeErrorCode` (as of #0090), so interpolating it directly yields the
   Swift case name, not the wire string. If you keep the human-readable line, interpolate
   `error.code.rawValue` so the human text matches the JSON.

5. `EnvelopeSchema`, `EncodableResult`, `EnvelopeError`, `EnvelopeErrorCode` and `matchExitCode()` are
   all in this file and are **correct as they stand. Do not modify them.**

## Expected behavior

- [ ] `write()` emits the JSON envelope to stdout and **nothing else** — no prefix, no suffix, no
      human-readable line, no trailing newline before or after the JSON.
- [ ] The human-readable line goes to **actual stderr** via `FileHandle.standardError`, never
      `Swift.print`. Keep the line; just send it where it belongs.
- [ ] `StandardStream` loses its `indirect` — the enum has no associated values and does not need it.
      If the type has no remaining purpose once it writes to real stderr, deleting it entirely is
      acceptable and preferable; say which you did and why.
- [ ] A test captures stdout, and asserts the captured bytes parse as JSON **and** that the first
      byte is `{` and the last is `}` — proving there is no leading or trailing non-JSON content. A
      test that only checks "parses as JSON" does not catch a prefix, because a prefix makes parsing
      fail rather than pass, and a *suffix* can still parse depending on the decoder.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line
      you paste. N must be greater than 83, the count on `main` before this change.

## Tests must be able to fail

Ask of the new test: if someone re-added the `[error]` line to stdout tomorrow, would it fail? If
not, it is not testing the thing this issue exists for.

- Every test function must contain at least one `#expect`.
- Do not assert on a captured string you never populated — capture stdout for real, restore it
  afterwards, and assert on the captured bytes.
