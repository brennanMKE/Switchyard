## Description

Second root cause found while planning #0418. Guide §11 decision 5 says Switchyard is
**unsandboxed** — *"a sandboxed build … cannot publish a Mach service an external process can reach"*
— and RemoteControl, the working prototype, ships `Support/RemoteControl.entitlements` with
`com.apple.security.app-sandbox = false`. But Switchyard's app target still carries the Xcode
template's sandbox settings, in **both** configurations
(`Switchyard.xcodeproj/project.pbxproj`, the `Switchyard` target's Debug and Release blocks):

```
ENABLE_APP_SANDBOX = YES;
ENABLE_USER_SELECTED_FILES = readonly;
```

This is invisible in every build agents make: with `CODE_SIGNING_ALLOWED=NO` there is no signature,
so no entitlements, so no sandbox (`codesign -d --entitlements -` on `/Applications/Switchyard.app`
prints nothing). The UI-test VM script even overrides it (`ENABLE_APP_SANDBOX=NO` in
`scripts/run-ui-tests-vm.sh`). It bites the moment the app is **signed** — Brennan pressing Run in
Xcode with his normal automatic signing — because Xcode then derives
`com.apple.security.app-sandbox = true` from this setting.

**Measured 2026-09-26 in a disposable Tart clone** (never on the host; no certificate — the
entitlement was applied with an ad-hoc signature, which is exactly what a signed build would carry):
the same Debug build of `main` at `c4d48a8`, sealed per #0418, once without entitlements and once
with `app-sandbox = true` + `files.user-selected.read-only = true`:

| app | broker in launchd | app log | `switchyard whereami --no-launch` |
|---|---|---|---|
| unsandboxed | running | endpoint registered | `"ok":true`, **exit 0** |
| sandboxed | running (registered by the other copy) | `broker connection invalidated` | `app_unavailable: the broker is reachable but no app endpoint is registered`, **exit 3** |

The sandbox denies the app's `mach-lookup` of the unprefixed name `co.sstools.Switchyard.broker`,
so the app never hands its endpoint to the broker. (It would also confine the app's `git`
subprocesses and split `ServiceNames.stateDirectory()` into the container — both named in
decision 5.)

## The change

`Switchyard.xcodeproj/project.pbxproj` — exactly two lines change, both in the `Switchyard` app
target (Debug block, then Release block). Nothing else in the file has this setting.

```sh
sed -i '' 's/ENABLE_APP_SANDBOX = YES;/ENABLE_APP_SANDBOX = NO;/' Switchyard.xcodeproj/project.pbxproj
grep -n 'ENABLE_APP_SANDBOX' Switchyard.xcodeproj/project.pbxproj   # two lines, both "= NO;"
```

Measured before: `grep -c 'ENABLE_APP_SANDBOX = YES;'` → `2`. After: `grep -c 'ENABLE_APP_SANDBOX = NO;'`
→ `2`, and no `= YES;` remains. Leave `ENABLE_USER_SELECTED_FILES` alone (inert without the
sandbox) and do not touch any `CODE_SIGN_*`, `DEVELOPMENT_TEAM` or provisioning setting.

## New: `YardKit/Tests/YardKitTests/AppSandboxSettingTests.swift`, exactly

```swift
// AppSandboxSettingTests.swift
//
// #0423: guide §11 decision 5 — Switchyard ships unsandboxed. The app target
// carried the Xcode template's ENABLE_APP_SANDBOX = YES, which is inert in the
// unsigned builds agents make but becomes com.apple.security.app-sandbox in
// every SIGNED build. A sandboxed app cannot look up the unprefixed Mach
// service co.sstools.Switchyard.broker, so it never registers its endpoint and
// every CLI command exits 3 (app_unavailable) — measured in the Tart VM,
// 2026-09-26. This pins the setting off.

import Foundation
import Testing

struct AppSandboxSettingTests {

    private var pbxproj: String {
        get throws {
            let url = URL(fileURLWithPath: #filePath)
                .deletingLastPathComponent()   // YardKitTests
                .deletingLastPathComponent()   // Tests
                .deletingLastPathComponent()   // YardKit
                .deletingLastPathComponent()   // repo root
                .appendingPathComponent("Switchyard.xcodeproj/project.pbxproj")
            return try String(contentsOf: url, encoding: .utf8)
        }
    }

    @Test func noTargetEnablesTheAppSandbox() throws {
        #expect(!(try pbxproj).contains("ENABLE_APP_SANDBOX = YES;"))
    }

    /// Both of the app target's configurations (Debug, Release) say NO
    /// explicitly, so a later Xcode template default cannot silently return.
    @Test func bothAppConfigurationsDisableTheSandbox() throws {
        let occurrences = (try pbxproj).components(separatedBy: "ENABLE_APP_SANDBOX = NO;").count - 1
        #expect(occurrences == 2)
    }
}
```

**Mutation run by the planner:** with the two lines set back to `YES`, both tests fail
(`noTargetEnablesTheAppSandbox`, `occurrences == 2`); with `NO`, both pass.

## Expected behavior

- [ ] Neither app configuration sets `ENABLE_APP_SANDBOX = YES`; both set `NO`.
- [ ] `AppSandboxSettingTests` (2 tests) passes.

## Verification

From the worktree root, **unsigned only** — never pass `-allowProvisioningUpdates`. Stop on
`No signing certificate`, `errSecInternalComponent`, `User interaction is not allowed`.

1. `cd YardKit && swift test 2>&1 | tail -5` — paste the `Test run with N tests` line (baseline + 2).
2. `xcodebuild build -project Switchyard.xcodeproj -scheme 'Switchyard UITests' -configuration Debug -destination 'platform=macOS' -derivedDataPath build/dd CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO -quiet; echo EXIT $?`
   — `EXIT 0`.
3. `grep -n 'ENABLE_APP_SANDBOX' Switchyard.xcodeproj/project.pbxproj` — paste; two lines, both `NO`.

## Needs Brennan

Nothing to do for this issue by itself. It is what makes **Run from Xcode with your normal
signing** work for the CLI (the RemoteControl way): after it merges, Run, then in a repository
`switchyard whereami; echo exit=$?` should print `"ok":true` and `exit=0`. Before it merges, a
signed run shows exit 3 `app_unavailable` even though the broker is registered. If you later want
a sandboxed variant, decision 5 has to be reopened first.
