# 0124 — Wire switchyard whereami into the command registry

| | |
|---|---|
| **Status** | open |

| **Milestone** | M3 |

## Description

`whereAmI` has been shipped, tested and hardened across four issues, and **no agent can reach it**.
`switchyard whereami` is an unknown subcommand. This wires the first engine function into the CLI and
establishes the pattern every other command follows.

It is deliberately the smallest possible version: one subcommand, no flags, operating on the current
working directory. Argument and flag parsing is #0010/#0011 and is **not** part of this.

## Givens — verified on `main` 2026-08-07, treat as true

1. **`YardKit` does not depend on `YardGit` yet.** `Package.swift` has
   `.target(name: "YardKit", dependencies: [], path: "Sources/YardKit")`. Adding `"YardGit"` to that
   list is part of this issue. `YardGit` stays dependency-free — the arrow points one way.

2. `runYard(arguments:) -> (stdout: String, stderr: String, exitCode: ExitCode)` is in
   `YardKit/Sources/YardKit/CommandLineRunner.swift`. Its dispatch is a `switch` on `arguments[0]`
   with arms for `--help`, `--version`/`-v`, `schema`, and `noop`. Add one arm.

3. `CommandRegistry.all` is `[switchyardSpec, noopSpec]` in
   `YardKit/Sources/YardKit/CommandRegistry.swift`. Adding a spec makes `--help` and `schema` pick the
   command up for free — that is what #0088 built.

4. **The signature, verbatim:**

   ```swift
   public func whereAmI(path: String, git: GitProcess = GitProcess()) throws -> WhereAmI
   ```

   `WhereAmI` is `Sendable, Equatable` and its public members are `branch: String?`,
   `upstream: String?`, `ahead: Int?`, `behind: Int?`, `isMidRebase/isMidMerge/isMidCherryPick: Bool`,
   `stashCount/untrackedCount/unstagedCount/stagedCount/conflictCount: Int`, `hasConflicts: Bool`,
   `headOID: String` (the **7-character short** form), `rawHead: String`.

5. **`WhereAmI` is not `Encodable`.** Making it so is part of this issue — see the next section.

6. **`whereAmI` does not throw outside a repository.** Measured: in an empty temp directory it returns
   `branch=nil`, `headOID=""`, `rawHead=""` and no error. So a `do/catch` around it **cannot** detect
   "not a repository", and a command relying on that would print a success envelope full of empty
   fields.

   `WorktreeContext.resolve(path:git:)` **does** throw there. Measured:

   ```
   not a git repository: /var/folders/…/not-a-repo-8A6C…
   (fatal: not a git repository (or any of the parent directories): .git)
   ```

   Its error enum has `notARepository(path:detail:)`. Resolve the context first and let it be the
   gate — which is also what CLAUDE.md requires, since every path lookup goes through
   `WorktreeContext`.

7. `EnvelopeErrorCode` has `repositoryError = "repository_error"`, mapping to `ExitCode` **6**. That is
   the code for "the repository is in a state the command cannot work with".

8. `main` reported **310** tests on 2026-08-07.

## The wire format — settled here

**Conform `WhereAmI` to `Encodable` with an explicit `CodingKeys`.** Do not rely on Swift's synthesized
key names: the JSON is the contract for agents, and a property rename would silently change it.

Use the property names as they stand — `branch`, `upstream`, `ahead`, `behind`, `isMidRebase`,
`isMidMerge`, `isMidCherryPick`, `stashCount`, `untrackedCount`, `unstagedCount`, `stagedCount`,
`conflictCount`, `hasConflicts`, `headOID`, `rawHead` — so writing them out is a no-op today and a
deliberate choice tomorrow.

Encode `nil` optionals as **absent**, not as `null`. `Envelope.encode(to:)` already omits a nil
`result` this way, so it matches the existing shape.

## Expected behavior

- [ ] `Package.swift`'s `YardKit` target gains `"YardGit"` in its `dependencies`.
- [ ] `WhereAmI: Encodable` with an explicit `CodingKeys` enum listing every case.
- [ ] `CommandRegistry.all` gains a `whereami` spec: a non-empty `summary`, a non-empty `schemaName`,
      and at least the exit codes `0` and `6`. #0088's registry test asserts all three on every spec,
      so a spec missing any of them fails an existing test.
- [ ] `runYard` gains a `case "whereami":` arm that resolves `WorktreeContext` for the current working
      directory, calls `whereAmI`, and returns the result inside a success envelope.
- [ ] A path that is not a repository returns the failure envelope with `error.code ==
      "repository_error"` and exit **6**. Not exit 0 with empty fields.
- [ ] `--help` and `schema` pick the new command up with no further change — that is the point of the
      registry. Show both outputs.
- [ ] **The test files are a deliverable**: `git diff --name-only` must list source *and* test files.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. They go in
      `YardKit/Tests/YardKitTests/`; `Tests/YardKit/` is not a declared target path and a file there is
      silently never compiled.
- [ ] `cd YardKit && swift build && swift test` — paste the `Test run with N tests` line. **`main`
      reported 311 on 2026-08-07.** Paste the branch's own pre-change baseline too; N must exceed it.

## Tests must be able to fail

**Run the real binary, not just `runYard`.** `swift run switchyard whereami` inside a
`FixtureRepository` must print a JSON envelope whose `result.branch` is the fixture's actual branch —
parse the stdout with `JSONSerialization` and compare the parsed object. A test that only calls
`runYard` in-process misses the binary's own wiring, which is the thing this issue adds.

Assert values the fixture determines, not shapes:

- `result.branch == "main"` for a fixture built by `FixtureRepository` — it inits with
  `--initial-branch=main`.
- `result.headOID.count == 7` — it is the short form. Asserting 40 fails; that is measured.
- `result.conflictCount == 2` for a fixture built with `FixtureRepository.conflictedTwo()`.

**Run these four mutations and report each with the name of the test that kills it.** A green suite is
not evidence — a mutation is something you perform on the source **after** the tests are written, not
a test that encodes the broken behaviour.

| # | mutation | required |
|---|---|---|
| 1 | drop the `WorktreeContext.resolve` gate | the not-a-repository test FAILS — it would return exit 0 with empty fields |
| 2 | return `.success` instead of `.repositoryError` on that path | the same test FAILS on the exit code |
| 3 | rename one `CodingKeys` case, e.g. `conflictCount` → `conflicts` | the parsed-JSON test FAILS on the missing key |
| 4 | remove the `whereami` spec from `CommandRegistry.all` | the `schema`/`--help` test FAILS |

Restore after each and confirm the suite is green and `git diff` is unchanged.

### Four things that were wrong independently of the build break

Even with that edit applied, this would have failed review.

1. **The `WorktreeContext.resolve` gate is absent.** The arm wraps `runWhereAmI` in a `do/catch` —
   the exact pattern Given 6 rules out, because `whereAmI` **does not throw** outside a repository. It
   returns empty fields, so the catch never fires and the command prints a success envelope full of
   nothing. Resolve the context first and let *that* be the gate.

2. **Wrong error code.** The catch emits `.requestFailed`. It must be `.repositoryError`, exit **6**.

3. **`schemaName: ""`** on `whereamiSpec`. #0088's registry test asserts a non-empty `schemaName` on
   every spec, so this fails an existing test.

4. **The `CodingKeys` were inverted.** The issue's "wire format — settled here" section says to use the
   property names **as they stand**, so writing them out is a no-op today and a deliberate choice
   tomorrow. The round renamed every key to snake_case — `is_mid_rebase`, `conflict_count`,
   `head_oid`. Use `branch`, `upstream`, `ahead`, `behind`, `isMidRebase`, `isMidMerge`,
   `isMidCherryPick`, `stashCount`, `untrackedCount`, `unstagedCount`, `stagedCount`,
   `conflictCount`, `hasConflicts`, `headOID`, `rawHead`.

### And no test file at all

## Review round 3 — cap spent, and the issue contradicts the settled architecture

Round 3 fixed all four named round-2 defects and **the implementation is correct at runtime**,
verified against the real binary: outside a repository, `error.code == "repository_error"` and exit 6;
inside a fixture, `branch=main`, `headOID` length 7, camelCase keys, `upstream`/`ahead`/`behind`
absent rather than `null`; with `conflictedTwo()`, `conflictCount=2`.

**It wrote no tests.** The suite is 311 before and 311 after, and `grep -rn 'whereami'
YardKit/Tests/` matches only comments. Three of the four mutations survive — including dropping the
`WorktreeContext` gate, after which the binary returns a success envelope full of empty fields outside
a repository and the suite stays green. Three consecutive rounds have treated "write the tests" as
optional trailing work.

### Stop — this issue asks for something the architecture forbids

CLAUDE.md's Layering section is explicit:

> **`switchyard` is a companion tool, not a standalone one.** It ships inside the app bundle … and
> drives Switchyard.app over XPC. **The app owns the engine.**
> **`YardGit` and libgit2 live in the app only. The CLI does not link them, and does not open a
> repository itself.**
> **The CLI marshals arguments over XPC and prints the reply.** It stays small.

This issue has `YardKit` import `YardGit`, and the `switchyard` executable depends on `YardKit` — so
the CLI now links the engine and opens repositories in-process. **That is the opposite of the settled
design**, and it is the same shape as the invented "works without the app" requirement CLAUDE.md
records as corrected on 2026-08-06.

Round 3 also rewrote `LayeringTests.yardKitDoesNotImportYardGit` into
`yardKitImportsYardGitInRunner` — inverting the assertion that guarded exactly this. The rewrite is
coherent on its own terms and it ratifies a decision nobody made.

**Status back to `open`. This needs Brennan's decision before any further round**, because the answer
changes what M1's remaining commands look like:

- If the CLI must go through XPC, then **no command can be wired until #0046–#0048 land** (broker,
  `AppXPCServer`, the XPC client) — which are M3. M1 would end with an engine and no CLI, and #0115
  would move to M3.
- If the CLI may call the engine directly for read-only commands, then this issue is right and
  CLAUDE.md's Layering section needs amending to say so.

### Two defects in this issue text, mine

1. **Given 3 is factually wrong.** It says adding a spec makes `--help` and `schema` pick the command
   up "for free". `schema` does — it maps over `CommandRegistry.all`. **`--help` does not**:
   `helpForTopLevel()` renders only `CommandRegistry.switchyardSpec` and never enumerates `.all`.
   Verified. So criterion (g) was unsatisfiable without also changing `helpForTopLevel`.

2. The `CodingKeys` requirement was met by **deletion**. Round 2 wrote the enum with snake_case names;
   round 3 removed the enum entirely and fell back to synthesis. `grep -c 'is_mid_rebase…'` returns 0
   — passing for the wrong reason. A criterion phrased as an absence can be satisfied by removing the
   thing it was meant to constrain.

### What is worth keeping from the branch

`Package.swift`'s dependency, the `whereami` spec, the `WorktreeContext` gate and the `runYard` arm
are all correct *if* the direct-call design is the right one. The branch is intact at
`issue/0124`; nothing is merged.

One assertion must come back regardless: round 3 deleted
`#expect(!swiftFiles.isEmpty, "no Swift sources found at …")` from `LayeringTests`, which is the guard
that stops its "every other file" loop from passing vacuously on an empty list.

## Re-milestoned to M3 — 2026-08-07

Guide §11 decision 11. This issue was blocked, not on missing work, but on a contradiction between
two settled documents: guide §9 required every M1 command to run from the built binary, while guide

engine directly now would be rework, which is precisely the reading that was rejected.
