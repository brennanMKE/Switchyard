## Description

`whereAmI` has been shipped, tested and hardened across four issues, and **no agent can reach it**.
`switchyard whereami` is an unknown subcommand. This wires the first engine function through the CLI
and establishes the pattern every other command follows.

**Re-authored 2026-08-17**, and the reason is below in the round-3 review: the original version had
`YardKit` import `YardGit`, which puts the engine inside the CLI and inverts the settled layering. The
XPC route now exists, so the command can be wired the way the architecture always said.

## The route, now that it exists

Guide §11 **decision 15**: the CLI marshals **argv plus its working directory** over XPC and prints
the rendered envelope it gets back. The chain is built and merged:

| piece | issue | where |
|---|---|---|
| broker agent, `BrokerProtocol` | #0045, #0046 | `BrokerAgent/`, `YardKit/Sources/YardKit/XPCProtocols.swift` |
| app's anonymous listener + registration | #0047 | `Switchyard/AppXPCServer.swift` |
| CLI client, launch, bounded poll, exit codes | #0048 | `YardKit/Sources/YardKit/{Broker,App}Connection.swift` |
| launch-agent registration | #0049 | `Switchyard/AgentRegistrar.swift` |
| app accepts and exports `AppService` | #0215 | `Switchyard/AppXPCServer.swift` |
| `perform(arguments:workingDirectory:)` both sides | #0218 | — |
| `YardCommands` target | #0223 | `YardKit/Sources/YardCommands/` |

So this issue adds **one arm in `YardCommands`, one `CommandSpec`, and the tests** — and nothing in
`YardKit` learns about `YardGit`.

## Givens — re-verify each on the branch; they were read on `main` 2026-08-17

1. **The signature, verbatim:**

   ```swift
   public func whereAmI(path: String, git: GitProcess = GitProcess()) throws -> WhereAmI
   ```

   `WhereAmI` is `Sendable, Equatable`; its public members are `branch: String?`, `upstream: String?`,
   `ahead: Int?`, `behind: Int?`, `isMidRebase`/`isMidMerge`/`isMidCherryPick: Bool`,
   `stashCount`/`untrackedCount`/`unstagedCount`/`stagedCount`/`conflictCount: Int`,
   `hasConflicts: Bool`, `headOID: String` (the **7-character short** form), `rawHead: String`.

2. **`whereAmI` does not throw outside a repository.** Measured: in an empty temp directory it returns
   `branch=nil`, `headOID=""`, `rawHead=""` and no error. A `do`/`catch` around it therefore **cannot**
   detect "not a repository", and a command relying on that prints a success envelope full of empty
   fields. `WorktreeContext.resolve(path:git:)` **does** throw there, with
   `notARepository(path:detail:)`. Resolve the context first and let that be the gate — which is also
   what CLAUDE.md requires, since every path lookup goes through `WorktreeContext`.

3. **`--help` does not enumerate the registry.** `helpForTopLevel()` renders only
   `CommandRegistry.switchyardSpec`. `schema` **does** map over `CommandRegistry.all`. The original
   issue claimed both came "for free" and one of them does not; check what `helpForTopLevel` does today
   before writing a criterion about it.

4. **`WhereAmI` is not `Encodable`.** Making it so is part of this issue.

## The wire format — settled, and it was got wrong twice

**Conform `WhereAmI` to `Encodable` with an explicit `CodingKeys` enum listing every case**, using the
property names **exactly as they stand** — `branch`, `upstream`, `ahead`, `behind`, `isMidRebase`,
`isMidMerge`, `isMidCherryPick`, `stashCount`, `untrackedCount`, `unstagedCount`, `stagedCount`,
`conflictCount`, `hasConflicts`, `headOID`, `rawHead`. Writing them out is a no-op today and a
deliberate choice tomorrow: the JSON is the contract for agents, and a property rename must not
silently change it.

Round 2 renamed every key to snake_case; round 3 satisfied the "no snake_case" criterion by **deleting
the enum** and falling back to synthesis. Both are wrong. The criterion is the enum's presence with
those names, and a test must assert a key that synthesis would also produce — so the test that catches
a deletion is the one that **renames a property and expects the JSON key to stay put**. State how you
covered it.

Encode `nil` optionals as **absent**, not `null`, matching `Envelope`'s own handling of a nil `result`.

## The CLI's own dispatch — folded in from #0218

#0218 deliberately left `YardKit/Sources/switchyard/main.swift` calling `runYard` directly, and that
was the right call: routing every invocation through the app before an app is installed would break
`--help` and `--version` for everyone. **This issue is where the decision has to be made**, because
`whereami` is the first command that cannot be answered locally.

The shape, and it must not become an argument parser (#0010/#0011 own that):

- `main.swift` asks whether the command needs the app. The honest test is **whether `runYard` knows
  it**: `--help`, `--version`, `schema` and `noop` are answered locally today, and everything else
  needs the app. Derive that from `CommandRegistry`/`runYard` rather than hardcoding a second list —
  two lists of command names drift, and the drift is silent.
- If it needs the app: `AppConnection.connect()`, then `perform(arguments:workingDirectory:)` with
  `FileManager.default.currentDirectoryPath` — **the CLI's** cwd, which is the whole reason
  `workingDirectory` is on the wire — then write the returned bytes to stdout **unmodified** and exit
  with `ExitCode(fromAppReply:)`.
- A failure to reach the app exits with the code `AppConnectionError`/`CLIError` already map to (2, 3,
  4, 5), and prints the structured error envelope. Those mappings landed with #0048; do not write new
  ones.

`main.swift` cannot be `@testable import`ed, so keep it to those few lines and put anything worth
asserting behind a function in `YardKit`.

## What is out of scope

**Running the real binary end to end.** `swift run switchyard whereami` now requires the app, the
broker and a registered launch agent, so it is a #0054 scenario, not a package test. The original issue
asked for it and was right to at the time; decision 15 moved it. Do not launch the app.

Flag and argument parsing is #0010/#0011. This is one subcommand, no flags.

3. **`schemaName: ""`** on `whereamiSpec`. #0088's registry test asserts a non-empty `schemaName` on

### Stop — this issue asks for something the architecture forbids

CLAUDE.md's Layering section is explicit:

> **`switchyard` is a companion tool, not a standalone one.** It ships inside the app bundle … and
> drives Switchyard.app over XPC. **The app owns the engine.**
> **`YardGit` and libgit2 live in the app only. The CLI does not link them, and does not open a
> repository itself.**
> **The CLI marshals arguments over XPC and prints the reply.** It stays small.

This issue has `YardKit` import `YardGit`, and the `switchyard` executable depends on `YardKit` — so
the CLI now links the engine and opens repositories in-process. **That is the opposite of the settled
design**, and it is the same shape as the invented "works without the app" requirement CLAUDE.md
records as corrected on 2026-08-06.

Round 3 also rewrote `LayeringTests.yardKitDoesNotImportYardGit` into
`yardKitImportsYardGitInRunner` — inverting the assertion that guarded exactly this. The rewrite is
coherent on its own terms and it ratifies a decision nobody made.

**Status back to `open`. This needs Brennan's decision before any further round**, because the answer
changes what M1's remaining commands look like:

- If the CLI must go through XPC, then **no command can be wired until #0046–#0048 land** (broker,
  `AppXPCServer`, the XPC client) — which are M3. M1 would end with an engine and no CLI, and #0115
  would move to M3.
- If the CLI may call the engine directly for read-only commands, then this issue is right and
  CLAUDE.md's Layering section needs amending to say so.

### Two defects in this issue text, mine

1. **Given 3 is factually wrong.** It says adding a spec makes `--help` and `schema` pick the command
   up "for free". `schema` does — it maps over `CommandRegistry.all`. **`--help` does not**:
   `helpForTopLevel()` renders only `CommandRegistry.switchyardSpec` and never enumerates `.all`.
   Verified. So criterion (g) was unsatisfiable without also changing `helpForTopLevel`.

2. The `CodingKeys` requirement was met by **deletion**. Round 2 wrote the enum with snake_case names;
   round 3 removed the enum entirely and fell back to synthesis. `grep -c 'is_mid_rebase…'` returns 0
   — passing for the wrong reason. A criterion phrased as an absence can be satisfied by removing the
   thing it was meant to constrain.

are all correct *if* the direct-call design is the right one. The branch is intact at

## Re-milestoned to M3 — 2026-08-07

Guide §11 decision 11. This issue was blocked, not on missing work, but on a contradiction between
two settled documents: guide §9 required every M1 command to run from the built binary, while guide
§5 and `CLAUDE.md` require the CLI to marshal over XPC and never link `YardGit` — and XPC is built in
M3.

Brennan's decision is that **M1 claims the engine and its tests; M3 owns the claim that the commands
run.** So this issue moves to M3 unchanged in substance, and stops blocking M1's close.

Nothing here should be dispatched until the XPC layer exists (#0046–#0048). Wiring the CLI to the
engine directly now would be rework, which is precisely the reading that was rejected.
