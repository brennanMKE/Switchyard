# 0093 — Verify the stdout and exit-code contract from a subprocess

| | |
|---|---|
| **Status** | open |
| **Module** | YardKit |
| **Milestone** | M1 |
| **Platform** | macOS |
| **First seen** | 2026-08-06 |

## Description

The contract is that a failure emits JSON **on stdout** and sets a **specific exit code**. Neither can
be proven by encoding a struct in-process — only by running the binary and inspecting what a caller
actually receives.

Both #0011 rounds substituted an encoder round-trip for this. Round 2's test was even *named*
`envelopeFailWriteEmitsJsonToStdout` while never calling `write()`.

## Givens — verified on `main`, treat as true

1. The new test file is **`YardKit/Tests/YardKitTests/YardBinaryContractTests.swift`**. Create it;
   do not add these cases to an existing file.
2. **`swift test` builds the `yard` executable.** This was checked: deleting `.build/debug/yard` and
   running `swift test` recreates it. You do not need to shell out to `swift build` first.
3. **The binary sits in the same directory as the test bundle.** Both `yard` and
   `YardKitPackageTests.xctest` are in `$(swift build --show-bin-path)`. So locate it from the
   bundle rather than hard-coding a path or guessing a triple:

   ```swift
   var yardBinary: URL {
       var dir = Bundle.allBundles.first { $0.bundlePath.hasSuffix(".xctest") }!.bundleURL
       dir.deleteLastPathComponent()
       return dir.appendingPathComponent("yard")
   }
   ```

   Do not build a path from `#filePath` and `.build/debug` — the real directory is triple-specific
   (`.build/arm64-apple-macosx/debug`), and hard-coding either form breaks on the other.
4. If the binary is missing, the test must **fail with a message saying so**. It must not skip
   quietly — a subprocess test that silently does nothing is exactly the failure this issue exists
   to prevent.
5. `ExitCode.usage` is `1`. #0092 wired the binary up, and these are its verified behaviours —
   confirmed by running it with the streams captured separately:

   | invocation | exit | stdout |
   |---|---|---|
   | `yard` | 0 | `{"result":"yard 0.0.1 (libgit2 1.9.6)","schemaVersion":1,"ok":true}` |
   | `yard bogus-command` | 1 | `{"error":{"code":"usage","message":"Unknown subcommand 'bogus-command'."},"schemaVersion":1,"ok":false}` |
   | `yard noop` | 0 | `{"schemaVersion":1,"ok":true}` |

   Assert against the **shape** — valid JSON, `ok` false, `error.code` equal to `usage` — not against
   these exact byte strings, which include a version number that will change.
6. stderr is currently **empty** on every path, including failures. That is a known gap tracked by
   #0100, not something for this issue to fix. Do not assert anything about stderr's contents beyond
   what you actually observe.

## Expected behavior

- [ ] A test spawns the built `yard` binary as a subprocess — `Process`, with pipes on stdout and stderr.
- [ ] It asserts stdout parses as JSON via `JSONSerialization`, not by string matching.
- [ ] It asserts `terminationStatus` equals the documented exit code for that failure.
- [ ] It asserts stdout contains **no** non-JSON prefix or suffix.
- [ ] A second case asserts a success path exits 0 with a valid envelope.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line
      you paste. **N must be greater than 105**, the count on `main` before this change.

## Notes

Split out of #0011. Blocked by #0092 — there must be a binary that emits envelopes before a
subprocess test can check one.

**A test that does not spawn a process cannot satisfy this issue**, however it is named. Neither
`EnvelopeFail.write()` called in-process nor an encoder round-trip counts, no matter how the test
function is named — both #0011 rounds substituted exactly that. If spawning
proves impossible in the test environment, say so and stop rather than substituting an in-process
approximation.
