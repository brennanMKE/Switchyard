## Description

**Filed 2026-08-08 after the same gap appeared in two consecutive issues, found both times by a
reviewer writing a mutation the table lacked.**

`GitProcess` accepts an `extraEnvironment` that callers use to pin behaviour. **Nothing proves it
arrives.** Delete it from an invocation and the suite stays green, because the fixtures happen not
to need it:

- **#0036** — dropping `extraEnvironment` from `CommitCreate`'s `git commit` call left all **775**
  tests green. The tests survive because `FixtureRepository` writes repo-local config that outranks
  anything global. The live consequence is that a developer's or user's global `commit.gpgsign` or
  `user.signingKey` can reach a commit the caller asked to be hermetic — exactly what the
  `GIT_CONFIG_GLOBAL=/dev/null` pinning exists to prevent.
- **#0152** — dropping `extraEnvironment: Self.commitEnvironment` from the `commit-tree` call left
  all **788** tests green, with two measured consequences:

  | | commit oid | author |
  |---|---|---|
  | as shipped | `897ebfb…` both times | `switchyard <journal@switchyard.invalid> 946684800 +0000` |
  | without it | `ca60e77…` then `93d3b18…` | **`Brennan Stehling <277419+brennanMKE@…>`** |

## Why this is worth its own issue

Two things break, and neither is cosmetic.

**The dedup claim is unverified, and #0171 depends on it.** #0152 decision 3 states that an
unchanged worktree dedupes because the commit oid is a pure function of its tree. That holds only
while the identity and timestamp are pinned. Unpinned, every checkpoint mints a new commit object
for identical content — the journal grows without bound and #0171's composition inherits it.

**Snapshot commits would carry the user's real identity.** A journal entry is internal machinery;
attributing it to a person is wrong on its face, and it leaks a name and email into objects that
`--mirror` clones carry to other machines.

## What this issue must deliver

- **An assertion per call site that the environment reached git**, for every `GitProcess`
  invocation whose correctness depends on it. Prefer asserting the **observable effect** — the
  pinned author line, a deterministic oid across two captures of the same tree, the absence of a
  global config's influence — over asserting that a dictionary was passed, which tests the call
  rather than the behaviour.
- **A mutation row per site**, dropping `extraEnvironment` there and observing the named test die.
  Both rows above are currently green; both must go red.
- **A determinism test for the dedup claim**: capture the same unchanged worktree twice and assert
  the oids are equal. That is #0152 decision 3 made executable, and it is the binding note #0171
  relies on.
- Consider whether a **hermeticity check** generalises — something asserting that a global config
  hostile to the operation (`commit.gpgsign=true`, a bogus `user.signingKey`) does not change the
  result. That is the property the pinning actually buys, and it would cover call sites nobody has
  thought to enumerate.

Sites to audit: `CommitCreate` (three `GitProcess` calls), `WorktreeSnapshot` (`commit-tree` and
the index work), and anything else where `grep -rn 'extraEnvironment' YardKit/Sources` finds a
caller.

## Notes

Ninth finding of this shape — the code is right, the evidence is missing — after #0176–#0180,
#0182–#0184. The recurring cause is stated in `docs/review-failures.md` check 0b: **a mutation
table drifts toward the code paths the tests already exercise**, so the untested path is the one no
row perturbs. Environment plumbing is a particularly pure case: it has no behaviour of its own to
notice, it only changes what *another* program does, and the fixtures are built to be independent of
the environment — which is exactly what makes its absence invisible.

## Givens — read from the merged code, 2026-08-08

1. `WorktreeSnapshot.commitEnvironment` is `internal static let` at `WorktreeSnapshot.swift:272`
   and pins six variables: `GIT_AUTHOR_NAME`/`EMAIL`, `GIT_COMMITTER_NAME`/`EMAIL`, and both dates
   to `2000-01-01T00:00:00Z`.
2. It is passed at exactly one site — the `commit-tree` call at line 164.
3. **The measured consequence of dropping it** (#0152's review): the same unchanged tree yields a
   *different* commit oid on each capture (`ca60e77…` then `93d3b18…` versus `897ebfb…` twice as
   shipped), and the commit is authored as the machine's real git identity rather than
   `switchyard <journal@switchyard.invalid>`.
4. `capture(in:git:)` is `public` and returns a `WorktreeSnapshot`; the tests already resolve a
   `WorktreeContext` and call it directly.

## Change 1 — `YardKit/Tests/YardGitTests/WorktreeSnapshotTests.swift`, append one test

Append inside the suite type. **Inside the type, not at file scope** — #0180's round appended after
the closing brace and the target did not compile while the round still reported success.

```swift
    /// #0152 decision 3 claims an unchanged worktree dedupes because the
    /// snapshot commit's oid is a pure function of its tree. That holds only
    /// while the identity and both dates are pinned. Dropping
    /// `extraEnvironment: Self.commitEnvironment` from the `commit-tree` call
    /// leaves the whole suite green — measured — while making every capture
    /// mint a new object AND authoring it with the machine's real git
    /// identity, which a --mirror clone then carries to other machines.
    ///
    /// This asserts the observable effect, not that a dictionary was passed:
    /// determinism, and the pinned author line.
    @Test func theSnapshotCommitIsDeterministicAndAnonymous() throws {
        let repo = try FixtureRepository.linear()
        defer { repo.destroy() }
        let context = try WorktreeContext.resolve(path: repo.url.path)
        try "dirty\n".write(to: repo.url.appendingPathComponent("a.txt"),
                             atomically: true, encoding: .utf8)

        let first = try WorktreeSnapshot.capture(in: context)
        let second = try WorktreeSnapshot.capture(in: context)
        #expect(first.tracked == second.tracked)

        let author = try GitProcess().run(
            ["show", "-s", "--format=%an <%ae> %ad", "--date=iso-strict", first.tracked],
            workingDirectory: repo.url.path).text
        #expect(author.contains("switchyard <journal@switchyard.invalid>"))
        #expect(author.contains("2000-01-01"))
        // The machine's real identity must not appear.
        let realName = try GitProcess().run(
            ["config", "user.name"], workingDirectory: repo.url.path).text
            .trimmingCharacters(in: .whitespacesAndNewlines)
        #expect(!realName.isEmpty)          // the fixture sets one; else the check is vacuous
        #expect(!author.contains(realName))
    }
```

**The round must confirm the member name.** `first.tracked` is written from the design, not measured
— if `WorktreeSnapshot`'s tracked-commit member is named otherwise, use the real one and say so.
That is the one thing here not read from the source.

The `realName` non-empty assertion is deliberate: without it, `!author.contains(realName)` passes
trivially when the fixture sets no identity, which is the emptiness trap that has bitten this
project repeatedly.
