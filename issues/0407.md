## Description

The per-spike summary loop at the end of `scripts/run-ui-tests-vm.sh` calls
`print "--- $(basename "$log_file")"`. zsh's `print` reads the leading `-` as an option, so the call
fails. The run on 2026-09-22 ended with:

```
==> RESULT: TEST FAILED (exit 65)
./scripts/run-ui-tests-vm.sh:print:327: bad option: -
==> Cleaning up (exit 1)
```

Under `set -e` that kills the script. It exits 1 instead of `$TEST_RC` (65 here, 0 on success), and
the per-spike summary never prints. VM runs are M9's verification path, so their exit code has to be
trustworthy.

## Expected behavior

- [ ] The summary prints one `--- xcodebuild-spike-NNNN.log` header per spike, and the script exits
      with `$TEST_RC`.

## Files and literal changes

`scripts/run-ui-tests-vm.sh`, in the loop after the `RESULT:` lines: change

```zsh
  print "--- $(basename "$log_file")"
```

to

```zsh
  print -r -- "--- $(basename "$log_file")"
```

That is the same `print -r --` form the script's own `log()` function already uses.

## Verification

`zsh -n scripts/run-ui-tests-vm.sh` must exit 0, and
`zsh -c 'print -r -- "--- x.log"'` must print `--- x.log`. The next VM run must end with the
`---` headers and exit with the test code.
