# 0406 — Open a commit's changes in their own window by double-clicking its graph node

| | |
|---|---|

## Description

Split from #0404. Once `CommitChangesView` exists, double-clicking a node in the graph opens it in a
window of its own. Brennan: *"If I want to see more I can either double click on the node or hit a
button."* The button is #0403.

**Depends on #0404** (`CommitChangesTarget`, `CommitChangesView`), which must be merged first.

## Expected behavior

- [ ] The app declares a `WindowGroup(for: CommitChangesTarget.self)` scene that shows
      `CommitChangesView`.
- [ ] Double-clicking a row in the History list opens that commit's changes window.
- [ ] Opening the same commit again focuses its existing window instead of opening a second one.
      `WindowGroup(for:)` gives this for equal values.
- [ ] A VM UI test double-clicks a graph row and asserts that a second window appears showing the
      commit's changed file.

## Files and literal changes

Planned to code level once #0404 is merged, against the merged API. Known shape, from the
2026-09-22 code map:

- `YardKit/Sources/YardUI/CommitHistoryView.swift`: `.contextMenu(forSelectionType:)` gains a
  `primaryAction:` closure. That's SwiftUI's double-click action for `List` selection. It calls a
  new `onOpenChanges: ((String) -> Void)?` init parameter with the single clicked oid.
- `YardKit/Sources/YardUI/ContentView.swift`: `@Environment(\.openWindow)`, and `onOpenChanges`
  opens `CommitChangesTarget(repositoryPath:oid:subject:)`, taking the subject from `history`.
- `Switchyard/SwitchyardApp.swift`: a second scene,
  `WindowGroup(for: CommitChangesTarget.self) { $target in if let target { CommitChangesView(target: target) } }`.
- `SwitchyardUITests/0406CommitChangesWindowUITests.swift` (new), and a
  `run_spike_if_selected 0406 …` line in `scripts/run-ui-tests-vm.sh`.
