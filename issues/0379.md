## Description

Brennan, 2026-09-12, filed from the M7 planning questions. One deliverable: clicking a branch in the
sidebar — local or remote-tracking — selects that branch's tip commit in the History pane and
scrolls it into view.

### Interaction

- **Click a branch or remote row** → the History selection moves to its tip and the list scrolls it
  to the centre. The Detail pane follows through its existing `.task(id: selectedCommit)`.
- **Clicking the same branch again** after scrolling away scrolls back. The request carries a fresh
  identity each time, not just the oid, so an unchanged oid still triggers.
- **Tip not loaded** (older than the 100-commit window): nothing is selected, `NSSound.beep()` gives
  the standard "can't do that" feedback, and the row's help text reads
  "The tip of “<name>” is older than the loaded history".
- The row whose tip is the selected commit draws semibold, the marking the sidebar already uses.

### Wiring

- `YardKit/Sources/YardUI/RepositorySidebarView.swift`: branch and remote rows become
  `Button { onRevealTip(entry.oid) } label: { … }.buttonStyle(.plain)`. That is the pattern
  `rerereRow` already uses, rather than a list-wide selection binding. The view gains
  `onRevealTip: (String) -> Void`.
- `YardKit/Sources/YardUI/ContentView.swift`: when `history` contains the oid, set `selectedCommit`
  through the same path the History binding uses (so the rerere selection clears), and set
  `revealRequest = RevealRequest(oid: oid)`, where
  `struct RevealRequest: Equatable { let id = UUID(); let oid: String }` (*not compiled*). Otherwise
  beep.
- `YardKit/Sources/YardUI/CommitHistoryView.swift`: wrap the `List` in `ScrollViewReader` and scroll
  on change. This shape *compiled* at `61c94aa` with a `String?` request:

  ```swift
  ScrollViewReader { proxy in
      List(entries, id: \.oid, selection: $selection) { /* rows */ }
          .onChange(of: revealRequest) { _, request in
              guard let request else { return }
              withAnimation { proxy.scrollTo(request.oid, anchor: .center) }
          }
  }
  ```

  The write that triggers this comes from a click handler (event origin), so the `onChange` scroll
  is not a layout-driven feedback loop.

## Expected behavior

- [ ] Clicking a branch or remote row whose tip is loaded selects that commit and scrolls it into view.
- [ ] Clicking the same row again after scrolling away scrolls back to it.
- [ ] A row whose tip is not loaded beeps and explains itself in its help text; `swift test` prints
      `Test run with N tests` with no failures.
