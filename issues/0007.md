## Description

Bundle identifier, Mach service name, launch agent plist name, URL scheme, log subsystem, CLI binary
name, install location, state directory, journal ref namespace. One file owns all of them and
nothing else hardcodes any of the strings.

This is cheap now and expensive later: these strings end up in the app target, the broker, the CLI,
the installer, the launchd plist, and the hook handler, and a mismatch between any two of them
produces a failure that looks like "XPC is broken".

## Expected behavior

- [ ] `ServiceNames.swift` in `YardKit` holds every value from guide §3.
- [ ] State directory resolution honors `XDG_STATE_HOME`, falling back to `~/.local/state/switchyard/`.
- [ ] A test asserts the bundle identifier matches what is in `project.pbxproj`.
- [ ] Grep confirms no literal `co.sstools.Switchyard` anywhere else in Swift sources.

## Notes

Guide §3. Blocked by #0006.

## Fix

`ServiceNames.swift` in `YardKit` holds every identifier from guide §3, grouped by concern: identity,
XPC, CLI, and storage. `stateDirectory(environment:homeDirectory:)` takes both as parameters so the
resolution is testable without mutating the process environment.

## Verification

`swift test` — **12 tests in 3 suites passed**. Coverage: `XDG_STATE_HOME` honored, fallback to
`~/.local/state/switchyard`, empty-variable fallback, bundle identifier matching `project.pbxproj`,
derived-name relationships, CLI path suffixes, and the journal ref prefix staying outside
`refs/heads` and `refs/tags`.

Both guards were verified by deliberately breaking them. Adding a literal `"co.sstools.Switchyard"`
to `YardGit.swift` failed `noOtherSwiftSourceHardcodesTheIdentifiers()` with
`offenders → ["YardGit.swift contains \"co.sstools.Switchyard\""]`; reverting restored green.

## Files changed

- `YardKit/Sources/YardKit/ServiceNames.swift` — every guide §3 identifier
- `YardKit/Tests/YardKitTests/ServiceNamesTests.swift` — 8 tests including the two guards

## Gotchas

**An empty `XDG_STATE_HOME` is not a set one.** `XDG_STATE_HOME=` in a CI environment would otherwise
resolve the state directory to `/switchyard`. There is an explicit test for this.

The identifier guard scans `Switchyard/` and `BrokerAgent/` as well as the package, so it will keep
holding once the app target has Swift sources — it is not scoped to what exists today.
