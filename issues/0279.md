## Description

**Finding 4 of the M1 milestone review, sixth pass, 2026-08-18.** `status`' submodule state survives a
field transposition.

`YardKit/Sources/YardGit/WorktreeStatus.swift:107-108`, mutated:

```swift
self.hasModifications = chars[2] == "U"     // was: chars[1] == "M"
self.hasUntracked     = chars[1] == "M"     // was: chars[2] == "U"
```

`Test run with 1078 tests in 78 suites passed after 52.098 seconds.` — **full suite, unfiltered.**

**Why nothing catches it:** the only two `SubmoduleState` values in the whole suite are **all-true**
(`SCMU`, `WorktreeStatusTests.swift:287-291`) and **all-false** (`SubmoduleState.clean` / `S...`,
`PipelineContractTests.swift:147-149`). Both are invariant under a swap of two booleans.

A **mixed** token distinguishes them — `SC.U` (commit changed, untracked, no modifications) or `S.M.`
(modifications only) — and no fixture produces one.

This is exactly the transposition case #0247 and #0259 were written around, unmet here.

## Expected behavior

- [ ] A test asserting a `SubmoduleState` parsed from a **mixed** token, with at least two of the four
      flags differing — `SC.U` and `S.M.` between them cover the swap and more.
- [ ] Prefer parsing the token through the production path rather than constructing `SubmoduleState`
      directly; a test that builds the value by hand pins the initializer's storage, not its parsing.
- [ ] **Mutation:** swap `hasModifications` and `hasUntracked` at `WorktreeStatus.swift:107-108`. Must
      redden. Confirm it landed there.
- [ ] **Second mutation:** swap `chars[0]`/`chars[1]` (the `S`/commit-changed pair) as well, and say
      whether the same test catches it or a second token is needed.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.
