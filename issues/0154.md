## Description

The thin process wrapper the installed `reference-transaction` hook script execs:
read argv[1] (the state), call `ReferenceTransaction.decide` (#0042) with the process
environment and a stdin closure, and exit with `Decision.exitCode` — which is 0 by the #0042
totality invariant. Per #0042 Givens 5, the process spawn (~8 ms) dominates the handler cost,
so this arm must stay a straight-line exec with no XPC wait and no journal I/O of its own
(#0153 owns persistence; forwarding to the app is M3).

## Expected behavior

- [ ] The arm checks its state argument and environment **before** draining stdin — #0042's
      `readStandardInput` closure contract, preserved at the process boundary.
- [ ] Exit status is 0 for every input, including garbage stdin on `committed` — a non-zero
      exit in `prepared` aborts the user's transaction (#0042 Givens 3).
- [ ] A test exercises the built binary as a real hook in a real repository, both ref formats —
      an in-process approximation cannot satisfy this criterion.
- [ ] `swift test` prints a `Test run with N tests` line; N must exceed the pre-change baseline
      (re-measure at planning time; state the delta).

## Milestone corrected to M3 — 2026-08-09

This is a **CLI arm**, and guide §11 decision 11 (2026-08-07) settled that **CLI reachability is an
M3 criterion, not an M1 one** — the CLI reaches the engine over XPC, which M3 builds. #0115 and
#0124 were re-milestoned M1 → M3 for exactly this reason at the time; this issue was filed before
that decision and kept its original label.

Its engine half is already done: #0042 merged the `reference-transaction` decision core, which is
the part that can exist without the CLI. What remains here is the arm that calls it, and that
cannot land before M3's XPC surface.

## Blocked on #0217 — 2026-08-17

This issue's own Notes say where the arm lives "is a planning-time decision that must be settled with
the M3 XPC design, not improvised by a round". Working the M3 queue reached that decision and it does
not have one defensible answer: routing a `reference-transaction` hook over XPC means a background
`git fetch` launches a GUI app, and refusing to launch means the journal silently loses entries
whenever the app is closed.

**#0217 states the three readings and recommends one.** Not dispatched until it is answered.
