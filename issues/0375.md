## Description

Brennan, 2026-09-12, filed from the M7 planning questions. One deliverable: the sheet behind #0359's
**Split…** item, where the user picks which change becomes a new commit.

### What the engine needs (*measured* from source, `2d96d3e`)

- `Split.run(commit:hunkID:first:second:signing:at:git:extraEnvironment:)` in
  `YardKit/Sources/YardGit/Split.swift`. `hunkID` names the **one** hunk that becomes the new, older
  first commit; every other hunk stays in the second. `first` / `second` are `String?`, and `nil`
  keeps the commit's original message. It refuses fewer than two hunks (`.nothingToDo`) and a stale
  id (`.unknownHunkID`).
- The ids come from `commitDiff` — the same call `loadCommitDiff(at:revision:)` makes for the Detail
  pane (`YardKit/Sources/YardUI/RepositoryLoader.swift`). `Split.run` re-lists them fresh, so an id
  from the sheet's own load is what it resolves.
- `FileDiff` (`YardKit/Sources/YardGit/Hunks.swift`): `path`, `oldMode`, `newMode`, `isBinary`,
  `headerText`, `hunks`. `Hunk`: `id` (12 hex characters of SHA-256 over path and body), `path`,
  `oldStart`, `oldCount`, `newStart`, `newCount`, `header`, `body`. Both have public memberwise-style
  initialisers.
- For a merge commit, `loadCommitDiff`'s doc says it returns an empty list (#0341). The sheet then
  shows its "nothing to split" state.

### `YardKit/Sources/YardUI/SplitChoice.swift` (new, *compiled*)

Compiled and tested in a scratch worktree of `main` at `61c94aa` (`swift test --filter plan` →
`Test run with 8 tests in 2 suites passed`); nothing from it is committed.

```swift
import Foundation
import YardGit

/// #0375: the arguments the Split sheet hands to `Split.run`.
public nonisolated struct SplitArguments: Equatable, Sendable {
    public let commit: String
    public let hunkID: String
    /// `nil` keeps the original message, `Split.run`'s own default.
    public let firstMessage: String?
    public let secondMessage: String?

    public init(commit: String, hunkID: String, firstMessage: String?, secondMessage: String?) {
        self.commit = commit
        self.hunkID = hunkID
        self.firstMessage = firstMessage
        self.secondMessage = secondMessage
    }
}

/// #0375: the Split sheet's state, pure so every rule is testable.
public nonisolated struct SplitChoice: Equatable, Sendable {
    public let commit: String
    public let originalMessage: String
    /// Every hunk the commit introduces, in file order then hunk order --
    /// the listing `Split.run` resolves `hunkID` against (`commitDiff`).
    public let hunks: [Hunk]
    public var selectedHunkID: String?
    public var firstMessage: String
    public var secondMessage: String

    public init(commit: String, message: String, files: [FileDiff]) {
        self.commit = commit
        self.originalMessage = message
        self.hunks = files.flatMap(\.hunks)
        self.selectedHunkID = nil
        self.firstMessage = message
        self.secondMessage = message
    }

    /// Why the sheet cannot split at all; `nil` when it can.
    public var unavailableReason: String? {
        hunks.count < 2 ? "This commit has only one change, so there’s nothing to split." : nil
    }

    /// `nil` until a listed hunk is selected and both messages are non-empty.
    public var arguments: SplitArguments? {
        guard unavailableReason == nil,
              let id = selectedHunkID, hunks.contains(where: { $0.id == id }),
              !firstMessage.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty,
              !secondMessage.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty
        else { return nil }
        return SplitArguments(
            commit: commit, hunkID: id,
            firstMessage: firstMessage == originalMessage ? nil : firstMessage,
            secondMessage: secondMessage == originalMessage ? nil : secondMessage)
    }
}
```

*Measured* passing, on hand-built `FileDiff`/`Hunk` values:

- one hunk → `unavailableReason` is "This commit has only one change, so there’s nothing to split."
  and `arguments == nil`;
- two hunks in two files → `hunks` ids `["h1", "h2"]`, no reason, and `arguments == nil` until a
  selection;
- a stale selection `"stale"` → `nil`;
- selecting `"h2"` with messages unchanged → `SplitArguments(commit: "c", hunkID: "h2", firstMessage: nil, secondMessage: nil)`;
- editing the first message to `"Just b\n"` → `firstMessage: "Just b\n"`;
- a whitespace-only second message → `nil`.

### The sheet — `YardKit/Sources/YardUI/SplitCommitSheet.swift` (new, *not compiled*)

- **Presentation**: `.sheet(item:)` from `ContentView` when #0359's Split… is chosen. Title
  "Split Commit", with the commit's subject beneath in `.secondary`. Minimum size 640 × 480.
- **Loading**: a `ProgressView` while `loadCommitDiff` runs. On failure, the error message in place
  of the list, with only **Close**.
- **Hunk list**: `List(selection: $choice.selectedHunkID)`, one `Section(file.path)` per file. Each
  row shows the hunk's `header` in monospaced caption `.secondary`, then its first three `+`/`-`
  lines in monospaced caption, each `.lineLimit(1)`. A binary file shows one disabled row, "Binary
  file — can’t be split". Above the list: "The change you select becomes a new commit just before
  the rest."
- **Messages**: two labelled `TextEditor`s with `.font(.body.monospaced())` — "New commit (the
  selected change)" bound to `firstMessage`, and "Remaining changes" bound to `secondMessage`. Both
  are pre-filled with the original message.
- **Buttons**: **Cancel** (`.cancelAction`, Esc) and **Split** (`.keyboardShortcut(.return,
  modifiers: .command)`, because plain Return belongs to the editors), disabled while
  `choice.arguments == nil`. When `unavailableReason` is non-nil, the list and editors are replaced
  by that sentence, and only **Close** remains.
- **Running**: dismiss the sheet, then run through #0359's runner. `CommitActionRequest.split` gains
  `first: String?` and `second: String?`, passed to `Split.run(commit:hunkID:first:second:at:)`.
  #0359's busy state, failure alert and refresh apply unchanged. Afterwards #0359's
  `RewriteSelection` keeps the chain index, which selects the second half — the remaining changes.
