## Description

**Two proposals from #0044's fourth umbrella review, 2026-08-17.** Both are dead weight left behind by
guide §11 decision 20, and both were measured.

### 1. The per-worktree carry-through in `JournalRestore`'s `candidate` is dead

```swift
refs: recorded.withoutPerWorktreeRefs.refs
    + current.refs.filter { WorktreeContext.isPerWorktree($0.name) }
```

Removing the `+ current.refs.filter { … }` term leaves the suite **green**. It existed to stop deletion
planning removing the caller's own per-worktree refs as "extras" — and **decision 20 removed deletion
planning entirely**, so there is nothing left for it to protect against.

Removing it also closes something the **second** umbrella review recorded and did not file: there are
**two independent copies of the per-worktree namespace set** — `RefSnapshot.perWorktreeNamespaces` and
the literal inside `WorktreeContext.isPerWorktree`. Deleting the second reader closes the drift risk by
removing the duplication rather than by adding a test to keep the copies in sync, which is the better
of the two fixes.

**Careful:** the suite being green after a deletion is exactly the evidence that would *also* appear if
the behaviour were simply untested. Before removing it, establish which it is — find the test that
covers the caller's per-worktree refs surviving a restore (`theRecordedWorktreesPrivateRefsAreNotWritten
IntoOurs` and `aForeignEntryRestoresUnderTheOverrideAndLeavesOurPrivateRefsAlone` are the candidates)
and say whether it exercises this term. **If nothing covers it, the finding is a missing test, not dead
code**, and this issue changes shape.

### 2. `JournalUndo.traverse` duplicates `JournalWorktreeScope`'s worktree key

The first umbrella review recorded this and did not file it. The key lives in two files, and mutating
the copy in `JournalUndo.traverse` reddens exactly one test — `undoWalksOnlyThisWorktreesEntries`. Fold
it into `JournalWorktreeScope` so there is one implementation.

## Expected behavior

- [ ] Part 1: establish whether the term is dead or untested, and say which. Then either remove it —
      with the suite green and `theRecordedWorktreesPrivateRefsAreNotWrittenIntoOurs` still passing —
      or add the missing test and leave it.
- [ ] Part 2: one implementation of the worktree scoping key, with `undoWalksOnlyThisWorktreesEntries`
      still reddening when it is broken.
- [ ] Mutation for each: for part 1, whichever way it goes, show a test that fails when the caller's
      per-worktree refs are **not** preserved; for part 2, break the single implementation and confirm
      the same test dies.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.
