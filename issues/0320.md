# 0320 — CommitLog's refs field is truncated by log.excludeDecoration

## Description

**Finding 3 of the M1 milestone review, thirteenth pass, 2026-08-18.** `CommitLogEntry.refs` is silently
truncated by `log.excludeDecoration`.

`YardKit/Sources/YardGit/CommitLog.swift:154` (`%D` in `formatString`), reached from `:164`. **Measured
through the engine**, with tag `v1` on `HEAD`:

```
PROBE refs default:            HEAD -> main, tag: v1
PROBE refs excludeDecoration:  HEAD -> main
```

`%D` obeys `log.excludeDecoration`; the engine passes no `--decorate-refs` or
`-c log.excludeDecoration=`, and no test sets the config.

**Lower blast radius than #0318 and #0319** — the config is uncommon — but the same class, and `refs` is
a documented payload field an agent reads.

## Expected behavior

- [ ] `CommitLog.run` passes `-c log.excludeDecoration=` (the empty value clears any user setting).
      **Confirm that is the right neutralising form** rather than assuming — measure it, since an empty
      value behaving as "exclude nothing" is the assumption the fix rests on.
- [ ] A named test setting `log.excludeDecoration=refs/tags/*` on the fixture and asserting `refs` still
      carries `tag: v1`.
- [ ] **Verify the config bites first**: plain `git log --format=%D` under it must omit the tag.
- [ ] **Mutation:** drop the `-c`. The new test must redden.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, above the count in `docs/test-baseline.txt`.
