## Description

The restore flow: apply a journal entry's snapshot to the repository, guarded, honestly reported —
the engine behind `restore <checkpoint>`, and the core #0169's undo/redo traverse through. The
verbs are M3; this is the engine function only.

**Structured stub, split from #0034 on 2026-08-08.** Re-authored to code level at its own
planning pass before dispatch, per CLAUDE.md. The design below is #0034's, binding.

## The design — bound by #0034 (Decisions 3, 4, 5)

`YardKit/Sources/YardGit/JournalRestore.swift`, shape to be finalized at the planning pass:

```swift
public enum JournalRestore {
    public enum Piece: String, Sendable { case refs, head, index, worktree, untracked }
    public struct Omission: Sendable, Equatable {
        public let piece: Piece
        public let reason: Reason        // .notCaptured | .restoreUnavailable (until #0171)
    }
    /// What happened: what was restored, what could not be and why, and the
    /// pre-restore checkpoint written so the restore is itself undoable.
    public struct Report: Sendable, Equatable {
        public let entry: JournalAnchor.Entry
        public let restored: [Piece]
        public let notRestored: [Omission]
        public let checkpoint: JournalAnchor.Entry
    }
    public static func restore(
        _ id: JournalEntryID,
        operation: String = "restore",           // #0169 passes "undo"/"redo"
        traversal: JournalChain.Traversal? = nil, // #0169 passes its record
        allowDifferentWorktree: Bool = false,
        bypassGuard: Bool = false,
        in context: WorktreeContext,
        git: GitProcess = GitProcess()
    ) throws -> Report
}
```

The order, inside `JournalLock.withLock` (#0032) — **nothing mutates before step 4**:

1. Resolve the entry (`JournalAnchor.list`), read its metadata (#0155 decode) and refs blob
   (`cat-file blob <anchor-ref>:refs` → `RefSnapshot(serialized:)`, #0165).
2. **Worktree check** (#0034 Decision 5): the recorded worktree must be the calling context's,
   or `allowDifferentWorktree` — otherwise a typed error naming both, exit class 6.
3. **The cross-tool guard** (#0031, #0034 Decision 4):
   `CrossToolGuard.requireUnchanged(since: recorded, in: context)` unless `bypassGuard`. The
   union comparison; on refusal the thrown `repositoryChanged` carries every divergence, exit
   class 6, **and nothing has been written** — no checkpoint entry, no ref moved.
4. The pre-restore checkpoint: `JournalCheckpoint.checkpoint(operation:traversal:)` (#0167) —
   a normal entry for explicit restore (resets the cursor: #0034 Decision 2 truncation), a
   traversal entry when #0169 passes its record.
5. `RefSnapshot.restore(in:)` (#0027, merged — HEAD first alone, then one atomic ref
   transaction), then build the `Report` from the metadata's `captured` map: refs/head restored;
   index/worktree/untracked listed in `notRestored` (`.notCaptured` today; `.restoreUnavailable`
   is the transitional reason if an entry captured by a post-#0171 build is restored by a
   pre-#0171 one — the planning pass settles whether that case is representable).

## Expected behavior (to be authored to code level)

- [ ] `YardKit/Sources/YardGit/JournalRestore.swift`: the flow above; typed errors conform to
      `ExitClassCarrying` (#0141); every process call through `GitProcess`.
- [ ] Round trip: checkpoint → mutate refs (`git` directly: branch created, branch moved, HEAD
      detached) → restore → `RefSnapshot.capture` equals the checkpointed capture, including the
      **deletion** of a ref created after the checkpoint (#0027's union restore).
- [ ] Guard refusal: mutate a ref between capture and restore with a *stale* recorded snapshot —
      restore throws `repositoryChanged` naming the ref, **and** the journal gained no entry and
      no ref moved (the nothing-mutated criterion, asserted on both).
- [ ] Worktree refusal: an entry recorded in a linked worktree refuses restore from the main one
      without `allowDifferentWorktree`; with it, refs restore and HEAD applies to the caller.
- [ ] The report is honest: `restored == [.refs, .head]`, `notRestored` names the other three
      pieces with reasons, and the pre-restore checkpoint id is returned.
- [ ] `YardKit/Tests/YardGitTests/JournalRestoreTests.swift` gains the tests, parameterized over
      both ref formats; the diff lists exactly two files.
- [ ] `swift test` prints a `Test run with N tests` line; N must exceed the branch's pre-change
      count by the exact delta the planning pass states.
- [ ] A mutation table, every row applied and observed red with the killing test named — one row
      must drop the guard call and be killed by the guard-refusal test.
