## Description

The right pane: for a selected commit, its metadata, message, trailers, signature status, and diff
rendered per file and per hunk. For the working tree, the staged and unstaged changes.

This is read-only in M3. It becomes the surface that the three-way merge (#0057) and review sheet
(#0055) build on in M4, so its diff rendering should be factored for reuse rather than inlined.

## Re-scoped 2026-08-18 for the MVP

CLAUDE.md's priority section makes the app MVP the only priority until there is a demo. Four bullets
moved out, and one is **impossible as written** and needs saying:

- **"Renames shown as renames rather than as a delete plus an add" cannot be done from `commitDiff`.**
  Both it and `listHunks` pin `--no-renames`, for a measured reason (#0267): a rename puts two
  different paths on the `diff --git` line and the reconstructed patch stops being something
  `git apply` accepts. So the diff **will** show a rename as a delete plus an add. If the pane should
  say otherwise it needs a second, separate source — `gitStatus` does report renames, since #0329
  pinned `status.renames=true`. **Out of scope here; file it if you want it.**
- **Large-diff and large-file responsiveness → deferred**, no issue yet. Render what `commitDiff`
  returns; a hundred-file commit being slow is an MVP-acceptable gap.
- **"Diff rendering factored for reuse by M4"** → keep it a separate `View` in its own file, which is
  the whole of what that meant in practice. No protocol, no abstraction layer.
- **Working-tree staged/unstaged rendering → stays as it is.** #0339's status list already occupies
  this pane; see the first bullet below.

## Expected behavior

- [ ] The Detail pane shows **the commit selected in the History pane** — `ContentView` already holds
      that selection as `@State private var selectedCommit: String?`, keyed on `oid`.
- [ ] **When nothing is selected, it keeps showing today's working-tree status list.** That is the
      #0339 behaviour and it must not regress; the commit view is an addition, not a replacement.
- [ ] Commit metadata from the already-loaded `CommitLogEntry`: `subject`, the full `message`, `author`,
      `shortOid`, `refs` when non-empty, `signatureStatus`, and **`trailers` surfaced distinctly** —
      agent provenance is recorded precisely so a human can see it.
- [ ] The diff below it, from **`commitDiff(at:revision:)`** (`Hunks.swift`, added by #0341), rendered
      per file and per hunk: the file path, then each hunk's `header` and `body` lines, with added and
      removed lines visually distinguished. Monospaced.
- [ ] **Binary files are reported, not rendered** — `FileDiff.isBinary` is the flag.
- [ ] **A merge commit shows an explicit note, not an empty pane.** `commitDiff` returns nothing for a
      merge (measured, #0341; decision pending in #0342), and a blank pane reads as "this changed
      nothing". One line of text is enough: that merge diffs are not shown yet.
- [ ] The engine call runs **off the main actor**, via a `@concurrent` loader beside the two in
      `RepositoryLoader.swift`. `YardUI` sets `.defaultIsolation(MainActor.self)` and `commitDiff`
      shells out to `git` synchronously.
- [ ] A `YardUITests` test for the loader: a `FixtureRepository` commit's diff comes back with the
      expected file path and hunk count. Assert values, not non-nil.
- [ ] Light and dark both correct; no hardcoded colours.
- [ ] `cd YardKit && swift test` twice, foreground, 900000 ms timeout, both green, above
      `docs/test-baseline.txt` (1160), and the unsigned `xcodebuild build` from #0339 exits 0.

## Placement — settled 2026-08-07

Every view and everything around it goes in **`YardKit/Sources/YardUI/`**, the package target created
by **#0126**. Not in the Xcode project.

The Xcode project keeps only the `@main` `App` type, the asset catalog, `Info.plist`, entitlements,
`SMAppService` registration, and the embedded `switchyard` binary.

**Why it matters for this issue specifically:** a view in the app target can only be exercised by a UI
test, and UI tests cannot run under CLI-driven `xcodebuild` on this machine — the runner times out
enabling automation mode without Accessibility rights. Anything built here would ship untested. In
`YardUI` it is reachable from `swift test`.

`YardUI` sets `.defaultIsolation(MainActor.self)`, so views are main-actor isolated exactly as they
are in the app target today.

Tests go in `Tests/YardUITests` and import **without** `@testable`, so they see what the app sees.
