## Description

**Filed by #0043's review on 2026-08-08.**

`PostRewrite.parse` must return **every** old→new pair the hook reports — a rebase of N commits
yields N pairs, and a mapping that silently loses commits is worse than none, because the journal
and the UI both trust it to follow a commit across a rewrite.

Review probed the claim two ways: `parse` truncated to `rewrites.prefix(1)`, and to
`rewrites.suffix(1)`. **Both go red** — so the claim is genuinely tested.

**But it rests entirely on two end-to-end tests.** Every unit-level parse test feeds single-line
input, or input yielding exactly one valid rewrite, so **a truncating parser passes all eight of
them.** The completeness guarantee currently depends on the e2e rebase fixture continuing to run.
If that fixture ever becomes unrunnable — a git version change, a slow-test quarantine, a CI
environment without the sequence editor — truncation ships silently and nothing says so.

## What this issue must deliver

- **A `parse` unit test over multi-line stdin** asserting `rewrites.count == 3` and the exact
  pairs, in order, with no repository involved.
- **A mutation row per truncation direction** — `prefix(1)` and `suffix(1)` — each observed red
  **against the new unit test specifically**, not merely red somewhere in the suite. That is the
  point: the guarantee must survive the e2e tests being unavailable.
- Keep the e2e tests. They prove the hook contract against real git; this proves the parser against
  its own input. Neither substitutes for the other.

Expected: **+1 test**.

## While here

`#0043` shipped three bare `Equatable` conformances — `Rewrite`, `ParseResult` and `Decision`.
Review removed all three and the suite stayed green. `Source` and `Replacement` are asserted (via
`== .amend` and a `groups == […]` comparison); these three are not. Not urgent — `Equatable` is
cheap and #0160 will compare these — but it is the same unasserted-conformance shape as **#0181**
(`ExitClassCarrying`, 9 of 26 bare) and **#0182** (`CustomStringConvertible`). **If #0181's registry
mechanism generalises to a third protocol, fold this in there instead of testing three types by
hand** — and say so rather than duplicating a scanner.

## Notes

`PostRewrite.swift` deliberately carries **no** `ExitClassCarrying` conformance: `decide` is total,
and per #0141 a post-rewrite hook that can fail is a hook that can break a rebase. That absence is
correct and should not be "fixed" by a future pass tidying conformances.

**The gap re-confirmed by reading the tests, not assumed.** Every existing `parse` test feeds input
yielding exactly **one** rewrite:

| test | input |

So `parse` returning `rewrites.prefix(1)` — or `suffix(1)` — satisfies all four. #0043's review

The fixture constants `oidA`, `oidB`, `oidC` already exist at the top of the test file, so the new
test needs no new fixtures.

## Change 1 — `YardKit/Tests/YardGitTests/PostRewriteTests.swift`, append one test

Append after `parseHandlesSixtyFourCharOids`. **Append; do not rewrite the file** (Rule 5c).

```swift
/// Completeness, at the unit level. Every existing `parse` test feeds input
/// yielding exactly one rewrite, so a parser truncated to `prefix(1)` or
/// `suffix(1)` satisfies all of them — #0043's review measured that both
/// truncations are caught, but ONLY by the two end-to-end rebase tests. A
/// mapping that silently loses commits is worse than none: the journal and
/// the UI both trust it to follow a commit across a rewrite.
@Test func parseReturnsEveryRewriteNotJustTheFirstOrLast() throws {
    let stdin = "\(oidA) \(oidB)\n\(oidB) \(oidC)\n\(oidC) \(oidS)\n"
    let result = PostRewrite.parse(Data(stdin.utf8))

    #expect(result.malformedLineCount == 0)
    #expect(result.rewrites.count == 3)
    #expect(result.rewrites == [
        PostRewrite.Rewrite(oldOid: oidA, newOid: oidB),
        PostRewrite.Rewrite(oldOid: oidB, newOid: oidC),
        PostRewrite.Rewrite(oldOid: oidC, newOid: oidS),
    ])
}
```

The equality assertion pins **order** as well as membership, so a parser that reverses or reorders
is caught too — a set comparison would not be.
