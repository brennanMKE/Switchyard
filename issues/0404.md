# 0404 — Commit changes window: changed files on the left, diffs on the right

| | |
|---|---|
| **Status** | open |
| **Module** | YardUI, Switchyard (app target) |
| **Milestone** | M9 |
| **Platform** | macOS |
| **First seen** | 2026-09-22 |

## Description

A commit's diff moves out of the detail pane (#0403) into a window of its own. Brennan: *"I would
have it pop up another window which lists the files which changed in a left column and diffs to the
right. If I click on a file on the left it should scroll to focus that file in the diff view on the
right."*

## Expected behavior

- [ ] Double-clicking a node in the graph opens a commit changes window for that commit.
- [ ] The **Show Changes** button in the detail pane (#0403) opens the same window.
- [ ] The window's left column lists every changed file, with the path and a change kind (added,
      modified, deleted or renamed).
- [ ] The right side shows every file's diff in one scrolling view, in the same order as the list.
- [ ] Clicking a file in the left column scrolls the right side so that file's diff is at the top.
- [ ] The window title names the commit (short SHA and subject). Opening the same commit again
      focuses its existing window instead of opening a duplicate.

## Notes

The existing `FileDiffView` rendering is reused for the right side. The planning pass decides
between a new `WindowGroup(for:)` scene in the app target keyed by the commit, and an in-process
`NSWindow`. Views stay in `YardUI` (guide §11 decision 10); only the scene declaration can live in
`Switchyard/`.
