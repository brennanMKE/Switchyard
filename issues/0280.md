## Description

**Finding 5 of the M1 milestone review, sixth pass, 2026-08-18, and the sharpest of the eight.**
`gitStatus` is **never exercised on a tracked change**, so the porcelain format it depends on is
unpinned.

`YardKit/Sources/YardGit/WorktreeStatus.swift:429`, mutated:

```swift
var args: [String] = ["status", "--porcelain=v1", "-z"]    // was: --porcelain=v2
```

`Test run with 1078 tests in 78 suites passed after 58.484 seconds.` — **full suite, unfiltered.**

**Why it survives, and why that is alarming.** `GitStatusTests`' fixtures contain only **untracked and
ignored** files, whose v1 (`? path`, `! path`) and v2 records are byte-identical — so the format
downgrade is invisible. **With any tracked modification present, v1 emits ` M path` and
`WorktreeStatusParser` throws `unrecognizedRecordType`**: `gitStatus` would fail outright on an
ordinary dirty repository.

The same thinness shows in the data: through `gitStatus`, `entry.staged` is only ever `.unmodified`
(`GitStatusTests.swift:40`, `:65`), and `pathBytes`, `originalPath`, `originalPathBytes` and
`submodule` are never asserted from it at all.

**`WorktreeStatusTests` does cover those — but it bypasses `gitStatus` entirely**, calling
`git.capture([...])` and feeding `WorktreeStatusParser` directly (`:35, 83, 112, 379, 405`). So the
parser is well covered and the *engine function* is not. #0245 added `GitStatusTests` for exactly this
reason; the fixture it added never reaches a tracked file.

      redden, which is what shows it asserts the states rather than merely their presence.
