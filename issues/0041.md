## Description

**Hook installation is a user decision, not something `yard` does silently.** Repositories often
already have hooks, or use `core.hooksPath` pointing at a managed directory that a team controls.
Clobbering either would be a serious breach of trust in a tool that is otherwise asking to be run
unsupervised.

## Expected behavior

- [ ] Detects existing hooks and `core.hooksPath` before writing anything.
- [ ] **Chains rather than clobbers** — an existing hook still runs, and its exit status is honored.
- [ ] `hooks uninstall` fully reverses installation, restoring any prior hook exactly.
- [ ] `hooks status --json` reports what is installed, what is chained, and what is missing.
- [ ] Never installs implicitly as a side effect of another command.
- [ ] Everything degrades to polling when hooks are declined — no command hard-requires them.
