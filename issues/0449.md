## Description

Found by the #0066 planner. `CommandSpec` has flags but no positional-argument metadata, so
arguments such as `<commit>` in `reword <commit> --message <m>` reach `--help` and
`skills/switchyard/SKILL.md` only through each command's exit-code-1 text. An agent reading the
skill has to infer the argument shape from an error description.

**Planned 2026-09-29 (Opus planning pass).** Everything below was built and run in a throwaway
worktree off `main` at `423f8769`: the whole change compiled, the full `swift test` passed, and
every mutation in *Mutations* was applied and seen to fail the named tests. Nothing here is from
memory.

## Expected behavior

One deliverable: **every `CommandSpec` carries a `usage` synopsis, and every surface that renders a
spec prints it.**

- [ ] `CommandSpec` gains `public let usage: String` (init parameter `usage: String = ""`, placed
      after `summary`) — Edit 1.
- [ ] All 30 entries in `CommandRegistry.all` carry the literal usage in Edit 2.
- [ ] `renderHelp`, `renderSkillSection` and `renderSchema` print it — Edits 3–5.
- [ ] `SchemaEmitterTests` updated for the new schema key — Edit 6.
- [ ] New `YardKit/Tests/YardKitTests/CommandUsageTests.swift` — Edit 7 — which fails if any
      registered command has an empty usage, or a positional-taking command's usage omits a
      positional.
- [ ] `YardKit/Schemas/*.json` (30 files) and `skills/switchyard/SKILL.md` regenerated **by the
      commands in Edit 8, never by hand**.

## Givens (all verified 2026-09-29)

1. **Format.** `usage` is the synopsis *after the program name*, beginning with `spec.name`
   (`reword <commit> --message <message> [--sign | --no-sign]`). Renderers prepend
   `ServiceNames.cliName` — the CLI name is never hardcoded in a usage string (CLAUDE.md:
   `ServiceNames` is the single source of truth). The one exception to "begins with `spec.name`"
   is `switchyardSpec`, whose usage is `[--help | --version | <command> [<arguments>]]`, rendered as
   `switchyard [--help | …]`. Notation: `<positional>`, `[optional]`, `(a | b)` alternatives,
   `...` repeatable. Every `--flag` in a usage is one of that spec's `flags`, written
   `--long <argument>` exactly as `FlagSpec.argument` names it.
2. **The default `usage: String = ""` is deliberate.** 14 hand-built specs in
   `HelpRendererTests`, `SchemaEmitterTests` and `CommandSpecTests` construct `CommandSpec`
   without it and must keep compiling unchanged. The registry is policed by
   `CommandUsageTests.everyCommandHasAUsage`, not by the compiler. An empty usage renders no
   `Usage:` line in help or the skill, and `"usage": ""` in the schema.
3. **Every usage string was derived from the parser and checked against the binary.** Run from a
   directory that is not a git repository, so an *accepted* argument shape reaches the engine and
   fails with exit 4/6 (`repository_error` / not a repo), while a *refused* one exits 1 (`usage`)
   before any repository access. `yard-engine` covers every engine command; the four arms
   (`review`/`ask`/`resolve`/`watch`) are intercepted by `dispatch` and exist only in
   `switchyard`, so only their refusals were run (an accepted shape would reach for the broker —
   not done). Measured:

   | `log main..HEAD a b` | 6 | `log [<range>...]` |

### Edit 7 — new file `YardKit/Tests/YardKitTests/CommandUsageTests.swift`

Verbatim (compiled and run):

```swift
// CommandUsageTests.swift — every registered command carries its synopsis (#0449)

import Foundation
import Testing
@testable import YardKit

/// The positionals each command's own parser accepts, read from the parsers
/// and confirmed by running `yard-engine`/`switchyard` with missing and extra
/// arguments on 2026-09-29 (issues/0449.md, Given 3). The table is the
/// independent source: a usage that drops one of these fails the test below.
private let positionalPlaceholders: [String: [String]] = [
    "log": ["<range>"],
    "verify": ["<revision>"],
    "split": ["<commit>", "<hunkID>"],
    "reword": ["<commit>"],
    "drop": ["<commit>"],
    "reorder": ["<commit>"],
    "revert": ["<commit>"],
    "cherry-pick": ["<commit>"],
    "merge": ["<branch>"],
    "rewrite-diff": ["<journal-entry-id>"],
    "review": ["<range>"],
    "ask": ["<question>"],
    "resolve": ["<pathspec>"],
    "watch": ["<repository-path>"],
    "tag": ["<name>", "<commit>"],
    "branch": ["<name>", "<start>", "<old>", "<new>", "<upstream>"],
    "rebase-onto": ["<commit>"],
    "set-tip": ["<commit>"],
]

/// Every `--flag` token in a usage string.
private func usageFlags(in usage: String) -> Set<String> {
    let pattern = /--([a-z][a-z-]*)/
    return Set(usage.matches(of: pattern).map { String($0.output.1) })
}

@Suite("Command usage")
struct CommandUsageTests {

    @Test("every registered command has a non-empty usage that starts with its name")
    func everyCommandHasAUsage() {
        #expect(CommandRegistry.all.count >= 30, "an empty registry would make this test vacuous")
        for spec in CommandRegistry.all {
            #expect(!spec.usage.isEmpty, "\(spec.name) has an empty usage")
            if spec.name != ServiceNames.cliName {
                #expect(spec.usage == spec.name || spec.usage.hasPrefix(spec.name + " "),
                        "\(spec.name)'s usage must start with its name: '\(spec.usage)'")
            }
        }
    }

    @Test("every command that takes positionals names each of them in its usage")
    func positionalsAppearInUsage() throws {
        #expect(positionalPlaceholders.count == 18)
        for (name, placeholders) in positionalPlaceholders {
            let spec = try #require(CommandRegistry.lookup(name: name), "\(name) is not registered")
            for placeholder in placeholders {
                #expect(spec.usage.contains(placeholder),
                        "\(name)'s usage '\(spec.usage)' does not name \(placeholder)")
            }
        }
    }

    @Test("a usage names exactly its command's flags, each with its argument")
    func usageAndFlagsAgree() {
        for spec in CommandRegistry.all {
            #expect(usageFlags(in: spec.usage) == Set(spec.flags.map(\.long)),
                    "\(spec.name): usage flags \(usageFlags(in: spec.usage).sorted()) != spec flags \(spec.flags.map(\.long).sorted())")
            for flag in spec.flags {
                let rendered = flag.argument.map { "--\(flag.long) <\($0)>" } ?? "--\(flag.long)"
                #expect(spec.usage.contains(rendered),
                        "\(spec.name): usage '\(spec.usage)' does not contain '\(rendered)'")
            }
        }
    }

    @Test("--help prints the usage line")
    func helpPrintsUsage() throws {
        let reword = try #require(CommandRegistry.lookup(name: "reword"))
        #expect(renderHelp(for: reword).contains(
            "\nUsage: \(ServiceNames.cliName) reword <commit> --message <message> [--sign | --no-sign]\n"))
        let top = renderHelp(for: CommandRegistry.switchyardSpec)
        #expect(top.contains("\nUsage: \(ServiceNames.cliName) [--help | --version | <command> [<arguments>]]\n"))
        let bare = CommandSpec(name: "bare", summary: "", flags: [], exitCodes: [], schemaName: "")
        #expect(!renderHelp(for: bare).contains("Usage:"), "an empty usage prints no Usage line")
    }

    @Test("every skill section carries its command's usage line")
    func skillSectionsCarryUsage() {
        for spec in CommandRegistry.all {
            #expect(renderSkillSection(for: spec).contains(
                        "\nUsage: `\(ServiceNames.cliName) \(spec.usage)`\n"),
                    "\(spec.name)'s skill section has no usage line")
        }
    }
}
```
