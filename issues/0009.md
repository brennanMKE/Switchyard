## Description

This is why worktrees are in M1 rather than a later milestone. Every git path resolution in the
codebase has to go through one context object, and adding it later means auditing every call site
that ever touched a git path — the definition of a retrofit nobody finishes.

`WorktreeContext` is resolved once per invocation and holds the worktree path, `$GIT_DIR`,
`$GIT_COMMON_DIR`, and the worktree id. In a linked worktree, `.git` is a *file* containing a
`gitdir:` pointer, `$GIT_DIR` is `<main>/.git/worktrees/<name>`, and `$GIT_COMMON_DIR` is
`<main>/.git`. Which one a given path uses depends on the ref name, so it cannot be guessed.

## Expected behavior

- [ ] Context resolved via `git rev-parse --git-dir --git-common-dir --show-toplevel`, never by string concatenation.
- [ ] Correct in the main worktree, in a linked worktree, and in a bare repository.
- [ ] Per-worktree refs of another worktree are reachable via `worktrees/<name>/HEAD` and `main-worktree/HEAD`.
- [ ] Tests build a real linked worktree and assert `$GIT_DIR` and `$GIT_COMMON_DIR` differ as documented.
- [ ] Grep confirms no `.git/` string concatenation anywhere in the package.

## Notes

Git internals §5 "The layout, precisely". Blocked by #0006. Blocks #0012 and every read command.

**Never read `$GIT_DIR` with `FileManager`** — reftable, index format variants, and worktrees each
break naive parsing independently. See `CLAUDE.md`.

## Fix

`WorktreeContext` resolves `topLevel`, `gitDir`, `commonDir`, and `worktreeName` from `rev-parse`,
canonicalizing every path so `/var` and `/private/var` cannot become two identities for one
repository. `path(for:)` delegates to `rev-parse --git-path` so the `$GIT_DIR` vs `$GIT_COMMON_DIR`
choice is git's, and `resolveRef(_:inWorktree:)` uses git's `main-worktree/` and `worktrees/<name>/`
prefixes to read another worktree's per-worktree refs.

## Verification

`swift test` — **36 tests in 5 suites passed**. Worktree coverage builds a real linked worktree and
asserts `$GIT_DIR` and `$GIT_COMMON_DIR` differ, that `.git` there is a *file* not a directory, that
both share `$GIT_COMMON_DIR` (the repository identity #0079 keys tabs on), and that cross-worktree
`HEAD` resolves in both directions. Also covers a subdirectory, a bare repo, a reftable repo, and a
non-repository.

## Gotchas

**A `DispatchGroup` deadlocked the whole suite.** `GitProcess` originally drained stdout and stderr
on a concurrent queue and blocked on `group.wait()`. That starves Swift concurrency's cooperative
thread pool once swift-testing runs tests in parallel — the suite hung for over seven minutes with no
git subprocess alive. Fixed by sending stderr to a temporary file, leaving one pipe and no blocking
wait. **Invisible with a single test; only parallelism exposes it.**

**`rev-parse --show-toplevel` fails in a bare repository** rather than printing nothing, so asking
for it in the same invocation as `--git-dir` made every bare repo look like "not a repository". It
is now a separate call whose failure is meaningful.

**`--git-path` returns an uncanonicalized path.** Comparing it against a canonicalized `gitDir`
fails on `/var` vs `/private/var`. Both sides must go through the same canonicalization.
