## Description

**Proposals 2 and 3 of the M1 milestone review, eighth pass, 2026-08-18.** Two test-file hygiene items,
one of which costs real review time.

### A force-unwrap takes the whole run down and names no test

`YardKit/Tests/YardGitTests/WorktreeWhereTests.swift:229` — `result.mainWorktreePath!` inside
`linkedGitDirDiffersFromCommonInRefFormats`. Under a #0284-class mutation (dropping `-z`) that unwrap
finds nil and **crashes the test process**:

```
Fatal error: Unexpectedly found nil while unwrapping an Optional value
```

The run aborts, **names no test, and every other suite in that run goes unreported.** The eighth pass
had to re-run filtered to discover that `newlineInLinkedWorktreePathDoesNotCorruptParsing` was the
intended casualty and that the pin was in fact intact.

**This is `AGENTS.md` Rule 7b's territory** — *bind with `try #require`, never with `if let`* — extended
to the force-unwrap case, and the cost is specific: **a mutation whose failure is unattributable is a
mutation that teaches nothing.** Same shape at `:201` and `:215`.

### A wire test now asserts what the type system guarantees

`YardKit/Tests/YardWireTests/WorktreeRemoveWireTests.swift:18,28` — its docstring names `refusal`,
`lockReleased` and `hadToForce` as members that "must NOT appear" in the JSON, and
`#expect(!json.contains("\"lockReleased\""))` still runs. **#0290 deleted all three members**, so the
assertion can no longer fail for the reason it was written.

Harmless, and worth correcting while someone is in the file: the docstring now describes code that does
not exist, which is the shape #0290 itself was filed against.

## Expected behavior

- [ ] The three force-unwraps at `WorktreeWhereTests.swift:201`, `:215`, `:229` become
      `try #require(...)`, so a nil fails **that test** by name instead of aborting the process.
- [ ] **Check the rest of the test targets for the same pattern** — `grep -rn '!$' ` is too noisy, so
      look for `)!` and `]!` on optional results in test bodies. Report what you found and what you
      changed; if there are many, fix the ones in `YardGitTests` and say what you left.
- [ ] `WorktreeRemoveWireTests`'s docstring is corrected to say those members no longer exist. **Decide
      whether the assertions still earn their place** — they pin that the wire shape excludes those
      *keys*, which a future re-addition of a computed property with `CodingKeys` could reintroduce —
      and say which way you went.
- [ ] **Demonstrate the fix**: re-run the #0284 mutation (drop `-z` at `WorktreeWhere.swift:54`) and show
      that the run now **names the failing tests** rather than aborting. That is the whole point of the
      issue and it is directly checkable.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, at or above the count in `docs/test-baseline.txt` (this issue may add no tests — say so
      explicitly if the count is unchanged).
