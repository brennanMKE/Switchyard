# 0232 — Two-agent undo deadlocks after the first step

| | |

## Description

**Found by the third #0044 umbrella review, 2026-08-17, and measured.** In a two-agent repository —
the usage #0044 exists to support — agent A's **second** undo is refused, and stays refused, because
of an ordinary commit by agent B in B's own worktree on B's own branch.

```
PROBE first undo ok
PROBE sibling commit exit=0 [agent-branch e9bdaa8] sibling work
PROBE second undo FAILED: repository changed since capture:
  refs/heads/agent-branch was 75644410…, now e9bdaa8b…
```

A's **first** undo succeeds only because its scoped cursor is nil, so the cross-tool guard is skipped
entirely. Once A is mid-traversal the cursor is non-nil, the guard runs against a
**repository-wide** snapshot diff, and every further step of A's walk is refused with a divergence
naming a ref A does not control and cannot act on. There is no non-force way out, and `bypassGuard`
has no CLI surface until M3.

## Why this is filed as a consequence rather than a violation

Decision 1 says the chain is per-worktree precisely so that one agent's work does not disturb
another's traversal. Decision 3 **explicitly endorses** the guard catching a sibling's move ("is
caught from any worktree"). So the umbrella records both halves and does not say what happens when
they meet — which is this. No stated criterion is violated; the criteria are jointly incomplete.

## The shape of an answer

Two candidates, and the choice is a design decision rather than a bug fix:

- **Scope the guard's diff to what the applied snapshot would actually write.** A divergence in a ref
  the restore will not touch is not evidence that the caller's world changed under it. This preserves
  the guard's purpose — catching a tool that moved something the journal is about to restore — while
  letting siblings work.
- **Keep the guard repository-wide and make the refusal actionable**: say which divergences belong to
  a sibling worktree, name that worktree, and say what to do. Weaker, but it does not narrow a safety
  check on the strength of one measurement.

The first is the better shape and also the riskier change, because the guard is what stands between
the journal and a tool that moved refs behind its back.

## Expected behavior

- [ ] The question above answered and recorded in guide §11.
- [ ] Whichever way: a test in the two-agent shape — A undoes twice while B commits in between — that
      pins the chosen behaviour. The probe above is the fixture.
- [ ] If the guard is scoped, a test that a divergence in a ref the snapshot **does** write is still
      refused. Narrowing a safety check without pinning what it still catches is how it stops catching
      anything.
