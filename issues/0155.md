## Description

The typed entry-metadata shape — what one journal entry records. #0028 settled *where* it lives:
verbatim bytes in the `metadata.json` blob of every snapshot commit's tree, written and read as
opaque `Data` by `JournalAnchor.write`/`JournalAnchor.metadata(for:)`, recoverable from refs alone
via `git cat-file blob <anchor-ref>:metadata.json`. This issue owns the shape of those bytes.

**Structured stub, split from #0028 on 2026-08-07.** Re-authored to code level at its own planning
pass before dispatch, per CLAUDE.md.

## The shape — decided at #0028's planning pass, binding

Git internals §3 "Entry shape", with two deliberate deviations recorded there and here:
`snapshotRef` is dropped (derivable — it is the anchor ref the reader just resolved; it lives in
the journal.json *cache* row instead, where it is genuinely informative), and `worktree.id`
is `worktree.name` (`WorktreeContext.worktreeName`, nil for the main worktree).

```json
{
  "schemaVersion": 1,
  "id": "01K1H8R100W7CBVX5TRJJEDDVM",
  "operation": "fixup",
  "command": "switchyard fixup HEAD~2",
  "timestamp": "2026-08-07T18:22:31Z",
  "worktree": { "name": "agent-a", "path": "/Users/b/src/proj-agent-a" },
  "captured": { "refs": true, "head": true, "index": "tree", "worktree": "stash", "untracked": true },
  "guard": { "HEAD": "abc123...", "refs/heads/main": "def456..." },
  "agent": { "name": "claude-code", "session": "01J8W..." }
}
```

`captured` is what lets `undo` report honestly what it can and cannot restore. `guard` is what
makes it safe (#0031 compares it before restoring). Both are load-bearing, not decoration — and
both must survive the refs-only rebuild (#0030), which is exactly why the whole shape rides inside
the anchored commit rather than only in `journal.json`.

## Measured facts to build on

- ISO 8601 `Codable` strategies drop sub-second precision (measured at #0029's planning pass,
  Given 4: encoding `Date(timeIntervalSince1970: 0.5)` → `"1970-01-01T00:00:00Z"`, decodes to
  `0.0`). Whole-second timestamps round-trip exactly; the entry id already carries milliseconds.
- Encoding must be deterministic for a given entry (`.sortedKeys`), because #0035's round-trip
  suite will compare metadata bytes.
