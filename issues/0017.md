# 0017 — Report conflicted files with per-stage blob ids

## Description

The structured form of what an agent otherwise has to scrape out of conflict markers in the working
tree: every conflicted path in the index, what kind of collision it is, and the blob id and mode of
each index stage that exists — base (stage 1), ours (stage 2), theirs (stage 3). Blob ids rather
than inline text so the caller can fetch exactly the version it needs, and so the three-way merge
UI (#0057) has something precise to open.

**One deliverable:** the engine function `conflictedFiles(at:git:)`, its result type
`ConflictedFile`, and the pure parser `ConflictParser` in
`YardKit/Sources/YardGit/Conflicts.swift`, with tests in
`YardKit/Tests/YardGitTests/ConflictsTests.swift`. The implementation is written out below — type
it in as given. The work of this round is the test file.

This issue is **engine only**. No CLI command, no `CommandSpec`, no exit-code behavior — see Notes.

## Givens — each one measured on `main` 2026-08-07 (git 2.50.1), treat as true

1. **The data source is `git status --porcelain=v2 -z`, whose `u` records carry everything at
   once** — the conflict kind (XY), the mode of each stage, and the three stage oids, one
   NUL-terminated record per conflicted path. Measured on a two-file content conflict (both sides
   edited `f.txt` and `g.txt` from a common base — the exact shape
   `FixtureRepository.conflictedTwo()` builds):

   ```
   u UU N... 100644 100644 100644 100644 334adba7b261109f0ebd5347d491172b3ad52f7d f08b71eba2bad1b394def9febc40e93c6f577888 1e76667a4a9713d4d2674161d6d24b470b45176c f.txt
   u UU N... 100644 100644 100644 100644 57f03579cd39347f92dac550409e9d7d549e5130 9d1d692acc299b7b2d06fee7e52759e022bc3f09 e25e12abf313096c29676bc10bd44d25b99472c0 g.txt
   ```

   Token layout after the leading `u`: `<XY> <sub> <m1> <m2> <m3> <mW> <h1> <h2> <h3> <path>` —
   **ten space-delimited tokens including the tag, then the path**, which may itself contain spaces
   and is therefore everything after the tenth space, not a split token. `m1/h1` are stage 1
   (base), `m2/h2` stage 2 (ours), `m3/h3` stage 3 (theirs), `mW` the worktree mode.

2. **A delete/modify conflict has no entry for the deleting side.** Measured: base holds `d.txt`,
   ours deletes it, theirs modifies it; the merge emits XY `DU` with `m2` = `000000` and `h2` = the
   zero oid:

   ```
   u DU N... 100644 000000 100644 100644 bbc0b0106f7e59ad4145e1de7d0224a49429db88 0000000000000000000000000000000000000000 7764d9cc1d20df4d1637da07bc23a34d156c1b69 d.txt
   ```

   An add/add conflict is the mirror image — no base. Measured, both sides adding `new.txt` with
   different content:

   ```
   u AA N... 000000 100644 100644 100644 0000000000000000000000000000000000000000 c45b56b79310e3543a1f03dca83fa5b301c8f517 62ded2e08c75450e63ac8d97f3a5c91bbeb47e35 new.txt
   ```

   So "stage absent" is signalled by mode `000000` (equivalently the all-zero oid), never by a
   missing token — the record always has all ten.

3. **`git ls-files -u` is the wrong tool for a per-path report**, because it emits one line per
   *stage entry* and the number of stages per path is not constant. Measured on a three-path
   fixture — `f.txt` and `g.txt` content conflicts (three stages each) plus the `d.txt`
   delete/modify above (two stages) — three paths produce **eight** lines:

   ```
   100644 bbc0b0106f7e59ad4145e1de7d0224a49429db88 1	d.txt
   100644 7764d9cc1d20df4d1637da07bc23a34d156c1b69 3	d.txt
   100644 334adba7b261109f0ebd5347d491172b3ad52f7d 1	f.txt
   100644 f08b71eba2bad1b394def9febc40e93c6f577888 2	f.txt
   100644 1e76667a4a9713d4d2674161d6d24b470b45176c 3	f.txt
   100644 57f03579cd39347f92dac550409e9d7d549e5130 1	g.txt
   100644 9d1d692acc299b7b2d06fee7e52759e022bc3f09 2	g.txt
   100644 e25e12abf313096c29676bc10bd44d25b99472c0 3	g.txt
   ```

   Grouping those lines and re-deriving the conflict kind from which stages are present would
   reimplement classification git already does in the `u` record's XY. Do not use `ls-files -u`.

4. **`git diff --name-only -z --diff-filter=U` lists each conflicted path exactly once**,
   NUL-terminated. On the two-file conflict the exact bytes are
   `66 2e 74 78 74 00 67 2e 74 78 74 00` (`f.txt\0g.txt\0`), and on the three-path fixture it
   lists `d.txt`, `f.txt`, `g.txt` once each — a true path count while `ls-files -u` shows eight
   lines. That is why `whereAmI` uses it for **counting**; it carries no stage or blob data, which
   is why it is not the source here.

5. **The engine already has two adjacent pieces; reuse the boundary, not the code.**
   - `WhereAmI.conflictCount` in `YardKit/Sources/YardGit/WhereAmI.swift` counts paths via the
     `diff --diff-filter=U` form above. It reports a count only — leave it alone; this issue's
     per-path result must agree with it by construction (both are one-per-path).
   - `WorktreeStatusParser` in `YardKit/Sources/YardGit/WorktreeStatus.swift` parses porcelain v2
     `u` records but **discards the modes and oids** — `WorktreeStatusEntry` has no stage fields.
     Do not modify `WorktreeStatus.swift` to add them; `Conflicts.swift` parses the `u` record
     itself. The one piece of its knowledge this issue inherits is the `2`-record rule in Given 6.
   - Every shell-out goes through `GitProcess` — a test asserts no other type in `YardGit`
     constructs a `Process`.
6. **A porcelain v2 `2` (rename) record carries a second NUL-terminated field** — the original
   path — so a NUL-split of the stream that ignores this would scan that field as a record of its
   own. A staged rename can coexist with conflicts in the same status output, and an original path
   can begin with `u ` (a file named `u orig.txt`), so `records(_:)` below consumes the extra
   field where `WorktreeStatusParser.splitRecords` does the same.
7. **During a rebase the sides swap; during a cherry-pick they do not.** Measured with base →
   `ours` / `theirs` both editing `f.txt`, then from a detached `ours`:
   - `git rebase <theirs>`: the `u UU` record's stage 2 blob is the **theirs** content (`theirs\n`)
     and stage 3 is `ours\n` — HEAD during a rebase is the onto side.
   - `git cherry-pick <theirs>`: stage 2 is `ours\n`, stage 3 is `theirs\n`.
   The function reports stages as git labels them; the rebase test below pins this down so nobody
   "fixes" it later.
8. **Conflict kinds are exactly the seven XY pairs git emits on `u` records**: `UU`, `AA`, `DD`,
   `AU`, `UA`, `DU`, `UD`. There is no rename kind — a rename conflict surfaces as add/delete/
   modify records at the paths involved, which is what git itself reports.
9. `FixtureRepository.conflicted()` and `.conflictedTwo()` already build merge-conflicted
   repositories (one path and two paths, both `UU`). The delete/modify, add/add, rebase, and
   cherry-pick shapes are not pre-built; the tests below construct them inline with
   `FixtureRepository` plus `GitProcess` calls, exactly as written.

## The deliverable — `YardKit/Sources/YardGit/Conflicts.swift`

```swift
// Conflicts.swift — conflicted paths with per-stage blob ids (#0017)

import Foundation

/// One conflicted path in the index, with the blob id and mode of every
/// index stage that exists for it.
///
/// Backed by the `u` records of `git status --porcelain=v2 -z`, which carry
/// the conflict kind, the three stage modes, and the three stage oids in a
/// single NUL-terminated record per path — one record per conflicted file,
/// however many stages it has.
public struct ConflictedFile: Sendable, Equatable {

    /// A blob id and file mode for one index stage.
    public struct StageEntry: Sendable, Equatable {
        /// Full object id of the blob, as git printed it.
        public let oid: String
        /// Octal mode string as git printed it, e.g. `"100644"`.
        public let mode: String

        public init(oid: String, mode: String) {
            self.oid = oid
            self.mode = mode
        }
    }

    /// How the two sides collided — the XY pair of the porcelain v2 `u`
    /// record. These seven values are the complete vocabulary git emits;
    /// there is no rename kind, because a rename conflict surfaces as
    /// add/delete/modify records at the paths involved.
    public enum Kind: String, Sendable, CaseIterable {
        case bothModified  = "UU"
        case bothAdded     = "AA"
        case bothDeleted   = "DD"
        case addedByUs     = "AU"
        case addedByThem   = "UA"
        case deletedByUs   = "DU"
        case deletedByThem = "UD"
    }

    /// Path relative to the repository root, decoded lossily as UTF-8.
    public let path: String

    /// Raw bytes of the path, losslessly preserved.
    public let pathBytes: [UInt8]

    public let kind: Kind

    /// Stage 1 — the merge base. Nil when that side has no entry, e.g. an
    /// add/add conflict.
    public let base: StageEntry?

    /// Stage 2 — ours. Nil when that side has no entry, e.g. deleted by us.
    /// During a rebase, git's "ours" is the side being rebased **onto**.
    public let ours: StageEntry?

    /// Stage 3 — theirs. Nil when that side has no entry.
    public let theirs: StageEntry?

    public init(path: String,
                pathBytes: [UInt8],
                kind: Kind,
                base: StageEntry?,
                ours: StageEntry?,
                theirs: StageEntry?) {
        self.path = path
        self.pathBytes = pathBytes
        self.kind = kind
        self.base = base
        self.ours = ours
        self.theirs = theirs
    }
}

/// Parses the `u` records out of `git status --porcelain=v2 -z` bytes.
///
/// Pure function on data — no `Process` construction, no filesystem access.
/// Records other than `u` are skipped. A malformed `u` record throws rather
/// than being dropped: silently losing a conflict is a correctness bug, not
/// a simplification.
public struct ConflictParser {

    public enum Failure: Error, Equatable, CustomStringConvertible {
        /// A `u` record had fewer than its ten fixed tokens, or no path.
        case truncatedRecord(String)
        /// A `u` record's XY pair was none of the seven git emits.
        case unrecognizedKind(xy: String, path: String)

        public var description: String {
            switch self {
            case let .truncatedRecord(record):
                "malformed porcelain v2 u record: \(record)"
            case let .unrecognizedKind(xy, path):
                "unrecognized conflict kind \"\(xy)\" for \(path)"
            }
        }
    }

    public init() {}

    public func parse(_ data: Data) throws -> [ConflictedFile] {
        var files: [ConflictedFile] = []
        for record in Self.records(data) {
            guard record.first == UInt8(ascii: "u") else { continue }

            // Fixed layout: `u <XY> <sub> <m1> <m2> <m3> <mW> <h1> <h2> <h3>
            // <path>` — ten space-delimited tokens including the tag, then
            // the path, which may itself contain spaces and is therefore
            // everything after the tenth space rather than a split token.
            var tokens: [String] = []
            var rest = record[record.startIndex...]
            for _ in 0..<10 {
                guard let space = rest.firstIndex(of: 0x20) else {
                    throw Failure.truncatedRecord(String(decoding: record, as: UTF8.self))
                }
                tokens.append(String(decoding: rest[..<space], as: UTF8.self))
                rest = rest[rest.index(after: space)...]
            }
            let pathBytes = Array(rest)
            guard !pathBytes.isEmpty else {
                throw Failure.truncatedRecord(String(decoding: record, as: UTF8.self))
            }
            let path = String(decoding: pathBytes, as: UTF8.self)

            guard let kind = ConflictedFile.Kind(rawValue: tokens[1]) else {
                throw Failure.unrecognizedKind(xy: tokens[1], path: path)
            }

            // Mode 000000 (equivalently the zero oid) means the side has no
            // stage entry — delete/modify has no ours, add/add no base.
            func stage(mode: Int, oid: Int) -> ConflictedFile.StageEntry? {
                guard tokens[mode] != "000000" else { return nil }
                return ConflictedFile.StageEntry(oid: tokens[oid], mode: tokens[mode])
            }

            files.append(ConflictedFile(
                path: path,
                pathBytes: pathBytes,
                kind: kind,
                base:   stage(mode: 3, oid: 7),
                ours:   stage(mode: 4, oid: 8),
                theirs: stage(mode: 5, oid: 9)))
        }
        return files
    }

    /// Splits porcelain v2 `-z` bytes into records. A `2` (rename) record
    /// carries a second NUL-terminated field — the original path — which is
    /// consumed with its record here, so a path that happens to begin with
    /// `u ` is never scanned as a record of its own.
    static func records(_ data: Data) -> [[UInt8]] {
        let bytes = [UInt8](data)
        var records: [[UInt8]] = []
        var i = 0
        while i < bytes.count {
            var end = i
            while end < bytes.count, bytes[end] != 0x00 { end += 1 }
            let record = Array(bytes[i..<end])
            i = end + 1
            guard !record.isEmpty else { continue }
            records.append(record)
            if record.first == UInt8(ascii: "2") {
                var skip = i
                while skip < bytes.count, bytes[skip] != 0x00 { skip += 1 }
                i = skip + 1
            }
        }
        return records
    }
}

/// Reports every conflicted path in the repository at `path`, in the order
/// git emits them (sorted by path). Empty when the index has no unmerged
/// entries. Works identically during a merge, a rebase, and a cherry-pick —
/// unmerged index stages are the same mechanism in all three.
public func conflictedFiles(
    at path: String,
    git: GitProcess = GitProcess()
) throws -> [ConflictedFile] {
    let output = try git.run(
        ["status", "--porcelain=v2", "-z"],
        workingDirectory: path
    )
    return try ConflictParser().parse(output.standardOutput)
}
```

## Tests — `YardKit/Tests/YardGitTests/ConflictsTests.swift`

`import Foundation`, `import Testing`, `@testable import YardGit`. Fixture-backed tests are
`@Test(arguments: FixtureRepository.RefFormat.supported())`, build their own fixture, and call
`repo.destroy()` in a `defer`. The three pure parser tests take no arguments and build no fixture.

Ten tests, by name:

1. **`contentConflictReportsAllThreeStages`** — `let repo = try
   FixtureRepository.conflictedTwo(refFormat: format)`. Call
   `conflictedFiles(at: repo.url.path)`. `#expect` `files.map(\.path) == ["f.txt", "g.txt"]`;
   for the first entry `kind == .bothModified`; unwrap `base`, `ours`, `theirs` with
   `try #require`; all three modes are `"100644"`; and pin the blob ids to real content via
   `GitProcess`: `cat-file -p <base.oid>` prints `"original f\n"`, ours `"ours f\n"`, theirs
   `"theirs f\n"` (the fixture writes exactly those bytes).
2. **`deleteModifyReportsNoOursStage`** — build inline:
   ```swift
   var repo = try FixtureRepository(refFormat: format)
   defer { repo.destroy() }
   try repo.build([.init("base", files: ["d.txt": "original d\n", "keep.txt": "keep\n"])])
   try repo.build([.init("theirs", parents: ["base"], files: ["d.txt": "theirs d\n"])])
   let git = GitProcess()
   try repo.checkoutDetached(repo.oids["base"]!)
   try git.run(["rm", "-q", "d.txt"], workingDirectory: repo.url.path)
   try git.run(["commit", "-qm", "ours deletes d"], workingDirectory: repo.url.path)
   ```

   ```swift
       + "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa "
       + "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb R100 renamed.txt"
   let originalPath = "u orig.txt"

       + "f08b71eba2bad1b394def9febc40e93c6f577888 "
   ```

   `#expect(files.map(\.path) == ["f.txt"])` and the entry's three stage oids equal the three in

9. **`truncatedURecordThrows`** — pure parser.
   `let data = Data("u UU N... 100644\u{0}".utf8)`, then

10. **`unrecognizedKindThrows`** — pure parser. The Given 1 `f.txt` record with its XY replaced by
