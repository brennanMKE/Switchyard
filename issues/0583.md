## Description

`Rewrite.reword` (Edit Message…, `switchyard reword`) rebuilds the commit with `git commit-tree`
and passes no author, so **the reworded commit's author becomes the current user, dated now**. The
descendants are replayed with `cherry-pick`, which does keep their authors — only the reworded
commit itself is affected.

`git commit-tree` takes the author from `GIT_AUTHOR_NAME` / `GIT_AUTHOR_EMAIL` / `GIT_AUTHOR_DATE`
and otherwise from the current identity and the current time. Measured 2026-10-05 (git 2.54.0): a
commit authored `Carol 1640995200 +0000`, rebuilt with `commit-tree <its tree> -p <its parent>` and
no environment, came back authored `Current User 1791233853 -0700`. `git commit --amend` and
GitUp's rewrites keep the author; a rewrite that silently re-attributes someone else's commit to
the user is wrong, and on a shared branch it misattributes work.

The fix carries the original commit's author into the rebuild through `StoredCommit` (#0581), which
parses `git cat-file commit` into `GIT_AUTHOR_*`.

`cherry-pick`, which refuses an **empty** commit ("The previous cherry-pick is now empty") —
measured while writing this test; see #0580's observations.
