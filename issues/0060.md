# 0060 — Decide and implement the rebase engine scope

| | |
|---|---|
| **Status** | open |
| **Module** | YardGit |
| **Milestone** | M5 |
| **Platform** | macOS |
| **First seen** | 2026-08-06 |

## Description

GitUp wrote its own rebase engine because stock libgit2's is not sufficient for interactive-style
history rewriting. M5's commands need something similar — but how much of one, and can `absorb` and
`split` be built on narrower primitives instead?

This is an open question in guide §11 and needs a written decision before the M5 commands are built,
not during.

## Expected behavior

- [ ] The minimum primitive set M5 actually requires is enumerated.
- [ ] Options compared: stock libgit2 rebase, shelling out to `git rebase`, a purpose-built engine.
- [ ] Decision recorded in `docs/` with reasoning, including what it costs each M5 command.
- [ ] Guide §11 updated to move this from open to settled.
