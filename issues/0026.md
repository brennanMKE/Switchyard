## Description

M1's deliverable is not just working commands — it is a **fixed, documented JSON contract** that
agents can rely on. Schemas are derived from the command metadata (#0010) so they cannot drift, and
`schemaVersion` is what lets a consumer detect a shape change instead of crashing on one.

## Expected behavior

- [ ] New file `YardKit/Sources/YardKit/SchemaExport.swift`. Create it; do not restructure existing files.
- [ ] `yard schema --json` emits schemas for every command from the metadata source.
- [ ] Schemas are committed to `docs/` so they are reviewable in a diff.
- [ ] A test fails when a command's response shape changes without `schemaVersion` being bumped.
- [ ] Every documented error code appears in at least one schema.
- [ ] The versioning policy — what constitutes a breaking change — is written down.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N must be greater than the count on `main` before this change.

## Notes

Guide §6 "Design principles" and §9 M1. Blocked by #0010, #0011.

This is the gate for calling M1 done. An undocumented contract is not a contract.

**Target placement:** `yard` is an `executableTarget`, so `@testable import yard` does **not** link in
SwiftPM — anything that needs unit tests must live in the `YardKit` library target. This was found
the hard way on #0085, whose round burned itself discovering the link error. Only `main.swift` and
code that genuinely cannot be unit-tested belong in `Sources/yard/`.
