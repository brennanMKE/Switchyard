## Description

M1's exit criterion (guide §9): *"The response schemas are documented and versioned (#0026)."* An
undocumented contract is not a contract — and a schema document that can silently diverge from what
the code emits is worse than none, because agents will trust it.

**The checkable artifact is a set of committed, generated schema files with a drift test.** A new
directory `YardKit/Schemas/` holds one `<schemaName>.json` per command in `CommandRegistry.all`,
generated by `renderSchema(for:)` — the same metadata source that builds `--help` and
`switchyard schema`, so the schema cannot drift from the binary: a test re-renders every schema on
each `swift test` run and fails on any byte difference. The schema gains an `envelope` section
describing the success and failure response shapes, and companion tests assert those declared
shapes against a **real encoded** `Envelope` and `EnvelopeFail` — so the schema cannot describe an
envelope the code does not emit, in either direction. The versioning policy is a written rule in
`YardKit/Schemas/README.md`, pasted verbatim below.

One honesty note, so nobody chases the old criterion: *"a test fails when the shape changes without
`schemaVersion` being bumped"* is not mechanically achievable — no test can classify a change as
breaking. What is achievable, and what this builds: **a test fails when the shape changes without
the checked-in schema being regenerated**, which forces every shape change through a reviewable
diff, where the written rule decides whether the version bumps. The registry currently holds two
commands (`switchyard`, `noop`); because the tests iterate `CommandRegistry.all` and reject both
missing and orphan files, every command registered later (the M1 read commands arrive in the
registry with M3's wiring, §11 decision 11) is forced to ship its schema file or the suite is red.

**One deliverable:** the drift-tested schema contract — a literal edit to
`YardKit/Sources/YardKit/SchemaEmitter.swift`, three literal edits to
`YardKit/Tests/YardKitTests/SchemaEmitterTests.swift`, the new test file

## Change 1 — `YardKit/Sources/YardKit/SchemaEmitter.swift`, two literal edits

Add one line to the `payload` dictionary, directly under `"command": spec.name,`:

```swift
        "envelope": envelopeShapes(schemaName: spec.schemaName),
```

Add this function above `private enum SchemaError` at the bottom of the file:

```swift
/// The two response shapes every command shares: the success envelope and the
/// failure envelope. Emitted into each command's schema so one schema file
/// describes that command's full stdout contract on its own. The key sets
/// declared here are asserted against a real encoded `Envelope` and
/// `EnvelopeFail` in `SchemaGoldenTests` — the schema cannot describe an
/// envelope the code does not emit.
nonisolated func envelopeShapes(schemaName: String) -> [String: Any] {
    [
        "failure": [
            "error": [
                "code": [
                    "enum": EnvelopeErrorCode.allCases.map(\.rawValue).sorted(),
                    "type": "string",
                ],
                "hint": ["optional": true, "type": "string"],
                "message": ["type": "string"],
            ],
            "ok": false,
            "schemaVersion": EnvelopeSchema.v1.rawValue,
        ],
        "success": [
            "ok": true,
            "result": ["optional": true, "schema": schemaName],
            "schemaVersion": EnvelopeSchema.v1.rawValue,
        ],
    ]
}
```

## Change 3 — `YardKit/Tests/YardKitTests/SchemaGoldenTests.swift`, new file, in full

```swift
// SchemaGoldenTests.swift — the drift gate for the checked-in schema contract (#0026)

import Foundation
import Testing
@testable import YardKit

/// `YardKit/Schemas/`, resolved from this file's compile-time path:
/// `Tests/YardKitTests/SchemaGoldenTests.swift` → up three → package root.
private let schemasDirectory = URL(fileURLWithPath: #filePath)
    .deletingLastPathComponent()   // YardKitTests
    .deletingLastPathComponent()   // Tests
    .deletingLastPathComponent()   // YardKit (package root)
    .appendingPathComponent("Schemas", isDirectory: true)

/// Parses the emitted schema for a spec back into a dictionary.
private func schemaObject(for spec: CommandSpec) throws -> [String: Any] {
    let text = try renderSchema(for: spec)
    let object = try JSONSerialization.jsonObject(with: Data(text.utf8))
    return try #require(object as? [String: Any], "schema must be a JSON object")
}

/// Top-level key set of a JSON object given as text.
private func topLevelKeys(ofJSON text: String) throws -> Set<String> {
    let object = try JSONSerialization.jsonObject(with: Data(text.utf8))
    let dictionary = try #require(object as? [String: Any], "expected a JSON object")
    return Set(dictionary.keys)
}

@Suite("Schema golden files")
struct SchemaGoldenTests {

    /// The drift gate. Every command in the registry must have a checked-in
    /// schema file that byte-matches what the code emits right now. Set
    /// SCHEMA_REGENERATE=1 to rewrite the files after an intentional change —
    /// see Schemas/README.md for the versioning rule that applies to the diff.
    @Test("every registered command's checked-in schema byte-matches the emitter")
    func checkedInSchemasMatchEmitter() throws {
        #expect(!CommandRegistry.all.isEmpty, "an empty registry would make this test vacuous")
        let regenerate = ProcessInfo.processInfo.environment["SCHEMA_REGENERATE"] == "1"
        for spec in CommandRegistry.all {
            let url = schemasDirectory.appendingPathComponent("\(spec.schemaName).json")
            let emitted = try renderSchema(for: spec) + "\n"
            if regenerate {
                try emitted.write(to: url, atomically: true, encoding: .utf8)
            }
            let checkedIn = try String(contentsOf: url, encoding: .utf8)
            #expect(checkedIn == emitted,
                    "Schemas/\(spec.schemaName).json no longer matches the code. If the change is intentional, regenerate with SCHEMA_REGENERATE=1 swift test --filter checkedInSchemasMatchEmitter and apply Schemas/README.md's versioning rule to the diff.")
        }
    }

    @Test("the schema directory holds exactly one file per registered command")
    func noOrphanSchemaFiles() throws {
        let onDisk = try FileManager.default.contentsOfDirectory(atPath: schemasDirectory.path)
            .filter { $0.hasSuffix(".json") }
            .map { String($0.dropLast(".json".count)) }
            .sorted()
        let expected = CommandRegistry.all.map(\.schemaName).sorted()
        #expect(!expected.isEmpty, "an empty registry would make this test vacuous")
        #expect(onDisk == expected,
                "Schemas/ must hold exactly the registry's schemas — stale: \(Set(onDisk).subtracting(expected)), missing: \(Set(expected).subtracting(onDisk))")
        #expect(FileManager.default.fileExists(
                    atPath: schemasDirectory.appendingPathComponent("README.md").path),
                "Schemas/README.md carries the versioning policy and must exist")
    }

    @Test("checked-in schemas carry the current envelope version")
    func checkedInSchemasCarryTheCurrentVersion() throws {
        for spec in CommandRegistry.all {
            let url = schemasDirectory.appendingPathComponent("\(spec.schemaName).json")
            let object = try JSONSerialization.jsonObject(with: Data(contentsOf: url))
            let dictionary = try #require(object as? [String: Any])
            #expect(dictionary["schemaVersion"] as? Int == EnvelopeSchema.v1.rawValue,
                    "Schemas/\(spec.schemaName).json must declare the current schemaVersion")
        }
    }

    /// Binds the schema to reality: the success shape the schema declares must
    /// have exactly the keys a real encoded `Envelope` produces.
    @Test("declared success keys match a real encoded envelope")
    func successShapeMatchesRealEnvelope() throws {
        let schema = try schemaObject(for: CommandRegistry.noopSpec)
        let envelope = try #require(schema["envelope"] as? [String: Any], "schema must declare the envelope shapes")
        let success = try #require(envelope["success"] as? [String: Any])
        let real = try topLevelKeys(ofJSON: jsonString(Envelope(result: EncodableResult("x"))))
        #expect(Set(success.keys) == real,
                "schema declares \(success.keys.sorted()); the code emits \(real.sorted())")
        #expect(real.contains("schemaVersion"))
    }

    /// Same binding for the failure shape, plus the closed error-code set:
    /// every code in `EnvelopeErrorCode` appears in the schema's enum.
    @Test("declared failure keys match a real failure envelope, and the error-code enum is the closed set")
    func failureShapeMatchesRealEnvelope() throws {
        let schema = try schemaObject(for: CommandRegistry.switchyardSpec)
        let envelope = try #require(schema["envelope"] as? [String: Any], "schema must declare the envelope shapes")
        let failure = try #require(envelope["failure"] as? [String: Any])

        let realText = jsonString(EnvelopeFail(code: .usage, message: "m", hint: "h"))
        let real = try topLevelKeys(ofJSON: realText)
        #expect(Set(failure.keys) == real,
                "schema declares \(failure.keys.sorted()); the code emits \(real.sorted())")

        let declaredError = try #require(failure["error"] as? [String: Any])
        let realObject = try JSONSerialization.jsonObject(with: Data(realText.utf8))
        let realDictionary = try #require(realObject as? [String: Any])
        let realError = try #require(realDictionary["error"] as? [String: Any])
        #expect(Set(declaredError.keys) == Set(realError.keys))

        let codeField = try #require(declaredError["code"] as? [String: Any])
        let declaredCodes = try #require(codeField["enum"] as? [String])
        #expect(declaredCodes == EnvelopeErrorCode.allCases.map(\.rawValue).sorted(),
                "every EnvelopeErrorCode must appear in the schema's enum, sorted")
    }

    /// Negative control: the key-set comparison above must be able to fail.
    /// An envelope missing `schemaVersion` must not match the declared shape.
    @Test("an envelope missing schemaVersion does not match the declared success shape")
    func wrongEnvelopeIsRejected() throws {
        let schema = try schemaObject(for: CommandRegistry.noopSpec)
        let envelope = try #require(schema["envelope"] as? [String: Any])
        let success = try #require(envelope["success"] as? [String: Any])
        let wrong = try topLevelKeys(ofJSON: #"{"ok":true,"result":{}}"#)
        #expect(Set(success.keys) != wrong,
                "a wrong envelope matching the schema means the comparison is vacuous")
    }
}
```

```markdown
# Response schema contract — version 1

The `.json` files in this directory are the versioned contract for every `switchyard` command's
stdout. One file per command, named `<schemaName>.json`, generated by `renderSchema(for:)` in
`Sources/YardKit/SchemaEmitter.swift` from the same `CommandRegistry` metadata that builds
`--help` and `switchyard schema` — the schema cannot drift from the binary because both are
renderings of one source.

They are generated, committed, and **drift-tested**:
`SchemaGoldenTests.checkedInSchemasMatchEmitter` re-renders every schema from the code on each
`swift test` run and fails on any byte difference, and the companion tests assert that the
envelope shapes declared here match what a real encoded `Envelope`/`EnvelopeFail` actually emits.
A shape change therefore cannot land silently: the suite is red until the file is regenerated,
and the regenerated file's diff is what review reads.

To regenerate after an intentional change:

    SCHEMA_REGENERATE=1 swift test --filter checkedInSchemasMatchEmitter

then commit the changed files in the same commit as the code change that caused them.

## What `schemaVersion: 1` covers

One number, envelope-wide. There are no per-command versions: every envelope from every command
carries the same `schemaVersion`, and an agent checks it once per response. Version 1 promises:

- The envelope keys and types — `schemaVersion` (int), `ok` (bool), `result` (object, success
  only, may be omitted), `error` (object, failure only, with `code`, `message`, and optional
  `hint`).
- The closed set of `error.code` strings, and that each pairs with the process exit status the
  same way `EnvelopeErrorCode.exitCode` does.
- Each command's result payload shape, named by its `schemaName`.

## What is a breaking change

Breaking — requires bumping the version:

- Removing or renaming any key an agent can currently read, in the envelope or in a payload.
- Changing a key's JSON type, or changing what an existing enum string means.
- Removing an `error.code` string, or changing the exit code it pairs with.
- Making a previously always-present key optional.

Not breaking — the version stays where it is:

- Adding a new optional key to a payload or to the envelope.
- Adding a new command, a new `error.code` string, or a new enum value agents can ignore.
- Text-only changes to `summary`, `help`, or `meaning` strings.

An additive change still fails the drift test and still regenerates the schema file. The version
number is a promise about compatibility, not a hash of the bytes: classifying a change as
breaking or additive is review's job, and the drift test's job is to make sure review sees every
change.

## What happens at version 2

`EnvelopeSchema` gains `case v2 = 2`, every envelope emits the new number simultaneously, and the
version-1 files move to `Schemas/v1/` and freeze — they document what agents pinned to 1 were
promised. There is no dual emission and no negotiation: an agent that reads `schemaVersion: 2`
and only knows version 1 must treat the response as unparseable rather than guess.
```

### The property this issue exists to establish, and the proof it holds

The schema had to be bound to what the code **encodes**, not merely to the emitter that describes it.
Mutation 4 renames a wire key in `Envelope.swift` only: the golden drift test stays **green**, because
the emitter's description was untouched and the bytes still match, while both cross-checks go **red**
against the real encoded envelope.

At review I applied the inverse — renaming the key in the emitter only — and got the mirror image:
golden **red** and cross-checks **red**. The two families are therefore independent rather than
redundant, and between them no single-sided change can pass.
