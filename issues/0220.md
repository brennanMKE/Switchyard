## Description

**Child of #0160, split 2026-08-17.** A **foreign** rewrite — `git commit --amend` or `git rebase` run
by someone who is not `switchyard` — becomes an **observed** entry, the class #0153 defined for foreign
ref transactions, so `undo` never offers to revert it.

`PostRewrite.decide` (#0043) already turns one hook invocation into a `Decision` carrying `source`
(`.amend`/`.rebase`/`.unrecognized`), `isOwnInvocation`, the ordered `[Rewrite]` mapping, and a
malformed-line count. This issue persists the `isOwnInvocation == false` case. Attaching an **own**
invocation's mapping to its in-flight journal entry is #0221.

## The payload shape — settled here, 2026-08-17

`JournalObserved.Metadata` (`JournalObserved.swift:26`) carries exactly one payload field today:

```swift
public let updates: [ReferenceTransaction.RefUpdate]
```

A rewrite is not a ref update — `PostRewrite.Rewrite` is an old→new **commit** pair with an optional
`extraInfo` (`PostRewrite.swift:61`) — so the shape has to grow a second kind. Of the three readings
#0160 listed, take the **discriminator, added additively**:

```json
{"schemaVersion":1,"kind":"ref_updates","updates":[…]}
{"schemaVersion":1,"kind":"rewrites","source":"rebase","rewrites":[{"oldOid":"…","newOid":"…"}]}
```

- `kind` is a new **required** key on both shapes; an existing reader that only looks at `updates` is
  unaffected, so no `schemaVersion` bump is needed and none should be made. The format is days old and
  reaches no agent yet — `refs/switchyard/observed/` is not exposed through any command.
- One namespace, not two. A second ref namespace would keep each metadata shape single-purpose and cost
  a second `list` on every read, for a distinction the `kind` key already makes.
- `source` is `PostRewrite.Source`, encoded as its git argument — `"amend"`, `"rebase"`, or the raw
  string for `.unrecognized`. **Do not drop an unrecognized source**: a future git verb the parser does
  not know is exactly the case where a record is worth having.
- `extraInfo` is emitted only when present.

Model the two kinds as an `enum Payload` with a `CodingKeys`-driven `encode(to:)`, or as a `kind` plus
two optionals — either is acceptable, but say which and why, and keep `Metadata: Equatable, Encodable`
as it is today.

## Expected behavior

- [ ] `JournalObserved` records a foreign `Decision` as an observed entry carrying `kind`, `source`,
      and the ordered old→new pairs, in the order `PostRewrite.parse` produced them. Order is part of
      the contract — a rebase's mapping is a sequence, not a set.
- [ ] Only `isOwnInvocation == false` decisions land here. An own invocation writes **nothing** in this
      issue (#0221 owns it) — assert that, so the two halves cannot both fire once #0221 lands.
- [ ] **Only the final `rebase` invocation is authoritative.** Measured in #0043's Givens on git 2.50.1:
      squash/fixup/reword steps raise extra `amend` invocations *mid-rebase* whose old oids are
      intermediate commits that never existed in the pre-rewrite history. A mid-rebase `amend` must not
      produce its own observed entry. Detect it the way git itself exposes the state — a rebase is in
      progress when `git rev-parse --git-path rebase-merge` exists — and **measure that this holds
      during a `post-rewrite` amend invocation** before relying on it; if it does not, say so and report
      what you measured instead of working around it.
- [ ] **Persistence failure never surfaces as a non-zero hook exit.** #0043's totality invariant holds
      through this layer: every write is best-effort and its failure is swallowed, exactly as
      `JournalObserved.record`'s `@discardableResult` callers in the hook path already do (#0191). Test
      it by making the write fail — a read-only `$GIT_DIR`, or an injected `GitProcess` pointing at a
      failing binary — and asserting the decision's `exitCode` is still 0.
- [ ] `cd YardKit && swift test` prints `Test run with N tests` where **N is greater than** the count in
      `docs/test-baseline.txt` at dispatch (932 on 2026-08-17). State the delta.
- [ ] The wire bytes are pinned in `YardWireTests`, as `JournalObserved`'s current shape already is —
      both kinds, sorted keys, byte-exact.

## Measured during planning — 2026-08-17, git 2.50.1. The mid-rebase discriminator works.

A `post-rewrite` hook logging `$1`, whether `$(git rev-parse --git-path rebase-merge)` exists, and its
stdin, over: one plain `git commit --amend`, then a `git rebase --autosquash` carrying one `fixup!`.
Verbatim log, three invocations:

```
post-rewrite arg1=amend no-rebase-merge
8072a06… 7add8b3…
---
post-rewrite arg1=amend REBASE_MERGE_EXISTS
dacdc1a… c0f6e0b…
---
post-rewrite arg1=rebase REBASE_MERGE_EXISTS
dacdc1a… c0f6e0b…
7add8b3… c0f6e0b…
3f56085… 7a97551…
```

Three facts to build on, none of which need re-deriving:

1. **The discriminator holds.** A plain amend reports `no-rebase-merge`; the mid-rebase amend reports
   `REBASE_MERGE_EXISTS`. So "skip an `amend` invocation while a rebase is in progress" is a real,
   cheap test — one `git rev-parse --git-path` and a `FileManager` existence check on **that resolved
   path**, never a string built from `.git/` (CLAUDE.md's rule).
2. **Skipping loses nothing.** The mid-rebase amend's pair `dacdc1a… → c0f6e0b…` appears again in the
   final `rebase` invocation, alongside the pairs only that invocation has. The final invocation is a
   superset here, which is what makes it authoritative rather than merely last.
3. **The final `rebase` invocation carries a pair whose old oid is an intermediate commit** — the one
   the mid-flight amend created — exactly as #0043's Givens recorded. Store it as reported; deciding
   which old oids existed in the pre-rewrite history needs the entry's snapshot and belongs to the
   consumer, not the writer.

The fixture is three commits and one `fixup!`; reproduce it rather than trusting these oids, which are
from one run.
