## Description

**Proposal B from #0160's fourteenth umbrella pass, 2026-08-18 — a full-suite survivor on #0043's
parser surface, which is why it is filed separately rather than against #0160.**

`YardKit/Sources/YardGit/PostRewrite.swift:161` splits each `post-rewrite` stdin line with
`omittingEmptySubsequences: false`. Flipping it to `true` leaves the whole suite green:

```
Test run with 1135 tests in 80 suites passed
```

**That flag is not cosmetic — it decides how a malformed line is classified.** A line with an
*internal* double space, `old␣␣new`, splits to `["old", "", "new"]` under `false` (three fields, and
`parse`'s `fields[1]` is the empty string, so it is rejected) and to `["old", "new"]` under `true`
(two fields, accepted as a well-formed rewrite pair). **The two settings disagree about whether that
input is a rewrite**, and nothing in the suite tells them apart.

**Why the existing test does not cover it:** `postRewriteParseDropsMalformedLinesAndCounts` uses a
*leading*-space line, which both settings reject — under `false` because `fields[0]` is empty (its
own guard, mutation 24, which does redden), and under `true` because the leading run is collapsed
away and the line has too few fields. A fixture that both settings reject pins neither.

## Expected behavior

- [ ] A named test feeding `PostRewrite.parse` a line with an **internal double space** between two
      oids, asserting it is classified as **malformed and dropped**, with the drop reflected in the
      count `parse` reports.
- [ ] **Mutation:** `omittingEmptySubsequences: false` → `true`. The new test must redden. Confirm it
      landed on the line you meant.
- [ ] **No production change is expected.** `false` is the current, correct behaviour and this issue
      pins it. If you conclude `true` is the better classification, **stop and say so in the issue
      rather than changing it** — that is a semantics decision, not this issue's deliverable.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, at or above the count in `docs/test-baseline.txt`.
