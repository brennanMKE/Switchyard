## Description

**Found by the second #0034 umbrella review, 2026-08-17, inside #0200's own edit.**

#0200 made `JournalRestore.restoreAssumingLock` capture four pieces at step 3 and pass them to the
pre-restore entry at step 7. Index and worktree are pinned by its two new round-trip tests. **The
sequencer third is pinned by nothing.**

Established by enumerating every `.sequencer` assertion in the test target: deleting `currentSequencer`
from `JournalRestore.swift` (its capture at step 3 and its argument at step 7) leaves **all 886 tests
green**. `UndoRoundTripSuiteTests` asserts `.merge` on an entry written by `JournalCheckpoint.checkpoint`
— not by the restore flow — and every other sequencer assertion is about the omissions list.

**Why it matters:** it is the same failure #0200 fixed, one piece over. Undo a mid-rebase operation and
the traversal entry records no sequencer; redo then restores refs, index and worktree but not the
rebase state, and reports `.sequencer` as `.notCaptured`. The interrupted rebase is gone with no entry
holding it — which is exactly what #0188 exists to prevent one layer up.

## Expected behavior

- [ ] One assertion added to a **mid-rebase** undo in
      `YardKit/Tests/YardGitTests/UndoRoundTripSuiteTests.swift`: read the traversal entry undo wrote
      and assert `captured.sequencer != .notCaptured`. Reuse that file's existing
      `repositoryStoppedMidRebase` helper — it already builds the fixture.
- [ ] Better, if it is no more work: extend it to a real round trip — undo mid-rebase, redo, and assert
      the rebase still resumes (`git rebase --continue` exits 0), the way
      `midRebaseSequencerRoundTripsThroughCheckpointAndRestore` does for checkpoint. State which you
      did and why.
- [ ] The mutation, **observed red**: delete `sequencer: currentSequencer` from the step-7
      `writeEntry` call. If it stays green the assertion is on the wrong entry — the one written by
      `checkpoint` rather than the one written by the restore flow, which is precisely how this gap
      arose.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt` by exactly 1. The delta is the criterion.

## Notes

**No production change.** #0200's code is correct; this is evidence, like #0178 item 1, #0192 and #0203.

The general lesson is worth carrying into planning rather than just fixing here: #0200's criteria named
index and worktree because its *finding* named index and worktree, and the third piece rode along
untested inside the same edit. **When a fix adds N things at one call site, the criteria have to name
all N** — the review that found this had to enumerate assertions across the whole test target to see it.
