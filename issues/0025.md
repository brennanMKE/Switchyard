## Description

A text notation for a commit DAG paired with its expected lane assignment, and a table-driven
suite of cases written in it, exercising `LaneAssigner.assign` (#0015, resolved).

**What the notation adds, honestly.** `LaneAssignmentTests.swift` already covers every case family
below with hand-built `GraphNode`/`GraphRow` arrays, so this suite adds no coverage the algorithm
lacks — it changes what a case *costs* and what a reader *sees*. In the notation, one line carries
a commit, its parents in order, and the expected lane of every edge, so a whole case is 4–7 short
lines whose expectation is visible next to its graph; the same case as literal arrays is ~15 lines
of constructor calls in two separate blocks. That cheapness is measured by this planning pass
itself: the six case families the old draft asked for became nine, because adding the extra three
cost a few lines each. The suite is also pure — octopus and branch-and-merge shapes are today
pinned only through fixture-backed tests that spawn real git; here they run in microseconds with
no subprocess. Deliberately small in exchange: one test file plus one short doc, no production
code, no separate fixture files.

**One deliverable:** the notation parser `DAGFixture`, the case suite, and the error tests, all in
`YardKit/Tests/YardGitTests/LaneAssignmentFixtureTests.swift`, with the notation documented in
`docs/dag-lane-notation.md`. **Both files are written out below in full and were compiled, run,
and mutation-tested on 2026-08-07 — type them in as given.** The round's work is transcription
plus running the verification.

**Clean-room constraint, stricter here than anywhere else:** graph fixtures are the one artifact
`CLAUDE.md` names as never-copyable — GitUp's are GPLv3 test data. **Do not open, read, or grep
anything under the GitUp checkout — not the layout code, not the tests, not the fixtures.** The
notation below is original to Switchyard: it is `GraphNode` and `GraphRow` flattened onto one line
per commit, designed from the shape of those two types and from nothing else, and both files say

This issue is **engine tests only**: no `CommandSpec`, no `runYard` arm, no CLI wiring, no

### 1. The notation, by example

One line per commit, children before parents — the input order `LaneAssigner.assign` requires.
Every token is `name@lane`. The first token on a line is the commit and the lane it must occupy;
the remaining tokens are its parents **in parent order**, each carrying the lane its edge must
continue in below the row. `#` starts a whole-line comment; blank lines are skipped. The
criss-cross from #0015's worked example, whose expected values are that issue's worked table:

```
# b and s each merge the other (x = b+s, y = s+b); z merges the results.
z@0     x@0 y@1
y@1     s@1 b@2
x@0     b@0 s@1
s@1     base@1
b@0     base@0
base@0
```

Line 1 reads: commit `z` occupies lane 0; its first parent `x`'s edge continues in lane 0, its
second parent `y`'s edge in lane 1 — i.e. `GraphRow(oid: "z", parents: ["x", "y"], lane: 0,
parentLanes: [0, 1])`, and `GraphNode(oid: "z", parents: ["x", "y"])`. A parent that never appears
as a commit is a dangling edge — legal, exactly like a parent outside a `--max-count` window; the
`allocationTakesTheLeftmostHole` case uses one (`pc`).

### 2. A loose error assertion was measured vacuous — the specific-error form is load-bearing

With the parser mutated to *skip* malformed tokens instead of throwing (mutation T3 below),
`#expect(throws: DAGFixture.Failure.self)` **stayed green**: the skip path leaves the line with no
refs, the fixture ends empty, and `.emptyFixture` still satisfies the type-level assertion. The
test below therefore asserts the **specific** `.malformedToken(token:line:)` values, and adds a
malformed *parent* on an otherwise valid line — under the skip mutation that parses to a
valid-looking one-commit fixture and throws nothing. Do not loosen these back to `Failure.self`.

// LaneAssignmentFixtureTests.swift — table-driven lane fixtures in the row notation (#0025)

import Testing
@testable import YardGit

// MARK: - The row notation

/// A commit DAG and its expected lane assignment, parsed from the row
/// notation (documented in `docs/dag-lane-notation.md`, #0025).
///
/// One line per commit, children before parents — the order
/// `LaneAssigner.assign` requires. Every token is `name@lane`: the first
/// token on a line is the commit and the lane it must occupy, the remaining
/// tokens are its parents in parent order, each carrying the lane its edge
/// must continue in below the row. A line starting with `#` is a comment;
/// blank lines are skipped. A parent that never appears as a commit is a
/// dangling edge — legal, exactly like a parent outside a `--max-count`
/// window.
///
/// The notation is original to Switchyard: it is the two types `GraphNode`
/// and `GraphRow` flattened onto one line per commit, designed from their
/// shape and from nothing else. No other project's fixture format was
/// consulted.
struct DAGFixture: Equatable {

    enum Failure: Error, Equatable, CustomStringConvertible {
        /// A token that is not `name@lane` with a non-negative integer lane.
        case malformedToken(token: String, line: String)
        /// The same commit name appeared on two lines.
        case duplicateCommit(String)
        /// No commit lines at all. An empty fixture would make every
        /// comparison `[] == []`, so it is refused outright.
        case emptyFixture

        var description: String {
            switch self {
            case let .malformedToken(token, line):
                "malformed token '\(token)' in line: \(line)"
            case let .duplicateCommit(name):
                "commit '\(name)' appears on two lines"
            case .emptyFixture:
                "fixture contains no commit lines"
            }
        }
    }

    /// The DAG, ready for `LaneAssigner.assign`.
    let nodes: [GraphNode]

    /// The expected output, row for row.
    let expected: [GraphRow]

    init(_ text: String) throws {
        var nodes: [GraphNode] = []
        var expected: [GraphRow] = []
        var seen: Set<String> = []

        for rawLine in text.split(separator: "\n", omittingEmptySubsequences: true) {
            let line = rawLine.trimmingCharacters(in: .whitespaces)
            if line.isEmpty || line.hasPrefix("#") { continue }

            var refs: [(name: String, lane: Int)] = []
            for token in line.split(whereSeparator: \.isWhitespace) {
                refs.append(try Self.parseRef(String(token), line: line))
            }
            guard let commit = refs.first else { continue }
            guard seen.insert(commit.name).inserted else {
                throw Failure.duplicateCommit(commit.name)
            }
            let parents = refs.dropFirst()
            nodes.append(GraphNode(oid: commit.name, parents: parents.map(\.name)))
            expected.append(GraphRow(
                oid: commit.name,
                parents: parents.map(\.name),
                lane: commit.lane,
                parentLanes: parents.map(\.lane)))
        }
        guard !nodes.isEmpty else { throw Failure.emptyFixture }
        self.nodes = nodes
        self.expected = expected
    }

    /// Parses one `name@lane` token. Exactly one `@`, a non-empty name, and
    /// a non-negative integer lane; anything else throws.
    static func parseRef(_ token: String, line: String) throws -> (name: String, lane: Int) {
        let parts = token.split(separator: "@", omittingEmptySubsequences: false)
        guard parts.count == 2, !parts[0].isEmpty,
              let lane = Int(parts[1]), lane >= 0 else {
            throw Failure.malformedToken(token: token, line: line)
        }
        return (String(parts[0]), lane)
    }
}

/// Parses the fixture, checks it holds exactly `commitCount` commits (so a
/// parser that silently drops lines cannot leave the comparison vacuous),
/// runs the assigner, and compares every row.
private func assertAssignmentMatches(
    _ text: String, commitCount: Int,
    sourceLocation: SourceLocation = #_sourceLocation
) throws {
    let fixture = try DAGFixture(text)
    #expect(fixture.nodes.count == commitCount, sourceLocation: sourceLocation)
    let rows = LaneAssigner.assign(fixture.nodes)
    #expect(rows == fixture.expected, sourceLocation: sourceLocation)
}

z@0     x@0 y@1
y@1     s@1 b@2
x@0     b@0 s@1
s@1     base@1
b@0     base@0
base@0
"""

    b@0

    m@0  a@0 b@1
    a@0  r@0
    b@1  r@1
    r@0  q@0
    t@1  q@1
    q@0

@Test func allocationTakesTheLeftmostHole() throws {
    // Lanes 0 and 1 are both free (pa and pb were roots) while lane 2 is

    // pc never appears as a commit — a dangling parent, like a parent

    a@0   pa@0
    b@1   pb@1
    c@2   pc@2
    pa@0
    pb@1
    d@0
    """, commitCount: 6)
}

@Test func notationEncodesTheSameDAGAsTheHandBuiltCrissCross() throws {
    // The same DAG `exactRowsForALiteralCrissCross` builds in code, decoded
    // from the notation. Both representations must be identical — this is
    // the test that fails when the parser misreads parent order, drops a

        GraphNode(oid: "z", parents: ["x", "y"]),
        GraphNode(oid: "y", parents: ["s", "b"]),
        GraphNode(oid: "x", parents: ["b", "s"]),
        GraphNode(oid: "s", parents: ["base"]),
        GraphNode(oid: "b", parents: ["base"]),
        GraphNode(oid: "base", parents: []),

    #expect(fixture.expected == [
        GraphRow(oid: "z", parents: ["x", "y"], lane: 0, parentLanes: [0, 1]),
        GraphRow(oid: "y", parents: ["s", "b"], lane: 1, parentLanes: [1, 2]),
        GraphRow(oid: "x", parents: ["b", "s"], lane: 0, parentLanes: [0, 1]),
        GraphRow(oid: "s", parents: ["base"], lane: 1, parentLanes: [1]),
        GraphRow(oid: "b", parents: ["base"], lane: 0, parentLanes: [0]),
        GraphRow(oid: "base", parents: [], lane: 0, parentLanes: []),
    ])
}

## The documentation — `docs/dag-lane-notation.md`, in full

```markdown
# The row notation for commit-DAG lane fixtures

**Original to Switchyard (#0025).** The notation is the engine's two graph types — `GraphNode`
and `GraphRow` in `YardKit/Sources/YardGit/LaneAssignment.swift` — flattened onto one line per
commit. It was designed from the shape of those types and from nothing else; no other project's
fixture format was consulted. The parser is test infrastructure:
`DAGFixture` in `YardKit/Tests/YardGitTests/LaneAssignmentFixtureTests.swift`. Nothing in the
shipped engine reads it.

## Grammar

- One line per commit, **children before parents** — the input order `LaneAssigner.assign`
  requires (`git rev-list --topo-order` emission order).
- Every token on a line is `name@lane`: a name (any characters except whitespace and `@`),
  one `@`, and a non-negative integer lane.
- The **first** token is the commit and the lane it must occupy. The **remaining** tokens are its
  parents **in parent order**, each carrying the lane its edge must continue in below the row.
  A line with one token is a root.
- A line whose first non-whitespace character is `#` is a comment. Blank lines are skipped.
  Comments share a line with nothing.
- A parent name that never appears as a commit is a dangling edge — legal, the same shape as a
  parent outside a `--max-count` window.
- Malformed tokens, duplicate commit names, and fixtures with no commit lines are parse errors
  (`DAGFixture.Failure`), never skipped: a silently dropped line would corrupt every expectation
  below it.

## Example

The criss-cross merge (x = b+s, y = s+b, z = x+y), with its expected layout:

    z@0     x@0 y@1
    y@1     s@1 b@2
    x@0     b@0 s@1
    s@1     base@1
    b@0     base@0
    base@0

Line 1 reads: commit `z` occupies lane 0; its first parent `x`'s edge continues in lane 0, its
second parent `y`'s in lane 1. Decoded, that line is `GraphNode(oid: "z", parents: ["x", "y"])`
and the expectation `GraphRow(oid: "z", parents: ["x", "y"], lane: 0, parentLanes: [0, 1])`.
`parentLanes[0] == lane` holds in every valid layout (rule 3, first-parent inheritance); a fixture
that writes something else fails its test rather than failing to parse.

## Where the cases live

Inline in `LaneAssignmentFixtureTests.swift`, one multiline string literal per case, next to the
test that runs it. Not in separate resource files: the test target declares no resources in
`Package.swift`, and a resource that fails to copy fails silently — inline literals cannot go
stale or missing. The algorithm the cases pin is specified in
`docs/clean-room/graph-lane-assignment.md` (#0075) and #0015.
```

this issue discharges. Built on #0015 (resolved 2026-08-07) — the old draft's "Blocked by #0015"
is satisfied. The notation is reusable for M3's map-view edge-routing fixtures (#0052) if they

**Corrections to the old draft, so nobody restores its claims:**

- *"One fixture file per case"* is replaced by **one multiline string literal per case, inline in
  the test file**. Separate files would need either a `resources:` declaration in `Package.swift`
  (the manifest is not to be touched) or `#filePath`-relative reads, and a resource that fails to
  copy fails **silently** — the same failure shape as #0095's orphaned test file, where absence
  reads as green. Inline literals keep each fixture visible next to its test and cannot go
  missing.
- *"Documented in `docs/`"* is kept and made concrete: `docs/dag-lane-notation.md`, pasted above.
- *"A deliberate regression … verified by temporarily breaking it"* is upgraded from one ad-hoc
  break to the 11-row mutation table, every row measured.
- The old draft's six case families are all present, plus three more (shared second parent,
  convergence reuse, leftmost hole) that cost a few lines each — which is the notation's argument
  for existing.

**Design decisions, so nobody relitigates them mid-round:**

- **The parser lives in the test target, not the engine.** Nothing shipped reads the notation;
  a production `YardGit` file would be dead weight and a second public parser surface. It also
  keeps this issue's diff out of `Sources/` entirely.
- **Expected parent lanes are mandatory, not optional.** An optional-expectation grammar invites
  fixtures that assert only the commit lane, and edge routing is where the mutations bit (P1, P5,
  T2). `parentLanes[0] == lane` is *not* validated at parse time on purpose: it is an algorithm
  property, and a fixture that miswrites it should fail its test comparison, visibly, not be
  rejected as a syntax error.
- **Parse errors are specific and tested as specific values** — Given 2 is the measured reason.
- **Comments are whole-line only.** A trailing `# …` after tokens would be a malformed token, and
  that is the intended behavior — it keeps the tokenizer to one rule.
