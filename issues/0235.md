## Description

**Finding 4 of the #0160 umbrella review, 2026-08-17.** #0160 bullet 1 requires an observed rewrite
entry to carry *"source, the ordered old→new pairs, **timestamp, and worktree**"*.

`JournalObserved.Metadata` carries `schemaVersion`, `kind`, `updates?`, `source?`, `rewrites?` — and
nothing else. The pinned wire literal is:

```json
{"kind":"rewrites","rewrites":[…],"schemaVersion":1,"source":"rebase"}
```

- **Timestamp** exists only implicitly, in the entry's ULID id, and **no API reads it back** —
  `JournalEntryID` embeds a 48-bit millisecond field with no accessor.
- **Worktree is absent entirely.** Observed refs are shared, not per-worktree, so a consumer cannot
  tell which worktree a foreign rewrite happened in. That is exactly the distinction #0044's whole
  premise turns on.

## Decided — add both, additively

Taken 2026-08-17 on the same terms as guide §11 decisions 14–18: reversible, and the alternative was
to amend the criterion, which would be quietly narrowing a promise rather than keeping it. The
criterion was written deliberately — a foreign rewrite whose worktree is unknown is a record a
two-agent repository cannot act on.

Both fields are added the way `kind` was in #0220: **new required keys, no `schemaVersion` bump**,
because observed entries reach no agent yet — `refs/switchyard/observed/` is exposed through no
command.

## Work log

- **Round 1 — 2026-08-17, Sonnet subagent, 120,978 tokens, 7m37s, accepted with one gap.** Both fields
  added for both kinds, reusing `JournalEntryMetadata.Worktree`. It found that
  `JournalObserved`'s encoders set **no** date strategy at all, so a `Date` would have encoded as a
  raw epoch `Double`, and added `.iso8601` to match what `JournalEntryMetadata.serialized()` does.
  It deliberately did **not** copy that type's sub-second flooring, on the ground that
  `JournalObserved.Metadata` is `Encodable`-only and has no round trip to protect — correct.
- **The gap:** the wire tests encode with the **test's own** `JSONEncoder`, configured to match, so
  deleting both `.iso8601` lines from production left all six green. They pin the type's `Codable`
  shape, not what `record` writes. Logged as a failure class and as preflight check 0d — it is the
  second instance in one day, after #0218's mirrored fake.
- **Round 2 — 161,412 tokens, 8m14s, accepted.** `aForeignRewriteRecordWritesTheExactPinnedBytes`
  drives the real `record` path with `now: Date(timeIntervalSince1970: 0)` and reads the blob back off

  ref name from `JournalAnchor.refPrefix`, the *journal* namespace, so against an observed id it throws
  `fatal: Not a valid object name`. It measured that, said so, and used the file's existing `cat-file`
  helper instead.
- **A guard caught it mid-round**, which is the system working: a draft doc comment spelled out
