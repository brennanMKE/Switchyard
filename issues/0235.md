## Description

**Finding 4 of the #0160 umbrella review, 2026-08-17.** #0160 bullet 1 requires an observed rewrite
entry to carry *"source, the ordered old→new pairs, **timestamp, and worktree**"*.

`JournalObserved.Metadata` carries `schemaVersion`, `kind`, `updates?`, `source?`, `rewrites?` — and
nothing else. The pinned wire literal is:

```json
{"kind":"rewrites","rewrites":[…],"schemaVersion":1,"source":"rebase"}
```

- **Timestamp** exists only implicitly, in the entry's ULID id, and **no API reads it back** —
  `JournalEntryID` embeds a 48-bit millisecond field with no accessor.
- **Worktree is absent entirely.** Observed refs are shared, not per-worktree, so a consumer cannot
  tell which worktree a foreign rewrite happened in. That is exactly the distinction #0044's whole
  premise turns on.

## Decided — add both, additively

Taken 2026-08-17 on the same terms as guide §11 decisions 14–18: reversible, and the alternative was
to amend the criterion, which would be quietly narrowing a promise rather than keeping it. The
criterion was written deliberately — a foreign rewrite whose worktree is unknown is a record a
two-agent repository cannot act on.

Both fields are added the way `kind` was in #0220: **new required keys, no `schemaVersion` bump**,
because observed entries reach no agent yet — `refs/switchyard/observed/` is exposed through no
command.

## The files

- **`YardKit/Sources/YardGit/JournalObserved.swift`** — `Metadata` gains the two fields; both
  `record` overloads populate them.
- **`YardKit/Sources/YardGit/JournalEntryMetadata.swift`** — read `Worktree` here and reuse it; do
  not define a second shape.
- **`YardKit/Tests/YardWireTests/JournalObservedWireTests.swift`** — the byte-exact literals, both
  kinds.
- **`YardKit/Tests/YardGitTests/JournalObservedTests.swift`** — the behaviour.

## Expected behavior

- [ ] `JournalObserved.Metadata` gains `timestamp: Date` and `worktree: JournalEntryMetadata.Worktree`
      (the existing `{name, path}` shape — reuse it, do not define a second).
- [ ] Both are populated for **both** kinds — a `ref_updates` entry has the same need — and both
      `record` overloads take the `now:` they already accept and the context they already have.
- [ ] The wire tests in `YardWireTests` are updated to the new byte-exact literals, both kinds.
      **Update the literal rather than relaxing the assertion**; pinning bytes is the point of them.
- [ ] Encode the timestamp the way the rest of the codebase does. `RepositoryRegistry` uses
      `.iso8601`, which **drops sub-second precision** — check what `JournalEntryMetadata` does for its
      own `timestamp` and match that, since these two are read side by side. State which you found.
- [ ] Mutation: drop `worktree` from the encoded output and confirm a wire test reddens.
- [ ] `cd YardKit && swift test` twice, both green, with **N greater than 1011**, the count on `main`
      measured 2026-08-17.
