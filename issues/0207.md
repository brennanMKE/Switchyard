## Description

**Found by #0198's round, 2026-08-17, while establishing that `init?(ychar:)` was dead.** Verified
independently by the reviewer.

`WorktreeStatusEntry.State(char:)` (`YardKit/Sources/YardGit/WorktreeStatus.swift`) handles
`.`, `A`, `+`, `D`, `-`, `M`, `R`, `C` and returns **nil** for anything else. Both call sites coalesce
that nil away:

```swift
WorktreeStatusEntry.State(char: stagedChar) ?? .unmodified          // :298
WorktreeStatusEntry.State(char: $0) ?? .unmodified                  // :302
```

**`T` and `U` are legal XY values and both become `.unmodified`.**

- **`T` is a typechange** — a file replaced by a symlink, or the reverse. `switchyard status` reports
  it as unmodified, so an agent reading the engine's output cannot see that the working tree changed
  shape.
- **`U` is unmerged** — the Y half of "added by us" (`AU`), "deleted by them" (`UD`) and the rest of
  the six unmerged combinations. A conflicted path reports as unmodified on that half.

This is a **silently wrong value**, which is worse than an error: nothing throws, nothing is empty, and
the caller has no way to tell. It is the same family as #0193 — a parser degrading quietly rather than
reporting — except that `T` and `U` are *valid* git output, so the fix is to map them, not to throw.

## Expected behavior

- [ ] `State` gains cases for typechange and unmerged, or maps them onto existing cases with a
      **recorded reason** — decide which and say why in the issue before changing code. Note the enum
      is agent-facing through the wire encoding, so adding a case is a schema question: check
      `YardKit/Tests/YardWireTests/` for what pins `WorktreeStatusEntry` before choosing, and treat a
      new enum string as the additive, non-breaking change `Schemas/README.md` describes rather than a
      rename.
- [ ] Both call sites stop coalescing a genuinely unknown character to `.unmodified`. Whether an
      unknown char should throw (following #0193's `unrecognizedRecordType`) or map to an explicit
      `.unknown` is part of the same decision.
- [ ] Tests driving **real** git output for each: a typechange is `ln -sf` over a tracked file then
      `git add`; an unmerged `U` comes from the existing conflict fixture. Assert the reported state,
      not merely that parsing succeeded.
- [ ] A mutation, observed: restore the `?? .unmodified` coalescing and confirm each new test dies.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt`; state the delta once the shape is settled.

## Notes

**Measure git's real output before designing the mapping.** `git status --porcelain=v2 -z` prints the
XY pair for ordinary (`1`), renamed/copied (`2`) and unmerged (`u`) records, and the alphabets differ
between them — `. M T A D R C` for the first two, `D A U` for unmerged. A mapping that ignores which
record type it came from will get one of them wrong.

`WorktreeStatusParser` is the engine behind `switchyard status`, an M1 read command. M1's exit criterion
3 forbids returning "a success value with empty fields"; a success value with *wrong* fields is not
literally that, which is why this is filed rather than reported as an M1 finding — but it is the same
spirit and worth mentioning if M1's criteria are ever revisited.

**The round reported a mutation result that contradicted the naive expectation, and was right.** Restoring
`?? .unmodified` at both call sites killed only the unknown-character test — the typechange and unmerged
tests still passed, because `State(char: "T")` now returns non-nil, so the coalescing is dead code for
exactly those characters. That is correct: **the fix lives in the enum's switch, not in the coalescing
operator**, so the coalescing mutation gates only the "genuinely unknown character" half.

The mutation that gates the other half is deleting the two new `case` lines, and the reviewer ran it:
both tests fail with `unrecognized porcelain v2 status character "T"` / `"U"`. Worth recording as a
pattern — **when a fix has two halves, one mutation usually gates one of them**, and a round that
reports "the mutation only killed one test" is describing the code accurately rather than falling short.

It also measured git's real output before writing anything, which is what made the mapping trustworthy:
`1 T. N... 100644 120000 120000` for a staged typechange and `u UU` for a both-modified conflict,
confirming the two alphabets differ by record type exactly as the issue warned.
