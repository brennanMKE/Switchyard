## Description

`yard` collides with the Ruby YARD documentation tool, which declares `yard`, `yardoc` and `yri` as
executables and installs into `/usr/local/bin` — the same path this project's CLI targets. Settled
decision 4 in guide §11: the binary is **`switchyard`**.

Do this now. It is three constants and a target name today; after #0026 publishes the JSON schemas
and #0066 generates the agent skill, the same rename touches agent-facing contracts.

## Givens — verified on `main`, treat as true

1. **`YardKit` and `YardGit` keep their names, and so do their directories.** They are module names,
   not commands. The collision is specifically about an executable in `/usr/local/bin`. Renaming
   them is **out of scope and will be rejected.**
2. `YardKit/Package.swift` has, at lines 15 and 38-39:
   ```swift
   .executable(name: "yard", targets: ["yard"]),
   ...
   .executableTarget(
       name: "yard",
       path: "Sources/yard"
   ```
   The product name, the target name, and the `path:` all change to `switchyard`, and the directory
   `YardKit/Sources/yard/` is renamed to `YardKit/Sources/switchyard/`. `main.swift` moves with it.
3. `YardKit/Sources/YardKit/ServiceNames.swift` holds exactly three constants that mention the
   binary, at lines 44, 48 and 51:
   ```swift
   public static let cliName = "yard"
   public static let cliInstallPath = "/usr/local/bin/yard"
   public static let cliBundleRelativePath = "Resources/bin/yard"
   ```
   These become `switchyard`, `/usr/local/bin/switchyard`, and `Resources/bin/switchyard`.
   **Every other constant in that file is unchanged** — `appName`, `bundleIdentifier`,
   `logSubsystem`, `machServiceName`, `agentPlistName`, `brokerExecutableName`, `urlScheme`,
   `journalRefPrefix`, `repoStateDirectoryName`, `journalMetadataRelativePath`. Do not touch them.
4. `YardKit/Sources/YardGit/GitProcess.swift` sets an environment marker
   `SWITCHYARD_YARD_INVOCATION`. **Leave it exactly as it is.** It is a hook-loop guard read by
   #0042, not a user-facing name, and changing it silently breaks a contract nothing tests yet.
5. `ServiceNames.swift` is the single source of truth for these strings. Nothing else may hardcode
   the binary name — if you find a literal `"yard"` in Swift source outside `ServiceNames.swift`,
   replace it with `ServiceNames.cliName` rather than with another literal.

## Tests must be able to fail

There is a real regression risk here that a passing build will not catch: a test that asserts on the
binary's *path* or *name* could be updated to match whatever the code now does, which tests nothing.

- If a test references the CLI name, it must reference `ServiceNames.cliName`, not a literal.
- Add or keep an assertion that `cliInstallPath` ends with `cliName` — that is the invariant which
  makes the three constants consistent, and it fails if someone updates one and forgets another.

later is not.

Do not add an alias in this issue. One deliverable.
