## Description

Since #0431 fixed `BranchStatus` parsing, sidebar rows show their status text, for example
`↑4↓11 vs map-main`. At the default sidebar width that text takes most of the row, so branch names
truncate to `featur…` and `fresh-…` (VM screenshot, spike 0430, run `20260927-011225-43851`). The
name is what a person scans for, so it must not be the part that truncates.

**Measured, 2026-09-27 (planning pass), from that run's `branch-map-merged` attachment:** the
sidebar is about 245 pt wide, and **both** halves of every row truncate — `map-…` / `in sync vs
map-…`, `featur…` / `↑4↓11 vs map-…`, `fresh-…` / `↑2↓34 vs map-…`. Only four-to-seven-character
names (`lane-01`) survive. The cause is `branchRow`'s `HStack`: the `Label` and the status `Text`
have equal layout priority, so SwiftUI splits the shortfall between them.

## Decision (planning, high confidence)

**The name gets layout priority; the status truncates; the full status moves into the help
tooltip as a second line.** Decision 27 (guide §11) is **not** changed: the row still names the
baseline (`vs map-main`) whenever the width allows, and the tooltip always carries it in full.

Why this and not "drop `vs <baseline>` when the baseline is the default branch":

- It fixes the defect as filed — the name truncating — without touching a decision that is
  Brennan's to overrule. Dropping the baseline name makes `↑4↓11` mean "vs default" by convention
  and `↑1 vs origin/topic` mean "vs upstream" by contrast, which is exactly the ambiguity decision 27
  exists to prevent (ahead of the upstream returns to 0 on push; ahead of the default does not).
- At the measured default width the baseline is **already** truncated today (`vs map-…`), so the
  row's naming of the baseline is width-dependent either way; the tooltip makes it
  width-independent, which is strictly more than the row gives now.
- It is a two-modifier change plus one pure function, reversible in one commit.

**Open question for Brennan, recorded, not blocking:** whether the row should drop `vs <default>`
to make room for the merged word (`· not merged`), which at the default width is now always cut
off. That would amend decision 27; not done here.

### The test file, verbatim

```swift
// BranchHelpTextTests.swift
//
// #0433 pins the sidebar branch row's help text (`branchHelpText`): the row
// gives its width to the branch name and lets the status truncate, so the
// hover text is where the full status -- decision 27's baseline name
// included -- stays readable.
//
// Imports YardUI WITHOUT `@testable`, matching this target's idiom (see
// BranchStatusTextTests.swift): the pinned members are `public`.

import Testing
import YardGit
import YardUI

private let topic = RefSnapshot.Entry(name: "refs/heads/feature-near", oid: String(repeating: "a", count: 40))

@Test("no status: the help text is the full ref name alone")
func branchHelpWithoutStatusIsTheRefName() {
    #expect(RepositorySidebarView.branchHelpText(for: topic, status: nil) == "refs/heads/feature-near")
}

@Test("a status: the help text adds it in full on a second line, baseline included")
func branchHelpCarriesTheFullStatus() {
    let status = "↑4↓11 vs map-main · not merged"
    #expect(RepositorySidebarView.branchHelpText(for: topic, status: status)
        == "refs/heads/feature-near\n↑4↓11 vs map-main · not merged")
}

@Test("the help text carries branchStatusText's exact output")
func branchHelpCarriesBranchStatusText() {
    let row = BranchStatus.Row(
        ref: "refs/heads/feature-near", upstream: nil, upstreamGone: false,
        baseline: .defaultBranch("map-main"), ahead: 4, behind: 11,
        defaultAhead: 4, defaultBehind: 11)
    let report = BranchStatus.Report(defaultBranch: "map-main", rows: [row])
    let status = RepositorySidebarView.branchStatusText(
        for: topic, report: report, content: ["refs/heads/feature-near": .notMerged])
    #expect(status == "↑4↓11 vs map-main · not merged")
    #expect(RepositorySidebarView.branchHelpText(for: topic, status: status)
        == "refs/heads/feature-near\n↑4↓11 vs map-main · not merged")
}
```
