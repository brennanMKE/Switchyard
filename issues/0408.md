# 0408 — Two tests fail intermittently when suites run concurrently

| | |
|---|---|
| **Status** | open |
| **Module** | YardUI, YardGit (tests only) |
| **Platform** | macOS |
| **First seen** | 2026-09-22 |

## Description

Two tests failed on 2026-09-22 while two `swift test` runs were loading the machine at once, and
each passed on an immediate re-run with no code change. Neither touches code M9 changed.

1. **`AbandonedSheetTests.theReaperStillEndsAnAbandonedReview`**
   (`YardKit/Tests/YardUITests/AbandonedSheetTests.swift`). It failed after 196.8 s on
   `issue/0405` with `main` merged, then passed in 8 s alone. The request uses
   `timeoutSeconds: 1`. When the pending's 1 s reaper fires before
   `store.abandonAll(ownedBy:)` lands, the model goes straight to `.timedOut`, so
   `waitUntil { model.isAbandoned }` never sees the abandoned state and waits out its deadline.
   That is a race between a real 1 s timer and the test's own steps.
2. **`GitProcessAsyncTests.cancellingAsyncCaptureTerminatesTheChildAndThrows`**
   (`YardKit/Tests/YardGitTests/GitProcessAsyncTests.swift:196`, `Expectation failed: thrown`).
   It failed once in the #0405 round's run 2 and once in a review run under concurrent load, and
   passed on the runs either side.

## Expected behavior

- [ ] Both tests pass deterministically under concurrent suite load. The reaper test must not
      depend on the test beating a real 1 s timer, per AGENTS.md Rule 7c's spirit: assert what the
      criterion claims, not timing.
