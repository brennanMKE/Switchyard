# 0408 — Two tests fail intermittently when suites run concurrently

| | |
|---|---|
| **Status** | resolved |
| **Module** | YardKit, YardGit (one production line each), YardUITests, YardGitTests |
| **Milestone** | — |
| **Platform** | macOS |
| **First seen** | 2026-09-22 |

## Description

Three tests fail intermittently under parallel load and pass on re-run. **Re-planned 2026-09-27
(Opus) with every root cause reproduced on demand** — none of them is "the machine is slow"; each is
a specific race, and two of the three are races a longer deadline cannot fix.

### Evidence

- `AbandonedSheetTests.theReaperStillEndsAnAbandonedReview` — `Caught error: WaitTimeout()` after
  ~188–197 s: 2026-09-22 (#0405), three of five full runs on 2026-09-23 (#0410, load average 70–95),
  2026-09-26 (#0426 review, two suites concurrently), and 2 of the last 6 full runs on
  2026-09-26/27 — once apparently with no second suite running.
- `GitProcessAsyncTests.cancellingAsyncCaptureTerminatesTheChildAndThrows` —
  `GitProcessAsyncTests.swift:196:25: Expectation failed: thrown` (the capture **returned** instead
  of throwing): #0405 round 2, a review run, two of five #0410 runs.
- `GitProcessAsyncTests.concurrentAsyncCapturesDoNotHoldCooperativePoolThreads` — failed once with
  `counter.completed == 0` false.

### Root cause 1 — the reaper test races a real 1 s timer (test defect)

`PendingReviewStore.awaitDecision` (`YardKit/Sources/YardKit/PendingReviewStore.swift:124`) arms
`Task { try await Task.sleep(for: .seconds(Double(request.timeoutSeconds))) … finish(.timedOut) }`.
The test uses `timeoutSeconds: 1` and must get `store.abandonAll(ownedBy:)` **and** the centre's
`.abandoned` main-actor hop in before that second elapses. It loses two ways:

1. The main actor is late by >1 s between registration and `abandonAll` (the 10 ms poll in
   `waitUntil { center.sheets.count == 1 }` can wake tens of seconds late under load). The timer's
   `finish` has removed the slot, `abandonAll` marks nothing, no `.abandoned` event exists.
2. `abandonAll` lands, but the two change hooks each hop through their own
   `Task { @MainActor in … }` (`ReviewCenter.init`, `YardKit/Sources/YardUI/ReviewSheet.swift:380`),
   enqueued from different threads, so `.timedOut` can run first — and
   `ReviewSheetModel.recordAbandonment()` is `guard outcome == nil else { return }`, so the
   abandonment is then ignored.

Either way `waitUntil { model.isAbandoned }` never becomes true and waits out its 180 s bound.
**Reproduced deterministically** by inserting `try await Task.sleep(for: .milliseconds(1500))`
before `store.abandonAll` in the current test: `AbandonedSheetTests.swift:75:6: Caught error:
WaitTimeout()`, `failed after 181.605 seconds` — the field signature exactly. The production
behaviour is correct (a pending reaped before abandonment has nothing to abandon); the test has to
stop racing the clock. Fix: inject the reaper's sleep so the test fires it after observing the
abandonment.

### Root cause 2 — a real production race in async `capture`'s cancellation (production defect)

`GitProcess.capture(...) async` (`YardKit/Sources/YardGit/GitProcess.swift`, the `onCancel:` block
of `withTaskCancellationHandler`, ~line 515) does:

```swift
} onCancel: {
    if childProcess.isRunning {
        childProcess.terminate()
    }
    gate.finish(.failure(CancellationError()))
```

`ResumeOnce.finish` is first-wins. After `terminate()` the SIGTERM'd child exits and its
`terminationHandler` + stdout-EOF `readabilityHandler` run on Foundation's queues and call
`complete()` → `gate.finish(.success(Output(exitCode: 15)))`. If the cancelling thread is preempted
between `terminate()` and its own `gate.finish`, the **success** wins: the cancelled capture returns
an `Output` with exit status 15 and throws nothing. That is `Expectation failed: thrown` at line 196.
The timeout watchdog in the same function already follows the right rule (`markDeadlineExpired()`
*before* `terminate()`); the cancel path does not.

**Reproduced deterministically**: with `usleep(200_000)` inserted between `terminate()` and
`gate.finish(...)` (widening the preemption window), 5 of 5 runs fail with
`GitProcessAsyncTests.swift:196:25: Expectation failed: thrown`. With the order swapped (finish,
then terminate) and the same `usleep` after both, 5 of 5 pass. The test is correct; the production
code is fixed.

### Root cause 3 — the starvation test's "none completed" is a wall-clock window (test defect)

Each child is `/bin/sleep 2`, and the test asserts `counter.completed == 0` after a poll loop of
`Task.sleep(for: .milliseconds(10))`. If any poll wakes more than ~2 s late — routine under this
suite's load, see CLAUDE.md "Never assert wall-clock elapsed time" — the first children have
finished and `completed == 0` fails. Fix: children block until the test **creates a release file**,
so no child can complete before the assertion regardless of scheduling. Each child also carries a
bounded self-release (3 600 × 50 ms ≥ 180 s), because under the blocking mutation the saturated
pool cannot resume the test's own poll loop — measured: a release-file-only version **hung for
over 10 minutes** under the mutation instead of failing.

### Not in scope

`SignatureVerificationTests.craftedBadSSHSignatureReportsBad(format: .files)` exiting 13 (SIGPIPE),
seen once on 2026-09-23, is a different failure shape and is not addressed here.

## The changes

Four files. Paste each block exactly; nothing else changes.

### 1. `YardKit/Sources/YardKit/PendingReviewStore.swift` — injectable reaper sleep

Replace `    public init() {}` with:

```swift
    /// How a pending's reaper waits out its `timeoutSeconds` (#0408). The
    /// app always uses the default, a real `Task.sleep`; a test injects a
    /// sleep it completes by hand, so "the timer fired" is an event the test
    /// causes rather than a race against a real clock. The closure MUST throw
    /// when its task is cancelled — cancellation is how a resolved slot
    /// disarms its reaper.
    private let reaperSleep: @Sendable (Duration) async throws -> Void

    public init(
        reaperSleep: @escaping @Sendable (Duration) async throws -> Void = { try await Task.sleep(for: $0) }
    ) {
        self.reaperSleep = reaperSleep
    }
```

In `awaitDecision`, replace

```swift
            let timeoutTask = Task { [weak self] in
                do {
                    try await Task.sleep(for: .seconds(Double(request.timeoutSeconds)))
```

with

```swift
            let reaperSleep = self.reaperSleep
            let timeoutTask = Task { [weak self] in
                do {
                    try await reaperSleep(.seconds(Double(request.timeoutSeconds)))
```

(the `catch { return }` and `_ = self?.finish(...)` lines below stay as they are). Every existing
`PendingReviewStore()` call site (34 of them) keeps compiling through the default argument.

### 2. `YardKit/Sources/YardGit/GitProcess.swift` — finish the gate before terminating

In the async `capture`'s `onCancel:` block, replace

```swift
        } onCancel: {
            if childProcess.isRunning {
                childProcess.terminate()
            }
            gate.finish(.failure(CancellationError()))
```

with

```swift
        } onCancel: {
            // Finish the gate BEFORE terminating (#0408): the terminated
            // child's exit + EOF race to `complete()` on Foundation's queues,
            // and whichever reaches the gate first wins. Terminating first
            // let a SIGTERM'd child report a successful capture (exit 15)
            // instead of the cancellation — the same ordering rule the
            // watchdog follows with `markDeadlineExpired()`.
            gate.finish(.failure(CancellationError()))
            if childProcess.isRunning {
                childProcess.terminate()
            }
```

The `Task.detached` SIGKILL escalation that follows is unchanged. The test
`cancellingAsyncCaptureTerminatesTheChildAndThrows` is **not** edited.

### 3. `YardKit/Tests/YardUITests/AbandonedSheetTests.swift` — fire the reaper by hand

Replace the whole `theReaperStillEndsAnAbandonedReview` test (its doc comment through its closing
brace, before `    // MARK: - Ask`) with:

```swift
    /// The pending's own timer remains the reaper: a terminal outcome after
    /// abandonment still lands, disables the decisions, and names itself in
    /// the banner.
    ///
    /// The reaper's sleep is injected and fired by hand (#0408). With a real
    /// 1 s timer the test raced it: under parallel load the timer could fire
    /// before `abandonAll` (the slot is gone, nothing is abandoned) or its
    /// `.timedOut` hop could reach the main actor before the `.abandoned`
    /// hop (the sheet ignores abandonment after a terminal outcome), and
    /// either way `waitUntil { model.isAbandoned }` waited out 180 s. Now the
    /// reaper fires only after the abandonment is observed.
    @Test func theReaperStillEndsAnAbandonedReview() async throws {
        let (reaperFired, fireReaper) = AsyncStream.makeStream(of: Void.self)
        let store = PendingReviewStore(reaperSleep: { _ in
            // Returns when the test fires the reaper; throws when the
            // reaper task is cancelled (the stream ends with no element).
            for await _ in reaperFired { return }
            throw CancellationError()
        })
        let center = ReviewCenter(store: store)
        let owner = PendingOwner()
        let request = ReviewRequest(
            commonDir: "/repos/a/.git", selector: .staged, timeoutSeconds: 1)

        // An unstructured task, not `async let`: if a wait below throws, an
        // `async let` would block the test's exit on a continuation only the
        // reaper can resume.
        let waiter = Task { await store.awaitDecision(for: request, owner: owner) }
        try await waitUntil { center.sheets.count == 1 }
        let model = try #require(center.sheets.first)
        #expect(store.abandonAll(ownedBy: owner) == 1, "the pending is still registered")
        try await waitUntil { model.isAbandoned }

        fireReaper.yield()
        try await waitUntil { model.outcome == .timedOut }
        #expect(await waiter.value == .timedOut, "the abandoned pending's own timer reaps it")
        #expect(model.outcomeLabel == "This review timed out before a decision was made.",
                "the terminal outcome names itself in the banner")
        #expect(!model.decisionsEnabled, "the reaper ends the review")
    }

```

### 4. `YardKit/Tests/YardGitTests/GitProcessAsyncTests.swift` — children wait for a release file

Replace the whole `concurrentAsyncCapturesDoNotHoldCooperativePoolThreads` test (its two-line doc
comment through its closing brace, before `    // MARK: - The engine twins match…`) with:

```swift
    /// A child that exits when the file named by `$0` exists, or after
    /// 3 600 polls of 50 ms — the backstop that lets a failing run end.
    private static let waitForRelease =
        "i=0; while [ ! -e \"$0\" ] && [ $i -lt 3600 ]; do sleep 0.05; i=$((i+1)); done"

    /// The starvation property, asserted by construction — see the suite
    /// comment for why "all started, none completed" demonstrates the fix.
    ///
    /// Each child blocks until the test creates a release file (#0408), so
    /// "none completed" cannot be broken by the clock: with a fixed
    /// `sleep 2`, a poll that woke late under parallel load saw captures
    /// that had already finished. Each child also gives up after 3 600
    /// polls of 50 ms (at least 180 s): under the blocking mutation the
    /// saturated pool cannot resume this test's own poll loop, so without
    /// that bound nothing would ever create the release file and the run
    /// would hang instead of failing.
    @Test func concurrentAsyncCapturesDoNotHoldCooperativePoolThreads() async throws {
        let shell = GitProcess(executablePath: "/bin/sh")
        let release = URL(fileURLWithPath: NSTemporaryDirectory())
            .appendingPathComponent("yard-starvation-release-\(UUID().uuidString)")
        defer { try? FileManager.default.removeItem(at: release) }
        // Twice the pool width: enough concurrent subprocesses that a
        // blocking implementation must saturate the pool and queue the rest.
        let count = ProcessInfo.processInfo.activeProcessorCount * 2
        let counter = CounterBox()

        try await withThrowingTaskGroup(of: Void.self) { group in
            for _ in 0..<count {
                group.addTask {
                    counter.markStarted()
                    _ = try await shell.capture(
                        ["-c", Self.waitForRelease, release.path])
                    counter.markCompleted()
                }
            }
            // Bounded wait for every capture to have started (Rule 7c: a
            // bounded loop, never a wall-clock assertion). 18 000 polls of
            // at least 10 ms — generous, because nothing can complete early.
            var polls = 0
            while counter.started < count, polls < 18_000 {
                try await Task.sleep(for: .milliseconds(10))
                polls += 1
            }

            #expect(counter.started == count,
                    "only \(counter.started) of \(count) captures started; pool threads are being held")
            #expect(counter.completed == 0,
                    "\(counter.completed) captures completed before the release file existed")

            // Release every child, so a failing run still terminates.
            FileManager.default.createFile(atPath: release.path, contents: nil)
            try await group.waitForAll()
        }

        #expect(counter.completed == count, "every capture must eventually complete")
    }

```

`sh -c '<script>' <path>` binds `<path>` to `$0` — that is intended.
