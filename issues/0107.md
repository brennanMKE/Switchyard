# 0107 — Delete the unused Envelope.write()

| | |
|---|---|

## Description

`Envelope.write()` — the **success** envelope's writer, at
`YardKit/Sources/YardKit/Envelope.swift:62` — has no callers anywhere in `Sources` or `Tests`.

It was added by #0092 because that issue's Givens asked for it, to mirror `EnvelopeFail.write()`. Then
#0092 built `runYard` to return a string and let `main.swift` do the writing, so nothing ever called
it. #0100 widened that return further. The method has been dead since the day it was written.

Specified-but-dead code is worse than absent code: it looks like the supported path, and the next
person to add a command may reasonably call it and route output around `runYard`, which is exactly
what makes `runYard` testable.

## Givens — verified on `main`, treat as true

1. There are **two** `public func write()` methods in that file: line 62 on `Envelope` (the success
   type, dead) and line 243 on `EnvelopeFail` (alive). They are easy to confuse — an earlier attempt
   at this checked the wrong one, found callers, and concluded it was in use.
2. The only `.write()` call site in the test suite is `JsonEnvelopeTests.swift:303`, and the receiver
   there is an `EnvelopeFail`, constructed at line 292. **That call must keep working.**
3. `EnvelopeFail.write()` is genuinely used and must not be touched.
4. `main` is at 139 tests.

## Expected behavior

- [ ] `Envelope.write()` at `Envelope.swift:62` is deleted, along with its doc comment.
- [ ] `EnvelopeFail.write()` is unchanged, and `JsonEnvelopeTests.swift:303` still exercises it.
- [ ] Nothing else in `Envelope.swift` changes. `Envelope`, `EncodableResult`, `EnvelopeError`,
      `EnvelopeErrorCode`, `EnvelopeSchema` and `matchExitCode()` all stay exactly as they are.
- [ ] `cd YardKit && swift build` succeeds with **no new warnings**, and `swift test` prints a
      `Test run with N tests` line you paste. **N must be greater than or equal to 139** — deleting
      dead code should not change the count, but it must not fall.
- [ ] `swift run switchyard` and `swift run switchyard bogus-command` still behave as before: valid
      JSON on stdout, exit 0 and 1 respectively, and the `[error] usage: …` line on stderr for the
      failure. Paste both, with the streams captured separately.

## Notes

Confirmed dead by grep over `Sources` and `Tests` before this issue was filed, not inferred from the
review that reported it.

Do not "use it somewhere" to justify keeping it. If a caller genuinely needs to write a success
envelope directly, that is a different issue with a real requirement behind it.
