## Description

**The command that makes this project worth building.** An agent pushes a diff into a real macOS UI,
blocks on a human decision, and receives the answer as structured data. No other git tooling does
this. Treat it as the centerpiece, not a nice-to-have.

Returns `{"decision":"approve"|"reject"|"amend","comments":[...],"editedPatch":"..."}` — exit 0 on
approve, 7 on reject.

## Expected behavior

- [ ] `yard review <range|--staged> --wait` blocks until the human decides.
- [ ] The review surface opens **on the tab for that repository**, routed through the focus-or-open rule (#0084) — it never opens a stray window or targets the wrong tab.
- [ ] If the repository has no tab, one is opened and its window brought forward.
- [ ] Reuses the diff rendering from #0082 rather than growing a second diff view.
- [ ] A review pending on one tab does not block interaction with other tabs.
- [ ] All three decisions round-trip, including `amend` carrying an edited patch.
- [ ] Per-hunk and per-line comments are returned as structured data.
- [ ] Exit 3 when the app is not running — never a silent non-interactive fallback.
- [ ] A timeout is available and produces a distinct, documented outcome.
- [ ] The app quitting mid-review is reported as exit 5, not as a rejection.
- [ ] Session survives a long review — minutes, not seconds.

## Notes

Guide §6 "Human-in-the-loop", §4 "The UI hierarchy", §9 M4. Blocked by #0047, #0048, #0082, #0084.

Conflating "app died" with "human rejected" would be a serious bug: an agent would treat a crash as
a considered decision.

## Planning decisions — settled by Brennan 2026-09-03, binding on the planning pass

1. **The decision envelope is structured + message.** The wire shape already pinned above
   (`{"decision":"approve"|"reject"|"amend","comments":[...],"editedPatch":"..."}`) gains an optional
   free-text `message` field — what the human typed alongside the decision. Closed enum for the
   decision, structured for comments/patch, optional string for the message. No free-text-only shape.
2. **`--timeout N` is the blocking semantics, and every M4 interactive command inherits it.** On
   expiry the agent receives a **typed timeout envelope** at a **distinct exit code** — landed as
   `ExitCode.timedOut = 10` in round 1 (8 is `blockedOnConflicts`, 9 is `signingFailed`; renumbering
   would break every existing contract). The
   default timeout is generous and labelled as a judgement (suggested: 3600 s). A forgotten session
   must not pin an app process forever, and an agent must never hang without a contract.
3. **Sequencing (Brennan, 2026-09-03):** #0055 first, then #0056 + #0059 (both hang off review),
   then #0057 (merge UI — its interaction design comes back for Brennan's sign-off before
   implementation is dispatched), then #0349 + #0058 (sessions/watch), with #0103 reviving only when
   a command actually needs libgit2.
4. **Exit-code vocabulary check for the timeout:** 4 is `requestFailed` — the timeout case must be a
   new `ExitCode` case, not a reuse.

## Planning pass — 2026-09-03, to code level. Three rounds.

**Round 1 — the wire, the CLI arm, the app-side pending store (this dispatch).**
- `ExitCode.timedOut = 8` (new case; 0-7 taken — 7 is reject). Doc comment: the human did not answer
  within `--timeout`; distinct from `sessionTerminated` (5, app died) and `appUnavailable` (3).
- `YardKit/Sources/YardKit/ReviewRequest.swift` (NEW) — the Codable wire types both sides share:
  `ReviewRequest` (repository commonDir, range or `--staged`, timeout seconds), `ReviewDecision`
  (enum `approve`/`reject`/`amend` — closed, `CodingKeys` case-name-is-wire-key per #0130),
  `ReviewReply` (decision, optional `message`, `comments: [ReviewComment]`, optional `editedPatch`;
  `ReviewComment` carries path + hunk id + optional line + text). Absent means absent (#0129
  Decision 4). `ReviewWireTests` pins the bytes.
- `AppServiceProtocol` gains `performReview(request:reply:)` (reply is `@escaping @Sendable`); the
  app side holds a **pending-review store** — one pending review per repository commonDir, replaceable
  (a second `review --wait` for the same repo supersedes), each armed with its own timeout timer that
  replies a typed timeout if the human never answers. The CLI's own backstop timeout is
  `--timeout + 5 s` margin.
- The CLI arm: `review` joins `CommandRegistry.all` (it is a remote command — exit 3 via
  `appUnavailable` when the app is down, `launchIfNeeded: false` — the M4 exit criterion). Spec:
  flags `--staged`, `--wait`, `--timeout <seconds>`; exit codes 0 (approve), 7 (reject), 3, 5, 8.
  Payload: nil (comments is an array; flat-only `PayloadShape`, #0194 precedent) — schema
  self-reference, golden schema regenerated, step-6 binding per #0243's amended pattern (both halves
  — though the result is array-bearing, so the #0226-style self-reference binding applies).
- Blocking: the CLI awaits the reply continuation for up to `--timeout` (+backstop); the app quitting
  mid-review surfaces through the connection's invalidation path as exit 5 — never as a decision.
- Tests: envelope round-trip through a real anonymous XPC listener (the #0154 pattern); exit 3 with
  the app down; timeout fires the typed envelope (short timeout in test); app-death → exit 5 via a
  killed listener; registry spec test; schema binding both halves.

**Round 2 — the review sheet UI (YardUI, decision 10).** `ReviewSheet.swift` + the pending-review
model in YardUI, driven by injected values (the #0216 pattern — no test touches the XPC layer);
renders the diff reusing #0082's `FileDiffView`; decision buttons + message field + per-hunk/per-line
comment affordances; amend's patch editing; the app target wires the pending store to the sheet on
the right tab via #0084's focus-or-open. Tests assert every state through the model.

**Round 3 — comments + amend polish + the manual script.** Per-hunk/per-line comment capture in the
sheet, `amend`'s edited-patch application path, `scripts/verify-review.md` (UNRUN manual scenarios:
real review round-trip, timeout, app-quit mid-review, no-tab open-and-focus).

**Non-goals for all rounds:** no session machinery beyond what the pending store needs (#0349 owns
sessions; a pending review IS the first session-shaped state, and its design feeds #0349). No
notarization/signing. The CLI never links YardGit — the app resolves the diff engine-side from the
range/--staged in the request.

**Verification (every round):** `cd YardKit && swift test` prints `Test run with N tests` with
**N greater than 1343**, the count on main before this issue. State the delta. `xcodebuild build …
CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO` → `** BUILD SUCCEEDED **`. The manual scenarios
land as `scripts/verify-review.md`, UNRUN, in round 3.
