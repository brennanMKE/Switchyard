## Description

**Findings 2 and 3 of #0044's fourth umbrella review, 2026-08-17.** Two defects that **must be fixed
together**, because fixing the first without the second silently un-pins the guard.

### 1. The guard refuses over refs the restore cannot touch

`CrossToolGuard.swift:165` skips a name only when the target snapshot does not record it **and the
belief did**:

```swift
if target == nil, believed != nil { continue }
```

So a name recorded by **neither** side falls through to the divergence branch. Measured: agent A undoes
once; agent B runs `git worktree add -b agent-branch` and `git branch b-wip` — pure creations, nothing
of A's touched — and A's second undo is refused:

```
PROBE second undo FAILED: repository changed since capture:
  refs/heads/agent-branch was absent, now c42d5a60…; refs/heads/b-wip was absent, now c42d5a60…
```

That is **verbatim the error #0232 was filed for**, in the creation case #0232's fix did not reach.
Recovery costs the traversal: a fresh checkpoint clears it by resetting the cursor and truncating the
redo run.

**The review answered #0244's open question in the same breath, and its reasoning is recorded here
because it is the justification for this change:**

- #0244 answered "no" for step 5 on the argument that `RefSnapshot.restore` emits no command for an
  unrecorded name. That argument is about `restore`, not about the disturbance check, so it transfers
  to step 4 unchanged.
- The guard's **own** stated contract already says no — `CrossToolGuard.swift:173`: *"Empty means no
  other tool moved anything restore would touch"*, and the three-snapshot `diff` comment: *"a name the
  restore's own target snapshot never recorded is a name this restore cannot disturb"*. Line 165 does
  not implement that sentence.
- The wide signal is **already** suppressed for a name `believed` records and `applied` does not — a
  strictly larger loss, since there the journal once knew the ref and it has since moved. Keeping the
  never-recorded case while dropping that one is inconsistent in the wrong direction.

**The change is one line:** `if target == nil, believed != nil { continue }` becomes
`if target == nil { continue }`.

### 2. #0230's order test no longer pins the order

The mutation #0230 specified — move the whole step-2 gate block to just before step 5 — now leaves the
suite **green at 1041**.

**Mechanism:** `aForeignEntryStillReportsTheWorktreeGateEvenWhenTheGuardWouldFire` plants
`refs/heads/rogue` **before** the foreign checkpoint, so the foreign entry's own capture records it at
its current value; after #0232 the guard skips any name where `now == target`, so the fixture produces
no divergence at all and the test cannot tell the orderings apart. #0230 was correct the day it
merged; **#0232 landed after it and invalidated it.**

Measured repair — plant the rogue **after** the foreign checkpoint, so neither `believed` nor `applied`
records it:

```
gate after guard : repository changed since capture: refs/heads/rogue was absent, now a0bcc9e4…
pristine         : entry was recorded in worktree '…-wt-agent' at …, not in the main worktree
```

**But that repair depends on the very behaviour part 1 removes.** After part 1, a rogue recorded by
neither side is skipped, so the fixture must instead use a rogue the target snapshot **does** record,
moved to a **third** value.
