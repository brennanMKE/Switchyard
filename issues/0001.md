## Description

Nothing else in the project can start until we know how libgit2 gets into a Swift package on macOS
in 2026. This is throwaway spike work whose only deliverable is a written decision.

Evaluate at least three routes: a system library target plus Homebrew, a vendored C target built
from source, and the current Swift bindings. Check SwiftGit2 and ObjectiveGit for staleness before
depending on either — both have been unmaintained for stretches. A Rust `gitoxide` bridge is a
legitimate alternative and deserves a paragraph of comparison, but the FFI and build complexity is
real, so default to libgit2 unless the spike finds a blocker.

## Expected behavior

- [ ] Each route built end to end far enough to link and call one libgit2 function from Swift.
- [ ] Universal binary (arm64 + x86_64) confirmed buildable, since the CLI ships inside an app bundle.
- [ ] Findings written to `docs/engine-findings.md` with a recommendation and the reasoning.
- [ ] Any route rejected has the specific reason recorded, not just "didn't work".

## Notes

Guide §5 "The engine decision". Blocks #0006 and everything after it.

Consumers of this decision are the CLI (built by `swift build`) *and* the app bundle's run-script
phase, so a route that only works from a terminal is not a route.

## Fix

Evaluated all three packaging routes.

## Verification

**Route A** (`systemLibrary` + `pkgConfig` + `.brew`) builds, links, and runs against real
repositories — it is what every other M0 probe used. **Route C** rejected on staleness checked
2026-08-06: `objective-git` last pushed 2023-09-17 (~3 years), `SwiftGit2` pre-1.0 at `v0.3` with 50
open issues. **Route B** (prebuilt `xcframework` via `binaryTarget`) identified as the shipping
route and deferred — nothing in M1 needs libgit2 in the bundle.

## Files changed

- `docs/engine-findings.md` — all three routes, with the two route-A traps
- `spike/libgit2-eval/` — throwaway evaluation (deleted by #0005)

## Gotchas

**Route A cannot ship.** It depends on the user's Homebrew, and the embedded `yard` (#0050) must run
on a machine with none.

Two traps that will resurface in CI (#0076) and the Xcode run-script phase (#0050): `pkg-config` is a
required dependency that `providers: [.brew(["libgit2"])]` does **not** install, and Homebrew is not
on the default non-interactive `PATH` — `swift build` needed `PATH=/opt/homebrew/bin:$PATH`.
