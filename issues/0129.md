# 0129 — Engine result types encode to the schemaVersion 1 envelope

| | |
|---|---|
| **Status** | open |

## Description

M1 exit criterion 1 (guide §9) requires each read-command engine function to return "a type that
encodes to a `schemaVersion: 1` envelope" — and no open issue owns that half. Surveyed 2026-08-07
during #0026's planning update: none of the engine result types in `YardKit/Sources/YardGit/`
(`WhereAmI`, `ConflictedFile`, `FileDiff`, `BlameLine`, `CommitLogEntry`, `GraphRow`,
`WorktreeEntry`, `WorktreeWhere`, `WorktreeStatus`, `SignatureVerification`, `WorktreeAddResult`,
`WorktreeRemoveResult`, `WorktreePrune.Report`, `WorktreeRepair.Repaired`) conforms to `Encodable`,
so none can be wrapped in `YardKit`'s `Envelope` (`EncodableResult` requires
`Encodable & Sendable`). The milestone review would find this gap; this issue files it now.

## Expected behavior (to be re-authored to code level before dispatch, per CLAUDE.md)

- [ ] Each engine result type behind `whereami`, `graph`, `status`, `hunks`, `conflicts`, `log`,
      `verify` and the `wt` group conforms to `Encodable` with explicit, stable JSON key names
      (an explicit `CodingKeys` enum exists AND its cases are the camelCase member names — phrased
      as a presence so it cannot be satisfied by deletion).
- [ ] A test per type encodes a real value through `Envelope`/`EncodableResult` and asserts on the
      JSON keys, in `YardKit/Tests/` (target to be settled at planning time — note `YardGitTests`
      does not currently depend on `YardKit`, so the envelope round-trip needs a dependency
      decision; that is a `Package.swift` question and likely a Sonnet round).
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line; N must exceed the
      pre-change baseline by the number of new tests, stated exactly once re-authored.

## Notes

Almost certainly a split into several one-type issues at planning time — one deliverable each.
When a type becomes `Encodable` and its command registers in `CommandRegistry`, #0026's golden
tests force a schema file into existence; the payload's field-by-field description lands there
through the regenerate-and-diff loop. Sequencing: after #0026; the per-type issues are
independent of each other.
