## Description

The original #0028 required "`switchyard`'s own ref enumeration filters `refs/switchyard/*`
everywhere it lists refs". Re-measured 2026-08-07 (git 2.50.1, Apple Git-155) at #0028's planning
pass, the exposure is narrower than the sentence suggests — but one leak is real, and nothing
currently pins any of it:

1. **`%D` decorations do not leak.** With an anchor ref pointing at `HEAD`,
   `git log -1 --format='%D'` prints `HEAD -> main` — custom namespaces (`refs/switchyard/*`,
   `refs/foo/*` both probed) are not decorated at all on this git. So `CommitLog`'s `%D` field is
   clean today, **unpinned**: no test would notice if a git upgrade or a format change started
   leaking journal refs into `refs` fields of log entries.
2. **`rev-list --all` DOES leak.** With one anchored snapshot commit present,
   `git rev-list --all` includes it (measured: present; a disconnected octopus-shaped commit in
   any future `--all`/`--branches`-style graph). `git rev-list --exclude='refs/switchyard/*' --all`
   excludes it (measured: absent). `graphRows(at:revisions:)` defaults to `["HEAD"]` today, so
   the graph leaks only when a caller passes `--all` — which the M3 graph view will want.
3. **`RefSnapshot` (#0027) already filters the namespace** for capture/restore, and
   `for-each-ref` output used by fixtures is test-side. No other engine enumeration lists all
   refs today (checked: `LaneAssignment`, `CommitLog`, `WhereAmI`).

**Structured stub, split from #0028 on 2026-08-07.** Re-authored to code level at dispatch.

## Planning update — 2026-08-08, authored in-context, all facts re-measured

### Given 1 — the leak, reproduced

In a two-commit repository with one anchored snapshot commit at
`refs/switchyard/journal/01PROBE`:

- `git rev-list --all` → **3 commits, the snapshot present.** It leaks.
- `git rev-list --exclude='refs/switchyard/*' --all` → **snapshot absent.** The exclusion works.

### Given 2 — `--exclude` is a no-op for explicit revisions. Measured, and this is what makes the fix one line.

`git rev-list --topo-order --parents HEAD --` and the same with
`--exclude='refs/switchyard/*'` inserted produce **byte-identical output** (compared by `md5`).

Git's `--exclude=<glob>` applies to the **next** `--all`/`--branches`/`--tags`/`--remotes` and to
nothing else. So the flag can be added **unconditionally** — it costs nothing when
`revisions == ["HEAD"]`, which is the default, and it takes effect exactly when a caller passes
`--all`. No conditional, no inspection of the revisions array.

### Given 3 — `%D` does not leak today, and that is worth pinning as-is

`git log -1 --format='%D'` with an anchor pointing at `HEAD` prints `HEAD -> main`. Custom
namespaces are not decorated on this git. The value of a test here is **regression detection**: if a
future git starts decorating custom namespaces, `CommitLog`'s `refs` field would begin carrying
journal refs into the UI, and nothing would notice.

## Change 1 — `YardKit/Sources/YardGit/LaneAssignment.swift`

In `graphRows(at:limit:revisions:git:)`, insert one line after the `--max-count` block and **before**
`arguments += revisions`:

```swift
    // Journal refs are engine bookkeeping and must never appear in the graph.
    // `--exclude` applies only to a FOLLOWING `--all`/`--branches`/`--tags`/
    // `--remotes`, so this is a measured no-op for the default `["HEAD"]` and
    // takes effect exactly when a caller passes `--all` — which the M3 graph
    // view will. Unconditional on purpose: a conditional would have to inspect
    // the revisions array and would miss `--branches`, `--tags`, `--remotes`.
    arguments.append("--exclude=\(RefSnapshot.switchyardNamespace)*")
```

Use `RefSnapshot.switchyardNamespace` rather than a literal — `ServiceNamesTests` scans sources,
including comments, for hardcoded identifier strings.

## Change 2 — `YardKit/Tests/YardGitTests/`, two tests

1. **The exclusion**: build a repository with an anchored snapshot commit, call
   `graphRows(at:revisions: ["--all"])`, and assert the snapshot's oid is **absent** while the
   ordinary commits are present. The "ordinary commits present" half is required — an empty result
   would otherwise satisfy the absence assertion.
2. **The `%D` pin**: with an anchor pointing at `HEAD`, assert `CommitLog`'s `refs` field for that
   commit contains `main` and does **not** contain `switchyard`. This pins current behaviour so a
   future git that starts decorating custom namespaces fails here rather than in the UI.
