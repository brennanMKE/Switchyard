## Description

The original #0028 required "`switchyard`'s own ref enumeration filters `refs/switchyard/*`
everywhere it lists refs". Re-measured 2026-08-07 (git 2.50.1, Apple Git-155) at #0028's planning
pass, the exposure is narrower than the sentence suggests — but one leak is real, and nothing
currently pins any of it:

1. **`%D` decorations do not leak.** With an anchor ref pointing at `HEAD`,
   `git log -1 --format='%D'` prints `HEAD -> main` — custom namespaces (`refs/switchyard/*`,
   `refs/foo/*` both probed) are not decorated at all on this git. So `CommitLog`'s `%D` field is
   clean today, **unpinned**: no test would notice if a git upgrade or a format change started
   leaking journal refs into `refs` fields of log entries.
2. **`rev-list --all` DOES leak.** With one anchored snapshot commit present,
   `git rev-list --all` includes it (measured: present; a disconnected octopus-shaped commit in
   any future `--all`/`--branches`-style graph). `git rev-list --exclude='refs/switchyard/*' --all`
   excludes it (measured: absent). `graphRows(at:revisions:)` defaults to `["HEAD"]` today, so
   the graph leaks only when a caller passes `--all` — which the M3 graph view will want.
3. **`RefSnapshot` (#0027) already filters the namespace** for capture/restore, and
   `for-each-ref` output used by fixtures is test-side. No other engine enumeration lists all
   refs today (checked: `LaneAssignment`, `CommitLog`, `WhereAmI`).
