## Description

**Proposal 3 of the M1 milestone review, sixth pass, 2026-08-18 — a latent correctness bug, not a
coverage gap.** `WorktreeWhere` omits `-z` where `WorktreeList` requires it.

`YardKit/Sources/YardGit/WorktreeWhere.swift:50` runs:

```swift
["worktree", "list", "--porcelain"]
```

and splits the output on newlines. **`WorktreeList` runs the same command with `-z`** precisely because
a worktree path may contain a newline — and `WorktreeListTests.newlineInPathRoundTrips` pins that for
`worktreeList`. There is no equivalent for `yardWhere`, and with a newline in a path it mis-parses.

This is the `CLAUDE.md` rule about never parsing git output naively, in the one place the M1 command set
did not apply it consistently. It is filed as a **production defect** rather than a review finding
because the code is wrong, not merely untested.

## Expected behavior

- [ ] `WorktreeWhere` passes `-z` and splits on NUL, matching `WorktreeList`'s handling. **Read
      `WorktreeList`'s parser first and follow it** rather than writing a second convention — the two
      commands parse the same output and should not disagree about how.
- [ ] A test with a newline in a worktree path, mirroring `WorktreeListTests.newlineInPathRoundTrips`.
      That test is the model for both the fixture and the assertion.
- [ ] **Mutation:** drop `-z` again. The new test must redden.
- [ ] Check whether `mainWorktreeLine` and the other line-oriented helpers in that file need the same
      treatment, and say what you found — a partial fix here is worse than none, because it would read
      as done.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.
