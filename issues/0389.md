### It is a new request for `Rewrite`, not a new engine

Verified against `YardKit/Sources/YardGit/Rewrite.swift` at `1b00f27`. `Rewrite.perform` already does
everything a rebase needs, given a `Plan`:

- it checks out `detachAt` detached;
- it runs **one** `git cherry-pick <signing> <picks…>`;
- it moves the ref once with the old value pinned (`moveRef`);
- it re-attaches with `symbolic-ref HEAD <refName>`.

The `Plan` fields are `operation`, `rebuild`, `detachAt`, `picks`, `refName`, `oldTip`, `attached`.
A rebase onto `T` is
`Plan(operation: "rebase-onto", rebuild: nil, detachAt: T, picks: <below>, refName: head.refName, oldTip: head.tip, attached: head.attached)`.

```swift
// Rewrite.swift, public API beside `reorder` (not compiled)
public static func rebaseOnto(
    target: String,
    signing: CommitCreate.Signing = .config,
    at path: String,
    git: GitProcess = GitProcess(),
    extraEnvironment: [String: String] = [:]
) throws -> Result {
    try run(.rebaseOnto(target: target), signing: signing,
            at: path, git: git, extraEnvironment: extraEnvironment)
}
```

### The `walk` arm, and the measurements behind it

git 2.50.1, 2026-09-12, scratch repository: `main` = `c1..c3`; `topic` forked at `main~1` with `t1`, `t2`.

1. **Resolve** the target (`resolve`, `.unknownCommit`), then `refuseUnmergedIndex`, then
   `resolveHead(at:git:extraEnvironment:)`.
2. **Detached `HEAD`** (`head.attached == false`) → new
   `RewriteError.detachedHeadRefused(operation: "rebase-onto")`. There is no branch to rebase.
3. **Already based on it**: the target equals `head.tip`, or
   `merge-base --is-ancestor <target> <tip>` exits 0 → `.nothingToDo` (existing case). *Measured*:
   `git rebase topic~1` on `topic` exits 0 with `Current branch topic is up to date.`
4. **The target contains the branch**: `merge-base --is-ancestor <tip> <target>` exits 0 → new
   `.rebaseTargetContainsBranch(target:ref:)`. *Measured*: `git rebase topic` on `main` exits 0 and
   **fast-forwards** `main`. That is a merge, not a rebase, so refuse it and let the UI say
   "merge it instead".
5. **Unrelated histories**: `merge-base <target> <tip>` exits 1 (*measured* for unrelated histories
   in #0388) → new `.unrelatedHistories(target:)`.
6. **Picks** = `rev-list --reverse --first-parent <target>..<tip>`. *Measured* on the fixture:
   `t1, t2`. Any pick with more than one parent → new `.mergeInReplayRefused(commit:)`, before
   mutation. The replay cannot cherry-pick a merge:
   `rewordBelowAMergeFailsTheReplayAndTouchesNothing` (`YardKit/Tests/YardGitTests/RewriteTests.swift`).

The new `RewriteError` cases map to `.repositoryError`. Adding cases breaks any exhaustive `switch`
over `RewriteError` (check `YardKit/Sources/YardCommands/RewriteServing.swift`); the compiler lists
each site.

### Conflicts (*measured*, relevant to #0394)

A conflicted multi-pick leaves `.git/sequencer/todo` holding the remaining picks.
`git cherry-pick --continue` finishes them, **but `HEAD` stays detached and the branch does not
move**: the ref move and re-attach live only in `perform`'s memory. `perform` leaves exactly that
resumable state (its `catch` rethrows `.blockedOnConflicts` without aborting). So continuing a
conflicted rebase from outside needs the plan persisted; that is #0394's concern, not this issue's.

## Expected behavior

- [ ] `Rewrite.rebaseOnto(target:…)` replays the current branch's first-parent commits after the fork
      point onto the target and moves the branch once, inside one journal checkpoint; `JournalUndo.undo`
      restores the pre-state (fixture test on the topic/main shape above).
- [ ] Refusals before mutation: detached `HEAD`, already based on the target, the target containing the
      branch, unrelated histories, and a merge among the picks.
- [ ] Signed commits stay signed through the replay (explicit flag, as `Rewrite` already does). Tests
      live in `YardKit/Tests/YardGitTests/RewriteTests.swift`, and `swift test` prints
      `Test run with N tests`.
