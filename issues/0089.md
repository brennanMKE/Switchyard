## Description

Work logs record `hosted — not separately metered` for authoring and review because nothing measures
them. That makes the delegation's value unfalsifiable: local implementation is provably $0.00, but
the hosted side it is being compared against has no number at all.

Two facts about the current setup:

- **Dispatcher subagents do report** `subagent_tokens` on completion. That is measured data and is
  now priced in the work logs, at a stated 85/15 input/output assumption.
- **The main loop reports nothing per-turn**, and there is no `ANTHROPIC_API_KEY` or `ant` CLI on
  this machine, so `count_tokens` cannot be called to measure an artifact either.

The gap is structural, not an oversight, which is why it is an issue rather than a TODO.

## Expected behavior

- [ ] A documented way to obtain per-issue authoring and review token counts — an `ant` CLI install
      with a profile, an API key available to the session, or a harness-side usage report.
- [ ] `scripts/` gains a helper that converts token counts to dollars using the rate table in
      `issues/Issues.md`, so the arithmetic is not re-derived by hand per issue.
- [ ] The input/output split is measured rather than assumed, retiring the 85/15 estimate — or the
      assumption is validated against real data and kept deliberately.
- [ ] A cumulative view: total hosted spend against total local rounds, so the delegation's actual
      economics are visible across the project rather than per issue.
- [ ] `issues/Issues.md` updated to require real figures once they are obtainable.
