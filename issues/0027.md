## Description

Every piece of a snapshot is a real git object — nothing is invented, and nothing lives outside the
repository. Three pieces: refs, index, worktree.

Refs and `HEAD` are a list of name/OID pairs captured with `git for-each-ref` plus `git symbolic-ref
HEAD`, stored as a blob, restored with `git update-ref --stdin` (which is transactional — the whole
batch applies or none of it does). The index is captured as a tree written from a temporary index.
The worktree is captured with `git stash create`, which builds a stash commit from the current
worktree and index and prints its OID **without touching the worktree or the stash stack** — this
primitive is underused and is what makes worktree capture cheap.

## Expected behavior

- [ ] Ref capture and restore round-trip exactly, including symbolic `HEAD` and detached `HEAD`.
- [ ] Restore uses `git update-ref --stdin` so a partial application is impossible.
- [ ] Index captured as a tree in the normal case.
- [ ] **Unmerged index handled**: `git write-tree` refuses one, so the index file is snapshotted as a blob and restored byte-for-byte.
- [ ] Worktree captured via `git stash create`, leaving the stash stack untouched — asserted by a test.
- [ ] **Untracked files captured separately.** `git stash create` silently ignores `-u` (verified on git 2.50.1 — it yields a 2-parent commit with tracked changes only; only `git stash push -u` gives the 3-parent form, and `push` mutates). Build a tree from untracked non-ignored paths via a temporary `GIT_INDEX_FILE` + `write-tree` + `commit-tree`, and record that OID alongside.
- [ ] A test asserts an untracked file survives a snapshot/restore round trip. Without it this regresses invisibly.
- [ ] All three restore paths verified by round-trip, not by inspection.
