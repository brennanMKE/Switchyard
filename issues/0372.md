## Description

**Child of #0358, split 2026-09-12.** One deliverable: each branch row in the sidebar shows that
branch's ahead/behind count and its merged state, as #0373 defines them.

**Unblocked 2026-09-13 — §11 decision 27 defines both terms.** Merged is the M6 composite
(ancestry, else upstream-gone, else content, with "unknown"); ahead/behind is A3 (upstream when
set, else the default branch, baseline named in the row); the default branch is `origin/HEAD`'s
target falling back to `main`. Do not re-open the definition question; implement as decided.

*Measured* engine gap (2026-09-12, `2d96d3e`): nothing in `YardKit/Sources/YardGit` computes a
per-branch ahead/behind or a merged state. Grep for `upstream:track`, `ahead-behind` and `left-right`
finds nothing, and `for-each-ref` appears only in journal code. `WhereAmI` covers `HEAD` alone.

## Expected behavior

- [ ] Each local branch row shows ahead/behind as §11 decision 27 defines it (A3): against the
      branch's upstream when one is set, else against the default branch (`refs/remotes/origin/HEAD`'s
      target, falling back to `main`), with the row naming which baseline the numbers are against.
- [ ] Each local branch row shows the merged state §11 decision 27 defines (M6): **merged** by
      ancestry (0 ahead of the default branch), else **merged** when the upstream reads `[gone]`,
      else **merged**/**not merged** by `git merge-tree --write-tree` against the default branch's
      tree, and **unknown** where merge-tree reports a conflict.
- [ ] The synchronous engine read at sidebar load is one `for-each-ref` process carrying
      `%(upstream:track)` and `%(ahead-behind:<default>)` together, within decision 27's budget of
      ≤ 100 ms wall clock on the largest measured corpus; the content check runs as a background
      pass that fills the merged column after the sidebar appears, showing *unknown* until it lands.
