## Description

Decisions 38, 39 and 41 built switching and tag deletion, file history and blame, and remote
management into the engine and the app, and each deferred its CLI verbs. An agent driving
`switchyard` today cannot switch branches, delete a tag, read a file's history or blame, fetch one
remote, or add/rename/remove a remote without falling back to raw `git` — which bypasses the
journal for the mutating ones and hands it unparsed text for the read ones.

**Guide §11 decision 43 is the design.** Each verb is a thin arm in `YardCommands` over the engine
call the app's menu item makes, in decision 37's shape: `CommandRegistry` entry, `runEngineCommand`
case, `engineSuccess` / `engineUsage` / `engineFailure`, schema and `SKILL.md` regenerated,
in-process tests against fixtures (bare remotes in a temporary directory, never the network). The
whole set was prototyped in a planning worktree (`../sy-plan-cli2`): it compiled, the full suite
passed with every child applied (YardCommandsTests +35 over its baseline; every other bundle
unchanged), and every mutation listed in a child turned its suite red.

## Questions for Brennan

Each has a decision in place (decision 43) and is cheap to reverse. Answer in this file.

1. **`tag --delete`, not `tag delete`.** `tag delete v1` already creates a tag named `delete` at
   `v1` (#0363), so the word cannot become a subcommand without breaking that; git's own spelling
   is `git tag --delete`. A test pins that `tag delete v1` still creates the tag. Assumed right.
2. **`file-history` as its own verb rather than `log --follow -- <path>`.** `log`'s payload is
   `CommitLog` entries; a file's history carries a per-commit `status` and `previousPath`. One verb,
   one payload shape. Would you rather `log` grow flags (it refuses every `-` token today, #0346)?
3. **`switch` only — no `checkout` alias, no `--create`, no `switch -`.** Branch creation is `branch
   create` then `switch`; `--track origin/x` always makes `x` (decision 38 question: choosing the
   local name). Add any of these?
4. **A switch blocked by local changes is exit 6 with the files named in the message**, never an
   automatic stash (the app offers Stash Changes and Switch; an agent runs `stash push` itself).
   Should the refusal instead be `ok: true` with a `blockedPaths` field, or carry a `hint`?
5. **`tag --delete` exits 6 for an unknown tag while `tag <name> <commit>` still flattens its
   refusals to 4** (#0497 question 4 — the older arms predate decision 37). Retrofit `tag` and
   `branch` to `engineFailure` in a follow-up?
6. **Remote `add` does not fetch.** The app's sheet fetches by default; over the CLI an agent runs
   `fetch <name>` next, so the add cannot fail for a network reason. Assumed right.
7. **Out of scope, pending your call:** deleting a remote branch (a push), editing push URLs,
   history search over the CLI (decision 40's Paths and Content scopes), `blame` with git's other
   `-L` forms, `file-history` of a folder.
