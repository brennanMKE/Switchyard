## Description

**Split out of #0039 on 2026-08-17.** #0039 fixes up the **staged index** into an ancestor commit. This
issue adds the other half of guide §6's `fixup`: take an **existing commit** — `HEAD` by default — and
squash it into an older ancestor.

Different mechanism, which is why it is a separate issue. #0039 creates the `fixup!` commit with
`git commit --fixup=<target>`, so git writes the subject. Here the commit already exists and must be
re-labelled: rewrite its message to `fixup! <target subject>` (or use `git commit --amend --fixup`, or
build the todo list directly), then autosquash. Only the autosquash step is shared.

## Expected behavior

- [ ] `Fixup.run(source:target:…)` where `source` defaults to `HEAD` and must be a descendant of `target`.
- [ ] Refuses when `source` is not a descendant of `target`, and when `source == target`.
- [ ] Refuses when the index is dirty — otherwise the staged changes are silently swept into the rebase.
      #0039's `.nothingStaged` guard is the mirror image of this one; state which error each is.
- [ ] The same conflict, signing, and checkpoint behaviour #0039 measured — reuse its code paths rather
      than a second copy.
