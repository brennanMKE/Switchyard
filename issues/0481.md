## Description

#0475 fixes `HunkParser`, which split git output on the Character `"\n"`. Swift treats `"\r\n"` as
a single grapheme cluster, so a CRLF file's lines merged into one, and swallowed later files. The
#0474 planner noted that `Blame.swift` may have the same bug; it was not measured. A line whose
first scalar is a combining mark would also be misread by `line.first`.

## Expected behavior

- [ ] Every parser of git output in YardKit is audited for `split(separator: "\n")` or `.first`
      on Character strings over git text. Each one is reproduced with a CRLF fixture (and a
      combining-mark line where relevant) before it is changed.
- [ ] Each affected parser splits on UTF-8 bytes or unicode scalars, with tests that fail without
      the change.

Needs an Opus planning pass before dispatch, after #0475 merges.
