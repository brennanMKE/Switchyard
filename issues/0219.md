# 0219 — switchyard --version reports the host app's version

## Description

**Split out of #0050 on 2026-08-17.** `switchyard --version` prints `switchyard 0.0.1`, from
`YardKit.version` — a hardcoded string in `YardKit/Sources/YardKit/YardKit.swift:11`. Once the binary
ships inside the app bundle it should report the **host app's** version, so a bug report names the
build it came from rather than a constant nobody bumps.

## Expected behavior

- [ ] The CLI resolves its version from the host bundle's `Info.plist` —
      `CFBundleShortVersionString`, plus `CFBundleVersion` in parentheses when they differ.
- [ ] **Symlinks are resolved first.** The installed entry point is `/usr/local/bin/switchyard`, a
      link into the bundle; without `resolvingSymlinksInPath()` the walk upward lands in
      `/usr/local` and finds no plist. This is the whole reason the helper is not three lines.
- [ ] Outside a bundle — running from `.build/debug/switchyard`, which is how every test runs it —
      the answer is the package version, not a crash and not an empty string. State which.
- [ ] `--version` keeps its current shape otherwise: plain text, no envelope, exit 0. Guide §11
      decision 6 — `--help` and `--version` print plain text; every other command emits JSON.
- [ ] Tests cover both branches by constructing a fake bundle layout in a temp directory
      (`Contents/Info.plist` plus `Contents/Resources/bin/`) and pointing the resolver at it. The
      resolver therefore takes the executable URL as a parameter rather than reading `Bundle.main`
      internally — that is what makes it testable at all.

## Notes

The implementation to adapt is in `../../RemoteControl/docs/cli-embedding-and-install.md` §3 under
"Report a real version" (MIT, same author). **Blocked by #0050**, which puts the binary in a bundle
for the first time.

## Planning update — 2026-09-03. Files and verification.

- `YardKit/Sources/YardKit/VersionResolver.swift` (NEW) — the resolver: takes the executable URL as a
  parameter, resolves symlinks, walks up to `Contents/Info.plist`, reads `CFBundleShortVersionString`
  (+ `CFBundleVersion` in parentheses when they differ); outside a bundle it returns `YardKit.version`
  — the package version, stated, not a crash and not an empty string.
- `YardKit/Sources/YardKit/CommandLineRunner.swift` — the `--version`/`-v` arm at line 96 calls the
  resolver instead of interpolating `YardKit.version`. Plain text, no envelope, exit 0 (guide §11
  decision 6) — unchanged shape.
- Tests in `YardKit/Tests/YardKitTests/VersionResolverTests.swift` (NEW): both branches via a fake
  bundle layout built under `build/` inside the worktree (NEVER `/tmp` or `/var/tmp` — the sandbox
  auto-rejects them): `Contents/Info.plist` + `Contents/Resources/bin/`, symlinked and unsymlinked
  entry points, differing short/version strings, and the no-plist branch returning the package
  version.
- Verification: `cd YardKit && swift test` prints `Test run with N tests` with **N greater than 1260**,
  the count on main before this change. State the delta. `swift run switchyard --version` (or the
  built binary directly) still prints plain text and exits 0.
