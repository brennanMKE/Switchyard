## Description

**Proposal 1 of the M1 milestone review, seventh pass, 2026-08-18, filed for the one item in it that is
a defect rather than untidiness.** `CommitLogOptions.includeBody`'s doc comment **promises a behaviour
that does not exist**.

`YardKit/Sources/YardGit/CommitLog.swift:133` states *"Without this option, only `subject` is
available"*. That is false: passing it changes nothing. `.agentOnly` is the only option ever read
(`CommitLog.swift:187,249`).

**A false doc comment is worse than a dead member**, because a caller reads it and believes it —
exactly how `SignatureVerification`'s "requires a real signing key" comment kept `signer`/`key`
untested until #0270 disproved it.

## Expected behavior

- [ ] **`includeBody`'s doc comment is corrected** — either to describe what the option actually does,
      or the option is deleted. **Decide which and say why**: if `log` is meant to grow a body-fetching
      mode, the option is a placeholder and the comment should say so; if not, it is dead.
- [ ] **The same question, once, for each remaining member**: delete, or keep with a comment saying what
      it is for. **Do not delete anything you cannot argue is unreachable** — check the app target and
      the CLI, not just `YardGit`, since a member reached only from `YardUI` would look dead from here.
- [ ] Anything deleted must leave the suite green **without** a test being changed to accommodate it. If
      a test has to change, the member was not dead — say so and keep it.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, at or above the count in `docs/test-baseline.txt` (this issue may not add tests, and an
      unchanged count is an acceptable outcome — say so explicitly if it happens).

**Milestone M1.** **Not a criterion violation** — the review was explicit that dead code violates none

## Work log

- **Round 1 — 2026-08-18, Sonnet subagent, 89,896 tokens, 8m22s, accepted.** Ten members deleted, no
  tests added — and the round **said so explicitly** rather than leaving an unchanged count reading as a
  failed run.
- **`includeBody` was deleted rather than corrected, with the reasoning given**: the format string
  fetches `%B` unconditionally, no subject-only parse path exists for the option to gate, and nothing in
  `docs/` or `issues/` names a planned one. A corrected comment would have documented an option that
  does nothing.
- **`parseClean` carried the same shape of false claim** — "exposed for testability", when the tests
  call `CommitLog.parse` directly. Two false comments in one file is the thing worth noticing here:
  the comments were describing an intent that the code never grew into.
- **No test had to change to accommodate any deletion**, which is the evidence that the members were
  unreachable rather than merely unused — the standard the issue set.
- **Reviewed by re-running** the suite twice on the merged result (1103 tests) and by grepping for every
  deleted name across `Sources`, `Tests` and the app target: the only survivors are a wire test
  asserting three of those keys are **absent** from the JSON, which they still are.
