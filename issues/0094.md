## Description

Resolve and report the current worktree context: worktree id, path, `$GIT_DIR`, `$GIT_COMMON_DIR`,
and the main worktree's path. The smallest of the worktree commands and a good first one — it is a
pure read over `WorktreeContext`, which #0009 already built.

## Givens — verified on `main`, treat as true

1. `YardKit/Sources/YardGit/WorktreeContext.swift` exists and provides, all public:
   - `WorktreeContext.resolve(...)` — the entry point; use it, do not resolve paths yourself.
   - `topLevel: String?` (nil in a bare repo), `gitDir: String`, `commonDir: String`,
     `worktreeName: String?`, `isLinkedWorktree: Bool`, `isBare: Bool`.
   - `path(for name: String, git:) throws -> String` and `resolveRef(...)`.
2. **`WorktreeContext` does not expose the main worktree's path.** Get it from
   `git worktree list --porcelain` — its **first** `worktree <path>` line is by definition the main
   worktree, in every worktree of the repo. Verified from a linked worktree: the first entry is the
   primary checkout, not the current one. Do **not** derive it by trimming `/.git` off `commonDir`;
   that is string surgery that breaks on bare repos and on a `.git` file pointing elsewhere.
3. `YardKit/Sources/YardGit/FixtureRepository.swift` provides
   `addWorktree(named name: String, branch: String) throws -> URL`, so the test can build a real
   linked worktree rather than simulating one. It also has `build(_:)`, `branch(_:at:)`,
   `destroy()`, and `RefFormat.supported()` for the dual-format sweep.
4. All shell-outs go through `GitProcess` (`YardKit/Sources/YardGit/GitProcess.swift`). Do not call
   `Process` directly — every shell-out is centralised there so the boundary stays testable.

- [ ] A function taking a path and returning a value type with those five fields — no printing. Name

- [ ] Correct in the main worktree, in a linked worktree, and in a bare repository.

- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line

## Tests must be able to fail

- Assert the extraction is non-empty before comparing it. A helper that silently returns nothing
  turns the following assertion into `[] == []`, which passes unconditionally — that has already cost
  a round here.
- No `#expect(true)` or any assertion over literals.
- The linked-worktree case must assert `gitDir != commonDir` **and** that `mainWorktreePath` is the
  primary checkout rather than the linked one. Asserting only that the two dirs differ would pass for
  a function that returned the wrong main path.

The given that mattered was #2 — that `WorktreeContext` does **not** expose the main worktree's path,
and that the first record of `git worktree list --porcelain` is the way to get it. That was probed
from inside a linked worktree before the issue was written, precisely because the obvious
alternative, trimming `/.git` off `commonDir`, is wrong on bare repos and on a `.git` file pointing
elsewhere.

`mainWorktreePath` was flagged in the issue as the assertion most likely to be vacuous — a function
returning the *current* worktree would satisfy a weaker test. Mutation-checked: replacing the
porcelain lookup with `ctx.topLevel` fails four tests across both ref formats.

One deliberate choice the issue did not specify: a bare repository returns `nil` for both `path` and
`mainWorktreePath`, rather than the bare directory that porcelain does report. Documented in the
source.
