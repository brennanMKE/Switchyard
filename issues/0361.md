# 0361 — Merge a branch into the current branch

## Description

**Merge into Current Branch… (⌃M)** from GitUp's context menu (#0359): merge the selected
branch into the current one, non-interactively. Switchyard has no merge operation — the resolve
UI (#0057) exists for conflicts but nothing in the engine *starts* a merge.

This is the first operation that creates merge commits, which the journal's machinery already
anticipates (`SequencerSnapshot`, `commitDiff`'s `--cc` handling for clean merges, the
mid-rebase-amend dedup). The new engine surface is the merge itself: find the merge base, run
`git merge --no-ff`/`--ff-only` per intent, surface conflicts as the resumable state the resolve
UI already consumes.

## Expected behavior

- [ ] `yard merge <branch> [--ff-only|--no-ff]` merges into the current branch; the default
      intent is explicit, never git's silent fast-forward guess.
- [ ] Auto-checkpoint; undo restores exactly (including dropping a merge commit).
- [ ] Conflicts exit 8 with the resumable merge state; the resolve UI (#0057) can complete it.
- [ ] The merge commit message is settable non-interactively; signing per the explicit-`-S` rule.
- [ ] Refusals typed before mutation: already-up-to-date, unrelated histories (refuse unless
      `--allow-unrelated` is a stated intent), unmerged index.

## Notes

The context-menu item disables when the node is on the current branch — the UI state mirrors
these typed refusals (#0359's pattern).
