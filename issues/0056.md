## Description

Surface a decision in the app UI and block on the answer:
`yard ask "<question>" --options a,b,c [--timeout N]`. The general form of the human-in-the-loop
pattern, for the cases that are not diff review.

## Expected behavior

- [ ] Question and options render in the app; the chosen option returns as structured data.
- [ ] `--timeout` produces a documented distinct outcome, not an arbitrary default choice.
- [ ] Exit 3 when the app is unavailable; exit 7 when the human declines to answer.
- [ ] The question appears on the tab for the repository the asking session is working in, routed through #0084.
- [ ] Multiple concurrent asks from different agent sessions do not collide — one per tab is the natural resolution, so asks for different repos are independently answerable.
- [ ] A second ask for a repository that already has one pending queues rather than replacing it.
- [ ] Question text is rendered as text — never interpreted as markup or a link.

## Notes

Guide §6, §4 "The UI hierarchy". Blocked by #0055, #0084.

The question comes from an agent, so treat it as untrusted input for rendering purposes.

## Planning pass — 2026-09-03, to code level. #0055's machinery, generalised.

`ask` is `review` minus the diff: the same wire pattern, the same blocking semantics, the same
pending-store shape — with a QUEUE instead of supersede (the issue's own criterion: a second ask for
a repository that already has one pending **queues** rather than replacing; that is the one
behavioural difference from review, where a second request supersedes).

- `YardKit/Sources/YardKit/AskRequest.swift` (NEW) — `AskRequest` (repository commonDir — CLI sends
  the path, app resolves, the #0055 pattern; question text; `options: [String]` in order;
  timeoutSeconds), `AskReply` (the chosen option's INDEX plus its text — an index is what survives
  option reordering and is unambiguous; optional `message`), `AskOutcome` (decided/timedOut/
  superseded-n-a — review's outcome vocabulary, adapted). `AskWireTests` pins bytes; nils omitted.
- `ExitCode`: no new case — timeout is `timedOut = 10` (shared with review, per the #0055 planning
  decision that every M4 interactive command inherits it); decline-to-answer is 7 (`humanDeclined`).
- `AppServiceProtocol.performAsk(request:reply:)` + the `AppConnection` client call (#0154/#0055
  pattern).
- `YardKit/Sources/YardKit/PendingAskStore.swift` (NEW) — keyed by commonDir, **FIFO queue** per
  repository: the head is presented; answering it presents the next; timeout applies to the head
  (a queued ask's timer starts when it reaches the head — decide and document). Never AppKit.
- The CLI arm: `ask` joins `CommandRegistry.all` (name "ask", schemaName "ask", flags
  `--timeout <seconds>`, the question + `--options a,b,c` as positional/flag arguments — parse
  strictly, refuse empty options with usage), exit codes 0 (answered)/7 (declined)/3/5/10; payload
  nil (options is an array). Golden schema regenerated; step-6 binding per the amended pattern.
- The sheet: `AskSheet.swift` in YardUI (the #0055 round-2 pattern — value-driven model, per-tab
  presentation via #0084, question rendered as TEXT — never markdown/links; the untrusted-input
  rule). One sheet per repository showing the head of its queue.
- Tests: wire bytes; round-trip through a real anonymous XPC listener; exit 3 app-down; timeout →
  10; decline → 7; queue order (three asks, answered in order); cross-repo independence; the
  question-is-text rule (a question containing `<script>`-ish content renders as literal text —
  assert the model carries it verbatim and the view has no markdown renderer).
- Mutations: timeout→exit 0 red; queue→replace red (the second ask must NOT supersede); one more.
- Verification: `cd YardKit && swift test` — **N greater than 1401**, the count on main. State the
  delta. `xcodebuild build … CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO` → `** BUILD
  SUCCEEDED **`. Manual scenarios append to `scripts/verify-review.md`'s sibling — a new
