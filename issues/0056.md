## Description

Surface a decision in the app UI and block on the answer:
`yard ask "<question>" --options a,b,c [--timeout N]`. The general form of the human-in-the-loop
pattern, for the cases that are not diff review.

## Expected behavior

- [ ] Question and options render in the app; the chosen option returns as structured data.
- [ ] `--timeout` produces a documented distinct outcome, not an arbitrary default choice.
- [ ] Exit 3 when the app is unavailable; exit 7 when the human declines to answer.
- [ ] The question appears on the tab for the repository the asking session is working in, routed through #0084.
- [ ] Multiple concurrent asks from different agent sessions do not collide — one per tab is the natural resolution, so asks for different repos are independently answerable.
- [ ] A second ask for a repository that already has one pending queues rather than replacing it.
- [ ] Question text is rendered as text — never interpreted as markup or a link.

## Notes

Guide §6, §4 "The UI hierarchy". Blocked by #0055, #0084.

The question comes from an agent, so treat it as untrusted input for rendering purposes.
