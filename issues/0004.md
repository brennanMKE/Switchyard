## Description

Reftable becomes the default reference storage format for newly created repositories in Git 3.0. A
libgit2 build that cannot read reftable will appear to work perfectly and then return *nothing* —
not an error, nothing — on any repo using it. Zed dropped libgit2 for the git CLI in June 2026
partly over this. Reftable support has landed upstream in libgit2, but "merged" and "in a tagged
release you can build against on macOS" are different states, and only a test tells us which we have.

## Expected behavior

- [ ] A repo created with `git init --ref-format=reftable` is used as the fixture.
- [ ] The chosen build can enumerate refs, resolve `HEAD`, and read the reflog in it.
- [ ] The exact libgit2 version tested is recorded, not just "latest".
- [ ] Finding recorded in `docs/engine-findings.md`, including what the fallback costs if negative.

## Notes

Git internals §1. This does not stop the project if it fails, but it **must be settled before M1
starts**: a negative answer moves ref enumeration and graph traversal onto `git for-each-ref` and
`git rev-list`, shifting the hybrid boundary substantially toward the CLI. That is not a retrofit.

## Fix

Built a throwaway `systemLibrary` + Homebrew spike and probed two fixtures differing only in ref
format, plus `git/git` as a large-repo control.

## Verification

`spike/libgit2-eval` `eval` binary, libgit2 1.9.6. The `files` fixture passed all five probes
(open, enumerate 3 refs, resolve HEAD, read 3 reflog entries, walk commits). The `reftable` fixture
**failed at `git_repository_open`** with `unsupported extension name extensions.refstorage`, making
every later probe unreachable. `git/git` passed all probes with 1,018 refs enumerated.

Fallback confirmed against the same reftable repository libgit2 refused: `for-each-ref`,
`rev-list --count`, `symbolic-ref`, `reflog`, `rev-parse --git-dir --git-common-dir`,
`stash create`, and `update-ref` (created `refs/switchyard/journal/test`, resolving to `9c2e51043c`).

Confirmed upstream rather than a packaging lag: v1.9.6 is the latest release, `refdb_reftable.c` and
`deps/reftable/` exist only in `main`, and the tracking issue is still open.

## Gotchas

libgit2 does not degrade gracefully here. It fails at `git_repository_open`, so any code that treats
a nil repository handle as "empty repo" rather than "unsupported format" will report a reftable
repository as having no history rather than as unreadable.
