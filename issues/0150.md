## Description

Git internals §3 puts three things in `~/.local/state/switchyard/` (or `$XDG_STATE_HOME/switchyard`):
the repository registry, **cross-repo recent operations**, and agent session records — the store
behind "what did I do everywhere today". #0029 was re-scoped to the repository registry only; this
issue owns the recent-operations store.

It cannot be specified to code level until the journal entry shape exists: each journal write
appends one cross-repo record referencing the repository identity (#0149), the journal entry id,
the operation, the timestamp, and the agent session — all fields #0028 defines.

## Expected behavior — sketch; re-author to code level at dispatch, per the planning standard

- [ ] A store file beside `repositories.json` in the injected state directory, written with the
      same required-injection, atomic-replace, owner-only pattern `RepositoryRegistry` established
      (#0029) — no test may touch the real state directory.
- [ ] Appending a record and querying "most recent across all repositories" both covered by tests
      with a mutation table.
- [ ] Bounded: a count limit so the file cannot grow without limit, aligned with #0033's pruning
      defaults.

### `YardKit/Sources/YardKit/RecentOperations.swift`

Same shape as `RepositoryRegistry` (`YardKit/Sources/YardKit/RepositoryRegistry.swift`) — **read it
first and copy its structure, not just its idea.** Every property in it exists for a reason this
issue shares: required directory injection, `.atomic` writes, an owner-only directory, a
`schemaVersion` on the file, and a missing file that reads as empty rather than as an error.

```swift
public struct RecentOperations: Sendable {

    /// Store file name inside the state directory, beside `repositories.json`.
    public static let fileName = "recent-operations.json"

    /// One recorded operation, in one repository.
    public struct Record: Codable, Equatable, Sendable {
        /// `RepositoryIdentity`'s opaque string (YardGit, #0149). Crosses the
        /// layer boundary as a plain `String`, so neither module imports the
        /// other — the same treatment `RepositoryRegistry.Entry.identity` gets.
        public let identity: String
        /// The journal entry this refers to: `JournalEntryID.description`.
        public let entryID: String
        /// `JournalEntryMetadata.operation` — "commit", "fixup", "restore", …
        public let operation: String
        /// `JournalEntryMetadata.timestamp`.
        public let timestamp: Date
        /// `JournalEntryMetadata.Agent.name` / `.session`, flattened. Nil when
        /// the operation carried no agent.
        public let agentName: String?
        public let agentSession: String?
    }

    public let directory: URL
    public init(directory: URL)
    public static func live() -> RecentOperations

    /// Appends one record, then trims to `limit` newest.
    @discardableResult
    public func record(_ record: Record, limit: Int = RecentOperations.defaultLimit) throws -> Int

    /// Every record, **newest first** — the order the question "what did I do
    /// everywhere today" is asked in.
    public func records() throws -> [Record]

    /// Records for one repository, newest first.
    public func records(identity: String) throws -> [Record]
}
```

**`defaultLimit` is 1000**, matching `JournalPrune.Policy.generous`'s `maxCount` — the issue asks for
the bound to be "aligned with #0033's pruning defaults", and 1000 is the number that policy uses. No
age limit here: this file is an index whose entries are cheap, and a second axis is a second thing to
get wrong. Say so in the doc comment rather than leaving the asymmetry unexplained.

### The two properties that are easy to get subtly wrong

1. **Newest-first ordering with a coarse timestamp.** `RepositoryRegistry`'s encoder uses
   `.iso8601`, which **drops sub-second precision** — so several operations in the same second sort
   equal. Keep insertion order as the tiebreaker: store oldest-first on disk, append, and reverse on
   read. A sort alone would scramble same-second records on every read, and the test that catches it
   writes three records with an identical `Date` and asserts they come back in insertion order.
2. **The trim keeps the newest**, not the first `limit`. Trim after appending, from the front of the
   oldest-first array. A test writes `limit + 5` records and asserts the five oldest are gone and the
   newest is present.

### Tests — `YardKit/Tests/YardKitTests/RecentOperationsTests.swift`

**Every test injects a scratch directory.** `RepositoryRegistryTests` is the model; no test may reach
`ServiceNames.stateDirectory()`, and `live()` must not be called anywhere in the suite.

| # | test | mutation that must redden it |
|---|---|---|
| 1 | a missing file reads as empty, not an error | make `records()` throw on a missing file |
| 2 | one record round-trips every field | drop `agentSession` from `CodingKeys` |
| 3 | three records with the **same** `Date` come back in insertion order, newest first | sort by timestamp alone |
| 4 | `limit + 5` records leaves exactly `limit`, oldest dropped | trim from the back instead of the front |
| 5 | `records(identity:)` filters, and returns them newest first | return all records unfiltered |
| 6 | a foreign or truncated file is a typed error, not a crash | swallow the decode error and return `[]` |
| 7 | the directory is created `0o700` when absent | drop the `posixPermissions` attribute |

Run every mutation, report the killing test by name, restore each.

### What this issue does not do

**Nothing calls it yet.** Wiring `JournalCheckpoint` to append a record on every journal write is a
separate change with its own failure mode — a state-directory write must never fail a git operation —
and it belongs with the caller, not with the store. File it as a follow-up when this lands rather
than reaching into the journal here.
