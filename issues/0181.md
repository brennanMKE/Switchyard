## Description

**Filed 2026-08-08 after the same defect appeared in two consecutive issues, found both times by a
reviewer writing a mutation the planner's table lacked.**

`ExitClass` is the agent-facing contract — guide §6, and `CLAUDE.md`: *"Exit codes are meaningful."*
An engine error's exit class tells an agent what kind of failure it hit and which recovery to take.

**Changing one is currently invisible to the suite.** Measured twice:

- `JournalRestore.Error` → `.signingFailed` (6 becomes 9): **704 tests green** (#0179).
- `JournalUndo.Error` → `.signingFailed`: **724 tests green** (found in #0169's review).

An agent receiving 9 for a refused restore concludes *signing failed* and takes an unrelated path.

## The scale of it, measured 2026-08-08

`grep -rlE ': *ExitClassCarrying' YardKit/Sources/YardGit/*.swift` lists **25 files**.
`YardKit/Tests/YardWireTests/ExitClassWireTests.swift` names roughly a third — the worktree family
and the parsers. Several journal types assert their own class inside their own test files
(`CrossToolGuardTests`, `WorktreeDisturbanceTests`, `JournalLockTests` all do), so real coverage is
better than the wire test alone suggests — **but nothing knows which conformers are unasserted, and
a new one is unasserted by default.**

That default is the bug. Every journal type added tonight inherited it.

## What this issue must deliver

**One test that fails when a conformer has no assertion**, so the next `ExitClassCarrying` type
cannot ship bare.

Reflection cannot enumerate protocol conformers in Swift, so do it by source scan — the pattern
already used by `ServiceNamesTests.noOtherSwiftSourceHardcodesTheIdentifiers`, which scans sources
including comments and has caught a real defect (#0028's own first draft). Concretely:

- scan `YardKit/Sources/YardGit/**.swift` for `: ExitClassCarrying` and collect the conforming type
  names;
- scan the test targets for an assertion naming each;
- `#expect` the difference is empty, and **fail with the missing names listed**, not just a count —
  a failure saying "3 conformers unasserted" costs someone a bisect.

Prefer an explicit allow-list for any deliberate omission, so skipping is a recorded decision rather
than an accident.

## Verification

The test must go red today, before the assertions are added — that is the proof it works. Add the
missing assertions in the same round, then it goes green. **State the before-count and after-count
as measured, not estimated.**

A mutation row must flip one conformer's class and observe the *specific* test die — per
`docs/review-failures.md` check 0b, the row has to aim at the headline claim.

## Relationship to #0179

#0179 covers `JournalRestore.Error` specifically, plus a `MissingObject` encode assertion and the
pruned-cursor clause. **This issue supersedes its exit-class half**: fixing the class systemically
covers that instance and every other. Keep #0179 for the two non-exit-class items, and note the
overlap there when either is picked up.

## Notes

Sixth consecutive issue where the code was right and the evidence was missing — after #0176 through
#0180. The recurring shape, now worth stating plainly: **a mutation table drifts toward the code
paths the tests already exercise**, so the untested path is exactly the one no row perturbs. A
conformance nobody asserts is the purest example — it has no behaviour of its own to notice.
