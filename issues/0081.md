## Description

The left pane: local branches, remote-tracking branches, tags, **worktrees**, and stashes for the
tab's repository.

The worktrees section is load-bearing rather than decorative. Since a linked worktree does not get
its own tab (#0079), this is the only place a worktree is selected, and it is where an agent's
isolated checkout becomes visible to a human.

## Re-scoped 2026-08-18 for the MVP

CLAUDE.md's priority section makes the app MVP the only priority. This issue becomes **the pane's
content and nothing else**. Four bullets move out:

- **"Selecting a worktree switches the tab's active context" → deferred.** There are no tabs yet
  (#0079) and no context switching. Selection changes a binding; nothing observes it.
- **"Updates when refs change outside the app, via the hook layer" → deferred.** The hook layer is
  #0217's; a manual reload via the existing Open button is MVP-sufficient.
- **Per-worktree ahead/behind and attached agent session → deferred.** `worktreeList` returns dirty
  state and lock state today; ahead/behind per worktree does not exist and agent sessions are M4.
- **Collapsible sections → keep if `DisclosureGroup` gives it for free, drop if it costs a round.**

## The data, all of it already available

- **Refs**: `RefSnapshot.capture(in:git:)` (`RefSnapshot.swift:123`) returns `head: Head` and
  `refs: [Entry]`, each `Entry` carrying `name` and `oid`. **It already filters `refs/switchyard/`**
  (`RefSnapshot.swift:166`), so the journal-ref bullet below costs nothing — but assert it anyway.
- **Worktrees**: `worktreeList(path:git:)` (`WorktreeList.swift:85`) returns `[WorktreeEntry]` with
  `path`, `head`, `branch`, `locked`, `lockReason`, `bare`, `detached`, `prunable`, `isMainWorktree`.
- **Stash count**: already on the loaded `WhereAmI` as `stashCount`. Enumerating stashes needs an
  engine function that does not exist — **show the count, do not invent one.**

## Placement — settled 2026-08-07

Every view and everything around it goes in **`YardKit/Sources/YardUI/`**, the package target created
by **#0126**. Not in the Xcode project.

The Xcode project keeps only the `@main` `App` type, the asset catalog, `Info.plist`, entitlements,
`SMAppService` registration, and the embedded `switchyard` binary.

**Why it matters for this issue specifically:** a view in the app target can only be exercised by a UI
test, and UI tests cannot run under CLI-driven `xcodebuild` on this machine — the runner times out
enabling automation mode without Accessibility rights. Anything built here would ship untested. In
`YardUI` it is reachable from `swift test`.

`YardUI` sets `.defaultIsolation(MainActor.self)`, so views are main-actor isolated exactly as they
are in the app target today.

Tests go in `Tests/YardUITests` and import **without** `@testable`, so they see what the app sees.
