## Description

Full-capture undo: wire the index snapshot (#0151) and the worktree snapshot (#0152) into the
checkpoint flow (#0167) and the restore flow (#0168), flipping the `captured` flags from the
refs-only honesty of #0034 Decision 3 to the guide §11 decision 3 policy — capture everything
except ignored files, always. **This is the issue that makes the M2 exit criterion "undo
round-trips every mutating command, including with an unmerged index" claimable, and it unblocks
#0035.**

**Structured stub, split from #0034 on 2026-08-08.** Re-authored to code level at its own
planning pass before dispatch, per CLAUDE.md — and only after #0151 and #0152 exist, since it
composes their real APIs.

## The work — bound by #0034 (Decision 3)

Edits `YardKit/Sources/YardGit/JournalCheckpoint.swift` (#0167) and
`YardKit/Sources/YardGit/JournalRestore.swift` (#0168) — **no new production file**; AGENTS.md
Rule 5c applies (`edit`/`cat >>`, never `cat >` onto them):

- Capture: `IndexSnapshot` (#0151 — tree oid normally, raw index blob when unmerged) and
  `WorktreeSnapshot` (#0152 — stash-form commit, nil-able, plus untracked tree, nil-able) feed
  `JournalAnchor.Contents(indexTree:/indexBlob:/untrackedTree:)` (#0028's slots, already there)
  and extend `keepAlive` with the stash-form commit. Metadata `captured` reports what actually
  got captured, including the unmerged-index `index: "blob"` case (#0155's map).
- Restore: apply the pieces the entry captured, in an order the planning pass settles and
  measures (refs/HEAD, then index, then worktree; the unmerged index restored byte-for-byte per
  git internals §3's one sanctioned raw-file case). The `Report` gains the real pieces; the
  `.notCaptured` reasons disappear for new entries; **entries written before this issue still
  restore refs-only and still report honestly** — the compatibility case has a test.
- The #0151/#0152 stubs' assumptions consumed here, restated so drift is visible: `IndexSnapshot`
  capture returns a two-case enum (tree vs raw blob); `WorktreeSnapshot` capture returns two
  nil-able oids (stash-form commit, untracked tree) and never touches the stash stack. If either
  lands differently, this issue's planning pass reconciles before dispatch.
