## Description

**Found by the #0044 umbrella review, 2026-08-17, and the decisive mutation run by the reviewer
afterwards — the finding is measured, not inferred.**

#0044 decision 3 requires that the sibling-disturbance check *"must run on the target snapshot in
every restore path, **including when the guard is bypassed** (`bypassGuard` skips the guard, never the
disturbance check)"*. `JournalRestore.restoreAssumingLock` honours it: step 5 sits outside the
`if !bypassGuard` block. **Nothing observes that it does.**

**Measured:** moving the whole step-5 block inside `if !bypassGuard` leaves the suite **completely
green — `Test run with 881 tests in 68 suites passed`**. So the one binding requirement of #0044 that a
plausible refactor would silently drop is pinned by nothing.

Why the existing tests cannot see it, each verified:

- `bypassGuardSkipsTheGuardAndNothingElse` (`JournalRestoreTests.swift:238`) builds its fixture with
  `standingOnAnEntryWithARogueRef`, which creates **no linked worktree** — there is no sibling to
  disturb, so the test cannot distinguish the two behaviours. Its name currently claims more than it
  asserts.
- `restoreRefusesToDisturbASiblingsCheckout` does have a sibling, but runs with the default
  `bypassGuard: false`, so it passes under the mutation too.
- #0168's mutation table has no row for this: M3 makes `bypassGuard` inert and M11 deletes the check
  outright — neither distinguishes *"the check runs always"* from *"the check runs only when the guard
  runs"*.

**The consequence if it regresses** is exactly what decision 2 was measured against: `update-ref`
clobbers a sibling worktree's checked-out branch at **exit 0**, with no message. A human passing
`--force` to get past a cross-tool guard would silently wreck another agent's worktree.

## Expected behavior

- [ ] One test in `YardKit/Tests/YardGitTests/JournalRestoreTests.swift`: a sibling worktree holding a
      branch, a checkpoint whose snapshot would move that branch, restored with **`bypassGuard: true`**,
      asserting `WorktreeDisturbance.Error.wouldDisturb` is still thrown **and** that nothing was
      written (no new journal entry, refs unchanged — `restoreRefusesToDisturbASiblingsCheckout` shows
      the shape).
- [ ] The mutation above — moving step 5 inside `if !bypassGuard` — **observed red** against the new
      test, and recorded in the issue with its output.
- [ ] Consider renaming `bypassGuardSkipsTheGuardAndNothingElse` or strengthening it to assert the
      "nothing else" its name promises; a test whose name overstates it is how this stayed invisible.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line exceeding the count in
      `docs/test-baseline.txt` by exactly 1. The delta is the criterion.

## Notes

The fixture needs a **real linked worktree with a branch checked out**, not just a second branch —
`WorktreeDisturbance` excludes the caller's own checkout and any detached sibling, so a fixture that
gets either detail wrong will pass for the wrong reason. `FixtureRepository.addWorktree(named:branch:)`
is the helper; `restoreRefusesToDisturbASiblingsCheckout` already builds this correctly and is the one
to copy.

**Do not "fix" the production code** — it is already correct. This issue is entirely about evidence,
which is the same shape as #0178 item 1 and #0192.
