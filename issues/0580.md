## Description

Brennan, 2026-10-05: *"Fixup with Parent is disabled. I want this implemented. This is a great
feature in GitUp which is the primary reference project. I also have a fixup alias in my
~/.gitconfig … My alias only does 1 at a time. You can see what happens with the commit message
when it is used."*

The alias is `fixup = !git reset --soft HEAD~1 && git commit --amend --no-edit`. The app's item is
disabled everywhere but the branch tip because `CommitActionRules.rewriteReason`
(`YardKit/Sources/YardUI/CommitActions.swift`) shares one arm with Squash, and that arm refuses any
commit but the newest and any staged change. The engine behind it, `Fixup.run(source: "HEAD",
target:)`, cannot fold anything but `HEAD` (`FixupError.unsupportedSource`).

## The design (guide §11 decision 46)

- **Semantics = the alias, generalized.** The selected commit's change folds into its parent; the
  **parent's message is kept byte for byte**, the **parent's author and author date are kept**, the
  committer is the current user. Measured (below). GitUp's Fixup Commit is the same operation.
- **Descendants are copied, not replayed.** The fold changes no tree from the selected commit up,
  so every descendant is rebuilt with `commit-tree` from its own tree, message and author, parents
  remapped; the ref moves once. No conflicts are possible, a merge above is carried intact, and the
  index and working tree are never touched.
- **Enabled** on every commit of `HEAD`'s first-parent chain (attached or detached) **except** the
  root and merge commits, plus the guards every action shares (busy, an operation in progress).
  Staged changes no longer disable it. A merge *parent* and a root *parent* are allowed.
- **One journal entry**, `fixup`: Edit ▸ Undo Fixup restores the branch, `HEAD` and the index.

### Measured, 2026-10-05 (git 2.54.0, scratch repos)

Brennan's alias on `root (Alice 2020) → parent (Bob 2021, "parent subject\n\nparent body") → child
(Carol 2022)`, with `s` staged and `f` edited unstaged:

| case | result |
|---|---|
| ordinary | message `parent subject\n\nparent body\n`; author `Bob 2021-01-01`; committer current user, now; parents = the parent's; reflog `commit (amend): parent subject` — the child's message survives only in the reflog |
| staged change | **swept into the fold** (`s` is in the result's tree) — the app does not do this; decision 46 leaves staged work staged |
| unstaged change | still unstaged |
| parent is the root | works; a new root commit with both files |
| `HEAD` is the root | the alias fails at `reset` (`HEAD~1` does not resolve); nothing changes |
| `HEAD` is a merge | the result is `mainc` with `side`'s file and **one** parent — the merge's second line is silently lost; the app refuses |
| parent is a merge | the result is a merge with both original parents and the child's tree; the app allows it |

`git commit-tree` with no `GIT_AUTHOR_*` makes the current user the author, dated now (measured) —
which is why #0581 carries authors explicitly, and why #0583/#0584 exist.

### GitUp (GPL — read to understand behaviour only; nothing copied or translated)

GitUp's Fixup Commit builds the new commit from the **parent** commit with the child's tree and no
message change, updating only the committer; it then replays every descendant in a mode that copies
trees rather than applying patches, with no conflict handler, because no tree changes. The menu item
is offered for a commit on any local branch with exactly one parent, and the operation requires a
clean working tree when the commit is an ancestor of `HEAD`. Switchyard keeps the semantics and the
copy replay, and drops the clean-tree requirement because the copy never touches the index or the
working tree (#0581's tests prove staged and unstaged work ride through).

### Prototype

The whole design was built in a planning worktree (`../sy-plan-fixup`, removed afterwards):
`Rewrite.fixup` plus its 10 tests, the rule and runner change plus the CommitActionMenuTests
updates, and the VM spike. Full suite green with it (`162 / 479 / 399 / 1252 / 14 / 206`). Every
code block in the children is that prototype, and every named mutation was run against it.

## Questions for Brennan (assumptions in force meanwhile)

1. **A `switchyard fixup` CLI verb.** None exists today (guide §6 lists `switchyard fixup <target>`
   with the older meaning "fold the staged index, or `HEAD`, into `<target>`", which nothing
   exposes). Recommendation: `switchyard fixup <commit>` = this operation (fold `<commit>` into its
   parent), matching the menu, with `--json` returning `{"head": "<oid>"}` like `reword`; the
   staged-index mode stays engine-only until someone asks for it. **Assumed meanwhile:** no CLI verb
   in this umbrella.
2. **Squash with Parent on any commit, too?** The same copy mechanism would let Squash fold a
   mid-branch commit (it already has its message sheet). Not done: Brennan asked for Fixup.
   **Assumed:** Squash stays tip-only.
3. **Folding several commits at once** (select a range, fix them all up) — GitUp does not, the alias
   does one at a time, and decision 46 does one. **Assumed:** one at a time; repeat the command.

## Observations, not filed

- **Edit Message, Delete Commit and Swap fail on an empty descendant.** Their replay is `git
  cherry-pick` without `--allow-empty`, which stops on an empty commit ("The previous cherry-pick is
  now empty, possibly due to conflict resolution") — measured while writing #0583's test. Empty
  commits are rare in practice; workstream C's suite is the right place to decide whether it matters.
  Fixup is not affected: it copies.

## Expected behavior

- Fixup with Parent works on any non-root, non-merge commit of the current branch, keeps the
  parent's message and author, leaves staged and unstaged work alone, and is one Undo step — proven
  by #0581's engine tests and #0582's VM spike reading git; Edit Message and Squash stop
  re-attributing commits to the current user (#0583, #0584).
