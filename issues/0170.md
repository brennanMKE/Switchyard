## Description

The journal listing and the prune composition: what an agent reads before deciding whether undo
is available, and the one place that hands #0033 its protected set. The engine behind `journal`
and `journal --prune`; the verbs are M3.

**Structured stub, split from #0034 on 2026-08-08.** Re-authored to code level at its own
planning pass before dispatch, per CLAUDE.md. **Deliberately decoupled from the restore flows:**
this is read-only (plus the prune call), needs no guard and no restore path, and is dispatchable
the moment #0028, #0030, #0155 and #0166 are in — however far #0167–#0169 are.

## The design — bound by #0034 (Decisions 2, 6)

`YardKit/Sources/YardGit/JournalList.swift`, shape to be finalized at the planning pass:

```swift
public enum JournalList {
    /// Where one entry stands relative to the cursor.
    public enum ChainPosition: Sendable, Equatable {
        case cursor          // the entry the repository currently matches
        case history         // below the cursor: reachable by undo
        case redoTail        // above the cursor: reachable by redo (or orphaned by truncation)
        case traversal       // an undo/redo entry — restorable explicitly, never walked
    }
    public struct Item: Sendable, Equatable {
        public let entry: JournalAnchor.Entry
        public let metadata: JournalEntryMetadata?   // nil when undecodable — see defect
        public let defect: String?                   // #0030's skip-and-report vocabulary
        public let position: ChainPosition
    }
    public struct Listing: Sendable, Equatable {
        public let items: [Item]        // oldest first, the journal's order
        public let state: JournalChain.State
    }
    public static func list(in context: WorktreeContext,
                            git: GitProcess = GitProcess()) throws -> Listing

    /// Plan + execute pruning with the live chain protected: computes
    /// JournalChain.state and calls JournalPrune.prune(policy:protected:
    /// state.protectedIDs) under the journal lock (#0032). The #0033
    /// handoff lives here and nowhere else.
    @discardableResult
    public static func prune(policy: JournalPrune.Policy, now: Date = Date(),
                             in context: WorktreeContext,
                             git: GitProcess = GitProcess()) throws -> [JournalAnchor.Entry]
}
```

- The listing reads **refs first**: `JournalRebuild.rebuild(in:)` (#0030) is the reader —
  skip-and-report, never fatal — with `journal.json` (#0156) as the cache layer per #0033's
  invariant (the cache may under-report the journal; it must never over-report it). Whether the
  listing consults the cache at all in v1, or always reads refs, is the planning pass's call —
  correctness first, the cache is an optimization.
- Per-item honesty: `metadata.captured` rides through so `journal` reports per entry what was
  captured, and `position` says whether plain undo/redo can reach it (#0034 Decision 2 — the
  redo tail above the cursor is orphaned by a later normal entry, still restorable by id).
- Reading takes no lock (anchors are atomic per entry; the planning pass confirms or corrects
  with a measured fact); `prune` locks.

## Expected behavior (to be authored to code level)

- [ ] `YardKit/Sources/YardGit/JournalList.swift`: listing + prune composition above; typed
      errors conform to `ExitClassCarrying`; every process call through `GitProcess`.
- [ ] Positions verified against a scenario with an active undo (cursor mid-chain): history,
      cursor, redoTail, and traversal each appear and match #0166's state.
- [ ] An entry with undecodable metadata lists with `defect` set and does not sink the listing
      (#0030's skip-and-report, end to end).
- [ ] `prune` never deletes a protected id: with the cursor mid-chain and an expiring policy,
      the live chain survives and expired history below the cursor goes (both asserted).
- [ ] `YardKit/Tests/YardGitTests/JournalListTests.swift` gains the tests, parameterized over
      both ref formats; the diff lists exactly two files.
- [ ] `swift test` prints a `Test run with N tests` line; N must exceed the branch's pre-change
      count by the exact delta the planning pass states.
- [ ] A mutation table, every row applied and observed red with the killing test named — one row
      must drop `protected:` from the prune call, killed by the live-chain-survives test.
