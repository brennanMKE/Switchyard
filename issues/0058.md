## Description

Stream repository and app events to the caller over a long-lived session. Already proven in
RemoteControl; here the event source is the hook layer (#0042) plus FSEvents plus app-side activity.

## Expected behavior

- [ ] Streams ref transactions from #0042, journal entries, and app events as newline-delimited JSON.
- [ ] `--timeout <sec>` detaches automatically; Ctrl-C detaches cleanly.
- [ ] Exit 5 when the app terminates the session.
- [ ] Memory stays flat over a long session — measured, not assumed.
- [ ] Events are ordered and no event is silently dropped under load.

## Planning pass — 2026-09-03, to code level. Two rounds.

**The session shape**: `watch` is the one command that needs a real long-lived session (#0349's
answer). The CLI connects (`launchIfNeeded: false` — exit 3 when the app is down, the M4 criterion),
EXPORTS a client object the app can push to (NSXPCConnection's reverse direction — the app-side
service calls the client's `WatchClientProtocol.event(_ data: Data)` per event), and prints each
event as newline-delimited JSON on stdout as it arrives. The app-side session registers the
watcher, streams events from the journal-observed layer (#0042's hook records land there) plus
app-side activity, and numbers every event with a monotonic sequence — the ordering/no-drop contract
is the sequence numbers, asserted end to end.

**Round 1 — the wire, the session, the CLI arm (this dispatch):**
- `YardKit/Sources/YardKit/WatchRequest.swift` (NEW) — `WatchRequest` (repository path or all-repos,
  timeoutSeconds optional — nil means until detached), `WatchEvent` (sequence number, kind, payload
  JSON — the journal-observed entry shape from #0042/#0153 plus app-event kinds), `WatchClientProtocol`
  (`event(_ data: Data)`, `sessionEnded(reason: Data)`) — the CLI-exported object. `WatchWireTests`
  pins bytes.
- `AppServiceProtocol.performWatch(request:client:reply:)` — the app registers the session, streams
  via the client proxy, and replies once at session end (reason: detached/timedOut/appShutdown).
  The app-side session store: bounded — the stream is push-based, nothing accumulates (the memory
  criterion's structural half).
- `YardKit/Sources/YardKit/WatchArm.swift` (NEW) — the CLI arm: `watch` joins `CommandRegistry.all`
  (name "watch", schemaName "watch", flags `--timeout <sec>`, exit codes 0/1/3/5; payload nil).
  Exports the client, prints events as they arrive, exits 0 on clean detach (timeout expiry or
  Ctrl-C), 3 app-down, 5 app-terminated-the-session. SIGINT handling: a signal handler sets a flag
  and detaches cleanly (exit 0) — the Ctrl-C criterion.
- The event source, round 1: journal-observed entries (the hook layer's records — read
  `JournalObserved.swift`) plus a synthetic app-event kind for testability. FSEvents is NOT in round
  1 — it is a source #0058 can grow; say so in the report.
- Tests: round-trip streaming through a real anonymous XPC listener (N events, in order, none
  dropped — the sequence numbers asserted); `--timeout` detaches with exit 0; app terminates the
  session → exit 5; app-down → exit 3; the CLI prints newline-delimited JSON (parse each line).
- Verification: `cd YardKit && swift test` — **N greater than 1545**. State the delta. `xcodebuild
  build … CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO` → `** BUILD SUCCEEDED **`.

**Round 2 — memory, Ctrl-C end to end, the manual script, the sweep:**
- The memory measurement: the CLI subprocess's footprint measured before/after streaming N (≥1000)
  events — growth bounded (the RemoteControl defect was 940 MB; the bound here is a stated constant,
  e.g. < 10 MB, labelled as a judgement). The app-side structural bound asserted too (the session
  store retains no event history).
- Ctrl-C end to end: SIGINT to the CLI subprocess mid-stream → clean detach, exit 0, no orphaned
  session (the app-side session store shows it gone).
- `scripts/verify-watch.md` (UNRUN): real long-session scenarios.
- The Expected-behavior sweep.
