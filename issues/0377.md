## Description

Brennan, 2026-09-12, filed from the M7 planning questions. One deliverable: copy the selected
commit's full ID.

### Interaction

- **Edit ▸ Copy (⌘C)** with a commit selected and the History list focused puts the commit's full
  40-hex oid on the general pasteboard, via `.copyable`. The standard menu item is the menu-bar
  entry point, so no Commit-menu item is added.
- **Context menu → Copy Commit ID** copies the *clicked* row's oid. It sits in its own first group,
  above #0359's rewrite groups, followed by a `Divider`. It is never disabled, so it is not a
  `CommitAction`.
- **Full, not short.** The full id is unambiguous in any repository and is what every git command
  accepts. The short id stays visible in the row for reading.

### Code (*compiled* at `61c94aa`, in a scratch view)

```swift
// YardKit/Sources/YardUI/CommitIDPasteboard.swift (new)

import AppKit

/// #0377: puts a full commit id on the general pasteboard.
public enum CommitIDPasteboard {
    public static func copy(_ oid: String) {
        let pasteboard = NSPasteboard.general
        pasteboard.clearContents()
        pasteboard.setString(oid, forType: .string)
    }
}
```

On the `List` in `YardKit/Sources/YardUI/CommitHistoryView.swift`:

```swift
.copyable(selection.map { [$0] } ?? [])
.contextMenu(forSelectionType: String.self) { clicked in
    if clicked.count == 1, let oid = clicked.first {
        Button("Copy Commit ID") { CommitIDPasteboard.copy(oid) }
    }
}
```

When #0359 has landed, its `CommitActionMenuItems` goes below this button, after a `Divider()`, in the
same `contextMenu` closure.

**Unverified**: that `.copyable` enables Edit ▸ Copy while the list has focus. The reviewer selects a
commit, confirms Edit ▸ Copy is enabled, presses ⌘C, and compares `pbpaste` with the commit's oid.
There is no pure logic to unit-test, and writing to the real general pasteboard from `swift test`
would clobber the user's clipboard, so this issue's verification is that manual check plus a green
`swift test`.
