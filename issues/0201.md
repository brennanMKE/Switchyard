## Description

**Disclosed by #0188's round, 2026-08-17, as the half of its keep-alive story that its fix does not
cover.**

#0174 built `SequencerSnapshot` with `keepAlive` returning *"every oid that must stay reachable for this
snapshot to restore"* — the sequencer tree plus `AUTO_MERGE`'s tree when present. #0188 then established
that this list **cannot** go into the anchor commit's parents: they are **tree** oids and `commit-tree -p`
requires a commit (`fatal: <oid> is not a valid 'commit' object`, exit 128, measured twice
independently).

The sequencer's own tree is fine — `JournalAnchor.write` embeds it as a `sequencer` subtree of the anchor
commit's tree, so it is reachable from the anchor with no parent needed, exactly as `index` and
`untracked` already are.

**`AUTO_MERGE`'s tree has no reachability path at all.** It is not embedded in the anchor tree, it cannot
be a parent, and it lives outside the sequencer directory (beside `HEAD`), so nothing keeps it alive.
Ordinary maintenance may reclaim it, and a restore that needed it would find a missing object.

## What has to be established first, and it may make this a wontfix

**Does restore actually need `AUTO_MERGE`?** Read `SequencerSnapshot.restore`
(`YardKit/Sources/YardGit/SequencerSnapshot.swift:93-124`) before designing anything: it materialises the
sequencer **directory** from the stored tree and **never reads `autoMerge`**. So on the current evidence
`autoMerge` is captured for keep-alive purposes only, and if nothing restores it, keeping it alive buys
nothing.

Two possible outcomes, and this issue is to settle which:

- **It is genuinely unused** → remove `autoMerge` from `keepAlive` (or drop the property), and record why
  in #0174's design notes. `keepAlive` then returns exactly `[tree]` and the name stops overpromising.
- **A restore does need it** → embed it in the anchor tree as a second entry, e.g. `auto-merge`,
  alongside `sequencer`, and restore it wherever git expects it.

**`AUTO_MERGE` only exists under `merge.conflictStyle=diff3` or `zdiff3`** (#0188's round noted this), so
any test has to set that config explicitly — a default-configured fixture will never produce one, which
is why this has stayed invisible.

## Expected behavior

- [ ] The question above answered from the source and recorded in this issue, before any code changes.
- [ ] Whichever branch follows, with a test that only passes for the right reason: if removed, a test
      that `keepAlive` is exactly `[tree]`; if embedded, a mid-rebase round trip under
      `merge.conflictStyle=diff3` that survives an aggressive `gc` of unreachable objects.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line; state the delta once the branch
      is chosen.

## Notes

**Do not run `git gc` against any repository outside a throwaway fixture** — CLAUDE.md forbids it for
the journal's own repositories, and the reachability half of this issue needs a fixture built to be
destroyed.

#0188's round attempted a gc-based diagnostic twice, hit failures and a timeout, and stopped rather than
looping (AGENTS.md Rule 5). Whoever picks this up should expect the measurement to be awkward and budget
for it rather than treating a failed gc probe as a surprise.
