# 0201 — Decide whether AUTO_MERGE's tree needs a reachability path

|---|---|
| **Status** | in-progress |

## Description

**Disclosed by #0188's round, 2026-08-17, as the half of its keep-alive story that its fix does not
cover.**

#0174 built `SequencerSnapshot` with `keepAlive` returning *"every oid that must stay reachable for this
snapshot to restore"* — the sequencer tree plus `AUTO_MERGE`'s tree when present. #0188 then established
that this list **cannot** go into the anchor commit's parents: they are **tree** oids and `commit-tree -p`
requires a commit (`fatal: <oid> is not a valid 'commit' object`, exit 128, measured twice
independently).

The sequencer's own tree is fine — `JournalAnchor.write` embeds it as a `sequencer` subtree of the anchor
commit's tree, so it is reachable from the anchor with no parent needed, exactly as `index` and
`untracked` already are.

**`AUTO_MERGE`'s tree has no reachability path at all.** It is not embedded in the anchor tree, it cannot
be a parent, and it lives outside the sequencer directory (beside `HEAD`), so nothing keeps it alive.
Ordinary maintenance may reclaim it, and a restore that needed it would find a missing object.

## What has to be established first, and it may make this a wontfix

**Does restore actually need `AUTO_MERGE`?** Read `SequencerSnapshot.restore`
(`YardKit/Sources/YardGit/SequencerSnapshot.swift:93-124`) before designing anything: it materialises the
sequencer **directory** from the stored tree and **never reads `autoMerge`**. So on the current evidence
`autoMerge` is captured for keep-alive purposes only, and if nothing restores it, keeping it alive buys
nothing.

Two possible outcomes, and this issue is to settle which:

- **It is genuinely unused** → remove `autoMerge` from `keepAlive` (or drop the property), and record why
  in #0174's design notes. `keepAlive` then returns exactly `[tree]` and the name stops overpromising.
- **A restore does need it** → embed it in the anchor tree as a second entry, e.g. `auto-merge`,
  alongside `sequencer`, and restore it wherever git expects it.

**`AUTO_MERGE` only exists under `merge.conflictStyle=diff3` or `zdiff3`** (#0188's round noted this), so
any test has to set that config explicitly — a default-configured fixture will never produce one, which
is why this has stayed invisible.

## Notes

**Do not run `git gc` against any repository outside a throwaway fixture** — CLAUDE.md forbids it for
the journal's own repositories, and the reachability half of this issue needs a fixture built to be
destroyed.

#0188's round attempted a gc-based diagnostic twice, hit failures and a timeout, and stopped rather than
looping (AGENTS.md Rule 5). Whoever picks this up should expect the measurement to be awkward and budget
for it rather than treating a failed gc probe as a surprise.

## Answered by measurement — 2026-08-17. `AUTO_MERGE` is not needed, and `keepAlive` is dead.

**Measured, not reasoned.** A real conflicted rebase under `merge.conflictStyle=diff3`, in a scratch
repository built for this:

```
git config merge.conflictStyle diff3      # AUTO_MERGE only exists under diff3/zdiff3
git rebase main                           # conflicts, as intended
git rev-parse --verify AUTO_MERGE         # ac9e49fe...  -> present
git update-ref -d AUTO_MERGE              # delete it outright
echo resolved > shared.txt && git add shared.txt
GIT_EDITOR=true git rebase --continue     # "Successfully rebased and updated refs/heads/side." exit 0
```

**`git rebase --continue` completes with `AUTO_MERGE` deleted.** So it is not required to resume an
interrupted rebase, which is the only thing `SequencerSnapshot` exists to make possible. Losing it
costs the three-way views tools can build from that tree, not resumability.

**And `keepAlive` now has no production caller at all.** #0188 established that its contents are
**tree** oids, which cannot be commit parents (`fatal: … is not a valid 'commit' object`), and removed
the one call site. Grep confirms the only remaining references outside `SequencerSnapshot.swift` are
the comment in `JournalCheckpoint` explaining why it is *not* used, and two assertions in
`SequencerSnapshotTests`. The sequencer tree's reachability comes from being embedded in the anchor's
own tree, exactly as `index` and `untracked` are.

So this issue resolves as the **first** of the two branches its Description offered.

## Expected behavior

- [ ] `SequencerSnapshot.keepAlive` is removed. It promises a keep-alive set that nothing can consume
      and that nothing needs; a property whose name states a contract the codebase cannot honour is
      worse than no property.
- [ ] `autoMerge` **stays** as a captured field — it is real state, cheap to record, and the capture
      test proves it is read correctly — but its doc comment is rewritten to say what is now known: it
      is **informational**, it is **not** restored, and a rebase resumes without it. Delete the
      "must join the anchor's keep-alive set or ordinary maintenance may reclaim it" claim; that
      sentence is the one that sent #0188 into a hard `commit-tree` fatal.
- [ ] `SequencerSnapshotTests` — the `#expect(snapshot.keepAlive.contains(snapshot.tree))` assertion at
      line 51 goes with the property. `autoMergeIsCapturedForKeepAliveWhenPresent` is **renamed** (it no
      longer captures "for keep-alive") and keeps its capture assertions.
- [ ] A test proving the measurement above, so the claim is pinned rather than trusted: a mid-rebase
      fixture with `merge.conflictStyle=diff3`, `AUTO_MERGE` deleted, and `git rebase --continue`
      asserted to exit 0. **Set the config on the fixture repository explicitly** — a default-configured
      fixture never produces an `AUTO_MERGE` at all, which is why this stayed invisible.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt` by exactly 1. The delta is the criterion.
