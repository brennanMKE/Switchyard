## Description

`post-rewrite` supplies a mapping git gives you no other way: `<old-object-name> SP
<new-object-name>` lines from `git commit --amend` and `git rebase`. For squash and fixup, all
squashed commits are listed as rewritten to the same new commit, so several lines share a new object
name, and commits appear in the order rebase processed them.

Stored in the journal entry, this is what lets Switchyard tell a human "these four commits became
this one" after a rewrite, instead of showing two unrelated graphs.

## Expected behavior

- [ ] Mapping stored on the corresponding journal entry.
- [ ] Many-to-one squash and fixup mappings are represented correctly, not collapsed to one pair.
- [ ] Processing order from git is preserved.
- [ ] Captured for rewrites performed by `git` directly, not only by `yard`.
- [ ] Consumed by #0064 to compute the range for `rewrite-diff`.
