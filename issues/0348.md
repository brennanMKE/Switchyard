## Description

Wire `switchyard verify` into the command registry, following **the six-step pattern in #0115**,
which #0124 established and #0225–#0228 applied four times. One of the four per-command filings
#0115's closure requires (the split the retired #0338 asked for).

## The engine entry point this wraps

```swift
public static func run(revision: String, in workingDirectory: String,
                       git: GitProcess = GitProcess(),
                       extraEnvironment: [String: String] = [:]) throws -> SignatureVerification
```

in `YardKit/Sources/YardGit/SignatureVerification.swift:83`. `SignatureVerification` is **already
`Encodable`** with an explicit `CodingKeys` enum (SignatureVerification.swift:194, plus a custom
`encode(to:)` at 233) and `SigningWireTests` pins its bytes (#0136) — step 2 of the pattern is
already done and must not be redone. `extraEnvironment` stays empty from the CLI; tests may use it.

## Arguments — parse what is required, refuse everything else (guide §6)

Exactly one revision argument is required (`switchyard verify HEAD`). A missing revision — or more
than one — returns the `usage` exit code and a structured `EnvelopeFail`, never a default guess.
Unknown flags are refused the same way.

**Exit-code semantics:** the command's exit code reports whether the command ran; the payload
carries the verdict. A commit with a bad or missing signature is a **successful** command returning
a `SignatureVerification` whose status field says so — the engine throws only on repository/transport
failure (those map to `repository_error`, exit 6).

## Notes

Guide §6, and M3's exit criterion "every M1 read command runs from the built binary". Nothing in
`main.swift` changes — the routing picks up any command in `CommandRegistry.all`. Running the real
