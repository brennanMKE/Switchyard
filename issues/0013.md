## Description

Per-file worktree state with staged and unstaged distinguished at the hunk level, so an agent can
tell what is already staged without diffing twice.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/WorktreeStatus.swift`. Create it; do not restructure existing files.
- [ ] Per-file entries distinguish staged, unstaged, untracked, ignored, and conflicted.
- [ ] Renames and copies are reported as such, with both paths.
- [ ] Submodule state is reported rather than silently flattened.
- [ ] Paths with spaces, newlines, and non-UTF-8 bytes round-trip correctly through JSON.
- [ ] Tested against both ref formats.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N must be greater than 176.

## Notes

Guide §6. Blocked by #0009, #0011.

Non-UTF-8 paths are not hypothetical — git permits arbitrary bytes, and the JSON encoder has to
decide on a representation rather than crash or silently lose the path.

## Review — round 1 produced nothing, and this issue is too big

Killed at the 1800s cap: exit 7, empty tree, no `WorktreeStatus.swift`. Four `Write failed` aborts,
three consecutive, then a stall.

**The proximate cause was the output token cap** — `opencode.json` limited the model to 8192 output
tokens, which must hold its reasoning *and* the whole file JSON-escaped inside one `write` call. Raised
to 16384 on 2026-08-07; see workflow log §2.5.

**But this issue is also genuinely oversized, and the cap only hid that.** It asks for five
classification states, plus rename and copy with both paths, plus submodule state, plus three separate
path-encoding hazards, plus both ref formats, plus swift-testing coverage of all of it — in one file,
in one round. `docs/review-failures.md` already records repeated unmet sub-criteria as the signature
of an oversized issue, and this is larger than #0011 was when it was split.

**Split, do not just re-dispatch.** #0113 takes the parser and the five basic states; this issue keeps
renames, copies, submodules and the awkward paths, and depends on it.

### Also worth fixing when this is next dispatched

The round ran `git status --porcelain=v2` against a **clean** worktree, got no output, and recorded
"Empty repo state" — it never saw a populated record before it started writing. Add a Givens block
containing real `--porcelain=v2 -z` bytes from a fixture with each state present, the way #0020's
`-z` givens were probed. That removes the guessing entirely.
