# 0084 — Route every "open a repository" entry point through focus-or-open

| | |
|---|---|

## Description

There are four ways a repository gets opened, and **all of them must go through the same
focus-or-open rule** from #0079: resolve to `$GIT_COMMON_DIR`, focus the existing tab if there is
one, otherwise create a tab.

1. **File ▸ Open…** and the recent-repositories menu
2. **Drag and drop** a folder onto the window or the Dock icon
3. **`switchyard://` URL** open
4. **XPC**, when `yard review --wait` or `yard ask` needs the app

Four entry points is exactly how "opening a repo twice gives two tabs" ships. One code path, four
callers.

## Expected behavior

- [ ] All four entry points call one function; verified by grep, not by inspection.
- [ ] Each is tested against an already-open repository and produces focus, not a duplicate tab.
- [ ] URL opens are handled by the app delegate only, and open no new window (#0078).
- [ ] An XPC request for a repository with no tab opens one in the frontmost window, and the window is brought forward.
- [ ] Opening a path inside a working tree resolves to the repository root.
- [ ] A path that is not a repository produces a clear message from every entry point.

## Notes

Guide §4 "The UI hierarchy". Blocked by #0079, #0047.

Entry point 4 is the one that matters for the differentiator: `review --wait` is useless if it
cannot reliably put the right repository in front of a human.
