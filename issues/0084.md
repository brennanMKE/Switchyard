## Description

There are four ways a repository gets opened, and **all of them must go through the same
focus-or-open rule** from #0079: resolve to `$GIT_COMMON_DIR`, focus the existing tab if there is
one, otherwise create a tab.

1. **File ▸ Open…** and the recent-repositories menu
2. **Drag and drop** a folder onto the window or the Dock icon
3. **`switchyard://` URL** open
4. **XPC**, when `yard review --wait` or `yard ask` needs the app

Four entry points is exactly how "opening a repo twice gives two tabs" ships. One code path, four
callers.

## Expected behavior

- [ ] All four entry points call one function; verified by grep, not by inspection.
- [ ] Each is tested against an already-open repository and produces focus, not a duplicate tab.
- [ ] URL opens are handled by the app delegate only, and open no new window (#0078).
- [ ] An XPC request for a repository with no tab opens one in the frontmost window, and the window is brought forward.
- [ ] Opening a path inside a working tree resolves to the repository root.
- [ ] A path that is not a repository produces a clear message from every entry point.

## Placement — settled 2026-08-07

Every view and everything around it goes in **`YardKit/Sources/YardUI/`**, the package target created
by **#0126**. Not in the Xcode project.

The Xcode project keeps only the `@main` `App` type, the asset catalog, `Info.plist`, entitlements,
`SMAppService` registration, and the embedded `switchyard` binary.

**Why it matters for this issue specifically:** a view in the app target can only be exercised by a UI
test, and UI tests cannot run under CLI-driven `xcodebuild` on this machine — the runner times out
enabling automation mode without Accessibility rights. Anything built here would ship untested. In
`YardUI` it is reachable from `swift test`.

`YardUI` sets `.defaultIsolation(MainActor.self)`, so views are main-actor isolated exactly as they
are in the app target today.

Tests go in `Tests/YardUITests` and import **without** `@testable`, so they see what the app sees.

## Planning update — 2026-09-03. The one function, the four callers, and what is testable.

**The one function already exists**: `RepositoryTabs.open(path:) -> Outcome` (#0079) is the
focus-or-open rule — resolve to `commonDir`, focus, or create, or refuse. This issue wires the four
callers to it and adds nothing that second-guesses it.

**The files:**

- `Switchyard/AppDelegate.swift` — `application(_:open:)` (documents + Dock drops) and the
  `switchyard://` URL handler. URL opens live HERE ONLY (`application(_:open:)` /
  `application(_:open url:)`), never in a scene modifier that could volunteer a window — #0078's
  `.handlesExternalEvents(matching: Set())` stays as-is.
- `Switchyard/AppXPCServer.swift` — the `AppService.perform` path calls the same function; a
  repository with no tab opens in the frontmost window and that window is brought forward
  (`NSApp.windows` order). App-target code, untestable headless — the manual script (#0054) owns the
  window-count and frontmost assertions.
- File ▸ Open and the recent-repositories menu — the app target's command/menu wiring, same call.
- `YardKit/Sources/YardUI/RepositoryTabs.swift` — only if a seam is missing for "open in the
  frontmost window" and "report the refusal as a human-readable message"; add it here, not in the
  app target.

**What is testable in `Tests/YardUITests/` (the deliverable):** the shared function's focus
behaviour under the four callers' argument shapes — an already-open repository (focus, no duplicate),
a path inside the working tree (resolves to root), a non-repository (the refusal outcome's message is
non-empty and names the path). Where an existing #0079 test already asserts a case, do not duplicate
it; reference it.

**What is NOT testable here, and must not be faked:** real URL opens, real Dock drops, real XPC
activations, window counts and frontmost order — #0054's manual script, per #0078's precedent. The
grep proof is the report's deliverable for criterion 1: paste the grep showing every caller reaches
the one function.
