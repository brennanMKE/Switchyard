## Description

`midMergeReportsFlagWhenMergeHeadPresent()` in
`YardKit/Tests/YardGitTests/WhereAmITests.swift` asserts nothing at runtime, and its name says
otherwise.

It merges `repo.oids["a"]!` — which is an **ancestor** of the current commit. Git prints
`Already up to date.` and exits 0, so `MERGE_HEAD` is never created. The test then hits
`guard let mPath = …, !mPath.isEmpty else { return }` and exits before reaching its single `#expect`.
It passes, every time, having tested nothing.

Even if the guard were reached, the assertion compares `r.isMidMerge` against the same `FileManager`
check the test just performed — so it would confirm that two readings of the same fact agree, not
that the implementation is right.

**And there is no mid-cherry-pick test at all**, though the Expected behavior of #0012 names it.

## Givens — verified on `main`, treat as true

1. The file is `YardKit/Tests/YardGitTests/WhereAmITests.swift`; the implementation under test is
   `YardKit/Sources/YardGit/WhereAmI.swift`, which is **correct** — it reports `isMidMerge` and
   `isMidCherryPick` from `git rev-parse --git-path`. Do not change it.
2. **Merging an ancestor is a no-op.** To create `MERGE_HEAD` you need two commits that have actually
   diverged: branch from a common base, commit on each side, then merge with a conflict or with
   `--no-commit` so the merge stays in progress.
3. `FixtureRepository` gives `build(_:)` with per-commit `parents` and `files`, `branch(_:at:)`,
   `checkout(_:)`, and `writeUntracked(_:)`. Commit names like `"a"` are keys in **`repo.oids`**, not
   refs — passing a bare name to git fails with `ambiguous argument`.
4. **Never `try!` in a test.** Mark the test `throws` and use `try`. A trap destroys the whole run
   summary, which cost #0012 a round.
5. `scripts/check-tests-assert.sh` flags a bare `return` in a `@Test` body as SKIPSHAPE. It is
   advisory today only because instances like this one exist.

## Expected behavior

- [ ] The mid-merge test creates a **real** in-progress merge — divergent commits, `MERGE_HEAD`
      present — and asserts `isMidMerge` is true. No early `return`.
- [ ] It asserts against the **function's output**, not against a `FileManager` check the test
      performs itself. A test that re-reads the same file the implementation reads proves only that
      the file exists.
- [ ] A **mid-cherry-pick** test exists and asserts `isMidCherryPick` is true, created by
      cherry-picking a commit that conflicts so the operation stays in progress.
- [ ] Both assert the *other* flags are false — a mid-merge must not report mid-rebase.
- [ ] No bare `return` in either test.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest.
- [ ] `cd YardKit && swift build` succeeds and `swift test` prints a `Test run with N tests` line you
      paste. **N must be greater than 216**, the count on `main` before this change.

## Tests must be able to fail

Prove each new test binds: make `isMidMerge` return a constant `false`, confirm the mid-merge test
fails, restore. Do the same for `isMidCherryPick`. A test that still passes with the field stubbed is
the exact defect this issue exists to remove.

## Review — round 1 reinvented a helper that already exists, badly

The suite does not complete. It aborts with `signal code 5` and **no `Test run with N tests` line at
all**:

```
WhereAmITests.swift:98:  Fatal error: Unexpectedly found nil while unwrapping an Optional value
WhereAmITests.swift:143: Fatal error: Unexpectedly found nil while unwrapping an Optional value
```

Both mutations were therefore **unrunnable**, which is a worse outcome than a failed mutation: the
tests trap at lines 98 and 143, *before* they ever call `whereAmI()`. They cannot distinguish a
correct implementation from a constant `false`, because they never reach it.

### 1. `FixtureRepository.branch(_:at:)` does not populate `oids`

`Sources/YardGit/FixtureRepository.swift:150` creates a ref and writes nothing to `oids` — only
`build(_:)` does, at line 134. So `repo.oids["branch1"]!` and `repo.oids["branch2"]!` are
**unconditionally nil** and trap on every run.

**Only commits created by `build(_:)` appear in `oids`.**

### 2. `FixtureRepository.conflicted()` already builds the state this issue needs

`Sources/YardGit/FixtureRepository.swift:296`. It creates `base`, then divergent `ours` and `theirs`
both editing `f.txt`, checks out `ours` detached, and runs `merge --no-commit` on `theirs` — leaving a
**real in-progress conflicting merge with `MERGE_HEAD` present**.

That is exactly the fixture the mid-merge test requires. **Use it. Do not build your own.** Read it
and follow the same divergent-commit shape for the cherry-pick test.

This is the round's real failure: it reconstructed, incorrectly, something the codebase already
provided. The fault is partly this issue's — it named the *constraint* ("merging an ancestor is a
no-op") without naming the *affordance* that satisfies it.

### 3. The tests still build only one commit

Both build `"base"` and then point `branch1` and `branch2` at it. That is not divergence. Even with
the nil traps fixed, the merge would print `Already up to date.`, `MERGE_HEAD` would never exist, and
the test would be exactly as vacuous as the one this issue was filed to replace.

**Two commits must exist with a common parent and conflicting content in the same file** before any
merge or cherry-pick can remain in progress.

### Also

Round 1 kept redundant `FileManager.default.fileExists` assertions alongside the real ones. Once the
tests actually bind, delete them — re-reading the file the implementation reads proves only that the
file exists.
