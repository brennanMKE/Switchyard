## Description

#0575 reached Brennan because every commit-menu operation had engine tests and menu-rule tests,
and nothing drove the app's own path (commit menu → `performCommitAction` → refresh → Detail
pane) and then compared git with the window. `docs/review-failures.md` records it, and the
preflight checklist gains a judgment line. This issue makes the rule **mechanical**, so it binds
the next commit-menu action without depending on anyone's memory. Workstream B (Fixup with Parent)
is the first one that will meet it.

The rule: if an issue's spec names one of the three commit-action source files in `YardUI`
(`CommitActions`, `CommitActionRunner`, `CommitActionMenu`), then it must also name a spike file
matching `SwitchyardUITests/<Name>UITests.swift` **and** mention a git helper: `UITestGit` (the
helper #0578 adds to `SwitchyardUITests/UITestSupport.swift`) or `GitRepo` (the fuller helper
workstream C plans in #0591, `SwitchyardUITests/GitAssertions.swift`). Otherwise it must carry a line that starts
`**VM spike:** not applicable` with the reason, which turns the failure into a warning. Anything
else is a hard FAIL (exit 9).

No currently open or in-progress issue names those files (checked 2026-10-05 with a loop over
`issues/0*.md` reading each Status row), so landing this blocks nothing in flight.

## The change — one file, `scripts/preflight-issue.sh`

Insert this block directly above the final `if (( FAILED )); then` (today at line 427, just after
the `@Test`-name clash check's closing `fi` and its blank line):

```zsh
# #0579: a commit-action change ships with a VM spike that asserts git state.
# #0575: Merge into Current Branch had engine tests and menu-rule tests, and
# nothing drove the app's own path and then asked git what it held -- so a
# merge that was right in git and showed "no file change" in the window
# reached Brennan. An issue naming a commit-action source file must name a
# SwitchyardUITests/...UITests.swift spike that runs UITestGit or GitRepo, or opt out
# with a stated reason.
if grep -qE 'YardKit/Sources/YardUI/(CommitActions|CommitActionRunner|CommitActionMenu)\.swift' "$SPEC"; then
  if grep -qE 'SwitchyardUITests/[A-Za-z0-9]+UITests\.swift' "$SPEC" && grep -qE '(UITestGit|GitRepo)' "$SPEC"; then
    pass "a commit-action change names a VM spike that asserts git state"
  elif grep -qE '^\*\*VM spike:\*\* not applicable' "$SPEC"; then
    warn "a commit-action change opts out of a VM spike" \
"Check that the reason on its '**VM spike:** not applicable' line holds."
  else
    fail "a commit-action change names no VM spike asserting git state" \
"The issue names a commit-action source file but no SwitchyardUITests/...UITests.swift
spike that runs UITestGit or GitRepo. #0575: Merge into Current Branch was right in git and
wrong on screen, and only an end-to-end spike could see it. Add the spike, or a
line starting '**VM spike:** not applicable' with the reason."
  fi
fi

```

The `grep`s sit inside `if` conditions, so a no-match exit 1 does not trip `ERR_EXIT`. That is the
trap the header comment warns about.
