## Description

Trailers change the commit SHA; notes (`refs/notes/*`) do not. So the split is: **agent provenance
belongs in trailers**, written at commit time and covered by the signature, while **review
decisions, approval records, and `review --wait` outcomes belong in notes**, attached after the fact
without invalidating anything.

Both, for different reasons. Document the split so it does not get relitigated later.

## Expected behavior

- [ ] `review --wait` outcomes are recorded as notes under a dedicated `refs/notes/` namespace.
- [ ] Attaching a note never changes a commit SHA — asserted by a test.
- [ ] `yard log` can surface notes alongside commits.
- [ ] The trailers-versus-notes split is documented in `docs/provenance.md`.
- [ ] Notes namespace is excluded from `yard`'s ordinary ref enumeration, like journal refs.

## Planning pass — 2026-09-03, to code level.

- `YardKit/Sources/YardGit/ReviewNotes.swift` (NEW) — `ReviewNotes.record(decision:for commitOID:in:)`
  writing a note under `refs/notes/switchyard-review` (a dedicated namespace, not `commits`), the
  note body the decision envelope's JSON (`decision`, `message?`, `comments`, `editedPatch?` — the
  `ReviewReply` shape from #0055, so the note is machine-readable); `ReviewNotes.list(in:)` reading
  them back. Built on `GitProcess` (`notes add`/`notes list`/`notes show` with `--ref=`), never on
  libgit2. Fixture-determined tests: attach → the commit SHA is UNCHANGED (the criterion), the note
  reads back byte-identical, both ref formats.
- `CommitLog` — entries gain the note's presence/decision when a note exists for the commit
  (`CommitLogEntry` gains an optional field; absent means absent). `yard log` then surfaces notes
  alongside commits.
- **Namespace exclusion**: `refs/notes/switchyard-review` is excluded from `yard`'s ordinary ref
  enumeration the way journal refs are — read `RefSnapshot.swift`'s `switchyardNamespace` handling
  and `graphRows`'s `--exclude` for the established patterns, and follow whichever applies per site.
  A test asserts a review note never appears in the graph/ref list.
- `docs/provenance.md` (NEW) — the trailers-versus-notes split, in this repo's own words: trailers
  for agent provenance (written at commit time, covered by the signature), notes for review decisions
  (attached after the fact, SHA-preserving), and why each belongs where it does.
- The app-side review flow calls `ReviewNotes.record` when a decision arrives (#0055's serving body)
  — persistence failure swallowed (the #0160 invariant: a journal/record failure never breaks the
  human's decision), surfaced as a log line.
- Verification: `cd YardKit && swift test` — **N greater than 1452**, the count on main. State the
  delta. Mutations: at least two (e.g. record writes to `refs/notes/commits` instead of the
  dedicated namespace → the namespace-exclusion test goes red; the note body drops a field → the
  byte-identical read-back test goes red).
