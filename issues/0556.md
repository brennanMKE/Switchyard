## Description

**Diagnosed in the VM; not size-dependent.** On #0555's large fixture ⌘G after typing `rel-5994`
("1 match") never selected `large commit 5994`. It reproduces on the small `uitest-fixture-repo`.

**Root cause, measured** (probe: `step` wrote the arguments it was called with into an on-screen
`Text` the UI test read — work log): the match bar's ⌘G / ⇧⌘G are `.keyboardShortcut`s on the
chevron `Button`s in `CommitHistoryView.matchBar(matchOids:layout:)`, whose actions call
`step(±1, in: matchOids, layout: layout)`. **The key equivalent runs the action closure from the
render that first showed the match bar**, so `matchOids` is that render's list — the first
keystroke's matches:

| fixture, typed | matches shown | `step` called with | selected |
|---|---|---|---|
| large, `rel-5994` | 1 | `n=5000` (the query `r`) | `large commit 5999` — index 1 of the stale list |
| small, `tip` then ⌘A `root` | 1 | `n=4` (the query `t`) | `0382 third commit` stays — index 1 of the stale list |
| large, `rel-5994`, **clicking** the chevron instead | 1 | `n=1` | `large commit 5994` ✓ |

A click runs the current closure; only the key equivalent is stale. `matchIndex` is `@State`, so it
reads fresh — it is the captured `matchOids` (and `layout`) that are old. **#0402's spike passes by
coincidence**: every small-fixture subject contains "t" ("commit"), so the stale list for `t` is all
four commits, and index 1 of it is `0382 third commit` — the commit #0402 types and expects.
(#0525's ⌘G step also passes; why was not measured.) The `.disabled(matchOids.isEmpty)` state is
**not** stale: typing `q` (0 matches, both buttons disabled) then `root` left ⌘G firing.

**The fix:** the buttons only write a `@State` request (`matchStep = MatchStepRequest(delta: ±1)`,
a fresh `UUID` per press so two presses in one direction are two changes), and
`.onChange(of: matchStep)` calls `step` — an `onChange` action is the current render's, the same
way `.onChange(of: query)` already reaches the current `matchOids` to jump to the first match. The
write is event-origin (a key press or a click), which is the routine case in swift-guidance's
observation rules. `step` and `focus` are unchanged.

**Hypotheses from the original report, settled:** stale action closure — **yes**. A fold opening
under the selection, lazy rows not realized — no: the fixed build selects `large commit 5994`
inside a fold on the large fixture. Focus — not involved: the filter field keeps keyboard focus and
the key equivalent still reaches the button.

### 2. `SwitchyardUITests/0556MatchStepUITests.swift` — new file, exactly this

```swift
import XCTest

/// #0556: ⌘G steps through the current query's matches. It used to step
/// through the matches of the render that first showed the match bar — here
/// "q", which matches nothing — so after "q" was replaced by "root" it
/// selected nothing.
final class Spike0556MatchStepUITests: XCTestCase {
    @MainActor
    func testCommandGStepsThroughTheCurrentMatches() {
        let app = XCUIApplication()
        app.launchWithFixtureRepository()
        let filter = app.sidebarFilterField()
        XCTAssertTrue(filter.waitForExistence(timeout: 30), "no filter field")
        filter.click()
        filter.typeText("q")
        XCTAssertTrue(app.matchCount("0 matches").waitForExistence(timeout: 10),
                      "the match bar does not say 0 matches for \"q\"")
        filter.typeKey("a", modifierFlags: .command)
        filter.typeText("root")
        XCTAssertTrue(app.matchCount("1 match").waitForExistence(timeout: 10),
                      "the match bar does not say 1 match for \"root\"")
        app.typeKey("g", modifierFlags: .command)
        let headline = app.staticTexts.matching(NSPredicate(
            format: "value == %@ OR label == %@",
            UITestFixture.rootSubject, UITestFixture.rootSubject)).firstMatch
        XCTAssertTrue(headline.waitForExistence(timeout: 10),
                      "⌘G did not select the one commit matching \"root\"")
        let shot = XCTAttachment(screenshot: app.windows.firstMatch.screenshot())
        shot.name = "history-command-g"
        shot.lifetime = .keepAlways
        add(shot)
    }
}
```

`matchCount(_:)` is #0525's extension (`0525HistorySearchUITests.swift`, same target); nothing in

`uitest-main`, `spike-side`, `alpha-fork`, `beta-older`, `origin/uitest-side`, `v0.1`).
