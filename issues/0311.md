## Description

**Finding 2 of the M1 milestone review, twelfth pass, 2026-08-18.** `conflictedFiles` **throws** on a
modify/delete conflict — the second-most-common conflict there is — and `UD` is unasserted.

`YardKit/Sources/YardGit/Conflicts.swift:38`, mutated `case deletedByThem = "UD"` → `= "Uq"`:
**full suite green, 1115 tests.**

**Measured**: a plain modify/delete merge emits `u UD N... … f.txt`. Under the mutation,
`conflictedFiles` throws `unrecognizedKind(xy: "UD")`.

**Coverage of the seven-value set, established by the review:**

| value | pinned by |
|---|---|
| `UU` | `ConflictsTests` |
| `DU` | `ConflictsTests` |
| `AA` | `StatusConflictsWireTests` |
| `DD` | `StatusConflictsWireTests` |
| **`AU`** | **nothing** |
| **`UA`** | **nothing** |
| **`UD`** | **nothing** |

The review measured `UD` directly; `AU` and `UA` share the gap by inspection — no test names them.

## Expected behavior

- [ ] A named test asserting `conflictedFiles` handles a **modify/delete** conflict (`UD`) without
      throwing, and reports the kind correctly.
- [ ] **Cover `AU` and `UA` too** if their fixtures are cheap — `AU` is added-by-us against deleted-by-them
      and `UA` its mirror. **If either is awkward to construct, say so and leave it**, naming which.
- [ ] **Consider a table-driven shape**: one test iterating every `Kind` case with the git bytes that
      produce it, so a future added case fails until its row exists. Say whether you took that shape or a

      the `u <XY>` record directly.
- [ ] **Mutation:** corrupt the `UD` raw value. The new test must redden by throwing.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both

## Work log

- **Round 1 — 2026-08-18, Sonnet subagent, 119,373 tokens, 9m53s, accepted.** Two tests. 1124 → 1126.
- **It checked what #0316 already covered and narrowed itself**, which is what the dispatch asked and
  what stops two guards becoming one guard written twice.
- **The distinction it drew is worth keeping**, and review confirmed it by measurement: #0316's scan
  builds each record **from the case's own `rawValue`**, so it is self-consistent by construction — it
  catches a *missing* case and cannot catch a *wrong* raw value. Under the `UD` → `Uq` mutation the scan
  stays **green** and only the end-to-end test reddens. Two guards, genuinely different questions.
- **Finding `AU` and `UA` took real work.** Neither arises from add/add or modify/delete, which give
  `AA` and `UD`/`DU`. Per git's own stagemask encoding they need exactly **one** non-base stage, which a
  **rename/rename(1to2)** conflict produces — a single fixture yields `AU`, `UA` and `DD` together, each
  confirmed against `git status --porcelain=v2` before the parser was trusted.
- **Reviewed by re-running.** Full suite twice on the merged result, both `Test run with 1126 tests in
  80 suites passed`.
