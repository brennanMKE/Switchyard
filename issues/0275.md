## Description

**Proposal of #0044's seventh umbrella review, 2026-08-18, filed as an ordinary issue rather than a
finding.** `aDetachedSiblingHoldsNoBranchAndIsNeverDisturbed`
(`YardKit/Tests/YardGitTests/WorktreeDisturbanceTests.swift:156-167`) **is vacuous with respect to
detachment** — the thing its name claims to test.

The fixture captures the snapshot **before** creating `agent-branch`, so `disturbances` skips the
sibling at `WorktreeDisturbance.swift:148` — an unrecorded ref name, per guide §11 decision 20 —
regardless of what the sibling actually holds.

**Proved by probe, not argued:** deleting the `git checkout --detach` line leaves the filtered suite
green at 18/18. The detach contributes nothing.

Its neighbour `aSnapshotPredatingTheWorktreeNeverDisturbsItsLiveCheckout`
(`WorktreeDisturbanceTests.swift:115`) is that same fixture with an *attached* sibling, asserting the
same emptiness — so the two tests differ only in a line that changes no outcome. The comment on the
detached one ("the snapshot predates agent-branch, so restore would delete it") is also pre-decision-20
language: restore has not deleted anything since #0231.

**Why this is not a review finding.** No production mutation survives because of it. After #0256 the
detached-sibling exclusion rests on `guard let branch = entry.branch` plus `sequencerHeldBranch`
returning nil, and a genuinely detached sibling has no artefact naming a branch — so the review could
construct nothing that this test alone would have caught. It is still a test that does not test what
its name says, sitting on the one exclusion decision 2 exists to protect.

## Expected behavior

- [ ] The fixture **records `agent-branch` in the snapshot first**, so the sibling's branch is a ref the
      restore would move — and only then detaches the sibling's `HEAD`. The detach must be what makes
      `disturbances` empty, not the snapshot's ignorance of the name.
- [ ] Assert against the **positive control in the same test or beside it**: the same fixture *without*
      the detach names the sibling as a disturbance. Two tests differing only in the detach, with
      opposite outcomes, is what makes the detach load-bearing.
- [ ] The stale comment is corrected — it still says restore would *delete* the branch, which stopped
      being true at #0231 / guide §11 decision 20.
- [ ] **Mutation:** delete the `git checkout --detach` line from the fixture. The test must **redden**.
      That is the whole criterion — today it stays green, which is the defect.
- [ ] **Second mutation:** drop the detached-sibling exclusion in production (make `disturbances` treat
      a detached sibling as holding its `HEAD`'s branch). State what happens. If nothing reddens even
      after the fixture is fixed, say so plainly rather than declaring the box met — the exclusion may
      genuinely be unfalsifiable through this path, and that is worth knowing.
- [ ] `cd YardKit && swift test` **twice, in the foreground**, both green, above the count in
      `docs/test-baseline.txt`.

## Work log

- **Round 1 — 2026-08-18, Sonnet subagent, 109,959 tokens, 14m41s, accepted.** Test-only. 1078 → 1079.
- **The second mutation was a real question and got a real answer: no.** Falling back to
  `entry.branch ?? entry.head` — treating a detached sibling as holding whatever its `HEAD` names —
  changes nothing, because that value is a raw 40-character oid and can never match a recorded branch
  name. **The detached-sibling exclusion is not falsifiable through this path.** That is worth knowing
  and worth having written down: it means the exclusion's safety rests on git's own data shape, not on
  a test, and a future change that makes `entry.head` carry a symbolic name would silently reopen it.
- **The positive control is what makes the first mutation meaningful.** Two tests with identical
  fixtures differing only in the detach, asserting opposite outcomes.
- **Reviewed by re-running.** Full suite twice on the merged result, both `Test run with 1079 tests in
  78 suites passed`. Deleting the detach line now reddens the test — which is precisely what it did not
  do before this issue.

## Confirmed by #0044's eighth review — 2026-08-18

**The second mutation's negative answer was independently reproduced.** Removing the exclusion in its
strongest form — `let branch = entry.branch` → `entry.branch ?? entry.head` at
`WorktreeDisturbance.swift:135` — left all 1081 tests green.

**So decision 2's detached-sibling exclusion is unfalsifiable by construction, and that is now settled
rather than suspected.** A genuinely detached sibling's only branch-shaped artefact is a raw oid;
`"refs/heads/" + <oid>` can never match a name any snapshot recorded, and `sequencerHeldBranch` returns
nil when none of the three sequencer files exist. The exclusion is correct because of git's data shape,
not because a test holds it in place.

**This issue's repair of the fixture is still load-bearing**, and the same review proved it: two of its
mutations die through the positive control this issue added.
