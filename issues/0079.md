## Description

One tab per repository, rendered with `SlidingTabBar`. **A tab's identity is its
`$GIT_COMMON_DIR`**, not the path the user opened, and that single choice settles several behaviors
at once:

- Opening an already-open repository **focuses its tab** instead of duplicating it.
- Opening a **linked worktree focuses the parent repository's tab** and selects that worktree inside
  it, because a worktree shares the common dir. Worktrees are a sidebar section (#0081), not peer
  tabs.
- "Same repo" and "same path" need only one answer, so the dedup logic has one input.

## Expected behavior

- [ ] Tabs render via `SlidingTabBar` with reorder and "+" wired up.
- [ ] Identity resolved with `git rev-parse --git-common-dir` through `WorktreeContext`, then canonicalized with `realpath`.
- [ ] Opening the same repo by a different path — symlink, trailing slash, `/tmp` vs `/private/tmp`, a subdirectory of the worktree — focuses the existing tab. Each is a test case.
- [ ] Opening a linked worktree of an open repo focuses that repo's tab and selects the worktree.
- [ ] Closing a tab releases its engine resources and any file watchers.
- [ ] Opening a path that is not a git repository reports it clearly and opens no tab.
