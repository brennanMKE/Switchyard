# 0079 — Implement repository tabs with $GIT_COMMON_DIR identity

## Description

One tab per repository, rendered with `SlidingTabBar`. **A tab's identity is its
`$GIT_COMMON_DIR`**, not the path the user opened, and that single choice settles several behaviors
at once:

- Opening an already-open repository **focuses its tab** instead of duplicating it.
- Opening a **linked worktree focuses the parent repository's tab** and selects that worktree inside
  it, because a worktree shares the common dir. Worktrees are a sidebar section (#0081), not peer
  tabs.
- "Same repo" and "same path" need only one answer, so the dedup logic has one input.

## Expected behavior

- [ ] Tabs render via `SlidingTabBar` with reorder and "+" wired up.
- [ ] Identity resolved with `git rev-parse --git-common-dir` through `WorktreeContext`, then canonicalized with `realpath`.
- [ ] Opening the same repo by a different path — symlink, trailing slash, `/tmp` vs `/private/tmp`, a subdirectory of the worktree — focuses the existing tab. Each is a test case.
- [ ] Opening a linked worktree of an open repo focuses that repo's tab and selects the worktree.
- [ ] Closing a tab releases its engine resources and any file watchers.
- [ ] Opening a path that is not a git repository reports it clearly and opens no tab.

test, and UI tests cannot run under CLI-driven `xcodebuild` on this machine — the runner times out
enabling automation mode without Accessibility rights. Anything built here would ship untested. In
`YardUI` it is reachable from `swift test`.

are in the app target today.

Tests go in `Tests/YardUITests` and import **without** `@testable`, so they see what the app sees.

## Planning update — 2026-08-17. The identity is already resolved; this issue is the store around it.

`WorktreeContext` (`YardKit/Sources/YardGit/WorktreeContext.swift`) already produces everything the
identity needs, and re-deriving any of it here would be a second answer to a settled question:

```swift
public static func resolve(path: String, git: GitProcess = GitProcess()) throws -> WorktreeContext
public let topLevel: String?      // nil for a bare repository
public let gitDir: String
public let commonDir: String      // ← the tab's identity
public let worktreeName: String?  // non-nil in a linked worktree
public var isLinkedWorktree: Bool
static func canonicalize(_ path: String) -> String
```

- **`commonDir` is the tab id.** It is already canonicalized by `resolve` — `canonicalize` uses
  `realpath(3)`, which is what makes `/tmp` and `/private/tmp` one directory. Do **not** call `realpath`
  again in the view layer; assert the property instead.
- **A linked worktree resolves to the same `commonDir` as its parent.** That is what makes criterion 4
  fall out rather than needing a rule: open a worktree, get the parent's tab, and select
  `worktreeName` inside it.
- **A subdirectory of the working tree resolves to the same context**, because `resolve` shells out to
  git rather than walking the path itself. This is the case the Notes call the most common in practice.
- **`resolve` throws `notARepository(path:detail:)`** outside a repository — criterion 6's gate, and it
  must be that rather than a check of the returned values (`whereAmI` returns empty fields instead of
  throwing there; see #0124 Given 2 for the measured behaviour).

### Where the code goes, and what the split makes testable

- **`YardKit/Sources/YardUI/RepositoryTabs.swift`** — the store: an `@Observable` type holding an
  ordered list of open repositories keyed by `commonDir`, with `open(path:) -> Outcome` returning
  whether it **focused an existing tab**, **opened a new one**, or **refused** (not a repository).
  Every criterion except the chrome is a property of this type, and it needs no view to assert.
- **The `SlidingTabBar` view** on top of it, also in `YardUI` (guide §11 decision 10). Chrome only:
  the reorder and "+" affordances come with the component.

**Resolution is injected, not called directly.** Take a `(String) throws -> WorktreeContext` closure
defaulting to `WorktreeContext.resolve(path:)`. That is what lets the store's tests run without
building a repository for every case — though the identity cases below should use **real fixtures**,
because the thing being tested is what git says, not what a fake says.

### Tests — `YardKit/Tests/YardUITests/`, importing **without** `@testable`

Criterion 3 is four separate cases and each is a real `FixtureRepository`:

- the same repository opened by its own path twice → one tab;
- opened via a **symlink** to the working tree → the same tab;
- opened with a **trailing slash** → the same tab;
- opened by a **subdirectory** of the working tree → the same tab.

Then: a **linked worktree** of an open repository focuses the parent's tab and selects the worktree
(`worktreeName`); a **non-repository** path opens no tab and reports the refusal; **closing** a tab
removes it and leaves the others' order intact.

`/tmp` versus `/private/tmp` is worth one explicit case even though `resolve` handles it, because it
is the one that has already cost this project a round (#0097, an assertion that could not evaluate
true for any input).

**Mutation, to run and report:** key the tabs on `topLevel` instead of `commonDir` and confirm the
linked-worktree test goes red. That is the single choice this issue exists to make, and no other
mutation proves it.

### Not testable here

"Closing a tab releases its engine resources and any file watchers" (criterion 5) has nothing to
release yet — there are no watchers until the sidebar and graph panes exist. Assert what is real: the
store drops its reference and a deinit/teardown hook fires. Say plainly in the report that the
resource half is deferred, and to which issue.
