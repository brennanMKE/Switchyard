## Description

Two Character bugs in `BlameParser` (`YardKit/Sources/YardGit/Blame.swift`), each measured on
`main` (git 2.54.0, 2026-09-29) through `blameFile(at:file:)`:

1. **CRLF files throw.** `parse` (line 139) splits `git blame --porcelain` output with
   `text.split(separator: "\n", …)`, on the `"\n"` **Character**. Swift reads `"\r\n"` as one
   Character. A CRLF file's content line is `"\ta\r"` + `"\n"`, so it fuses with the next entry's
   header line, and the next tab-prefixed content line then reaches `parseEntryStart`.
   - before, `f.txt` = `"a\r\nb\r\n"`: throws `malformedEntryHeader("\tb\r")`.
   - after: two lines, contents `["a\r", "b\r"]`, final lines `[1, 2]`.
2. **A subject or name opening with a combining mark throws.** `applyHeaderLine` (line 204)
   matches `line.hasPrefix("summary ")`. `hasPrefix` compares Characters, and the separating space
   plus a following U+0301 are one Character, so `"summary \u{301}x".hasPrefix("summary ")` is
   **false** (scratch check, `swift` 6). The summary is never recorded and the entry throws.
   - before, a commit whose message is `"\u{301}x"`: throws `missingCommitHeader`.
   - after: `summary == "\u{301}x"`.

   The same applies to `author `, `author-mail `, `author-tz ` and `filename ` values. The fix matches
   every key scalar by scalar, and returns the value as the scalars after the key.

**Unaffected, checked:** `parseEntryStart` splits `<oid> <n> <n>[ <n>]` on `" "`, and that line never
holds user text. The content line's `line.hasPrefix("\t")` and `line.dropFirst()` are correct: a tab
is a control character, which never joins a grapheme cluster (`"\t\u{301}x".hasPrefix("\t")` is
`true`, measured).

```swift
    static func applyHeaderLine(_ line: String, to info: inout CommitInfo) throws {
        // Matched scalar by scalar: a value opening with a combining mark
        // fuses with the separating space into one `Character`, so
        // `line.hasPrefix("summary ")` is false for `summary \u{301}x`
        // (#0483, measured).
        func value(after prefix: String) -> String? {
            guard line.unicodeScalars.starts(with: prefix.unicodeScalars) else { return nil }
            return String(Substring(line.unicodeScalars.dropFirst(prefix.unicodeScalars.count)))
        }
        if let author = value(after: "author ") {
            info.author = author
        } else if var mail = value(after: "author-mail ") {
            if mail.hasPrefix("<") { mail.removeFirst() }
            if mail.hasSuffix(">") { mail.removeLast() }
            info.authorEmail = mail
        } else if let time = value(after: "author-time ") {
            info.authorTime = Int(time)
        } else if let zone = value(after: "author-tz ") {
            info.authorTimeZone = zone
        } else if let summary = value(after: "summary ") {
            info.summary = summary
        } else if line == "boundary" {
            info.isBoundary = true
        } else if let path = value(after: "filename ") {
            if path.hasPrefix("\"") { throw Failure.quotedPath(line) }
            info.path = path
        }
```

// MARK: - #0483: CRLF lines and combining marks

/// Swift reads "\r\n" as one `Character`, so splitting porcelain on the "\n"
/// Character fused a CRLF content line with the next entry's header line,
/// and the following tab-prefixed content line then failed as an entry
/// header (measured on `main`: throws `malformedEntryHeader("\tb\r")`).
@Test func aCRLFFileBlamesOneEntryPerLine() throws {
    var repo = try FixtureRepository()
    defer { repo.destroy() }
    try repo.build([.init("base", files: ["f.txt": "a\r\nb\r\n"])])

    let lines = try blameFile(at: repo.url.path, file: "f.txt")

    #expect(lines.map(\.content) == ["a\r", "b\r"])
    #expect(lines.map(\.finalLine) == [1, 2])
}

/// `summary <subject>`: a subject opening with a combining mark fuses with

    let lines = try blameFile(at: repo.url.path, file: "f.txt")

    #expect(lines.map(\.summary) == ["\u{301}x"])
}
