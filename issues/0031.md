## Description

An agent will run `git` directly in the same repository between two `yard` commands. Constantly.
This is the normal case, not the exception, and undo must never clobber work it did not know about.

Before restoring, compare every ref in the entry's `guard` map against its current value. On
mismatch, refuse with exit 4 naming the ref, the expected value, and the actual one — a bare
"repository changed" is useless to whoever hits it.

## Expected behavior

- [ ] Guard captured at snapshot time for every ref the operation could touch, plus `HEAD`.
- [ ] Mismatch refuses with exit 4 and names ref, expected OID, and actual OID.
- [ ] `--force` available to a human, and **refused for a non-interactive caller** — not merely discouraged.
- [ ] Guard also checks sibling worktrees' `HEAD` values, per #0044.
- [ ] Tests: mutate with `yard`, then move a ref with `git`, then assert `undo` refuses.
