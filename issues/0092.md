## Description

`main.swift` is still the placeholder. The envelope's whole purpose is to be what `yard` emits, and
right now no code path in the binary produces one — so none of its behaviour is exercised by actually
running the thing.

Wire the existing envelope into the entry point. Do **not** build the command registry; that is #0088.

## Givens — verified on `main`, treat as true

1. `YardKit/Sources/yard/main.swift` is today, in full:

   ```swift
   // main.swift

   import Foundation
   import YardGit
   import YardKit

   // Placeholder entry point. …

   let version = YardGit.libgit2Version
   print("yard \(YardKit.version) (libgit2 \(version.major).\(version.minor).\(version.revision))")
   ```

2. `YardKit/Sources/YardKit/Envelope.swift` provides, all public and all correct — **do not change
   their behaviour**:
   - `Envelope(result: EncodableResult? = nil)` and `Envelope(ok: Bool)` — the success envelope.
   - `EncodableResult(_ value:)` — a type-erased wrapper for any `Encodable & Sendable`.
   - `EnvelopeFail(code: EnvelopeErrorCode, message: String, hint: String? = nil)`, with
     `write()` — which puts **only** the JSON on stdout and the human line on stderr — and
     `terminate() -> Never`, which writes and then exits with `error.matchExitCode().rawValue`.
   - `ExitCode.usage` is `1`.
3. `Envelope` (the success type) has **no** `write()` today. `EnvelopeFail` does. Adding the matching
   `write()` to `Envelope` is in scope and expected — mirror `EnvelopeFail.write()`: encode to JSON,
   write to `FileHandle.standardOutput`, `fflush`, and put nothing else on stdout.

## The entry point must stay thin, because an executable target cannot be tested

SwiftPM cannot `@testable import` an executable target, so **anything in `main.swift` is untestable**.
Put the logic in the library and leave the entry point as a call into it:

- Add **`YardKit/Sources/YardKit/CommandLineRunner.swift`** with a pure, `nonisolated` function:

  ```swift
  public func runYard(arguments: [String]) -> (stdout: String, exitCode: ExitCode)
  ```

  It takes the arguments *after* the executable name, returns the exact bytes that belong on stdout
  and the exit code to use, and performs **no I/O of its own**. That is what makes it testable.
- `main.swift` becomes: build the argument array, call `runYard`, write `stdout` to standard output,
  and `exit` with the code. Nothing else.

## Expected behavior

- [ ] New file `YardKit/Sources/YardKit/CommandLineRunner.swift` with `runYard(arguments:)` as above.
- [ ] `main.swift` keeps `import YardGit` and `import YardKit`, and is reduced to argument
      collection, one call to `runYard`, the write, and the exit.
- [ ] **No arguments** → the version string as today, wrapped in a success envelope, exit 0.
- [ ] An **unrecognised command** → a failure envelope with code `.usage`, exit `1`.
- [ ] A **recognised no-op command** (`yard noop` is fine) → a success envelope, exit 0.
- [ ] Arguments are guarded before any subscript or `first!`. A previous round shipped `args.first!`
      ahead of its own empty-args guard.
- [ ] Every path returns valid JSON on stdout and nothing else — no bare `print`, no version line
      outside an envelope.
- [ ] Tests over `runYard(arguments:)` cover all four cases above, asserting **both** the exit code
      and that the returned stdout parses as JSON whose first byte is `{` and last is `}`.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s
      summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line
      you paste. **N must be greater than 93**, the count on `main` before this change.
- [ ] Paste the real output and exit code of `swift run yard bogus-command`, obtained by running it.

## Tests must be able to fail

Assert the exit code *and* the payload for each case. A test that only checks "it returned some JSON"
passes for every case equally and distinguishes none of them.

Two things the review surfaced that were **consequences of this issue's own design**, not model
error:

- `Envelope.write()` was added because Given 3 required it, but has no call site and no test —
  `main.swift` writes the returned string directly. #0093 is expected to consume it; if it does not,
  it should be deleted rather than left as specified-but-dead code.
- Moving all I/O out of `runYard` means the **binary no longer emits the human-readable
  `[error] …` line on stderr** for failures. `EnvelopeFail.write()` still does it; the entry point
  just never calls it. Filed as #0100 — that line was the whole point of #0091's stderr routing, and
  losing it at the entry point undoes half of that work.
