## Description

`main.swift` is still the 12-line placeholder — untouched by both #0011 rounds. The envelope's
criterion is "used by every command"; right now it is used by none, so none of its behavior is
exercised by running the binary.

Make `yard` actually emit envelopes and set exit codes.

## Expected behavior

- [ ] `main.swift` keeps `import YardGit` and `import YardKit` and its version output.
- [ ] An unknown command emits a **failure envelope on stdout** and exits with the usage code (1).
- [ ] A recognized no-op command emits a **success envelope on stdout** and exits 0.
- [ ] Arguments are guarded before any subscript — no `args.first!`.
- [ ] `swift run yard --json bogus-command` prints valid JSON and exits non-zero; paste the output and the exit code.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `swift build` succeeds and `swift test` prints a `Test run with N tests` line you paste.

## Notes

Split out of #0011, whose rounds skipped this twice. Blocked by #0090 and #0091. Start from
`issue/0011`.

This is deliberately small: wire the existing envelope into the entry point. Do not build the command
registry — that is #0088.

## Sequencing — blocked by #0091

**Blocked by #0091.** #0090 through #0093 all modify the same file,
`YardKit/Sources/YardKit/Envelope.swift`, so they are strictly sequential: each one branches from a
`main` that already contains its predecessor. Dispatching two of them at once produces two models
editing one file from a base that does not contain the other's work.

Branch this issue from `main` **after** #0091 is squash-merged, not before. A worktree created
early must be rebased onto that `main` first.
