## Description

The unglamorous problem that actually breaks agent worktrees, and the highest-value worktree feature
Switchyard could ship: a fresh worktree has the tracked files and nothing else. No `node_modules`,
no `.env`, no `Pods`, no `.venv`, no build cache. The agent's first command fails and it starts
improvising — which is exactly the failure mode worktree isolation was supposed to prevent.

A repo-level config lists untracked paths to copy, symlink, or regenerate on `yard wt new`, plus
optional post-create commands. Stored in the repo so the whole team and every agent gets the same
treatment.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/WorktreeTemplate.swift`. Create it; do not restructure existing files.
- [ ] Config lives in the repository and is versioned, not in per-user state.
- [ ] Three actions supported per entry: copy, symlink, and regenerate-by-command.
- [ ] Symlinks are used for shared caches, copies for per-worktree secrets — both demonstrated in the default example.
- [ ] Post-create commands run with the new worktree as the working directory and their failure is reported, not swallowed.
- [ ] A missing source path is a clear warning, not a hard failure of the whole worktree creation.
- [ ] Secrets copied this way are never written to the journal or logged.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N must be greater than the count on `main` before this change.
