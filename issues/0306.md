## Description

**Finding 3 of the M1 milestone review, eleventh pass, 2026-08-18.** `verify` is blind to signed commits
in **SHA-256** repositories.

`YardKit/Sources/YardGit/SignatureVerification.swift:158`, dropping `|| line.hasPrefix("gpgsig-sha256 ")`:
survived the **full suite**.

**Measured**: the review signed a commit in an `--object-format=sha256` repository with a fake gpg, and
git 2.50.1 wrote the header as

```
gpgsig-sha256 -----BEGIN PGP SIGNATURE-----
```

Under the mutation, `format` reports `.none` instead of `.openpgp` for **every signed commit in a
SHA-256 repository**. `grep gpgsig-sha256 Tests/` returns **zero hits**.

**The fixture is cheap**: `craftedCommit` already fabricates commit headers, so no SHA-256 repository is
strictly required to pin the *detection* — though building one is also possible and is what the review
did.

## Expected behavior

- [ ] A named test in `YardKit/Tests/YardGitTests/SignatureVerificationTests.swift` asserting
      `detectFormat` reports `.openpgp` for a commit whose signature header is **`gpgsig-sha256`**.
- [ ] **Say which route you took** — a fabricated header through `craftedCommit`, or a real
      `--object-format=sha256` repository. The fabricated header pins the detection; a real repository
      would also exercise `SignatureVerification.run` end to end. Take the cheaper one and say what it
      does and does not cover.
- [ ] **Mutation:** drop the `gpgsig-sha256` clause at line 158. The new test must redden while the
      existing `gpgsig` tests stay green.
- [ ] `cd YardKit && swift test` **twice, in the foreground with an explicit 900000 ms timeout**, both
      green, above the count in `docs/test-baseline.txt`.
