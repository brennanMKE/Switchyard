## Description

**Finding 1 of #0160's sixth umbrella review, 2026-08-18 — the fifth wrong-entry attach against one
root cause, and the review argued convincingly that a sixth patch is the wrong move.** Settled as
**guide §11 decision 24**; this issue implements it.

**Why #0264's stamp does not hold.** It stamps the slot with the live operation's `orig-head` and
requires a match on read. **`orig-head` is the commit the operation started from, not the operation.**
`git rebase --abort` restores `HEAD` to exactly that commit, so a retry from the same tip — the
ordinary thing a caller does after an abort — carries the identical stamp, and the slot from the
abandoned operation is trusted again.

**#0264's own accepted test says so in a comment** (`PostRewriteAttachTests.swift:1353-1356`):

```
// Advance HEAD by one plain, unrelated commit so the foreign
// rebase's own `orig-head` cannot coincidentally match A's stamp --
// both rebases would otherwise start from the same tip left behind
// by the abort.
```

**Probe** — that test verbatim minus the manufactured commit, foreign rebase driven through
`runForeignGit`:

```
PROBE slot after A:           01M0A2RCMP643S155XFZY7VCHF 92866a0cb4bd1334d850a2d754d809d095a2e1a5
PROBE head after abort:       92866a0cb4bd1334d850a2d754d809d095a2e1a5
PROBE live foreign orig-head: 92866a0cb4bd1334d850a2d754d809d095a2e1a5
PROBE attached:               Optional("01M0A2RCMP643S155XFZY7VCHF")  entryA=01M0A2RCMP643S155XFZY7VCHF
✘ (attached) == nil
```

## The change

**Write the entry id inside the sequencer directory**, so it has git's lifetime instead of one
switchyard has to guess. Measured, git 2.50.1, with our file present:

| probe | result |
|---|---|
| `echo … > "$(git rev-parse --git-path rebase-merge)/switchyard-entry-id"` then `git rebase --continue` | `Successfully rebased and updated refs/heads/side.` — **unaffected** |
| the directory after `--continue` | **gone**, with our file |
| the same, then `git rebase --abort` | directory **gone**, with our file |

So the record cannot outlive the operation, and **every staleness rule that exists for it can go.**

## Notes

**Parent #0160**, bullet 2 — the fifth issue against *the slot's lifetime is not bound to an operation*,
and the one that stops answering the staleness question and removes it instead.

**What this spends** is in decision 24 and should not be rediscovered: switchyard writes a file into a
directory git owns. It is a write of a file git ignores, resolved through `rev-parse --git-path`, whose
failure mode is a missed attach. The alternative — drop the mechanism until #0217's hook glue can carry
the id in its environment — was considered and rejected as giving up working behaviour for a milestone.

**`git am` writes `rebase-apply` with no `orig-head`** (measured by the review). Under decision 24 that
stops mattering, because nothing depends on `orig-head` any more — a point worth confirming rather than
assuming as you delete.
