## Description

Split out of #0012, whose round 1 timed out partly on breadth. An agent needs to know whether commits
it makes will be signed, and how — before it makes one, not after. This issue adds one value type,
`SigningConfig`, that reports what git is configured to do. It does not sign anything and does not
verify anything — #0036 and #0037 do that in M2.

The type answers two different questions the guide separates deliberately: **will commits be
signed** (`commit.gpgsign`), and **can SSH signatures be verified as good**
(`gpg.ssh.allowedSignersFile`). They are independent fields with independent tests; see Given 5 for
why conflating them is wrong.

Re-authored to code level 2026-08-07. Every fact below marked *measured* was produced by running the
command on this machine (git 2.50.1, Apple Git-155) on 2026-08-07, not recalled from documentation.

### 2. `GitProcess` — the exact API you call

`GitProcess` is a concrete struct in `YardKit/Sources/YardGit/GitProcess.swift`, constructed
`GitProcess()`. There is no runner protocol and no injection seam — do not invent one. The three
declarations you need, pasted verbatim from that file:

```swift
    public struct Output: Sendable {
        public let standardOutput: Data
        public let standardError: String
        public let exitCode: Int32

        /// stdout decoded as UTF-8, lossily. Git paths may contain arbitrary
        /// bytes, so callers that must preserve them use `standardOutput`.
        public var text: String {
            String(decoding: standardOutput, as: UTF8.self)
        }

        /// stdout split into lines with the trailing empty element removed.
        public var lines: [String] {
            text.split(separator: "\n", omittingEmptySubsequences: false)
                .dropLast(while: { $0.isEmpty })
                .map(String.init)
        }
    }
```

```swift
    /// Runs `git` and returns its output, throwing on a non-zero exit.
    @discardableResult
    public func run(
        _ arguments: [String],
        workingDirectory: String? = nil,
        standardInput: Data? = nil,
        extraEnvironment: [String: String] = [:]
    ) throws -> Output
```

```swift
    /// Runs `git` and returns its output whatever the exit code.
    ///
    /// Some git commands use exit status as information rather than failure —
    /// `diff --quiet` and `merge-base --is-ancestor`, for instance — so callers
    /// that expect that use this and inspect `exitCode` themselves.
    public func capture(
        _ arguments: [String],
        workingDirectory: String? = nil,
        standardInput: Data? = nil,
        extraEnvironment: [String: String] = [:]
    ) throws -> Output
```

**`capture` does not throw on a non-zero exit; `run` does.** Verified by executing the existing
suite tests `captureReturnsNonZeroWithoutThrowing` and `failingCommandThrowsWithStderr`
(`swift test --filter GitProcessTests`, all 12 passed, 2026-08-07). This matters because
`git config --get` exits 1 for a missing key, and a missing key is the **normal case** here, not an
error — so every config read in this issue goes through `capture`, never `run`. The error type for
the genuinely-broken case is `GitProcess.Failure.exited(code:stderr:arguments:)`, a public enum case
in the same file.

`extraEnvironment` is merged over the process environment per invocation — that is the seam the
hermetic tests use (Given 6).

### 4. Measured `git config` behaviour — the facts the implementation turns on

Measured 2026-08-07 on git 2.50.1 (Apple Git-155), in a scratch repository created for the purpose
(local scope unless stated; the same exits reproduce at global scope):

| command | key state | exit | stdout |
|---|---|---|---|
| `git config --get commit.gpgsign` | unset | **1** | (empty) |
| `git config --type=bool --get commit.gpgsign` | unset | **1** | (empty) |
| `git config --get commit.gpgsign` | `true` | 0 | `true` |
| `git config --get commit.gpgsign` | `false` | 0 | `false` |
| `git config --get commit.gpgsign` | `yes` | 0 | `yes` |
| `git config --type=bool --get commit.gpgsign` | `yes` | 0 | `true` |
| `git config --type=bool --get commit.gpgsign` | `banana` | **128** | stderr: `fatal: bad boolean config value 'banana' for 'commit.gpgsign'` |
| `git config --get gpg.format` | unset | **1** | (empty) |
| `git config --get gpg.format` | `ssh` | 0 | `ssh` |
| `git config --get gpg.format` | `openpgp` | 0 | `openpgp` |
| `git config --get user.signingKey` | unset | **1** | (empty) |
| `git config --get user.signingKey` | set to `~/.ssh/id_ed25519.pub` | 0 | `~/.ssh/id_ed25519.pub` (verbatim, no tilde expansion) |
| `git config --get gpg.ssh.allowedSignersFile` | unset | **1** | (empty) |
| `git config --get gpg.ssh.allowedSignersFile` | set | 0 | the configured path, verbatim |
| `git config --get commit.gpgsign` | global `true` **and** local `false` | 0 | `false` (local wins) |

Three consequences, all binding:

- **Exit 1 means unset. It is not an error and must not be reported as `false`.** This is the
  distinction the whole issue exists to preserve.
- **Exit 128 is an error** (malformed boolean) and must throw, not read as unset.
- **`--type=bool` normalizes** `yes`/`1`/`on` to `true`. Use it for `commit.gpgsign` so the reported
  `Bool` matches what git will actually do; plain `--get` would return the raw string `yes`.
- **The config subsection is case-sensitive**: querying `gpg.SSH.allowedSignersFile` when the key
  was set as `gpg.ssh.allowedSignersFile` returns exit 1, nothing (measured). Spell the key exactly
  `gpg.ssh.allowedSignersFile`.

### 5. Why "will sign" and "can verify" are separate fields

`docs/engine-findings.md` (#0002 findings), quoted verbatim:

> **`gpg.ssh.allowedSignersFile` is not optional for verification.** Without it git reports the
> signature as untrusted rather than good — the signature is valid, but git has no basis to trust the
> key. `yard verify` (#0019) must distinguish "no signature", "signature present but signer not
> allowed", and "good signature", which is three states, not two.

So in a repository with `commit.gpgsign=true`, `gpg.format=ssh`, `user.signingKey` set, and **no**
`gpg.ssh.allowedSignersFile`: `willSign` is `true` and `canVerifySSHSignatures` is `false`. That
exact configuration is a test (test 3 below).

### 6. Hermetic tests

`git config --get` blends system → global → local → worktree scope; that resolution is git's job
(never parse config files). But it means a developer's real `~/.gitconfig` could leak into a test
that expects "unset". The isolation mechanism, measured 2026-08-07: with
`GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_SYSTEM=/dev/null` in the environment, global and
system scope read as empty while **local scope remains fully visible** (a local
`gpg.ssh.allowedSignersFile` still returned exit 0 and its value). Tests pass those two variables
through the `extraEnvironment` seam. The scope-resolution test points `GIT_CONFIG_GLOBAL` at a fake
global config file written *inside the fixture directory* — never at a path outside the worktree
tree the fixture owns.

## The API — implement exactly this

`YardKit/Sources/YardGit/SigningConfig.swift`:

```swift
// SigningConfig.swift

import Foundation

/// What git is configured to do about commit signing, read from the effective
/// configuration (system → global → local → worktree) via `git config --get`.
/// Reporting only: nothing here signs or verifies anything (#0036, #0037).
///
/// Two independent questions, two independent fields:
/// - `willSign` — will a plain `git commit` produce a signed commit?
/// - `canVerifySSHSignatures` — can git report an SSH signature as *good*,
///   rather than merely present? Requires `gpg.ssh.allowedSignersFile`
///   (docs/engine-findings.md, #0002 findings).
public struct SigningConfig: Equatable, Sendable {

    public enum Format: Equatable, Sendable {
        case openpgp
        case ssh
        case x509
        /// A value git itself would reject at commit time. Reported, not
        /// validated — reporting is this type's whole job.
        case unrecognized(String)

        init(configValue: String) {
            switch configValue {
            case "openpgp": self = .openpgp
            case "ssh":     self = .ssh
            case "x509":    self = .x509
            default:        self = .unrecognized(configValue)
            }
        }
    }

    /// `commit.gpgsign`, normalized through `--type=bool`. `nil` means the key
    /// is unset in every scope. Git treats unset as "do not sign", but
    /// reporting `nil` as `false` would erase a distinction an agent needs:
    /// unset means "nobody decided", `false` means "someone decided no".
    public let commitSigningEnabled: Bool?

    /// `gpg.format`. `nil` means unset; git's default is then openpgp, but the
    /// default is git's to apply, not ours to bake in.
    public let format: Format?

    /// `user.signingKey`, verbatim as configured — no tilde expansion, no
    /// existence check. `nil` means unset.
    public let signingKey: String?

    /// `gpg.ssh.allowedSignersFile`, verbatim as configured. `nil` means unset.
    public let allowedSignersFile: String?

    /// Will a plain `git commit` produce a signed commit?
    public var willSign: Bool { commitSigningEnabled == true }

    /// Can git verify an SSH signature as good rather than merely present?
    public var canVerifySSHSignatures: Bool { allowedSignersFile != nil }

    public init(commitSigningEnabled: Bool?,
                format: Format?,
                signingKey: String?,
                allowedSignersFile: String?) {
        self.commitSigningEnabled = commitSigningEnabled
        self.format = format
        self.signingKey = signingKey
        self.allowedSignersFile = allowedSignersFile
    }

    /// Reads the effective signing configuration for the repository at
    /// `workingDirectory`.
    ///
    /// - Parameter extraEnvironment: merged over the process environment for
    ///   every `git config` invocation. Tests use it to neutralize global and
    ///   system scope; production callers leave it empty.
    public static func read(
        in workingDirectory: String,
        git: GitProcess = GitProcess(),
        extraEnvironment: [String: String] = [:]
    ) throws -> SigningConfig
}
```

### The read algorithm — exact commands, exact exit-code mapping

All four reads use `git.capture(_:workingDirectory:extraEnvironment:)` — **never `run`**, because
exit 1 is the normal unset case and `run` would throw on it (Given 2).

1. `commitSigningEnabled`: arguments `["config", "--type=bool", "--get", "commit.gpgsign"]`.
   - exit 0 → `true` when `output.lines.first == "true"`, `false` when `"false"` (after
     `--type=bool` those are the only exit-0 outputs — measured, Given 4)
   - exit 1 → `nil`
   - any other exit → `throw GitProcess.Failure.exited(code: output.exitCode, stderr:
     output.standardError, arguments: <the arguments>)`
2. `format`: arguments `["config", "--get", "gpg.format"]`.
   - exit 0 → `Format(configValue: output.lines.first ?? "")`
   - exit 1 → `nil` · other → throw as above
3. `signingKey`: arguments `["config", "--get", "user.signingKey"]` — same 0/1/other mapping,
   exit 0 → `output.lines.first ?? ""`.
4. `allowedSignersFile`: arguments `["config", "--get", "gpg.ssh.allowedSignersFile"]` — same
   mapping. The subsection spelling `ssh` is case-sensitive (Given 4).

## Tests — `YardKit/Tests/YardGitTests/SigningConfigTests.swift`

swift-testing (`import Testing`, `@Test`, `#expect`) — not XCTest. `@testable import YardGit`.
Every test builds its own `FixtureRepository`, calls `defer { repo.destroy() }`, and passes the
hermetic environment from Given 6. A shared file-private helper keeps them short:

```swift
private let hermetic = ["GIT_CONFIG_GLOBAL": "/dev/null", "GIT_CONFIG_SYSTEM": "/dev/null"]

private func set(_ key: String, _ value: String, in repo: FixtureRepository) throws {
    try GitProcess().run(["config", key, value], workingDirectory: repo.url.path)
}

private func unset(_ key: String, in repo: FixtureRepository) throws {
    try GitProcess().run(["config", "--unset", key], workingDirectory: repo.url.path)
}
```

The eight tests, each with the production change that would make it fail:

1. `explicitFalseIsFalseNotNil` — fresh fixture (init already set `commit.gpgsign=false`, Given 3);
   read; `#expect(config.commitSigningEnabled == false)` — `== false`, not `!= true` — and
   `#expect(config.willSign == false)`.
2. `unsetKeysReportNil` — fixture, then `unset("commit.gpgsign")` (required — Given 3); read with
   `hermetic`; expect `commitSigningEnabled == nil`, `format == nil`, `signingKey == nil`,
   `allowedSignersFile == nil`, `willSign == false`, `canVerifySSHSignatures == false`.
3. `sshSigningWithoutAllowedSignersWillSignButCannotVerify` — set `commit.gpgsign=true`,
   `gpg.format=ssh`, `user.signingKey=~/.ssh/id_ed25519.pub`; read with `hermetic`; expect
   `commitSigningEnabled == true`, `format == .ssh`,
   `signingKey == "~/.ssh/id_ed25519.pub"`, `willSign == true`, and
   `canVerifySSHSignatures == false`. This is the engine-findings configuration from Given 5.
4. `allowedSignersFileTurnsVerificationOn` — same setup as test 3 plus
   `gpg.ssh.allowedSignersFile` set to a path string; read; expect `allowedSignersFile` equal to
   that exact string and `canVerifySSHSignatures == true`.
5. `booleanAliasesAndFormatsNormalize` — set `commit.gpgsign=yes` and `gpg.format=openpgp`; read;
   expect `commitSigningEnabled == true` (proves `--type=bool` is in the pipeline — plain `--get`
   returns the string `yes`, Given 4) and `format == .openpgp`.
6. `malformedBooleanThrows` — set `commit.gpgsign=banana`; `#expect(throws: (any Error).self)`
   around the read. Distinguishes exit 128 (throw) from exit 1 (`nil`).
7. `localScopeOverridesGlobal` — fixture; write a file named `fake-global-config` **inside
   `repo.url`** containing `[commit]\n\tgpgsign = true\n` (use `writeUntracked`); read with
   `extraEnvironment: ["GIT_CONFIG_GLOBAL": <that file's path>, "GIT_CONFIG_SYSTEM": "/dev/null"]`.
   Local `false` (from init) wins: expect `commitSigningEnabled == false`. Then
   `unset("commit.gpgsign")` and read again with the same environment: the global scope shows
   through, expect `commitSigningEnabled == true`.
8. `reportsInBothRefFormats` — `@Test(arguments: FixtureRepository.RefFormat.supported())`; build
   the fixture with that format, set `commit.gpgsign=true`, read with `hermetic`, expect
   `commitSigningEnabled == true` and `willSign == true`.
