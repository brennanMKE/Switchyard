# 0205 — Decide what restore does with a sequencer the target never captured

## Description

**Noticed by the second #0034 umbrella review, 2026-08-17.** Recorded because it is a real behavioural
question nobody has answered, not because it is known to be wrong.

`JournalRestore` **materialises** a captured sequencer (`JournalRestore.swift:356-361`) and has no
inverse. So restoring a target that captured **no** sequencer, while a rebase is in progress, leaves the
rebase directory standing: the refs, index and worktree come back to a pre-rebase state while
`.git/rebase-merge` still describes an operation that no longer matches them.

Nothing is lost — the pre-restore entry captures the live sequencer, so the mid-rebase state is
recoverable by restoring that entry. The question is what the repository should look like **immediately
after** such a restore, and today the answer is "half of each".

## What has to be decided

- **Clear it.** A restore whose target has `captured.sequencer == .notCaptured` removes the sequencer
  directory, so the working state matches the snapshot exactly. Consistent with "restore restores a
  snapshot" — but it is a **deletion** on a path that currently only writes, and deletions are how
  restore could destroy something the journal does not hold.
- **Leave it, and report it.** Add the fact to the `Report` — the caller learns a rebase is still in
  progress and can decide. Cheaper and safer; makes the honest-reporting contract carry one more thing.
- **Leave it silently** (today's behaviour), and document it as intended.

## Expected behavior

- [ ] The decision recorded in guide §11, in the shape of decisions 12 and 13.
- [ ] Whichever branch: a test that pins the chosen behaviour, driving a real mid-rebase restore of a
      pre-rebase checkpoint. `UndoRoundTripSuiteTests.repositoryStoppedMidRebase` builds the fixture.
- [ ] If "leave it, and report it": the new `Report` field, its wire encoding, and a wire test —
      `Report` is an agent-facing type and every field of it is pinned by `YardWireTests`.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt`; state the delta once the branch is chosen.

## Notes

**Measure before deciding.** The obvious question — does git itself mind? — is answerable in a scratch
repo in about a minute: start a rebase, reset the refs and worktree underneath it, and see what
`git status` and `git rebase --continue` do. That measurement should be in the issue before the
decision is.

Related but distinct: **#0201** establishes that `AUTO_MERGE` is not needed to resume a rebase, and
**#0204** pins that the restore flow captures the sequencer at all. Neither answers this.
