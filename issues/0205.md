## Description

**Noticed by the second #0034 umbrella review, 2026-08-17.** Recorded because it is a real behavioural
question nobody has answered, not because it is known to be wrong.

`JournalRestore` **materialises** a captured sequencer (`JournalRestore.swift:356-361`) and has no
inverse. So restoring a target that captured **no** sequencer, while a rebase is in progress, leaves the
rebase directory standing: the refs, index and worktree come back to a pre-rebase state while
`.git/rebase-merge` still describes an operation that no longer matches them.

Nothing is lost — the pre-restore entry captures the live sequencer, so the mid-rebase state is
recoverable by restoring that entry. The question is what the repository should look like **immediately
after** such a restore, and today the answer is "half of each".

## What has to be decided

- **Clear it.** A restore whose target has `captured.sequencer == .notCaptured` removes the sequencer
  directory, so the working state matches the snapshot exactly. Consistent with "restore restores a
  snapshot" — but it is a **deletion** on a path that currently only writes, and deletions are how
  restore could destroy something the journal does not hold.
- **Leave it, and report it.** Add the fact to the `Report` — the caller learns a rebase is still in
  progress and can decide. Cheaper and safer; makes the honest-reporting contract carry one more thing.
- **Leave it silently** (today's behaviour), and document it as intended.

## Expected behavior

- [ ] The decision recorded in guide §11, in the shape of decisions 12 and 13.
- [ ] Whichever branch: a test that pins the chosen behaviour, driving a real mid-rebase restore of a
      pre-rebase checkpoint. `UndoRoundTripSuiteTests.repositoryStoppedMidRebase` builds the fixture.
- [ ] If "leave it, and report it": the new `Report` field, its wire encoding, and a wire test —
      `Report` is an agent-facing type and every field of it is pinned by `YardWireTests`.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt`; state the delta once the branch is chosen.

## Notes

**Measure before deciding.** The obvious question — does git itself mind? — is answerable in a scratch
repo in about a minute: start a rebase, reset the refs and worktree underneath it, and see what
`git status` and `git rebase --continue` do. That measurement should be in the issue before the
decision is.

Related but distinct: **#0201** establishes that `AUTO_MERGE` is not needed to resume a rebase, and
**#0204** pins that the restore flow captures the sequencer at all. Neither answers this.

## Measured — 2026-08-17. "Leave it silently" is not a viable option.

The measurement this issue asked for, run in a scratch repository: start a rebase that conflicts, then
reset refs, `HEAD` and the worktree underneath it — exactly what restoring a pre-rebase checkpoint does
— and see what git makes of the leftover sequencer.

**1. `git status` advertises an operation that cannot be completed.**

```
On branch side
Last command done (1 command done):
   pick 98eab8c # side
No commands remaining.
You are currently rebasing branch 'side' on 'f67437e'.
  (all conflicts fixed: run "git rebase --continue")
```

**2. `git rebase --continue` fails, and its error names nothing a user can act on:**

```
error: update_ref failed for ref 'refs/heads/side': cannot lock ref 'refs/heads/side':
       is at cdf04b0… but expected 98eab8c…
error: could not update refs/heads/side
```

The rebase's recorded expectation and the restored ref disagree, which is precisely what the restore
made true.

**3. `git rebase --abort` succeeds — and silently undoes the restore.** Measured: `side` moves from the
restored `cdf04b0` back to the rebase's original `98eab8c`, the worktree file reverts, and the sequencer
clears. So the one clean exit from the state **destroys the operation the user just performed**, with no
message saying so.

That third one is the finding. Leaving a stale sequencer does not merely look untidy: it produces a
repository that advertises a resumable operation, refuses to resume it, and offers an escape hatch that
reverts the restore.

## Decision — clear it. Guide §11 decision 14.

Taken 2026-08-17 in Brennan's absence under the standing instruction, **reversible and flagged for his
confirmation**, on the strength of the measurement rather than taste:

- **"Leave it silently"** — today's behaviour — is eliminated outright by measurement 3.
- **"Leave it and report it"** still leaves the broken state on disk; the report tells a caller about a
  situation it then has to clean up by hand, and the obvious hand-cleanup (`--abort`) is the one that
  destroys the restore.
- **"Clear it"** makes the repository match the snapshot, which is what restore promises. **Nothing is
  lost**: the pre-restore entry captures the live sequencer (#0200), so the mid-rebase state is
  recoverable by restoring *that* entry — the journal's own guarantee is what makes the deletion safe.

## Expected behavior

- [ ] `YardKit/Sources/YardGit/JournalRestore.swift` — when the target's `captured.sequencer` is
      `.notCaptured` and a sequencer directory **is** present, remove it, and add `.sequencer` to the
      report's `restored` list (the piece was brought into line with the snapshot, which is what
      `restored` means).
- [ ] Reuse the existing path resolution rather than building one: `SequencerSnapshot` already resolves
      `context.path(for: layout.rawValue)` and already removes a destination directory before moving a
      staged one into place. **Never concatenate onto `.git/`** — CLAUDE.md's hardest rule.
- [ ] Both layouts are handled: a `rebase-apply` state must clear as well as `rebase-merge`.
      `SequencerSnapshot.Layout.allCases` exists.
- [ ] A test in `YardKit/Tests/YardGitTests/UndoRoundTripSuiteTests.swift`: stop mid-rebase, restore a
      pre-rebase checkpoint, and assert the sequencer directory is **gone** and `git status --porcelain=v2
      --branch` no longer reports a rebase in progress.
- [ ] A second test asserting the round trip still holds — restore the pre-restore entry and confirm the
      rebase is back and `git rebase --continue` completes. **This is the test that proves the deletion
      is safe**, and without it the issue has only removed state.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line **greater than** the count in
      `docs/test-baseline.txt` by exactly 2. The delta is the criterion.
