## Description

**The enforcement issue for M1 criterion 5's clause (b), and the direct analogue of what #0316 did for
clauses (a) and (c).** Guide §11 records why: the thirteenth review pass declared class 2 closed after
enumerating **the places the engine already passes a pinning flag** — a space bounded by what previous
authors thought of. The fourteenth pass sampled the sites that enumeration did not list and found
**three levers in about a dozen candidates** (#0323, #0324/#0325, #0326), and designing this issue
found **two more** (#0328, #0329). Five gaps from two ad-hoc samples is not a criterion anyone can
call met by inspection.

**The property, stated exactly:** *an engine result's encoded `schemaVersion: 1` bytes must not depend
on the user's git configuration.* That is checkable, and this issue makes it a test.

**A shell sweep of the same shape found #0328 and #0329 in one run** — eleven argument vectors against
twenty-nine configs, comparing `od -c | md5` of git's output. Its three true positives out of 319
pairs, all reproduced by hand afterwards:

```
DIFFERS  gitStatus            <-  status.renames=false     (#0329)
DIFFERS  conflictedFiles      <-  status.renames=false     benign: only the `2 R.` line moves;
                                                            ConflictParser reads `u ` records only
DIFFERS  listHunks/unstaged   <-  core.abbrev=16           (#0328)
```

**Do not port the shell sweep.** Comparing git's raw bytes produces the benign `conflictedFiles` row
above, which a test would have to special-case forever. Compare **encoded results** instead: it is
drift-proof (the vectors are never transcribed), it is uniform across all seven functions, and it is
the property the criterion actually states.

## Expected behavior

- [ ] A new test file `YardKit/Tests/YardGitTests/ConfigImmunityTests.swift` with one parameterized
      test over a table of `(config key, value)` pairs. For each pair, in one fixture: run every
      criterion-1 engine function, `git config` the pair, run them all again, and `#expect` the
      encoded bytes are equal — reporting **which function and which config** on failure, not just
      that something differed.
- [ ] **Compare encoded JSON, not values.** `WorktreeStatus` and `WorktreeStatusEntry` are not
      `Equatable` (`WorktreeStatus.swift:138`, `:10`); all seven results are `Encodable`. Encode with
      `JSONEncoder` configured `.sortedKeys` — the same configuration `YardWireTests` uses — and
      compare `Data`.
- [ ] **The seven functions**, with the file each is in:
      `whereAmI` (`WhereAmI.swift:138`), `graphRows` (`LaneAssignment.swift:184`),

## Notes

**Milestone M1**, criterion 5. **All six blockers are resolved as of 2026-08-18** — #0323, #0324,
#0325, #0326, #0328 and #0329 — so every row in the starting table should pass on a clean tree. **If
one does not, that is a new finding, not a broken test**: file it, allow-list it with that number, and
say so in the report.

**Three of the six pins are on `git log`'s vector** (`--no-show-signature`, `--encoding=UTF-8`) and one
on `git diff`'s (`--full-index`), so the `log.showSignature`, `i18n.logOutputEncoding` and
`core.abbrev` rows are the ones that will tell you fastest whether the harness is actually exercising
what it claims.

**Runtime is the risk worth sizing up front.** Thirty-one configs × eight function calls × two runs is
roughly five hundred `git` invocations in one test. The suite already runs seventy-odd suites in
parallel shelling out to `git`, and that load has produced two distinct failures on `main`. **Build the
fixture once for the whole table**, and if the parameterized form is slow enough to matter, say so with
a number rather than restructuring on a hunch.
