## Description

Screenshot of GitUp's context menu on a commit node in the Batty repo —
`build/gitup-context-menu.png` (node `0442f97` "Add a plan…", the HEAD commit on `main`):

> Quick View… (Space) · Diff with HEAD… (I, disabled) · Checkout "main" Branch (⇥, disabled) ·
> **Edit Message… (E)** · **Fixup with Parent (F)** · **Squash with Parent… (S)** ·
> **Swap with Parent (Move Down) (D)** · **Swap with Child (Move Up) (U, disabled)** ·
> **Delete (⌫)** · **Rewrite… (W)** · **Split… (⌥S)** · Revert Against Current Branch… (R) ·
> Cherry-Pick Against Current Branch… (C, disabled) · Merge into Current Branch… (⌃M, disabled) ·
> Rebase Current Branch onto Here (⌃R, disabled) · Set Tip of Current Branch Here (⌃T, disabled) ·
> Add Tag… (T) · Create Branch… (B) · Edit Local Branch "main" (→)

Three things to learn from, stated as measured:

1. **Every M5 operation Switchyard built is in this menu** — fixup, squash, swap/reorder both
   directions, delete/drop, split, reword (Edit Message). Switchyard ships the same operations
   (`yard absorb`, `split`, `reorder`, `drop`, `reword`) but only as CLI verbs: the app has **no
   node context menu and no in-app history rewriting at all**. A human using Switchyard's UI
   cannot do any of what this menu offers.
2. **The menu is context-aware**: items disable when the operation is impossible from this node
   (Swap with Child at HEAD; merge/rebase legs when the node is already on the current branch).
   The disabled state is information — it teaches the graph's rules instead of erroring.
3. **Shortcuts are on every item** — the rewrite operations are one keystroke from the node, and
   the menu is the discoverability layer for them.

Switchyard's differentiators stand (modern signing, CLI remote control — the same operations are
agent-invocable), but the human surface for history rewriting is empty.

## Expected behavior

- [ ] Right-clicking a commit node in the app's history view opens a context menu carrying the
      M5 operations that apply to that node — fixup-with-parent, squash, swap up/down, delete,
      split, reword — each mapped to the existing engine calls (`Fixup`, `Split`, `Rewrite`,
      `Absorb`), never reimplemented.
- [ ] Items disable with a reason when impossible from the selected node (merge commits, tip
      position, cross-branch targets), mirroring the typed refusals the engine already returns.
- [ ] Every rewrite lands in the journal and is undoable (`yard undo`), exactly as the CLI verbs
      do — one checkpoint per operation.
- [ ] The menu's items carry shortcuts, and the graph updates in place after the rewrite.

### What the engine actually offers, per menu item (*measured*, signatures from source)

| Menu item | Engine call | Notes |
|---|---|---|
| Edit Message… | `Rewrite.reword(commit:message:signing:at:git:extraEnvironment:)` | Works on merges (`commit-tree` keeps every parent). |
| Fixup into Parent | `Fixup.run(source: "HEAD", target: <first parent>, signing:at:git:extraEnvironment:)` | **Only `HEAD`**: any other `source` throws `.unsupportedSource`. Refuses staged changes (`.indexNotClean`). Keeps the *parent's* message. |
| Squash into Parent… | **none** | Nothing in `YardGit` combines two messages. CLAUDE.md priority rule 2 applies — see below. Engine support is filed as **#0374**. |
| Split… | `Split.run(commit:hunkID:first:second:signing:at:git:extraEnvironment:)` | `hunkID` is the **one** hunk that becomes the new, older first commit; the rest stay in the second. Ids come from `commitDiff`, the same call `loadCommitDiff` makes. Refuses fewer than two hunks (`.nothingToDo`). `Split.Result` has `first`/`second`, **no head**. |
| Move Up | `Rewrite.reorder(commit: C, position: .after, reference: <child of C on the chain>)` | |
| Move Down | `Rewrite.reorder(commit: C, position: .before, reference: <C's first parent>)` | `.before` inserts on the *older* side: the chain is `rev-list --first-parent --reverse`, oldest first (`Rewrite.swift`, the `.reorder` plan). Moving onto the root throws `.rootRewriteRefused`. |
| Delete Commit… | `Rewrite.drop(commit:signing:at:git:extraEnvironment:)` | Refuses merges (`.dropMergeRefused`) and the root (`.rootRewriteRefused`). |

Four facts that shape the design:

- **Do not write a checkpoint in the UI.** Every call above already runs inside
  `JournalCheckpoint.around` (`Rewrite.swift:677`, `Fixup.swift:405`, `Split.swift:220`). A second
  checkpoint would make one user action take two undo steps — the trap `Fixup.swift`'s header
  cites as #0212.
- **A merge anywhere above the commit breaks the replay.**
  `rewordBelowAMergeFailsTheReplayAndTouchesNothing` (`YardKit/Tests/YardGitTests/RewriteTests.swift`)
  shows git refusing to cherry-pick the merge: a raw `GitProcess.Failure`, nothing moved. Batty's
  `main` has a merge (*measured*: 1). The rules below disable those items with a reason instead
  of letting the user reach git's error.
- **`Absorb` is not a node operation.** It distributes *staged* hunks to whichever commits they
  belong to; there is no target commit to right-click. It is listed in the Expected behavior but
  has no place in this menu — see the planning report's questions. Do not add it here.
- **No human-reachable undo exists yet.** `JournalUndo.undo(steps:command:agent:lockTimeout:in:git:)`
  is an engine function; no `undo` arm exists in `YardCommands`, `switchyard` or `yard-engine`
  (*measured*, grep). Copy in this issue therefore never tells the user to run
  `switchyard undo`. The undo *criterion* is met by the engine's checkpoint; making it reachable
  from the app is a question for Brennan.

And three about the app today (*measured*):

- The only key equivalent in the app is ⌘O (`Switchyard/Commands.swift`). No `.contextMenu`,
  `.confirmationDialog`, `.alert`, `.help` or `FocusedValue` exists in `YardKit/Sources/YardUI` —
  **this issue sets the pattern #0360–#0363 copy**, which is why the model is shared and pure.
- `ContentView.reload()` sets `summary = nil` and clears history, graph, sidebar and selection, so
  the whole window drops to the "Loading…" spinner. Calling it after a rewrite is exactly the
  flicker and lost scroll position to avoid.
- `RerereDetailView.swift:176` puts `.keyboardShortcut(.defaultAction)` on a destructive button.
  **Do not copy that here**: Return must never delete history.

### Where the user finds each action

1. **Right-click** (or Control-click) a History row: a context menu for *that* row, even when
   another row is selected. `List.contextMenu(forSelectionType:menu:primaryAction:)` gives the
   native behaviour — AppKit draws the focus ring on the clicked row and hands the menu its oid.
2. **Menu bar → Commit**: the same items acting on the **selected** commit. This is what makes the
   shortcuts real; a shortcut shown only in a context menu is not guaranteed to fire while that
   menu is closed (*not verified either way* — **spike #0382** settles it, including whether a shortcut registered in both menus fires twice).
3. **Key equivalents**, shown in both menus.

Both menus render one `CommitActionMenuItems` view, so titles, order, shortcuts and disabled states
cannot drift apart.

**Order and grouping** (a `Divider` between groups; the destructive item alone at the end):

| Group | Items | Shortcut |
|---|---|---|
| Change this commit | Edit Message… | ⌥⌘E |
| | Fixup into Parent | ⌥⌘F |
| | Squash into Parent… | ⇧⌥⌘F |
| | Split… | ⌥⌘S |
| Reorder | Move Up | ⌥⌘↑ |
| | Move Down | ⌥⌘↓ |
| Remove | Delete Commit… | ⌘⌫ |

Why these, not single letters: macOS key equivalents carry ⌘. Bare letters would collide with
`List`'s type-to-select and never appear as menu key equivalents. Keys the system or standard menus
own are avoided: ⌘E (Use Selection for Find), ⌘F, ⌘D, ⌘M, ⌘H, ⌘T, ⌃⌘F (full screen), and ⌘Z / ⇧⌘Z,
which stay reserved for Edit → Undo / Redo. ⌘⌫ is Finder's Move to Trash, the nearest convention for
"remove this item". An ellipsis marks exactly the items that ask for input or confirmation
before acting (HIG).

**Allocated now for the sibling issues**, so their rounds do not collide: Revert ⌥⌘R, Cherry-Pick
⌥⌘C (#0360); Merge ⇧⌘M (#0361); Rebase onto ⇧⌘R and Set Branch Tip — **no shortcut,
deliberately** (#0362); New Branch ⇧⌘B, New Tag ⇧⌘T (#0363). *Not verified*: that ⌥⌘↑/↓ reach the menu while the
`List` is first responder — **spike #0383** settles it.

```swift
// CommitActions.swift
//
// #0359: the commit-node actions, their menu titles and shortcuts, when each
// is available, and what gets selected afterwards. Pure and `nonisolated`, so
// every rule is reachable from `swift test`; the views only render
// `CommitActionState`s and call back with a `CommitAction`.

import SwiftUI
import YardGit

public nonisolated enum CommitAction: String, CaseIterable, Sendable {
    case editMessage, fixupIntoParent, squashIntoParent, split, moveUp, moveDown, delete

    /// Menu title. An ellipsis marks exactly the actions that ask for more
    /// input or a confirmation before they run.
    public var title: String {
        switch self {
        case .editMessage: "Edit Message…"
        case .fixupIntoParent: "Fixup into Parent"
        case .squashIntoParent: "Squash into Parent…"
        case .split: "Split…"
        case .moveUp: "Move Up"
        case .moveDown: "Move Down"
        case .delete: "Delete Commit…"
        }
    }

    public var shortcut: KeyboardShortcut? {
        switch self {
        case .editMessage: KeyboardShortcut("e", modifiers: [.command, .option])
        case .fixupIntoParent: KeyboardShortcut("f", modifiers: [.command, .option])
        case .squashIntoParent: KeyboardShortcut("f", modifiers: [.command, .option, .shift])
        case .split: KeyboardShortcut("s", modifiers: [.command, .option])
        case .moveUp: KeyboardShortcut(.upArrow, modifiers: [.command, .option])
        case .moveDown: KeyboardShortcut(.downArrow, modifiers: [.command, .option])
        case .delete: KeyboardShortcut(.delete, modifiers: .command)
        }
    }

    /// Menu sections, top to bottom; a `Divider` between each.
    public static let menuGroups: [[CommitAction]] = [
        [.editMessage, .fixupIntoParent, .squashIntoParent, .split],
        [.moveUp, .moveDown],
        [.delete],
    ]
}

/// The first-parent chain from a tip, newest first, within the loaded rows.
public nonisolated enum FirstParentChain {
    public static func oids(in rows: [GraphRow], from tip: String) -> [String] {
        let byOid = Dictionary(rows.map { ($0.oid, $0) }, uniquingKeysWith: { first, _ in first })
        var chain: [String] = []
        var next: String? = tip
        while let oid = next, let row = byOid[oid] {
            chain.append(oid)
            next = row.parents.first
        }
        return chain
    }
}

/// Everything the availability rules need to know about one node.
public nonisolated struct CommitActionContext: Equatable, Sendable {
    public let oid: String
    public let isMerge: Bool
    public let isRoot: Bool
    /// Index on `HEAD`'s first-parent chain, 0 = the commit `HEAD` names;
    /// `nil` when the node is off that chain.
    public let chainIndex: Int?
    public let parentIsRoot: Bool
    public let parentIsMerge: Bool
    /// A merge sits between this node and `HEAD` on the chain -- the replay
    /// would have to cherry-pick it, which the engine cannot do.
    public let mergeAbove: Bool
    public let branchName: String?
    public let hasStagedChanges: Bool
    public let operationInProgress: String?
    public let isBusy: Bool

    public init(
        oid: String, isMerge: Bool, isRoot: Bool, chainIndex: Int?, parentIsRoot: Bool,
        parentIsMerge: Bool, mergeAbove: Bool, branchName: String?, hasStagedChanges: Bool,
        operationInProgress: String?, isBusy: Bool
    ) {
        self.oid = oid
        self.isMerge = isMerge
        self.isRoot = isRoot
        self.chainIndex = chainIndex
        self.parentIsRoot = parentIsRoot
        self.parentIsMerge = parentIsMerge
        self.mergeAbove = mergeAbove
        self.branchName = branchName
        self.hasStagedChanges = hasStagedChanges
        self.operationInProgress = operationInProgress
        self.isBusy = isBusy
    }

    /// `nil` when `oid` is not in `rows`.
    public static func make(
        oid: String, rows: [GraphRow], whereAmI: WhereAmI, isBusy: Bool
    ) -> CommitActionContext? {
        let byOid = Dictionary(rows.map { ($0.oid, $0) }, uniquingKeysWith: { first, _ in first })
        guard let row = byOid[oid] else { return nil }
        let chain = whereAmI.rawHead.isEmpty ? [] : FirstParentChain.oids(in: rows, from: whereAmI.rawHead)
        let index = chain.firstIndex(of: oid)
        let parent = row.parents.first.flatMap { byOid[$0] }
        let mergeAbove = index.map { chain[..<$0].contains { (byOid[$0]?.parents.count ?? 0) > 1 } } ?? false
        return CommitActionContext(
            oid: oid,
            isMerge: row.parents.count > 1,
            isRoot: row.parents.isEmpty,
            chainIndex: index,
            parentIsRoot: parent?.parents.isEmpty ?? false,
            parentIsMerge: (parent?.parents.count ?? 0) > 1,
            mergeAbove: mergeAbove,
            branchName: whereAmI.branch,
            hasStagedChanges: whereAmI.stagedCount > 0,
            operationInProgress: TrackingSummary.operationInProgress(for: whereAmI),
            isBusy: isBusy)
    }
}

public nonisolated struct CommitActionState: Equatable, Sendable {
    public let action: CommitAction
    /// `nil` when the action is available; otherwise the reason it is not.
    public let disabledReason: String?

    public init(action: CommitAction, disabledReason: String?) {
        self.action = action
        self.disabledReason = disabledReason
    }

    public var isEnabled: Bool { disabledReason == nil }
}

public nonisolated enum CommitActionRules {
    public static func states(for context: CommitActionContext) -> [CommitActionState] {
        CommitAction.allCases.map { CommitActionState(action: $0, disabledReason: reason($0, context)) }
    }

    /// Every item disabled with one reason -- the menu bar's state when no
    /// commit is selected.
    public static func allDisabled(reason: String) -> [CommitActionState] {
        CommitAction.allCases.map { CommitActionState(action: $0, disabledReason: reason) }
    }

    public static func reason(_ action: CommitAction, _ c: CommitActionContext) -> String? {
        if c.isBusy { return "Another operation is still running" }
        if let operation = c.operationInProgress { return "\(operation) — finish or abort it first" }
        switch action {
        case .editMessage, .fixupIntoParent, .squashIntoParent, .split, .moveUp, .moveDown, .delete:
            return rewriteReason(action, c)
        }
    }

    /// The guards shared by every action that rewrites `HEAD`'s own history.
    /// #0360-#0363's actions are not rewrites and never reach this.
    private static func rewriteReason(_ action: CommitAction, _ c: CommitActionContext) -> String? {
        let branch = c.branchName.map { "“\($0)”" } ?? "HEAD"
        guard let index = c.chainIndex else {
            return "Only commits in \(branch)’s own history can be rewritten"
        }
        switch action {
        case .editMessage:
            return c.mergeAbove ? "A merge commit above this one can’t be replayed" : nil
        case .fixupIntoParent, .squashIntoParent:
            if index != 0 { return "Only the newest commit on \(branch) can be folded into its parent" }
            if c.isRoot { return "This commit has no parent" }
            if c.isMerge { return "A merge commit can’t be folded into its parent" }
            if c.hasStagedChanges { return "Commit or unstage your staged changes first" }
            return nil
        case .split:
            return c.mergeAbove ? "A merge commit above this one can’t be replayed" : nil
        case .moveUp:
            if index == 0 { return "Already the newest commit on \(branch)" }
            if c.isRoot { return "The root commit can’t be moved" }
            if c.isMerge || c.mergeAbove { return "Merge commits can’t be reordered" }
            return nil
        case .moveDown:
            if c.isRoot { return "Already the oldest commit" }
            if c.parentIsRoot { return "A commit can’t move below the root commit" }
            if c.isMerge || c.parentIsMerge || c.mergeAbove { return "Merge commits can’t be reordered" }
            return nil
        case .delete:
            if c.isMerge { return "A merge commit can’t be deleted" }
            if c.isRoot { return "The root commit can’t be deleted" }
            return c.mergeAbove ? "A merge commit above this one can’t be replayed" : nil
        }
    }
}

public nonisolated enum RewriteSelection {
    /// Where the acted-on commit sits on the chain afterwards.
    public static func chainIndex(after action: CommitAction, from index: Int) -> Int {
        switch action {
        case .moveUp: max(index - 1, 0)
        case .moveDown: index + 1
        case .editMessage, .fixupIntoParent, .squashIntoParent, .split, .delete: index
        }
    }

    /// The oid to select once the refreshed rows arrive. `newHead` is the
    /// refreshed `WhereAmI.rawHead`.
    public static func oid(
        after action: CommitAction, from index: Int, rows: [GraphRow], newHead: String
    ) -> String? {
        let chain = FirstParentChain.oids(in: rows, from: newHead)
        guard !chain.isEmpty else { return nil }
        return chain[min(chainIndex(after: action, from: index), chain.count - 1)]
    }
}

public nonisolated struct CommitActionFailure: Equatable, Sendable {
    public let title: String
    public let message: String

    public init(title: String, message: String) {
        self.title = title
        self.message = message
    }

    public static func make(for action: CommitAction, error: any Error) -> CommitActionFailure {
        let verb: String = switch action {
        case .editMessage: "Edit Message"
        case .fixupIntoParent: "Fixup Commit"
        case .squashIntoParent: "Squash Commit"
        case .split: "Split Commit"
        case .moveUp, .moveDown: "Move Commit"
        case .delete: "Delete Commit"
        }
        var message = String(describing: error)
        switch (error as? any ExitClassCarrying)?.exitClass {
        case .blockedOnConflicts:
            message += "\n\nGit stopped on a conflict. Resolve the conflicted files, then continue the operation in git."
        case .signingFailed:
            message += "\n\nHistory was not changed. Check that your signing key or agent is available, then try again."
        case .repositoryError, nil:
            break
        }
        return CommitActionFailure(title: "Couldn’t \(verb)", message: message)
    }
}
```

Which rules mirror a typed engine refusal and which are UI-side, so a reviewer knows what the
engine will back up:

- **Engine refusals**: not on the chain (`.commitNotOnRef` / `.reorderTargetNotOnBranch`),
  fixup off `HEAD` (`.unsupportedSource`), staged changes for fixup (`.indexNotClean`), merge
  delete (`.dropMergeRefused`), root delete or move below root (`.rootRewriteRefused`), an
  in-progress conflict (`.blockedOnConflicts`).
- **Measured engine outcome, not a typed refusal**: a merge above the commit (git's own
  cherry-pick error).
- **UI-conservative, not verified against the engine**: "a merge commit can't be folded into its
  parent" (an autosquash rebase across a merge is untested) and "merge commits can't be reordered".
  Loosen either only with a fixture test proving the engine handles it.

A chain commit older than the loaded 100-row window is never on screen, so it can never be
right-clicked. A parent outside the window reads as "not root, not merge" — the engine's typed
refusal then covers it through the failure alert.

### `YardKit/Sources/YardUI/CommitActionRunner.swift` (new, *compiled*)

```swift
// CommitActionRunner.swift
//
// #0359: the one place a commit action reaches the engine. Every engine call
// here already runs inside its own `JournalCheckpoint.around`, so this file
// writes no checkpoint of its own.

import Foundation
import YardGit

public nonisolated enum CommitActionRequest: Equatable, Sendable {
    case editMessage(commit: String, message: String)
    case fixupIntoParent(parent: String)
    case split(commit: String, hunkID: String)
    case moveUp(commit: String, child: String)
    case moveDown(commit: String, parent: String)
    case delete(commit: String)
}

@concurrent
public func performCommitAction(_ request: CommitActionRequest, at path: String) async throws {
    switch request {
    case let .editMessage(commit, message):
        _ = try Rewrite.reword(commit: commit, message: message, at: path)
    case let .fixupIntoParent(parent):
        _ = try Fixup.run(source: "HEAD", target: parent, at: path)
    case let .split(commit, hunkID):
        _ = try Split.run(commit: commit, hunkID: hunkID, at: path)
    case let .moveUp(commit, child):
        _ = try Rewrite.reorder(commit: commit, position: .after, reference: child, at: path)
    case let .moveDown(commit, parent):
        _ = try Rewrite.reorder(commit: commit, position: .before, reference: parent, at: path)
    case let .delete(commit):
        _ = try Rewrite.drop(commit: commit, at: path)
    }
}
```

It returns nothing on purpose: `Split.Result` carries no head, so the new head always comes from the
refreshed `WhereAmI.rawHead`, one path for all seven actions.

// CommitActionMenu.swift
//
// #0359: one menu body shared by the History list's context menu and the
// menu bar's Commit menu, so both show the same items, order, shortcuts and
// disabled states.

import SwiftUI

public struct CommitActionMenuItems: View {
    private let states: [CommitActionState]
    private let perform: (CommitAction) -> Void

    public init(states: [CommitActionState], perform: @escaping (CommitAction) -> Void) {
        self.states = states
        self.perform = perform
    }

    public var body: some View {
        let byAction = Dictionary(uniqueKeysWithValues: states.map { ($0.action, $0) })
        ForEach(Array(CommitAction.menuGroups.enumerated()), id: \.offset) { groupIndex, group in
            if groupIndex > 0 { Divider() }
            ForEach(group, id: \.self) { action in
                let state = byAction[action]
                Button(action.title) { perform(action) }
                    .keyboardShortcut(action.shortcut)
                    .disabled(state?.isEnabled != true)
                    .help(state?.disabledReason ?? "")
            }
        }
    }
}

/// What the menu bar's Commit menu acts on: the focused window's selected commit.
public struct CommitMenuTarget {
    public let states: [CommitActionState]
    public let perform: (CommitAction) -> Void

    public init(states: [CommitActionState], perform: @escaping (CommitAction) -> Void) {
        self.states = states
        self.perform = perform
    }
}

extension FocusedValues {
    @Entry public var commitMenuTarget: CommitMenuTarget? = nil
}

public struct CommitCommands: Commands {
    @FocusedValue(\.commitMenuTarget) private var target

    public init() {}

    public var body: some Commands {
        CommandMenu("Commit") {
            CommitActionMenuItems(
                states: target?.states ?? CommitActionRules.allDisabled(reason: "Select a commit first"),

        }
    }
}

**The flow in `ContentView`** (*not compiled*; every name verified against source):

```swift
@State private var runningAction: CommitAction?
@State private var actionFailure: CommitActionFailure?

private func run(_ request: CommitActionRequest, _ action: CommitAction, fromIndex index: Int) {
    guard let repositoryPath else { return }
    runningAction = action
    Task {
        defer { runningAction = nil }
        var succeeded = true
        do {
            try await performCommitAction(request, at: repositoryPath)
        } catch {
            succeeded = false
            actionFailure = CommitActionFailure.make(for: action, error: error)
        }
        await refreshAfterMutation { rows, newHead in
            succeeded
                ? RewriteSelection.oid(after: action, from: index, rows: rows, newHead: newHead)
                : selectedCommit
        }
    }
}

/// Re-reads after an in-app mutation without blanking the window: every value
/// loads into a local, then all assignments happen together on one main-actor
/// turn. `reload()` stays the open-a-repository path.
private func refreshAfterMutation(select: ([GraphRow], String) -> String?) async {
    guard let repositoryPath else { return }
    do {
        let newSummary = try await loadRepositorySummary(at: repositoryPath)
        let newHistory = (try? await loadCommitHistory(at: repositoryPath)) ?? []
        let newRows = (try? await loadCommitGraph(at: repositoryPath)) ?? []
        let newSidebar = try? await loadRepositorySidebar(at: repositoryPath)
        summary = newSummary
        history = newHistory
        graphRows = newRows
        sidebar = newSidebar
        selectedCommit = select(newRows, newSummary.whereAmI.rawHead)
    } catch {
        errorMessage = String(describing: error)
        summary = nil
    }
}
```

Refresh **after a failure too**: a conflicted replay leaves the repository mid-cherry-pick, and only
a refresh makes the header show "A cherry-pick is in progress" (#0369's `operationInProgress`) and
disables every rewrite with that same sentence. That is this issue's conflict hand-off; routing the
user into the resolve pane is a question, because `ResolveCenter` today only receives panes from
CLI `resolve --interactive` requests (`YardKit/Sources/YardUI/ResolvePane.swift`).

The action runs from a button or menu handler, so writing `@State` from its `Task` has one clear
owner and no update-transaction hazard. `defer` clears the busy state on every exit.
