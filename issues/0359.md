## Description

Screenshot of GitUp's context menu on a commit node in the Batty repo —
`build/gitup-context-menu.png` (node `0442f97` "Add a plan…", the HEAD commit on `main`):

> Quick View… (Space) · Diff with HEAD… (I, disabled) · Checkout "main" Branch (⇥, disabled) ·
> **Edit Message… (E)** · **Fixup with Parent (F)** · **Squash with Parent… (S)** ·
> **Swap with Parent (Move Down) (D)** · **Swap with Child (Move Up) (U, disabled)** ·
> **Delete (⌫)** · **Rewrite… (W)** · **Split… (⌥S)** · Revert Against Current Branch… (R) ·
> Cherry-Pick Against Current Branch… (C, disabled) · Merge into Current Branch… (⌃M, disabled) ·
> Rebase Current Branch onto Here (⌃R, disabled) · Set Tip of Current Branch Here (⌃T, disabled) ·
> Add Tag… (T) · Create Branch… (B) · Edit Local Branch "main" (→)

Three things to learn from, stated as measured:

1. **Every M5 operation Switchyard built is in this menu** — fixup, squash, swap/reorder both
   directions, delete/drop, split, reword (Edit Message). Switchyard ships the same operations
   (`yard absorb`, `split`, `reorder`, `drop`, `reword`) but only as CLI verbs: the app has **no
   node context menu and no in-app history rewriting at all**. A human using Switchyard's UI
   cannot do any of what this menu offers.
2. **The menu is context-aware**: items disable when the operation is impossible from this node
   (Swap with Child at HEAD; merge/rebase legs when the node is already on the current branch).
   The disabled state is information — it teaches the graph's rules instead of erroring.
3. **Shortcuts are on every item** — the rewrite operations are one keystroke from the node, and
   the menu is the discoverability layer for them.

Switchyard's differentiators stand (modern signing, CLI remote control — the same operations are
agent-invocable), but the human surface for history rewriting is empty.

## Expected behavior

- [ ] Right-clicking a commit node in the app's history view opens a context menu carrying the
      M5 operations that apply to that node — fixup-with-parent, squash, swap up/down, delete,
      split, reword — each mapped to the existing engine calls (`Fixup`, `Split`, `Rewrite`,
      `Absorb`), never reimplemented.
- [ ] Items disable with a reason when impossible from the selected node (merge commits, tip
      position, cross-branch targets), mirroring the typed refusals the engine already returns.
- [ ] Every rewrite lands in the journal and is undoable (`yard undo`), exactly as the CLI verbs
      do — one checkpoint per operation.
- [ ] The menu's items carry shortcuts, and the graph updates in place after the rewrite.
