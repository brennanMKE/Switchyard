## Description

Brennan, 2026-09-12: file the engine support behind #0359's **Squash into Parent…** — fold `HEAD`
into its first parent, keeping **both** commit messages (the user edits the combined message).
Linked from #0359, whose menu item shows its "not implemented yet" alert until this resolves.

### Why `Fixup` does not cover it (*measured* from source, `2d96d3e`)

`Fixup.run(source:target:…)` rewrites `HEAD`'s message to `fixup! …` with
`git commit --amend --fixup`, then runs `rebase --autosquash`. The folded commit's message is
discarded by design (`YardKit/Sources/YardGit/Fixup.swift`, header and the `extension Fixup` doc).
Autosquash's `squash!` mode would open an editor for the combined message, and `GitProcess` pins
`GIT_EDITOR=false`.

### Mechanism (*measured* with plain git 2.50.1, 2026-09-12)

Because `HEAD` is the tip, no replay is needed. In a three-commit repository (`root`, `parent msg`,
`head msg`):

```sh
T=$(git rev-parse HEAD^{tree})
N=$(printf 'parent msg\n\nhead msg\n' | git commit-tree $T -p HEAD~2)
git update-ref refs/heads/main $N $(git rev-parse HEAD)
```

This left 2 commits: the new tip has `HEAD`'s tree (checked equal) and the message
`parent msg\n\nhead msg\n`. The index and working tree need no change, since the tree is unchanged.

### Proposed surface — `YardKit/Sources/YardGit/Squash.swift` (new, *not compiled*)

```swift
public enum Squash {
    /// The message the UI pre-fills: the parent's message and HEAD's, each with
    /// trailing newlines trimmed, joined by one blank line, ending in one newline.
    public static func combinedMessage(parent: String, child: String) -> String

    /// Folds HEAD into its first parent as one commit with HEAD's tree and
    /// `message`, moving the branch once. One journal checkpoint.
    public static func run(
        message: String,
        signing: CommitCreate.Signing = .config,
        at path: String,
        git: GitProcess = GitProcess(),
        extraEnvironment: [String: String] = [:]
    ) throws -> Rewrite.Result
}

public enum SquashError: Error, Equatable, Sendable, CustomStringConvertible {
    case headIsRoot
    case parentIsRoot
    case mergeRefused(commit: String)
    case emptyMessage
    case blockedOnConflicts(files: [ConflictedFile])
    case signingFailed(reason: String)
}
```

`SquashError` conforms to `ExitClassCarrying` the way `RewriteError` does: `blockedOnConflicts` →
`.blockedOnConflicts`, `signingFailed` → `.signingFailed`, everything else → `.repositoryError`.

**Sequence**, modelled on `Rewrite`'s reword plan (`YardKit/Sources/YardGit/Rewrite.swift`), whose
helpers are private today — the planning pass decides whether to promote or duplicate them:

1. Refuse an unmerged index (`blockedOnConflicts`), as `Rewrite` does.
2. Resolve `HEAD`: attached ref or detached, as `Rewrite`'s `resolveHead` does.
3. Refuse a root `HEAD`, a root parent, or a merge on either side. The root-parent refusal mirrors
   `RewriteError.rootRewriteRefused`: the result would be a new root commit.
4. Refuse a message that is empty after trimming.
5. Inside `JournalCheckpoint.around(operation: "squash", at:git:)`: `commit-tree` with `HEAD`'s tree,
   the parent's parents, the message on stdin, and the explicit signing flag (`commit-tree` ignores
   `commit.gpgsign` — measured, `Rewrite.swift`'s doc). Then `update-ref --stdin` with the old value
   pinned.

Staged and unstaged changes need no refusal: the tree does not change.

## Expected behavior

- [ ] `Squash.run` folds `HEAD` into its first parent as one commit carrying `HEAD`'s tree and the
      given message, inside one journal checkpoint (one undo step).
- [ ] Typed refusals before any mutation: root `HEAD`, root parent, a merge on either side, an empty
      message, an unmerged index.
- [ ] Signing follows the explicit-flag rule; with `commit.gpgsign=true` the new commit is signed.
      Tests go in `YardKit/Tests/YardGitTests/SquashTests.swift` (new).
