## Description

Every SwiftUI view belongs in a package target, not in the Xcode project. This creates `YardUI`, moves
what little UI exists into it, and reduces the app target to what genuinely cannot live in a package.

**The reason is testability, not tidiness.** A view in the app target can only be exercised by a UI
test, and UI tests **cannot run under CLI-driven `xcodebuild` on this machine** — the runner times out
enabling automation mode without Accessibility rights (CLAUDE.md). The same view in a package target
is reachable from `swift test`, unattended, in seconds. Guide §11 decision 10.

Doing it now, while the UI is 19 lines, costs minutes. Doing it after M3 means moving a whole shell.

## Givens — verified on `main` 2026-08-07, treat as true

1. `YardKit/Package.swift` is `swift-tools-version: 6.3`, `platforms: [.macOS(.v26)]`. Its targets are
   `YardGit`, `YardKit` (both `dependencies: []`), the `switchyard` executable, and three test
   targets. **No target sets `swiftSettings` today.**

2. **`.defaultIsolation(MainActor.self)` is available in this toolchain** — verified by adding it to
   `YardKit` temporarily and building: it compiled far enough to raise
   `call to main actor-isolated global function 'renderFlagLine' in a synchronous nonisolated context`,
   which only happens if the setting took effect. Reverted.

3. The app target sets `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (`project.pbxproj:443,487`) and
   `SWIFT_VERSION = 5.0`, with `MACOSX_DEPLOYMENT_TARGET = 26.5`. **A package target does not inherit
   the isolation setting**, so `YardUI` must declare it or every moved view silently changes
   isolation.

4. The entire app UI is two files: `Switchyard/SwitchyardApp.swift` (12 lines, the `@main` `App`) and
   `Switchyard/ContentView.swift` (19 lines — a globe, `Hello, world!`, and a `#Preview`).

5. The app target already links `YardKit` and `YardGit` as package products (`adba141`), so adding a
   third product to link is the same mechanism.

6. **New Swift files under synchronized groups need no `project.pbxproj` edit** (CLAUDE.md), but
   *removing* `ContentView.swift` from the app and *adding* a package product to link are project
   changes. Xcode may be open — see the sequencing note.

7. `main` reported **310** package tests on 2026-08-07.

## What a real test for a view looks like here

Do not assert on rendering, and do not reach for snapshot testing. Assert on **what the view is built
from**: a view is a value, and its stored properties and any formatting helpers are ordinary code.

For `ContentView` as it stands there is almost nothing to assert, and that is fine — the test that
matters right now is that **`YardUI` is importable and its types are `public`**, which is the same
class of defect #0116 found in `YardGit`. So:

- `import YardUI` **without** `@testable`, exactly as `YardGitPublicAPITests` does. That is the only
  construct that sees what the app sees.
- Construct a `ContentView()` and assert on a property you deliberately expose — or, if the view has
  no state worth exposing yet, assert that the type is constructible and say plainly in the test's
  comment that it is a compile-level contract, not a behavioural one.

**Mutation**: remove `public` from `ContentView` and confirm `YardUITests` **fails to compile** with
`'ContentView' is inaccessible due to 'internal' protection level`, and that the app target fails too.
That compile failure is the proof the boundary is real. Restore.

**Second mutation**: add `import YardUI` to a file in `Sources/YardGit` and confirm the package fails
to build — the arrow must not be reversible. Restore.

## Sequencing — read before touching the project file

`project.pbxproj` needs two changes: link the `YardUI` product, and drop `ContentView.swift` from the
app target's sources. **Xcode rewrites `project.pbxproj` while it has the project open and has
silently dropped hand-added configuration mid-edit** (CLAUDE.md).

So: make the `Package.swift` and `Sources/YardUI/` changes first and confirm `swift build && swift
test` passes with them alone. Then report, and **stop before editing `project.pbxproj`** — say exactly
what needs adding in Xcode's UI (target → General → Frameworks, Libraries, and Embedded Content → +
→ `YardUI`) and let Brennan do it, the same way #0045 was resolved. Do not hand-edit that file.

Verify afterwards with `xcodebuild -showBuildSettings`, not by reading the file.
