## Description

Signature verification for a revision, using `ssh-keygen -Y verify` or `gpg --verify` depending on
the signature format found on the commit.

## Expected behavior

- [ ] New file `YardKit/Sources/YardGit/SignatureVerification.swift`. Create it; do not restructure existing files.
- [ ] Reports format (SSH or GPG), signer identity, and a clear verified/unverified/absent state.
- [ ] Honors `gpg.ssh.allowedSignersFile` for SSH verification.
- [ ] An unsigned commit is reported as "no signature", distinct from "signature failed to verify".
- [ ] Skips GPG paths cleanly when `gpg` is absent rather than reporting a failure.
- [ ] Exit code 9 reserved for signing failures, not verification results.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. `swift test`'s summary line counts only swift-testing tests, so an XCTest file passes invisibly.
- [ ] `cd YardKit && swift build` succeeds, and `swift test` prints a `Test run with N tests` line you paste. N must be greater than the count on `main` before this change.

## Notes

Guide §5 "Signing implementation" and §6. Blocked by #0002, #0011.

The three-state distinction matters: an agent treating "unsigned" as "invalid" would reject most
real repositories.
