## Description

The user-facing journal commands. Undo restores a snapshot rather than computing an inverse
operation, which is precisely why it works for rebases and merges where an inverse is ill-defined.

`yard journal` must report per entry what was captured and whether it is still undoable, so an agent
can tell before acting whether undo is available.

## Expected behavior

- [ ] `checkpoint [label]` returns a checkpoint id; `restore <checkpoint>` jumps to it.
- [ ] `undo [--steps N]` and `redo [--steps N]` traverse entries in order.
- [ ] `journal` reports operation, timestamp, worktree, `captured`, and undoable state per entry.
- [ ] Undo reports honestly what it could not restore, based on `captured`.
- [ ] Redo after undo returns to the exact post-operation state.
- [ ] All paths run the guard (#0031) before writing.
