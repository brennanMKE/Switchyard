## Description

The link that makes `switchyard <anything>` reach the app: the CLI hands its argv and working
directory to the running app, the app runs the command, and the CLI prints the bytes it gets back and
exits with the code it is given. Guide §11 decision 15 settles the wire; this issue builds it.

**No engine yet.** The app executes `runYard(arguments:)` — the existing `YardKit` dispatcher, which
today knows `--help`, `--version`, `schema` and `noop`. That is deliberate: it makes the round trip
provable with a command whose output is already pinned by tests, before any repository work is in the
picture. Wiring the first engine-backed command is #0124, and the `YardCommands` target it needs is
part of that issue.

## Givens — verify each against the branch, they were read on `main` 2026-08-17

1. `runYard(arguments:) -> (stdout: String, stderr: String, exitCode: ExitCode)` lives in
   `YardKit/Sources/YardKit/CommandLineRunner.swift`.
2. `ExitCode` is `public enum ExitCode: Int, Sendable` — `Int`, so crossing an `@objc` boundary as
   `Int32` needs an explicit conversion in both directions, and an unrecognized value must map to
   something rather than trapping.
3. `AppServiceProtocol` and `XPCInterfaces.appService` landed with #0048, and the app exports an
   `AppService` implementing them (#0215, `Switchyard/AppXPCServer.swift`). Both are on `main`.
4. `Sources/switchyard/main.swift` is the executable; it may not be `@testable import`ed, so
   everything worth testing goes in `YardKit`.

## Expected behavior

- [ ] `AppServiceProtocol` gains `perform(arguments:workingDirectory:reply:)` with exactly the
      signature in guide §11 decision 15. `Data` and `Int32` — `NSXPCInterface` will not carry a Swift
      enum.
- [ ] The app's exported object implements it by calling `runYard`, and returns
      `stdout.data(using: .utf8)` with `Int32(exitCode.rawValue)`.
- [ ] The CLI writes the returned bytes to stdout **unmodified** — no re-encoding, no
      pretty-printing, no trailing newline it did not receive. A JSON envelope that survives the
      round trip byte-for-byte is the criterion; assert it as bytes, not as a decoded object.
- [ ] stderr is carried too, or the issue says explicitly why it is not. `runYard` returns it, so
      dropping it silently would be a decision made by omission.
- [ ] An exit code the app returns that is not a known `ExitCode` maps to `requestFailed` (4) rather
      than trapping on `ExitCode(rawValue:)!`.
- [ ] Tests stand up an **in-process** `NSXPCListener.anonymous()` exporting the same object the app
      exports, connect to it, call `perform`, and compare the bytes against `runYard`'s own output for
      the same argv. Measured during #0048's planning: an anonymous listener round-trips to itself in
      one process, so this needs no app, no broker and no launchd registration.
- [ ] `cd YardKit && swift test` prints `Test run with N tests` where **N is greater than 949**, the
      count on `main` measured 2026-08-17 at dispatch.

## Notes

Guide §4, §5, §11 decision 15. **Blocked by #0215.**

Do not add per-command payload types — #0194 is unanswered and this design is what makes it not block
the CLI.

## Work log

- **Round 1 — 2026-08-17, Sonnet subagent, 117,382 tokens, 7m23s, rejected on coverage.** The wire,
  the app side, the client side, `ExitCode(fromAppReply:)` and four tests. Its own second mutation is
  worth keeping in mind: force-unwrapping `ExitCode(rawValue:)` killed the whole test process with
  signal 5 and produced **no suite line at all** — worse than a red test, and exactly what the
  fallback exists to prevent.
- **The rejection.** `FakeAppService.perform` **reimplemented** `AppService.perform`, so the test
  proved the fake and the client agreed. Mutating the real app-side method — trimming its stdout —
  left `swift test` green at 18/18, because the package suite never builds the app target. Logged as
  a failure class and as preflight check 0c.
- **Round 2 — 135,328 tokens, 3m41s, accepted.** `performCommand(arguments:workingDirectory:)` in
  `CommandLineRunner.swift` is now the single body; `AppService.perform` is a two-line forwarder and
  the fake calls the same function. **No new tests** — the point was to make the existing ones
  exercise the shipped code.
- **Review.** 964 green, app builds unsigned, and my own mutation on `performCommand` (append a
  newline) reddens all four round-trip cases with byte counts one apart.
- **Deferred, with the reasoning accepted:** `main.swift` still calls `runYard` directly. Routing
  every invocation through the app before an app is installed would break `--help` and `--version`
  today. **Folded into #0124**, which is the first command that cannot be answered locally, together
  with the rule that the local/remote split is derived from what `runYard` knows rather than a second
  list of command names.
- **stderr is not carried**, deliberately: decision 15 pins the reply to `(Data, Int32)`, and the two
  cases where `runYard` sets stderr format it from the same `EnvelopeFail` already present in the
  stdout envelope. Recorded here so it is a decision rather than an omission.
