## Description

**M1 exit criterion served (guide §9, criterion 5):** "every engine function has tests that can
fail: each has a mutation recorded against a named test that dies under it."

Found by the M1 milestone review, 2026-08-07. `worktreeList`
(`YardKit/Sources/YardGit/WorktreeList.swift`) has **no behavior mutation tied to a named test**
anywhere in `issues/`:

- #0020's one recorded mutation (the `-z` separator) crashed the suite with `Index out of range`
  (signal 5) rather than failing a test — a crash is a trap, not a red assertion, and the M1
  criterion distinguishes them.
- #0095's work log records "mutating `worktreeList` to return `[]` fails the suite in ten places" —
  a count, no names.
- #0130's named tests (`worktreeEntryFullValueEncodesToTheLiteralWireShape`, …) pin `WorktreeEntry`'s
  encoding, not the porcelain parse.

## Expected behavior

At least one real mutation of the porcelain parsing in `worktreeList` (e.g. a field mis-parse, not
a crash) is applied, the named test in `YardKit/Tests/YardGitTests/WorktreeListTests.swift` that
dies under it is recorded in this issue's work log, and the mutation is reverted. If the `-z`
mutation can only crash rather than fail an assertion, add a test that turns that failure mode into
a red assertion and record it.

## Mutations recorded — run by the reviewer 2026-08-07

Applied to `YardKit/Sources/YardGit/WorktreeList.swift`, full suite run each time, file restored, tree
verified clean. Verdicts come from the `Test run with N tests` summary line, never from whether a name
was extracted.

| # | mutation | verdict | named test(s) that died |
|---|---|---|---|
| L1 | the `locked` flag line never matches | **RED** | `lockedWorktreeWithoutReasonShowsBareLocked` |
| L2 | the `prunable` flag line never matches | **GREEN** | none — see below |
| L3 | stop stripping the `refs/heads/` prefix | **RED** | `fullRefNameMatchesShortName`; `branchHeldBySiblingIsRefusedNamingTheHolder`; `branchHeldByTheMainWorktreeReportsIsMain`; `mainWorktreeReportedFromLinked`; `newBranchWorktreeIsCreatedAndListed`; `ownWorktreeReportsIsCurrent`; `populateFalseLeavesOnlyDotGit`; `siblingHoldsBranch` |

**The criterion is met by L1**, which is a clean one-mutation/one-named-test pairing. #0020's original
mutation crashed with `Index out of range` rather than failing an assertion, and the criterion
distinguishes a trap from a red test — L1 supplies the red test.

L3 is worth keeping in the record for the same reason #0142's R2 was: it kills eight tests across
worktree creation, removal and identity, because the short-branch-name form is what every one of them
compares against.

## The finding: the `prunable` flag's parsing is untested

L2 blanks the `prunable` branch and **nothing fails**. `prunable` and `prunableReason` are pinned on
the wire by #0130 — but from *constructed* values, not from parsed porcelain, so no test drives
`worktreeList` against real `git worktree list --porcelain` output containing a `prunable` line.

That is a coverage hole inside a function whose criterion is otherwise met, so it is filed separately
rather than stretched into this issue.
