## Description

**M1 exit criterion served (guide §9, criterion 5):** "every engine function has tests that can
fail: each has a mutation recorded against a named test that dies under it."

Found by the M1 milestone review, 2026-08-07. `worktreeList`
(`YardKit/Sources/YardGit/WorktreeList.swift`) has **no behavior mutation tied to a named test**
anywhere in `issues/`:

- #0020's one recorded mutation (the `-z` separator) crashed the suite with `Index out of range`
  (signal 5) rather than failing a test — a crash is a trap, not a red assertion, and the M1
  criterion distinguishes them.
- #0095's work log records "mutating `worktreeList` to return `[]` fails the suite in ten places" —
  a count, no names.
- #0130's named tests (`worktreeEntryFullValueEncodesToTheLiteralWireShape`, …) pin `WorktreeEntry`'s
  encoding, not the porcelain parse.

## Expected behavior

At least one real mutation of the porcelain parsing in `worktreeList` (e.g. a field mis-parse, not
a crash) is applied, the named test in `YardKit/Tests/YardGitTests/WorktreeListTests.swift` that
dies under it is recorded in this issue's work log, and the mutation is reverted. If the `-z`
mutation can only crash rather than fail an assertion, add a test that turns that failure mode into
a red assertion and record it.
