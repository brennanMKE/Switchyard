# 0148 — worktreeList never parses a real prunable line

## Description

Found while recording #0143's mutations. Blanking the `prunable` branch in
`YardKit/Sources/YardGit/WorktreeList.swift` — so a `prunable` porcelain line never matches — leaves
the **entire suite green**.

`prunable` and `prunableReason` are pinned on the wire by #0130, but from **constructed**
`WorktreeEntry` values. No test drives `worktreeList` against real `git worktree list --porcelain`
output containing a `prunable` line, so the parsing of that flag is unverified even though its
encoding is not.

`FixtureRepository` can produce a genuinely prunable worktree — delete the working directory and the
administrative entry becomes prunable, which is what `WorktreePrune`'s own tests already rely on.

## Expected behavior

- [ ] A test drives `worktreeList` against a repository containing a real prunable worktree and
      asserts `prunable == true` plus the `prunableReason` git actually emits.
- [ ] Blanking the `prunable` branch in the parser turns that test **red**, recorded as a mutation row
      naming the test.
- [ ] Tests use swift-testing — `import Testing`, `@Test`, `#expect` — are `throws`, and use `try`,
      never `try!`.
- [ ] New tests go in `YardKit/Tests/YardGitTests/`.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line you paste, and N exceeds the
      branch's own pre-change baseline. State the criterion as a delta; absolutes go stale within the
      hour on this project.
