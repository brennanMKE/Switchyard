## Description

Found while recording #0143's mutations. Blanking the `prunable` branch in
`YardKit/Sources/YardGit/WorktreeList.swift` — so a `prunable` porcelain line never matches — leaves
the **entire suite green**.

`prunable` and `prunableReason` are pinned on the wire by #0130, but from **constructed**
`WorktreeEntry` values. No test drives `worktreeList` against real `git worktree list --porcelain`
output containing a `prunable` line, so the parsing of that flag is unverified even though its
encoding is not.

`FixtureRepository` can produce a genuinely prunable worktree — delete the working directory and the
administrative entry becomes prunable, which is what `WorktreePrune`'s own tests already rely on.

## Expected behavior

- [ ] A test drives `worktreeList` against a repository containing a real prunable worktree and
      asserts `prunable == true` plus the `prunableReason` git actually emits.
- [ ] Blanking the `prunable` branch in the parser turns that test **red**, recorded as a mutation row
      naming the test.
- [ ] Tests use swift-testing — `import Testing`, `@Test`, `#expect` — are `throws`, and use `try`,
      never `try!`.
- [ ] New tests go in `YardKit/Tests/YardGitTests/`.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line you paste, and N exceeds the
      branch's own pre-change baseline. State the criterion as a delta; absolutes go stale within the
      hour on this project.

## Planning update — 2026-08-08, authored in-context, facts measured

### Given 1 — the porcelain line git actually emits

Built in a scratch repo: add a worktree, `rm -rf` its directory, then
`git worktree list --porcelain`:

```
worktree /…/gone
HEAD ba9e2a8b074a3a2233eb64905833f34f15efa451
branch refs/heads/gone
prunable gitdir file points to non-existent location
```

So the reason string is **`gitdir file points to non-existent location`**, and the line is the
`prunable <reason>` form — not the bare `prunable` form. Both branches exist in the parser
(`WorktreeList.swift:150` and `:152`); **only the reason-bearing one is reachable this way**, which
is worth stating so a round does not "fix" the bare branch to make a mutation bite.

### Given 2 — production reads NUL-terminated porcelain

`worktreeList` passes `-z` (pinned by `parserUsesNulTerminatedPorcelain`). The `prunable` line is
unchanged by that; only the record separator differs.

### Given 3 — the fixture already supports this

`FixtureRepository.addWorktree(named:branch:)` returns the worktree URL, and `WorktreePrune`'s tests
already make a worktree prunable by removing that directory. No new fixture support is needed.

## Change 1 — `YardKit/Tests/YardGitTests/WorktreeListTests.swift`, append one test

Append **inside** the `WorktreeListTests` struct — not at file scope. A round appended after the
closing brace earlier today and the target did not compile while still reporting success.

```swift
    // MARK: - The prunable flag (#0148)

    /// #0130 pins `prunable`/`prunableReason` on the wire, but from
    /// CONSTRUCTED `WorktreeEntry` values. Nothing drove the parser against
    /// real porcelain carrying a `prunable` line, so blanking that branch left
    /// the entire suite green — encoding verified, parsing not.
    ///
    /// Measured: removing a worktree's directory makes git report
    /// `prunable gitdir file points to non-existent location`. That is the
    /// reason-bearing form; the bare `prunable` branch is not reachable this
    /// way and is deliberately not asserted here.
    @Test func parserReadsARealPrunableLineAndItsReason() throws {
        var repo = try FixtureRepository.linear()
        defer { repo.destroy() }
        let gone = try repo.addWorktree(named: "gone", branch: "gone-branch")
        let alive = try repo.addWorktree(named: "alive", branch: "alive-branch")
        defer { try? FileManager.default.removeItem(at: alive) }

        // Make it genuinely prunable, and prove the wreck took effect: git
        // must actually report the flag, or this test passes on a healthy
        // worktree and asserts nothing.
        try FileManager.default.removeItem(at: gone)
        #expect(try git.run(["worktree", "list", "--porcelain"],
                            workingDirectory: repo.url.path).text.contains("prunable"))

        let entries = try worktreeList(path: repo.url.path)
        let pruned = try #require(entries.first { $0.path == gone.path })
        #expect(pruned.prunable)
        #expect(pruned.prunableReason == "gitdir file points to non-existent location")

        // The surviving worktrees must not be marked prunable — a parser that
        // sets the flag unconditionally would otherwise pass everything above.
        let others = entries.filter { $0.path != gone.path }
        #expect(!others.isEmpty)
        #expect(others.allSatisfy { !$0.prunable && $0.prunableReason == nil })
    }
```

`gone.path` may need `.resolvingSymlinksInPath()` on macOS if `/private` vs `/var` differs between
the fixture URL and git's output — **the round must check and say so** rather than loosening the
comparison to `contains`.
