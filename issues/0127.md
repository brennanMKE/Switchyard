# 0127 — CommitLog reports a good signature as invalid

| | |
|---|---|
| **Status** | open |
| **Module** | YardGit |
| **Milestone** | M1 |
| **Platform** | macOS |
| **First seen** | 2026-08-07 |

## Description

`CommitLog.SignatureStatus` maps `%G?` backwards. A **good** signature is reported as `.invalid`, and
`.valid` is unreachable — git never emits the character it looks for.

`YardKit/Sources/YardGit/CommitLog.swift:19-20`:

```swift
case "g": self = .valid     // git never emits lowercase g
case "G": self = .invalid   // uppercase G is GOOD
```

The comments on the cases say the same thing — `case valid // %G? -> \`g\`` and
`case invalid // %G? -> \`G\`` — so the error is in the design of the type, not a typo at one site.

## Givens — verified 2026-08-07, treat as true

1. **Git's own source is authoritative and unambiguous.** `git/gpg-interface.c` sets
   `sigc->result` and the only values it assigns are uppercase:

   ```
   gpg-interface.c:417   sigc->result = 'B';
   gpg-interface.c:434   sigc->result = 'G';
   gpg-interface.c:439   sigc->result = 'G';
   gpg-interface.c:454   sigc->result = 'B';
   gpg-interface.c:669   sigc->result = 'N';
   ```

   `git/pretty.c:1662` is where `%G?` renders it. **There is no lowercase `g` anywhere in the
   mapping.**

2. The documented set, from `git log --help`: `G` good, `B` bad, `U` good but untrusted, `X` good but
   expired, `Y` good but the key expired, `R` good but the key was revoked, `E` cannot be checked,
   `N` no signature.

3. So `SignatureStatus` today: every good signature falls to `case "G": self = .invalid`, and
   `.valid` is dead code.

4. The file is `YardKit/Sources/YardGit/CommitLog.swift`. `SignatureStatus` is declared around line 8
   with `init(_ flag: String)` at 16 and `init(_ char: Character)` at 25. `CommitLogEntry` carries it
   as `signatureStatus`.

5. **No test catches this.** `FixtureRepository` presets `commit.gpgsign=false`, so every fixture
   commit is unsigned and lands on `N` — the one case the mapping gets right. Confirm by reading
   `YardKit/Tests/YardGitTests/CommitLogTests.swift`.

6. `main` reported **325** tests on 2026-08-07.

## Expected behavior

- [ ] `SignatureStatus` covers git's full documented set, with uppercase characters, and no case maps
      to a character git does not emit.
- [ ] A good signature reports as good. The doc comment on each case names the character git actually
      emits.
- [ ] `CommitLogEntry.signatureStatus` keeps its name and type position, so callers do not change.
- [ ] **The test file is a deliverable**: `git diff --name-only` lists source and test files.
- [ ] Tests use **swift-testing** — `import Testing`, `@Test`, `#expect`. Not XCTest. They go in
      `YardKit/Tests/YardGitTests/`; `Tests/YardGit/` is not a declared target path and a file there
      is silently never compiled.
- [ ] `cd YardKit && swift test` prints a `Test run with N tests` line you paste, greater than the
      branch's own pre-change baseline, which you also paste.

## Tests must be able to fail

**Do not create a signing key.** Signing assets are off limits (CLAUDE.md) — no `ssh-keygen`, no gpg
generation, no keychain writes. That is not a limitation here: the mapping is a pure function from a
character, so test it directly.

Assert the whole documented set, one case per character: `G`, `B`, `U`, `X`, `Y`, `R`, `E`, `N`, and
an unrecognised character. **Name the expected case for each explicitly** — a loop that only checks
"some case came back" would pass on today's inverted mapping.

**Run these mutations and report each with the test that fails:**

| # | mutation | required |
|---|---|---|
| 1 | restore `case "g": self = .valid` / `case "G": self = .invalid` | the `G` test FAILS |
| 2 | map every unrecognised character to the good case | the unrecognised test FAILS |
| 3 | map `U` to the same case as `G` | the `U` test FAILS — "good but untrusted" is not "good", and #0108 encodes exactly that distinction for SSH |

Restore after each and confirm the suite is green and `git diff` is unchanged.
