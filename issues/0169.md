## Description

Undo and redo: traverse the chain (#0166) by restoring through #0168, writing the traversal
record that moves the cursor. The engine behind `undo [--steps N]` and `redo [--steps N]`; the
verbs are M3.

**Structured stub, split from #0034 on 2026-08-08.** Re-authored to code level at its own
planning pass before dispatch, per CLAUDE.md. The design below is #0034's, binding.

## The design — bound by #0034 (Decision 2)

`YardKit/Sources/YardGit/JournalUndo.swift`, shape to be finalized at the planning pass:

```swift
public enum JournalUndo {
    public enum Error: Swift.Error, Equatable, CustomStringConvertible, Sendable {
        case nothingToUndo
        case nothingToRedo
    }   // ExitClassCarrying → .repositoryError (6)

    @discardableResult
    public static func undo(steps: Int = 1, in context: WorktreeContext,
                            git: GitProcess = GitProcess()) throws -> [JournalRestore.Report]
    @discardableResult
    public static func redo(steps: Int = 1, in context: WorktreeContext,
                            git: GitProcess = GitProcess()) throws -> [JournalRestore.Report]
}
```

Each step, recomputed fresh (the previous step appended an entry):

1. `JournalAnchor.list` + metadata decode (#0155) → `JournalChain.Node`s (traversal iff the
   metadata carries the `traversal` field — #0034 Decision 7) → `JournalChain.state(of:)`.
2. Undo: `state.undoTarget` or throw `nothingToUndo`. Restore it via
   `JournalRestore.restore(target, operation: "undo",
   traversal: Traversal(restored: target, resultingPosition: target))`.
3. Redo on `state.redoTarget`: `.entry(T)` → restore T with
   `Traversal(restored: T, resultingPosition: T)`; `.present(capturedBy: F)` → restore **F** (a
   traversal entry — its snapshot is the captured present) with
   `Traversal(restored: F, resultingPosition: nil)`; nil → throw `nothingToRedo`.
4. "Redo after undo returns to the exact post-operation state" (#0034's honesty line) holds
   because step 3's `.present` arm restores the bytes the run's first undo captured.

Locking: each step runs inside `JournalLock.withLock` (#0032). The planning pass decides whether
`steps: N` holds one lock across all steps (preferred: one acquisition, no interleaving window)
and measures nothing new — every primitive is already verified by its own issue.

## Expected behavior (to be authored to code level)

- [ ] `YardKit/Sources/YardGit/JournalUndo.swift`: the flow above; `Error` conforms to
      `ExitClassCarrying`; every process call through `GitProcess`.
- [ ] End to end against a real repository, both ref formats: checkpoint → move a branch →
      undo → refs match the checkpoint; redo → refs match the pre-undo state **exactly**
      (`RefSnapshot.capture` equality on both hops).
- [ ] Two undos then one redo land where #0166's semantics say (cursor mid-chain; the listing's
      chain state confirms).
- [ ] Undo past the oldest entry throws `nothingToUndo`; redo at present throws `nothingToRedo`;
      a checkpoint after an undo makes redo throw (logical truncation).
- [ ] `steps: 2` equals two single steps (same final `RefSnapshot.capture`).
- [ ] `YardKit/Tests/YardGitTests/JournalUndoTests.swift` gains the tests; the diff lists
      exactly two files.
- [ ] `swift test` prints a `Test run with N tests` line; N must exceed the branch's pre-change
      count by the exact delta the planning pass states.
- [ ] A mutation table, every row applied and observed red with the killing test named — one row
      must swap the `.present` arm to restore the run's newest traversal instead of its first,
      killed by the exact-post-operation-state test.
