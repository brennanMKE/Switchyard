# 0053 — Audit XPC callback closures for @Sendable under MainActor isolation

| | |
|---|---|
| **Status** | in-progress |
| **Module** | Switchyard / YardKit |
| **Milestone** | M3 |
| **Platform** | macOS |
| **First seen** | 2026-08-06 |

## Description

`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` is already set on the app target. Objective-C callback
closures that the XPC framework invokes off the main queue — `remoteObjectProxyWithErrorHandler`,
`interruptionHandler`, `invalidationHandler` — must be marked `@Sendable`, or they inherit
main-actor isolation and **crash with `SIGTRAP` at runtime with no compiler warning**.

This was one of the two most expensive defects in RemoteControl and it is invisible to a passing
build and a successful happy-path test. It only appears on the failure path.

## Expected behavior

- [ ] Every XPC callback closure audited and marked `@Sendable` where the framework calls it off-main.
- [ ] Pure helpers marked `nonisolated` so they stay unit-testable.
- [ ] The failure path is **deliberately triggered** — kill the app mid-request and confirm the error handler runs without a crash.
- [ ] Same for `interruptionHandler` and `invalidationHandler`.

## Planning update — 2026-08-17. Make it a standing guard, not a one-time audit.

An audit is a fact about the tree on the day it was run. This defect returns every time someone writes
a new XPC callback, it is invisible to the compiler, and it only fires on the failure path — so the
deliverable is **a test that fails when the annotation is missing**, plus the audit that test's first
run performs.

### What exists to audit, as of 2026-08-17

- `Switchyard/AppXPCServer.swift` — three annotated closures (#0047): the
  `remoteObjectProxyWithErrorHandler` error handler, `interruptionHandler`, `invalidationHandler`.
- `BrokerAgent/main.swift` — the broker's own listener delegate and connection handlers (#0045/#0046).
- `YardKit/Sources/YardKit/XPCProtocols.swift` — reply closures in the `@objc` protocols, already
  `@escaping @Sendable` in their declarations.
- Whatever #0048 lands in `YardKit/Sources/YardKit/{Broker,App}Connection.swift`.

**Dispatch this after #0048 and #0215 merge**, so the guard covers the whole surface on its first run
rather than being extended twice.

### The guard — `YardKit/Tests/YardKitTests/XPCSendableTests.swift`

Source-scanning tests already exist in this target: `LayeringTests` walks `Sources/**` with
`listSwiftFiles(recursive:at:)` and asserts on the text of each line. Copy that shape — including the
`#expect(!swiftFiles.isEmpty, …)` guard, without which the loop passes vacuously on a path typo.

Scan **`Sources/YardKit`, `Switchyard/`, and `BrokerAgent/`** — note the last two are outside the
package, reached by walking up from `#filePath` to the repository root, so the test must tolerate
their absence rather than fail when the package is built standalone. State which behaviour you chose.

For each occurrence of `remoteObjectProxyWithErrorHandler`, `interruptionHandler`,
`invalidationHandler`, `exportedObject`-bearing `shouldAcceptNewConnection`, or a `reply:` closure
literal, require `@Sendable` on the closure. A pragmatic matcher: find the line containing the
trigger, then require `@Sendable` within that line or the next one — closures here are written
`{ @Sendable [weak self] in`, so the annotation is adjacent by convention.

**The matcher must be tested against a known-bad string**, not only against the tree. Feed it a
literal snippet with the annotation removed and assert it reports a violation; otherwise a matcher
that never matches anything passes forever. That is the exact vacuity class `AGENTS.md` Rule 7 names.

### The runtime half stays manual, and that is #0054's job

Criteria 3 and 4 — kill the app mid-request, restart the broker under it, confirm the handlers run
without `SIGTRAP` — cannot be done from `swift test`: they need a built app, a registered launch agent,
and two live processes. **Do not fake them.** Write them as named scenarios in #0054's script and say
in the report that they are covered there rather than here.

`nonisolated` on pure helpers (criterion 2) is checked by eye during the audit; there is no sensible
source-level rule for "this helper should have been nonisolated", and inventing one would produce
noise rather than a guard.
