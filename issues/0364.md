## Description

**Child of #0358, split 2026-09-12.** One deliverable: the History pane's two loaders read every
local and remote-tracking branch, in the same topological order. Until this lands nothing else in
#0358 can show topology, because only `HEAD`'s history is loaded.

*Measured* facts below were run on 2026-09-12 against `main` at `2d96d3e` with git 2.50.1; the text
is moved verbatim from #0358's first planning update.

### Root cause

1. **Only `HEAD` is loaded.** `loadCommitHistory` passes `["-100", "HEAD"]` and `loadCommitGraph`
   calls `graphRows(at: path, limit: 100)`, whose `revisions` default is `["HEAD"]`
   (`YardKit/Sources/YardUI/RepositoryLoader.swift`, `YardKit/Sources/YardGit/LaneAssignment.swift`).
   *Measured* on Batty (`/Users/brennan/Developer/brennanMKE/Batty`): 1 merge commit among the 1,182
   reachable from `HEAD`; of the first 100 of `git rev-list --topo-order HEAD --branches --remotes`,
   **68 are not reachable from `HEAD`**. Branches are squash-merged, so a `HEAD`-only walk is a
   straight line no matter how well the gutter draws.
2. **The two loaders disagree on order once widened.** `CommitLog` runs `git log` in its default
   order; `graphRows` is `--topo-order`. *Measured* with `HEAD --branches --remotes`, 100 rows:
   **48 row positions differ on Batty, 19 on Switchyard.** With `--topo-order` on both: **0 differ
   on both repositories.** `CommitHistoryView` iterates `entries` and joins `GraphRow` by oid, so a
   mismatch draws edges between the wrong rows.
### Loader change

```swift
// YardKit/Sources/YardUI/RepositoryLoader.swift, loadCommitHistory — body
try await CommitLog.run(path: path, rangeArguments: ["--topo-order", "-100", "HEAD", "--branches", "--remotes"])

// loadCommitGraph — body
try await graphRows(at: path, limit: 100, revisions: ["HEAD", "--branches", "--remotes"])
```

Tags are deliberately not walked (`--tags` would open lanes for old release tags). `graphRowsArguments`
already emits its `--exclude=refs/switchyard/*` and review-notes excludes *before* `revisions`, so
the journal's own refs stay out. Update both doc comments, which currently say "reachable from
`HEAD`". Test: a fixture with an unmerged side branch — both loaders return the **same oid
sequence** and it includes the side commit. (`FixtureRepository`'s API is not pasted here; read
`YardKit/Sources/YardGit/FixtureRepository.swift`.)
