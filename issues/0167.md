## Description

The checkpoint flow: capture the repository's current state and write it as one journal entry —
the engine behind `checkpoint [label]`, and the primitive every restore-class flow (#0168, #0169)
calls to write its own pre-mutation entry. The verbs are M3; this is the engine function only.

**Structured stub, split from #0034 on 2026-08-08.** Re-authored to code level at its own
planning pass before dispatch, per CLAUDE.md. The design below is #0034's, binding; the facts
cited were measured at the passes named.

## The design — bound by #0034

`YardKit/Sources/YardGit/JournalCheckpoint.swift`, shape to be finalized at the planning pass:

```swift
public enum JournalCheckpoint {
    /// Captures current state and writes one journal entry, returning it.
    /// `traversal` is non-nil exactly when undo/redo is writing the entry
    /// (#0034 Decision 7 — kind is decided by the field, not the string).
    @discardableResult
    public static func checkpoint(
        operation: String,                       // "checkpoint", "commit", "restore", "undo", …
        label: String? = nil,
        traversal: JournalChain.Traversal? = nil,
        in context: WorktreeContext,
        git: GitProcess = GitProcess()
    ) throws -> JournalAnchor.Entry
}
```

The flow, in order, inside `JournalLock.withLock` (#0032):

1. `RefSnapshot.capture(in:)` (#0027, merged) → `serialized()` (#0165) →
   `git hash-object -w --stdin` via `GitProcess` → the `refsBlob` oid.
2. `JournalEntryID.generate(after: newest existing id)` (#0028 — pass the newest id from
   `JournalAnchor.list` so same-millisecond writes still ascend).
3. Metadata (#0155) with `captured: { refs: true, head: true, index: false, worktree: false,
   untracked: false }` — **honest about the refs-only reality until #0171 flips them** — plus
   `label` and `traversal` (#0034 Decision 7's two #0155 additions).
4. `JournalAnchor.write(Contents(metadataJSON:refsBlob:keepAlive:), id:in:)` (#0028).

## The open planning question — keep-alive parents (#0028 decision 8 defers here)

The snapshot commit's parents keep captured history reachable. #0028 measured: git deduplicates
parents (warning, exit 0) and rejects a non-commit parent (`fatal`, exit 128). An annotated tag's
`for-each-ref` oid is the **tag object**, not a commit — so `keepAlive` cannot be "every captured
oid" verbatim. The planning pass must measure and decide:

- Peeling: `for-each-ref --format='%(objectname) %(*objectname)'` for the commit behind each tag,
  or `rev-parse <oid>^{commit}`; behavior for tags pointing at blobs/trees.
- Whether a gc'd tag *object* (unreachable after the tag ref was deleted post-capture) makes the
  restore transaction fail atomically, and how the failure surfaces (measured, not assumed).
- Deduplication scale: hundreds of refs on one tip is one parent, measured via git's own dedup or
  pre-deduped in Swift.
