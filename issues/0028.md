# 0028 — Implement journal anchor refs and entry metadata

## Description

Objects unreferenced by any ref are garbage. Every snapshot writes `refs/switchyard/journal/<entry-id>`
pointing at the snapshot commit, which keeps the whole snapshot reachable and survives `git gc` and
`git maintenance`.

`refs/switchyard/` rather than anything under `refs/heads` or `refs/tags` so entries never appear in
branch listings and are never pushed by a default refspec. They *will* appear in `git for-each-ref`,
so `yard`'s own ref enumeration must filter them — including in `yard graph` and `yard whereami`.

Entry metadata (operation, command, timestamp, worktree, what was captured, guard values, agent
session) goes in `.git/switchyard/journal.json`.

## Expected behavior

- [ ] Anchor ref written per entry; snapshot survives an aggressive `git gc` — asserted by a test.
- [ ] Entry shape matches git internals §3, including `captured` and `guard`.
- [ ] `yard`'s ref enumeration filters `refs/switchyard/*` everywhere it lists refs.
- [ ] A default `git push` does not push journal refs — asserted against a scratch remote.
- [ ] Entry ids are sortable by creation order.

## Notes

Git internals §3 "Anchoring" and "Entry shape". Blocked by #0027.

`captured` is what lets `undo` report honestly what it can and cannot restore. `guard` is what makes
it safe. Both are load-bearing, not decoration.
