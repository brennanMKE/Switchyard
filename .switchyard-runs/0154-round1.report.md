Add the hook reference-transaction CLI arm

## The arm

`HookArm` (new `YardKit/Sources/YardKit/HookArm.swift`) implements
`switchyard hook <handler> <state> …` — the process #0041's installed script
execs (`HookInstall.script(for:)` runs `switchyard hook ref-txn "$@" <payload>`
with output discarded and `|| :`; the real handler name is `ref-txn`, per
`ObservedHook.handlerName`).

- **Local routing.** `hook` joined `localCommandNames`; it is NOT in
  `CommandRegistry.all`. `route(["hook", …])` classifies `.local` via
  `isAnsweredLocally`, so it never takes the remote path.
  `dispatch` (new injectable `connectHook`, defaulting to
  `AppConnection.connect(launchIfNeeded: false)`) intercepts `hook` before the
  pure `runYard`; `runYard` keeps a `hook` case that refuses stray remote
  requests with a usage envelope. No remote connector runs for it.
- **Gate before stdin.** `HookArm.gate(arguments:environment:markerVariable:
  readStandardInput:)` is pure: handler must be `ref-txn`, then the state
  argument is checked (missing → `.refused`, non-`committed` → silent
  `.nothingToRecord`), then the marker check (present non-empty → own
  transaction → `.nothingToRecord`), and only `.forward` drains stdin —
  #0042's closure contract at the process boundary. Refusals are logged on
  stderr and exit 0.
- **XPC (decision 22).** `.forward` connects with `AppConnection.connect
  (launchIfNeeded: false)` — a background `git fetch` must never launch the
  GUI — then `performReferenceTransactionHook(state:environment:
  standardInput:workingDirectory:)`, and exits 0 in every case: unreachable
  app, timeout, garbage stdin, missing state. The app's replied code is never
  trusted as the process exit.
- **Timeout — a judgement, not a measurement: 2 seconds**
  (`HookArm.appTimeout`). The app-side body shells out to git (context
  resolve + observed-entry write), so the bound must sit above that; 2 s is an
  order of magnitude above it, negligible next to anything a human notices,
  and an unreachable app never reaches it (mach-layer connect fails ~0 ms,
  measured in #0048; `broker.appEndpoint` replies instantly when no app has
  registered). The ~8 ms spawn (#0043 Givens 5) still dominates.
- **The consequence, documented in the type comment:** ref transactions while
  Switchyard.app is closed are NOT journalled — decided knowingly (decision
  22), so it does not read as an oversight.

## Protocol extension

`AppServiceProtocol` gained `performReferenceTransactionHook(state:
environment:standardInput:workingDirectory:reply:)` (no hook method existed;
both sides are in this repo). `AppConnection` gained the matching client call.
The app side (`Switchyard/AppXPCServer.swift`, now importing YardCommands)
forwards to `runReferenceTransactionHook` (new, in YardCommands — the
`performCommand` pattern: one body both sides run, package-testable): resolve
`WorktreeContext` from the hook's cwd, then `ReferenceTransaction.runHook`
(decide + `JournalObserved.record`, every persistence throw swallowed). Total:
0 for every input. The whole hook environment ships so the core re-derives
every gate itself; `ServiceNames.yardInvocationMarkerVariable` names the
marker CLI-side (YardKit cannot see `GitProcess.markerVariable`), and
`YardWireTests/HookMarkerAgreementTests.swift` pins the two equal across the
layering boundary.

## Real-hook tests (`YardGitTests/HookProcessTests.swift`)

`swift test` builds the `switchyard` executable; the harness resolves it from
`#filePath` (package root `.build/debug/switchyard`, `try #require`d to
exist), symlinks it into a unique bin dir under the package's `build/`, and
prepends that dir to the environment git passes to hooks. Both ref formats
(`FixtureRepository.RefFormat.supported(git:)`): #0041's script installed
verbatim into the fixture's hooks dir, a foreign (empty-marker escape hatch)
commit exercises the full forward path inside the real chain, an own-marker
commit exercises the short-circuit; both commits succeed, `refs/heads/main`
exists, `rev-parse HEAD` resolves. A wrapper test runs the script via
`/bin/sh` with a stand-in `switchyard`, proving the script execs
`switchyard hook ref-txn committed` with the payload on stdin. Direct-binary
tests (no `|| :` masking): garbage stdin on `committed` → exit 0; missing
state argument → exit 0 with "missing state argument" on stderr; `prepared`
→ exit 0. Unit/wire coverage: `HookArmTests` (gate rows, reader-never-called,
dispatch routing — remote connector never invoked, hook connector exactly
once, timeout still exit 0), `AppConnectionTests
.performReferenceTransactionHookRoundTripsTheRequest` (state/env/stdin
byte-intact over a real anonymous XPC listener), `ReferenceTransactionHookTests`
(app-side body: foreign committed records exactly one observed entry; own,
non-committed, garbage, outside-a-repo → 0, nothing recorded).

## Mutations (run, killed, reverted byte-exact)

1. **Exit non-zero on unreachable app** — `HookArm.run`'s catch returned
   `.appUnavailable`. Killed by `HookProcessTests.garbageStdinOnCommittedExitsZero`
   (real binary, no app): `Expectation failed: (result.status → 3) == 0`.
   Reverted.
2. **Drain stdin before the state-argument check** — `_ = readStandardInput()`
   hoisted above the state guard in `HookArm.gate`. Killed by
   `HookArmTests.preparedNeverDrainsStdin`:
   `Expectation failed: (reader.callCount → 1) == 0`. Reverted.

## PostRewrite applicability

`PostRewrite` exists as a decision core (`decide`/`parse`, #0043) but
`PostRewrite.runHook` does not — and could not be added honestly here: the
persistence it must swallow throws from (#0160's machinery: attach own
mappings to the in-flight entry / record foreign ones) has no post-rewrite
recording path to compose with, only `JournalObserved.record(_ decision:)`
whose sole production caller is #0160's. Recorded **NOT APPLICABLE** for the
`PostRewrite.runHook` bullet; it lands with #0160. The exit-0 totality
invariant itself is implemented and tested for THIS arm at the process
boundary (mutations and tests above).
