## Layering decision (where the JSON encoding happens)

YardGit cannot import YardKit, so `ReviewNotes` takes the note body as an opaque JSON **string**;
`ReviewReply` → JSON (`sortedKeys`, the #0055 wire shape) happens in `reviewNoteBody(for:)` in
YardCommands' `runReviewRequest` body — the one site that sees both. Any reader decodes the note
back to a `ReviewReply` without YardGit.

## Exclusion pattern and CommitLog mechanism

Exclusion per site, following the established patterns: prefix `hasPrefix` guard inside
`RefSnapshot.listDirectRefs` (same shape as the `switchyardNamespace` guard), glob `--exclude=`
inside `graphRowsArguments` (same placement rule as the journal `--exclude`: precedes `--all`;
measured on git 2.50.1 that `rev-list --all` DOES traverse notes refs, so the flag is load-bearing).
CommitLog mechanism: the git-native `%N` placeholder + `--notes=<ns> --no-standard-notes` in the
existing single-invocation format string — chosen over a second `git log` subprocess (doubles
per-log cost, races HEAD). Measured quirks pinned in comments/tests: `notes add` stripspace appends
`\n` (avoided via `--no-stripspace`); `%N` appends one `\n` when the note doesn't end with one
(stripped exactly once in `parse`); `-F -` carries the body on stdin (large `editedPatch` never hits
argv limits); `notes show` is verbatim; `notes list` on an empty ref exits 0 empty.
