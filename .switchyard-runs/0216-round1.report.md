Show XPC transport status in the app

Files changed:
- YardKit/Sources/YardUI/TransportStatus.swift (NEW) — `AgentStatus` (a
  `nonisolated` CaseIterable enum mirroring SMAppService.Status's four cases
  with the exact label wording from #0049's vocabulary: "Not registered",
  "Requires approval", "Enabled", "Not found"), `TransportStatusModel`
  (@Observable, all values settable: machServiceName defaulting to
  ServiceNames.machServiceName, agentStatus, endpointRegistered,
  clientCount, plus an `@ObservationIgnored openLoginItems` action closure —
  the model has NO register() method at all), and `TransportStatusPane`
  (pure function of the model: monospaced selectable service name, status
  row with SF Symbol + tint, the "Open System Settings > Login Items" button
  ONLY when `showsApprovalButton`, endpoint row, client-count row).
- YardKit/Tests/YardUITests/TransportStatusTests.swift (NEW, 10 tests,
  imports YardUI and YardKit WITHOUT @testable) — all four agent states
  (exact labels, per-state button visibility, symbol names), endpoint
  registered vs not, zero vs several clients, model-updates-flow-through,
  the action closure is invocable, the default mach service name equals the
  real ServiceNames constant, and public-API construction of both
  TransportStatusPane and ContentView(transportStatus:).
- YardKit/Sources/YardUI/ContentView.swift — gained
  `public var transportStatus: TransportStatusModel?` and
  `public init(transportStatus: TransportStatusModel? = nil)` (so `ContentView()`
  still compiles for previews/tests); renders the pane as a bottom
  safeAreaInset DisclosureGroup only when a model is injected.
- Switchyard/TransportStatusBridge.swift (NEW, app target) — the adapter:
  `SMAppService.Status.transportStatus -> AgentStatus` mapping
  (@unknown default -> .notFound) and `TransportStatusBridge`, which owns
  the model, wires `openLoginItems` to AgentRegistrar.openLoginItemsSettings(),
  and refresh()s agentStatus from AgentRegistrar.status.
- Switchyard/AppDelegate.swift — owns `transportBridge` (explicit
  `override init()`; NSObject needed the override), refreshes after
  registerIfNeeded().
- Switchyard/SwitchyardApp.swift — `ContentView(transportStatus:
  appDelegate.transportBridge.model)`.

Design: value-driven model rather than a protocol — the issue allowed
either; values keep every state constructible in tests with no SMAppService
anywhere near, and the app-side bridge is the single adapter that maps the
real vocabulary onto it.

Client count: no count is exported by the app yet (grep of AppXPCServer.swift
and the whole tree found none — #0215's accounting is not in this tree), so
per the issue the model carries `clientCount` as a settable value. Live
wiring points documented on TransportStatusBridge.refresh(): endpointRegistered
is written where AppXPCServer.registerWithBroker() hands the endpoint over
(and false from the connection's invalidation handler); clientCount is
written by the accepted-connection accounting (#0213/#0215).

Tests: `swift test` from YardKit — "Test run with 1260 tests in 90 suites
passed after 75.053 seconds." EXIT:0. Baseline 1250 at dispatch; delta +10.
