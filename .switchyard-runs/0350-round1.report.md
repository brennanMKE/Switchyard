Refuse combined hunks with a typed error

Staging.swift: added `StagingError.combinedHunkNotStageable(path: String)` to
`StagingError`, description "hunk(s) of m.txt belong to a combined diff
(`diff --cc`) — a conflicted file is not stageable by hunk; resolve the
conflict, then stage the resolved content" (pinned exactly by a test, since
the string is what an agent parses). The check sits in `selectPatch`
(Staging.swift), which `stageHunksWithoutCheckpoint` and
`unstageHunksWithoutCheckpoint` both share: when a file with at least one
requested hunk has a `headerText` beginning `diff --cc `, it throws before
any patch text is assembled, so the refusal precedes `git apply` and is ours,
not git's. A combined file with none of its hunks requested is skipped
untouched; one combined id in a mixed request stages nothing at all. Exit
class is unchanged (`.repositoryError`) — this issue changed the error's
shape, not its §6 mapping; doc comments in Staging.swift and Unstaging.swift
updated to match.

Tests (YardKit/Tests/YardGitTests/StagingTests.swift):
- `conflictedFileIsVisibleButItsHunksCannotBeStaged` no longer asserts git's
  `GitProcess.Failure`; it now asserts `StagingError` equal to
  `.combinedHunkNotStageable(path: "m.txt")` for the single conflicted id,
  plus a mixed selection (conflicted + ordinary id) refused typed with the
  index untouched, and `exitClass == .repositoryError`.
- New `selectPatchRefusesACombinedBlockTypedInBothAreas`: pure, loops both
  `DiffArea.allCases` (count asserted first), because unstaging shares
  `selectPatch`. No fixture-backed unstage test exists because git never
  prints a combined block for the staged area (`* Unmerged path` instead) —
  noted in Unstaging.swift's doc comment.
- New `selectPatchTreatsAnOrdinaryDiffGitBlockAsStageable`: a realistic
  `diff --git` headerText still selects.
- `stagingErrorMapsToRepositoryError` extended with the new case's class and
  its exact description.

suites passed after 120.083 seconds" (run twice, before and after the
mutations; both green). Baseline on main is 1316, delta +2.

Mutations (each run, then reverted byte-exact; `git diff` shows no residue):
1. Removed the typed-refusal check from `selectPatch`. Killing test:
   `conflictedFileIsVisibleButItsHunksCannotBeStaged(format:)` — red with
   "an error was expected but none was thrown" at StagingTests.swift:216
   (both ref formats). Side finding: the call that failed was the MIXED
   selection, and git did not refuse it — without our check, `git apply`
   returned success on a mixed patch (it applied the ordinary part rather
   than refusing), so git's own exit 128 only guards the combined-only case.
   The pre-apply typed refusal is what actually preserves all-or-none.
2. Classifier prefix loosened to `diff --` so ordinary `diff --git` blocks
   count as combined. Killing test:
   `selectPatchTreatsAnOrdinaryDiffGitBlockAsStageable` — red, "Caught error:
   hunk(s) of f.txt belong to a combined diff …".

Not done: no change to the §6 exit class (still `.repositoryError` for the
whole enum, including the new case); no fixture-backed unstage refusal test
