## The Encodable finding

`SignatureVerification` is already `Encodable` with an explicit `CodingKeys` enum
(`state, format, signer, key`) plus hand-written `encode(to:)` for `State` (uniform `{code: …}`
frame, `reason` on `cannotCheck` only) and `Format` (declared case-name string). Nothing was
changed; `SigningWireTests` (#0136) already pins the bytes. Step 2 of the pattern is done.

## Argument-refusal rule

Tail is `Array(arguments.dropFirst())`. Valid is exactly one token with no `-` prefix. Empty tail,
two-plus tokens, or any `-`-prefixed token renders `EnvelopeFail(code: .usage, …)`, `[error] usage:`
on stderr, exit 1 — before any repository access, so the refusal is identical in an empty directory
and in a real fixture (test 2 asserts both).

## Exit-code-vs-verdict semantics

Exit 0 means the command ran; the `SignatureVerification` payload carries the verdict — an unsigned
or bad signature is a successful command. Thrown engine errors (not a repository, unresolvable
revision) map to `EnvelopeFail(code: .repositoryError)`, exit 6. `extraEnvironment` stays empty
from the CLI.

## Notes

- The result type has no oid field — its wire keys are exactly `state`/`format`/`signer`/`key` — so
  the issue's suggested "oid field matching `repo.oids["c"]`" assertion has nothing to bind to;
  test 3 instead asserts the engine-level unsigned values (`SignatureVerificationTests`:
  state `.noSignature` → wire `"noSignature"`, format `.none` → wire `"none"`, signer/key absent)
  and documents why no oid comparison exists.
- A nonexistent revision: the engine test `unknownRevisionThrows` pins that `run` throws
  `GitProcess.Failure`, so the arm maps it to exit 6 / `repository_error` — test 4 asserts that
  real behavior (there is no payload-status path for an unreadable revision).
- Test 6 pins both encodings: a fully-populated verification to exactly its four CodingKeys with
  values (`{"code":"good"}`, `"openpgp"`, signer, key), and a minimal one (nil signer/key) to
  exactly `["state", "format"]` — nils omitted, not null (#0129 Decision 4), the #0228 shape.
