**Resolver design**

Symlinks resolved first (`resolvingSymlinksInPath()`), then an upward walk of
the parent chain looking for a directory named `Contents`; at the first
`Contents` found it reads `Contents/Info.plist` (`CFBundleShortVersionString`,
plus `CFBundleVersion` in parentheses when the two differ) and returns. Any
failure past that point — no `Contents`, no plist, no short-version key —
falls back to the package version `YardKit.version`, never a crash or empty
string. The walk handles both `Contents/Resources/bin/` and `Contents/MacOS/`
depths; it does not hardcode the install path (which `noOtherSwiftSourceHardcodesTheIdentifiers`
would reject — it caught my first draft's doc comments and I reworded them).

**Which sites print a version**

`--version`/`-v` (plain text) and the bare-invocation envelope both route
through the resolver. The `schema`/help path prints no version line at all
(`renderHelp` emits name/summary/flags/exit codes; `runSchema` emits command
specs), so there was nothing to change there.

**Tests** (`swift test --filter VersionResolverTests`): `Test run with 8 tests

plist-without-short-version all fall back to `YardKit.version`.
