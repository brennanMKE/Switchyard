Add a non-blocking async path to GitProcess

## What changed

`GitProcess` (YardKit/Sources/YardGit/GitProcess.swift) gained async `capture` and
`run` overloads with the same signatures, errors and `Output` as the synchronous
entry points, which are unchanged. Construction is shared: the process/argv/
environment/stdout-pipe/stderr-file setup moved into a private `prepare()` used by
both paths, so the stderr-to-tempfile deadlock guard is one source of truth.

Async design:

- **Pipe draining** — stderr still goes to a temp file, so stdout is the only pipe.
  It is drained with `readabilityHandler` (Foundation's own queue), which receives
  empty data at EOF and is then nilled. stdin is written from a dedicated
  `Thread`, not the calling task, because a large payload can fill the pipe.
- **Completion** — requires BOTH stdout EOF and process exit (either can arrive
  last). Whichever event observes the second condition builds the `Output` and
  funnels it through a file-private `ResumeOnce<T>` (modeled on BrokerConnection's;
  YardGit cannot import YardKit), guaranteeing exactly one resume across the
  EOF/exit/timeout/cancel races; early events are stashed as a pending result and
  delivered on attach. Handlers are installed BEFORE `run()` — Foundation does not
  fire `terminationHandler` set after a fast child already exited.
- **Timeout** — a detached watchdog sleeps to the deadline, marks the deadline
  expired (which disables the success path), then runs the existing escalation:
  `terminate()` → `terminationGracePeriod` → `kill(pid, SIGKILL)`, reaps, and
  reports `Failure.timedOut` with the child's `terminationStatus` (15/9), as
  `waitWithDeadline` does synchronously. Without the deadline-expired mark, the
  killed child's exit+EOF could report success ahead of the watchdog — mutation 2
  below demonstrates exactly that.
- **Cancellation** — `withTaskCancellationHandler` terminates the child and resumes
  with `CancellationError`, plus a detached SIGTERM→SIGKILL escalation so a
  SIGTERM-trapping child cannot outlive the caller.

Engine twins (each shares its argument builder with the sync original or is a
probe-for-probe mirror pinned by a test): `WorktreeContext.resolve`,
`RefSnapshot.capture` (+ its two private helpers), `whereAmI` (shares
`countNULSeparatedPaths`, extracted from the sync body), `gitStatus` (shares
`gitStatusArguments`), `CommitLog.run` (shares `arguments(rangeArguments:)`),
`graphRows` (shares `graphRowsArguments`), `commitDiff` (shares
`commitDiffArguments`), `worktreeList`.

Loaders (YardKit/Sources/YardUI/RepositoryLoader.swift): all five now `await` the
async twins — `loadRepositorySummary`, `loadCommitHistory`, `loadCommitGraph`,
`loadCommitDiff`, `loadRepositorySidebar`. Still `@concurrent` (keeps parsing off
the main actor); doc comments updated.

Swift 6 ripple: async contexts prefer async overloads (verified empirically before
designing on it), so two existing async test call sites in
Tests/YardUITests/RepositorySidebarLoaderTests.swift needed `await` and now
exercise the new path.

## Property test and why it demonstrates the fix

`concurrentAsyncCapturesDoNotHoldCooperativePoolThreads` (Tests/YardGitTests/
GitProcessAsyncTests.swift) starts `2 × activeProcessorCount` concurrent async
captures of `/bin/sleep 2` and asserts, via a bounded poll loop (500 × 10 ms; Rule
7c safe — no clock assertion), that ALL children have started while NONE has
completed. A suspended capture holds no cooperative-pool thread, so all 2×cores
can be in flight at once and this holds with a ~100× margin (starts take
microseconds each; the first subprocess completes at 2 s). If the path blocks
(mutation 1), the pool saturates at ~core-count blocked children, the rest stay
queued, and a queued child can only start when a blocking child finishes — so
completions necessarily precede the last start and the assertion goes red. Nine
other tests cover sync/async output parity, `.exited` stderr, stdin, >600 KB
output, timeout semantics, cancellation, 8-way concurrency, and sync/async
equivalence of the engine twins on real fixtures.
