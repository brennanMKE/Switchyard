Wire switchyard status into the command registry

## What changed

- `YardKit/Sources/YardCommands/EngineCommands.swift` — added `case "status"` to
  `runEngineCommand` and a private `runStatus(workingDirectory:)` that resolves
  `WorktreeContext` for the **passed** working directory, calls `gitStatus(at:)`
  with `includeIgnored` at its default, and wraps the result in
  `Envelope(result: EncodableResult(...))` at exit 0. Failures become
  `EnvelopeFail(code: .repositoryError, ...)` with exit 6.
- `WorktreeStatus` **already conforms to `Encodable`** with an explicit
  `CodingKeys` enum (`case entries`, no raw values) at
  `WorktreeStatus.swift:498-503`, as does `WorktreeStatusEntry` and its nested
  types. Per the issue: said so and changed nothing.
- `YardKit/Sources/YardKit/CommandRegistry.swift` — added `statusSpec` to
  `CommandRegistry.all`: name "status", non-empty summary, non-empty
  schemaName "status", exit codes 0 and 6.
- **Payload shape: `nil`, deliberately.** The result type's only wire key is
  `entries` — an array of objects — and `PayloadShape` is flat-only;
  `CommandSpec`'s doc comment (#0194) says "nested objects and arrays are not
  supported ... do not half-build nesting to fit it in here", and #0194's
  decision 4 says nesting is "that command's issue". The checklist's spec item
  (summary, schemaName, exit codes) does not require payload. status.json
  therefore carries the self-reference form (`"result": {"schema": "status"}`),
  and the spec's comment documents why. Array support, if wanted, is its own
  issue.
- `YardKit/Schemas/status.json` — regenerated via
  `SCHEMA_REGENERATE=1 swift test --filter checkedInSchemasMatchEmitter`
  (1 test passed), per Schemas/README.md.
- `YardKit/Tests/YardCommandsTests/StatusCommandTests.swift` (new, declared
  target) — 5 swift-testing tests: not-a-repository (exit 6,
  `error.code == "repository_error"`); clean `FixtureRepository.linear()` →
  `entries` present and empty; modified `a.txt` + untracked file → exactly two
  entries with porcelain states `M`/`?`; registry spec lookup with non-empty
  summary/schemaName and exit codes 0 and 6; a schema-binding test asserting
  status.json carries the self-reference form (not a field list) and that a
  fully-populated `WorktreeStatus` encodes exactly the top-level key `entries`.
- `YardKit/Tests/YardKitTests/CommandRegistryTests.swift` — the existing
  "registry reports exactly three entries" test hardcodes
  `CommandRegistry.all.count`; the issue's own requirement (add statusSpec)
  makes it 4, so the test was updated to 4 (same thing #0124 did when whereami
  made it 3). Named `registryHasExactlyFourEntries` now.

## Mutations (each applied, killing test run and named, then reverted)

1. **Break the not-a-repository path so it returns success** — replaced
   `runStatus`'s catch with a success envelope of empty entries. Killed by
   `StatusCommandTests.nonRepositoryPathReturnsRepositoryErrorAtExitSix`
   (failed with 3 issues: exit code, `ok`, `error.code`).
2. **Rename one CodingKeys case** — first tried the bare rename
   `case entries` → `case items` on `WorktreeStatus.CodingKeys`: that is a
   **build error**, not a test failure, because synthesized conformance
   matches case names to property names. The compilable rename is an explicit
   raw value (`case entries = "items"`), which changes the wire key while the
   property name is unchanged. Killed by
   `StatusCommandTests.cleanRepositoryReturnsAnEmptyEntriesList` and
   `schemaResultIsTheSelfReferenceAndTheTypeEncodesOnlyEntries` (3 of 5 tests
   in the suite failed). Reverted both forms.
3. **Remove the spec from `CommandRegistry.all`** — dropped `statusSpec` from
   the array. Killed by
   `StatusCommandTests.statusSpecIsRegisteredWithRequiredMetadata`
   (`try #require(CommandRegistry.lookup(name: "status"))` fails). Reverted.

All mutations were reverted with exact inverse edits (no git state commands);
the final full suite above ran on the reverted tree.

## Could not do

- Running the real binary end to end (needs an installed app and a registered
  launch agent) — #0054's script, per the issue's Notes; not attempted.
- A `fields[]`-style schema binding like whereami's is impossible until
  `PayloadShape` can express arrays; the binding test pins the self-reference

  to WhereAmIWireTests) if a field list ever appears in status.json.
