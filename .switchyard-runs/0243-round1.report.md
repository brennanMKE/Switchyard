Bind schema optional flags to encoded absence

Second half of the #0194 schema binding (#0243): the `optional` flags a
checked-in schema declares are now pinned to what the result type actually
encodes. Together the two tests pin names (fully-populated) and absence
(minimally-populated); absent means absent, not null.

Helper design
-------------

New shared file `YardKit/Tests/YardWireTests/SchemaPayloadBinding.swift`:

- `checkedInSchemaPayloadFields(schemaURL:)` — reads
  `envelope.success.result.fields[]` off a checked-in schema file; every
  extraction is `try #require`, so a missing file, the historical
  self-reference, a non-string name, or a non-boolean `optional` stops the
  test loudly instead of degrading to "no fields".
- `schemaOptionalMismatch(schemaFields:encodedFullKeys:encodedMinimalKeys:)`
  — pure comparison, kept out of the assertions so the matcher itself is
  testable. "Absent" is computed from what the type ACTUALLY encodes
  (full keys minus minimal keys), not from the schema's own name list, so a
  bogus schema field marked `optional` cannot satisfy the comparison.
- `assertSchemaOptionalFlagsMatchEncodedAbsence(schemaURL:...)` — the
  one-call binding for a wire test; asserts the two directional mismatches
  separately, each naming the lying fields and the direction they lie in.
- `topLevelKeys(ofJSON:)` moved here from WhereAmIWireTests.swift as an
  internal helper so the next command's wire test reuses it.

The next command's wire test is therefore: encode full + minimal, two
`#expect(!keys.isEmpty)` guards, one `assertSchemaOptionalFlags...` call.

New tests (+2; 1299 -> 1301)
----------------------------

- `WhereAmIWireTests.schemaOptionalFieldsMatchTheKeysAMinimalValueOmits` —
  minimal `WhereAmI` (every optional nil), asserts the keys ABSENT are
  exactly whereami.json's `optional: true` fields, via the shared helper.
  Guards: both key sets non-empty, minimal subset of full.
- `SchemaOptionalMatcherTests.matcherQuietWhenFlagsAreTrueAndLoudInBothDriftDirections`
  — negative control for the matcher: quiet when flags are true, and exact
  set assertions for both drift directions (a required-demoted field lands
  in `typeOmitsButSchemaMarksRequired`, an optional-promoted field in
  `schemaMarksOptionalButTypeAlwaysEncodes`).

#0115 pattern decision
----------------------

Yes, the check belongs in the step list — but as an amendment to step 6
("Bind the schema to the type"), not a ninth step: it is the same activity
and the same file. Step 6 now requires both halves (names off a
fully-populated value, absence off a minimally-populated value), names the
two tests and the shared helper, and records the #0243 measurement that the
name half alone goes green under a lying flag. Only step 6's text changed;
nothing else in issues/0115.md was touched.
