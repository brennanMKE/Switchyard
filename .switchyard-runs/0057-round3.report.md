## The polish the sweep exposed: a rename group could never exit 0

The round-2 pane made the rename group's DD record a READ-ONLY card
("no choices, no stage button"), and the AU/UA cards offered only
`renameTakeOurs`/`renameTakeTheirs`. But `ResolveApply` is strictly
per-path: nothing propagated the DD record's deletion when a rename card
staged. A rename group (DD + AU + UA, rename/rename(1to2)) therefore kept
its old path unmerged no matter what the human staged — every rename
resolution through the UI would exit 8 forever, and the DD card's own
explanation ("this path records as deleted with it") promised something no
code did. The engine already treats all three records as
"keep the deletion" cards (`ResolveApply`'s doc comment;
`ResolveApplyTests/renameTakeOursStagesOursNewPathAndTheRestResolvesAsDeletions`,
`keepDeletionResolvesABothDeletedRecord`); only the pane hid it.

Fix, confined to `YardKit/Sources/YardUI/ResolvePane.swift`:

- New `ResolveCardKind.bothDeleted`: the explanation (now truthful) plus ONE
  stageable choice, `keepDeletion` — stage the deletion, the unmerged
  entries clear. `.readOnly(explanation:)` remains the design's mechanism
  for a kind the engine cannot resolve; nothing routes there today.
- Rename cards gain `keepDeletion` as their second choice: the take choice
  is the side the record carries (round 1's finding unchanged), keepDeletion
  drops that side's rename — how the group's other records resolve.
- View: the read-only gate became `if let explanation = card.kind.explanation`
  + `if !card.choices.isEmpty`, so the both-deleted card renders its
  explanation AND its controls; a read-only card still renders explanation
  only. Mapping is unchanged (`PathChoice.keepDeletion` →
  `ResolveResolution.keepDeletion`, one-to-one already); the engine already
  proved keepDeletion on DD/AU/UA records.

No fake choice was introduced: `keepDeletion` on DD/AU/UA is engine-proven
(working file removed when present, `git add` records the deletion), so it
is not a choice the engine must refuse.
