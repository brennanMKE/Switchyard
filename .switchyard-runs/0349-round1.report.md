## The abandoned design (gap filled)

- Each of `ReviewOutcome`/`AskOutcome`/`ResolveOutcome` gained `case abandoned`, encoded as the
  single key `{"abandoned":true}` (pinned byte-for-byte by `abandonedOutcomeRoundTripsThroughTheOneKeyWireShape`).
  Per-store cases, not a shared wrapper: a wrapper would re-shape every outcome's wire form and merge
  three stores' vocabularies (reasoning in the `AskOutcome` doc comment).
- `PendingOwner` (new, YardKit) is the per-connection token; `awaitDecision(for:owner:)` defaults to a
  fresh token (unowned pendings can never be abandoned); `abandonAll(ownedBy:)` is idempotent, marks
  every owned pending, fires the hook with `.abandoned`, and returns the count.
- **Abandonment is NOT a resolution.** The slot stays registered, the blocking waiter keeps waiting
  (its reply has nowhere to go either way, and releasing it would sever the decision path the note
  recording rides), and the human may still decide — resolve-after-abandonment succeeds and #0059's
  note still records (`decisionAfterAbandonmentStillRecordsTheNote`).
- Sheets/panes: `recordAbandonment()` sets `isAbandoned` (only while no terminal outcome); banner
  "The asking agent went away — you can still decide; it will be recorded as a note." (ask: "…you can
  still answer."; resolve: "…you can still decide."). Decisions STAY enabled; `.abandoned` is treated
  as non-terminal in `decisionsEnabled`/`answersEnabled`. The centre routes the hook's `.abandoned` to
  `recordAbandonment()` — never dismissal. A later terminal outcome (the reaper's `.timedOut`) still
  lands and ends the review (`theReaperStillEndsAnAbandonedReview`).
- App wiring (`AppXPCServer.swift`): `ListenerDelegate.shouldAcceptNewConnection` mints one
  `PendingOwner`, threads it into the per-connection `AppService`, and sets
  `connection.invalidationHandler = { @Sendable in …abandonAll(ownedBy:)… }` BEFORE `resume()`
  (`@Sendable` per this file's established handler discipline; stores captured through Sendable
  locals). `AppService` passes the owner into all three `run*Request` calls.

## The reaping policy (documented in each store's doc comment)

An orphaned pending is one whose CLI connection is gone (the per-connection invalidation handler
called `abandonAll(ownedBy:)`). Abandonment is not a resolution: the pending stays registered and
decidable. Each pending's own timer is the reaper — it stays armed through abandonment and fires
typed `.timedOut` at `timeoutSeconds` if the human never acts. No background reaper exists and none
is needed: each pending carries its own deadline, so orphans cannot accumulate. A decision after
abandonment resolves normally and is still recorded (#0059's note outlives the agent). Ask-specifics:
head AND queued asks are marked; the abandoned head keeps its position; the queued ask's timer arms
when it reaches the head, and the queue advances when the reaper fires.

per-pending timer is the only reaper; abandonment is a sheet STATE, never an early waiter release;
`PendingOwner` is the pattern for binding stream lifetimes to connections.
