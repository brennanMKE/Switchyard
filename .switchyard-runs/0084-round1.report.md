Route repository opens through one function

## What changed

The one function is `RepositoryTabs.open(path:) -> Outcome` (#0079, unchanged). This round added
`YardKit/Sources/YardUI/RepositoryOpener.swift` — the shell-side funnel — and wired all four
callers to it. Nothing resolves paths or constructs tabs outside `open(path:)`.

**The four callers and what each got:**

1. **File ▸ Open… + Open Recent** (`Switchyard/Commands.swift`, new): `.commands { SwitchyardCommands() }`
   attached to the existing scene; the #0078 `.handlesExternalEvents(matching: Set())` suppression
   is untouched. Open… → `RepositoryOpener.chooseAndOpen(store:)` (directory NSOpenPanel → funnel).
   Open Recent lists `RepositoryTabs.shared.tabs` and re-opens by `tab.openPath` — the open tabs
   ARE the recents for focus purposes; no new persistence store was built. `RepositoryRegistry`
   (repositories.json) exists but nothing in production calls `register`, so it is not a usable
   recents source this round.
2. **Drag-and-drop** — window half: `ContentView.dropDestination(for: URL.self)` →
   `RepositoryOpener.openDropped(urls:)`; Dock-icon half: new `application(_:open:)` in
   `AppDelegate.swift` → `RepositoryOpener.openDelivered(urls:)`. ContentView's own toolbar and
   empty-state buttons were also rerouted off their private `NSOpenPanel` onto
   `chooseAndOpen` — they were a bypassing open path in YardUI itself.
3. **`switchyard://` URL** (`Switchyard/AppDelegate.swift`): handled by the app delegate ONLY, in
   the same `application(_:open:)` (AppKit delivers both document drops and custom-scheme URLs
   there). No `.onOpenURL`, no new window. Registered the scheme (`CFBundleURLTypes`) and folder
   document types (`CFBundleDocumentTypes`, `LSHandlerRank None`) in a new `Switchyard/Info.plist`,
   referenced by `INFOPLIST_FILE` in both app-target configs (pbxproj; GENERATE_INFOPLIST_FILE
   stays YES and merges), with a synchronized-group membership exception so the plist is not also
   copied as a resource.
4. **XPC** (`Switchyard/AppXPCServer.swift`, `AppService.perform`): a request with a non-empty
   working directory hops to the main actor, `NSApp.activate()`, then
   `RepositoryTabs.shared.openInFrontmostWindow(path:workingDirectory, windowStore: .shared)` —
   the model half of "open in the frontmost window" is a new public seam on `RepositoryTabs`
   (attaches a NEW tab to the window showing the selected tab, else the first window; a focus or
   refusal touches no window). The CLI reply is sent before the UI hop, and a refusal is logged
   (`os.Logger`), never a modal — the message text comes from the same
   `RepositoryOpener.refusalMessage(for:)` formatter the user-facing entry points show in an alert.

**Testable seams added to YardUI** (all in `Tests/YardUITests/RepositoryOpenerTests.swift`, no
`@testable`): `refusalMessage(for:)` (non-empty, names the path, carries the resolver detail; nil
for open/focus), `repositoryPath(from:)`/`deliveredPath(from:)` (percent-decoded `path` query;
foreign scheme and pathless URLs name nothing), and `openInFrontmostWindow(path:windowStore:)`
(new tab lands in the active window; focus touches no window; refusal opens nothing). #0079's
identity cases were NOT duplicated — referenced, in RepositoryTabsTests.swift.

## Mutation (run and reverted byte-exact)

1. **URL delegate bypasses the funnel** — `application(_:open:)` replaced by a locally-constructed
   `RepositoryTabs().open(path: url.path)`. Caught twice by the greps: the positive grep lost
   `Switchyard/AppDelegate.swift` from the funnel-call list, and the negative grep flagged
   `Switchyard/AppDelegate.swift:40: RepositoryTabs().open(path: url.path)` (a second open path).
   Reverted with `cmp`-verified byte-exact restore; `git diff` shows only the round's 12 intended
   lines.
2. **Refusal formatter returns `""`** — `swift test --filter RepositoryOpenerTests` went red:
   "A non-repository refusal formats a message that is non-empty and names the path" failed
   (`!(("").isEmpty)` and `.contains(dir.path)`), and "A refusal message carries the resolver's
   detail" failed on `.contains(detail)`. Reverted byte-exact; full suite re-run green afterwards.

## Not testable here (→ #0054's manual script)

Real URL opens, real Dock drops, the open panel, the alert, XPC activations, `NSApp.windows`
ordering and frontmost/bring-forward behaviour, and window counts. The app target cannot map an
NSWindow to a `WindowState` — no such mapping exists in the codebase — so "frontmost" at the model
level is defined as the window showing the selected tab (what the tab-bar binding commits), with
the real NSWindow half in the app delegate/XPC handler for #0054 to check.

## Not done / for review

- Open Recent is deliberately unpersisted (open tabs as recents, per dispatch); a persistent
  recents store would need the `RepositoryRegistry` wiring, which nothing populates today.
- Tabs opened via entry points 1–3 attach to the shared `RepositoryTabs` store but no
  `WindowState.tabIDs` — the open→window binding commit is #0080's remaining wiring; only the XPC
  entry point attaches tabs to windows this round (its criterion is the one that names windows).
- A malformed `switchyard://` URL (no `path` query) is ignored, not alerted — nothing to name in a
  refusal message.
