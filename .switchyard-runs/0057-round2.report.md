## The cards, per the signed-off design table

- content (`UU`): Use ours / Use theirs / Edit merged; editor seeded with
  the working file's conflict-marked text.
- add/add (`AA`): same three; editor seeded with ours' content.
- delete/modify (`DU`/`UD`): Keep the deletion / Keep the modification /
  Edit merged; editor seeded with the surviving side.
- rename (`AU`/`UA`): per-record cards — AU offers Take ours'
  path+content, UA offers Take theirs'. A record carries exactly one
  side's stage (#0057 round 1's finding), so the side without a stage is
  NOT offered — a choice the engine must refuse is a fake choice.
  Recorded assumption: the design table's grouped two-choice rename card
  is presented here at the round-1 per-record granularity; the grouped
  three-record presentation was left to a future round.
- `DD` (both deleted) is the read-only card: an explanation, no choices,
  no stage button (`resolution()` is nil, `stage` refuses). Assumption
  recorded: the design table has no choice for a both-deleted record; its
  resolution rides the rename group's records.
- Every card: note-to-agent field (absent on the wire when empty), a
  Stage resolution button, a staged badge, and a typed stageError that a
  failed apply sets (the pending is never resolved by a failed apply; a
  retry is allowed; an already-staged card returns true without
  re-applying, since the engine would refuse the no-longer-conflicted
  path).

## Submit/cancel wiring

`ResolvePaneModel.composedReply()` -> `.resolutions(cards.compactMap {
$0.resolution() })` — staged cards and still-open cards alike, because the
reply is the record and the arm's exit-8 re-check reports the consequence
of what did not stage. `submit()` sends it through `onDecide`, wired by
the centre to `PendingResolveStore.resolve(id:answer:)`. `cancel()` sends
`.cancelled` and never calls the apply seam — stages nothing. `.decided`
dismisses the pane (centre removes the model, binding clears); timedOut/
superseded banner until Close. The apply seam is centre-level
(`applyResolution(originPath, PathResolution)`), wired by the bridge to
`ResolveApplyMapping.apply`; an unwired seam is a typed
`ResolvePaneApplyError` on the card, never a silent no-op.

## Rendering and the untrusted-content rule

Each card's sides (ours/base/theirs, only the stages that exist) render
side by side through #0082's `FileDiffView` — no second renderer. Blob
text is wrapped as context lines (`ResolveCardView.sideDiff`, public so
the no-`@testable` test asserts it): the leading space is the diff
marker, the line after it is the blob's line verbatim, conflict markers
included. Nothing interprets the text. Semantic colours only (.secondary,
.orange, .bar, .background) — dark mode by construction.
