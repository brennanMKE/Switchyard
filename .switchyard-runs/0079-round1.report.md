Dependency scoping decision and verification

`.package(url: "https://github.com/brennanMKE/SlidingTabs", from: "1.0.0")`
is declared at package level (SwiftPM requires it there), and the product is
named in ONLY the YardUI target's `dependencies`
(`.product(name: "SlidingTabs", package: "SlidingTabs")`), matching the
existing manifest's style. The CLI executable target was not touched. The
package resolved and built on the first attempt, so the issue's escape hatch
was not needed and the chrome landed with the store. Verified three ways:
`swift build` of the whole package succeeds; `xcodebuild build ... unsigned`
prints `** BUILD SUCCEEDED **`; and `otool -L` on the built
`YardKit/.build/debug/switchyard` binary lists only system frameworks and
Swift runtime dylibs — zero SlidingTabs entries (grep count 0).

Store design

`RepositoryTab` is an `@Observable` class with a stable `id: UUID` (the
handle `WindowState.tabIDs: [UUID]` from #0078 can reference; #0080/#0084
wire the two), the resolved `WorktreeContext`, the `openPath` as spelled by
the caller, `selectedWorktreeName`, `displayName` for the chip, and an
`onTeardown` hook. `RepositoryTabs` holds an ordered `tabs` array keyed by
`context.commonDir` and a `selectedTabID`; `open` resolves through an
injected `(String) throws -> WorktreeContext` closure defaulting to
`WorktreeContext.resolve(path:)`, focuses an existing tab on a commonDir
match (also selecting the worktree the opening path names, nil for main),
otherwise appends, and returns `.focusedExisting` / `.opened` /
`.refused(path:detail:)` — the refusal carries the resolver's
`notARepository` detail. The store calls no realpath itself; the tests assert
the canonicalization property instead (commonDir is a realpath fixed point).
`close(_:)` fires the tab's `onTeardown` hook once, removes the tab leaving
the others' order intact, and allows the list to empty — the never-empty
guarantee is WindowStore's (#0078) at the window level; when the closed tab
was selected, selection moves to the tab now at that index or to nil. The
tab bar view (`RepositoryTabBar`) binds `$store.tabs` (drag reorder commits
into the store), `$store.selectedTabID` (tap selects), wires each chip's
close to `store.close(_:)`, and passes a required `onAdd` through to the
bar's "+" button — the app target supplies the closure that ends in
`store.open(path:)` once a path picker exists (#0080/#0084).

Tests: exact line and delta

`Test run with 1229 tests in 89 suites passed after 62.165 seconds.`
Baseline 1215 → delta +14. All 14 new tests are in `Tests/YardUITests/`
(declared target path verified with `ls YardKit/Tests/`), import YardUI
without `@testable`, and are `@MainActor` like the store. Identity cases run
through the DEFAULT resolver against real `FixtureRepository` fixtures:
same path twice; symlink to the working tree; trailing slash; subdirectory;
linked worktree (`repo.addWorktree(named:branch:)`) focusing the parent tab
and selecting the worktree; reopening the main-worktree path reselecting
main; the unresolved `/var/...` spelling of a `/private/var/...` fixture
(requiring the `/private/` prefix first so it cannot silently test
nothing); and a non-repository path refusing with non-empty detail and no
tab. Pure-store behaviour (injection + commonDir keying, refusal leaving
tabs untouched, close order, last-close empties, teardown hook fires once
and the store drops its reference, commonDir realpath fixed point) uses an
injected table resolver built from pre-resolved fixture contexts.

One fixture surprise, found by the red suite and fixed in the tests: git
names a worktree after its directory's last path component, not the fixture
helper's `named:` parameter, so `addWorktree(named: "side", ...)` yields
worktreeName `yard-fixture-<uuid>-wt-side`; the expectations now assert
against `worktreeURL.lastPathComponent`.

Mutation (required, run and reverted byte-exact)

Changed the tab lookup from `$0.context.commonDir == context.commonDir` to
`$0.context.topLevel == context.topLevel` and ran
`swift test --filter openingLinkedWorktree`:
`Test "Opening a linked worktree of an open repository focuses the parent
tab and selects the worktree" ... failed ... Caught error: unexpected
outcome: opened(tab: YardUI.RepositoryTab)` — the mutation opened a second
tab instead of focusing the parent's. That test is the killing test for the
single choice this issue exists to make. Reverted to the commonDir key;
`git diff` shows only Package.swift modified plus the new files.

Not testable here — said plainly

Criterion 5's resource half: there are no file watchers in the codebase yet,
so "closing a tab releases its watchers" cannot be asserted for real. The
seam is implemented and tested at the level that exists: `onTeardown` fires
exactly once at close and the store drops its reference to the closed tab.
The file watchers themselves belong to #0081's sidebar/graph work; when
they exist they must register their teardown there.
