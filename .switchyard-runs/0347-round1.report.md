## Argument-refusal rule (guide §6)

The accepted grammar is strict: the only valid tails are `[]` and
`["--limit", "<positive-int>"]`, both parsed from `Array(arguments.dropFirst())` before
any repository access (so the refusal holds in an empty dir and a real fixture alike).
The value must be bare ASCII digits — checked before `Int` because `Int("+3")` and
`Int("-1")` both parse — and must be > 0; zero, negative, non-numeric, empty, and
overflow-length values are refused. Decided and documented: the joined form `--limit=3`
is refused (one token, not the flag-then-value shape this surface accepts), as are a
duplicated flag, a trailing token, and every unknown flag including `--all` (the app's
graph view grows its own revision surface, not this command). Every refusal renders
`EnvelopeFail(code: .usage, …)` on stdout, `[error] usage:` on stderr, exit `.usage` —
never a default guess.
