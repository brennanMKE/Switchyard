## Files changed

- `YardKit/Sources/YardUI/WindowID.swift` (new) — `WindowID`, a `nonisolated`
  value type (`Hashable`, `Codable`, `Sendable`), wrapping a `UUID`. Explicit
  `nonisolated` on the type: under YardUI's `.defaultIsolation(MainActor.self)`
  the synthesized Codable witnesses would otherwise be MainActor-isolated; a
  window id is inert value data that scene persistence must decode anywhere.
- `YardKit/Sources/YardUI/WindowState.swift` (new) — `WindowState`
  (`@Observable`, one window's `id` + placeholder `tabIDs: [UUID]`; #0079 owns
  the real tab model) and `WindowStore` (`@Observable`): seeds exactly one
  window at init, exposes `initialWindowID`, `windowState(for:)`,
  `addWindow()`, `removeWindow(_:)`. The list is never empty:
  `removeWindow` is a no-op on the last remaining window, so `initialWindowID`
  always names an id the store holds.
- `Switchyard/SwitchyardApp.swift` — `WindowGroup(for: WindowID.self)` whose
  `defaultValue` returns `WindowStore.shared.initialWindowID`, plus
  `.handlesExternalEvents(matching: Set())` on that scene (the only scene the
  app has). Cmd-N / `openWindow(value:)` unaffected. Comments carry both
  traps' substance from Batty's `BattyApp.swift` (MIT, same author, read
  first at `/Users/brennan/Developer/brennanMKE/Batty/Batty/BattyApp.swift` —

## Store design

`WindowStore` owns `[WindowState]` in creation order. The store seeds one
window in `init`, so the app's `defaultValue` closure returns an id ALREADY
in the store — SwiftUI's first content window reuses the existing runtime
instead of creating a phantom second one (trap 1). Removing the seeded
window while others exist is allowed; `initialWindowID` is defined as the
first window still in the list, so it never names a phantom. Removing the
last window is a no-op — the invariant the defaultValue depends on.
