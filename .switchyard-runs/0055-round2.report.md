## The model/sheet design

`ReviewSheetModel` is one per pending review, value-driven like
TransportStatusModel: the app target feeds it (registrations via the
store's hook, the diff via `attachDiff`), and every composable field is
assertable — `message`, `comments` (`addComment(path:hunkID:line:text:)`,
empty text refused), `editedPatch` (amend's capture surface, seeded from
the diff in `attachDiff`; a seed never overwrites edited text), and
`outcome`. `composedReply(for:)` builds the `ReviewReply`: message only
when non-empty (absent means absent), comments, and the patch text only
for `.amend` — approve/reject never carry a patch. `decide(_:)` sends
through an injected `onDecide` closure the centre wires to
`store.resolve(id:decision:)` — the same store API the app target uses.

The sheet is a pure function of the model: header (selector label +
origin path), the outcome banner when the store reported a typed outcome,
the diff via `FileDiffView` with a per-hunk comment affordance under each
hunk (DisclosureGroup + text field + optional line field — a comment
attaches to the hunk's stable content-derived id and an optional line),
the attached-comment list with remove buttons, the optional message
field, and the three decision buttons; selecting Amend reveals a
monospaced TextEditor bound to `editedPatch` plus Send/Cancel. Semantic
colours only (.secondary/.orange/.bar/.quaternary); a guardian test scans
the source for hardcoded colour literals.

## The pending-review model vs the store

`ReviewCenter(store:)` wires itself as the store's change observer
(hopped to the main actor). Registration creates a sheet keyed by the
pending's id with `onDecide`/`onClose` bound to the same store; `.decided`
removes the model (the sheet dismisses); `.timedOut`/`.superseded` set the
model's outcome — banner + disabled buttons, and the sheet STAYS until the
human closes it, so a lost review is never a silent vanish. A diff that
arrives before its registration (the serving body computes it first) is
stashed per commonDir and applied at registration, making the two arrivals
order-independent. `attachDiff` targets the newest still-pending sheet for
the commonDir, so a superseding request wins the diff too.

## Tab routing

`ReviewCenter.routeToTab(for:tabs:windowStore:)` applies #0084
focus-or-open to the review's resolved context: an open repository has its
tab selected; a missing one is opened into the frontmost window via
`RepositoryTabs.openInFrontmostWindow`. The routed tab's id is recorded on
the sheet (`model.tabID`), and `activeSheet(forTabID:)` is the per-tab
presentation seam for when windows carry tab chrome. Today the app target
binds through `activeSheet(forRepositoryPath:)` — matched against the
request's origin path (either may be a subdirectory of the other) and the
common dir — from `ContentView`, which is the only content view the app
has; the presentation is per-view (never app-modal), so a review on one
repository does not block another's window.

## The diff-resolution path

`runReviewRequest` resolves the context (as round 1), decodes the request,
computes `reviewDiff` for the selector, and calls `onPending(request,
context, files, errorMessage)` BEFORE handing to `ReviewServing.handle`
— which registers and blocks exactly as round 1 left it. The app service
hops the delivery to the main actor into `ReviewSheetBridge
.pendingDidRegister`, which routes the tab and attaches the diff. Round 1
callers are unaffected: `onPending` is optional and nil by default.

## Not done / judgement calls

- The app target presents the sheet on the content view that shows the
  repository (`activeSheet(forRepositoryPath:)`), because the app's
  windows do not render tab chrome yet (#0078's window/tab wiring is
  model-complete, view-incomplete). The per-tab accessor
  (`activeSheet(forTabID:)`) and the recorded `tabID` are the seam the
  tab-chrome wiring will use; no stray window can open — routing goes
  through the #0084 funnel.
- The store's hook fires on XPC's queues and the centre hops to the main
  actor; the hook is read unlocked, documented as caller-owned like the
  store's existing design.
- The diff is computed BEFORE registration — a snapshot of what the agent
  asked to review; a staged change landing in the milliseconds between
  compute and register is not re-read (round 3+ can refine).
- One full-suite run happened between the two mutation restores; the
  restored file's sha256 matches the pre-mutation one exactly, and the
  filtered suites re-ran green after the restore.
