Persist and restore window and tab state

Implements #0083 round 1. Layout persists to the shared state directory and
restores on relaunch; corrupt state degrades to the fresh launch; the
deleted-repository tab is the normal case and is reported, never dropped.

Persistence shape

JSON at `<stateDirectory>/window-state.json`, written atomically (0700
directory created as needed), sorted/pretty like RecentOperations. Tab
identity across relaunches is `commonDir` (already realpath-canonical), not
the per-lifetime tab UUID. Restore never throws: missing/unreadable/corrupt/
truncated/foreign-schema/zero-window files all degrade to the fresh single-
window launch. Restore REPLACES the window list with exactly the stored
windows (stored WindowIDs reused) — the #0078 phantom trap is the failure it
guards against. The active tab comes back through the global
`selectedTabID`, from the snapshot's single `isActive` flag.

Write throttling

Structural changes (addWindow/removeWindow, WindowState.tabIDs mutation,
RepositoryTabs open/close/reorder/activate — the latter two through didSet,
so the tab-bar bindings are covered) call `scheduleWrite()`, which only
marks a write pending. The write happens at `flushNow()` — at most one write
per flush no matter how many changes accumulated. The flush unit (not a
timer) is the throttle, so tests count writes with zero wall-clock
assertions. Flush points in the running app (terminate/background) are
launch wiring left to #0125; the writer seam is complete and tested.
