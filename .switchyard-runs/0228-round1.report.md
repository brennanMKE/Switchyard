## Spec-naming rationale

The spec is named `"wt"`-distinct `"wt where"` so `lookup(name:)` yields its own schema instead of `wt`'s and the distinct-names assertion stays satisfied. Routing is unaffected: `route(_:)` classifies by the first token and `wt` is already known, so `["wt", "where"]` reaches the engine arm regardless; the arm dispatches on the second token. `payload: nil` follows the statusSpec (#0225)/conflictsSpec (#0226)/wtSpec (#0227) precedent. The fields ARE flat strings/optionals that `PayloadShape` could express, but no precedent yet supports adding a shape for one command alone, and the issue's schema-binding test asserts the self-reference form — so nil + comment, and the encoded key set is pinned by the test instead.
