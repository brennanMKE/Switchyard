## The wire types

`ReviewRequest` (commonDir, selector, timeoutSeconds) — the CLI sends
`commonDir` empty because it does not link the engine; the app-side body
fills the resolved common dir before registering. `ReviewSelector` encodes as
a one-key object — `{"staged":true}` or `{"range":"main..HEAD"}` — because a
bare string is ambiguous (`staged` is a legal branch name). `ReviewDecision`
is a closed String-raw enum; the case name is the wire key. `ReviewReply`
(decision, message?, comments, editedPatch?) and `ReviewComment` (path,
hunkID, line?, text) omit nil optionals — never `null` (#0129 Decision 4).
`ReviewOutcome` is the app→CLI reply: `decided(reply)` / `timedOut` /
`superseded`, tagged-object encoding, pinned byte-for-byte in
`ReviewWireTests`. Degenerate app-side refusals (undecodable request,
unresolvable repository) reply a JSON `EnvelopeFail` instead — never a
review outcome, because "there was no repository" is not an answer to "what
did the human say".

## Pending-store design

Keyed by resolved `commonDir` — one pending per repository, per the issue.
A second request supersedes the first: the first waiter is resumed with
`.superseded` (typed — never a timeout lie, never a decision), which the CLI
maps to exit 4 with a superseded message. Timeout ownership: the STORE arms
each pending with the request's own `timeoutSeconds` and fires `.timedOut`
when the human never answers; the CLI separately backstops at
`--timeout + 5 s` so a lost reply cannot hang the process. The store is
lock-guarded (`@unchecked Sendable`, resumed outside the lock), exposes
`pendingReviews` (+ per-pending ids) for round 2's sheet, resolves via
`resolve(commonDir:decision:)` / `resolve(id:decision:)`, and never touches
AppKit. Renamed the resolver parameter `reply:` → `decision:` because
`XPCSendableTests` scans for `reply:` labels and would flag a non-XPC
method carrying one.

## The CLI arm's exits

0 approve or amend — **amend carries exit 0; it is not a rejection** (the
envelope still carries `editedPatch`). 7 reject (RemoteControl parity; the
envelope is still `ok:true` with the full reply). 3 app unavailable
(`launchIfNeeded: false`, M4 criterion). 5 app quit mid-review, via the
connection error path — never a decision. 10 the wait timed out (typed
`timedOut` outcome from the store, or the CLI backstop). 4 superseded or
unservable. 1 usage. **Deviation from the issue, documented in the doc
comment: the planning pass named the timeout code 8 under the belief 0-7
were the taken range; `blockedOnConflicts` (8) and `signingFailed` (9) predate
it, so `ExitCode.timedOut = 10` — the first free value. Renumbering existing
codes would break every other command's documented contract.** A non-`--wait`
form is a usage refusal for now (no non-blocking form exists in this build).

## Mutations (each run, killed, reverted byte-exact)

1. CLI maps a timeout to exit 0 (`ReviewArm.render`, `.timedOut` →
   `.success`): killed by `storeTimeoutArrivesAsExitTenWithTheTypedEnvelope`
   — "Expectation failed: (result.exitCode → .success) == .timedOut".
2. Store allows two concurrent pendings for one repo (slot keyed
   `commonDir#id` instead of `commonDir`): killed by
   `secondRequestForTheSameRepositorySupersedesTheFirst` — the run never
   completed: the mutated store can never resume the first waiter
   (`finish` looks the slot up by `commonDir`, which the mutation stopped
   matching), so the test hangs, and the 900 s shell timeout killed it. A
   hang is the honest behavior of that mutation and cannot pass the test.
3. Amend treated as a rejection (`case .reject, .amend, .approve:` → exit 7):
   killed by `decidedRepliesMapToTheirExitCodes` — amend and approve rows
   recorded `(result.exitCode → .humanDeclined) == (expected → .success)`.
