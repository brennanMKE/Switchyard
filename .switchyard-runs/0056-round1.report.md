Queue design (the one behavioural difference from review)

- queues: [commonDir: [Slot]]; awaitDecision appends; resolve only ever
  resolves the HEAD (resolve(id:) returns false for a queued ask — no
  jumping the queue); resolving the head promotes the next and arms ITS
  timer.
- Timeout applies to the HEAD only, and a queued ask's timer starts when it
  reaches the head — decided and documented in PendingAskStore's doc
  comment: arming at registration would run the clock while the human is
  looking at a different question. Note: because finish() is head-gated, a
  registration-armed timer would be outcome-equivalent (its fire is a no-op
  on a non-head id) — the guard lives in both places.
- Decline-to-answer is a decided reply with declined semantics: the store
  resolves .decided(reply{declined:true}), the CLI maps it to exit 7 with
  the envelope still ok:true (the review-reject contract). Never a timeout.

The arm's exits: 0 an option was picked (payload IS the reply), 1 usage
(no question / no --options / an empty option in the list / malformed
--timeout / unknown flag), 3 app unavailable (connect launchIfNeeded:false),
5 app quit mid-ask, 7 declined, 10 typed timeout (store fires at
--timeout; CLI backstop at --timeout + 5 s). Default --timeout 3600 —
labelled a judgement.

The sheet: question renders through Text(verbatim:) — never markdown, never
a link (untrusted agent input); options as buttons in presentation order;
optional message field; Decline to answer button; timed-out banner stays
until closed; decided sheets dismiss. AskCenter presents the FIRST
still-pending model per repository — registration order is queue order, so
no promotion event is needed.
